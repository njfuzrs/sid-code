# 接下来读什么

**到这里你已经会用了。** 装好了、配好了、跑通过一个真实任务——
剩下的全部是按需读，没有"必须读完"的部分。

这页的作用只有一个：帮你判断**下一篇该读哪个**，而不是让你从头读到尾。

## 先按你现在的处境挑一条

| 你现在的状态 | 去这里 | 为什么 |
| --- | --- | --- |
| 能跑了，但每一步都要确认，很烦 | [权限与人工确认](/use/permissions) | 六种权限模式的取舍表 + 规则怎么写。这是从"能用"到"用得顺"最短的一步 |
| 想让它懂我这个项目的规矩 | [记忆与 CLAUDE.md](/use/memory) | 把项目约定写一次，之后每个会话自动带上，不用每次重复交代 |
| 关心花了多少钱 | [成本与用量](/use/cost) | `/cost` 怎么读、缓存命中率怎么提。sid-code 在这块有实测数据 |
| 想接自己的工具或流程 | [扩展方式总览](/extend/) | 一张选择表：想干什么 → 该用 CLAUDE.md / Skill / Hook / MCP / 子代理里的哪个 |

拿不准就选第一条。权限是绝大多数人用完第一天就想改的东西。

## 四条完整路径

### 路径一：把日常用顺（多数人走这条）

按这个顺序读三篇，大约二十分钟，覆盖日常九成场景：

1. [权限与人工确认](/use/permissions) —— 不再被每一步打断，同时不让它乱改代码
2. [交互模式与键位](/use/interactive) —— 全部快捷键，含 `--inline` 逃生舱
3. [上下文与压缩](/use/context) —— 长任务为什么会变慢变贵，什么时候该 `/compact`

想更细就补[会话管理](/use/sessions)（怎么找回上周那次会话）和
[Plan Mode 与 Todo](/use/plan-mode)（复杂任务先出计划再动手）。

### 路径二：让它适配你的项目

从最省力的开始，往下逐级变重：

1. [记忆与 CLAUDE.md](/use/memory) —— 写一个文件就生效，性价比最高
2. [Skill](/extend/skills) —— 把一套重复流程打包成可调用的能力
3. [Hook 指南](/extend/hooks) —— 在固定时机自动做事（提交前跑 lint、拦危险命令、自动格式化）
4. [MCP](/extend/mcp) —— 接入外部系统（数据库、工单、内部 API）
5. [子代理](/extend/subagents) —— 拆任务并行做，还能按类型分配便宜模型省钱

**先试 CLAUDE.md 再考虑后面的。** 很多人一上来就想写 Hook，
结果发现要的效果写三行 CLAUDE.md 就够了。

### 路径三：写脚本、进 CI（当 SDK 用）

不开 TUI，直接当命令行工具调：

```bash
sid-code -p "看一下这次改动有没有问题" --output-format json
```

- [无头模式与脚本化](/extend/headless) —— `-p`、JSON 输出、stream-json 协议、结构化输出
- [代码智能（LSP）](/extend/lsp) —— 让它拿到编译器级的诊断，而不是靠猜
- [CLI 参数与子命令](/ref/cli) —— 全部参数速查

### 路径四：在团队里推开

- [团队默认配置分发](/team/defaults) —— 一份配置发给所有人，且不覆盖已有配置
- [配额与成本控制](/team/quota) —— 给人均成本设上限
- [企业 policy 与安全边界](/team/policy) —— 哪些操作在你的环境里必须禁掉
- [轨迹采集与可观测](/team/observability) —— 团队实际用得怎么样，看数据不靠感觉
- [从 Claude Code 迁移](/team/migrate) —— 团队里有 cc 用户就先读这篇

## 查东西的时候去哪

需要确切写法而不是教程时，去**参考**那一层。这几页**全部由脚本从源码生成**，
所以不会跟实现漂移——表里的名字就是你配置里要写的字符串：

| 查什么 | 去 |
| --- | --- |
| 某个命令行参数叫什么 | [CLI 参数与子命令](/ref/cli) |
| 会话里能打什么斜杠命令 | [斜杠命令](/ref/slash-commands) |
| 权限规则/hook matcher 里工具名怎么写 | [内置工具](/ref/tools) |
| settings.json 某个字段的类型和默认值 | [settings.json 字段](/ref/settings) |
| 有哪些环境变量 | [环境变量](/ref/env) |
| Hook 某个事件的输入输出和退出码 | [Hook 事件](/ref/hooks) |
| 某个术语什么意思 | [术语表](/ref/glossary) |

指南页和参考页是分工的：**指南页讲怎么做，参考页讲确切写法**。
指南页刻意不贴完整字段表（会漂移），需要时用一句话加链接指到参考页。
