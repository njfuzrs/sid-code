# 快速上手

这页写给**后端已经装好、第一次用管理台的管理员**。照着走一遍，大约 30 分钟，你会把一台员工机器接进来，给它下发一份策略和一份预算，并在管理台里看到它们生效的证据。

后端还没装的，先看[部署与配置](/backend/deploy)。只想在自己电脑上先看看管理台长什么样，用那页的「本地试用」一节，十分钟能起来，然后回到这里。

下文的示例统一用组织 `acme`、团队 `platform`、员工「张三」、后端地址 `https://agent.example.com/traj`。

## 0. 先确认三件事

| 要确认的 | 怎么确认 |
| --- | --- |
| 后端在跑 | `curl https://agent.example.com/traj/api/v1/health` 返回 `{"status":"ok",...}` |
| 你是 admin | 用飞书登录管理台后能看到左侧菜单。看到整页「没有管理台权限」说明你还是 member，按[部署与配置](/backend/deploy#首个管理员)把自己设成管理员 |
| 员工的 sid-code 版本 | `sid-code --version`。注册码命令 `sid-code auth enroll` 和策略轮询需要 v0.1.610 之后的版本 |

## 1. 建组织和团队

飞书登录的设备默认落在 `default` 组织（由 `CTL_LOGIN_ORG_ID` 决定）。一家公司一个组织就够了，如果 `default` 这个名字可以接受，可以直接用它，只建团队。

1. 左侧菜单「**组织与团队**」。
2. 需要新组织时点「**新建组织**」，「组织 ID」填 `acme`，「理由」填「首次接入」。
3. 在组织那一行点「**新建团队**」，「团队 ID」填 `platform`，「理由」必填。

**怎么确认成功了**：「团队」表里出现 `acme / platform`，「设备数」为 0；页面底部「变更审计（最近 100 条）」多了两条「新建组织」「新建团队」。

::: tip ID 建好后只能改名称
组织 ID 和团队 ID 会被策略、预算、市场条目引用，建好以后不能改，只能改显示名称。详见[组织与团队](/backend/org-team)。
:::

## 2. 接入第一台设备

让张三在自己的电脑上执行：

```json
// ~/.sid-code/settings.json（只要配一次；也可以由团队默认配置统一下发）
{ "backend": { "url": "https://agent.example.com/traj" } }
```

```bash
sid-code login
```

浏览器里完成飞书授权后，终端显示「✓ 已登录：张三」。员工侧的细节（SSH 远程机器、凭据存在哪）见[企业登录](/team/login)。

没有浏览器或飞书的机器（CI、构建机）改用注册码，见[设备与注册码](/backend/devices#注册码)。

回到管理台：

1. 左侧菜单「**设备**」，列表里出现一行新设备，「用户」是张三，「组织」是 `default`（或你的登录组织），「团队」是 `—`。
2. 在这一行点「**调整归属**」，「组织」选 `acme`，「团队」选 `platform`，「理由」填「分进 platform」，确定。

**怎么确认成功了**：提示「已调整，设备下一次请求控制面即生效」，这一行的「团队」变成 `platform`。让张三执行 `sid-code auth status --verify`，「组织」「团队」两行显示新值，下面各条企业通道都是 ✓。

## 3. 给组织下发一份策略

1. 左侧菜单「**策略**」，点「**新建策略**」。
2. 「层」选组织，「组织 ID」填 `acme`。
3. 「permissions.deny」填一行 `Bash(curl *)`；建议同时打开「**禁用 bypass 权限模式**」。
4. 「变更原因」填「接入试点」，确定。
5. 在列表下方输入张三那台设备的 ID，点「**预览命中**」。

**怎么确认成功了**：

- 预览显示「将命中 `org` `acme`」。如果显示的是 `team` 或 `device`，说明下层已经有一份策略把它遮住了，见[策略](/backend/policy)页首的警告。
- 张三重启 sid-code（或执行 `/login`），让它跑一条 `curl` 命令，会被拒绝。不重启的话，交互会话最迟约 33 分钟内也会拉到。

## 4. 给团队配一份月预算

1. 左侧菜单「**成本**」，在「预算（超限开关）」区块点「**新建预算**」。
2. 「层」选团队，「组织 ID」`acme`，「团队 ID」`platform`。
3. 「周期」选自然月（UTC），「上限（USD）」填 `50`，「超限动作」保持「告警放行」。
4. 「变更原因」必填，确定。

**怎么确认成功了**：预算表里出现这一行，「本周期 used / limit」显示 `$0.0000 / $50.00` 之类的值；在预览框输入设备 ID 点「预览命中」，显示命中团队层 `platform`。

先用「告警放行」跑一段时间，看清团队的真实花费，再考虑切「硬拦」。两者区别见[预算](/backend/budget)。

## 5. 看到效果

让张三正常用 sid-code 做一两件事，然后：

| 去哪 | 应该看到 |
| --- | --- |
| 「成本」→「按人看用量」 | 张三一行，会话数 ≥ 1，有 `cost_usd` |
| 「成本」→ 预算表 | `platform` 那行的 used 变大了 |
| 「设备」→ 张三那行「生效配置」 | 策略命中组织层、预算命中团队层，以及「最近一次 policy_enforced」 |
| 「审计」 | 「策略与护栏是不是在拦东西」表里，这台设备的 `policy applied` 不为零 |

「按人看用量」是空的：多半是账本还没上报（会话结束或每一轮结束时才推）或员工开了 `no-telemetry`，见[成本](/backend/cost#常见问题)。

## 本页做了什么，没做什么

做了：一个团队、一台设备、一份组织层策略、一份团队层预算。这已经是一套能用的最小配置。

没做、但上线前值得做的：

- 把 `backend.url` 分发给全员，见[团队默认配置分发](/team/defaults#怎么让全员接上企业后端)；
- 把员工都分进团队。飞书登录的新设备默认不在任何团队，团队层的策略和预算对它们不生效；
- 提醒员工企业后端会收集哪些数据，见[隐私与数据流向](/use/privacy)；
- 部署侧的上线检查清单，见[部署与配置](/backend/deploy#上线检查清单)。
