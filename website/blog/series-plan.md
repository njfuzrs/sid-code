# 博客系列规划

博客的定位：**拆开 sid-code 的一个机制，讲清「为什么这么设计 → 怎么实现的 → 实测数据 → 踩了哪些坑 → 当前边界在哪」**。每篇都有硬数据和 file:line 级证据，和一般技术博客的区别写在[目录页](/blog/)里了。

选题按北极星四个方向 + 底座来组织。一篇能串起多个方向时，放在它主攻的那个系列下。

---

## 一、上下文工程系列

> 规则 / 提示词 / 压缩 / cache —— 什么内容在什么时刻进入上下文，以什么代价。

- ✔ [JIT 上下文：让规则在正确的时刻进入上下文](/blog/jit-context) — 两条注入路径、19 会话实测基线、三个静默缺陷、JIT 与 cache 的张力。**2026-08-02**
- ✔ [Prompt Cache：两族协议的分叉，和 4.2 亿 token 的实测账](/blog/prompt-cache) — Anthropic vs OpenAI 协议的分段/前缀差异、283 会话账本、三个只有实测能发现的坑。**2026-08-04**
- [ ] **上下文压缩机制** — 自动压缩的触发判据、压缩策略怎么保证"信息保真"、压缩后的 token 省了多少、压缩与 cache 的张力（压缩会打断前缀）。这是 JIT 和 cache 两篇都提到但没收口的第三块拼图。
- [ ] **系统提示词的结构与编排** — 为什么切成这么多块（角色设定、工具规范、规则注入、动态提示）、静态/动态边界怎么划、`DYNAMIC_BOUNDARY` 哨兵的设计取舍。这篇可以串起 JIT 和 cache 两篇的架构前提。
- [ ] **CLAUDE.md 七层规则系统** — 企业 → 全局 → 用户 → 项目根 → 子目录 → `.claude/rules/` → `CLAUDE.local.md`，优先级、覆盖关系、变更监听、与 JIT 的交互。

## 二、数据与度量系列

> 轨迹底座 —— 度量不是"验收达没达标"，而是"确认每一步是不是在朝北极星走"。

- [ ] **轨迹系统：events.jsonl 从埋点到闭环** — 1481+ 会话的轨迹结构设计、trace-digest 的统计口径、怎么从"埋了数据"走到"数据能回答北极星方向问题"。这是底座，也是最该有一篇的——前两篇每次都引用了它的数字但没展开讲过它本身。
- [ ] **成本度量体系的演进** — usage-ledger 的设计、命中率/成本采集的口径缺陷（影子调用绕过埋点）、`promptTotal` 与 `costUSD` 不同源导致"不能相除"的根因、修复过程。cache 篇已经交代了问题，这篇专讲度量系统自己的演进。
- [ ] **缓存命中率检测器** — cache-break 的检测与归因、前缀 hash 判据的设计思路、847 条假数据污染事故的完整复盘。cache 篇的坑一写了一半，这里把归因体系展开讲透。

## 三、Agent 架构系列

> 主循环、子代理、会话管理 —— agent 怎么跑起来的。

- [ ] **子代理系统** — 何时派、怎么隔离（worktree）、只读/可写分级、上下文预算分配、子代理 JIT 与主循环的关系。jit-context 那篇提到了子代理 JIT 关不掉的边界，这篇专讲子代理的完整设计。
- [ ] **主循环机制** — 一轮请求的完整流水线：工具调用 → 结果回灌 → 下一轮推理。循环终止条件、压缩触发时机、异常恢复、流式与非流式的分叉。
- [ ] **会话生命周期** — 从 cold start 到 resume、sessionId 的生成与复用、会话恢复时哪些状态必须重建、`--continue` 的语义边界。

## 四、安全与权限系列

> 拦截链、HITL、防线体系 —— "更安全"是怎么落地的。

- [ ] **权限校验机制（PermissionChecker）** — 工具调用前的拦截链、fail-closed 设计、权限模式切换（acceptEdits / dontAsk）、B0-B6 防线分层。
- [ ] **Bash 安全防线** — 危险命令拦截的静态分析、`*` 不跨 `/` 这类已知缺口、防线命中率实测。
- [ ] **四环防线体系** — 从静态防护到 HITL 的分层设计、每层的触发数据、与 CC 的对标差异。

## 五、TUI 系列

> Ink/React 渲染管线 —— 终端里的像素是怎么画出来的。

- [ ] **Ink/React 渲染管线** — 怎么把 React 组件树变成终端像素、假 stdout 复现方法、alternateBuffer 的兼容性回归。TUI 是用户最直观感知的部分，实现细节几乎没人写。
- [ ] **Footer 状态栏设计** — 两行状态栏的信息架构、百分比指标的语义（contextWindow / tokenBudget）、右侧对齐的那次 yoga 布局 debug。

## 六、工程实践与踩坑系列

> 切口更小，但坑够深 —— 单篇讲透一个事故或一个设计的演进。

- [ ] **测试隔离的演进** — 从无隔离 → 显式变量 → preload 兜底 → 静态扫描门禁。每一步都是被真实污染逼出来的：cache-breaks 6 万行假数据、migrations 无条件删 env 连坐其他测试文件、`debug.log` 被 e2e 测试截断。
- [ ] **NUL 字节问题** — ripgrep / subagent 的静默致盲、怎么发现的、怎么修的、为什么容易复发（两次复发实测）。
- [ ] **流式处理事故** — `stream_restart` 作废广播的根因与修复、空参数连坐 bug。
- [ ] **git worktree 隔离** — 并行子代理改文件不冲突的方案选型、worktree 的踩坑记录。
- [ ] **假 stdout 调试方法论** — 怎么用假 stdout 驱动真实 ink 管线、`onRender` 的手动触发与真实运行时的差异。

## 写法约定

每篇都遵守[目录页](/blog/)的三条自我约束，再补两条从已发布两篇里提炼的：

- **不解释概念本身**。prompt cache 是什么、JIT 是什么——一两句话给定义就够了，剩下的篇幅留给"在 sid-code 里它是怎么实现的、测出来是什么样"。市面上有的是讲概念的文章，博客的差异点不在那里。
- **归因分布要有"出乎意料"那一栏**。cache 篇的归因分布里 99.8% 是服务端波动——这个数本身是结论。数据跑出来之前没人能猜到，它比任何定性分析都有信息量。每篇的实测小节都应该追求至少一个让人意外的数字。
- **边界写"怎么绕"，不写"以后修"**。jit-context 篇的边界表每行都有绕法——这不是免责声明，是让读者知道踩到边界的正确姿势。
