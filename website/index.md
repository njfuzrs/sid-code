## 一分钟装上

<!--
  ⚠ 这一段刻意分成「装」和「配」两步，别合回一个代码块。
  曾经写成 `curl … | bash` 紧跟「装完直接启动 `sc`」——那是一条**假的成功路径**：
  sid-code 不含模型，没配 provider 时进 TUI 打第一句话就报模型错误。
  用户会把这当成安装失败，而真正的原因（还没配 provider）在安装页第 198 行才解释。
  所以这里第一步只验证版本（不启动 TUI），把「配 provider」摆成明确的第二步。

  同理，「不带模型、费用走你自己那份」这个前提必须写在首屏：
  它决定用户要不要先去申请网关权限，以前要点进配置页第 8 行才看得到。
-->

```bash
curl -fsSL https://www.sid-code.cc/releases/sid-code/install.sh | bash
sid-code --version    # 确认装上了
```

装不上或 PATH 没生效，[安装页](/start/install)列了三类最常见失败的原样报错与处理。
服务器在团队内网，需要在公司网络或 VPN 下访问。

**然后配一个模型再启动。** sid-code 本身开源免费，但它**不带模型**——
你需要一个 LLM 端点（公司网关 / 任意 OpenAI 兼容 API / 本地 ollama），token 费用走你自己那份。
[配置 provider](/start/configure) 给了三族协议各一份可直接粘的配置；
第一次启动没检测到配置时，TUI 也会弹分步引导问你要哪个。

<!--
  ⚠ 首页教启动命令时必须写清 sc 是全放行别名，别只写「`sc` 启动」。
  安装脚本真的会往 rc 文件里写 alias sc='sid-code --dangerously-skip-permissions'
  （dist/release/install.sh:242），即改文件、跑命令一律不问。
  安装页第 80 行有这条警示，但首页是绝大多数人唯一会看的一页——
  在这里把它说成"推荐启动方式"而不提权限，等于默认让新手在自己的仓库里全放行。
-->

配好之后启动。**这里有个坑**：安装脚本写的 `sc` 别名等价于
`sid-code --dangerously-skip-permissions`，也就是改文件、跑命令都不再问你。
熟手顺手，但**第一次用建议直接跑 `sid-code`**，把每一步确认看清楚：

```bash
sid-code      # 逐步确认，推荐第一次这么跑
sc            # 全放行（= --dangerously-skip-permissions），确认过风险再用
```

两种模式的边界见[权限与人工确认](/use/permissions)。

想知道花多少钱：一个「加个函数 + 跑测试」级别的小任务实测约 $0.08
（[完整账单读法](/use/cost)）。

## 和 Claude Code 的关系

功能面对标 Claude Code：agentic loop、工具调用、权限门控、Hook、Skill、MCP 都有对应实现，
用过 cc 的人几乎零迁移成本（见[迁移指南](/team/migrate)）。

差别在上面那四条——它们不是"做得更好"，而是**闭源商业产品结构上给不了**：
模型绑死一家、harness 改不了、进不了企业内网、数据不在你手里。
自研是同时拿到这四样的唯一路径。
