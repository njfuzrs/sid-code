# 内置 skill 下沉插件市场：否决的六个方案

方案文档 §9 要求把这几条否决留在仓库里，免得下一个 agent 重新提议。完整论证在
`docs-research/sid-code/bugfixes/todo/20261010-内置Skill下沉到插件市场-方案设计.md`
（§3.2 / §5 / §6.1 / §7），这里只记结论和最短理由。

## 决定了什么

下面六个方案都**不做**。前四个是永久否决，后两个写了重新评估的触发条件。

1. **独立的 Skill 市场**：单个 skill 也打包成最小插件（`plugin.json` + `skills/<名>/SKILL.md`），
   直接复用插件市场的 sha256 校验、防 zip slip、可见范围、下载归因和来源锁定。CC 和 Codex 都是这么做的。
2. **GitHub 源（把 git 仓库当市场）**：只用 `url` 源的静态 index。
3. **短名回退（不冲突时允许只敲 `/security-audit`）**：一律 `/插件名:skill名`。
4. **发布即自动推送安装**：自动更新只升级已经装了的插件，从不新装；hooks / MCP 有变化时只提示。
5. **为了对齐 CC，把 commit / pr / pr-workflow 迁成 markdown 插件**，包括 v2 的「插件版 prompt 指示模型调用内置 commit / pr」。
6. **让 CI 持有 sid-code.cc 的上传凭据**：官方插件发布由维护者在本机跑 `scripts/plugins-release.sh`。

## 放弃了什么（以及为什么不选）

1. **独立 Skill 市场**：要再造一套校验、归因和锁定，与插件市场重复，而且锁定企业要分别管两套白名单。
   代价是装 `compliance` 会同时拿到两个 skill，listing 里多一行，可以接受。
2. **GitHub 源**：要新写 clone 或 API 拉取、认证、缓存和 ref 固定，代码量是静态方案的好几倍。
   国内访问 GitHub 不稳定，本仓实测过 gh 正常、git 卡在 443。发布制品本来就放在自有服务器上，
   有 `rollback.sh` 的指针回滚机制，不需要再引入一条新的信任链。
3. **短名回退**：用户或项目一旦新增一个同名 skill，原来那条命令就会**静默**改成调用另一个东西。
   CC 只对 claude.ai 同步的 skill 开了这个口子，还专门写了一套冲突提示。我们没有这个需求。
4. **发布即自动推送安装**：hooks 会在每个员工本机执行命令。新装比升级的权限更宽，
   不能比用户自己手动 install 还松。
5. **commit / pr / pr-workflow 迁成 markdown**：这三个是 TS skill，在 `getPromptForCommand` 里从
   `context.config.git` 读归因配置。改成 markdown 就读不到：用户关掉归因，插件照样加。
   这种错不报错，只会悄悄变。v2 的绕法也走不通：commit 和 pr 是 inline，`cli.ts` 不会把 inline
   skill 包成工具，SkillManager 里也没有它们，所以模型**根本调不到**；就算改成 fork，
   `bundled/tool.ts:94` 传的是空 ctx，照样读不到 `settings.git`。
   - 重新评估的条件：有团队真的要定制自己的 commit 流程。届时的通解是在 `processSkillPrompt`
     里加 `${GIT_COMMIT_ATTRIBUTION}` 这类变量，前提是先修空 ctx，并单独评审「插件读本机配置」这个新口子。
6. **CI 持有上传凭据**：现在能上传 sid-code.cc 的只有维护者本机的 `scripts/deploy.env`（SSH）。
   放进 GitHub Actions，等于把能改服务器上**所有**发布制品（包括 sid-code 本体二进制和 `latest.txt`）
   的凭据交给 CI，范围远大于「发插件」。
   - 重新评估的条件：发布频率高到手动发布成了瓶颈。届时先在服务器上开一个只能写 `plugins/`
     目录的独立账号，再把官方发布挪进 CI。

## 拿什么证明它生效了

否决项没有运行时信号，证据是现状与这几条一致：

- `packages/cli/src/plugin/market.ts` 的 `resolveMarkets()` 只接受 `source:"url"`，其余来源一律告警并丢弃（第 2 条）。
- `plugins/tests/*.test.ts` 断言插件 skill 的名字是 `ops:incident-rca` 这种带命名空间的形式（第 3 条）；
  P4 的旧命令迁移提示只告诉用户新名字，不会替用户转调（`packages/cli/src/command/migrated-skills.ts`）。
- `packages/cli/src/plugin/auto-update.ts` 只遍历已安装的插件（第 4 条，P2 Agent Note 有测试）。
- P4 之后 `bundled/index.ts` 仍然注册 commit / pr / pr-workflow，`packages/core/tests/tool/git-attribution.test.ts`
  断言 `/pr-workflow`、`/pr` 按配置注入或关闭归因（第 5 条）。
- `.github/workflows/` 里没有上传 sid-code.cc 的 job；P3 用 `plugins-release.sh` 在本机发布了 3 个插件（第 6 条）。
