# 否决给 masking 进出加滞回阈值（4d）

## 决定了什么

工具输出遮罩（observation masking）**不加**「进入 soft 线后要低于 soft 线 − X 才退出」的滞回阈值。振荡由两条根因修掉：**校准同源**（4a，masking 轮不拿遮罩后的 usage 去更新校准因子与锚点，见 `packages/core/src/context/manager.ts` 的 `recordActualTokens`）与**遮罩粘滞**（4b，首次遮罩的占位写入 `maskedState`，level 回落也不恢复原文）。来源：评估会话 ce7ea52e 的评估报告 §5 决策 5。

## 放弃了什么（以及为什么不选）

- **4d 进出滞回（只做它、不做 4a）**：这是最典型的折中——阈值能压住 level 抖动，但压不住**估算本身被污染**：遮罩后的 usage 继续把校准因子拉低，全量估算继续被低估，界面上「稳住了」，实际触发时机仍然漂移。它属于「在下游打补丁」。
- **4a + 4b + 4d 三件一起做**：4a 修掉自激之后，level 不再因估算被拉低而回落，滞回只剩「防边界抖动」一个作用；而 4b 的粘滞已经保证边界抖动不改写已发送前缀（这是抖动真正伤到的东西——缓存）。此时再加一个阈值，只是多一份要测试、要解释、可能自身抖动的状态。
- 代价：masking 的进入/退出判据保持单阈值，边界附近的 level 仍可能抖动一次；但因 4b 粘滞，抖动不再改写前缀、不再造成 cache 反复脱落，可观测伤害为 0。

## 拿什么证明它生效了

（rejected 记录，没有可跑的验证。）验证落在被采纳的 4a+4b+4c 上：重放 soft 线附近历史循环 10 轮，修复前 level 交替、修复后稳定且被遮罩的 id 集合单调不减、校准因子恒 ≈1，做变异自证；端到端口径是「同形态长会话中 cache_read 突降到约 6 万的非压缩轮为 0」。详见 `implemented/bug-fix/2026-10-21-压缩判据同源与masking校准粘滞.md`。
