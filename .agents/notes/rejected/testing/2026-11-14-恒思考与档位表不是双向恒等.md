# 不把「always-on ⇔ 有非空档位表」做成门禁：这两个维度本来就正交

## 决定了什么

**否决「把恒思考门禁改成双向恒等式 `thinkingMode === "always-on"` ⇔ `reasoningEffortValues` 非空」这个修法。**

这个建议原本写在方案 §4.3/§4.4 两处（「后续如果要让这道门禁真正闭合，应改成双向」），
起因是 `o3` / `o3-pro` 漏标 `thinkingMode` 而当时无人发现。方向判断是对的（单向门禁确实有缺口），
但选错了判据。

正确做法是**族级不变量**：只对 `o-series` 这一族断言「全族恒思考」，理由与落地见
`implemented/testing/2026-11-14-恒思考门禁补族级不变量与判定链上游扫描.md`。

## 放弃了什么（以及为什么不选）

### 反例：注册表里现有 4 条「有档位表但能关思考」的条目

```
glm-5.2                     reasoningEffortValues=["low","high","max"]   thinkingMode=undefined
grok-4.3                    reasoningEffortValues=["low","medium","high"] thinkingMode=undefined
grok-build-0.1              reasoningEffortValues 非空                    thinkingMode=undefined
grok-4.20-0309-reasoning    reasoningEffortValues 非空                    thinkingMode=undefined
```

这 4 条**本来就该**是 `undefined` —— 它们接受 `disabled`，`/think off` 能真的关掉思考。
其中 `glm-5.2` 与 `grok-4.3` 还是现有测试的**负向对照**
（`thinking-off-floor.test.ts` 里「能关思考的模型不兜底」与「未登记的旧模型不发 effort」）。

双向恒等式一旦落地，只有两种结局：

- 断言方向写成「有 values ⇒ 必须 always-on」→ 这 4 条立刻变红，或者被逼着改数据，
  把能关思考的模型标成恒思考 —— 那会让 `/think off` 在它们身上**从 disabled 变成 low**，
  即「想关却关不掉」，比本次要修的 bug 更严重；
- 断言方向写成「always-on ⇒ 有 values 且 values ⇒ always-on」→ 同上。

### 根因：两个维度正交

- `reasoningEffortValues` 回答「**有哪几档可压**」（协议/模型是否接受 `reasoning_effort` 及其取值集合）；
- `thinkingMode: "always-on"` 回答「**能不能不发思考 / 关掉思考**」（服务端是否接受 `disabled`）。

能关思考的模型（`glm-5.2`）照样有档位表；恒思考的模型（`kimi-k3`）档位表只有 3 档。
两个字段各自独立取值，不存在函数依赖。

### 为什么「族级不变量」这个替代方向成立

`o-series` 是注册表里唯一「族 = 恒思考」的封闭集合（5 个模型全部不接受关闭思考，
`openai-reasoning-models.md:51`）。所以只在它身上做「族内一致性」断言：
同族模型里漏标 `thinkingMode` 会被立刻抓住，且不会误判混合族。
`glm-openai`（17 条里 3 条恒思考）与 `grok-openai`（6 条里 3 条）都是混合族，
不能立这条 —— 这也说明「族级」不是普适判据，只能用在封闭集合上。

## 拿什么证明它生效了

直接 import 生产注册表跑探针（不靠读文档），确认反例真实存在：

```ts
// bun /tmp/probe-registry.ts
total always-on = 17
有 mode 没 values: 无
有 values 但 mode 不是 always-on: 共 4 条
  glm-5.2 (mode=undefined)
  grok-4.3 (mode=undefined)
  grok-build-0.1 (mode=undefined)
  grok-4.20-0309-reasoning (mode=undefined)
```

若双向恒等式成立，这 4 行应当是空集；实测非空且全部合法，故否决。
