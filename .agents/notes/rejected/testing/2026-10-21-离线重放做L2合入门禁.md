# 否决用「367 会话离线重放」作为 L2 的合入门禁

## 决定了什么

L2 的合入门禁是**单测 + 变异自证**，加上线上影子期的 `StallEscalation` 事件；离线重放只作为**参考数据**写进 Agent Note，不进门禁。来源：评估报告 §5 决策 2。

## 放弃了什么（以及为什么不选）

- **离线重放做门禁**，两个前提都不成立：
  1. 重建不出来：轨迹里 edit 只存 old/new 片段、没有全文件内容，bash 改的文件连片段都没有，2a 依赖的工作区 hash 离线算不出。实际做参考重放时只能把「每次成功 edit」当「一个新状态」，这会把真实回退也算进展，**触发数只是下界**。
  2. 负样本不足：本机 370 个有 events 的会话里 ≥200 次 API 的只有 5 个，其余 365 个都是短会话；「零触发 L2」对短会话几乎恒成立，证明不了长任务不被误伤，形同恒绿门禁。
- **「埋点一版本质上是拖延」的原论证**：它建立在「离线重放现在就能给分母」上，这个前提被证伪，论证撤回。影子期是拿到长任务误伤率的唯一途径。
- 实际效果印证了第二点：这次做参考重放时，**唯一的误判（`57de4f89`，CI 轮询）正好出现在 ≥200 次 API 的稀少样本里**，365 个短会话没有任何一个命中 L2。如果拿「短会话零触发 L2」当门禁，这个误判会被直接放过。

## 拿什么证明它生效了

（rejected 记录。）依据是重放本身：370 会话中 <50 次 API 的 293 个均无触发、50–199 的 72 个均无 L2（6 个仅触发 L1），而 ≥200 次的 5 个里 2 个触发 L2 影子（1 真 1 误）。数据与方法见 `implemented/feature/2026-10-21-停滞升级阶梯L1L2影子与收尾闸门联动.md`。
