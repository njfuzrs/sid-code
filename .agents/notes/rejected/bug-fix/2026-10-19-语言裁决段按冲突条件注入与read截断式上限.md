# 否决：语言裁决段按「是否冲突」注入 / read 超限截断 / 上限按窗口缩放 / 不存在时全仓搜

配套的已落地方案见 `implemented/bug-fix/2026-10-19-read体量上限与glob路径基准与语言段文案.md`。

## 决定了什么

以下五个方案都在排查会话 `20261018-224823-dbc19982` 时提出过，全部不做。

## 放弃了什么（以及为什么不选）

1. **语言段只在「设置语言与 CLAUDE.md 语言条款冲突」时注入**
   - 判断冲突只能正则识别 CLAUDE.md 正文里的「中文 / English」——自由文本，误判两头都有。
   - 退化版「只在 en/auto 注入，zh 不注入」漏掉真实场景：英文 CLAUDE.md 的开源仓库 + 显式 `/language zh`
     的用户。少了裁决段，回复会被压回英文，等于把 P0-4（`/language en` 被中文 CLAUDE.md 压回）反方向重开。
   - 复读问题已改为从文案去诱因处理，不动注入条件。
2. **read 超过 token 上限时截断而非报错**：CC `FileReadTool/limits.ts` 注释记录 #21841 实测——
   截断后工具错误率降了，平均 token 反而升高（截断塞满上限，报错约 100 字节）。
3. **read 上限按模型上下文窗口比例缩放**：本次正是 1M 窗口模型一次吞下约 4.8 万 token 的生成文件；
   窗口大不等于这次读取有价值。固定上限 + 环境变量覆盖。
4. **read 报「文件不存在」时在仓库里按文件名全局搜索给出真实位置**：命中率高，但每次错误路径都要起 rg
   子进程，cwd 是 `~` 等大目录时慢；必须再接一遍 deny 规则，否则会把被隐藏的文件路径泄露给模型。
   CC 只做 cwd 内的轻量建议。改为让 glob 直接给出可用路径 + 纠错建议先验证存在性。
5. **对 MiniMax-M3 单独处理（去掉裁决段或换文案）**：违反「不按模型名硬编码分级」的约定。
   基线里只有它复读，但修法必须对所有模型一致。

## 拿什么证明它生效了

否决依据：CC 源码（`tools/FileReadTool/limits.ts` 注释、`utils/file.ts suggestPathUnderCwd`、
`utils/path.ts toRelativePath`），以及 `packages/core/tests/config/language-preference.test.ts` 锁定的
P0-4 语义（en + 中文 CLAUDE.md 时必须注入且位置在 CLAUDE.md 之后），本 PR 未改这些用例的行为断言。
