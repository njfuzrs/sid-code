# 不把 `gh api` 放进 bash 只读白名单

## 决定了什么

`gh api` 一律判非只读，包括看起来是 GET 的 `gh api repos/o/r`。它照常落到权限判定，用户需要免确认时自己配 allow 规则。

## 放弃了什么（以及为什么不选）

候选是「解析 `-X/--method`，GET 且不带 `-f/-F/--field/--raw-field/--input` 时判只读」。否决理由：

- `gh api` 的方法不是只看 `-X`。带任何一个 `-f/-F/--input` 时，它会**隐式从 GET 变成 POST**。解析器要同时认全 `-X` 的各种写法（`-XPOST`、`--method=POST`）、全部字段参数的长短形态，漏一个就把写操作判成只读。
- 判成只读的后果不只是免确认：只读命令可以并发执行（`isConcurrencySafe`），写操作会和别的工具调用并行跑。
- 收益很小：被评会话 ce7ea52e 里的 gh 调用都是 `issue view` / `pr list` 这类高层子命令，PR B2 已经覆盖。

## 拿什么证明它生效了

`packages/core/tests/tool/gh-readonly.test.ts` 的「gh api 不进白名单（GET 形态也不放行）」锁住三种形态。变异自证：往白名单加 `api` 后该用例变红。
