# Harbor 评测的四处仪器偏差修掉了，外加一条「自报成功却 0 分」判据

## 决定了什么

第十棒（`02-Harbor接入方案设计.md` §20）用 $0 的本地分析挖出两个新缺陷、
并留了两处三棒未动的缺口。本次把四条全部修掉，**每条都配变异自证**。

**① `tool_use_without_result` 在 max_turns 题上是假阳性（§20.3）**
`packages/core/src/trace/digest.ts`：新增 `sawObservationAfterOrphan` 追踪孤儿是否
只出现在轨迹**尾部**。`exit_status=="max_turns" && trailingOnly` 时，
L0 严重度 `high → low`、措辞改成「结果因撞上 maxTurns 被丢弃（已执行）」，
且 **L1 `hypothesis_crash_or_violation` 整条不发**。

⚠️ 只降 L0 严重度、留着 L1 假设是错的修法（交接文档点名的坑）：那条假设自己的证伪条件
（"它是末次调用且其后正在等模型响应"）在这里**已被数据满足**，成立的证伪条件应当推翻假设，
而不是让同一个错结论换个层级继续误导排查。

**② P1-1 强制总结轮整轮不进任何仪器（§20.4）**
`packages/core/src/query/loop.ts`：该轮走 `deps.sendWithRetry/processStream`，但它在
`while` 循环**之外**，于是不经过循环内的 `BeforeModel`/`AfterModel` 发射点。
根因链已回源码核实：`collector.handleAfterModel`（`collector.ts:1114`）`!this.currentPair`
即 early-return，而 token 累加在它内部（`:1228`）——于是 **token / 成本 / `API N 次`
三处同时漏同一轮**。补发两个 hook + `sessionState.updateUsage`，走与循环内完全相同的入账路径。

- `turn_index` 用 `turnCount + 1` 而非复用 `maxTurns`：复用正是「一个 index 出现两次
  `first_content`」的成因，按 index 聚合 TTFT 会把两次不同调用叠在一格，而这一轮
  恰落在 P95/P99 尾部。`setSseDumpContext` 同步同口径。
- 刻意**不检查** hook 的 blocking 返回值：已在收尾路径上，按循环内那套 `return` 掉
  会跳过 `max_turns` yield 与 `emitTurnCompleteHere()` —— 用一个观测点换掉两个收尾信号。
- 该轮失败此前**只有一行 warn**，现落 `errors.jsonl`（`phase:"stream"`, `index:maxTurns+1`）。

⚠️ 偏差**有方向**：只有撞满上限的题才有 P1-1 轮，而那正是最贵的一批
（实测一道 $3.54 的题漏掉 `cache_read=122594`），所以「更省」曲线是**系统性偏低**。

**③ 「自报成功却 0 分」判据（三棒未动）**
`evals/external-benchmarks/harbor/verifier_health.py` 新增 `self_reported_success()`
（判据 `sid_subtype=="success" && reward==0.0`），两个消费脚本同时接上。

⚠️ **它不是排除规则，方向恰好相反** —— 这类是最该计分的失败。照 §13.2 字面排除会复算出
0.111 而真实基线 0.100，白送的正是最该扣的那一分。函数只负责让它在表里自己站出来。
实测 r4 命中 **2/9**（`configure-git-webserver` / `polyglot-c-py`），
且**分母仍 9/10、均值仍 0.444** —— 证明它没进 `excluded()`。

**④ success 路径缺 `num_turns_without_model_interaction`（§20.5）**
该键此前只在错误结果上存在，`success` 压根没有 —— 「正常收尾 + 预算被偷」在
`result.json` 里完全不可见。`types.ts` 的 `done` 事件加字段（**22 处 yield 全部填**，
已核实零遗漏）、`message-converter.ts` 消费、**`schemas.ts` 的 success 变体也加**
（漏了 schema 会被静默剥掉，因为类型是从 schema 推的）、`query-engine.ts` 合成路径填 0。
实测 r4：6 道 success 题该字段全是 `None`，正是这个缺口在真实数据里的样子。

**⑤ digest 接进流程（流程债）**
`run-permission-switch.sh`：跑完自动逐题嚼轨迹落盘到 `runs/$JOB/_digests/`，并附带一次
逐题进度。只读旁路，失败一律不改 `$RUN_RC`——分析步骤炸了不该把评测结果染成失败。
digest 在第九棒就存在而**九棒里零次被跑过**：价值不在工具，在它被真的执行。

## 放弃了什么（以及为什么不选）

- **不抬 40 轮上限**。沿用 §20.7 的结论：解出题最高 27 轮，`chess-best-move` 有
  `entropy_zero`（真空转），抬上限等于买更多空转。先修空转，不抬上限。
- **不把 `self_reported_success` 放进 `excluded()`**。见上，会白送最该扣的分。
  已加一条门禁钉死这个设计决策（断言 `excluded()` 函数体里不出现它）。
- **不为 P1-1 轮另造一份统计口径**。补发既有 hook 而不是新加计数器 —— 本仓教训：
  仓库里已有的口径重实现一遍就是重踩一遍。
- **不用真实数据当判据的唯一验证**。见下方，这是本次最贵的一条。
- **`apiDuration` 填 0 而不猜**。该轮没有 `perfHandle`，宁可缺，不可假。
- **没跑评测**。四条修复都不改判读之外的行为，重跑 10 题要 ~$7；
  本次全部用既有 r4 轨迹做只读验证。**这是本次的诚实边界**。

**⛔ 本次最贵的一条：真实数据让一次变异自证假绿。**
把 `self_reported_success` 的严格 `float(reward)==0.0` 改成 `return not reward`（falsy），
拿真实 r4 跑，**输出一模一样、变异没能翻红** —— 因为 r4 里恰好没有
「`subtype=success` 且 `reward=None`」这种样本。而缺陷是真的：falsy 会把
「verifier 压根没判分」也算成「agent 自报喜」，两者处置完全相反。

于是补了 `tests/eval/harbor-agent-contract.test.ts` 的 **L1c 行为层**
（`verifier_health.py` 纯 stdlib，可直接 import，属 L1、CI 上真的在跑）：
7 种形态的合成样本 + 3 种错误取数形状。再跑同一个变异 → **当场变红**，
报「自报成功 + reward=None：期望 false，实得 true」。

**教训**：真实数据只能证明判据在**它覆盖到的形态**上对；缺失的形态要靠合成样本补，
否则变异自证会假绿 —— 而假绿的变异自证比没做更坏，它让人以为验证过了。

**⛔ 第二条：写完 shell 只做 `bash -n` 等于没验。**
新加的 digest 步骤语法检查通过，**真跑却暴露我自己两个 bug**：
① `grep -c` 无匹配时**既打印 0 又 exit 1**，`|| echo 0` 于是补出第二个 0，
输出成了「高危 0(换行)0 条」（4/9 题都这样）；
② 判据写成 `[ ! -d .../sessions ]`，而 `regex-log` 的 `sessions/` **建出来了但是空的**，
于是跳不过去、digest rc=1，一个**预期内的空轨迹**被报成 `⚠️ rc≠0`（假红）。
改用 `compgen -G` 判「有没有会话子目录」+ `|| true` 兜退出码后复跑：9 跑成 / 1 跳过。

**⛔ 第三条：我的改动打红了一条无关门禁，而它暴露那条门禁本来就是空的。**
22 处 `yield done` 加字段后被 oxfmt 拆成多行，
`negative-yield-defense-audit-fixes.test.ts` 里写死单行的
`indexOf('yield { kind: "done"')` 于是找不到、当场变红 —— **而被测的代码顺序压根没变**。
改成容忍换行时顺手做了变异自证：把 terminate 埋点整块挪到 `return;` **之后**
（正是那条门禁要拦的回归），**它照样通过**。原因是无界搜索 —— 文件里有 22 处
`yield done`，断言退化成「文件里存在 yield done」，恒为真。
改为锚在该分支唯一的告警文案上，同一个变异**当场变红**。

一条会被无关格式化打红的门禁，训练出来的反应是「去改门禁让它闭嘴」而不是去看代码；
而这一条在闭嘴之前，已经空了不知多久。
