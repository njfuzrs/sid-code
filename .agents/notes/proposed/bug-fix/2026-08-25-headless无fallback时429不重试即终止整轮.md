# headless + 无备用模型时，一次 429 就终止整轮 —— 11 次重试预算一次没用

## 决定了什么

**还没修，这份 Note 是交接。** 记录一个在 SWE-bench 跑分中撞出来的
**主循环 bug**（不在 evals/ 里）：headless（`-p` / CI）+ 只配一个模型时，
网关返回 429 会**直接终止整轮**，而不是退避重试。

根因链：

1. `packages/cli/src/app.ts:1973` —— 无交互通道（headless/SDK/CI）
   → 直接走 `autoFallback()`，不弹窗。
2. `autoFallback()`（`app.ts:1960`）在没有 `defaultFallbackModel` 时
   返回 `{action: "abort"}`。
3. abort 被上层当成「用户选择不切换」→ 打出
   `用户/钩子选择不切换，终止本轮` → `fatal_error` → 进程 exit=1。

**问题不是「没配备用模型」**（单模型在评测里是**正确**配置 ——
换模型就换了被测对象），而是 **2→3 这一跳把「限流」当成了「模型不可用」**：

- 429 = 稍后再试就好。`fallback.ts:1494` 的注释自己写着
  「各路退避重试本身就是正确应对（换个时刻可能就有容量了）」。
- fallback 机制解决的是「这个模型不行了，换一个」。

限流不该触发换模型决策，该触发退避重试。**没有备用模型时更不该因此终止** ——
应该是「退避、重试、直到预算用尽」。

## 放弃了什么（以及为什么不选）

**① 否决「给评测容器配一个备用模型」。**
能让那两条跑完，但是掩盖：
- 换模型就换了被测对象，两轮分数不可比（D17 必控变量表）；
- 把 bug 埋掉 —— 429 是外部条件随时会再来，而「一次 429 就终止」
  是我们自己的行为，在任何网关上都会复现；
- 影响面远超评测：任何用户在 `-p` / CI + 单模型 + 网关限流下都会撞到，
  而那正是 CI 最常见的配置。

**② 否决「把 autoFallback 的 abort 改成静默继续」。**
那会让真正的「模型不可用」也被吞掉。要分的是**错误类别**
（429/529 限流过载 vs 401/400 终态），不是笼统放宽 abort。

**③ 否决「只在 headless 分支上打补丁」。**
这已经是第二次了（见下），只补当前入口会有第三次。
修的时候要把「还有哪些入口会走到 abort 而错过退避」列全。

## 拿什么证明它生效了

**⚠️ 修复尚未实施，所以这一段是「问题存在」的证据，不是「修好了」的证据。**

实测样本：`runs/smoke-8/` 两条实例（`pydata__xarray-6461`、
`pytest-dev__pytest-10081`），agent.log 里致命错误前的序列是：

```
[FALLBACK]  流式阶段尝试 1/11                          ← 有 11 次预算
[LLM:ANTHROPIC] 429 当前分组上游负载已饱和，请稍后再试
[FALLBACK]  无交互通道，降级为自动切换默认 fallback
[FALLBACK]  用户/钩子选择不切换，终止本轮                ← 第 1 次就放弃
[ENGINE]    queryLoop 异常，封装为 fatal_error
```

机械判据（两条一致，**这是最硬的一条**）：

| | xarray-6461 | pytest-10081 |
| --- | --- | --- |
| 发出的流式请求数 | 19 | 13 |
| 出现过的尝试编号 | **只有 `1/11`** | **只有 `1/11`** |
| 429 次数 | 3 | 3 |
| 「终止本轮」 | 1 | 1 |

**19 次请求里重试计数器从没涨到 2** —— 即 429 根本没进退避重试路径。
如果退避生效，日志里应该出现 `尝试 2/11`、`3/11`。

## ⚠️ 这是有档案的同型复发

`packages/core/src/llm/fallback.ts:2135` 的注释：

> 事故 `20260730-183103-5e334145`：**一次 429 即失败**
> （子代理走 provider 直连时完全没有退避可用）

那次修的是**子代理路径**，把退避抽到 `retry-backoff.ts` 共用。
**headless + 无 fallback 这条路径没被覆盖** ——
同一个「一次 429 即失败」换了个入口又长出来一次。

## 修的时候必须带上什么

1. **单测覆盖「headless + 无 fallback + 429」这个组合**，
   并做变异自证：把重试改回立即 abort，断言测试转红。
   （没有变异自证的断言说不清它拦的是真行为还是恒真表达式。）
2. **把所有会走到 `abort` 的入口列全**，逐个确认限流类错误是否绕过了退避。
   这是防第三次复发的唯一做法。
3. 修完可用 `runs/smoke-8/` 那两条实例复跑验证（题目与环境都还在）。
