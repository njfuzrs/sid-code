# 接入 Harbor 评测底座：拿一个类换 33 个对照 agent，代价是题目来源在外部

## 决定了什么

新建 `evals/external-benchmarks/harbor/`，让 sid-code 能作为自定义 installed agent
在 Harbor 的任务容器里跑，从而与 Harbor 内置的 33 个 agent（claude-code / codex /
mini-swe-agent / aider …）做**同题、同模型、同容器、同 verifier** 的对照。

**服务的北极星方向是「更准」。** `CLAUDE.md` 把「更准」定义为「**同一个模型**，
在 sid-code 里返工更少」，并明确主语是 harness 不是模型 —— 这需要一个「控制模型、
只换 harness」的对照实验（换 scaffold 摆动 15–25pp ≫ 换模型 2–15pp，所以这是唯一可归因的形态）。
此前做这件事要**手工搭对照 + 自己守住五个必控变量**；在 Harbor 里容器 / verifier /
超时 / 提示模板天然同源，**变量控制从「靠纪律」变成「靠底座」**。

七个具体决定：

1. **安装模式固定为 binary**：上传 `scripts/build-branch-artifact.sh` 交叉编译的 linux
   自包含二进制。install 阶段**零网络** → `no-network` 类任务能干净 setup，
   不需要 `ensure_system_dependencies`，也不会因基础镜像是 Alpine/musl 而失败，arm64 天然可用。
2. **二进制来源三级优先级，且第三级报错而非回落**：`SID_HARBOR_BINARY_{ARM64,X64}` 显式点名
   → `dist/branch-builds/*-<当前 commit12>/sid-code` 自动发现 → **报错并打印构建命令**。
   commit 优先从**产物字节**读回（复用既有 `scripts/artifact-identity.ts`，不自己写嗅探正则），
   读不到才退化到宿主 HEAD 并如实标 `commit_source: host-head-fallback`。
3. **`--output-format stream-json`，不是 `json`**：两者是**分叉的两条实现**
   （`app.ts:5833` 的 early-return 是分界线），只有 stream-json 的 result 事件带
   `total_cost_usd` / `num_turns` / `subtype`。
4. **认证不进容器**：`settings.json` 的 `baseURL` 指向宿主网关，容器里只有占位 token
   `no-auth-dummy`（不能用 `__xxx__` 形态 —— sid-code 有 `TEMPLATE_PLACEHOLDER_PATTERN` 校验）。
   放通靠 `--allow-agent-host`，它只在 `agent.run()` 期间生效，verifier 阶段网关不可达 ——
   这正是我们想要的。
5. **`SID_CONFIG_DIR` 指向 `environment_logs_dir/sid-home`**（用实例属性，不硬编码 `/logs/agent`）。
   目的是把**完整轨迹**带回宿主：`AgentContext` 只有 5 个字段，
   而 TTFT / 缓存命中 / retry 白烧 / compaction 全在 `session.traj` 里。
   Harbor 侧只存 `sid_session_id` 作接缝。
6. **`capabilities` 首版全 False**，声明式 `CLI_FLAGS` 只开三个旋钮
   （`max_turns` / `permission_mode` / `max_budget_usd`）。
7. **门禁分两层**（`tests/eval/harbor-agent-contract.test.ts`）：L1 用 stdlib `ast` 静态解析、
   **不需要 harbor 因此在 CI 上真的在跑**；L2 真 import，装了 harbor 才跑。

**A0 前置条件已由源码回答**（原设计把它列为「结论可能否决整个方案」的前置调研）：
`HARBOR_TELEMETRY=0` 关遥测（默认**开**，发 PostHog）；Hub 上传**严格 opt-in**，
`--upload` 默认 off 且 `--public`/`--share-*`/`--org` 缺它一律硬报错。
→ A0 从 blocker 降级为「README 固化」，且 `HARBOR_TELEMETRY=0` 写进**每条命令的前缀**
而不是「注意事项」——写在注意事项里没人看。

**它牺牲了什么（自检第 3 问）**：**数据主权的一部分**。评测题目与容器镜像从公网 registry 拉。
轨迹仍全部落在我们自己的挂载目录，但「题目来源在外部」是事实，不掩饰。
换来的是「几十个 benchmark + 33 个对照 agent」，这个交换可接受。

## 放弃了什么（以及为什么不选）

**这一段是本 Note 最贵的部分。** 下面每条都被认真考虑过并否决 ——
不落盘的话，下一个 agent 明天会重新提议同一件事，而论证要整套重做（已经发生过）。

- **source / local / published 三种安装模式**（参照实现 oh-my-pi 有四种）。
  否决：local/published 要在容器里装 bun 再 `bun install` → 触发 apt-get + 网络，
  与 `no-network` 任务**直接冲突**；source 要 bind-mount 一棵 linux `node_modules`，
  oh-my-pi 需要它是因为它有按平台匹配的 Rust natives，**我们没有这个约束**。
  ⚠️ 代价必须承认：binary 模式下**改一行 TS 就要重新交叉编译**，
  放弃了 source 模式「host TS edits 下一个 trial 直接生效」的迭代速度。
  补偿是开发期用 `-t hello-world/hello-world` 单题冒烟（一次几十秒），而不是靠免编译。

- **`MODEL_CONNECTION = ModelConnectionSpec(...)`**（Harbor 的官方声明式认证注入）。
  否决：**它的作用恰恰是把 key 从宿主环境解析出来、注入容器 env**，
  而容器是不可信执行环境（跑着 benchmark 的任意代码）。与本方案的安全前提直接冲突。
  L1 门禁把「`MODEL_CONNECTION` 不得出现」做成了机械断言，防的就是有人图省事加回来。
  ⚠️ 但要说破**剩余风险**：我们防住了 key 泄露，**没防住被薅额度** ——
  容器能访问那个网关。对策在网关侧（per-trial 预算上限），agent 侧的补偿是 `--max-budget-usd`。

- **`--output-format json`**。否决：那条路径的 `usage` 来自 `getTotalUsage()`，**不含 cost**。
  ⚠️ 这条是复核中**推翻初稿结论**得来的：初稿写「cost 必须从轨迹文件取，因为 stdout 的 JSON 没有 cost」
  —— 对 `json` 成立，但对 `stream-json` 是错的。教训值得留：
  **同一个 CLI 的两种输出格式可以是两条独立实现**，读了一条就断言「无头输出没有 cost」是过度概括。

- **pytest / 任何 Python 测试栈**。否决：仓库里**没有任何 Python 测试基础设施**
  （无 `pytest.ini`、无根 `pyproject.toml`、`package.json`/`Makefile` 里零 pytest 引用），
  五道门禁一道都不认 `.py`。写「加 pytest」等于在这个 PR 里**夹带「引入 Python 测试栈」
  这个独立决策**。改为走现有 `bun test` 的一条 TS 测试：零新栈、直接进现有门禁。

- **「harbor 缺失即整体 skip」的单层门禁**（原设计 §9.3 的形态，它自己也承认这点）。
  否决：CI 不装 Python 依赖 → **CI 上永远 skip → 门禁形同不存在，而 PR 页面一片绿**。
  本仓有过同型先例：**防线自己成了它当初要消灭的死功能**。
  改为两层，L1 只依赖 `python3`（macOS / GitHub runner 自带），在 CI 上真的在跑。

- **`prompt-template.j2`**（原设计的文件树里有它）。否决：对照实验的裁决是
  **所有 agent 一律不传模板**（`--prompt-template-path` 是按 agent 传的，
  给我们传、给 claude-code 不传，则第一必控变量就破了**而两边都跑得很成功**）。
  而 `../swe-bench/prompt-v1.txt` 是为 SWE-bench 调的，拿到 Terminal-Bench 未必合适 ——
  **一致性比「我们的模板更好」更重要**。建一个没人该用的文件 = 引诱下一个人破掉这条。

- **在 Harbor 侧重算 TTFT / 缓存命中 / retry 等我们已有的指标**。否决：会造**第二个事实源**。
  `sid_session_id` 是接缝，深度指标一律回 sid-code 自己的 digest 取。
  这是记忆里同一个错误（「没用既有口径、自己另找源」）的第四次，认出来就别再踩。
  同理 `_read_artifact_identity` 复用 `scripts/artifact-identity.ts` 而不自己写嗅探正则。

- **迁移 `grade.ts`（1070 行）/ `preflight.ts`（923 行）**。否决：Harbor verifier 在容器内跑
  `/tests/test.sh` 并读 `reward.{txt,json}`，**agent 既不产出 patch 也不参与判分** ——
  这两块在 Harbor 路径上整块不存在。这是接入的最大一笔净收益。
  ⚠️ 但**不能盲信** verifier：见下面 A9 的双向对照。

- **让自建 SWE-bench 链路退役**，或**拿两条链路的分数互比**。双双否决：
  自建链路是**深度**（能取任意内部字段），Harbor 是**广度 + 可比性**（有对照 agent），
  职责不同。而 Harbor 的 `swebench-verified` adapter 与我们的 `verified-subset.yaml`
  子集不同、提示模板不同、超时不同、判分实现不同 —— **跨底座比分数是纯噪声**。
  两条各出自己的曲线，不做加权、不做平均、不做「哪个更准」的裁决。

- **首版声明 `resume` / `handoff` / `atif`**。否决：sid-code 确实有 `--resume`，
  但恢复路径有实测缺口。**声明 True 而实际不可靠，会让 `--resume-trajectory` 的多步任务
  静默走错分支**（不报错的那类）。ATIF 是写一个轨迹双向转换器，独立 PR 的量。
  这三项各自是后续独立 PR：`resume` → `handoff` → （ATIF 不排期，
  它的价值取决于「是否真要做跨 agent 轨迹比对」，**这个前提还没验证**）。

- **给 `--dangerously-skip-permissions` 留一个旋钮**。否决：它会**关掉我们想测的那层防线**，
  而且 sid-code 侧本就有早退拦截。L1 门禁把它做成了机械断言。
  相关：`--permission-mode acceptEdits` 不是拍的 —— 自建链路实测在此模式下**仍有 113 次权限拒绝**，
  说明它不等于全放开，评测里正应该观察这层的触发情况。

- **把 `--output-format` 做成声明式旋钮**。否决：改成 `json` 后 `populate_context_post_run`
  就解析不了，而形态是**成本静默全 None**。把实现细节做成可调是给自己埋坑。

## 拿什么证明它生效了

**已经跑过、有输出的（本 PR 内）**：

```
bun test ./tests/eval/harbor-agent-contract.test.ts
  → 14 pass / 1 skip / 0 fail（skip 是 L2：本机未装 harbor，实测 ModuleNotFoundError）
```

**三条变异自证**（`CLAUDE.md`：新增门禁必做变异自证）。在真源文件上逐条改坏、
跑测试、还原，每次都**只红对应那一条**：

| 变异 | 实际翻红的断言 |
| --- | --- |
| `@with_prompt_template` / `@override` 换序 | `run 的 @with_prompt_template 在 @override 之上` → 1 fail |
| `"stream-json"` → `"json"` | `--output-format 的取值是 stream-json，不是 json` → 1 fail |
| `def name()` → `def name_typo()` | `Harbor 要求的四个成员齐备` → 1 fail |

还原后回到 14 pass / 0 fail，`git status` 干净（只剩本次新增文件）。

> 变异自证过程中发现并修掉了一个**测试自己的**缺陷：最初用「整段删掉 `name()`」做变异，
> 但那会留下悬空的 `@staticmethod`/`@override` → fixture 变成 SyntaxError → checker 报错了，
> **但报错原因指错了地方**（语法坏了 ≠ 成员缺失）。改用「改名」精确命中那条判据，
> 并另加一条断言把「语法坏 → 必须非 0 退出」单独锁死。

**门禁边界如实标注**：L1（静态、只要 `python3`）在 CI 上真的生效；
L2（真 import）在 CI 上 skip。**不假装仓库门禁完整覆盖了这份 Python 代码。**

**还没证明、必须实测的**（需要 Docker + 装 harbor + 网关就位，**不在本 PR 内打勾**，
清单与判据在 README 的「验收清单」）：

- **A1** `no-network` 任务能否被 `--allow-agent-host` 放通 —— `no-network` 与 `allowlist`
  是互斥模式，很可能 merge 不进去。若不通 → 该类任务排除，且**排除数量必须 log 出来**
  （静默跳过 = 分母悄悄变小 = 分数虚高）。
- **A2** `provider/model` ↔ 渠道别名映射：要看轨迹里**实际发出的 wire model**，
  不是看命令行参数 —— 配错 base_url 会 404 后**静默 fallback**。
- **A7** `cost_usd` 非 0 且非 null。最容易假过的一条：cost 为 0 时 trial 照样成功、
  reward 照样有值。（代码侧的对策已就位：拿不到时**留 None + 标 `sid_cost_source: missing`**，
  绝不填 0 —— 填 0 会让「没采到」伪装成「没花钱」。）
- **A9** oracle 满分 / nop 零分**双向**对照。单向拦不住：verifier 恒返 0 会把
  「链路坏了」伪装成「没解出来」（两者在数据上不可区分），而恒返 1 时 oracle 对照防不住，
  要靠 nop 才能发现「任务初态就是通的」。
- **A10** 三 agent 对照产出三份 `results.json`。

**最终判据是 A11**：**Harbor 上的数据驱动了一次真实的 harness 优化决策**
（一份 Note 记「因为看到 X 数据，所以改了 Y」）。
它无法在本 PR 合入时打勾 —— 在那之前这个接入的状态如实是**「已建成，未验证有用」**。
这一条不是形式主义：本仓的验收判据是「真实会话里被触发过」而不是「build 过 + 单测过」，
因为**防线自己变成死功能这件事已经发生过一次**。
