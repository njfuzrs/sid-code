# 新底座选区引擎纯逻辑（B9 / T6.2a）

## 决定了什么

规则全部来自对 legacy 的黑盒探针，没读旧底座 `selection.ts`（D-5）。探针脚本与原始结果备份在 `~/Backups/sid-code-t67-probe-results-20261008/T6.2a/`。

- **新文件 `packages/tui/src/selection.ts`**：纯函数加一个状态对象，不碰终端、不持有定时器，鼠标事件（带时间戳）和屏幕缓冲都由调用方传入。
  - 连击：两次按下间隔 < 500ms（右开），且横纵坐标各差 ≤ 1 格（与上一次**按下**比）。拖动不打断连击计数，四击及以上仍是选行。
  - 字符模式：按下后要拖离锚点格，选区才成立。起点落在宽字符右半格时从下一格开始；终点落在宽字符左半格时包含整个字。
  - 词边界分三类：空白、词字符（字母 / 数字 / 组合符号，加 `_ - . / ~ + \`）、其余标点。同类相邻的连成一段。NBSP 与全角空格各自成段，不和普通空格连在一起。
  - 往回拖时，词模式 / 行模式保留锚点那个词或那行的尾端。行模式的焦点行夹到屏幕内，词模式和字符模式不夹，屏幕外的行复制出来是空行。
  - 复制：硬换行的行去掉行尾空白，行与行之间用 `\n`；软换行的行只取到内容结束的那一列，与下一行直接拼接。
  - 只认 SGR 左键。中键、右键、无键移动、滚轮、X10 编码都不建选区，也不清选区。
- **`Screen.wrapEnd`**：每行一个软换行记录，由 `render-node-to-output` 在换行时逐行标记，`output.ts` 写入，`clipToViewport` 跟着复制。只记软换行，硬换行的写入不清这条记录（并排两列时，右列的文本不能把左列的折行记录盖掉）。
- **next 实例上补齐 `setSelectionBgColor` / `copySelectionNoClear` / `clearTextSelection`**，X7 在 next 上转绿。鼠标字节接入、高亮绘制、OSC52 复制留给 T6.2b。

## 放弃了什么

- **选区跟随内容滚动**：探针显示 legacy 的选区是屏幕坐标。重渲染后内容挪动，选区不跟着移（`scroll-down-1` 复制出的是新内容）。`captureScrolledRows` / `shiftSelectionForScroll` 只作用于 ScrollBox 滚动，而端口驱动不了 ScrollBox，所以这部分没做，等 T6.2b / T6.2c 接上真实滚动路径时再对拍。
- **把探针临界值放进向量**：离 500ms 阈值只差几毫秒的用例（495 / 500 / 505）不进向量，因为生成器的定时器抖动会让结果时有时无。阈值改由单测里的精确用例钉住。
- **emoji 行的高亮位置**：`@xterm/headless` 只带 Unicode 6 宽度表，把 emoji 算成 1 列，同一行后面的高亮位置全都偏移。这些行记成 `blindRows`，只比文本、不比高亮（294 条里有 123 条带 blind 行）。

## 拿什么证明它生效了

- `bun run tui:selection-vectors` 从 legacy 生成 294 条向量（`selection-vectors.json`），`packages/tui/tests/selection.test.ts` 用新底座布局加引擎逐条对拍，298/298 通过。
- 变异自证 5 处全红：连击容差改为 2、`/` 移出词字符、软换行不截到内容结束、四击退回字符模式、宽字符右半格起点不右移。
- `render-instance.test.tsx`（X7）在 next 上 5/5 通过。
