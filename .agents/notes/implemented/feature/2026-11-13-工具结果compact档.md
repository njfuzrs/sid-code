# 工具结果新增 compact 档：读写搜索类默认折成零行正文，正文不丢、ctrl+o 可展开

## 决定了什么

`resultDisplayMode` 从两档（`hidden` / `summary`）扩成三档，新增 `"compact"`：

- **语义**：保留正文（`resultDisplay.content` **不置空**），默认折叠成零行、标题行给结果规模
  （「54 行输出」「12 个结果」），`ctrl+o` 与普通工具走同一套 `expandLevel` 阶梯展开。
  与 `summary` 的分界是「正文对用户有没有价值」——summary 的正文是给模型读的提示词，
  compact 的正文是文件内容 / 搜索结果 / 命令输出。
- **声明方**：`read` / `grep` / `glob` 用常量；`bash` 用函数形态**看执行结果**——
  只有 `meta.exitCode === 0` 才折叠。非零退出（含 `grep` 退出码 1、`gh pr checks` 退出码 8
  这类「非零但不是错误」的）一律原样展示：失败输出是排查第一现场，折起来等于藏故障。
- **函数签名扩一个可选参数**：`resultDisplayMode(input, result?)`，`result` 只带
  `{ output, isError, meta }`（`DisplayModeResultView`）。两处执行器调用点同步传入。
  `bash` 的 `meta.exitCode` 在 `executeCommand` 的**唯一汇合点**（`Promise.race` 之后）写入，
  不在六七个 return 处逐个补——早退路径（缺参数、cwd 不存在、转后台）没有退出码，
  消费侧据此回退到原样展示。
- **少量行降级放在数据层**（`history-adapter.ts` 的 `buildCompletedToolCall`）：
  `compact` 档按**有效行数**（trim 后按换行切分）判，≤ `COMPACT_MAX_INLINE_LINES`（5）行时
  去掉档位、按普通卡片画。「未找到匹配的内容」这类一句话结论不会被折成误导的「1 行输出」；
  `glob` 匹配 3 个文件、`git log --oneline` 5 条这类一眼看完的结果同理（阈值是第二轮 review
  从 1 行调上来的，理由见下）。

起点是「TUI 主屏历史被截断」：主屏模式下历史在终端 scrollback 里，条数受终端设置限制；
工具卡片一次铺几十行会把可用行数吃掉。R1（本 PR）+ R2（官网写 scrollback 上限怎么调）
合起来才解决问题——方案文档实测 R1 让大会话行数降 26%–43%，仍有过半超 1000 行默认上限。

## 放弃了什么（以及为什么不选）

- **不把 compact 塞进 `suppressBody`**（= 复用 summary 的正文置空）。这是最容易写错、
  且**错了无法补救**的一条：正文在数据层丢了，渲染层再想支持 ctrl+o 也无从恢复。
  审计测试里有一条断言专门锁它。
- **不给 `bash` 加「执行中占位」来抵消收缩**。成功命令完成时卡片从「命令行 + 实时输出」
  收到 compact 一行，帧净矮 ~3 行 → 多一次整帧重画。本可以留空白占住高度让它不变矮，
  但那等于每次命令白占 3 行，与「省屏幕」的目标直接冲突——折了等于没折。
  选择接受这一次重画：它是**每轮每命令至多一次**的完成事件，不是高频交互
  （打字 / Ctrl+U / 开关补全菜单 / 取消退出提示仍锁 0 次重画），换来每条成功命令长期少占 3 行。
  门禁 `main-screen-shrink-e2e` 的阈值因此从 ≤2 放宽到 ≤3，注释写清了来源与变异自证方法。
- **不给错误结果留任何折叠可能**。除了执行器不打印记，`buildCompletedToolCall` 与
  `ToolMessage` 各自再挡一道 `isError`——硬约束 ② 是「错误必须可见」，多一道判据比少一道便宜。
- **不把档位做成 UI 层工具名白名单**。档位由工具在自身定义处自报，审计测试与期望名单双向对账
  （`EXPECTED_COMPACT` + `FUNCTION_FORM_TOOLS` 加 `bash`），新增工具时漏评估会变成 CI 硬错误。
- **不动 `ESC[3J`**（方案文档第一版的 R3，已否决）：整帧重画的机制是重写全部历史，
  去掉 `3J` 会让每次重画都往 scrollback 追加一份重复历史，撞上限更快。

## 第二轮：review 反馈修订（同日，同一 PR）

初版落地后按 `src/ui/CLAUDE.md` 复核，三处该补的都改在本 PR 内：

- **折叠态完全没有展开提示**（L3.3 明文要求「折叠时给摘要 + 可展开提示」）。compact 卡片
  刻意不渲染 `ToolResultDisplay`，因而不登记溢出，`ToolGroupMessage` 那条
  `isExpandable && hasOverflow` 的提示永远不会为它出现。后果不是「占地方」，是**正文还在、
  用户却以为丢了**——典型一轮（read 几个文件 + grep + 成功 bash）屏幕上没有任何 `ctrl+o` 线索。
  修法：`ToolGroupMessage` 按组检测 compact 折叠卡片（`expandLevel === 0` 且非 error 的 success 卡），
  在组尾补一次提示，**复用既有文案** `ctrl+o 展开完整输出`（不新编第二套，L3.3 要求文案统一），
  并按 L4-C 接 `shouldShowHint("toolResultCompactExpand", 3)`：看满 3 次收敛，不长期唠叨。
  - 为什么提示放在**组尾**而不是每张卡片：L3.3 要求「在子区域 / 虚拟列表内不重复显示提示」，
    十张 compact 卡片各带一句提示正好是它要防的形态。
  - 为什么不改成「不折叠」：折叠本身是对的（主屏历史被截断才是要治的病），缺的只是
    「还能展开」这一个信号。
- **降级阈值 1 行太窄**。原判据只挡住「一句话结论」，把「一眼看完」那一整段漏在外面：
  `glob` 3 个文件、`grep` 命中 2 条、`git log --oneline` 5 条都会被折成「N 行输出」，
  文件名 / 命中行反而看不见，还得去按 ctrl+o —— 而 ctrl+o 是**全局**档位，一按整屏所有
  compact 卡片一起展开，代价比省下的那几行大得多。阈值改为 `COMPACT_MAX_INLINE_LINES = 5`
  （一眼看完 → 需要滚动的分界）。
- **审计测试漏扫 `resultDisplayMode: "compact"`（冒号写法）**。原正则只认 `=` 和 `(`，
  对象字面量 / 带类型标注的属性写法两条都不命中 → 该文件被 `continue` 跳过 → 「无遗漏」断言
  看不到它 → **静默假绿**。补上 `:` 分支（`[:=(]`）；可选标记 `resultDisplayMode?:` 由 `?`
  挡住，不会误命中。这条正是审计自身最该防的失效形态，而一条冒号写法就能绕过。
