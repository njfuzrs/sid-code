# 外部来源工具结果加 `<external-content>` 不可信包裹（B14 / HB-13a 第一半）

## 决定了什么

MCP 工具、`ReadMcpResource` / `ListMcpResources`、`web_search` 的结果在**执行器出口**被包成
`<external-content source="…" untrusted="true">`，system prompt 增加一段无条件的「外部内容安全边界」。
只加文本标记，不改任何执行、权限或落盘行为。

- 新增 `packages/core/src/tool/content-provenance.ts`：`resolveContentProvenance`（工具名 + 入参 → 来源闭集）
  与 `wrapExternalContent`。判定表当前三档，`file` 档留空返回 `undefined`。
- `query/tool-executor.ts` 与 `query/run-tool-use.ts` 各在 **return 之前**插一行包裹：位置排在
  `PostToolUse.getUpdatedToolOutput` 替换、hook 追加、编辑提醒、改参告知、状态查询提示全部之后。
- `config/system-prompt.ts` + `config/prompt-sections-en.ts`：新增 `buildExternalContentBoundarySection(En)`，
  在 `buildSubagentResultBoundarySection` 之后**无条件**注入（不加 `tools.some` 守卫，避免 MCP 连上/断开
  让 prompt 前缀抖动击穿 cache）。
- `content-provenance.ts` 保留 `isWithinWorkingDirs` 参数位但 PR-1 不读它：`file` 档（`read` / `read_many` /
  `grep` 的工作区外判定）按方案要等 ⑫ 基线冻结后单开 PR，届时只补分支、不动两处调用点。

## 放弃了什么（以及为什么不选）

- **工具自己包**（在 `MCPTool.execute` / `web_search` / `read` 里各写一份）：PostToolUse 的
  `getUpdatedToolOutput` 是整段替换，标签会被冲掉且现有 hook 测试不会红；`read` 的工具层也拿不到
  `PathValidator`（`LegacyTool.execute` 没有 context 位），判不了工作区内/外。
- **给 `ToolResult` 加 `untrusted` 字段让工具自报**：`tool/bridge.ts` 会把新字段压掉，得同步改 bridge 与
  `FORWARDED_KEYS`；而且判定依据是入参路径而非执行结果，放进 result 语义错位。
- **复用 `meta` 字段**：`meta` 的契约明写「不进模型上下文」，拿它决定进上下文的形态会让下一个读注释的人踩坑。
- **`read` 一律包裹**：用户自己刚写的代码也被标成不可信，与「先读后写」语义打架，还会把 `read.ts` 已有的
  `<system-reminder>` 记忆新鲜度提示包进「不可信内容」。这也是 `file` 档必须等基线实测的原因。
- **`web_fetch` 一起改成 XML 标签**：它已有更强的隔离提炼（正文不进主上下文）+ 降级路径显式标注不可信，
  改成标签会把「已隔离的受控输出」降级到和原始注入文本同一档。
- **本 PR 直接做 `file` 档**：方案 §6 的行为验收要求基线 A/B（通过率与返工率不劣化），⑫ 基线尚未跑，
  现在上没有判据。用户确认本次只做三档、合成一个 PR。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/tool/content-provenance.test.ts`：14 pass。含反漂移哨兵——读
  `website/ref/tools.md`（`--dump-tools` 的真实 registry 产物）核对判定表里的工具名仍存在，
  删/改名会红；`read` / `read_many` / `grep` 断言本 PR 一律 `undefined`（PR-2 的入口）。
- `bun test ./packages/core/tests/query/tool-executor-external-content.test.ts`：9 pass。两侧出口都覆盖，
  最关键一条是 **hook 替换输出后仍然包裹**（标签若写在替换之前会丢且无测试变红）。
- `make build` + `bun run scripts/smoke/run.ts X7-mcp-web-search-wrap`：PASS（0.4s）。用例用 `settings`
  把 search 后端指到用例内 `Bun.serve` 桩（searxng 协议），回放让模型发一次 `web_search`，断言主会话
  JSONL 的 tool_result 含 `<external-content source="web_search" untrusted="true">` 且桩返回的注入原文
  完整留在标签内。
- 变异自证：把 `resolveContentProvenance` 的 `web_search` 分支改成恒 `undefined` →
  `bun run scripts/smoke/mutate.ts X7-mcp-web-search-wrap` 报 KILLED（1/1）。
- 门禁：`bun run typecheck:gate`（62 处存量 / 基线 64，无新增）、`bun run lint`、`bun run format:check`、
  `bun run affected-tests:run`、`bun run docs:gen-reference`（无漂移）全绿。
