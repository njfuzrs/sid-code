# monitor 工具按行事件监控外部状态：等待期前台零请求

## 决定了什么

新增 `monitor` 工具（`packages/core/src/tool/monitor.ts`）与 `local_monitor` 任务类型
（`packages/core/src/task/monitor-task.ts`）：后台脚本的 stdout 每行（经 200ms 批处理）
变成一条 `<task-event>` 通知，进程退出或期限到必有终态回报。模型挂上之后 `end_turn`，
等待期不再前台轮询（事故会话 7dd98bf5 / 9e3a681d 分别轮询 96 / 106 次 `gh pr checks`）。

落地的关键决定：

1. **进程模型**：`stdio: ["ignore", "pipe", "pipe"]`，stdout 由父进程逐行读（切行 →
   200ms 批处理 → 限流 → 通知），stderr 只落 `.output` 不产生事件。与 shell-task 的
   `stdio: [ignore, outFd, outFd]` 刻意不同——两个写者写同一个文件会互相覆盖偏移。
2. **用 `close` 而不是 `exit` 收尾**：Node 的 `exit` 在 stdio 流关闭**之前**触发，
   `printf abc`（无换行）的残行还在 stdout 缓冲里就被丢弃（实测 T-M1-9 变红）。
   `close` 在进程退出且所有流关闭后触发，此时残行与批处理缓冲都能一并投递。
3. **三道限流阀**（突发 10s/40 行直接停、持续 6 条/分钟合并而不丢弃、总量 60 条停）：
   每条通知都会叫醒主循环跑一轮完整请求，刷屏的代价比 TUI 难看大得多；而合并而非丢弃
   是因为 CI 分片结束丢一条就漏一个失败分片。

   > 更正（2026-11-09）：「合并而不丢弃」当时只在 `admit` 的常规路径成立——
   > 退出时持续阀 / 总量阀已满、到期、`task_stop` 三条路径都会把缓冲与暂存行整批丢掉
   > （D2 / D3，实测 R2 / R3）。已由 #688（退出冲刷）与 #690（暂存行窗口冲刷、
   > 四个终态出口统一 `finalizeAndDrain`）修复；现在的契约是「任一终态出口都先冲刷，
   > 且终态冲刷不受限流阀约束」。
4. **权限复用 bash 管线**：`permission/checker.ts` 加 `isCommandSemanticsRequest`
   与 `commandRuleRequest`，把 monitor 的 `command` 按 `bash` 规则名匹配
   （`Bash(gh pr checks:*)` 对它同样生效），审计侧 tool_name 仍是 `monitor`。
5. **TUI 呈现按去重原则**：monitor 进现有后台面板（`[MO]` 行，`N 事件 · 剩 Xm`），
   事件只出现在消息流（`⏺ <description> · <首行>` + `⎿` 折叠），面板**不**显示最新事件。
6. **子代理禁用**：`tool-filter.ts` 的 `ALL_AGENT_DISALLOWED_TOOLS` 加 `monitor`
   ——子代理生命周期短于 monitor 期限，结束后事件无人消费。

## 放弃了什么（以及为什么不选）

- **`ws` 源（WebSocket 监控）**：本场景用不上；Bun 里可用但要单独处理重连、二进制帧、
  代理，放到有真实需求时再做。
- **把 monitor 做成 `local_shell` 的一个 `kind`**：shell 的 60s 静默判据会把 monitor
  判成「不值得等」（它静默恰恰是常态），且 shell 没有硬期限承诺。单列类型让
  `isShellTask` 为假，两套语义不会互相污染。
- **在 harness 里内置 `gh pr checks --watch` 特判**：把具体工具写进内核，等于每接一个
  CI 系统都要改内核。改用通用「stdout 每行一个事件」协议 + 仓内脚本（`scripts/watch-pr-checks.sh`）。
- **持续限流用「丢弃」而不是「合并」**：丢一条就漏一个失败分片，与「沉默不等于成功」
  的设计前提冲突。
- **monitor 行显示「最新事件」**：与正上方的消息流事件行构成同一句话的第二份，
  违反 TUI 去重原则（§5.7.2）。
- **让模型自己写 `key` 参数做 subject 匹配**：`schedule_wakeup` 已有「模型管理 key
  已被否决」的记录（#642 §6.1），改为从命令里抽取已知实体（`gh pr <n>` / `gh run <id>`）。

packages/core/tests/tool/monitor.test.ts         7 pass / 0 fail

覆盖：切行/残行/CRLF/超长截断、突发与持续限流（含合并语义与行不丢）、
退出码 0/3 + stderr 末尾、期限 kill 的 0 条事件文案、`task_stop` 不重复终态、

同 subject 提示、子代理不可见、事件行/面板行/Footer/Ctrl+F 文案。
