# Read 到一条记忆时，把年龄提醒前置到正文之前

## 决定了什么

`packages/core/src/tool/read.ts` 在 Read 成功路径上，当 `classifyMemoryReadPath` 命中
且 `isIndex === false`（即读的是一条记忆，不是 `MEMORY.md` 索引）时，把
`buildFreshnessWarning(mtime)` 的返回值用 `<system-reminder>` 包裹后**前置**到工具输出。

落地《20261102-07H2-漂移与维护-落地方案》T2 的第 1 条，对齐 CC 的
`memoryFileFreshnessPrefix`。这条与 T2 第 2、3 条（索引稀疏化 / 措辞改写）**解耦**：
后两条依赖影子统计的结论拍板（单档阈值不可达），而这条不依赖任何参数选择。

四条口径：

1. **阈值沿用 `buildFreshnessWarning` 内置的 1 天**，不另立参数。
2. **封装沿用 `recall.ts` 的 `<system-reminder>`**，让模型把它当系统提示而不是文件正文。
3. **前置而非追加**。模型读长文件时对开头的注意力最高，追加在末尾等于没写。
4. **只对单条记忆加**，`MEMORY.md` 索引不加 —— 索引里每行已经有 `⏳`（`annotateIndexAges`），
   再叠一条全局警告只是噪声。

## 放弃了什么（以及为什么不选）

- **给 `MEMORY.md` 索引也加一条全局提醒**：索引每行已有逐条年龄，再叠一层说明
  等于同一条信息说两遍，还多占每轮常驻上下文。索引端的措辞改进属于 T2 第 3 条，独立做。
- **另立一个「Read 路径专用」阈值**：`freshness.ts` 的 1 天判据同时被 `recall.ts` 用着，
  两处各写一个阈值必然漂移。要改就改 `buildFreshnessWarning` 本身，而不是在调用点分叉。
- **把文案改成中文**：`buildFreshnessWarning` 的输出是既有实现，`recall.ts` 在用，
  `paths-scan.test.ts` 也在断言它的边界行为。为了这一条 Read 路径单独改文案会让两条
  消费路径的口径分裂，收益只是"读起来顺眼"。
- **在 `read-stats.json` 里再记一次"提醒已展示"**：模型有没有被提醒，不等于它有没有
  照做；这个数没有可行动的判据。现有 `memory_read` 事件已经回答了"这条记忆被读过"。
- **顺手把 T2 第 2、3 条一起做**（`annotateIndexAges` 阈值改档 + `INDEX_FRESHNESS_NOTICE`
  改措辞）：影子统计证明「单档阈值 + 覆盖率 ≤30%」在四个记忆库都不可达
  （7 天档 46.7%–90.9%，90 天档 iam-studio-fe 仍 57.2%），改法要在分档标注 / top-K /
  自适应三选一里拍板。把它和这条确定无争议的改动绑在一起，会让这条等一个还没定的决策。

## 拿什么证明它生效了

**单测**：`packages/core/tests/tool/read-memory-freshness.test.ts` → **4 pass / 0 fail**。
四条判据都穿过 `ReadTool.execute` 的真实调用，而不是只测 `buildFreshnessWarning`——
后者早就正确且有测试，坏的一直是「有没有人调用」（同 `read-side-drift-p0.test.ts`
头注释点名的失效模式）。

- 3 天前的记忆 → 输出 `toStartWith("<system-reminder>")` 且含 `This memory is 3 days old`，
  正文仍在提醒之后（前置不是替换）
- 1 天内的记忆 → 不含提醒，`toStartWith("1\t")`（直接是正文行号）
- `MEMORY.md`（mtime 30 天前）→ 不含提醒
- 普通文件 → 不含提醒

**变异自证**：把 `if (!hit.isIndex)` 改成 `if (false && !hit.isIndex)` →
「超过 1 天的记忆」一条变红，报错原文
`Expected to start with: "<system-reminder>"` / `Received: "1\t# 旧记忆\n2\t\n3\t这条写于三天前。\n4\t"`；
恢复后 4 pass。（顺带观察到 `false &&` 会阻断 `hit` 的非空收窄、LSP 报
`'hit' is possibly 'null'`——这也说明该分支确实依赖 `hit` 非空。）

**门禁**：`bun run format` / `bun run lint`（0 warning 0 error）/
`bun run docs:gen-reference-check`（参考页无漂移）/ `bun run typecheck:gate`（62 处，
基线 64，无新增）/ `bun run affected-tests:run`（**1318 pass / 0 fail**，83 文件）/
`make build`（产物自检通过）/ `bun run smoke`（**13 例全通过**）。

**落盘隔离**：测试把 `SID_CONFIG_DIR` 指向 tmpdir 并在 `afterAll` 恢复原值（不是无条件
`delete`，否则会抹掉 preload 兜底），记忆文件全部写在 tmp 目录下。
