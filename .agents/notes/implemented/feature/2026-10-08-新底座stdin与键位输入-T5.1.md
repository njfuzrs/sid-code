# 新底座 stdin 与键位输入：Ctrl+Z 挂起恢复（I7）与 T5.1 收口（B9 / T5.1e）

## 决定了什么

T5.1 拆成 a–e 五段，这是最后一段，也是整个 T5.1 的收口 Note。前四段各自的 Note：`2026-10-08-新底座stdin所有权与raw-mode计数-T5.1c.md`、`2026-10-08-新底座drainStdin与信号退出-T5.1d.md`；T5.1a/b 的结论在设计文档 T5.1 完成段落里。

本段做的是契约 **I7**：Ctrl+Z 挂起与 SIGCONT 恢复，实现在 `packages/tui/src/components/App.tsx`。规则全部来自对拍 legacy 的黑盒探针（`_probe_z` 加本次补的 `z2 … z9`），没有读旧底座代码（D-5）。探针结果备份在 `~/Backups/sid-code-t51-probe-results-20261007/t51e/`。

- **触发条件**：只看解码后的按键，`ctrl && input === 'z'`。所以 `\x1a`、kitty `122;5u` / `90;5u`、modifyOtherKeys `27;5;122~` 都算，叠加 shift / meta / super 也算。release / repeat 事件、多字符文本块（`\x1ab`、`\x1a\x1a`）、`ESC \x1a`、粘贴里的 `\x1a` 都不算。这个按键不交给任何监听者，同一块里前后的事件照常送达。
- **挂起**：
  1. 写 `ESC[>4m ESC[<u ESC[?1004l ESC[?2004l`，stdout 非 TTY 也写；
  2. `setRawMode(false)`，然后 `unref`，再摘 `readable`；
  3. TTY 下再写 `ESC[?25h` 和关鼠标跟踪的全套；
  4. 挂一次性 SIGCONT 监听，然后 `kill(pid, 'SIGSTOP')`。

  raw mode 计数不动，组件仍然算"持有"。
- **恢复**：底座已有的 SIGCONT 处理（R10）先跑，alt-screen 下重进 alt 并擦屏。然后 `ref`，开 raw mode，挂 `readable`，挂起期间缓冲的字节在这时交出。最后同步写 `ESC[?2004h ESC[?1004h`，TTY 下再补 `ESC[?25l ESC[?1004h`。
- **挂起期间**：`readable` 循环停读，`setRawMode` 只记账、不碰 stdin。卸载时零 stdin 调用，那条一次性监听留着，触发时什么都不做。这些都是 legacy 实测结果。

收口：13 个 `_probe_*` 全部删除或转正，`packages/cli/tests/render-port/` 下已经一个不剩。语料里 `\x1a` 的排除说明改成指向 I7 测试。SPEC 新增 I7，`tui:spec` 现在 63 条、60 条已测。

## 放弃了什么（以及为什么不选）

- **恢复时重发终端探查（`ESC[>0q` + DA1）**：legacy 会发，但这是 I2，next 的 `setSuppressTerminalProbe` 还是 T5.2 的 `notImplemented`。在这里补等于提前做 T5.2 的一半，还绕过它的抑制开关。所以测试比较前先把这两段剥掉，在文件头注释里点明了。
- **用 `pauseInput` / `resumeInput`（上游 suspendTerminal 那套）实现**：它会清解析器状态，而且不 `unref` 的顺序与 legacy 不同。更重要的是它写 bracketed paste 时看计数，legacy 的挂起序列不看计数、无条件写。字节对不上，所以没复用。
- **Ctrl+Z 放进语料走 I8 向量**：生成器进程会被真的 SIGSTOP 停住。mock `process.kill` 又会改变生成器对所有其他条目的语义。所以单独写测试文件。
