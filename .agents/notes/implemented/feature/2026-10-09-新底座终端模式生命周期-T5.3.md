# 新底座终端模式生命周期：T5.3 收口（契约 I4，B9 / T5.3a–c）

## 决定了什么

- T5.3 由三个子任务组成：
  - T5.3a（`0f1d504e` + `b9bd841b`）：底座侧 I4 开关。raw mode 计数 0 → 1 开 `?2004h ?1004h`（扩展键再开 `>1u >4;2m`），归零先关模式再关 raw mode；Ctrl+Z 恢复、stdin 静默 > 5s 重申、TTY 卸载再关一次。扩展键只看环境变量（`terminal/extended-keys.ts`）。契约 `terminal-modes.test.tsx`。
  - T5.3b（`a9df79a3`）：CLI 直写收口。三处来源全部留在 CLI，归属表写明理由；`detectCapabilities()` 在生产中没有调用方，CLI 的 kitty / mok 开关与 `?2004` 清理都是死代码。契约 `cli-modes.test.tsx`。
  - T5.3c（本次）：外部编辑器前后的模式恢复，以及 T5.3 / 阶段 5 收口。**没改底座代码**。
- T5.3c 补的是 I4 × X5 的交叉：外部编辑器让渡（`enterAlternateScreen` → `exitAlternateScreen`）期间 raw mode 计数变化时，模式怎么开关。legacy 黑盒探针（D-5）结论：
  - 让渡期间 I4 计数规则**照常当场生效**：0 → 1 当场 `ref` + 开 raw mode + 写模式 + 探查；归零当场关模式 + 关 raw mode + `unref`。不推迟到收回。
  - 收回时开不开 raw mode 只看**让出那一刻**有没有人持有（让出时关过才重开），不看收回时的计数。所以「让渡中归零」的收回仍写 `{raw:true}`，「让渡中第一次 0 → 1」的收回不再写。
  - `?1004h` 与扩展键重申 `<u >1u >4;2m` 照 X5 无条件写，与计数无关。主屏与 `<AlternateScreen>` 里规则相同。
  - next 在 T6.1b 之后已与 legacy 逐字节一致，本次只是把这些钉成契约。
- S8（I4 + X5）在 T6.1b 合入后已在 next 上转绿，设计文档里「S8 记为待 T6.1」的预案不再需要。

## 放弃了什么（以及为什么不选）

- **把「收回时看计数决定开不开 raw mode」改得更「合理」**：legacy 在让渡中归零后收回仍 `setRawMode(true)`，看起来多余，但它是基线，且之后的 0 → 1 会按计数重新走一遍，不会漏关。改了就是行为回退，按 D-5 不动。
- **删 `detectCapabilities` 那套死代码**：不归 B9，另开整改项（T5.3b 已记）。

## 拿什么证明它生效了

- 新契约：`packages/cli/tests/render-port/external-editor.test.tsx` 的 `I4 × X5` 组 4 条（让渡中 0 → 1、让渡中归零、归零再回到 1、alt 里同规则，含 kitty 扩展键变体），夹具 `fixtures/external-editor-app.tsx` 加 `mountDuring` / `unmountDuring` / `remountDuring` / `altMountDuring` / `altUnmountDuring` 场景。双底座 19/19。
- 变异自证 3 处全红：让渡期间计数变化推迟到收回（4 红）、收回时看计数才开 raw mode（2 红）、让渡中新开的也在收回时再开一次（4 红）。用备份还原，`cmp` 核对一致。
- SPEC I4 行把「外部编辑器前后归 T5.3c」改写为上述规则并指向新测试；`tui:spec` 64 条、61 条已测。
