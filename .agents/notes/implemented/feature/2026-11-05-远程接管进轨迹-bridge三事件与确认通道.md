# 远程接管进轨迹：Bridge 三事件、metadata.bridge 与确认通道 confirm_via

## 决定了什么

落地《观测缺口-hook回滚loop远程接管四处补轨迹事件》的 PR2（T4 + T5 的 bridge 部分）。
触发清单 A12「会话远程接管」此前证据列只能写「无，看管理台」——轨迹里一条 bridge
记录都没有，`PermissionDecision` 也分不出批准是本地点的还是远程点的。

**五个落点**（都只进本地 `events.jsonl` / `session.traj`，不经遥测出机器）：

1. `bridge/bridge-telemetry.ts`（新）—— 三个事件名常量 + 字段闭集 + `emitBridgeTelemetry`，
   生产侧与消费侧共用，避免字面量漂移。
2. `BridgeSession` 四个 phase：`connected`（relay_host 剥 query + permission_timeout_ms）、
   `start_failed` / `permanent_failure`（close_code + reason）、`stopped`
   （inbound_messages + aborts + duration_ms）。phase 由 `consumePermanentFailure(phase)`
   按调用时机传：**启动即被拒**与**连上后被踢**处置不同，只靠 close_code 分不开
   （4001 在两个时机都会出现）。
3. `BridgeInbound`：`BridgeCore.handleIncoming` 去重后记 `kind` + `text_len`；
   **ping 不记**（每秒级高频、零信息量）；abort 与权限应答各一条。
4. `BridgePermission`：`PermissionProxy` 的三种结果 `allow / deny / timeout` + `wait_ms`。
   超时与远程明确拒绝分开——前者是运维信号，后者是用户意图。
5. `metadata.bridge` + `PermissionDecision.confirm_via`：
   - `trace/session-flags.ts`（新）进程级标记，`App.runBridge` 在 `init()` **之前**置位；
     collector 构造 metadata 时读取。不能走 `SessionStartInput`（对外 hook 契约）；
     不能只在 `runBridge` 里改一次 metadata——远程可以发 `/clear`，重建时标记会丢。
   - `confirm_via: "tui" | "bridge" | "sdk" | "headless"`，由 `App.requestUserConfirmation`
     按实际走的分支设置，门面 `logPermissionAllow/Deny` 只在 `prompted=true` 时读。
     `PermissionSource` 闭集**不扩**（那是外发遥测字段，扩了要动后端 schema）。

**接线方式**：`BridgeRunnerDeps.onTelemetry` 依赖注入，由 `App.runBridge` 注入
`traceCollector.recordCustomEvent`。不用 hook/skill 那套模块级 sink——那些存在是因为
生产点拿不到 collector；bridge 在 `new BridgeRunner` 时 `await this.init()` 已跑完，
整条链路只有 runner → core → proxy 一个实例链，构造参数透传即可。sink 一路透传到
`PermissionProxy`（`bridge-core.ts` 的构造处），否则入站与权限事件全部静默丢失。

**消费侧**：`trace/digest.ts` 加 `triggerCounts`（本 PR 只有 `bridge_inbound`），
`renderHuman` 输出「触发计数」一节；没有任何 bridge 事件时 section 不出现——
普通本地会话不该凭空多出 `bridge_inbound=0`（那会把「没被遥控」与「没接线」混成一个数）。

**反死线门禁**：`packages/core/tests/trace/trigger-events-wiring.test.ts`，读代码不读注释
（先剥 `//` 与块注释）。断言：三个常量定义在单一事实源；runner 的 emit **恰好三处**且
`connected` / `stopped` / `start_failed` 都被生产侧用到；core 把 sink 透传给 proxy；
app 的 `onTelemetry` 行与 `recordCustomEvent` 同一行；collector 读 `isBridgeSession()`。

## 放弃了什么（以及为什么不选）

- **放弃给 `SessionStartInput` 加 `bridge?: boolean`**。那是对外 hook 契约
  （用户脚本的 stdin），加字段要动参考页与用户脚本；而「被遥控」只服务本地轨迹归因。
  选了进程级标记 `trace/session-flags.ts`，`/clear` 重建 metadata 时同样成立。
- **放弃模块级 sink（`setBridgeTraceSink`）**。看起来与 `skill/telemetry.ts` 一致，
  但 bridge 的生产点**拿得到** collector（`runBridge` 在 init 之后才创建 runner）。
  模块级单例会掩盖一个真问题：隔离的 `BridgeCore`（测试 / 将来的第二条连接）该不该
  记进主会话轨迹。依赖注入把这个决定留在调用方。
- **放弃扩 `PermissionSource` 加 `bridge`**。那是遥测出机器的字段闭集
  （`analytics/events.ts`），扩了要动后端 schema 与历史曲线。选了只进本地轨迹的
  `PermissionDecision.confirm_via`，只在 `prompted=true` 时填。
- **放弃在 `PermissionProxy.requestPermission` 发「请求已发出」事件**。只有结果有意义
  （`allow/deny/timeout` 各一条，与验收「BridgePermission allow 1」对得上）；
  发请求事件会让一次确认变成两条，还要引入 request_id 才能配对。
- **放弃让 `stop()` 无条件发 `stopped`**。`start()` 失败时 runBridge 的 `finally` 也会调
  `stop()`——无条件发会把「启动即被拒」记成一次正常会话（connected 都没有却有 stopped）。
  用 `startedAtMs` 取走即清（同时保证 stop 调两次只发一条）。
- **放弃在测试服务端的 `open` 回调里立即 `ws.close(4001)`**。实测会退化成 1006
  （异常关闭），永久失败判定不触发，`start()` 反而成功，测试间歇性全绿。
  改成收到客户端 auth 帧之后再拒——真实中继也是首帧必鉴权，时序确定且更贴近生产。
- **放弃把三组（hook / 回滚 / 定时触发）一起做**。方案拆 PR 的理由是端到端验收依赖
  企业后端（A12 要管理台配合），绑在一起会让本机可验收的部分被环境卡住。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/bridge/bridge-telemetry.test.ts` → **10 pass / 0 fail**：
  去重后 1 条、ping 0 条、abort 1 条、权限 allow/deny/timeout 各 1 条、
  4001 → `start_failed` + close_code=4001、stop 两次只 1 条 stopped；
  事件 JSON 里 `grep` 不到 token 与 query（`SECRET-TOKEN-XYZ` / `token=` / `org=acme` 全 0）。
- `bun test ./packages/cli/tests/app/permission-confirm-via.test.ts` → **4 pass / 0 fail**：
  bridge / tui / headless 三条通道取值正确；`prompted=false` 时字段不存在。
- `bun test ./packages/core/tests/trace/trigger-events-wiring.test.ts` → **5 pass**。
- **变异自证**（5 处，每处改坏 → 跑对应测试 → 恢复）：
  ① 删 `app.ts` 的 `onTelemetry` 注入 → 门禁红；
  ② 删 runner 的 `connected` emit → 门禁红（第一版门禁只断言「至少一处 emit」，
  这一变异**仍然全绿**——据此把断言改成「恰好三处 + 相位字面量」，重跑才红）；
  ③ 断 `core → proxy` 的 sink 透传 → 门禁红；
  ④ 删 `events.ts` allow 分支的 `confirmVia` 透传 → 3 条通道用例红；
  ⑤ 删 collector 的 `bridge: true` → 门禁红。
- `bun run typecheck:gate` → 无新增类型错误。
- `bun run affected-tests:run` / `make build` / `bun run lint` / `bun run format:check` /
  `bun run lint:boundary` → 见 PR 正文（同一组命令的输出）。
- **未做**：端到端 A12（管理台签发 + 遥控）依赖企业后端，本机环境不具备；
  按方案要求，T4 单测必须过、端到端在 PR 描述里标「未做」，不写「已验证」。
