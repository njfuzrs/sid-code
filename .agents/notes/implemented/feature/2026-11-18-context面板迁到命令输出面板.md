# /context 从专属 Dialog 迁到命令输出面板，取数收进 core 一层

## 决定了什么

把 `/context` 从「专属 Dialog + `DialogType` 登记 + `TUICallbacks.getContextBreakdown`
回调」改成与 `/cost`、`/perf` 同形态的**命令输出面板**，并把面板要的全部数字收进
core 的一个纯函数里。

三件事：

1. **新增取数层** `packages/core/src/context/context-report.ts`：
   `buildContextReport(ctxMgr, opts) → ContextReport`。分类分组（常驻 / 会话）与小计、
   占已用百分比、距触发还剩多少、四档阈值、完成预留的两分量拆分、释放明细（含条数）、
   实测对账（末次真实输入 vs 下一次预测 vs 差额）、结论行「最大的三个可变成分」、
   最多 3 条提示——**全在这一层算完**。
2. **新增排版层** `packages/cli/src/command/commands/context/context-render.ts`：
   `renderContextReport(report, { width, color }) → string`，只做分区、对齐、千分位、
   窄列自适应、按显示宽度折行。**不含任何算术**（与 cost-render 同一条纪律）。
3. **删掉专属面板与三处登记**：`ContextDialog.tsx`、`DialogSwitch` 的 `context` 分支、
   `DialogType` 的 `"context"`、`TUICallbacks.getContextBreakdown`，以及 `app.ts` 里
   那份私有的 `getContextBreakdownWithSources`（它做的固定开销拼接搬进了取数层）。

顺带补齐两处字段：

- `FixedOverheadReport.residual`（A4）：母项「记忆/CLAUDE.md」减去已列细目之和，恒 ≥ 0。
  负值时钳到 0 并记一条 debug 日志，**不在面板上造负数**——对用户没有可行动含义，
  对开发者是一条口径漂移的排查信号。母项为 0 时残差为 0，该节整节省略。
- `CompactionThresholds.outputReserve / summaryReserve`：完成缓冲区原本只给合计
  （`completionBuffer`），面板要展示「36,000 = 回复输出 16,000 + 一次摘要 20,000」，
  所以把两个分量一起返回。不变量 `outputReserve + summaryReserve === completionBuffer`
  （被 `TOTAL_MAX_RATIO` 钳制时摘要分量取钳制后剩余）。
- `ContextTokenBreakdown.freed.byStrategy[].count`：面板要显示「过期清理 24 项」，
  只给 token 数说不出「清理了几次」。同一条 `recordCompact` 记录同时撑起两个量。

**依赖关系**：本改动的面板读 PR1 补的 `thinking` 分类与锚点抬升、PR5 修好的会话级
`stockPromptTokens`、PR2 的 `freed.byStrategy`。这四项在 main 上已就位
（`#918` / `#919` / `#920` / `#921`）。

## 放弃了什么（以及为什么不选）

**① 不保留 Dialog，也不做「Dialog 与面板双形态」。**
`src/ui/CLAUDE.md` 的 L4-H 明确：查看/诊断类命令直接标 `outputPanel`，不要为它写专属
Dialog + 登记 `DialogType`。双形态的代价是两个渲染器各有一套数字与版式，下一次改口径
必然只改一处——这正是本次要修的「面板与 footer 不同源」那类缺陷的温床。

**② 不在 CLI 侧算百分比/差额，也不让 `computeFixedOverheadSources` 自己算残差。**
排版的算术是 D9（`/stats` 用 stock÷flow 算出 4% 命中率）的根因。残差放在
`computeFixedOverheadSources` 是因为它才知道「哪些细目真的从 system prompt 里切出来了」；
母项必须由调用方传（`opts.memoryFilesTokens`），因为母项来自分类分配，函数自己看不到。

**③ 不做彩色的分类网格。** 旧面板 10 个分类撞成 3 种颜色，既区分不了又违反「克制点睛」。
新面板**不给分类配色**：构成交给对齐成列的表格，颜色只给三处——进度条（随档位）、
「已用」数字、警告提示。分类之间的差异用缩进与分组标题表达。

**④ 小窗口（≤60K）不假装四档都在。** `getCompactionThresholds` 在小窗口下
`maskingRemaining`/`compressionRemaining` 恒 0，展示成「触发点 = 窗口上限」会让用户
以为该档在生效。取数层按 `remaining > 0` 过滤，面板只剩 `emergency` + `blocking`。

**⑤ 不在会话还没发过请求时把「末次实测」显示成 0。** 那会让「实测值真的是 0」与
「还没有实测」看起来一样。显示「— 尚无实测（本会话还没发过请求）」。

**⑥ 没有把 `/context` 做成 `headless: false`。** 它标 `headless: true` + `outputPanel: true`，
与 `/cost` 一致：`-p` 与管道输出走同一条路径，`color` 由 `process.stdout.isTTY` 决定，
非 TTY 下**一个转义码都不输出**，脚本能直接解析。

## 拿什么证明它生效了

**G1 单测（42 项，新增两个文件）**：

- `packages/core/tests/context/context-report.test.ts`（21 项）：
  `report.used === getContextUsageForDisplay().used` 逐字相等；
  `Σ sources + residual === memoryFiles` 严格相等；`toTrigger`/各档 `remaining` 能由
  `thresholds` 反推；`outputReserve + summaryReserve === completionBuffer`；
  小窗口只列两档；`largestVariable` 只取会话组；调用前后 breakdown 逐字不变（只读性）。
- `packages/cli/tests/command/context-render.test.ts`（21 项）：
  120/80/60 三个宽度下**逐行**断言 `stringWidth(line) <= width`；`color: false` 无 ANSI；
  进度条颜色随档位两两不同（`chalk.level = 3` 模拟真终端，否则这扇门恒绿）；
  「已用」「末次实测」「差额」**按行过滤后**断言等于 report 字段；
  跨层对账：同一个 `ctxMgr`，面板「已用」百分比 === footer 的
  `getContextUsageForDisplay().percentOfWindow`。

**变异自证（看了失败信息，不只看退出码）**：

| 变异 | 结果 |
| --- | --- |
| 去掉 `residual`（恒 0） | `Σ sources + residual === memoryFiles` 红：`Expected: 213 / Received: 142`，差值 71 正是残差 |
| 渲染层「已用」改读 `grossTokens` | 「已用行 === report.used」红：`Expected to contain: "1,113"` / `Received: "已用（= 状态栏）    931"`，差值 182 正是锚点抬升量 |

⚠️ 第二条变异**第一次跑是绿的**——原夹具没有锚点抬升，`subtotal === used`，读哪个都一样。
这正是 §8.2 要防的「恒绿门禁」。改法是让夹具连续 `recordActualTokens` 两次造出抬升，
并在注释里写明这条前提为什么必须存在。

**门禁**（见 PR 正文的实测输出）：`affected-tests:run`、`make build`、`bun run smoke`、
`bun run smoke:tui`（新增 G4 用例 `A16-context-panel`）、`lint`、`format:check`、
`typecheck:gate`（62/62 无新增）、`docs:gen-reference`（改了 `command/`，
`website/ref/slash-commands.md` 已同步）。

**G4 用例守什么**：单测能证明「给定 report 能排出正确文本」，证明不了文本真的到了屏幕上
——命令是否标了 `outputPanel`、`executor.resolvePanel` 是否判进面板、
`CommandOutputDialog` 是否画出来、Esc 是否一次关掉，这几段接线任一处断了单测都看不见
（旧实现是专属 Dialog，接线方式完全不同，正是本次替换的部分）。剧本的 `wait` 只取
面板独有文案（「上下文用量」「常驻（每轮都带）」「压缩阈值」「强制截断」），
不取「上下文」三个字——命令行回显里也有，面板没开也会命中。
