# /model 面板新增价格/上下文窗口/档位画像列，并统一四处分散的展示口径

## 决定了什么

新增 `packages/core/src/llm/model-profile.ts`，把一条 `availableModels` 条目所需的
**展示级**事实（上下文窗口、输出上限、单价、按次价、effort 档位、数据来源档位）聚合成
单一 `ModelProfile` 对象，供 `/model` 弹窗、`/model pricing`、状态栏等所有展示位统一取数。

具体改动：

- `token-estimator.ts` 新增 `ModelMetaSource` 类型（`user/registry/catalog/fuzzy/fallback`）
  与 `resolveContextLimit` / `resolveMaxOutputTokens`，在原 `getContextLimit` /
  `getMaxOutputTokens` 之外**新增**带来源标注的版本（旧函数委托新函数，不改变签名与行为）。
- `model-profile.ts` 的 `buildModelProfile` / `detectPricingSource` 聚合窗口、价格、
  effort 档位；`packages/cli/src/command/commands/model/model.ts` 的
  `detectPricingSource` 改为委托这里，消灭两份判定逻辑并存。
- `ModelDialog.tsx` 新增上下文窗口列、价格列，以及光标所在行的详情区（完整参数 + 价格来源）；
  新增 `model-meta-layout.ts` 做列宽预算（枚举 8 种可选列组合取最优，保证"越宽显示越多"单调）。
- `DialogSwitch.tsx` 把传给 `StatsDialog` 的定价改成 `resolvePricingUSD`（=
  `resolvePricing` + `effectivePricing`），修掉人民币价被当美元显示的真 bug（
  deepseek-v4-pro 注册表存 ¥9/M，原实现直接印成 `$9.00/M`，高估 7.1 倍）。
- `model.ts` 里 `/model list` 的定价来源判定顺带修掉一处真 bug：原实现第 4 步
  `lookupRegistry(name)` 传别名而非真名，前缀式/自定义别名（如 `gw-claude-opus-4-8`）
  会 miss 掉注册表命中，误标"兜底估算"（实际取价一直是对的，错的是来源标注）。

## 放弃了什么（以及为什么不选）

- **没有让 `resolvePricing` / `getContextLimit` 直接返回来源**：它们在计价热路径上被
  反复调用（每轮 usage 都要算钱），来源信息只有展示时才需要，改签名的波及面
  （6 个调用点）远大于收益。改用新增委托函数的方式，旧调用点零改动。
- **没有把画像塞进 TUI state 随渲染下发**：网关价与能力缓存是异步后台刷新的
  （`refreshGatewayPricingOnStartup`、400 自愈），随 state 推下去会停在启动那一刻的
  旧值，与实际计费的价不一致——这恰是"更省"方向最不能出错的地方。改用命令式回调
  `getModelProfiles()`，面板打开时现算，读的一定是当前缓存。
- **没有给按次计费模型编一个 token 价**：`perCallUSD` 与 `pricing` 互斥，宁可让
  展示层判空分支处理，不在数据层填假值。
- **列宽裁剪没有用优先级贪心**：实测反例——终端拖宽后贪心认领端点列会挤掉价格+窗口列，
  出现"拖宽窗口信息反而变少"的观感 bug。改为枚举全部 8 种组合取最优（列数优先、
  同列数按权重），保证单调。
