# 新增 run 级配置指纹采集与比对：不一致即 INVALID 且点名到字段

## 决定了什么

落地《评测接入 CI/CD：分层门禁与基线闭环》T11（P2-3 指纹采集）。方案 §3.4 说
「基线不是一个分数，是一组带配置指纹的逐题结果」，但此前只有题集这一项被钉住
（`taskset_fp.py` 的题名 + `task.digest`），模型、二进制字节、架构、harbor 版本、
轮数/预算上限这些**同样会改变分数**的必控变量散落在各处，没有任何一处汇总、更没有任何
机制判「这两次结果能不能比」。

四处改动：

1. **新增 `evals/external-benchmarks/harbor/run_fingerprint.py`**，两个子命令：
   - `collect <run_dir>`：从 run 产物采 13 个字段，落 `<run_dir>/run-fingerprint.json`
   - `compare <base> <current>`：逐字段比对，输出 `VALID` / `INVALID` / `INCOMPLETE`
2. **`sid_code_agent.py` 补两格 metadata**：`sid_max_turns` / `sid_max_budget_usd`。
   取自 `self._resolved_flags`（Harbor 解析后的终值），不是 result 事件。
3. **新增 `run-fingerprint.sh` 并接进四条跑法脚本的收尾**，让「每次 run 落盘」不依赖
   人记得跑一下。
4. **`taskset_fp.py` 提 `digest_fingerprint()` 公开函数**，run 级指纹复用它算题集段，
   不在别处重算一遍。

判据（`compare` 的三态）：

| 结论 | 条件 | 退出码 |
| --- | --- | --- |
| `INVALID` | 任一字段值不同 / 单边缺失 / 任一侧 run 内部冲突 | 2 |
| `INCOMPLETE` | 无差异，但有字段**两边都没采到** | 3 |
| `VALID` | 全部采到且逐字段相同 | 0 |

⚠️ `INCOMPLETE` **不是通过**。方案 §5.2 里 `INVALID` 的语义是「不出结论，不放行」，
所以 T12 的判定器消费时 2 和 3 都要当不通过。单独给一个码是为了让人一眼看出
「是配置变了」还是「采集没覆盖到」——两者的修法完全相反。

## 放弃了什么（以及为什么不选）

- **只做「值不同 → INVALID」，不管缺失**：那是黑名单思路，且会造出本仓最贵的那类失效 ——
  两侧都缺的字段会「一致」，而这个一致毫无信息量。所以缺失走三态 + 显式 `missing` 清单。
- **缺失字段填 `"unknown"` / `0` 当默认值**：`sid_code_agent.py` 里成本兜底那处写着
  「绝不填 0」，理由是填 0 会让「没采到」伪装成「没花钱」。指纹同理。
- **run 内部冲突时「取第一个值」**：一个 run 的 10 个 trial 出现两个二进制 sha，说明
  中途换了包，这个 run **本身就不该当一个整体**。所以 `conflicts` 记下具体是哪几个
  trial 分歧，比对时直接判 INVALID —— 而不是静默择一。
- **把 `network_policy` 也从产物里采**：Harbor 把它放在 trial 运行期
  （`harbor/trial/network_policy.py`），**不写进 `result.json`**（2026-11-04 核过
  `a11-sid` 的 10 份产物）。所以它进 `DECLARED_ONLY`，由跑法脚本用
  `SID_HARBOR_NETWORK_POLICY` 声明；不声明留 null，比对时判 INCOMPLETE。
- **`--declare` 对所有字段开放**：只允许 `DECLARED_ONLY` 里那两个。否则「从产物采到的」
  和「人手工声称的」会混成同一个值，而这两件事的可信度完全不同。
- **用 `run*.sh` glob 数覆盖面**：`run-fingerprint.sh` 是采集库不是跑法脚本，
  混进「跑法脚本」这个集合会让那个定义失去意义。所以两份门禁里都显式排除它。
- **改 `evals/CLAUDE.md` 里的规则内容**：我只更新了因本次插入 16 行而漂移的
  `file:line` 出处（§1.6 / §3.7 / §7 三处 + `CITATIONS` 登记）。规则正文一个字没动。

## 拿什么证明它生效了

**① 采集在真实产物上跑通**（`runs/a11-sid`，10 个 trial）：

```
python3 run_fingerprint.py collect .../runs/a11-sid --declare network_policy=allowlist
→ 已落盘指纹（10 个 trial）
  fields: model_id=anthropic/claude-sonnet-5, sid_binary_sha256=c401748…,
          arch=x64, harbor_version=0.22.0,
          taskset_digest=10:c785769f4f01dadd:f9da75acc9febd5e
  missing: traj_bench_commit, max_turns, budget_usd, permission_mode, stall_escalation
```
（后四个是该 run 早于这两格 metadata 上线，正如实报缺 —— 不填默认值。）

**② 核心判据：逐字段单独变异 → INVALID 且只点名那一个**
`python3 test-run-fingerprint.py` → **56 通过 / 0 失败**。其中最重的一组对 `FIELDS`
里 13 个字段**逐个**变异一遍，断言 `verdict == INVALID` 且 `differing_fields == [该字段]`。
只测「随便改一个值 → INVALID」不够：那分不清「它对每个字段都比对」和「它只比了第一个」。

**③ TS 侧门禁（`bun test ./tests/eval/harbor-run-fingerprint.test.ts`）27 pass / 0 fail**，
按 `evals/CLAUDE.md` §4.1 的要求给 `.py` 补门禁，L1 只依赖 stdlib（CI 上真的在跑），
含 §4.3 要求的四类变异自证：
- 删掉 `FIELDS` 一个字段 → SOURCES/FIELDS 覆盖断言翻转
- **加一个「下一个」同类字段** → 同样翻转（拦形态不是拦个案）
- `FIELDS` 抠成空集 → 「非空」断言翻转
- 语法整体坏掉 → checker 自己非 0 退出并报 `SYNTAX_ERROR`

**④ 接线门禁**：四条跑法脚本都 source 了 `run-fingerprint.sh` 且调用
`run_fingerprint_collect`；调用点不被 `|| exit` 串成会传播失败的形式，
采集函数自身 `return 0`、不 `exit`（只读旁路，失败不改 RUN_RC）。

**⑤ 仓库门禁**：`format:check` / `lint` / `lint:boundary` / `lint:command-system` /
`lint:legacy-tool` / `typecheck:gate`（无新增类型错误）/ `make build`（产物自检 5 项全过）
全部通过。

**⑥ 选测**：1707 pass / 2 fail。两条失败是 worktree 环境假失败
（`tests/build/rules-paths-scope-nonempty.test.ts`），三条举证：该测试只读
CLAUDE.md frontmatter + `git ls-files` + `rules.ts`，不 import 本次改动模块；
父仓 main 上单跑 3 pass / 0 fail；根因是 `ruleOwnerDir()` 把 worktree 绝对路径里的
`.sid-code` 段当成规则归属边界，导致候选集为空（与本次改动无关，在 worktree 里做任何
改动都会红）。

**已知局限**（本条最重要，别当成"全绿"）：本改动只证明「采集与比对逻辑正确」，
**不证明「基线可比了」**。那要等 T15 真跑一次 k=3 基线、T16 样本外复跑、
T17 冻结 S/ε/m 之后才有结论 —— 单测只证明接线通了。
