# harbor 适配器加停滞阶梯评测档 `stall_escalation`（T7 第二步前置）

## 决定了什么

`evals/external-benchmarks/harbor/sid_code_agent.py` 新增旋钮 `stall_escalation ∈ {off, shadow, hard}`（`--ak stall_escalation=hard`，或宿主 env `SID_HARBOR_STALL_ESCALATION`）：

- `off`（默认）：不往容器传任何 env，和历史 run 逐字等价，基线不动
- `shadow` / `hard`：在 `run()` 的 exec env 里合入 `SID_CODE_STALL_ESCALATION_HEADLESS=1` 和 `SID_CODE_STALL_HARD_STOP=0/1`
- 非法值在宿主侧就拒绝启动。sid-code 只认字面 `"1"/"0"`，传错会被静默当成默认
- 每个 trial 的 metadata 记 `sid_stall_escalation`。这一档会改变 agent 行为，`hard` 的 reward 不能和 `off` 的基线直接比

`run-model-switch.sh` 的 `SID_HARBOR_BINARY_*` 改成外部已设就沿用。原来写死的 30586ff（08-30）早于 `stall-escalation.ts`（10-21），用它跑 T7 等于没开阶梯。闸 0 仍按产物字节核对 commit。

### 换新二进制时一并暴露的两个断点（都是「0 次模型调用」形态）

pin 的 30586ff（08-30）把下面两件事都挡住了，第一次换 10 月的产物才同时暴露：

1. **适配器缺 `--verbose`**：`fa54a325`（09-25）起 `--print` + `--output-format stream-json` 不带 `--verbose` 直接 exit 1。冒烟 `build-pmars` 的 `sid-code.jsonl` 只有一行这个报错。已补进命令行，`harbor-agent-contract` 加了断言（去掉它会变红）
2. **bun 1.4.2 的 `bun-linux-x64-baseline` 编译产物在 qemu-x86_64 下挂起**：`--version` 90s 不返回，且 6/6 个 trial 都卡在 install 阶段的 `--version`（ps 看到 28 分钟）。同一份源码用 `--compile-executable-path` 指向 bun **1.3.14** 的 baseline 运行时，编出来的产物 `--version` 和 `--self-check` 全部通过；1.4.2 编的 hello-world 也正常，说明不是运行时整体坏了，具体触发点没查。本轮 x64 产物用的是 1.3.14 运行时，`scripts/build-branch-artifact.sh` 没改（要不要钉运行时版本留给单独的 PR）
   - 顺带：`build-branch-artifact.sh` 按 target 覆盖 `packages/core/vendor/rg-embed`，先编 arm64 再手动编 x64，会嵌入 arm64 的 rg，`--self-check` 能拦住。编完已用 `fetch-ripgrep.ts --as-embed` 恢复成本机平台

3. **容器 2GiB 上限下 sid-code 自己被 OOM 杀**：T7 全量第一批里 2 个 trial 被 memcg OOM 杀掉（dmesg `Killed process … (sid-code) anon-rss 1224/1382MiB`），形态是 `NonZeroAgentExitCodeError` + reward 0。同一批题容器峰值 p95 从上轮（30586ff）的 1439MiB 涨到 1836MiB，`break-filter-js-from-html` 上轮 reward 1.0、本轮被杀在第 12 轮。`run-model-switch.sh` 加了 `SID_HARBOR_OVERRIDE_MEMORY_MB`（默认不传，与历史 run 等价）。**30586ff → 27df03bf 之间 sid-code 进程内存涨了这件事本身没查**，是一条独立的「更省」方向线索

## 放弃了什么（以及为什么不选）

- **做成 harbor `EnvVar` 描述符**：pin 的 harbor 0.22 里，`ENV_VARS` 解析结果只进 `_env_sources`，用于查找，不保证注入 sid-code 进程。显式合进 `exec_as_agent(env=...)` 是唯一能读源码确认的路径
- **只靠 `--ae`**：同理，`extra_env` 走 Trial 的 scoped exec env，覆盖哪些 exec 由 harbor 内部决定，而且档位不会进 metadata
- **写进容器 `settings.json` 的 `stallHardStop`**：headless 开关 `SID_CODE_STALL_ESCALATION_HEADLESS` 只认 env，单写 settings 时整套阶梯仍是关的
