# 注册表外引导规则与边界检查补触发事件（只加事件，不改行为）

## 决定了什么

八类此前只写 logger 的规则补上结构化轨迹事件，行为一处不改：

| 事件 | 台账条目 | 发射点 | 通道 |
| --- | --- | --- | --- |
| `ContextPressureReminder` | P12 | `query/loop.ts` 上下文压力提醒 push 后 | `deps.traceAppendEvent` |
| `GoalReminderInjected` | P14 | `query/loop.ts` Goal 回注 push 后 | 同上 |
| `OmissionRejected` | T8 | `tool/write.ts`、`tool/edit.ts` 省略占位拒绝分支 | 模块级 sink |
| `ToolResultCleared` | C1/C2 | `compact/tool-result-budget.ts`、`compact/microcompact.ts` | 同上 |
| `CredentialInContext` | B18 | `query/tool-executor.ts` 凭证检测分支 | 同上 |
| `WebFetchModelUrl` | B18 | `tool/web-fetch.ts` 模型自造 URL 分支 | 同上 |
| `MemoryGuard` | B18 | `analytics/events.ts` `logMemoryGuard`（analytics 照发，本地轨迹另留一份） | 同上 |

- sink 与事件名常量集中在新文件 `query/guidance-events.ts`，`cli/src/app.ts` 在 collector 就绪后接到 `recordCustomEvent(event, data)`。
- P12 / P14 / T8 作为防线登记进 `defense-registry.ts`（`context_pressure_reminder` / `goal_reminder` / `omission_reject`）；其余四个作为观测事件登记 `notDefenseReason`。
- 事件只放闭集标签与计数：文件只留 basename，web_fetch 只记 origin（路径与查询串可能就是外泄载荷），凭证只记类型名，省略占位只记规则名。
- `ToolResultCleared` 带被清的 `tool_use_ids`，后效指标「清理后 N 轮内同签名重跑」靠它回到 `PreToolUse` 取签名（HB-3 用）。

## 放弃了什么（以及为什么不选）

- **把 sink 放在各自模块（`tool/omission-detector.ts` 等）**：`defense-registry-complete.test.ts` 只扫 `query/` 下的 `*_EVENT_NAME` 与 `traceAppendEvent`，放在 `tool/` 里门禁看不见，新增发射点可以不登记。集中到 `query/guidance-events.ts` 让门禁自动覆盖。扩门禁扫描范围到全仓是「对账门禁扩到工具层」的独立事项，不在本 PR。
- **P16 LSP 诊断 / T11 后台轮询拦截也补事件**：回源码核实已有 `LspDiagnostics`（11 月 2843 条）、`BackgroundPollIntercepted`（38 条），台账「无事件」是过时描述，不重复造。
- **P26 / P27 / C7（hypothesis 族）一起补**：三条都依赖 `SID_ENABLE_HYPOTHESIS`（默认关），补了也攒不到数据，后置。
- **B18 注入校验器补事件**：#681 已让 `PermissionDecision.guard=injection:*` 落轨迹，不再是缺口。
- **在 `CompactionAttempt` 里加 ids 代替新事件**：budget 还有入队时刻的入口（`context/manager.ts` `applyToolResultBudgetToContent`），不经过 `CompactionAttempt`，加在那里会漏掉这一路。
- **OmissionRejected 带命中行原文**：原文是用户代码，事件会随轨迹上传；规则名足以归类，误拒抽检回到 session.traj 看。

取舍：方向是「可观测」，为 M4「更快 / 更省」A/B 准备量尺。不改模型可见的任何内容，不牺牲「更准」；代价是 events.jsonl 多几类低频事件（按 11 月本机量级：压力提醒约百次 / 月、清理约数百次 / 月）。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/query/guidance-events.test.ts`：14 pass。覆盖每个发射点的触发 / 不触发、字段不含原文、sink 旁路不抛、App 接线与 loop 接线源码位置。
- 变异自证（逐个把发射调用换成空函数后跑上面的测试，各红对应的一条）：write、edit、tool_result_budget、microcompact、web_fetch、logMemoryGuard 共 6 处，全部红在预期用例上。
- 注册表门禁变异：删掉 `EVENT_ANCHORS.MemoryGuard` 后 `defense-registry-complete.test.ts` 报 `unregistered: ["MemoryGuard（query/guidance-events.ts:29）"]`，恢复后 11 pass。
- 端到端（`make build` 产物 + replay provider，隔离 `SID_CONFIG_DIR`）：一条会话依次 web_fetch 自造 URL、write 带 `// ... existing code ...`、bash 回显 AWS 示例 key。events.jsonl 里出现 `OmissionRejected{tool_name:write,file:a.ts,patterns:["JS comment ellipsis"]}`、`CredentialInContext{tool_use_id:toolu_p3,kinds:["AWS Access Key"]}`；default 档下同一夹具出现 `WebFetchModelUrl{origin:"https://evil.example.com"}`，不含路径与 `payload`。
- **探针顺带发现的口径限制**：skip 档（`--dangerously-skip-permissions`）下 web_fetch 不经 `checkPermissions`，`WebFetchModelUrl` 结构上恒 0。本机 11 月 93% 会话是 skip 档，所以这条事件的本机计数**不能**当「模型不自造 URL」的证据，只有 default / auto 档会话有分母。
- `bun run smoke`：23 例全过。`affected-tests:run`：5893 pass / 1 fail，失败是 `packages/cli/tests/render-port/rss.test.ts` 的峰值 RSS 比值（TUI 渲染层，不 import 本次任何模块）；在本 worktree 单跑与父仓 main 单跑均 2 pass，成因是全量并发跑时进程内存争用。
- 真正的验收是下一周 dev 轨迹里这几类事件的计数，与 11 月文案子串计数（压力提醒 114、省略占位 90、清理占位 272+139）同量级。
