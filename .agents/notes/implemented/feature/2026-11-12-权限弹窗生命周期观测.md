# 确认弹窗的生命周期进本地轨迹：把「点不动」从猜变成一次查询

## 决定了什么

给 `PermissionDecision` 加一个 `prompt` 子结构（`PromptObservation`），由 TUI 层通过
`permission/decision-telemetry.ts` 的模块级单例上报，随决策落进会话 `events.jsonl` 的
`prompt_lifecycle` 字段（上传前由 `LOCAL_ONLY_EVENT_DATA_FIELDS` 剥掉，只留本地）。

六个字段：`queue_ms`（请求产生→弹窗首帧挂载）、`shown_ms`（首帧→决策落定）、`mounts`、
`keys`（handler 收到几个键）、`keys_dropped`（被 `resolvedRef` 吞掉几个）、
`resolve_dropped`（被 app.ts `settled` 吞掉几次）。

起因是 2026-11-12 排查「连续两个 bash 审批，第二个弹窗点不动」：轨迹里只有终态
`outcome=deny / source=timeout / duration_ms=300009`，而**四种完全不同的故障**在这条记录上
长得一模一样，最后只能靠 PTY 探针逐个场景复现去排除：

1. 弹窗压根没显示（排队等显示权时被 abort）→ `mounts=0`、无 `shown_ms`；
2. 显示了但按键没到组件（handler 未订阅 / 焦点被别处吃掉）→ `keys=0` 且 `shown_ms` 很大；
3. 按键到了组件、`onSelect` 也触发了，被 `resolvedRef` 静默吞掉（#756 的根因形态）→ `keys_dropped>0`；
4. `decide` 走了 resolve，被 app.ts 的 `settled` 去重吞掉 → `resolve_dropped>0`。

顺带纠正一个口径误解：`duration_ms` 从权限检查开始计时，**含 interactionQueue 排队**，
所以「等了 5 分钟」原本分不出是卡在队列还是卡在弹窗——`queue_ms` / `shown_ms` 拆开了这一段。

## 放弃了什么（以及为什么不选）

- **只加 `log.info("TUI:PERM", …)` 日志**：debug.log 默认不落盘（`--debug` 才写），
  用户事后没有日志可查；轨迹是默认开启且本地可查的。日志点保留，但不再是唯一手段。
- **新增独立轨迹事件 `PermissionPrompt`（显示/按键/落定各发一条）**：事件量会随按键数膨胀
  （一次弹窗几十个键就是几十行），而排查只需要聚合计数；`PermissionDecision` 本来就是
  「一条决策一条事件」，加子结构不改变事件条数口径。
- **把观测放进 `InteractionQueue` 内部**：队列只知道「拿到显示权」，不知道 React 是否真的
  挂载、按键是否到达组件——这两层恰恰是本次故障的分界点。
- **复用 `confirmVia` 的口径（`source==="user"` 才消费）**：超时（`source=timeout`）正是最需要
  这组数据的场景，所以消费条件改成 `prompted`，不用 `source`。

## 拿什么证明它生效了

- `packages/core/tests/permission/prompt-observation.test.ts`（6 个用例）锁住单例语义：
  未观测时 no-op、消费即清、重挂载只累加 `mounts` 不重算 `queue_ms`、新 `begin` 重置残留、
  没挂载过时 `shown_ms` 缺失。
- `packages/cli/tests/ui/components/permission-dialog-observation.test.tsx`（2 个用例）证明
  组件真的接上了埋点：按键到达 → `keys` 增加；resolve 后再按键 → `keys_dropped` 增加。
- **变异自证**（两次都实测）：
  - 去掉 `HotkeyChoiceList` 的 `onKeyObserved?.()` → `keys` 从 ≥2 变 0，用例红；
  - 去掉 `PermissionDialog.decide` 的 `notePromptKeyDropped()` → `keys_dropped` 从 ≥1 变 0，用例红；
  - 恢复后两文件全绿。
- 端到端：用 PTY 探针重放「两个并行 bash + acceptEdits」，检查会话 `events.jsonl` 的
  `PermissionDecision` 是否带 `prompt_lifecycle`，并核对 `keys` / `mounts` 与剧本按键数一致。
