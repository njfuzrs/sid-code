# 无头形态放行 A 档 22 个命令，并把「声明 → 行为」做成可变异自证的门禁

## 决定了什么

按《20261106-无头模式斜杠命令放行-现状缺陷与分档方案》的 T3+T4 落地（同一 PR）：

1. **22 个命令加 `headless: true`**（`packages/cli/src/command/commands/*/index.ts`）：
   - 零 ctx 依赖 8：`cache` `conflict` `diff` `doctor` `ps` `telemetry` `whoami` `workflows`
   - 纯读状态 4：`cost` `todos` `status` `checkpoints`
   - 需 T1 已修的逻辑 id 3：`insights` `perf` `trace`
   - 混合型 5（无参 dialog、必须带参）：`permissions` `config` `help` `stats` `commands`
   - 纯提示词展开 2：`batch` `plan`

2. **无头 cmdCtx 构造抽成 `command/headless-command-context.ts` 的 `buildHeadlessCommandContext()`**。
   `app.ts` 与门禁测试共用同一个函数——注入表因此只有一份事实源。

3. **新增门禁 `packages/cli/tests/command/headless-allowed-commands.test.ts`（50 用例）**，四组断言：
   - 清单一致性：真实命令表里声明 `headless` 的内置命令集合 == 22 个 + `/init`（多一个少一个都红）；
   - 放行生效：22 个命令经 `resolveHeadlessSlash` 不再返回 `error`；
   - 行为安全：每个命令用典型参数在**真实无头 cmdCtx** 下执行，结果类型不得是
     `dialog`/`confirm`/`clear`/`quit`，且不得读取注入表外的字段（Proxy 运行时探测，白名单双向相等）；
   - 混合型 5 个无参必须是 `dialog`（安全失败），不得退化成 `quit`（退 0 假装成功）。

4. **同步扩展 T1 的门禁 `packages/cli/tests/app/cmdctx-session-id-wiring.test.ts`**：
   构造点从「app.ts 两处字面量」变成「TUI 字面量 + app.ts 无头调用点 + 新模块构造函数」三处，
   扫描面扩到三个位置，断言强度不降（三处都必须传逻辑会话 id）。

## 放弃了什么（以及为什么不选）

- **不手抄一份「无头注入了哪些字段」的清单做门禁**。抄一份就会在 cmdCtx 增删字段后静默过期，
  门禁恒绿——这正是方案 §7.3 明写要避免的形态。改为抽出真实构造函数供测试直接调用。
- **不用正则扫命令源码检测未注入字段访问**。正则只扫命令自己的文件，漏掉经 `shared/` 等
  辅助模块间接访问的字段。改为 `Proxy` 包住真实 cmdCtx，运行时记录对**注入表外**字段的 `get`。
- **不把 `app.ts` 里那份 cmdCtx 字面量保留一份「给测试读」的副本**。两份注入表必然漂移。
- **不把 `compact` / `loop` 混进本批放行**。它们的价值依赖「同进程有后续轮」，`-p` 单轮下
  `compact` 净亏（摘要费 + 污染一条历史）、`loop` 是哑操作；且需要形态维度，归 T6。
- **不把 A2 档 5 个（`cron`/`lsp`/`export`/`worktree`/`hooks`）混进本批**。放行粒度是顶层命令，
  整条放行会连带放开写子命令（`/cron delete` 写盘、`/worktree clean` 删资源），等 T4b 的子命令维度。
- **没有把混合型命令的无参 `dialog` 改成纯文本默认输出**（方案 §八.3 已否决）：那是负资产，
  `helpTexts` 硬编码表已经漂移过一次（`memory --scope` 条目 vs 实际 `--global`）。
- **`HeadlessCommandContextDeps` 不 export**：它只有类型用途、零生产调用，导出会被命令体系
  门禁 G1 判成新死导出（实测从 8 涨到 9）。调用方传对象字面量即可，不需要这个类型名。

## 拿什么证明它生效了

- **新门禁**：`bun test ./packages/cli/tests/command/headless-allowed-commands.test.ts` → **50 pass / 0 fail**。
- **变异自证两轮**（仓库铁律，先改坏再恢复）：
  1. 给 `/status` 临时插一行 `ctx.setEffort?.("high")` → `missing` 断言红（失败信息里 received 多出 `setEffort`），恢复后绿；
  2. 给 `/exit` 临时加 `headless: true` → 清单一致性断言红（`+ Received + 1`），恢复后绿。
  两轮都确认门禁**报出了正确的那个命令**，不只是退出码非 0。
- **T1 门禁扩展后**：`bun test ./packages/cli/tests/app/cmdctx-session-id-wiring.test.ts` → **14 pass / 0 fail**。
- **选测**：`bun run affected-tests:run`（判定 cli 全包）→ **2912 pass / 9 skip / 1 fail**。
  唯一失败是 `render-port/rss.test.ts` 的峰值 RSS 基线，按仓库三条举证判定无关：
  ① 该测试 spawn `fixtures/rss-app.tsx`，后者只 import `react` + `render-port/components.ts` + `tty-streams.ts`，不触及命令体系；
  ② 父仓 `main` 单跑通过（2 pass），且 worktree（含本改动）单跑也通过；
  ③ 该测试用「子进程现场采样峰值 / 冻结基线」，自身注释就写明「同一实现 3 次峰值差 ±7MB」，
  2922 个测试同批跑的负载下采样偏高，单跑即绿。
- **其它门禁**：`make build` 通过（含产物自检）；`bun run lint` 0 warning/0 error；
  `format:check` 全绿；`lint:boundary` 通过；`lint:command-system` 四道全通过（死导出回到基线 8）；
  `lint:legacy-tool` 通过；`typecheck:gate` 无新增类型错误；`docs:gen-reference --check` 无漂移。
- **信息面**（方案 §五.6 要求写进 PR 正文）：放行同时作用于 `-p` / stream-json / Bridge 三形态，
  即允许 SDK 宿主与 Bridge 远端发这 22 个命令；`config`/`permissions`/`doctor`/`whoami`
  会把本机配置、权限规则、登录态返回给远端。该取舍已拍板接受（远端是可信操作员前提下侦察价值边际），
  T4b 结构体落地后可按 `modes` 单命令回退。
