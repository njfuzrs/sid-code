# 团队默认模板改为 6 家官方端点，首装缺 key 不再报错而是进 TUI 引导

## 决定了什么

- `scripts/team-defaults.template.json` 不再绑定维护者公司网关：改为 DeepSeek / Anthropic / OpenAI / GLM / Kimi / Qwen 6 家**官方端点**的当前主力模型（7 条，DeepSeek 有 pro + flash），apiKey 全是 `__YOUR_API_KEY__`；默认 `model` / `fallbackModel` / `subAgentModels` 都在 DeepSeek 内闭环；删除指向维护者服务器的 `search.searxngUrl`。
- `validateConfig` 占位符分级：当前模型已填真 key 时，其余厂商条目仍是占位符降为 warning（不再顶 `[配置错误]`）；当前模型自己是占位符 / 不在清单里仍是 error。
- 首装体验：TUI 模式缺 key 不退出，进界面自动弹**一次**向导；有预置时第一步是「选预置模型 → 只填 key」（`core/config/onboarding-preset.ts` 纯函数）：同端点占位符条目一起回填，`fallbackModel` / `subAgentModels` 里指向没 key 模型的引用改到可用模型，其余厂商条目保留。Esc 关掉后欢迎页常驻引导行；`/model` 在未配好时直接回到向导；未配好就发消息会拦截、重开向导并把输入放回输入框。headless `-p` 仍报错退出。
- 引导完成后无条件重建 fallback provider（名字没变但 key 刚被回填，启动时构建的降级 provider 仍持有占位符）。
- 注册表补 `qwen3.8-max`（否则前缀落到 qwen3.7-max 的 65K 输出上限）。

## 放弃了什么（以及为什么不选）

- **只放一家**：用户要求 6 家都列；分级告警解决了「列多家就一直报错」的副作用，没必要为此砍预置。
- **模板列全部厂商（Gemini / Grok / Ollama…）**：每多一条就多一个必然 401 的 `/model` 选项，完整清单放官网文档。
- **向导关一次弹一次**：会把「先进去看看」的用户困在向导里；改为只自动弹一次，之后靠常驻提示 + 发送拦截。
- **启动时自动删除没 key 的条目**：改写用户文件超出引导职责，且用户以后拿到 key 还得手加回来。

## 拿什么证明它生效了

- `bun test packages/core/tests/config/onboarding-preset.test.ts packages/core/tests/config/schema.test.ts packages/core/tests/migrations/team-defaults-template.test.ts` 全绿（模板守卫：引用的模型名都在 availableModels、URL 均为官方端点、无 searxngUrl / 网关域名）。
- 上一轮用空 `SID_CONFIG_DIR` + 模板起 `sc-dev`：进入 TUI 并弹向导；选 Kimi 预置填 key 后 settings.json 写入正确；Esc 路径发消息被拦截、输入回填。
- `make build` 成功；`bun run affected-tests:run` 通过。
