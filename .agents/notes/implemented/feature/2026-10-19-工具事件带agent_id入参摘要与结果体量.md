# 工具事件落盘补 agent_id、入参摘要（仅本地）与结果体量

## 决定了什么

`trace/collector.ts` 的 `PreToolUse / PostToolUse / PostToolUseFailure` 落盘 `data` 新增三个条件字段（缺席不落 null，主循环行形状只多不少）：

- `agent_id`：子代理执行链身份。hook 输入早就带（`hook/event-handler.ts` `agentFields()`），落盘时丢了。会话 20261018-230439-a41bcd77 的 406 条工具事件里 226 条属子代理，0 条可归属。
- `PreToolUse.input_summary`：白名单键（`file_path/path/offset/limit/pattern/glob/output_mode/type`、`command`，字符串截 200；`paths/file_paths` 记数量与路径）。用途是重读率、读窗重叠、读引导遵从率这类「读了哪个文件哪一段」的统计。此前只有主循环 raw.jsonl 有入参，子代理完全没有。
- `PostToolUse(Failure).output_chars`：hook 收到的 output 字符数，即「这次调用往上下文塞了多少」。

`input_summary` 加入 `trace/uploader.ts` 的 `LOCAL_ONLY_EVENT_DATA_FIELDS`，上传前剥掉（路径、命令片段可能敏感），与 `error_head` 同一机制。

服务的问题与取数计划见 docs-research `bugfixes/todo/20261019-可观测性缺口-补埋点方案.md` 的 G1。

## 放弃了什么（以及为什么不选）

- **落全量 tool_input**：体量不可控（write/edit 的 content），且敏感内容多；统计只需要定位字段。
- **落工具结果全文**：主循环 raw.jsonl 已有全文，子代理大结果有 tool-outputs 外溢文件；events.jsonl 要保持一行流可 grep。
- **input_summary 上传云端**：云端统计目前不需要路径；先留本地，需要时再按字段单独放开。
- **output_chars 取「回注模型的最终字符串」**：那一层在 hook 之后还会拼 Hook 附加上下文，口径会随用户 hook 漂；取 hook 收到的工具输出，口径只由工具决定。
