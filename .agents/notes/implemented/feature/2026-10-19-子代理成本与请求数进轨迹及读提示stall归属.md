# 子代理成本与真实请求数进轨迹，read 提示与 stream_stall 带归属（G2/G3/G4/G6）

## 决定了什么

- G2：`agent/usage-sink.ts` 每次给子代理入账后落一条 `SubagentCost` 事件（agent_id / model / cost_usd / tokens / api_requests），金额就是 `SessionState.updateUsage` 刚入账的那个数（`updateUsage` 现在返回本次 cost），不另算。collector 累加 `metadata.subagent_cost_usd` / `subagent_api_calls`，traj 与 digest 都展示。`total_cost_usd` 运行中语义不变。
- G6：`SubAgentResult.apiRequests` 由持有入账票据的三个调用方（agent/tool.ts、agent/custom.ts、workflow/sub-agent-runner.ts）按 `UsageSinkTicket.claimedCount` 回填；`updateUsage` 新增 `requestCount` 参数（主循环缺省 1）。⟳ / /stats / SessionEnd 统计从「一个子代理算 1 次」变为真实 HTTP 次数。拿不到票据时按 1 计并在事件里标 `api_requests_exact: false`。
- G3：`tool/read.ts` 两类引导提示（`repeat_narrow` / `narrow_first`）经模块级 sink 落 `ReadHint` 事件，子代理带 agent_id（hook 作用域 ALS）。路径用专用键 `hint_file_path`，加进 uploader 的 LOCAL_ONLY 名单，不上传。
- G4：fallback 给 `stream_stall` / `stream_completed` 附 `turnIndex`（及旁路的 `caller`），collector 映射成 `pair_index`（主循环）或 `agent_turn`（子代理，20000 号段另标 `agent_summary_turn`）。旁路调用和映射不到的不补。
- G5 不做，见下。

## 放弃了什么（以及为什么不选）

- G2 逐条 `BilledRequest.cost_usd`：要把计价函数接进 stream-observer，改动面大；按子代理粒度已能回答 Q5（成本按子代理重建）。需要定位到单次 fetch 时再做。
- 让 `total_cost_usd` 运行中就含子代理：历史曲线断层。改为新增字段，消费侧按 `cost_scope` 判断是否已含（`main+subagent` 时不能再加）。
- G6「保留现值，只改 ⟳ 标签」：「每请求成本」等派生口径会继续偏。代价是请求数曲线在本版本整体上移（本会话实测 52 → 103），发版说明须写明分母变化。
- G3 用通用 `file_path` 键：放进 LOCAL_ONLY 名单会误剥别的事件，所以用专用键。
- G5 全量落子代理 raw：体量约为主循环 3 倍。G1 的入参摘要 + 结果体量已覆盖 Q1 需要的读窗信息，先观察是否够用。
