# 无头模式补注 B 档 6 个命令的上下文并放行

## 决定了什么

方案《20261106-无头模式斜杠命令放行》T5 落地：`effort` / `think` / `language` / `model` /
`goal` / `memory` 六个「可放行但必须先补注入」的命令，补齐无头 cmdCtx 的注入面后声明
`headless: true`。

- **注入面扩 15 个字段**（`packages/cli/src/command/headless-command-context.ts`）：
  `getEffortState` / `setEffort` / `getThinkingState` / `setThinking` / `setLanguage` /
  `setFallbackModel` / `setSubAgentModel` / `getGoalState` / `setGoalState` /
  `updateGoalState` / `setAutoMemory` / `getAutoMemoryState` / `setExternalImportsApproved` /
  `getExternalImportsState` / `notify`。deps 字段**全部必填**：漏搬一个应当是类型错误，
  而不是运行时静默降级回「可选链跳过 + 照旧报成功」。
- **`notify` 映射到 stderr**（而非丢弃或 stdout）：它是命令层一次性提示（`/goal` 的
  「评估者 = 主模型」），无头没有状态栏；stdout 是答案/结果通道，混入提示会破坏下游解析。
- **`/goal` 的三个回调抽成 `App.goalCommandHooks(updateState?)`**：TUI 与无头共用同一份
  实现，`updateState` 只在 TUI 传。此前 TUI 构造点内联三行，无头再抄一份会迟早在一侧
  漏掉 `persistGoalState()`——goal 状态丢了 resume 就恢复不出来，属于静默损失。
- **放行 6 个命令**（各自 `index.ts` 加 `headless: true`）；`statusline` / `vim` / `rename`
  仍不放——它们改的是 TUI 运行时态，补了也无头无意义（方案 B 档表后半）。
- **门禁 `headless-allowed-commands.test.ts` 扩到 93 用例**：清单断言并入 B 档 6 个；
  行为断言（不产出 dialog/confirm/clear/quit、不碰注入表外字段）覆盖 B 档；
  新增「字段真的被命令用到」三条探针（`/goal <objective>` 走 setGoalState+notify、
  `/effort high` 走 setEffort、`/memory auto on` 走 setAutoMemory）；B 档无参 dialog
  单独锁（`effort`/`think`/`language`/`model`/`memory` 是 dialog，`goal` 无参是 text）。
  同时**删掉 `DEGRADATION_ALLOWLIST.status` 的 `getEffortState` 条目**——该字段已注入，
  白名单留着就等于没人发现「`/status` 不再降级」。

## 放弃了什么（以及为什么不选）

- **不补 `statusline` / `vim` / `rename`**：它们改 TUI 运行时态（状态栏文案、Vim 输入模式、
  会话标题），无头进程里没有消费方。补注入等于制造新的「接线了但没人看」的死路。
- **不在 `app.ts` 手写一份 setter 逻辑**：直接复用 App 上已有的
  `setEffortRuntime` / `setThinkingRuntime` / `setLanguageRuntime` / `setFallbackModelRuntime` /
  `setSubAgentModelRuntime` / `setAutoMemoryRuntime` / `applyExternalImportDecision`。
  无头与 TUI 的差异只在「有没有状态栏」，runtime/config 写入路径必须同一条
  （各自发 `persistKnob` / `persistAgentSetting`，两处漂移会导致一侧 resume 恢复不到档位）。
- **不按形态（T6 的 `modes`）限制这 6 个命令**：它们的价值不依赖「同进程存在后续轮」。
  `-p` 单轮下 `/effort high -p` 仍真实写 settings.json（下次启动即生效），`/language en -p`
  会重建系统提示词（本轮之后的模型调用即用），`/model fallback` 改的是 fallback 引擎
  当前读取的 config。方案把 `compact` / `loop` 单列 T6 的理由是「`-p` 下净亏/哑操作」，
  这 6 个不成立。
- **不给无参 dialog 加纯文本默认输出**：沿用 §八.3 拍板。`headless-dispatch` 把
  `dialog` 翻成非 0 的明确报错就是设计好的 fail-closed；补一份手写默认输出等于维护
  第二份易漂移的文案（`help.ts` 的 `helpTexts` 已经漂移过一次）。
- **不在测试里用 `{...CTX}` 展开构造 deps**：`CTX` 是 `CommandContext`（构造结果），
  与 `HeadlessCommandContextDeps`（构造入参）类型面不同，展开会被 tsc 拒；改为抽出
  `HEADLESS_DEPS` 常量，探针从 deps 出发只覆盖一两个字段。
