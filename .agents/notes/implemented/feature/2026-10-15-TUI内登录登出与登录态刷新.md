# TUI 内新增 /login /logout /whoami，登录态变更后会话内刷新企业状态

## 决定了什么

- 新增三个内置命令 `/login [cancel]`、`/logout`、`/whoami [--verify]`（`packages/cli/src/command/commands/{login,logout,whoami}/`），核心流程复用 core 的 `performCliLogin` / `performCliLogout`，不复制。
- `/login` 拿到授权链接就立即返回，授权在后台等，结果走 `ctx.notify` 报到状态栏；同一进程内只允许一个登录流程，重复执行返回同一链接。已登录时、登出前都走 `confirm`。
- 登录状态的采集与渲染从 `auth.ts` 下沉到 `packages/core/src/identity/login-status.ts`，`sid-code auth status`、`/whoami`、`/status` 共用。CLI 输出逐行不变；`--verify` 额外显示组织 / 团队。
- `credential.ts` 新增 `onCredentialChanged`（只在凭据明文变化时触发，credential-sync 只续期过期时间不触发）、`onCredentialRejected` + `reportCredentialRejected`（每一代凭据最多通知一次），以及凭据代数 `getCredentialGeneration()`。
- 策略 / 预算 / 账本 / 事件四条通道的 401 都调统一上报点；事件与账本的「401 / 无凭据只告警一次」改为按凭据代数去重，重新登录后凭据再失效时用户能再看到告警。事件导出器只在本批带的是设备凭据（不是 authHeader 兜底）时上报。
- 新增 `reloadEnterprisePolicy()`、`reloadRemoteBudget()`。app 层 `wireEnterpriseLoginRefresh` 订阅凭据变更：重载策略 → `applyLoadedPolicy` → `initRules` → 重新应用 Hook 门控 → 当前权限模式被禁用则拨回 default；重载预算；重放账本失败盘。订阅 401 与「启动时配了 backend.url 却没登录」各推一次状态栏提示。
- 官网新增 `website/team/login.md`，侧边栏排在配额前；隐私页、policy/defaults/quota/plugins/mcp 各加一句链接。PR-4 与 PR-5 合成一个 PR：`docs-gen-reference --coverage-strict` 在提交时要求新命令必须有指南页提到，分开提 PR-4 过不了 pre-commit。

## 放弃了什么（以及为什么不选）

- **`/login` 做成 local-jsx 对话框**：不需要。`notify` 是闭包、每次调用才读实例上的 statusNotifier，命令返回后调用是安全的（方案 §8 第 3 条），普通 local 命令加后台 Promise 足够，少一套 UI。
- **用 `/auth` 或给 `/whoami` 加 `/account` 别名**：`/auth` 已是 MCP 认证别名；`/account` 会和将来的模型账户概念混淆。
- **登录后重建系统提示词里的 deny 摘要**：会打断 prompt cache（伤「更省」）；权限检查本身已热更新，模型被拦时会收到拒绝结果。
- **登出时清掉已加载的远程策略**：登出不应成为绕过企业管控的手段。登出也走同一条重载，远程策略有缓存兜底。
- **状态栏常驻登录标记**：Footer 两行已满，登录态很少变化，只在未登录和 401 时临时提示。
- **告警去重标记在 onCredentialChanged 里逐个重置**：要给每个模块加一个公开重置函数；按凭据代数比较只需一个读函数，且对事件导出器这种多实例也成立。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/identity/login-status.test.ts`：9 pass（变更事件只在换凭据时触发、订阅方抛错不影响落盘、401 每代只通知一次且重新登录后再通知、状态采集默认零网络请求、`--verify` 带出组织团队）。
- `remote-budget.test.ts` 新增两条：启动未登录后 `loadEnterpriseBudgetOnce` 不再拉取，登录后 `reloadRemoteBudget` 真的发请求并生效；401 走 `reportCredentialRejected("budget")`。
- `bun test ./packages/cli/tests/command/login-commands.test.ts`：/login 立即返回含 `port=` 的授权链接、重复执行返回同一链接、cancel 后状态栏报「已取消登录」；/logout 确认前零请求、确认后调 `/cli/logout` 并删本地文件；/whoami 默认零请求、`--verify` 调 whoami；/status 显示「企业登录: 张三」。
- `auth-status.test.ts` 原有用例全绿，证明 CLI 输出未变。
- 未验证（需真实飞书账号与线上后端）：方案 §7 端到端第 1–4 条，特别是 TUI 内登录后同一会话七条通道全绿、预算生效。
