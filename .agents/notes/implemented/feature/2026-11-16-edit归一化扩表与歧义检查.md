# edit 字形归一化扩表 + 归一化歧义检查

## 决定了什么

`packages/core/src/tool/edit.ts` 的 `normalizeQuotes`（只映射弯引号）换成
`normalizeForMatch` + 一张逐字符映射表，仍然严格 1:1（长度不变），覆盖四类变体：

- 弯引号 U+201C/201D、U+2018/2019 → `"` `'`（原有行为）
- 破折号 U+2010–2015、U+2212 → `-`
- Unicode 空格 U+00A0、U+2002–200A、U+202F、U+205F、U+3000 → 空格
- 全角 ASCII U+FF01–FF5E → U+0021–007E（含 `：` `（` `）` `，`）

同时修掉扩表后才会暴露的**静默漏改**：原实现用 `indexOf` 取第一处归一化命中、切出
`actualOld` 再精确替换，不同原文（`x—y` 与 `x-y`）归一化撞车时另一处被无声忽略。
新实现 `tryNormalizedMatch` 按命中位置的 **distinct 原文形态** 分三支：

- 只有一种形态：等价精确匹配（保留「找到 N 处匹配」的既有报错，不误报歧义）；
- 多种形态 + `replace_all=false`：返回 `occurrences=-2`，上层报专门的「归一化歧义」文案
  （建议 `replace_all=true` 或补上下文，不复用「模糊匹配歧义」）；
- 多种形态 + `replace_all=true`：按位置逐处替换，不允许只换一种形态。

判据**不是**「命中次数 > 1」：文件里多处字面完全相同时它也成立，而那种情况现状报的
「找到 N 处匹配」是准确的。

## 放弃了什么（以及为什么不选）

- **不做 NFKC**：NFKC 会把 `…` 拆成 `...`、把连字 `ﬁ` 拆成 `fi`，长度变化会破坏
  「归一化串下标直接映射原文」的前提，slice 出错误子串会污染前后文。只取 NFKC 里
  1:1 的全角 ASCII 段。
- **不用 `count(quotedContent, quotedSearch) > 1` 当歧义判据**：文件里多处字面相同的
  直引号串（中文文档很常见）也成立，会把准确的「找到 N 处匹配」误报成「模糊匹配歧义」，
  而后者建议的「提供更精确的 old_string」对本来就是精确的 old_string 帮不上忙。
- **不在本 PR 一并做 T2（归一化命中后保留原风格）**：用户本次只点名 T1。代价明确记录：
  T1 单独上线时，全角标点命中后写入的仍是模型的半角 new_string（`错误：文件过大` +
  old `错误:` → `错误!文件过大`），已在测试里用「已知缺口（T2 才修）」显式锁住现状，
  T2 落地时该条要反过来改断言。
- **不复用 `fuzzy` 策略名承载归一化歧义**：`deferUnreadCheck` 会把非 exact/normalized
  的策略当成近似匹配先拒，报出的就不是歧义本身的诊断。歧义结果显式标 `normalized`。

## 拿什么证明它生效了

- 单测 `packages/core/tests/tool/edit-normalize-for-match.test.ts`：14 条全绿，
  覆盖每类字符命中、distinct 撞车报错且不改文件、多处字面相同仍报「找到 N 处匹配」、
  `replace_all=true` 全替换（不同原文形态）、1:1 长度不变量（固定边界样例：`…`/`ﬁ`/
  emoji/组合字符 + 表内每条 key 长度为 1）、事件仍报 `normalized`。
- 相关三文件 `edit*.test.ts` 合计 49 pass / 0 fail；`bun run affected-tests:run`
  1630 pass / 0 fail；`make build` 成功且无 `will always be undefined` 告警。
- **变异自证两次**：① 从表里移除全角 ASCII 段 → 全角命中与已知缺口两条变红（12 pass /
  2 fail），恢复后全绿；② 把多形态 `replace_all` 分支换成「只替换第一种形态」→
  「两处原文不同 + replace_all=true」一条变红（13 pass / 1 fail），恢复后全绿。
- **轨迹回放（保守口径）**：两个 luna 主会话里 `edit` 的「未找到要替换的字符串」共
  **75 次**（51 + 24），其中 `old_string` 含全角 ASCII 42 次、弯引号 4 次、破折号 0、
  Unicode 空格 0（任一类 42）。端到端回放（用会话中同内容版本的 read 片段拼接成连续
  区块，`new EditTool()` 重放）结果：命中 0（normalized）/ 71 个无法判定（old_string
  落在从未读到的区域）/ 1 个无片段 / 3 个在拼接内容上精确命中但内容版本可能被会话里的
  bash 改过，不计入。结论与文档预期一致：T1 的收益在「造出来的 fixture」与未来真实触发，
  历史回放给不出正收益证据；合入依据是单测 + 变异自证。
