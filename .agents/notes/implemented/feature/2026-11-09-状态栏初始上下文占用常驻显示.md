# 状态栏初始上下文占用常驻显示（打开 TUI 即可见，不再等首条消息）

## 决定了什么

用户诉求：打开 TUI 后、没发任何消息前，footer 状态栏看不到上下文占用，必须发一条消息让循环转起来才显示；想知道一打开时的初始占用。四个配套改动：

1. **显示条件与 usage 解耦**（`useStatusLineData.ts`）：context 列的隐藏条件从
   `usage.inputTokens === 0 && usage.outputTokens === 0`（"没发过请求就藏"）改为
   `contextPercent <= 0`（"估算为 0 才藏"）。打开 TUI / 刚 /clear 时 usage 全零，
   但常驻开销（system prompt + 工具 schema）的估算已在——首帧 StateBridge 构造时
   `runTUI` 已注入 `...this.contextDisplayState()`（`await this.init()` 在先，
   setSystemPrompt 已完成），数字本来就有，只是被显示条件藏掉了。
   语义分工变为：context 列 = 窗口占用估算（始终在），tokens 列 = 真实 API usage
   （调过模型才显示，隐藏条件不动）。
2. **未校准估算加 `~` 前缀**（改动 4）：数据链
   `manager.getContextUsageForDisplay` 新增 `calibrated` 字段 → `app.contextDisplayState()`
   → `TUIState.contextEstimated` → `deriveContext` 纯函数。会话没发过请求时
   estimateTokens 是纯字符启发式（0.2/0.65 tok/char），误差可能 ±20%；首条消息后
   recordActualTokens 校准，前缀消失、数值可能跳变——`~` 让用户看出那是校准不是凭空涨。
3. **/clear 回落到初始占用而非隐藏**：调用点（`app.ts` handleCommandExecutionResult）
   在 `getConversationClearedPatch()` 之后 merge `this.contextDisplayState()`。
   /clear 只清消息历史，常驻开销还在；patch 里的 `contextPercent: 0` 降级为哨兵值
   （未来新增不 merge 的调用点兜底），`contextEstimated: false` 哨兵同理。
4. **工具池变化后刷新**（既有缺口顺带修）：`Registry` 新增 `onChange` 广播
   （queueMicrotask 去抖，MCP 连上后循环 register 几十个工具只广播一次），
   register / removeByPrefix / removeByNames / retainBuiltInByNames 在**实际改变了
   工具集合**时触发。App 构造函数订阅：刷新 `refreshToolSchemaTokens()`（此前全仓
   只在启动时算一次，MCP 连上后 schema tokens 持续偏低、compact 触发过晚）+
   经 `tuiStateUpdater` 推送占用。无头模式 tuiStateUpdater 为 null，只刷新 schema tokens。

## 放弃了什么（以及为什么不选）

- **不改 `getConversationClearedPatch` 的硬编码 0 为"现场重算"**：它是纯函数、无 this
  访问，把估算逻辑搬进去要么给它传 ctxMgr（破坏它"纯 patch 工厂"的定位），要么在
  内部 import App（循环依赖）。调用点 merge `contextDisplayState()` 一行解决，
  patch 里的 0 降级为哨兵。
- **不用 `unifiedRegistry.onCommandsChanged` 做工具池变更信号**：它广播的是**命令集合**
  （斜杠命令补全），与工具池是两个事实源——MCP tools/list 变化时命令未必变（无 prompt
  时），MCP prompt 变化时工具未必变。schema tokens 的口径是工具定义，挂错源会出现
  "工具变了估算不刷"。`Registry.onChange` 与工具池同源。
- **不在 estimateTokens 里做增量/缓存来省广播成本**：订阅方每次全量重算 schema tokens
  是 O(工具数) 一次序列化，微任务去抖后每批次一次，量级足够；为省这点计算引入缓存
  失效问题（MCP 重连换 schema）不值。
- **`~` 前缀只标 used 百分比，不标触发点**：触发点由窗口算出（maxTokens 与 buffer 系数），
   是确定值，不参与估算。
- **保留 `deriveContextColor` 不动**：变色逻辑（level 优先、缺省回退百分比阈值）
  与显示条件正交，本次只动"显不显示"，不动"显示什么颜色"。
