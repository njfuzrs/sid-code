# 引导规则后效报告：nag 后首工具、ReadHint 后读法、清理后同签名重跑（按模型拆）

## 决定了什么

新增 `scripts/aftereffect-report.ts`：从 events.jsonl 派生三个「规则触发之后模型做了什么」的指标，按会话内最近一条 `BeforeModel.model` 归组。只读轨迹，不改任何运行时代码。

1. **nag 后第一个工具**：`NoProgressNagInjected` → 同会话下一条主循环 `PreToolUse`，按工具名分桶，单独给出 `todo_write` 占比。
2. **ReadHint 后同文件下一次 read**：`followed`（整读）/ `still_narrow`（仍传 limit/offset，再拆出起始行落在提示窗口内的 `still_narrow_overlap`）/ `no_reread` / `not_applicable`（`suggest_full_read≠true`）。
3. **清理后同签名重跑**：`ToolResultCleared.tool_use_ids` → 被清调用的签名（工具名 + `input_summary` 键排序 JSON），在清理之后 `RERUN_WINDOW_TOOLS=10` 次工具调用内再次出现即算重跑。依赖 HB-4（#726）的新事件，之前的会话这一项渲染为「没有这一项」而不是 0%。

模型归属、tmp 会话剔除、事件读取复用 `defense-trigger-report.ts` 的导出（`iterSessionEvents` / `isTmpCwd` / `defaultTmpRoots`），两份报告的口径不会漂开。

## 放弃了什么（以及为什么不选）

- **塞进 `northstar-snapshot.ts`**：那份脚本读的是 session-index / usage-ledger 这类会话级汇总，事件级派生要逐会话扫 events.jsonl（本机 11 月约 960 个会话、2.6s），会把每次快照变慢，而且快照进 release 曲线、口径冻结规则更严。后效指标还在定口径阶段，先独立成脚本；稳定后再由快照引用其数字。northstar 的模型维度（⑪）另做。
- **ReadHint 只分 followed / still_narrow 两档**：11 月实测 `narrow_first` 之后的下一次读里，往后换段 135、往前换段 106、同段重叠 47、整读 7（独立脚本复核）。不拆重叠的话，「仍窄读 27%」会被读成「提示无效」，实际大部分是正常推进的换段读。
- **按会话内时间窗（N 秒）判重跑**：工具调用间隔从毫秒到几分钟不等，时间窗对快模型偏宽、对慢模型偏窄；按工具调用次数计数与「N 轮内」的原始口径（01 §2.2）一致。
- **子代理调用也进统计**：nag / ReadHint 事件的 agent 归属不全，混进来会把子代理的工具错配成主循环 nag 的后效。
- **加 `package.json` 脚本入口**：`defense-trigger-report` 同样没有；改 `package.json` 会让 affected-tests 判定为仓库级全量。

## 拿什么证明它生效了

- `bun test ./tests/scripts/aftereffect-report.test.ts`：13 pass。
- 变异自证（各改一处跑上面的测试）：去掉 `hasLimit` 判据 → 1 fail；`after` 不截断到事件之后 → 5 fail；重跑窗口不限长 → 1 fail；不过滤子代理 → 1 fail；重叠判据去掉上界 → 1 fail（第一次变异因 oxfmt 换行没命中、0 fail，用 `diff -q` 确认文件确实变了之后重做才红）。
- 本机真实数据（`bun scripts/aftereffect-report.ts --since 2026-11-01`，836 会话，剔除 tmp 124）：
  - `nag[todo]` 之后首工具 `todo_write` 23.9%（924 次），`nag[work-log]` 11.1%（1057 次）；deepseek-v4-1-flash 24.6% vs opus 12.8%。01 §2.3「催促主要换来补记账」在 todo 通道上约四分之一成立，不是多数。
  - `ReadHint[narrow_first]` 1067 次：整读 0.6%、仍窄读 26.9%（同段重叠 4.4%）、未再读 72.5%。提示「可整读」几乎从不被采纳，但同段重复读也很少 —— 这是 ⑰ 读写提示 A/B 的基线。
  - 清理后重跑：`ToolResultCleared` 从未出现（#726 合入并 `make build` 后开始积累）。
