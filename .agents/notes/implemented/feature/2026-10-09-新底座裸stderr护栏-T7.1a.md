# 新底座裸 stderr 护栏（B9 / T7.1a）

## 决定了什么

规则全部来自对 legacy 的黑盒探针（16 组），没读旧底座代码（D-5）。探针脚本与输出备份在 `~/Backups/sid-code-t67-probe-results-20261008/T7.1a/`。

- 新增 `packages/tui/src/stderr-guard.ts`，`ink.tsx` 构造时**无条件**调用 `patchStderr()`，与 TTY、`patchConsole`、`debug` 选项、stdout 是哪个流都无关；只换全局 `process.stderr.write`，不碰 `options.stderr`。
- **吞掉**：底层流 0 字节，恒返回 `true`，回调同步、无参调用。**不擦屏、不重绘**，主屏和 alt 都是，下一帧照常增量 diff。
- **debug 日志**：`SID_CODE_DEBUG` 在模块加载时恰为 `1` 或 `true` 才写 `console.error("[ink] [stderr] " + 文本, {level: "warn"})`。大小写和空白都敏感。字符串忽略 encoding 参数，其余按 UTF-8 解码；非法 chunk 先调回调、再抛 TypeError。
- **重入守卫（E2）**：日志路径里再写 stderr 时直接交给原始 write。日志抛错时，回调照调、错误上抛、守卫复位。
- **卸载**：在卸载一开始、React 清理之前还原，所以 effect 清理里写的 stderr 会直接落地。只有 `process.stderr.write` 仍是自己时才还原：多实例按顺序各自还原，乱序卸载会留下前一个拦截器（与 legacy 一致），别人后来换掉的不动。

## 放弃了什么

- **SPEC 原描述的「alt 下强制全量重绘」**：探针证明 legacy 没有这个行为（吞掉后一个字节都不写）。照描述实现会让 S10 红。SPEC E1 已按实测改写，契约测试里有一处变异专门钉住「不重绘」。
- **复用上游 `patchConsole`**：它只拦 console，拦不到裸 `process.stderr.write`，而且 CLI 有意传 `patchConsole: false`（见 `console-guard.ts` 头注释）。
- **乱序卸载时修复成「最后一个卸载才还原」**：属于行为变更，CLI 生产路径只有串行交接（会话选择器 → 主 TUI），没有收益，就照 legacy 保留。
- **E3（EIO / EPIPE）**：底座不处理，靠 CLI 在 render 之前注册处理器，`contracts-runtime` 的 E3 两条在 next 上本来就绿，本任务不动。

## 拿什么证明它生效了

- 新契约 `packages/cli/tests/render-port/stderr-guard.test.tsx` 共 15 条（E1 ×13、E2 ×2），夹具 `fixtures/stderr-guard-app.tsx` 在子进程里跑。每条先断言 legacy 等于写死的期望，再断言 next 与 legacy 一致，两套底座都是 15/15。SPEC 的 E1 / E2 改为指向它。
- 变异自证 17 处全红：不安装、不记日志、debug 大小写不敏感、debug 去空白、无重入守卫、回调带 null、回调异步、返回 false、透传不吞、无条件还原、守卫不复位、抛错不调回调、Buffer 按 latin1、字符串按 encoding 解码、React 清理之后才还原、拦 options.stderr、alt 下强制重绘。
- **S10 在 next 上转绿**。render-port + tui：legacy 1050/1050；next 1045 pass / 5 fail（M5 ×2、O5、X7、S13，都归别的子任务），比基线少了 S10，没有新增。
- `make build` 通过，无 undefined 警告；`lint`、`format:check`、`lint:boundary`、`tui:spec`、`tui:similarity`、`docs:gen-reference --check` 都通过；`tsc` 87，与基线相同。
