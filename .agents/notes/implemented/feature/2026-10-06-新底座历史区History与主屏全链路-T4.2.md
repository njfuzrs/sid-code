# 新底座历史区 History 与主屏全链路（B9 / T4.2）

## 决定了什么

- **新写 `History` 组件，端口 next 以 `History as Static` 导出**。CLI 调用点（MainScreenLayout、S3 场景）不动。
  它就是浅比较 memo 包住的竖排 Box：项是普通子树，内容变了照常 reconcile，没变的行靠帧 diff 零写入，
  滚进 scrollback 的历史自然留在终端里。memo 只比 `items` / `children` / `style` 三个引用，任一变了就整块重渲；
  不补 key，不去重，参与正常布局（会被父级高度挤压、能放进横排容器）。这些边界全部在 legacy 上黑盒对拍得出，没有读旧代码。
- **S3 在 next 上的差异不在 History，在屏幕层**。逐条二分，最后定位到两条 T3.1 / T3.2 没覆盖到的规则：
  1. **「看不见的空格」**：整行输出（首帧 / 追加 / full reset）且屏幕至少 2 行时，如果空格的样式和当前画笔相同，
     而这种样式下空格看不出来（前景色、粗体、暗、斜体、闪烁、隐藏、双下划线、下划线颜色），旧底座就把它当默认空白，
     用 `CUF` 跳过。背景色、反显、下划线、删除线、上划线，以及原样留在样式里的链接码会让空格可见，这几种照写。
     行首第一个这样的空格要先切样式，照写。增量帧里变化的单元一律照写，因为要盖掉旧内容。
     单行屏照写空格，T3.1 的单行语料就是这样钉住的，所以当时没暴露。
  2. **多个变化段共用一支笔**：两段之间只移光标，样式和链接不关。最后一段写完才收笔；收缩时在回到第 n 行之后收。
- 语料：屏幕层加 20 条，帧层加 11 条，向量从 legacy 重生成（217 / 97 条）。**原有条目一字节未变**，脚本逐键核对过。
- **阶段 4 出口的 S3 部分**：新增组件级场景 C1 / C2（`term-bench/component-scenarios.tsx`），挂真实的
  `HistoryItemDisplay`（user / tool_group / assistant），按 MainScreenLayout 的骨架排成历史区加动态区，
  legacy 与 next 当场差分。C2 把执行中的 tool_group 挤进 scrollback 后再让它完成，钉住「恰好一次 full reset」（R5）。
  完整 App 级 S 场景在 next 上要等阶段 5 的 stdin。

## 放弃了什么（以及为什么不选）

- **把已进 scrollback 的历史排除在每帧布局之外**（T3.4 移交过来的 P3 问题）：和 D-3 定案 A 冲突。
  R5 要求屏外项一变就 full reset，按完整内容重画（含 scrollback），这需要整棵历史树仍在布局里。
  排除出去以后，要么 full reset 时临时补布局（延迟落在最不该慢的那一帧），要么屏外项完成时画不出终态，退化成 print-once。
  现在 next 的帧耗时约为 legacy 的 1.7 倍，P2 的 1.1 倍门槛要等 S1 能在 next 上跑（阶段 5 后）才判。真超了再单独立项，不在这里预支。
- **直接 re-export 上游 `<Static>`**：print-once 语义，工具行会永远停在执行中。`next-switch.test.ts` 加了源码断言，
  不改名地导出 `Static` 会红。
- **在 History 里给项补 key / 去重**：legacy 不做，补了会改变 CLI 侧 key 冲突时的表现。
- **把「看不见的空格」做成按样式白名单逐码判断以外的形式**（比如只看「有没有背景色」）：下划线 / 反显 / 删除线 / 上划线
  也让空格可见，只看背景会少写这几种。规则按 SGR 首参数分类，变异「下划线算看不见」能抓到。

## 拿什么证明它生效了

- S3 在 next 上，五个步骤的网格、scrollback、光标、字节数、full reset 次数全部与 legacy 一致。只剩「(退出后)」那一步的 OSC 计数不同，那是卸载生命周期，属于 T7.x，和 E 场景同一口径。
  S1 / S2 / S4 / S5 / S6 在 next 上也逐步一致。
- R11 三条在 next 上转绿；新增 memo 口径一条（调用次数序列 `2,2,4,6,6,8`，两边一致）。C1 / C2 双底座一致。
- next 上 render-port 的失败集合从 31 条降到 25 条：转绿 7 条（R11 ×3、R12、C 组 ×3），新增 0 条。
  `next-switch` 的占位样本从 Static 换成 AlternateScreen（T6.1）。
- 变异自证 11 处全红：去掉 memo、改成 print-once、去掉默认竖排、看不见的空格恒假、下划线算看不见、背景色算看不见、
  单行屏也跳过、行首空格也跳、每段各自收笔、收缩时先收笔再下移、端口直接导出上游 Static。改动用 sha256 核对后已还原。
- `tui:spec`（58 条，55 条已测）/ `tui:similarity` / `lint:boundary` / `lint` / `tui:screen-vectors --check` / `tui:frame-vectors --check`
  / `docs:gen-reference --check` 全过；tsc 错误数与 HEAD 相同（71，逐条比对无增减）；`make build` 通过，无 undefined 警告。
- 全量 14163 pass / 1 fail：失败的是 `contracts-termio` 的 O6（这次是 win32 那条），全量负载下子进程超时，单跑 3/3 通过；本任务没碰 termio，T3.4 / T4.1 时也是同一组。
