# 三道门禁把构建身份接成判据：编进去了不等于有人在读（方案 PR-B + PR-C）

## 决定了什么

PR-A 只做到「身份编进字节、能读回来」。**一个没人读的字段等于没有这个字段** ——
本仓已经有过一次「四环防线全在、调用全 0」，所以这一轮的全部内容是**接线**：
把那 40 位 commit 接成三处会拦人的判据。

**G1（评测前置，`exec-swebench.sh`）** —— 替换掉原来的 `warn_if_stale_artifact`。
判据从「产物 mtime 比 HEAD 提交时间老」换成「产物**自报**的 commit ∈ 当前历史，
**且此后没改过任何编译输入**」。五档 verdict：`ok` / `stale` / `foreign` /
`unknown-commit` / `sidecar-mismatch` / `no-identity`。两个逃生舱**刻意不合成一个**
（`SWE_ALLOW_STALE_ARTIFACT` = 我要跑旧的，`SWE_ALLOW_FOREIGN_ARTIFACT` = 我要跑别的分支），
`unknown-commit` / `sidecar-mismatch` **没有**逃生舱 —— 那两个是数据本身有问题。

**G2（发布通道，`release.sh`）** —— `--upload` 前三条：`origin == release`（拦手工编的包）、
dirty 时脏文件只能是 `package.json`、`commit == v<ver>^`。`--promote` 前一条：
产物 commit 必须是 main 的祖先。后两条按直觉写会**100% 误拦每一次真实发版**：
本脚本的顺序是 洁净门禁 → bump（改 `package.json` → 工作区变脏）→ **构建** → 提交 → 打 tag，
所以构建那一刻 `git status` 必非空、HEAD 是 bump 提交的**父**提交。
连带把 `CLAUDE.md` 里那条人工核验（`git merge-base --is-ancestor v<ver> main`）机械化了。

**判定逻辑只有一份**：`scripts/lib/artifact-identity.ts`，bash 侧经
`scripts/artifact-identity.ts` 这个 CLI 桥调用（退出码是跨语言契约）。
三份 bash 各自漂移的形态是「门禁看起来在跑、实际全在放行」。

配套三件：`artifact_for()` 的默认查找从「版本号对应的包」改成「**当前 commit** 对应的包」
（`dist/branch-builds/<slug>-<commit12>/`），所以起因那个形态在**挑选阶段**就不会发生；
`scripts/build-branch-artifact.sh` 是编这种包的唯一入口（baseline target + 两个 define +
三个生成脚本 + 编完自证身份可读回）；`scripts/prune-branch-builds.sh` 回收空间，
**默认 dry-run**、判据是「commit 还被引用吗」而**不看 mtime**。

`run-meta.json` 把两个 commit 分开记（`artifact_commit` 是事实源，`host_head_commit` 仅供对照），
`git_commit` 作为旧别名保留 —— `grade.ts` 优先读新字段、回退旧字段并在报告里标明
「该 run 早于构建溯源」。**历史 run 的数据不能被静默重新解读成新语义。**

## 放弃了什么（以及为什么不选）

**放弃「编一次再比 sha256」**（最完备的判据）。它要几十秒到几分钟，而这是**每轮评测的前置**。
把一个几分钟的构建塞进门禁，结果是有人为了跳过它而常态化 `SWE_ALLOW_STALE_ARTIFACT=1` ——
那时连「忘了重编」都不防了。选的是「快而不完备的检查（毫秒级）+ 完备但事后的手段
（要复算某轮时按 `artifact_commit` 重编、比 `artifact_sha256`）」。

**放弃要求评测产物 `origin=release`**。评测是发版的**前置门禁**不是后置验收，
要求「先发版才能评测」会死锁。所以 G1 刻意只关心「这个包含不含你要测的 commit」，
G2 才管 origin。这两道门的判据不同是有意的。

**放弃把构建挪到 bump 提交之后**（那样 dirty 就真是 false、commit 就真是 bump 提交，
G2 两条判据都能按直觉写）。当前顺序是「构建失败时不留下 bump 提交」这个性质的来源，
`track_for_rollback` 建立在它之上。动它要单独论证，不搭在这个 PR 上。

**放弃保留 mtime 判据作为主路径**。它两个方向都会错：`cp old new` 重置 mtime →
内容一字未改而放行（假阴性，而 `cp` / 下载 / `docker cp` 正是最常见的搬运方式）；
docs-only 提交推进 HEAD 时间 → 好产物被拦（假阳性）。假阳性的代价不是多敲一次命令，
**是训练人绕过门禁**。mtime 只作 `no-identity` 时的兜底，且必须显式记
`identity_source=mtime-fallback`。

**放弃 `--keep` 判据用 mtime**（清理脚本）。同上，外加本仓另一条实测教训
（`mtime-float-breaks-maxage-zero`：mtime 是浮点，边界会静默恒 false 且不报错）。
用「目录名里的 commit 是否仍被某个本地分支引用」+ git 说的提交时间。

**放弃让清理脚本顺手删掉判不出来的目录**。判不出来一律保留并点破：
留一个多余目录的代价是几十 MB，删错一个是别人几小时的工作（本仓 §0 铁律有真实事故）。

## 拿什么证明它生效了

**42 条单测**（`tests/eval/artifact-identity.test.ts`）全绿，且每条都做过变异自证。
六个变异逐个实测确认变红，其中**两个当场暴露了 false gate、断言被改强**：

- `stat -f %m` 换掉排序键 → 第一版 mtime 断言**照样绿**（"全打成同一个旧时间"让
  `sort -rn` 的键全部相等，结果由不稳定排序决定）。改成**把 mtime 排成与 commit 时间恰好相反**
  才真的红。
- 删掉 `--keep` 数字校验 → 第一版断言（退出码非 0 + 目录还在）**照样绿**：
  `[ "$i" -le abc ]` 在 `set -e` 下当场打死脚本，也没删东西。那条测的是 bash 的行为不是我的校验。
  改成断言**失败的形态**（一条人能看懂的话，且发生在分档/删除之前）才红。
  同型教训：`s2-cooldown-clear-test-is-false-gate`。

**端到端跑真脚本**（不是只跑单测）：

- G1 放行：当前 commit 的 baseline 包 → `✅ 产物身份门禁（G1）：ok`，之后才失败在缺 python venv（无关）。
- G1 拦 stale：改掉字节里那 40 位造一个旧产物 → `❌ ... G1：stale`，打出产物 commit 与宿主 HEAD 的差。
- 逃生舱：`SWE_ALLOW_STALE_ARTIFACT=1` → 放行，且 run-meta 里
  `artifact_commit=38a05d88…` ≠ `host_head_commit=0f22c47a…`、`gate_bypassed=['stale']`。
- 报告：把那份真 run-meta 喂进 `grade.ts` 的 `buildAcceptance` + `renderReport`，
  两个 commit 分行显示、脏工作区与逃生舱都被点破。
- `artifact_for()`：**实机跑 bash**（不是读源码）验四条查找路径。这条抓到过一个真 bug ——
  第一版 `ARTIFACT_SOURCE=` 赋值在命令替换的**子 shell** 里，run-meta 的
  `artifact_source` 恒为 `unknown`；只读源码的断言看不出 `printf` 与 `echo` 的差别。
- 清理脚本：合成 10 个目录（1 个当前 HEAD、6 个历史 commit、1 个坏名字、1 个不在对象库的），
  dry-run 后目录数不变；`--apply --keep 3` 只删窗口外那 1 个，protected 与两个 unknown 一个没动。

**门禁与格式**：`bash -n` 三个脚本全过、`bun run format:check` 全过、`bun run lint` 0 error、
`bun test tests/` 只剩一个与本次无关的既存失败（plan-mode 权限，成因是 worktree 路径含 `.claude/`
命中敏感路径守卫，见 `worktree-cwd-breaks-permission-tests`）。

**还没证明的那件事**（写出来别当成保证）：按本仓判据，防线的验收不是「代码写完 + 单测过」
而是**「真实会话里被触发过」**。G1 至今**零真实触发**。所以合入后留一个观察项：
G1 的触发次数。三个月一次都没触发时有两种可能——大家都很小心，或它在某处静默失效了——
靠上面那些变异自证测试来区分（测试还绿 = 前者）。
