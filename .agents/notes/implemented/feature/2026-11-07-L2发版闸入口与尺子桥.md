# L2 发版闸入口：TS 编排器 + 加载钉住 commit 的尺子桥，所有红项只经判定器出 INVALID

## 决定了什么

方案 T20：`scripts/eval/release-gate.sh <version>` 拉 linux-arm64 发布产物，过完闸后跑 traj-bench 全量，
写出 `~/.sid-code/eval-gate/<version>.verdict.json`。

- **入口** `release-gate.sh` 只做一件事：套 `caffeinate -dimsu`，并设 `SID_L2_CAFFEINATED=1`。
  没包住的话 TS 侧判 INVALID，不在 shell 里直接退出，这样失败也会落一份裁决文件。
- **编排器** `scripts/eval/release-gate.ts`，顺序是「先 $0 后真钱」：
  1. 下载 tarball，sha256 对 `.sha256`（必须有）和 `versions.json`（清单可能滞后，缺席只记提示）。
  2. 产物身份按 G2 判据 `judgeReleaseUpload` 核，不用闸I 的 `dirty==false`（发布产物必然 dirty）。
  3. caffeinate、docker 可用内存（MemTotal 减去在跑容器，要求 ≥ 9GiB）、预算账本（`checkBudget`，上限 $40）、尺子 preflight。
  4. oracle / nop 预检。
  5. 两档全量。只要全量开跑过就记账，红了也记。
  6. `pmset -g log` 查运行区间内的 Sleep。容器内二进制 sha 必须恰好一个，且等于下载解出的那份。
  7. 调 `eval-verdict.py`。
- 前面任一步红就不跑后面的模型步骤，红项全部作为 `--block` 交给判定器。**结论只由判定器给**。
  唯一例外：判定器自己崩溃时落一份 INVALID，不能让 promote 读到空文件。
- 已有 PASS/WARN/REGRESSION 裁决就不重跑（给 T22 每日调用用），INVALID 会重跑。单实例锁写在 `eval-gate/release-gate.lock`。
- **尺子桥** `evals/external-benchmarks/harbor/l2-ruler.py`：用 importlib 加载**钉在基线 commit 上**的
  agent-traj-bench `scripts/t15-baseline.py`，复用它的 `tiers / build_cmd / build_env / preflight`，改动只有三处：
  - 闸I 换成只核 ELF=arm64；
  - 产物根改到 `--out`，尺子仓里不落文件；
  - PYTHONPATH 指向本 checkout 的适配器。
  另外会校验尺子 HEAD 等于基线的 `traj_bench_commit`、已跟踪文件没被改过，缺 `REQUIRED` 里的名字就退出 1。
- **基线文档**（前置提交）：`build-l2-baseline.py` 从 T15 三轮 run 目录复算出 S/m/成本/缓存，
  并和冻结值对账，产出 `baselines/traj-bench-v0.2.1.json`。这份 JSON 排除在 oxfmt 之外，因为它必须能由生成器原样复现。

尺子 checkout 的准备：
`git -C agent-traj-bench worktree add --detach <dir> <traj_bench_commit>`，再把 `dist/v0.2.1` 拷进去。
`dist/` 不入库，正确性由尺子闸B 核 digest 三处一致来保证。

## 放弃了什么（以及为什么不选）

- **在 sid-code 里自己拼 harbor 命令**：`-n`、`--verifier-timeout-multiplier` 这些参数会改分数，但不在指纹里。
  抄一份出来漂移了也没有任何东西报错。现在复用同一 commit 的 `build_cmd`，这几项在结构上就等于基线。
- **直接调 `t15-baseline.py` 的 main**：它的闸I 会拦下每一个发布产物，产物目录也写死在尺子仓里。
- **给尺子仓加 `--under-test` 开关**：一改 commit 就变了，`traj_bench_commit` 对不上，T15 基线当场作废。
- **全写成 Python**：产物身份（G2）和账本已经是 TS 的，再在 Python 里复刻一份就是两套口径。
- **编排器自己写 verdict**：那样同一份产物就有两个结论出处。

## 拿什么证明它生效了

- `bun test ./tests/eval/release-gate.test.ts`：25 pass / 0 fail。端到端用假发布目录（file://）、假 docker / pmset / harbor / 尺子仓。
  每道闸各红一次，断言的是 `release_gate.blocks` 的内容，不只看退出码 3。
  - 跑前闸红时假 harbor 调用日志为空，即零模型调用。
  - 账本写到 $149 再开跑会被拒绝，账本逐字节不变。
  - 全量跑过才记账，实付按 null→$1.8 折算，`actual_usd = 1.8×2 + 0.25`。
- `python3 test-l2-ruler.py`：26 / 0（这个文件已经接进 bun test）。
- 变异自证，五处都变红，恢复后 sha256 一致：
  | 变异 | 变红的用例数 |
  | --- | --- |
  | 摘掉预算闸 | 1 |
  | 摘掉睡眠闸 | 1 |
  | 睡眠判据改成看整行 | 1 |
  | 跑前闸红了仍跑预检 | 5 |
  | 内存判据不减在跑容器 | 2 |
- 真实环境 dry-run：`release-gate.sh 0.1.614 --ruler <钉在 5bbd974 的 worktree> --dry-run`。
  真实下载 + sha + G2 + docker + 账本 + 尺子闸 A–J 全绿，退出 0。
- **未验证**：真跑一轮全量（约 $6–11、2h），这是 T23 的验收「真跑」项。T21（promote 读裁决）、T22（launchd）不在本 PR 内。
