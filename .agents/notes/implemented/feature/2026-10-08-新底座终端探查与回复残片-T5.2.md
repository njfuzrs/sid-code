# 新底座终端探查与回复残片：T5.2 收口（契约 I2 / I3，B9 / T5.2a–c）

## 决定了什么

- T5.2 由三个子任务组成，代码都在 T5.2a / T5.2b 里：
  - T5.2a（`38d8097c`）：next 的 `input-parser.ts` 丢弃终端回复与回复残片（I3），契约 `stdin-response-fragment.test.tsx` 35 条。
  - T5.2b（`f9e34e0e`）：新增 `terminal-probe.ts`，raw mode 计数 0 → 1 与 SIGCONT 恢复时探查 XTVERSION + DA1，`setSuppressTerminalProbe` 实装（I2），契约 `terminal-probe.test.tsx` 17 条。
- T5.2c 只做场景核对与收口，**不改底座代码**。
- S11 在 next 上**仍红，但红的部分不归 T5.2**。差异只在 `modes` 字段。探查字节（`>0q`、DA1）、输入框内容（分片 DA1 回复没漏成按键，只收到 `hi`），以及 X6 的两个 note（选择器卸载后实例注销、主 TUI 接手）都与 legacy 逐字一致：
  - legacy 在 raw mode 计数 0 → 1 时写 `?2004h ?1004h`，计数归零时写 `>4m <u ?1004l ?2004l`。next 这两处都没写，只靠 bracketed paste 自己的引用计数写 `?2004h`。所以「主 TUI」步骤 `sendFocus` 为 false（legacy 是 true），「(退出后)」`bracketedPaste` 为 true（legacy 是 false）。
  - 这就是 I4 的底座侧开关，归 **T5.3a**，也就是设计文档「起点」表里说的「raw mode 打开时开 `?1004` 没找到」。按 T5.2c 的约束，记下归属，不顺手修。
  - 归属有实验佐证：临时在 next 的 `handleSetRawMode` 0 → 1 与 `releaseRawMode` 里补上这两段写入，S11 立刻转绿（1 pass / 0 fail）。实验后已还原，sha1 核对一致。这只说明 S11 剩下的差异全部来自 I4，不代表 T5.3a 照这样实现就对：T5.3a 还要探针确认 kitty / modifyOtherKeys 的开启条件、`isTTY` 为假时写不写，以及卸载时的再关一次。
