# 工具入参归一两层进轨迹：新增 ToolInputCoerced 事件

## 决定了什么

`packages/core/src/tool/nullish-normalize.ts` / `numeric-coerce.ts` / `input-validator.ts`：

1. 两个归一函数从「返回裸值」改成返回 `{ value, hits }`（形状对齐 `normalizeInputAliases`）。
   `hits` 是 `{ field, count }`：
   - `field` 是字段路径：`offset` / `cfg.n` / `items[].source`；
   - `count` 是本次调用里该路径的归一次数（同一数组的多个元素累加，下标不进路径）；
   - **只在真的发生归一时计数**：被拒绝的值（`"abc"`、显式 `.nullable()` 的业务 null）
     不计，事件不会夸大「替模型擦屁股」的次数。
2. `packages/core/src/trace/stream-observer.ts` 新增
   `emitToolInputCoerced({ tool, layer, field, count })`，事件名 `ToolInputCoerced`；
   `input-validator.ts` 在两层归一后各发一遍（nullish 先、numeric 后，与执行顺序一致）。
   **不记参数值**——值已经在 messages 里，事件只放能聚合的量。

## 放弃了什么（以及为什么不选）

- **不用模块级 sink + `cli/src/app.ts` 接线**：方案原文写的是「加同样的 sink」，但这两层的
  唯一调用点就在 `input-validator.ts`，而它已经在用同一通道的 `emitToolInputAliasApplied`
  （stream-observer 的 `_eventWriter`）。走这条路不需要在 CLI 侧再接一根线，也不会出现
  「无 App 的环境（headless / 子代理）事件恒 0」这种失效形态。
- **不给 `ToolInputCoerced` 登记 `EVENT_ANCHORS`**：与 #626 同一结论——该门禁只解析
  `packages/core/src/query/` 下的发射点，`tool/` 不在扫描范围，硬登记会因「stale：锚点没有
  发射点」直接红。要登记需先把门禁扫描范围扩到 `tool/`，那是另一个改动。
- **不按「每次命中一条事件」发**：数组里 20 个元素会把事件放大成 20 条。按 `field` 聚合成
  `count` 后，下游 `GROUP BY field` 的写法不变，轨迹体积也不随数组长度膨胀。
- **不改归一判定逻辑**：`hits` 只在原判定命中后 `bump`，`""`/`null`/`true`/`[]` 与显式
  nullable 的行为完全不变（既有两个归一的 90 条测试全部保持绿）。
- **不记参数值 / 不记文件路径**：与 `ToolInputAliasApplied`、`EditLenientMatch` 同口径。

  → **90 pass / 0 fail**。
- 变异自证两次（恢复后均回到全绿）：
  - 把 `input-validator.ts` 里 numeric 的发射改成 `void hit` → **4 条接线断言变红**
    （11 pass / 4 fail）；
  - 把 `numeric-coerce.ts` 里的 `bump(stats, path)` 删掉 → **7 条变红**
    （3 条 hits 取数 + 4 条接线；8 pass / 7 fail）。
- `bun run affected-tests:run` → **2416 pass / 0 fail**（`packages/core/tests/tool/` + `tests/trace/`）。
- `bun run lint` 0 warning / 0 error；`bun run format:check` 通过；
  `bun run lint:boundary` / `lint:command-system` / `lint:legacy-tool` 通过；
  `bun run docs:gen-reference-check` 通过（未改工具 schema 与描述）。
- `make build` 产物自检通过。
- `bun run typecheck:gate` 在**父仓 main** 上 62/64、无新增；worktree 内报的 6 项全部是

  `skill/*.test.ts`，成因是 worktree 的 `node_modules` 软链到主仓，CI 干净安装不复现。
