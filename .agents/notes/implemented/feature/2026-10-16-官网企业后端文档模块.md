# 官网新增「企业后端」模块（/backend/，17 页），员工端页面双向链接

## 决定了什么

- 官网新增顶栏「企业后端」与 `/backend/` 侧边栏，共 17 页：概览、快速上手、部署与配置、用户、设备、组织与团队、策略、预算、Feature Flag、仪表盘与轨迹、审计、成本、插件市场、飞书文档授权、遥控、接口鉴权与枚举、排障。
- 受众是管理 agent-backend 的管理员和运维。员工端怎么执行留在 `/team/`、`/extend/`、`/use/`，两边只用链接互指，不重复写下发规则。
- 写法以 agent-backend `315107e` 和 sid-code main 的源码为准；没修完的功能按「未修时」的口径写进各页「能力边界」。依据见私有方案文档 `20261015-官网企业后端文档方案.md` 的 §3 核对表。
- 客户端改动在 v0.1.610 之后才有的功能都标了最低版本：`auth enroll`、策略轮询、`plugin_installed` 上报。
- 示例后端地址统一用 `agent.example.com`。`backend` 字段的注释同步改掉，并重新生成 `website/ref/settings.md`。

## 放弃了什么（以及为什么不选）

- **并进 `/team/`**：不选。读者不同（员工 vs 后端管理员）；混在一起会让员工以为要自己配后端。
- **模块叫「管理台」**：不选。部署、接口、飞书授权这几页不属于 Web 界面；现有文档里也已经在用「企业后端」这个词。
- **官网链接线上 OpenAPI**：不选。线上本来就没暴露 OpenAPI；公开管理接口全量清单只会增加攻击面。reference 页只给模块前缀、鉴权方式、状态码和枚举。
- **写生产装机的逐条命令**：不选。会和 agent-backend `deploy/` 脚本形成两份事实源，所以只写骨架和必改的配置项。

## 拿什么证明它生效了

- `cd website && bun run build`：build complete，含死链检测。
- `bun test ./tests/website`：202 pass / 0 fail。
- `bun run docs:coverage`：65 个内置命令都有叙述页覆盖。`docs:gen-reference --check` 通过。
- 用 VitePress 的锚点生成规则写了临时脚本，扫 `backend/ team/ extend/ use/` 全部站内链接和锚点。本次新增的链接 0 断链。另有 2 处断链是 main 上原本就有的（`team/migrate.md`、`team/quota.md` 里的 `/team/defaults#…`），不属于本次任务，没改。
- 对照 agent-backend 源码抽查：`/ctl/flags` 不鉴权；事件 metadata 最多 64 键，被拒原因代码一致；市场版本 draft→published→yanked。
- quickstart 关键路径在本地 SQLite 实例上实测过（阶段 2）。飞书登录、前端界面、bridge 没有实测。
