# 新底座帧 diff 与出帧调度，对拍旧底座逐帧字节（B9 / T3.2）

## 决定了什么

- `packages/tui/src/frame/main-screen.ts`：`diffMainScreen(prev, next, viewportRows)` 是纯函数，输入两帧 `Screen` 和视口行数，
  输出本帧要写的字节以及 full reset 原因。它取代上游 log-update 的整行字符串比较和 `shouldClearTerminalForFrame`。
  ink.tsx 每帧只调一次 write，用 DEC 2026 包住（R1）；没有变化的帧不写字节，onFrame 照样回调。
- 规则全部来自黑盒对拍：用 `bun run tui:frame-vectors` 从旧底座的 TTY 路径逐帧录字节，得到 62 条向量（`--check` 防过期）。
  语料 `frame-corpus.ts` 和驱动 `frame-drive.tsx` 都不 import 底座，底座由调用方注入。对拍得出的规则：
  - 只比两帧都有的前 min(p, n) 行。每个变化行先用 `\r` + `CUF x` + `CUU`/`CUD` 定位，再用 `serializeRowDiff` 只写变化的单元。
    没变的单元用 `CSI n C` 跳过，样式不关；跳过没变的宽字符时前进 2 列。写完用 `\r\n` + `\n`×k 回到底部；
  - 纯增长时按首帧口径追加新行（R4）；
  - 收缩时先 `eraseLines(p−n)` + `CUU 1`，再写变化行（以第 n 行为基准），最后用整行宽的空格逐行盖掉多出的 p−n 行；
  - full reset 用 `2J 3J H` 后重画整帧，触发条件有三：宽度变化（原因 resize）；变化行 y < p − H + 1（R5，原因 offscreen）；
    收缩时 p − n > H − 1，或 p ≥ H 且 n ≤ H（R6，原因 offscreen）。
- 调度（R2 / R13）：`frame/scheduler.ts`。第一次请求进 microtask，合并同 tick 的提交；之后 16ms 窗口内来过请求，就补一个 trailing 帧。
  测试环境（`NODE_ENV=test`）同步出帧，端口 `enableFrameThrottle` 改走 `frame/schedule.ts` 的开关，不再借 `NODE_ENV`。
  上游的 maxFps 和 lodash 两级节流删掉了。
- 非 TTY（R12）：每帧写整帧并用同步输出包住，空帧不写，卸载时写 `BSU \n ESU`。交互判定只看 `stdout.isTTY`，不再用 is-in-ci（L5 的这一半）。
- `ClockContext` 和 `useAnimationFrame` 在新底座落地（`clock.ts`、`hooks/use-animation-frame.ts`）。行为对拍旧底座：
  只有 keepAlive 订阅者时时钟才走，每一跳通知全部订阅者，`now()` 从首次读取起算。
- 端口 next 的 `testing.ts` 实现了 `render / lastFrame / frames / stdout.get / stdin.write / forgetRenderInstance / enableFrameThrottle`，
  语义来自黑盒探测 legacy shim：默认 80×24，非 TTY，卸载时补一个 `"\n"` 帧。

## 放弃了什么（以及为什么不选）

- **沿用上游 log-update（整行字符串比较）**：改一个字符就要重写整行，R3 要求「只写变化的单元」。
  上游也不分屏外行和视口内行，满屏后一律清屏，做不到 R4 那样增量追加、让旧行自然进 scrollback。
- **按行 diff，再拼一遍 SGR**：对不上旧底座「跳过时样式不关」的字节。旧底座的规则是逐单元的，必须直接比 Screen 的四个数组。
- **只比纯文本、不比字节**：xterm 场景本来就只比呈现。但帧 diff 的规则（阈值、竖向移动、收缩怎么盖）在呈现上差一点就看不出来，
  所以另做逐帧字节向量，两层都要。
- **继续借 `NODE_ENV=production` 打开调度**：这是旧底座的实现细节。新底座改成显式开关，端口 `enableFrameThrottle` 只改一处。
- **离屏暂停（useAnimationFrame 的 ref）**：要配合视口可见性计算，归 T3.4 的性能项，这次只保留 ref 位置。

## 拿什么证明它生效了

- `packages/tui/tests/frame.test.ts`：62 条向量逐帧字节一致，另有 5 条单元规则。
- 引擎级 xterm 场景 E1–E7（`term-bench/engine-scenarios.tsx`，只用 Box/Text）：每个场景在 legacy 和 next 上各跑一遍，
  用 `compareToBaseline` 当场比较，网格、scrollback、光标、模式全部一致，full reset 次数和字节数都不超过 legacy。这是阶段 3 出口的 T3.2 部分。
- 变异自证 10 处全红：屏外判定差一、收缩阈值、占满视口条件、宽度不 reset、首帧多字节、整行重写、增长改 reset、收缩不盖空格、
  丢 trailing 帧、宽字符跳过按 1 列。
- 全量 13970 pass / 0 fail；`make build` 通过；tsc 错误数与 HEAD 相同（71）；`tui:spec` / `lint:boundary` / `tui:similarity` 通过。

## 没做 / 移交

- 卸载时恢复终端模式、清 OSC 9 进度和 tab 状态（S 场景「退出后」那一步）属 X 组，归 T7.x。E 场景不比这一步。
- resize 事件合并、视口变矮、forceRedraw、SIGCONT 归 T3.3（S6 的字节数超标就在这里）。
- 上游 `useCursor` 的光标定位不再生效（CLI 没用）；`<Static>` 新增项暂时走「擦动态区 → 写静态 → 整帧重画」，端口 Static 归 T4.2。
- 读屏模式的输出路径保留上游写法，没有对拍。
