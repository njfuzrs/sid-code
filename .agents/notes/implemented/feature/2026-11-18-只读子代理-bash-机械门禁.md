# 只读子代理的 bash 只读性由工具层机械判定，不靠提示词

## 决定了什么

`explore` 类型子代理的工具表加了 `bash`（`agent-definition.ts` 的 `tools` 与
`tool-filter.ts` 的 Layer 2 白名单两处，两者是交集），并在
`sub-agent.ts:buildIsolatedToolRegistry` 里对**声明了 `readOnly: true` 的代理类型**
给 bash 套一层机械门禁（新模块 `agent/read-only-bash-guard.ts`）：

- 判定复用现成的两段口径：`isReadOnlyCommand`（纯函数）→ 不通过再走
  `judgeReadOnlyCompoundBash`（带 cwd / 仓库上下文的 `cd <工作区> && git log` 形态）；
- 两段都不过 → `execute` **之前**返回 `isError: true` + 可读原因 + 可行下一步，
  内层 bash 一次都不执行；
- 判定自己抛错时按拒绝处理（门禁失效不能变成放行）；
- 包装用 `Object.create(tool)` 原型链继承、只遮蔽 `execute`，与
  `BashTool.withFileReadTracker` 同一写法：`checkPermissions` / `maxResultSizeChars` /
  `interruptBehavior` 等能力字段与内层视图原样生效。

覆盖范围是 `buildIsolatedToolRegistry` 的两条调用路径（进程内 `executeInner` 与
`executeCustomInner`）——spawn 路径的子代理工具也由父进程经同一注册表执行，
所以一处接线同时覆盖两条。`verify` 也声明了 `readOnly: true` 且本来就有 bash，
本次起同样受门禁约束（此前只有系统提示在约束）。

## 放弃了什么（以及为什么不选）

1. **只在系统提示里写「你处于只读模式」**。这是修复前的形态，也是本次要修的东西：
   提示词是模型可以违背的建议，把 `rm -rf` 交给一句约束等于没有防线。
2. **只在权限层拦（plan 模式的只读放行复用）**。权限层按 `permissionMode` 生效，
   子代理继承什么档位取决于调用方；无头/跳过权限时整条防线消失。工具层门禁与权限档位
   无关，是兜底的正确位置。
3. **给 guard 模块 `import type { LegacyTool }`**。第一版这么写，`lint:legacy-tool`
   棘轮立刻红（基线 57 → 实测 58）：新增生产文件引用旧接口会把只减不增的数字永久抬高。
   改为结构化最小类型 `BashLikeTool`（只含 `execute`）+ 泛型 `T extends BashLikeTool`，
   返回值仍是 `T`，调用方拿到的类型不变。
4. **新写一份「只读命令名单」**。两份名单必然漂移，且漂移方向总是「门禁比权限层更松」。
   复用 `isReadOnlyCommand` + `judgeReadOnlyCompoundBash`，与 plan 模式的判定同源。
5. **让门禁对「判不准」放行**。方向与权限层一致：多拒一次模型会换写法（拒绝文案给了
   只读命令清单），多放一条写操作就落到了只读代理手里。缺 `PathValidator` 的退化路径
   只信 `isReadOnlyCommand`，`cd` 复合一律拒。

## 拿什么证明它生效了

- **G1**：`packages/core/tests/agent/read-only-bash-guard.test.ts`，24 个用例覆盖
  判定口径（`git log -S` / `git blame -L` / `git show <rev>:<path>` / `wc -l` 放行；
  `git checkout .` / `rm` / 重定向写 / `git commit` 拒绝）、包装器行为（拒绝时内层
  `execute` 零调用、判定抛错按拒绝、命令缺失交给内层）、以及接线（explore 工具表含 bash、
  只读 agent 的 bash 是门禁视图、非只读 agent 不受影响）。`bun test` 该文件 24 pass。
- **变异自证两次**（改坏 → 看到断言红 → 恢复 → 全绿）：
  ① 把 `sub-agent.ts` 的门禁包装条件改成 `false` → 「只读 agent 的 bash 是门禁视图」1 例变红；
  ② 把 guard 的拒绝分支改成永不生效 → 3 例变红（拒绝文案、判定异常按拒绝、接线）。
  恢复后 24 pass。

  （拒绝发生在执行之前）、子代理正常收尾。`bun run smoke X15-...` → 1 通过；
  `bun run smoke` 全量 43 例 43 通过。
