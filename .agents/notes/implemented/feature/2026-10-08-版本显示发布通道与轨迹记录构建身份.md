# 非正式版在 --version / TUI 上显示通道标签，轨迹记录通道与构建身份

## 决定了什么

- 新增 `packages/shared/src/release-channel.ts`，通道三态：
  - `dev`：构建身份 `origin ≠ release`（`make build` 的 sc-dev、源码运行、CI 产物），判据编在字节里；
  - `beta`：`origin = release` 且二进制旁 `versions/<ver>/.channel` 为 `beta`；
  - `stable`：其余，**不显示任何标签**。
- `install-template.sh` 每次安装都覆盖写 `.channel`（同一版本目录先 beta 后 stable 安装时会被复用，标记必须翻回 stable）。
- 展示：`--version` / `/doctor` / `/bug` 走新的 `getVersionDisplay()`（追加 `· beta 预发布版` / `· dev 本地开发版`）；
  TUI 首屏 Version 行追加警示色标签；状态栏行2 追加 `beta` / `dev`，与权限模式一样永不丢弃。
- 轨迹：`session.traj` metadata 新增 `release_channel` / `build_commit` / `build_origin` / `build_dirty` / `build_describe`；
  上传清理后留下的 `metadata.json` 快照同步保留这些字段与 `app_version` / `git_head`（此前一个版本字段都没有）。

## 放弃了什么（以及为什么不选）

- **把通道编进字节（给 beta 单独构建）**：promote 是纯指针操作，用户装到的字节 = beta 期被测的字节。
  单独构建会让这条失效，通道机制的唯一价值就没了。
- **把通道拼进 `getVersion()`**：它是网关定价刷新水位线（`app.ts`）与 daemon 锁的值，
  拼进去会让 promote 前后被判成「刚更新过」。所以新增 `getVersionDisplay()` 只给人看。
- **dev 靠路径判断（是否在 `~/.local/share/sid-code/versions/` 下）**：本地产物可以被拷到任何地方，
  构建身份的 `origin` 才是跟着字节走的判据。
- **读不到 `.channel` 时按 beta 处理**：没有证据就不打标，误标 beta 比漏标更误导。
