# 新底座选区接入渲染、复制与超链接（B9 / T6.2b）

## 决定了什么

规则全部来自对 legacy 的黑盒探针，没读旧代码（D-5）。探针脚本与结果备份在 `~/Backups/sid-code-t67-probe-results-20261008/T6.2b/`（m1–m16）。

- **鼠标接入**：App 把 `ESC [ <` 开头的 SGR 鼠标序列原样交给 Ink（`onMouseSequence`），Ink 只在 alt-screen 里喂给 T6.2a 的选区引擎。选区变了就当场重画，松开鼠标不重画也不复制。
- **高亮（M5）**：每帧先补到视口高（`padToViewport`），再在出帧用的副本上涂高亮。内容帧保持干净，供复制、链接命中和下一次重涂使用。设了选区色时，去掉单元原有的背景和反显 7，再加上选区背景；前景、粗体、下划线和链接都保留。色值认不出或没设时加反显。
- **复制（M3）**：`copySelectionNoClear` 同步返回文本，经 `setClipboard` 异步写一条 OSC 52（tmux 包裹复用已绿的 O7）。没有选区时什么都不写。
- **超链接（M4）**：新文件 `hyperlink-at.ts`，先看这一格的 OSC 8 链接，再找行内的纯文本 url。纯文本 url 的规则：只认小写 `http(s)://` 和 `file://`；正文是 ASCII 可打印字符，遇到 `"'<>\`` 结束；尾部反复去掉 `.,;:!?` 和多出来的右括号。没拖动的单击落在链接上时，等 500ms 再调 `onHyperlinkClick`：期间来了连击就取消，单击另一个链接则只开后一个。`TERM_PROGRAM=vscode` 时不开，因为 xterm.js 自己会开。端口 `RenderInstance` 加了 `getHyperlinkAt` / `onHyperlinkClick`。
- **`SID_CODE_DISABLE_MOUSE_CLICKS`**：取值 `1` / `true` / `yes`（不分大小写）为真，为真时选区和链接点击都不响应。

## 放弃了什么（以及为什么不选）

- **松开即复制**：这是直觉上的做法，但 legacy 实测松开时不写 OSC 52，复制只发生在 `copySelectionNoClear`，由 CLI 侧决定时机。照直觉做会多写字节，S13 和 M3 都会红。
- **只在有高亮时才补视口高**：这样会在清掉一段伸到内容以下的高亮时，让那几行不在新帧里，残留在屏幕上（探针 m16）。改成每帧都补。render-port 全目录 438/438 双绿，没有改动既有出帧字节。
- **宽字符右半格回头看左半格的链接**：legacy 的写法是这样，但新底座 `Screen.putId` 写宽字符时 spacer 格本来就带着同一个链接 id，回看是死代码，已删。变异「spacer 不带链接」会让 M4 红。
- **XTVERSION 识别 xterm.js**：legacy 还会按探查结果识别 xterm.js 并跳过开链接。新底座目前不留存 XTVERSION 回应，只认 `TERM_PROGRAM=vscode`。SSH 进 VS Code 终端的情形（`TERM_PROGRAM` 不传）留给 T8.1 终端矩阵。
