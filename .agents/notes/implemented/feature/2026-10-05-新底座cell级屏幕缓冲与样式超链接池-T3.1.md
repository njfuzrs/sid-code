# 新底座 cell 级屏幕缓冲 + 样式 / 超链接池，对拍旧底座首帧（B9 / T3.1）

## 决定了什么

- `packages/tui/src/screen/` 新增屏幕缓冲。每个单元记四样东西：字形簇、列宽（宽 / 窄 / spacer）、
  样式 id、超链接 id，平铺存在四个数组里。T3.2 的帧 diff 逐格比较这四个整数 / 字符串，不再比较整行字符串。
  上游 `output.ts` 的操作序列（write / clip / unclip）原样保留，只是最终落到 `Screen`，`get()` 变成它的纯文本形态。
- 规则全部来自黑盒对拍：旧底座 TTY 路径的**首帧字节**（前一帧为空，正好是整屏序列化的口径）。
  `bun run tui:screen-vectors` 从旧底座生成 `packages/tui/tests/fixtures/screen-vectors.json`（`--check` 防过期）。
  语料 `screen-corpus.ts` 是纯数据 DSL，生成器和测试共用，测试不 import 旧底座。对拍得出、写进代码的规则：
  - SGR 切换 = ansi-tokenize `diffAnsiCodes`，按 `(from, to)` 缓存在样式池里；
  - 默认空白（空格、无样式、无链接）不写，下一个字符前用一次 `CSI n C` 跳过，**样式不关**；行尾的默认空白丢掉；
  - 超链接：只有 `OSC 8 ;; url BEL` 改写成 `id=<url 的 Java 式 hash，无符号 36 进制>`，终止符跟 OSC 工具一样（kitty 用 ST）；
    带参数、已带 id、ST 结尾的链接码**当 SGR 样式原样保留**——它们和改写链接互相切换时的顺序只有这样才对得上；
  - 宽度补偿（R9）：含 U+FE0F 的宽字形簇写成 `CHA(x+2) ' ' CHA(x+1) 字符`，收尾的 `CHA(x+3)` 惰性输出
    （紧跟着另一个同样式的补偿字符时省掉）。旧底座在 14 种终端环境下都补偿，不按终端区分；
  - 宽字符不劈半：压在裁剪框 / 屏幕右边界上整个丢掉；覆盖写入劈开宽字符时剩下的半格还原成默认空白（契约 T4）；
  - tab 推到屏幕绝对列的下一个 8 的倍数；零宽簇、控制字符丢弃。
- 顺带修了两处上游与旧底座不一致、且落在本层的行为：带冒号子参数的 SGR 整条丢弃（上游会把 `[4:3m` 当可见字符画出来）；
  换行后仍超宽的行按 `ceil(行宽 / 可用宽)` 计布局高度。

## 放弃了什么（以及为什么不选）

- **沿用上游 `StyledChar[][]` 再 `styledCharsToString`**：只能比较字符串，T3.2 的 diff 要逐格比样式。上游的序列化也不做
  CUF 跳过、不改写链接 id、不做宽度补偿，首帧 90 条里大半对不上。
- **超链接全部进链接池、统一用池的开关**：实测 `改写链接 → 带 id 链接` 时旧底座先关前一个再开，`带 id → 改写` 时直接开，
  ST 链接切到 BEL 链接时会出现两个关闭序列。这些顺序只有「原样链接是样式的一部分」才能复现。
- **按终端决定要不要宽度补偿**：探测过 iTerm2 / vscode / Apple Terminal / kitty / ghostty / WezTerm / tmux / Windows Terminal /
  Warp / VTE / alacritty / dumb 等 14 种，旧底座一律补偿，没有可分的条件。
- **语料里放 `<Text>` 的 props 组合**（`dimColor`、`dim`、多 prop 叠加顺序）：那是宿主组件的语义，实测旧底座的 `<Text dimColor>`
  不出 SGR、上游没有 `dim` prop。留给 T4.x，屏幕层的语料只给原始 SGR 串。

## 拿什么证明它生效了

- `bun test ./packages/tui/tests/screen.test.ts`：102 pass / 0 fail。首帧对拍 90 条（默认 82 + bidi 3 + kitty 2 + 条目一致性），
  外加 Screen 单元规则（6 种写入两两组合 × 6 个位置覆盖后无孤立 spacer）与两个池的单测。
- 变异自证 10 处，全部转红，已还原：不清劈开的左半格（5 fail）、不清孤立 spacer（4）、边界劈宽字符（6）、
  tab 相对推进（5）、去掉宽度补偿（11）、补偿收尾不省略（1）、链接不带 id（13）、冒号 SGR 不丢（1）、测量不补行（2）、
  bidi 不认 WT_SESSION（3）。
- 全量 13890 pass / 0 fail；`make build` 自检通过；`tui:similarity` 无违规；tsc 错误数与 HEAD 相同（71 → 71），没有新增。
- **还没证明的**：帧之间的增量输出（R4–R6）、引擎级 xterm 场景。那是 T3.2 的出口，本任务只证明了首帧字节一致。
