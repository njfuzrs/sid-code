# 停滞升级阶梯：进展判据 flow 化 + L1 收敛提示 + L2 影子（可选真停）+ 清单振荡时收尾闸门放行

## 决定了什么

新模块 `packages/core/src/query/stall-escalation.ts`（纯函数 + 纯数据），`query/loop.ts` 只做接线。来源：评估会话 20261020-110542-ce7ea52e 发现 2a/2c/2d/2e，评估报告 §5 决策 1（issue #387）。

- **进展判据改 flow（2a）**：账本记「文件 → 内容 hash」，「真实进展」= 出现一个**此前从未出现过**的工作区 hash 组合；改回历史状态记**回退**，不算进展。只登记**成功**落盘的 edit/write；非只读 bash 之后，对账本里已登记的文件补算 hash（否则「用 sed 改回去」对判据是盲的）。
- **绿点账本（2c）**：只解析 bun test 汇总行（`N pass` / `M fail` 各占一行、pass>0），绿后变红记一次回归。解析不了就不计。
- **L1（缺省生效）**：连续 15 个工具轮无新工作区状态，且信号（振荡 + 空转 + 绿点回归 + 回退）≥3、其中至少 1 个非回退 ⇒ 下一轮经 reminder 通道注入一次收敛提示（不落历史、不动前缀）。
- **L2（缺省影子）**：L1 后再过 10 轮仍停滞，且出现新的确证信号（2b 振荡 / UnchangedObservationRun）或期间无任何文件改动 ⇒ 落 `StallEscalation{level:2, acted:false}`。**只有** `stallHardStop`（settings）或 `SID_CODE_STALL_HARD_STOP=1`（env 优先）打开才真停：走 **P1-1 强制总结出口**（与 maxTurns 共用，不新造机制），提示文本改为「现状 / 卡点 / 可选方案」，`done.incompleteReason="stalled"`、`TurnComplete.stop_reason="stalled"`；同一条消息内第二次 L2 阈值翻倍；用户回复后阶梯清零（挂 `LoopState`）。
- **L2 只认已确证信号**：hash 回退与绿点回归**只喂 L1**，不触发 L2（单测里用「窗口一直是满的」证明挡住 L2 的正是这条规则，不是别的原因）。
- **2e 收尾闸门联动**：todo 闸门在本份清单 `oscillations ≥ 3` 时不再劝「继续」，改发一条「不再自动续跑」的 system 提示。
- **`/goal`**：L2 真停时目标置 `blocked`，不再自动续跑；总结提示带上目标原文。
- **范围**：只开交互主循环。headless（`config.print`）缺省**整套不开**，`SID_CODE_STALL_ESCALATION_HEADLESS=1` 才启用；子代理走 agentic-loop，不经过 `queryLoop`（`new QueryEngine` 全仓只有 `app.ts` 一处）。`SID_CODE_STALL_ESCALATION=0` 一键全关（含 2e）。
- **契约变更**：SDK result 新增 `subtype:"error_stalled"`（`sdk/schemas.ts` 闭集 + `message-converter.ts`），`DoneIncompleteReason` / `TurnStopReason` 加 `stalled`。**进程退出码不因此变非 0**（和 `timeout_retry_exhausted` 同形，`$?` 只由 runError / budgetExceeded 决定），官网 `extend/headless.md`「退出码可靠吗」如实写明。
- 文档：`website/use/interactive.md` FAQ、`website/extend/headless.md`、`website/ref/{env,settings}.md`（`docs:gen-reference` 重新生成）。

## 放弃了什么（以及为什么不选）

- **L2 用 `tool_choice:"none"`**：三族 provider 与各网关对它的支持不一致，要逐个确认。不带 tools 的代价是这一次请求断一次缓存，P1-1 已经接受了同样的代价。
- **L2 直接跳**（不经 L1）：未经提示就强停，误伤代价最大。现在 L2 只能从 L1 升，且有单测。
- **hash 回退 / 绿点回归也算 L2 的确证信号**：这两个判据还没在真实长任务上验证过误报率。「试一个方案再撤销」是合法实验。
- **headless 默认开**：调用方本来就有 `--max-turns` 和预算；Harbor 评测的可比性依赖行为不变，默认开等于静默改了基线。
- **默认直接真停**：见 `rejected/feature/2026-10-21-交互模式默认轮数上限.md`（同源论证）与下面第三段的误判证据。
- **用退出码 1 表达停滞**：会改变 `process.exit` 路径，超出本次范围，且与既有 `incompleteReason` 形态不一致；留作后续、写进文档让脚本读 `subtype`。
- **牺牲了什么**：更安全 / 更省 ↔ 长任务流畅度。影子期把首版误伤代价压到 0，换来的是 ce7ea52e 这类事故在影子期内只能靠 L1 + 2e + ESC 拦。

## 拿什么证明它生效了

**单测与接线**（`bun test ./packages/core/tests/query/stall-escalation.test.ts ./packages/core/tests/query/stall-escalation-loop.test.ts ./packages/core/tests/query/done-not-success.test.ts`）：纯函数 30 条 + 主循环集成 13 条 + `done-not-success`（SDK 映射，含新增的 `stalled → error_stalled`）9 条，合计 52 pass / 0 fail。集成测试驱动真 `queryLoop`，覆盖：L1 文案出现在发给模型的 reminder 且不落历史；影子 L2 只落事件、循环不停；hardStop 走强制总结、`done.incompleteReason=stalled`、`TurnComplete.stop_reason=stalled`；`/goal` 置 blocked；headless 缺省关 / opt-in / 总开关；2e 对照组；失败 edit 不算进展、成功 edit 是真进展。

**变异自证**（每条把实现改坏，看**哪条断言红**，改完恢复，三个文件重新全绿）：

| 变异 | 变红的断言 |
| --- | --- |
| L1 不注入（`pendingStallReminder` 不赋值） | 「L1 真的进了发给模型的消息」 |
| L2 不置 `stallStopRequested` | hardStop 强制总结 / headless opt-in / goal 共 3 条 |
| goal 不置 blocked | goal 用例 |
| 2e 闸门不联动 | 「振荡 ≥ 阈值一次收尾即放行」 |
| headless 缺省也开 | headless 缺省关 + 开关优先级 + env 严格解析共 3 条 |
| 回归/回退也算确证信号 | 「回退/回归只喂 L1，不能触发 L2」 |
| 回退单独可升 L1 | 「回退单独不构成 L1」 |
| 影子也真停（`acted: true`） | 影子集成 + 影子单测 2 条 |
| env 宽松解析（`"true"` 也算开） | env 只认字面 1/0 |
| L2 直接跳过 L1 | 5 条（含「L2 不能直接跳」「L1 先于 L2」） |
| 振荡增量可为负 | 振荡增量 + L2 振荡路径 2 条 |
| bash 改回不 rehash | rehash 回退 |
| 失败 edit 也登记 / 成功 edit 不登记 | 进展判据两条，各红 1 条 |
| `stopReason` 不认 stalled / SDK 不映射 `error_stalled` | 各红 1 条 |

变异过程中发现并修掉两处**空转的绿**：① 先登记 A/B 两个状态再测「只喂 L1」，否则前两轮的新状态会复位窗口，断言因别的原因变绿，现在额外断言窗口一直是满的；② 失败 edit 登记与否原本没有测试覆盖（M13 变异无红），补了两条集成用例后重做变异才红。

**离线参考（不是门禁，口径见决策 2）**：用 `events.jsonl` 里**可重建**的信号（BeforeModel 切轮；成功的 edit/write 记为「一个新状态」；`UnchangedObservationRun` / `TodoReworkDetected` / `TodoProgressAdvanced` 算信号）喂**真实的** `observeStallTurn` 状态机，覆盖本机 370 个有 events 的会话。工作区 hash 重建不出来，所以把每次成功 edit 都当新状态——这会把真实回退也算进展，**触发数是下界**。

| API 次数 | 会话 | 触发 L1 | 触发 L2（影子） |
| --- | --- | --- | --- |
| <50 | 293 | 0 | 0 |
| 50–199 | 72 | 6 | 0 |
| 200–499 | 2 | 1 | 1（`57de4f89`） |
| ≥500 | 3 | 2（`a41bcd77`、`ce7ea52e`） | 1（`ce7ea52e`） |

- `ce7ea52e`（9 小时事故会话）：L1×1，L2 影子×5，首次在第二条消息的第 528 个工具轮。这是**下界**：真实的 A↔B 反复在 hash 判据下是回退，停滞窗口会更早攒满。
- **`57de4f89` 是误判，已逐步核实**：L2 影子在第 173、193 工具轮命中，但那 79 轮无 edit 的区间是模型在**轮询 CI**（约 40 次 `gh pr checks` / `gh run watch`），是合法的等待。触发路径：L1 的 3 个信号 = 1 次早先的 TodoRework + 2 次空转上报；L2 靠 L1 后新增 1 次空转上报 + 期间无文件改动。它和「停止编辑后原地空转」在可用信号上同形。
- 负样本只有短会话（本机最长 1343 次，≥200 次 API 的只有 5 个），「零触发」对它们几乎恒成立，**证明不了长任务不被误伤**。另 6 个只触发 L1 的 50–199 会话没有逐条抽检。

**因此结论是**：L2 真停保持默认关；`57de4f89` 是 D3（默认开启）的硬阻塞，见 `proposed/feature/2026-10-21-D3-L2默认开启的前置条件.md`。

**门禁**（本分支，worktree 内）：`affected-tests:run` 6084 pass / 10 skip / 0 fail（496 文件）；`make build` rc=0 且无 `will always be undefined` warning，产物自检通过；`bun run lint` rc=0、`format:check`、`lint:boundary`、`lint:command-system`、`typecheck:gate`（66/66，无新增）、`docs:gen-reference --check` 全绿。真实二进制冒烟：`./sid-code --help` 带三个新 env；`settings.json` 写 `stallHardStop:true` 经 `getSettings()` 读到 `true`，非布尔被 schema 拒绝。
