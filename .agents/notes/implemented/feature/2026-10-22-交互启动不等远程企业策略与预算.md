# 交互 TUI 启动不再 await 远程企业策略 / 预算，改为首轮对话前生效

## 决定了什么

交互模式（非 `-p`、非 `--max-turns`、非 Bridge）下：

- `cli.ts` 先套 `loadOfflineEnterprisePolicy()`（不打网：未过期且 endpoint 一致的 200 缓存 → 否则本地 managed 文件），再在 `initLogger` **之后**后台发起远程策略链与预算拉取。后台发起推迟到 logger 就绪之后，是为了让秒回的 401 / 连接拒绝 WARN 只进 audit.log，不走 stderr 兜底打到终端。
- `init-helpers.ts` 的 `loadEnterpriseBudgetOnce()` 交互模式下不 await（无头照旧 await）。
- `App.wireDeferredEnterpriseLoad()` 拿到同一个 in-flight（进程内去重，不多打网）后走 `applyEnterprisePolicyInSession`（权限 / Hook 门控 / 模式降级），再补两项「注册时才看」的 policyLimits（撤 sub_agent、断 MCP，IDE 除外）。拉取失败只发 TUI 状态栏提示，未登录不提示。
- `tuiAgentLoop` 每轮开头等这个 promise：远程 deny 从「TUI 出现前生效」挪到「第一条消息前生效」，模型跑起来时不存在远程 deny 没落地的窗口。等待有上界（策略 15s×2、预算 5s）。

无头 / Bridge 路径行为不变。

**牺牲**：更安全 → 更快。临时视图期间（TUI 出现到首轮之间）只有缓存 / 本地策略；CLI 启动 fail-fast（`--dangerously-skip-permissions` 被远程禁用时报错退出）在缓存缺失时不再触发，改由 `applyEnterprisePolicyInSession` 运行时拨回 default 并提示。远程放开（临时视图禁、远程放开）不补注册工具 / 连接，留到下次启动，方向上更严。

## 放弃了什么（以及为什么不选）

- **全部 fire-and-forget**：`PermissionChecker.initRules()` 读进程内单例，首轮可能在 deny 落地前开跑，即 cli.ts 注释里写的「远程 deny 空转」。所以保留首轮闸门。
- **只把超时从 15s 调短**：注释里实测本机生产 HTTPS 握手 17–25s，调短会把权威 204 误判成超时，再用旧 deny 续命。网络慢的问题不该靠缩短超时解决。
- **把 logger 兜底分支改成不写 stderr**：OBSERV-4 的设计目的就是「早期 ERROR/WARN 不能静默丢」，改它影响面是全部模块。这里只把会刷屏的那一类挪到 logger 就绪之后。

## 拿什么证明它生效了

本地起一个永不响应的 HTTP 服务（`127.0.0.1:47123`），`SID_CODE_BACKEND_URL` 指过去，用 `script` 伪终端启动，从 debug.log 里等 `ink 实例已创建` 出现：

- 线上版 `sid-code`：约 **37s** 出 TUI；终端 tty 输出含 `[POLICY]` ×2、`[BUDGET]` ×1。
- 本地构建 `./sid-code`：约 **8s** 出 TUI；tty 输出 `POLICY|BUDGET` 命中 **0** 行。debug.log 里 TUI 挂载前已没有 POLICY/BUDGET 等待。

剩下约 8s 来自 SessionStart hook（≈1.7–2.4s）和 MCP / shell 快照等启动项，跟这次改动无关，本次没动。
