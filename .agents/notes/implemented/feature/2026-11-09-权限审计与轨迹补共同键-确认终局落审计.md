# 权限审计与轨迹补共同键，确认终局落审计，拒绝记录另存（厚薄归位 B19 / B20 / B21）

## 决定了什么

只加字段和落盘，**不改任何权限判定结果**。Refs #672。

**B19 共同键**
- `PermissionRequest` 加 `toolUseId`。主循环（`query/tool-executor.ts`）和子代理（`query/run-tool-use.ts`）构造请求时都填 `block.id`。
- `PermissionChecker` 新增私有方法 `audit(req, entry)`，作为审计的唯一写入口，负责盖 `tool_use_id`。原来 12 处 `this.auditLogger.log(` 全部改走它。静态哨兵保证全文件只剩 `audit()` 自己这一处直写。
- `AuditLogger.log` 在写入时盖 `session_id`，取 `bootstrap/state.ts` 的 `getSessionId()`，也就是本进程会话 id。调用方显式传了就不覆盖；进程 id 为空时不写。
- 轨迹 `PermissionDecision` 加 `tool_use_id`，主循环、子代理、forked 三条路径都带。

**B20 余项**
- ask 的终局落审计。三路竞争出结果后，tool-executor 调新增的 `Checker.auditConfirmationOutcome`，写一行带 `confirm_source`（user / hook / classifier / timeout / auto）的记录。`user_confirmed` 现在等于「由人作答」：批准、拒绝都算，结论看 `decision`。这个方法只写审计，不碰 denial tracking 和会话记忆，因为这两者调用方另有入口，再记一次会让计数翻倍。
- A5（PreToolUse hook 要求 ask，但没有交互通道而拒绝）补一行审计。
- A2 注入校验器和 A6 展开超限在轨迹上靠新字段 `guard` 区分，取值为 `injection:<id>` 或 `expansion-limit`。`guardOf()` 只认这两类有闭集来源的 pattern，LLM 分类器给的自由文本一律不取。
- headless 和 dontAsk 两个分支会用新的 decisionReason 覆盖阶段一的成因，所以 checker 用 `guardMetadata()` 把闸门标签搬进 `metadata.guard`。
- forked 路径的 `step` 记固定标签 `forked`，**`mode` 不填**。forked 的裁决来自调用方注入的 `canUseTool`，不经过 PermissionChecker；填主会话的 mode 等于编造。
- A9：auto 档没有放行、回退人工时，`metadata.autoClassifier` 记回退成因（absent / safety-guard / unsafe / unavailable / error），落到轨迹的 `auto_classifier` 字段。

**B21 保留**
- `decision=deny`、带 `confirm_source` 的行，另外追加一份到 `logs/permissions-audit-retained.log`，按 5MB 轮转、保留 1 代。启动探针（`source=policy-probe`）不进这份日志。主日志的路径、格式、轮转方式都不变，`scripts/policy-trigger-rate.ts` 这些读取方不受影响。

官网 `team/policy.md`「审计日志」和 `use/troubleshooting.md` 同步写了新字段和保留日志。

## 放弃了什么（以及为什么不选）

- **把 toolUseId 放进 `PermissionCheckOptions`**：`swarm/team.ts` 的 escalate 包装器调 `baseChecker.check(req, tool, toolContext)` 时会丢掉 options，`req` 却原样透传。放在请求上，结构上就不会被半路丢掉。
- **用 AsyncLocalStorage 给审计行注入 tool_use_id**：所有审计调用点手里都有 `req`，用显式的 `audit(req, …)` 加静态哨兵就够了。ALS 的作用域靠 await 链隐式传递，出错时更难排查。
- **B21 把主日志从 1 代加到多代**（比如 4 代、40MB）：保留时间只是从约 11.5 天线性拉长，噪声比例不变。本机实测两代共 34,387 行、12.3MB，其中 deny 469 行、约 662KB，约 58KB/天。单独存一份，按约一半的磁盘就能保留几个月的 deny。
- **B21 在轮转时压实，丢掉 allow 只留 deny**：每次轮转要重写 10MB 文件，进程中途崩溃还可能写坏文件。收益和另存一份相同，复杂度更高。
- **把 forked 决策写进权限审计**：forked 的拒绝来自内部旁路（记忆抽取、`/btw`）对工具的裁剪，不是用户的权限策略在生效。写进去只会给审计加噪声。轨迹里已经有带 `tool_use_id` 和 `step=forked` 的 PermissionDecision。
- **哈希链 / 不可篡改审计**：02 厚侧研究已经否决，见专项文档「范围外」一节。

代价：磁盘最坏多 10MB（保留日志 5MB × 2）。每次 ask 的终局在主日志里多一行，按本机数据每天个位数到几十行。不牺牲更快、更准；严格说是用一点磁盘换可观测。
