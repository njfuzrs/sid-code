# edit 归一化命中后保留文件原有字形（T2）

## 决定了什么

`packages/core/src/tool/edit.ts` 新增 `preserveFileStyle(matchSearch, actualOld, replace)`，
只在**走归一化匹配路径**时调用（`tryNormalizedMatch` 的两条替换分支：单形态与多形态
`replace_all`）。归一化是为了**匹配**，不再顺带改变文件风格——文件里是 `“inherit”`，
模型用直引号写 old/new 时，写回的是 `“inherit”`/`“x”`，而不是 `"x"`。

算法三条规则（都是刻意保守的）：

1. **前后缀对齐**：取 old_string 与 new_string 的最长公共前缀 / 后缀，圈出模型沿用的区段；
2. **中间段长度守卫**：中间段长度不等说明模型做了插入或删除，按位置映射会错位 →
   整段不还原（宁可不改，也不改错字符）；长度相等才逐位置映射；
3. **只还原模型沿用的字符**：位置可映射、`newChar === oldChar`、文件侧确实是同类字形
   变体（归一化后相同）三个条件同时成立才替换。模型新写的字符（如 `错误!` 里的 `!`）一律不动。

`replace_all=true` 且命中位置有多种原文形态时，**逐处**算一次保留风格后的替换串——
同一份 new_string 在 `x—y` 与 `x–y` 两处会被还原成不同的变体（`x—z` / `x–z`）。

## 放弃了什么（以及为什么不选）

- **不照 CC 的整串替换**（claude-code `FileEditTool/utils.ts` 的 `preserveQuoteStyle`：
  文件里有弯引号就把 new_string 的**所有**直引号换成弯引号）。中文文档里这会误伤模型
  有意写的直引号，典型是它新写进去的代码片段。代价是 `"inherit"` → `"foo"` 这种
  「两端全换、中间全替换」的编辑只会还原开头的引号（末尾那个在 new 里不存在，
  没有位置可以还原），比 CC 少还原一半——**接受这个不完整，换「不改错」**。
- **不补反方向（文件是直引号、模型写弯引号）的镜像逻辑**。文档 §T2「已知缺口」
  要求二选一，这里明确选「只保证主方向」，理由：
  ① 反方向是模型**主动选择**写弯引号，不是它把文件风格写错的场景；
  ② 补镜像要把 new_string 里的弯引号批量转成直引号，中文源码里误伤面比收益大；
  ③ 单独实现后需要另一套「哪一侧算原风格」的判定，复杂度翻倍而收益不可测
  （轨迹里还没有这类样本）。
  该缺口已用测试显式锁住（「已知缺口（刻意不支持）：文件直引号 + 模型写弯引号 →
  写回模型的弯引号」），不是忘了做。
- **不在精确匹配 / 灵活 / 正则 / 模糊路径上生效**。那几条路径本来就用模型给的字形
  精确命中，没有「文件用了另一个变体」这个前提；给它们加还原只会扩大误伤面。
- **不导出 `preserveFileStyle` 供单测直接调**。保持与 `tryNormalizedMatch` 一致，
  走 `new EditTool().execute()` 端到端；导出一个内部实现会让测试锁住函数签名而不是行为。
