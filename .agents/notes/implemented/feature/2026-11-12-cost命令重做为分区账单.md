# /cost 重做为分区账单：数据层 / 渲染层分离，计价公式只留一份

## 决定了什么

落地方案的 D11–D15（PR-B 的剩余项），一个 PR：

- **计价公式收口**（D12/D20 前半）：`SessionState.calculateCost` 与 `calculateUSDCost`
  各写一份同形公式（已有两处漂移：本地 provider 判断、兜底价记法）。抽到
  `cost-tracker.ts` 的 `calculateCostBreakdown`（四段 + `source` + `tier`），两个入口都改为
  对它求和。`FALLBACK_PRICING` 与 `isLocalPricingProvider` 导出为全仓唯一一份。
- **`SessionState.updateUsage` 四段同源入账**（D12）：`ModelUsageStats` 新增
  `uncachedUSD/hitUSD/writeUSD/outputUSD`（四段之和 === costUSD 由同一行代码保证）、
  `peakCostUSD/offpeakCostUSD`（D11 时段拆分，tier 与计价同一个 `priceTierAt`）、
  `pricingBaseURL`（剥 query，`sanitizedBaseURL`）、`pricingSource`、`reasoningTokens`。
  `hydrateUsage` 白名单全量回灌。
- **数据层**（新文件 `core/src/session/cost-report.ts`）：`buildCostReport(ss, opts)` 纯函数，
  进程级单例（side-call-sink / 后台闸门 / 缓存断裂）全部经 opts 注入快照。含 D13 的
  逐次环形缓冲（`RequestLogEntry`，上限 500，/clear 清空）取 p50/p95/max 与最贵 3 次。
- **渲染层**（新文件 `cli/.../cost/cost-render.ts`）：`renderCostReport` 纯函数。
  D15 版式：首行总花费加粗、分区标题品牌蓝、进度条 ▰▱、千分位、金额 4 位小数、
  `stringWidth` 对齐成列；ANSI 只在 TTY（headless / 管道零转义码）；窄列（<80）
  去进度条与单价列；兜底价亮黄警告（D11）；说明文字全放注释区。
- `cost.ts` 只剩接线（取数 → build → render）；`/stats`、`/debug` 未动（方案 4.2 的
  「/stats //debug 改读 buildCostReport」归 D19，不在本 PR）。
- 官网 `website/use/cost.md`：示例换成取证会话重放的真实新版式输出，口径表按新版字段重写。
- **合并 origin/main（D5/D6/D8）时的取舍**（2026-11-12）：main 上「输入 token 三段互斥 +
  千分位」「命中率按实测值提示」「辅助调用耗时单列」三个修复是在本分支切出后合入的，
  与本 PR 的分层重做冲突。处理原则是「**语义取 main、落点取新分层**」：
  - 命中率提示：main 的 `formatCacheHitHint`（阈值 50% / 最少 5 次请求）迁进
    `cost-render.ts` 并在 `cost.ts` re-export；替换 PR 初版里遗留的旧「openai 族 60-70%
    属正常上限」判断（main 已删除那个口径）。
  - 0 值行：取 main「命中/写入为 0 时整行省略」的契约，渲染层宽列/窄列都按此省略；
    PR 渲染测试的对齐断言随之从 4 行改为 3 行（基线会话写入为 0）。
  - 字段名：`ModelUsageStats` 的四段费用取 main 的命名（`uncachedInputUSD` / `cacheHitUSD` /
    `cacheWriteUSD` / `outputUSD`），`cost-report.ts` 只做一次映射到 `CostModelRow.breakdown`
    的短名——两处各起一套名字，下次改名就会静默漂移。
  - `CostBreakdown` 保留 PR 的 `tier` 与**细粒度** `source`（`gateway:expr`）：main 的
    `"pricing" | "fallback" | "local"` 闭集会把网关价展示成「注册表」，D11 的来源展示就失真；
    `state.ts` 的 fallback 告警仍用 `=== "fallback"` 判断，两种口径共存。
  - 本地 provider 判断收口到 `llm/provider-infer.ts` 的 `isLocalProvider`（main 已导出），
    PR 自己那份 `isLocalPricingProvider` 不保留——两份同义实现正是 D20 要消灭的形态。
  - 命中率精度：`SessionState.getCacheHitRate()` 返回整数（Footer/状态栏契约），面板要 1 位
    小数，改由 `buildCostReport` 用 `cacheView` 精确算一次；不去改 `getCacheHitRate()`，
    否则 Footer 的既有契约会跟着漂。

## 放弃了什么（以及为什么不选）

- **D11 分时段二选一：选了「按时段拆分入账」（peakCostUSD/offpeakCostUSD），不做
  「只显示单价（高峰）+ 高峰占比」**。理由：不拆分时「单价 × token ≠ 费用」在跨时段会话
  里无法解释，而拆分入账让 /cost 能回答「把长任务挪到空闲时段能省多少」（priceTierAt
  注释里写的用途）。代价是快照多两个字段 + tier 判据多一条入账路径——tier 从
  `calculateCostBreakdown` 带出（计价前在 raw 上判，不拿折算后清空 peakWindows 的 p 判）。
- **D13 轮次分析：选了内存环形缓冲（上限 500），不从 events.jsonl 读**。命令面板首帧不能被
  磁盘 IO 卡住；resume 会话跨文件拼历史明细的复杂度换不来对等的展示价值。代价如实标注：
  resume 后只有本进程明细，面板写明「按本进程最近 N 次请求统计」。
- **不做实时刷新面板**（D2 已由 PR #754 定案）：静态快照 + 后台任务提示。
- **不做 `/cost --json`**：方案 4.2 规则 11 列为可选。当前没有脚本消费方，做了没有
  验收方；等有真实需求再随需求一起进（避免一个没有用户的接口先定死格式）。
- **`uncachedOf` 的手写实现被否决**：变异自证（MUTATION-2）发现 byModel 行的 uncached
  是第二份算法（main 区走 `getNormalizedCacheUsage`），改坏它测试全绿。收口到
  `normalizeCacheUsage` 派生 + `Σ byModel === main` 同源断言，而不是给第二份实现补断言。
