# 权限/Shell 确认框从「只能敲字母」改为「↑↓+Enter / 数字 / 字母」三路并存，并顺带接通一直按不出来的持久档

## 决定了什么

**用户可感知的变化**：`⏺ 权限请求` 与 `⏺ Shell 命令确认` 两个框现在有光标、可以上下选、
Enter 确认、数字直达、Esc 有明确出口；原来的 y/n/a 字母**一个都没删**。

四处改动：

1. **新增 `packages/cli/src/ui/components/permission-choices.ts`** —— 选项集构建 +
   `resolveChoiceKey` 按键决策，都是纯函数。选项集不是固定三项：随工具类型（Bash 才有持久档）
   与危险性（破坏性命令去掉持久档、「拒绝」提到首位）变化，这套分支原先散在两份组件副本里。
2. **新增 `packages/cli/src/ui/components/shared/HotkeyChoiceList.tsx`** —— 确认类弹窗的
   选择控件，权限框与 Shell 确认框共用。它只做副作用（移光标 / 回灌），判定全部委托给纯函数。
3. **改 `DialogManager.tsx` 的 `PermissionDialog` / `ShellConfirmDialog`** —— 各自删掉手写的
   `key.name === "y"` 分支和两套硬编码 JSX 选项行，改用上面的组件。
   顺带把安全默认从「文案暗示（拒绝写在前面并标『推荐』）」升级为**光标真的落在拒绝上**——
   原先危险操作下 Enter 是空操作，「默认聚焦拒绝」这句在线上这份组件里从来没实现过。
4. **删 `packages/cli/src/ui/components/PermissionPrompt.tsx`** —— 全仓零引用的重复实现
   （grep 确认：除自身外只有 `website/blog/` 里讲 claude-code 源码的同名文件命中）。

**顺带修掉一个后端有、前端没入口的缺陷**：`always-persist`（持久化到项目配置，跨会话生效）
在 `app.ts` 有完整链路（`persistBashAllowRule` → `addSessionRule` + `persistRule` 写
project settings），但**线上那份 `PermissionDialog` 从来不 resolve 这个值**——它只在那份
死代码 `PermissionPrompt.tsx` 里有入口。用户按不出来，整条链路是死的。现在 Bash 类工具会
显示 `A 持久化到项目配置`（Shift+A）。

文档同步了四处受影响的描述：`packages/cli/src/ui/CLAUDE.md` L4-E（补三条规则）、
`website/start/first-task.md`、`website/ref/glossary.md`、`website/use/troubleshooting.md`。

## 放弃了什么（以及为什么不选）

- **复用 `shared/BaseSelectionList`**（第一直觉，否决）。四个不匹配：它不支持**字母**
  快捷键，而 y/n/a 是既有肌肉记忆 + 官网文档写明的契约；`A`(Shift+A) 与 `a` 是两个不同决策，
  需要 shift 参与匹配，它的数字快捷键逻辑里没有这个概念；每项要按语义上色（允许绿/拒绝红/
  会话黄/持久蓝），它的 `titleColor` 只有焦点/禁用两态；最后，想靠「再注册一个平级 useKeypress
  补字母键」绕过前三条会与它内部的 Critical handler **同优先级竞争**，命中顺序取决于注册
  顺序（`KeypressContext` 的 `broadcast` 按 reverse 注册序遍历），太脆。
  → 沿用 `ModelDialog` 在注释里记录不复用理由的先例，写一个 80 行专用组件。
- **只给方向键、删掉字母**（否决）。y/n/a 是三份官网文档写明的契约，也是老用户的肌肉记忆；
  且确认框是高频交互，敲一个字母比「移光标再回车」快。三路并存的成本只有一份 `hotkey` 字段。
- **保留 `PermissionPrompt.tsx` 作为「更完整的那份」并改为引用它**（否决）。两份组件长期
  分叉正是这次缺陷的成因（线上那份缺持久档、死的那份缺 shadowedRules 展示）。留着两份
  就是留着下一次分叉。选项集抽成纯函数后，两份的差异全部收敛到一处判定。
- **把 `resolveChoiceKey` 留在组件里**（否决，且这条是关键）。本次缺陷的实质是**判定顺序**：
  原实现把 `if (!key.insertable) return false` 写在导航判定**之前**，方向键 `insertable=false`，
  于是 ↑↓ 在第一步就被吞掉。这种 bug 只有「喂一个 up 键、断言得到 move 而不是 ignore」
  才测得到；只单测选项集是测不到的——选项集全对、方向键照样死。所以决策必须是可单测的纯函数。
- **给危险操作也提供持久档**（否决）。一键把破坏性命令永久写进 project settings，
  代价远大于省下的几次确认。已在 `buildPermissionChoices` 里断言掉。

## 拿什么证明它生效了

**变异自证（最重要的一条）**：把 `permission-choices.ts` 里的 `insertable` 门禁挪回导航
判定之前——也就是**精确复现原缺陷**——重跑单测：

```
$ bun test ./packages/cli/tests/ui/components/permission-choices.test.ts
26 pass / 7 fail        ← 四条方向键断言全红 + Enter/Esc 相关红
```

恢复正确顺序后 `33 pass / 0 fail`。这证明测试锁的是真行为，不是恒绿的空断言
（照 `static-scan-misses-indirect-disk-writes` 那条教训：新增门禁必做变异自证）。

其余门禁：

```
$ bun test ./packages/cli/tests/ui/components/permission-choices.test.ts
  33 pass / 0 fail / 87 expect()
$ bun run affected-tests:run          # 判定 selective：./packages/cli/ ./tests/website/
  1513 pass / 1 fail                  # 唯一失败见下
$ bunx tsc --noEmit                   # 改动文件零错误
$ bun run lint                        # oxlint 通过
$ bun run format:check                # 通过（先跑过 format）
$ bun run lint:boundary               # 越界依赖 0 处
$ bun run docs:gen-reference --check  # 参考页与源码一致
$ make build                          # 成功，自检 4 项全过
                                      # 且 grep 无 "will always be undefined"（worktree 陷阱）
```

**那 1 个失败与本次改动无关**，按 CLAUDE.md 要求的三条证据举证：
① `packages/cli/tests/cli/flag-e2e.test.ts` 零 import 本次任何模块（只 import
`node:path`/`node:fs`/`node:os` + bootstrap 路径常量）；
② 失败于 **5000.30ms**——那是 bun **默认 5s 单测超时**，不是断言失败；
`bun test <该文件> --timeout 30000` → **15 pass / 0 fail**；
③ 成因是 spawn 子进程的 e2e 在负载下踩线，与 `run-statusline-1s-timeout-ci-flake`
记录的同型 flake 一致。
（未在父仓 main 上复跑：父仓 checkout 有另一个 agent 在改代码，不去动它。
用「放宽超时即全绿」替代该证据。）

**端到端按键验证（新增 `HotkeyChoiceList.test.tsx`，15 pass）**：起初想省掉这一层，
用「纯函数单测 + 组件只做 setCursor 一个副作用」的结构性论证代替，
但那样「按 ↑ 光标真的动了」仍是推断而非观测——**按键还要经 KeypressProvider 的转义序列
解析 + 优先级分发才能到 handler 手上**，那一段没被任何测试覆盖过。于是往 stdin 写真实终端
序列（`\x1b[A`=↑、`\r`=Enter、裸 `\x1b`=Esc），断言帧里 `▸` 指针落在哪一行：

```
$ bun test ./packages/cli/tests/ui/components/HotkeyChoiceList.test.tsx
  15 pass / 0 fail        # ↓ 移动、↑ 环绕、Enter 确认、y/n/a/A/数字直达、Esc 出口
```

同样做了变异自证：复现原缺陷后 **8 pass / 7 fail**（方向键与 Enter 相关全红）。

这一层踩到两个坑，都记在测试文件注释里：
① **不能复用 `_vendor/testing.tsx` 的 `render`**——它的 `stdin.write` 发 `Buffer`，
而生产路径 `setEncoding("utf8")` 后解析器按字符串逐字符遍历，喂 Buffer 会
`ch.toLowerCase is not a function` 直接抛错，按键根本到不了 handler。所以本地另建了个
emit 字符串的 harness（没去改 vendor shim：它被 `CoreRendering` 等既有测试依赖）。
② **打键必须 await**：`setCursor` 要一个 tick 才 flush 到下一帧；裸 Esc 还要等
`ESC_TIMEOUT`(50ms) 才能与「方向键前缀」区分开。同步读帧会读到旧光标。

本文件是仓库里第一处这么测键盘交互的地方（此前
`grep -rl "KeypressProvider" packages/cli/tests/` 零命中），新增确认类弹窗可照此写。

**视觉验收**：用一次性脚本把**真实 `DialogRenderer`** 的五种形态渲成帧读了一遍
（普通 write / bash 含持久档 / 危险命令 / Shell 确认 / 48 列窄终端），用完即删。
实际帧（已去 ANSI）：

```text
╭──────────────────────────────────────────────╮
│ ⚠ 危险操作确认                               │
│   工具: bash                                 │
│   详情: rm -rf ./build                       │
│   ⚠ 此操作不可逆：递归/强制删除文件          │
│                                              │
│  ▸ ● n  拒绝（推荐）                         │
│        模型会知道被拒，换个思路继续          │
│    ○ y  确认执行                             │
│    ○ a  本会话始终允许                       │
│                                              │
│ ↑↓ 选择 · Enter 确认 · n/y/a 直达 · Esc 取消 │
╰──────────────────────────────────────────────╯
```

三条肉眼确认的事：① 危险态光标**真的**落在「拒绝」上（不再是靠文案顺序暗示）；
② 持久档只在 bash 出现、危险命令下消失；③ 48 列窄终端下 CJK 混排对齐不漂、
提示行正常换行（框宽由 ink 算，未用 `.length` 手算宽度）。

**仍未做的一步**：没在真实交互终端里用 `sc-dev` 跑一次（本次验收走的是同一套渲染器 +
真实转义序列，但不是人在 iTerm 里亲手按）。剩余风险限于具体终端的字体/配色差异。
