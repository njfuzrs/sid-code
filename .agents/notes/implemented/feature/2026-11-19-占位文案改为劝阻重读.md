# 过期清理占位改为劝阻重读，K 经离线回放校准后保持 8

## 决定了什么

`context/stale-tool-output.ts` 的只读工具占位换成新文案（方案文档 PR6）：

- `read`：`[已过期清理: read("path")，原始 N 字符，tool_use_id=<id>。这是上下文管理的自动清理，文件没有变化。若只是回忆内容，以你已写下的结论为准，不要重读；若要修改这个文件，只重读要改的那一段。]`
- 其他可复现只读工具：`[已过期清理: <call>，原始 N 字符，tool_use_id=<id>。这是自动清理，不代表结果变化。以你已写下的结论为准；确实需要原始结果时再重跑。]`

四处刻意的措辞，对应主会话「未改动重读」25.8% → 42.4%（方案 §2.5）的四条成因：

1. **删掉 `offset=..., limit=...` 模板** —— 模板本身在教模型「重读一次」，而清理之后更常见的场景是「结论已经写下了，只是想再看一眼原文」；
2. **写明「文件没有变化」** —— 模型看到占位最常误判成「内容丢了 / 文件被改了」；
3. **区分「只是回忆」与「要改」** —— 主会话改文件前重读是正当的，不能一律劝阻；
4. **带上 `tool_use_id`** —— 省得模型翻历史猜这条结果对应哪次调用。

`describeInput` 认数组：`read_many` 的 `pattern` 是 `string[]`，不认数组时它被清理后占位里一个参数都没有。`pattern` 在键序里提到 `path` 之前（两者同时出现时，「读/搜什么」才是重跑必须带上的信息）。`filePath` 提取同步改用 `pickPath`，**单元素数组才当路径**——多元素是 glob 列表，硬取第一个会编出一条不存在的路径。

**K 不动，保持 8。** 11-12 Note 预登记的处置是「重读率上升就优先调大 K」，本次执行它之前先用离线回放量化了成本侧，结论是这个方向不成立（数据见第三段），于是 K 这一维留在 8，重读循环交给文案治。

## 放弃了什么（以及为什么不选）

| 方案 | 否决理由 |
|---|---|
| K=12 / 16 / 24（调大 K） | 离线回放（本机 550 个真实主会话）显示成本侧**净亏**：缓存未命中 p95 只比 K=8 少 0.12 / 0.29 / 0.45pp，但末态释放 p50 从 36.4% 直接归零（一半以上会话攒不到 N=20k，整条通道等于关掉）、p95 掉 2.8 / 4.1 / 6.3pp。采纳规则「每会话 input token 不劣于 K=8」在 K>8 时结构性不成立 |
| 在线 A/B（S-E，7–10 任务 × 2 臂） | 需要真钱与 1–2 小时台架搭建，本次由用户明确选择不做。**代价是本 PR 拿不到「未改动重读率是否回到 30% 以下」的在线证据**，只能上线后从轨迹看——这一点不许在验收记录里写成已通过 |
| 保留 `offset=..., limit=...` 模板 | 模板给模型一个「怎么重读」的现成动作，与「不要为回忆而重读」的目标直接冲突 |
| 放宽只读白名单来减少清理 | 11-12 Note 已明文否决；要治的是文案，不是判据 |
| 给有副作用工具的占位也加 `tool_use_id` | 那类占位本来就带 200 字符摘要，能对上号；最小改动 |
| K/N 做成环境变量 | 沿用 11-12 的否决：会出现「本机调过、CI 没调」两套行为 |

**CI 首轮红了一处，是选测漏掉的第三类跨域断言**：`packages/core/tests/agent/fork-prefix-alignment.test.ts:344` 用 `expect(sentT0).toContain("offset=")` 作为「这条历史只被 stale 通道改写过」的**前提断言**。改文案后前提不再成立，断言红。

- 为什么本地没拦住：`affected-tests` 按目录映射（`src/context/` → `tests/context/`），选不到 `tests/agent/`；而我推送前 grep 的是旧文案的**整句**（「按需用 read」「需要时重新执行该调用即可恢复」），没 grep 被删掉的**片段本身**（`offset=`）。CLAUDE.md 记的前两类跨域断言（源码字面量、写盘哨兵）都命中了这个盲区，这是第三类：**测试把某个字符串片段当「前提/指纹」用，而不是断言语义**。
- 处置：改前提断言为 `tool_use_id=t0`（新文案同样能证明「只被 stale 通道改写过」）。这是契约被有意变更后的同步修正，**不是为凑绿改预期值**——被测行为没有回归，回归的是断言所依赖的指纹。
- 复发预防：改字符串常量时，grep 的对象应是「被删/被改的那个片段」（`offset=`、`精度重读`…），而不只是完整句子。

**还没证明的**：在线「未改动重读率」与「轮次 p95」。没有 A/B，本 PR 只能证明文案与参数解析在 G1 层面正确、成本侧不倒退（K 不变时占位只长几十字符）。方案文档 PR6 采纳规则的第一条「未改动重读率回到 30% 以下」**尚未验收**，需要在合入后从轨迹看，或补跑 S-E。**不要把本 PR 当成「主会话重读循环已解决」。**
