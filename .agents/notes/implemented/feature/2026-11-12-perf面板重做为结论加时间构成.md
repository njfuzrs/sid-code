# /perf 面板重做：结论在前，时间拆四段，后台调用单列

## 决定了什么

这是 PR-B，修 D5 D6（展示） D7 D8 D9 D10 D12 D14 D15 D16 D17。北极星方向：**可观测**的产品出口。
数据口径由 PR-A（#768）定，这里不改任何进索引的字段。

- **三层拆开**。取数在 cli `perf.ts`。报告模型 `buildSessionPerf` 和瓶颈判定 `judgeBottleneck` 在 core
  `perf-report.ts`，都是纯函数，不带格式。渲染在新文件 cli `commands/perf/render.ts`。`--json` 直接输出报告结构，字段即契约。
- **明细在 digest 里算**。新增 `trace/perf-detail.ts` 的 `aggregatePerfDetail`，挂到 `Digest.perfDetail`。
  它产出时间构成、按工具聚合、最慢 3 次调用、慢响应/停滞/超时/重试计数、后台辅助分组，以及 n<5 时的原始样本。
  digest 已经把 events 读进内存了，命令层不再读第二遍文件。来源判据只用 `callScopeOf`。
- **时间构成四项之和等于活跃时间**（T-B1）。四项是：等首字节 = Σ主循环 TTFB；生成 = Σ主循环 `stream_completed`；
  工具 = Σ主循环 `PostToolUse`；其他 = 差值。差值为负时（老轨迹没有 TurnComplete）把活跃时间抬到三项之和，
  不让「其他」出现负数。
- **瓶颈判定**按方案 D7 的 5 条规则实现，阈值都是导出常量。`TTFB_BUFFER_GAP_RATIO` 直接等于
  `latency-by-model.ts` 的 `ROUTE_BUFFERING_GAP_THRESHOLD`，测试同时读 `northstar/README.md` 锁住「> 50%」。
  `TTFT_P95_WARN_MS` 从 `digest.ts` 的 provider warning 里抽成常量，`/trace` 和 `/perf` 共用。
- **样本规则**（D5）：n<5 时不渲染分位数，直接列出样本；n<100 时 P99 写 `—`；n 永远显示。
  `MIN_TREND_SAMPLES` 改成复用 `MIN_PERCENTILE_SAMPLES`，仓库里只有一个 5。
- **后台被中止的判据**（D10/D11 显示部分）：fetch 发出后没等到 `StreamPhase(completed)` 就算中止，括号里给出最长一次的
  `fetch_sent → stream_completed` 墙钟。**不按 60s 字面量判**，因为各调用方上限不同（记忆 fork 60s、dream 120s）。
- **进行中**（D16）：第一行写「进行中 · 截至 HH:MM:SS」。墙钟来自 30s 节流的快照，活跃时间来自实时 events，
  会出现墙钟比活跃时间短，所以墙钟取两者中较大的一个。
- **D12 做了**：`buildByVersion` 带上每个版本的 `incompleteSessions`。占比 >30% 的版本加一行暗色脚注，
  不改写历史索引。
- **D14**：`--by-version` 补「生成 P95」「工具/会话 P50」两列，窄终端时省略。整列无样本的版本点名说明。
- **渲染**：列宽用 `string-width`；横条用八分之一格；时长统一为 `<10s 一位小数 / <60s 整秒 / XmYYs / XhYYm`。
  超宽行优先在空格处折行，折行时在续行重放 SGR（`<Ansi>` 按行解析，颜色不跨行）。窄于 80 列时去掉横条、P99 列和工具「最长」列。
  颜色只在交互 TUI 开：`config.print`、非 TTY、`NO_COLOR` 三种情况都不出 ANSI。
- 官网 `website/use/performance.md`：示例换成取证会话的真实输出，补上「怎么判断慢在哪」的 6 条规则、样本规则、`--json` 字段说明。

## 放弃了什么（以及为什么不选）

- **渲染放 core**：没选。列宽需要 `string-width`，只有 cli/tui 依赖它。颜色要跟终端能力走，这也是 cli 的事。
  给 core 加依赖会让 `lint:boundary` 和单文件 core 的定位都变差。代价是 PR-A 的两条渲染断言跟着从 cli 导入。
- **保留旧的 `renderSessionPerf` / `renderTrend` / `renderByVersion` 作为 core 的无色兜底**：没选。两套渲染一定会漂移；
  无色输出已经由 cli 渲染器的 `color: false` 覆盖，而且是同一份代码。
- **按模型分档阈值**（比如 glm 系 TTFT 天然高就放宽）：没选。规则只认实测信号（reasoning 占比、gapRatio、命中/未命中比），
  见记忆 `feedback-no-hardcoded-model-tier-rules`。
- **拆成多个子命令**（`/perf time`、`/perf tools`……）来控制面板长度：没选。面板变长是有意的取舍（简洁 ↔ 信息完整）。
  用户打 `/perf` 时问的是「慢在哪」，答案要在一屏里自洽：结论 → 构成 → 证据。拆开后用户要自己拼起来，这正是 D7 要消除的推理负担。
  面板已经按条件省略空段（无后台辅助、单模型、全 0 事件都不渲染），CommandOutputDialog 本身支持滚动。
- **后台中止按 `stream_completed − fetch_sent ≥ 60s` 判**：没选，原因见上（上限因调用方而异）。
  现在的判据「没走到 completed」覆盖了墙钟超时和会话退出两种中止。
- **基线收紧**：`typecheck:gate --update-baseline` 显示可以从 64 收紧到 62，但那两处是 main 上别人修掉的，不属于本 PR，没有提交。
