# 权限可观测三件套：模式切换留痕、决策补成因、确认按成因分桶

## 决定了什么

PR-0（可观测，无行为变更），三处改动同一关注点——**让「哪些确认本来可以没有」这个问题
能从轨迹里直接读出来**，而不是每次写临时脚本重跑判据：

1. **B11 · 模式切换留痕**。`cli/src/app.ts` 新增私有 `setPermissionMode(next, source)`，
   `config.permissionMode` 的 6 处赋值全部改走它；每次真切换写一条
   `PermissionModeChanged { from, to, source }` 进会话 `events.jsonl`。
   `source` 是闭集（`keyboard` / `plan_enter` / `plan_exit` / `claude_md` / `policy` / `command`），
   常量与类型在 `permission/mode.ts`。
   顺带把启动期 pending 队列从「只存 ProjectRulesPermission 的 data 数组」泛化成
   「`{ event, data }` 数组」——CLAUDE.md 模式采纳、企业策略回拨都在 collector 就绪之前发生，
   两条事件共用一个 flush 点，不再各复制一套。
2. **B12 · 决策补成因**。`PermissionDecision` 落盘新增
   `danger_pattern` / `danger_severity` / `bash_shape` / `env_prefix_vars` / `git_trust`。
   `bash_shape` / `env_prefix_vars` / `git_trust` 由 `permission/bash-shape.ts` 的三个纯函数在
   **checker 的 `check()` 出口**统一算好（完整命令 + 工作区路径都在手上），入库
   `Decision.metadata`；`danger_pattern` / `danger_severity` 由 `decisionFactsOf(decision)`
   从 `decisionReason` 取。7 个调用点 spread 一行接入。
   forked 决策的 `mode` 从「留空」改为填 fork 策略名（`fork:memory-extract` 形态）。
3. **B13 · 确认成因分桶**。`SessionLevelMetrics` 新增 `hitl_cause_buckets`
   （`{ bucket, n, timed_n, total_ms }`，按次数降序），digest 的「等人确认」行下面就地输出。
   判据与附录 A.3 的脚本一致：危险优先 → `bash_shape` → 非 bash 按 `reason_type`
   （`pathValidation` 单列为「路径：工作区外读/写」）。

顺带发现并记录：文档说 B12 缺 `metadata.guard`，**实测 guard 早已在 B20 落地并映射**
（`collector.ts` 的 `...(e.guard ? { guard: e.guard } : {})`），本次不重复加。

## 放弃了什么（以及为什么不选）

- **不在 digest 里从命令文本重算 `bash_shape`**。`events.jsonl` 存的是截断后的命令
  （本会话 51 条普通确认里 25 条超过 200 字符），从截断文本重跑判据会把长命令整段误判成
  「非只读其他」——那个读数看起来像数据，其实是错的。分类必须在决策时算。
- **不做成「各处各记一条事件」**。6 处赋值里 5 处原本不留痕，逐个补就是下一个入口漏抄；
  静态门禁（`config.permissionMode =` 只能出现在 `setPermissionMode` 内）守的是模式，
  不是这一批调用点。
- **不给 `setPermissionMode` 加「值没变就不调用」的调用方契约**。同值不写事件由函数内部判，
  调用方不必自己判——原先 6 处各写各的，漂移正是这么来的。
- **`bash_shape` 不做精确的 cd 目标解析**（`PathValidator.isWithinWorkspace`），
  沿用 A.3 的裸 `startsWith` 前缀判据，包括它已知的粗糙点：`/Users/x/proj2` 会被算进
  `/Users/x/proj` 的工作区内。理由：**基线数字出自那份脚本，判据不同就无法对拍**；
  它是上界估计（只看 cd 前缀 + 主体是否只读，不看 git 仓库身份），PR-2 才由精确解析取代。
- **`env_prefix_vars` / `git_trust` 的取值，由本 PR 自己接线而不是「等 PR-1 填值」**。
  方案原文写的是「PR-0 先留字段、PR-1 填值」，但 PR-1（#826）在 05:59 合入 main，
  **早于这两个字段存在** —— 那个分工在时间上不可能成立，留着就永远是两个空字段。
  所以 merge main 后在本 PR 补了 `collectEnvPrefixVars`（复用 B1 的
  `isForbiddenAssignmentName`）与 `resolveCdTargetGitTrust`（复用 `resolveGitRepoTrust`
  + checker 构造时已算好的 `ownCommonGitDir`，不重复 stat）。键缺省不落盘
  （落空数组会被读成「看了，没有变量」——那是另一种事实）。
- **不把分桶进 `session-index`**。digest 的定位是单会话报告；索引行已有固定字段集，
  分桶数组只对本机排障有意义，不扩索引体积。

## 拿什么证明它生效了

- **新增测试 + 变异自证**（三组共 23 个用例全部通过）：
  - `packages/core/tests/permission/bash-shape.test.ts`（7 个）：五个形状桶逐桶钉死，
    包括上面的前缀粗糙点与 `dangerous` 的优先级。
  - `packages/core/tests/trace/permission-observability-pr0.test.ts`（11 个）：真实 checker →
    门面 → 真实 `TraceCollector` → **读 `events.jsonl` 原文**断言 `danger_pattern` /
    `danger_severity` / `bash_shape` / `env_prefix_vars`（`GIT_DIR=/tmp/x git status` →
    `["GIT_DIR"]`）/ `git_trust`（`cd <tmpdir> && git status` → `none`）/ fork 的 `mode`；
    以及 digest 分桶的计数、墙钟、「未分类」与「非主循环不进桶」。
  - `packages/cli/tests/app/permission-mode-event.test.ts`（5 个）：静态门禁 + 真实 App 的
    `PermissionModeChanged` 落盘（from/to/source）、同值不写事件、未就绪进 pending。
  - **变异自证**：把 Shift+Tab 那处改回直接赋值 → 静态门禁从「1 处」变红成「2 处」；
    删掉 collector 的 `bash_shape` 映射 → 两条落盘断言从 `"dangerous"` /
    `"cd_workspace_readonly"` 变红成 `undefined`。两处均已恢复。
- `bun run typecheck:gate`：62 处 / 基线 62 处，**无新增类型错误**。
- 待跑的完整门禁与验收（`make build` / `bun run smoke` / affected-tests / lint / format）
  在 PR 说明里贴结果。

**未证明的一件事**：分桶对真实历史轨迹的读数（§6.4 的基线采集）需要维护者本机跑
`bun scripts/trace-digest.ts <id>`；本次只证明了「同一份 events 进去，桶算得对」。
