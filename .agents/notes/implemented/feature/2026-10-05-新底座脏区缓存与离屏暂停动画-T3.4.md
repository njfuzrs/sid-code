# 新底座脏区缓存、离屏暂停动画与 yoga WASM 开销实测（B9 / T3.4）

## 决定了什么

- **节点级输出缓存（P3）**：每个 DOM 节点带 `renderDirty` / `renderCache`。文本、子节点增删、样式、属性、transform、显隐
  这几个变更入口把节点和**全部祖先**标脏（不在半路停：`display: none` 跳过的子树可能留着脏标记而祖先已清）。
  输出时，子树没标脏、横坐标 / 宽高 / 外层 transformer / skipStatic 都没变，就回放上次记下的输出操作，
  按纵向位移平移，不再遍历子树、不读 yoga。横坐标必须比，因为 `\t` 对齐的是屏幕绝对列。
- **屏幕单元存整数 id**：字形簇进程级驻留（0 = 空格，1 = spacer），`chars` 改为 `Uint32Array`，取字符串走 `charAt`。
  整屏分配从逐格字符串数组变成一次清零，帧 diff 的行比较直接比四个平铺数组，不再每格调函数。
- **TTY 交互帧不生成纯文本**：只有 debug / 非 TTY / 读屏路径读 `output`，交互路径只比屏幕缓冲。
- **离屏暂停动画（新契约 P5）**：`useAnimationFrame` 在渲染时按**上一次提交的布局**判断 ref 盒是否在主屏视口内，
  不在就不订阅时钟。规则来自黑盒扫描旧底座 105 组「盒高 h × 上方行数 y × 帧高 p」（视口 10）：
  p ≤ H 一律在走；否则盒底边 `y + h - 1 ≥ p - H + 1` 才在走（视口里看得到的是帧的最后 H - 1 行）。
  恢复要等父级重渲、且上一帧里已回到视口；`React.memo` 包住的一直停着。这几条也都对拍过旧底座。

## 实测数字（`useSyncExternalStore` 每 5ms 改底部一行，历史 N 项，每项 Box + 2 个 Text，100×30，onFrame 帧耗时 p50 / ms）

| N | legacy | next 改前 | next 改后 |
| --- | --- | --- | --- |
| 200 | 0.35 | — | 0.64 |
| 500 | 0.61 | 2.89 | 1.08 |
| 1000 | 0.98 | — | 1.76 |
| 2000 | 1.68–1.76 | 8.05 | 2.87–2.95 |
| 5000 | 4.73 | — | 8.22 |

**yoga WASM 开销（D-2 遗留）**：同一场景每帧 `calculateLayout` 在 N = 2000 时 p50 1.34ms、N = 5000 时 3.97ms。
合成树（2000 个盒、只有最后一个叶子标脏）重排约 0.95ms，measure 函数只调 1 次。也就是说，开销不在 measure 回调，
而在 yoga 遍历 root 的全部直接子节点（column 方向上一个叶子变了，后面兄弟的位置都要重算）。没变化时重排 0.001ms。
**结论：WASM 本身不是瓶颈，能打包、能用；但这部分是 O(子节点数)，脏区缓存管不到。**

## 放弃了什么（以及为什么不选）

- **在帧之间复用 `Screen` 只重写脏区**：要处理「被删 / 被挪走的区域要清成空白」，还得和覆盖顺序、裁剪框一起推导，
  正确性证明比操作级回放难得多。操作回放的语义就是「重放上次的写入」，与冷渲染逐字节一致可以直接断言。
- **按 yoga `hasNewLayout()` 判断子树是否变化**：实测一个叶子变化后 root 下 2000 个子节点全部报 new layout，不可用。
- **离屏暂停用 IntersectionObserver 式的布局监听，暂停后自动恢复**：旧底座不是这样（回到视口后还要再来一次父级重渲才恢复），
  照做反而对不上行为；而且会多一次每帧回调。

## 拿什么证明它生效了

- `packages/tui/tests/render-cache.test.tsx`（10 条）：
  ① 经 React 走 16 种变更（中间插入 / 删除 / 等高换项 / 颜色 / padding / tab 跟横坐标 / 显隐 / 定高盒里显隐 / transform / 父级拉高 / 同宽文本 / resize），
  每步取底座这一帧**真正写出**的内容，与清空缓存后冷渲染逐字节比；
  ② 2000 项历史只改底部一行，每帧真正遍历的节点数 ≤ 3，与 N 无关（N = 200 / 2000 同一断言）；
  ③ DOM 层逐个 API 自证：直接调 `setTextNodeValue` / `setStyle` / `setAttribute` / 增删 / insertBefore / transform，一次只动一处。
- `packages/cli/tests/render-port/contracts-animation.test.tsx`（13 条 P5）：legacy 与 next 上都通过（期望值是 legacy 实测）。
- 变异自证 18 处全红：缓存不平移、不比 x / 宽 / 高 / transformer、从不清脏；dom 的 setStyle / 文本 / 删除 / insertBefore / append 不标脏；
  动画不暂停、可见段多 1 行、只看盒顶、p = H 判离屏。改动用 `cmp` 核对后已还原。
  **第一轮有 12 处是绿的**：测试拿「自己再调一次 renderer」当带缓存那一侧，底座刚按当前布局渲过，缓存已是最新，测不出平移和键遗漏；
  另外 PassThrough 的 `data` 是异步派发，同步断言读到的是空串，`expect("")` 恰好和别的什么一起被吞掉。改成接管 `write`、等提交后比真实写出，才转红。
- next 上的 render-port 测试：失败集合与改动前完全相同（30 条，都是 T4–T7 还没做的功能），没有新增红；引擎级场景 E1–E10 照常一致。
- `tui:spec`（58 条，55 条已测）/ `tui:similarity` / 三份向量 `--check` / `lint:boundary` / `lint` 全过；tsc 错误数与 HEAD 相同（71）；`make build` 通过。
- 全量 14019 pass / 1 fail：失败的是 `contracts-termio` 的 O6（win32 / linux 首选成功轮流挂），是全量负载下的子进程超时，
  单独跑 3/3 通过，这次没碰 termio。

## 没做 / 移交

- **P3 只做到「节点遍历 O(dirty)」，帧耗时整体仍随 N 增长**：剩下的是 yoga 重排（O(root 子节点数)）、整屏分配与 diff（O(帧高)）。
  N = 2000 时 next 约为 legacy 的 1.7 倍，N = 5000 约 1.7 倍。SPEC 的 P3 已按这个口径改写，没有声称「不随历史增长」。
  真实会话里历史在 `Static`（T4.2）里，能否把已进 scrollback 的历史排除在每帧布局之外，归 T4.2 一起设计；P2 的 1.1 倍门槛要等 S1 能在 next 上跑（T5.x）再判。
- `measureElement` / `useBoxMetrics` 读布局不受缓存影响（它们读 yoga，不读输出缓存），没有单独加测试。
