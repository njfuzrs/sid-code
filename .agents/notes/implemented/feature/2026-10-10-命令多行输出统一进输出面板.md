# 命令的多行报告统一进输出面板

## 决定了什么

斜杠命令的多行诊断/查看报告（/doctor /status /trace /mcp list 等）不再追加进消息流，统一进一个
通用的命令输出面板 `CommandOutputDialog`：Esc / q 关闭，可滚动，视口按终端高度截断，消息流不留痕（命令行与摘要都不写；初版留过一行「xxx（N 行 · 已在面板中查看）」，人工走查判为噪音，已去掉）。

排查出的问题与处理（全部已完成）：

- [x] **缺一条「命令结果进弹窗」的通用通道**。此前想要弹窗只能为每个命令手写 Dialog、登记 `DialogType`、
  在 `DialogSwitch` 加分支，成本高到大部分命令都直接返回文本。现在命令声明 `outputPanel: true` 即可。
- [x] **文本结果在消息流里不折叠**（`CommandMessage` 对非 bash 命令刻意全量渲染），几十行灌进 scrollback。
- [x] **结果进了消息流就关不掉**，只能等它被滚上去。
- [x] **命令结果会被冲掉**：结果不进 ctxMgr，`syncDisplay` / `rebuildDisplay` 从 ctxMgr 全量重建 historyItems，
  下一次同步时就没了（`app.ts` 原注释已承认这一点，但只修了 submit_prompt 一路）。改为记进侧表、重建时按锚点插回
  （`ui/local-command-items.ts`）；/clear、/compact 时清空侧表。
- [x] **/export 的结果从未显示**：写的是 `tuiStateUpdater({ commandOutput })`，TUIState 没有这个字段。
  改走与斜杠命令同一条上屏通道，导出失败也给回执（原来是静默吞掉）。
- [x] **38 个命令标上 `outputPanel`**：新体系 14 个（doctor status debug insights workflows keybindings todos
  conflict terminal-setup diff bug claude-api model statusline），旧体系 24 个（help config cost stats cache trace
  telemetry checkpoints memory hooks undo restore mcp ide lsp skills agents commands plugin reload-plugins
  permissions ps worktree cron）。
- [x] 规则写进 `packages/cli/src/ui/CLAUDE.md` L4-H，新增查看类命令照此声明。

关键口径：

- **命令声明 + 行数下限**：标了 `outputPanel` 的命令，结果 ≥ `PANEL_MIN_LINES`(3) 行才进面板。
  同一命令的报告与回执长度悬殊（`/cron` 列表 vs「已删除任务 x」），回执和用法错误留消息流。
  结果上显式带 `panel` 则强制进，不受下限约束。
- **子命令继承父命令**：`executor.resolveOutputPanel` 沿命令路径取最近一个声明。必须单独走一遍：
  legacy 适配器递归适配子命令时不带门控字段，只看叶子会漏掉 `/mcp list` 一族。
- **只影响 TUI**：headless / `-p` 照样输出纯文本（面板字段只在 TUI 的结果分发里被消费）。

## 放弃了什么（以及为什么不选）

- **全局按行数自动判定**（任何命令超过 N 行就弹）：同一命令输出变长就突然换交互形态，不可预期；
  /btw /loop 这类与对话相关的长回答也会被误弹。
- **为每个命令写专属 Dialog**（沿用 /stats /help 的做法）：正是这个成本导致了现状。专属面板只留给
  需要选择/编辑交互的场景。
- **启用 executor 里已有的 `local-jsx` 通道**：`app.ts` 的 `setToolJSX` 是空函数，要接就得在两个布局里
  再加一块挂载点，而这些命令只需要「展示一段文本」，用不到任意 JSX。
- **/diff 不进面板**（分析时列为待定，顾虑是 diff 要复制而面板有边框）：面板按 ui/CLAUDE.md L2.2
  只画上下横线、不画左右竖线，复制干净，顾虑不成立，于是一并进面板。
- **round 全框**：同上，命令输出属于「用户会复制」的区域。
