# 新底座 termio 端口面：OSC / 多路复用器包裹 / 剪贴板 / 超链接判定，经端口在两套底座上差分对拍（B9 / T2.3）

## 决定了什么

- `packages/tui/src/terminal/` 新增 `osc.ts`、`clipboard.ts`、`hyperlinks.ts`。`render-port/next/termio.ts` 的 6 个导出全部接上，
  next 的 termio 端口不再有占位。阶段 2 结束时，next 的 text / termio 两个端口模块都没有占位了。
- 规则全部来自黑盒对拍（D-5）。行为里最容易写错的几条：
  - OSC 终止符在**模块加载时**判定：kitty（`TERM` 含小写 `kitty`、`TERM_PROGRAM === 'kitty'`、`KITTY_WINDOW_ID` 非空）用 ST，其余用 BEL；
    `wrapForMultiplexer` 却是**调用时**读环境。两者时机不同，测试里分别钉住。
  - 剪贴板：本机工具发出去不等结果。`SSH_CONNECTION` 非空就跳过（`SSH_CLIENT` / `SSH_TTY` 不算）。
    linux 依次试 wl-copy → xclip → xsel，记住第一个成功的，之后它失败也不换；三个都失败就记成「没有」，之后不再试。
    darwin / win32 每次都调，不缓存。
  - tmux：**等** `tmux load-buffer`，2 秒超时。只有 `LC_TERMINAL` 恰好是 `iTerm2` 时不带 `-w`。
    成功才返回包裹后的序列，失败、超时、没有 tmux 都返回未包裹的序列。
    **包裹的里层固定用 BEL 终止，哪怕外层是 kitty**；未包裹的那份才按终端选终止符。这一条是差分测试抓出来的，
    单测里原先写的是 `wrapForMultiplexer(sequence)`。
  - 超链接：先信 npm `supports-hyperlinks` 对 stdout 的判定（它在加载时读 `FORCE_HYPERLINK` 等变量），
    否则用 6 个终端名补判：`TERM_PROGRAM` 或 `LC_TERMINAL` 精确匹配（大小写敏感），或 `TERM` 含小写 `kitty`。
- 测试分两层：
  - `packages/tui/tests/terminal.test.ts`：注入命令执行器，钉住调用顺序、缓存、超时参数这些差分测试不好造的分支；
  - `packages/cli/tests/render-port/contracts-termio.test.ts`（新契约 **O6**）：同一段探针只经端口调用，
    在 `SID_TUI_RENDERER=legacy|next` 两个子进程里各跑一遍，25 条环境矩阵逐字节比较。剪贴板命令换成 PATH 前置的假命令，不碰真实剪贴板。

## 放弃了什么（以及为什么不选）

- **把 `setClipboard` 改成等本机剪贴板写完再返回**：调用方（`/copy` 等）现在拿到序列就写终端，改成等会让命令变慢，
  而且会改变可观察行为。没改。
- **差分测试比较完整的调用日志**：本机工具不等结果、tmux 要等，两者谁先写日志是竞态，前两次跑出了不稳定的失败。
  现在 native 和 tmux 分开记录，各自保序（linux 的试探顺序是契约，要保），不比较两者之间的先后。
- **在差分测试里放宽 kitty + tmux 那条**：它反映的是真实行为（外层 kitty 时包裹里层仍是 BEL），所以改实现，不改测试。
