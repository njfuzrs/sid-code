# 新底座按 XTVERSION + DA1 回复认出 xterm.js，alt-screen 单击链接不重复打开（B9 / T8.1a，契约 M4）

## 决定了什么

T8.1 的人工终端矩阵里，第一条能自动化的缺口是「SSH 进 VS Code 集成终端」。这种情况下 `TERM_PROGRAM` 不传，
next 只认这个环境变量，所以单击链接会和 xterm.js 自己各开一次。legacy 在这里会看探查回复。

规则全部来自对 legacy 的黑盒探针（35 个变体，没读旧代码，D-5）：

- 每个实例只认**自己收到的第一条** XTVERSION（`DCS >| 名字`，ST 或 BEL 结尾）。名字以 `xterm.js` 开头才算，区分大小写。
- 这个实例收到**第一条** DA1（`CSI ? … c`）时定案；DA1 比 XTVERSION 先到，这个实例就不再定案。DA2、DECRPM、别的 DCS 都不算定案。
- 定案结果是**进程级**的，只定一次。没定案过就按「不是 xterm.js」处理。
- 可见效果只有一处：M4 链接点击。OSC 8 输出、bidi、渲染字节在喂不喂回复两种情况下逐字节一致（探针 `other` / `render` / `fresh`）。

改动：`input-parser.ts` 的 `createInputParser(onResponse?)` 把完整收到的回复原样交给回调（冲刷时丢弃的半截不交）；
`terminal-probe.ts` 新增 `createTerminalIdentityTracker()` / `isXtermJsTerminal()`；`App.tsx` 每个实例接一个 tracker；
`ink.tsx` 点击判定多加一个条件 `!isXtermJsTerminal()`。

## 放弃了什么（以及为什么不选）

- **一看到 XTVERSION 就判定，不等 DA1**：更简单，但和 legacy 不一致。只收到 XTVERSION 时 legacy 照样开链接，见用例「只有 XTVERSION」。
- **识别结果放在实例上**：legacy 是进程级的。现在 `selection-runtime.test.tsx` 里点击类用例必须放子进程跑，就是因为这一条。
  做成实例级等于悄悄改了行为，会话选择器交接给主 TUI 的那段时序也会跟着变。
- **顺手把识别结果用到别的地方（真彩、同步输出）**：探针显示 legacy 别处都没用它，加了就是新行为，不在本次范围内。

## 拿什么证明它生效了

  legacy 与 next 都绿。子进程没打印结果算失败，不会零断言全绿。
- 变异自证 5 处全红：永远返回「不是」、取最后一条 XTVERSION、定案后可改写、不定案、DA2 也算定案。
  第一轮里「不定案」和「DA2 也算」这两处是绿的（漏网），补了「DA1 → XTVERSION → DA1」「只有 DA2」两条用例后才红。
