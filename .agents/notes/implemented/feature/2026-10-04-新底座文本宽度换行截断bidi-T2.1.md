# 新底座文本工具：宽度 / 换行 / 四种截断 / bidi，对拍旧底座生成的向量（B9 / T2.1）

## 决定了什么

- `packages/tui/src/text/` 新增四个模块：`width.ts`（列宽）、`slice.ts`（按列切 ANSI 文本）、
  `truncate.ts`（换行 + 四种截断）、`bidi.ts`（软件 bidi）。上游的 `wrap-text.ts`、`measure-text.ts`、
  `render-node-to-output.ts` 改为调用它们，所以 `<Text wrap>` 在 next 上走的就是这套语义。
  端口 `next/text.ts` 的 `stringWidth` 接上。
- 规则全部来自**黑盒对拍**：只调用旧底座、比较输出，不读它的实现（D-5）。具体做法：
  - 列宽：`Bun.stringWidth` 加 `ambiguousIsNarrow: true`。在全部码位（去掉代理区）上与旧底座逐个一致。
  - 换行：`Bun.wrapAnsi` 加 `hard: true`。`wrap` 与 `wrap-trim` 两种模式都与旧底座逐字节一致。
  - 截断：基于 `@alcalzone/ansi-tokenize` 自写列切片。省略号放在样式之外；零宽字符跟着前一个字符；
    宽字符不劈半，宁可少占一格。
  - bidi：只在 win32、设置了 `WT_SESSION`（空串也算）、`TERM_PROGRAM=vscode` 时，用 `bidi-js` 按字符簇重排。
- 向量入库：`bun run tui:text-vectors` 从旧底座生成 `packages/tui/tests/fixtures/text-vectors.json`，
  加 `--check` 可检查是否过期。`packages/tui/tests/text.test.ts` 只读这份向量，不 import 旧底座，
  所以 T9 删掉旧底座后测试照样成立。这份 JSON 已从 oxfmt 排除，属于生成物。

## 放弃了什么（以及为什么不选）

- **直接用上游的 npm 组合**（`string-width` / `wrap-ansi@10` / `cli-truncate` / `slice-ansi`）：对拍后不可接受。
  `string-width` 有 478 个码位与旧底座不同，集中在天城文连字：终端实占 2 格，它算 1 格，会让布局和光标错位。
  `wrap-ansi@10` 在 CJK、ZWJ、`\t` 上的折行结果与旧底座不同。`cli-truncate` 把省略号放进 SGR 里面，还会吞掉 `\t` / `\n`。
  语料 952 例中 73 例不一致。
- **把差异写进白名单、接受行为变化**：本方案的前提是 TUI 零回退。白名单要逐条给理由，而这些差异里没有一条是「新行为更好」。
- **在测试里直接 import 旧底座做实时对拍**：T9 删掉旧底座后测试就失效了，还会让 `packages/tui` 的测试依赖 vendor 目录。
- **从旧底座复制 bidi-js 的类型声明**：本会话里先这样做过，随即发现违反 D-5，已改为按 bidi-js README 自己写。

## 拿什么证明它生效了

- `bun test ./packages/tui/tests/text.test.ts`：178 pass / 0 fail。覆盖全码位宽度、14 个多码位序列、
  19 段语料 × 8 种模式 × 宽 0–20 的换行与截断、11 段 bidi 语料。
- 本地探针（未入库）：`sliceColumns` 与旧底座的列切片在 15 段 × 2250 例上 0 差异。
  bidi 在 darwin / `WT_SESSION=1` / `WT_SESSION=` / vscode / win32 / linux 六种环境下 0 差异。
- 变异自证：以下 8 处改动各自至少让 1 条测试转红，sha256 核对后已还原。
  - `ambiguousIsNarrow: false` → 7 fail
  - 截断去掉宽字符收紧 → 21 fail
  - middle 改用 ceil → 15 fail
  - `WT_SESSION` 判定改成真值判断 → 1 fail
  - 超链接关闭码过滤 → 5 fail
  - 末尾悬空序列分支 → 1 fail（初版 0 fail，补了直测）
  - 空切片提前停 → 4 fail
- next 下：`SID_TUI_RENDERER=next` 跑契约 T1 共 8 pass。契约 T2 走 `testing.render`，要等 T3.2 才能在 next 上跑。
  这期间用 `renderToString` 手核了 `<Box width={9}><Text wrap>` 的四种模式，输出与 T2 期望一致。
- 门禁：`tui:similarity` 显示无非上游重复块；`lint`、`format:check`、`lint:boundary`、`tui:spec` 全绿。
- 全量：`bun test` 13708 pass / 1 fail。失败项是 `gen-reference --check`，原因是 T1.3 新增的
  `SID_TUI_RENDERER` 没有重新生成到 `website/ref/env.md`。本次已重新生成并一同提交，单独重跑 54 pass。
  `make build` 无 undefined 警告。
- 顺带修正 `next-switch.test.ts` 里的抛错样本：原来取的是 `stringWidth`（T2.1），现在它已经实现了，
  所以改用 T4.3 的 `measureElement`，免得每完成一个阶段 2 任务都要换一次样本。
