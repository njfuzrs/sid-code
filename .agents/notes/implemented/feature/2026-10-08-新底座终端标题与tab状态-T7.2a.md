# 新底座实现 useTerminalTitle / useTabStatus（契约 O1 / O2，B9 / T7.2a）

## 决定了什么

- 新增 `packages/tui/src/hooks/use-terminal-title.ts`、`use-tab-status.ts`，换掉 `render-port/next/hooks.ts` 里两个 `notImplementedFn`。
- 规则来自黑盒对拍旧底座，没有读旧代码（D-5）：
  - **标题**：`null` 不写。其余用 `strip-ansi` 去 ANSI，空串也照写。先写 OSC 2 再写 OSC 0，终止符随终端，**不经** tmux / screen 包裹。win32 不写序列，改写 `process.title`。同一个值重渲不重写，组件卸载也不写。
  - **tab 状态**：OSC 21337 带三个字段，busy / idle / waiting 的颜色和文案固定。序列**要**按 tmux / screen 包裹。`null` 写清除序列，但只在之前写过状态时才写。`SID_DISABLE_TAB_STATUS` 非空就关闭（`0`、空格都算，空串不算），每次状态变化时读一次，关闭期间不记账。组件卸载不写。
- 两个 hook 都直写渲染用的 stdout，不走 `writeToStdout`（那条路会擦屏再重绘）。旧底座在 TTY 和非 TTY 下都只追加 OSC 字节。
- 新增依赖 `strip-ansi@7.2.0`，与根 `package.json` 解析到的版本相同，精确钉版本。
- 契约测试 `packages/cli/tests/render-port/terminal-title-tab.test.tsx` 共 10 条。SPEC 的 O1 / O2 测试列从 S14 改指向这个文件。S14 继续 covers O1 / O2 / O3，作为端到端对照。
- `next-switch.test.ts` 里「函数占位会抛」的样本改成直接测 `notImplementedFn` helper。值占位早就是这么测的。剩下的函数占位 `setSuppressTerminalProbe` 正在 T5.2 并行实现，再挑一个真实符号当样本，下一次又得换。

## 放弃了什么（以及为什么不选）

- **经 `writeToStdout` / `TerminalWriteContext` 写**：上游的 `writeToStdout` 会先擦主屏再重绘最后一帧，标题每变一次就多出一整帧的字节，和旧底座不一致。`TerminalWriteContext` 的归属留给 T7.2b（O3 进度 / 通知）再定，这次不动。
- **自己写去 ANSI 的正则**：`strip-ansi` 在 9 组样本上与旧底座逐字一致（CSI、OSC 8、C1 CSI 都去掉；孤立 ESC、DCS 原样保留），自写正则只会多出一处要维护的边界。
- **组件卸载时清 tab 状态**：旧底座只在 Ink 卸载序列里清（属于 X3 的同步写序列，还会清进度），组件卸载时什么都不写。这件事归 T7.1b，这次没做。
