# 延迟拆解与防线可观测：attempt 唯一键 + 真 Histogram + 防线四件套 + raw 内容开关

## 决定了什么

一个 PR 落四项（对应方案 PR5–PR8），共同点是**都在补"指标存在但用不了"这一类缺陷**，
不是加新功能。

**① `StreamPhase` 补 `attempt`（PR5）。** `(session_id, index)` **不是唯一键** ——
重试复用同一 index，实测 `20260806-182533-a927c544` 的 `index=4` 下有 7 组完整 phase 序列。
序号由 `stream-observer.ts` 按 phase 序列自行推导（`fetch_sent` 进位；
anthropic 不发 `fetch_sent`，用"本代已见过 headers"作换代信号），
不要求 provider 透传 —— `openStream()` 签名里根本没有这个参数。

要害在**计数表 `_attempts` 与 `_snapshots` 分开存**：快照在每次重试前被
`clearStreamSnapshot` 主动清掉（防看门狗读到脏 `lastContentProgressAt` 误杀），
attempt 放进快照会跟着归零，于是同一 `(session,index)` 下出现多个 `attempt=1` ——
**键仍不唯一，但它现在看起来像唯一的**，比没有这个字段更糟。
`_attempts` 因此只在 loop / agent 整体收尾时清（与"一个 index 的生命周期"对齐，
而非"一次 fetch 的生命周期"）。

**② `MetricPoint` 支持分桶，TTFT 与 turns 出真 Histogram（PR6）。** 落盘基线是
2817 条**全是 counter**、5 个 `recordMetric` 调用点全在 `metrics/token-meter.ts`。
`type: "histogram"` 早就声明了但无处安放分桶，导出器只能降级成 gauge。
现在 `otlp.ts` 带 bounds 就出真 histogram，聚合键是 **(attributes, bounds)**。
TTFT 埋在 `first_content` —— 三条 provider 路径的唯一汇聚点（T14.6 收敛过的）。
turns 依据是实测「轮数 vs e2e r = 0.767」，二版把最强的因子漏在了 metric 之外。

**③ 三层防线补 metric 四件套（PR7）。** `circuit-breaker` / `denial-tracking` /
`policy-limits` 三处此前 `recordMetric` 全部零命中。形状取自 codex guardian：
counter + duration + token histogram 共用同一组 tag。埋点放在**标签真正存在的那一层**
（三层变量作用域几乎不相交，见 `defense-metrics.ts` 文件头那张表）。

**③b 顺带把 `policyLimits` 接上线（PR7 的前置，这是本次唯一的行为变更）。**
`isPolicyAllowed()` 在 `origin/main` 上**生产调用点为 0**（只有 `setPolicyLimits()`
被调），也就是说企业管理员配了功能开关**毫无效果**，而 `website/team/policy.md`
写着"注入生效"。这直接卡住 PR7：给一个**结构上不可达**的分支埋点，
拿到的是一列永久为零的假数据 —— 那正是本 PR 要消灭的缺陷类型，不能自己再造一个。
所以先接线（4 处 gate：`sub_agent` 工具注册 / MCP 服务器集合 / 自定义命令加载 /
扩展面扫描），再埋点。

**必须点破：这一项超出了"加仪表"的范围，是用户可感知的行为变更** ——
此前配了 `policyLimits` 的企业，升级后功能才真的会被禁掉。
这是修复"文档承诺了但没实现"，不是新增限制，但仍应在 review 时单独看这 4 个 gate 点。

**④ `raw.jsonl` 补内容级开关（PR8）。** `TraceConfig.recordRawPayloads`（默认 `true`），
env 兜底 `SID_CODE_TRACE_NO_RAW=1`。**开关关的是内容，不是文件**：
`request_sent` 那行纯计数记录必须留着，`collector.countExistingPairs()`
靠数"没有 type 字段的行"续接会话 index，两种记录一起关掉，续接就只剩
`metadata.json` 一条回退路 —— 而那个文件**只有 uploader 会写**（实测全仓仅一处），
没配上传的用户续接时 index 会从 1 重号。

## 放弃了什么（以及为什么不选）

**① 放弃删掉 OTLP 的 histogram→gauge 降级分支。** "现在支持分桶了"是个诱人的删除理由，
但老调用点与任何忘记传 `buckets` 的新调用点仍然只有单值，对它们硬造 bucket 边界
得出的分布是**错的**。降级保留 = 形态诚实。空 `bounds: []` 同样走降级（只有一个
`(-∞,+∞)` 桶没有意义）。

**② 放弃把报告层的分位搬进 metric 层。** `digest.ts` 的 `percentile()` 被
ttft/gen/elapsed/e2e 四组消费，**报告层不是债，是另一个消费面**，且是相对 CC 的领先项。

**③ 放弃跨 model 汇总 TTFT。** 同底层模型走不同网关路由，`ttfb`/`ttft` gap 差 17 倍
（`deepseek-v4-pro` 86.77% vs `origin-deepseek-v4-pro` 5.02%），汇总出的分位是假数。
所以 histogram 按 attributes 分组成多个 data point 交后端切分，不在本地合并。

**④ 放弃给 `policy_limits` / `denial_tracking` 埋 duration。** 前者是同步布尔查表（纳秒级）；
后者的熔断落地为 `needsConfirmation` 后**当场返回**，「等用户确认」的墙钟不在它的
作用域内（那个数要埋在 HITL 应答回路上，当前 trace 层无权限决策埋点，是已知缺口）。
硬凑会得到一列恒等于 0 的假数据 —— 比没有更糟，因为它让人以为这个维度已被观测。
**这一条是复核时改的**：初版 `recordDefenseDuration` 导出了、测试覆盖了、
生产零调用点，且注释宣称它含 HITL 墙钟 —— 正是本仓「防线建好零触发」那个病灶。
现在只埋在唯一有真实可测耗时的那条路径（compact 熔断降级），注释改成如实说明另两层为何不埋。

**⑤ 放弃照着 `PolicyFeature` 枚举挨个补 gate。** 10 个 feature 只有 4 个由
`policy-limits` 真正把关，剩下 6 个各有理由（`hooks` 已由 `hook/enterprise-policy.ts` 管、
`bypass_permissions`/`auto_mode` 已由 `permission/mode-policy.ts` 管、
`sandbox_bypass` 语义是反的、`file_upload` 无对应功能、`network_access` 无单一咽喉）。
挨个补只会制造重复门禁或恒零指标，理由已写进文件头。

**⑥ 放弃顺手把 `ttft-cache-buckets.ts` 改成按 `(key, attempt)` 精确配对。**
技术上可行且能救回全部 `dropped` 样本，但**分母会静默改口径**：`attempt` 是新字段，
老轨迹一条都没有，混用两套配对规则时 `dropped` 会突然下降 ——
那个下降既可能是"救回了样本"也可能是"配错了"，从曲线上分不出来。
要改得先拿同时含新老会话的真实轨迹做双跑对账，是独立一件事。已把理由写进那个文件。

**⑦ 放弃把 raw 开关写成性能优化。** 体积实测 48 个会话共 16MB、单会话最大 1.2MB，
省磁盘收益≈0。它是**隐私开关**：此前企业要求"不落 prompt 原文"只能整体关 trace，
那会连带失去 `/trace` 排查能力。也放弃了去重与灰度（方案已明确不做）。

**⑧ 放弃夸大 PR7 的收益。** `bun scripts/defense-trigger-rate.ts` 实测 50 会话、
审计核查类 4 个、触发率 **0.0%**，加了 metric 之后**大概率仍是全零**。
收益是「零触发这件事能被自动确认、成为可持续观测的时间序列」，**不是「发现新问题」**。

## 拿什么证明它生效了

**① 接线断言走真实入口，且做了变异自证。** 这是本次最该说的一条。
`defense-metrics.test.ts` 原本只直接调 `recordDefenseDuration` 断言形态 ——
那种测试在「函数导出了、测试覆盖了、生产零调用点」时**照样全绿**（本仓已有教训）。
新加的 `★ 走真实 autoCompact` 用真失败的 provider 把全局熔断器打开，
再断言 trigger/tokens/duration 三件套都有增量。变异自证：把
`recordDefenseDuration(...)` 那一行注掉后重跑 —— `10 pass / 1 fail`，
报 `Expected: > 0  Received: 0`；恢复后 `11 pass / 0 fail`。**它是个真门禁，不是恒绿的。**

**②「接线」这个词在本 PR 里被兑现了两次，第二次也做了变异自证。**
`policy-limits-wiring.test.ts` 9 例，每条都配反向对照（策略允许时行为必须与接线前一致，
否则是把功能改坏了而不是加了开关）。变异自证：删掉 loader 里的
`type !== "commands"` 例外后，`★ commands 面不受 extensions 开关影响` 立刻报红。

同一批里有**一条明确不是门禁**，写下来免得下次误读：`reason` 字段那条。
把 `PolicySettings.policyLimits` 的类型改回没有 `reason` 之后重跑 —— **9 pass / 0 fail**，
因为 bun 不跑类型检查，且 `PolicyManager.load()` 走 `JSON.parse` + 展开不做 schema 剥离，
所以运行时的 reason 本来就流通。那个改动是**类型对齐，不是修 bug**，
源码注释与测试注释都已按这个事实改写（初版两处都写成了"值到不了"，是错的）。

**③ PR8 的边界被单独锁住。** `raw-payload-switch.test.ts` 9 个用例断言
关掉后完整 pair 消失、而 `request_sent` 计数行**仍在**（续接 index 依赖它）。
只断言"能关掉"会漏掉这个反向要求。

**④ 分桶落桶口径被逐条锁住。** `otlp-exporter.test.ts` 新增 5 例：
count/sum/bucketCounts/explicitBounds 正确、边界值走左开右闭 `(lo, hi]`
（正好等于边界落进该桶而非下一个）、不同 attributes 不合并、不同 bounds 不合并、
空 bounds 降级 gauge。

**⑤ 门禁全绿（实际命令与输出）。**

- `bun run affected-tests:run` → **4095 pass / 0 fail**，296 文件，33.43s
  （选测判定为 8 个目标：cli/config/extension/permission/query/telemetry/trace/website）
- `make build` → 成功，且**显式 grep 过 `will always be undefined`**：零命中
  （worktree 新增导出必查这条 —— 只看 exit 0 会交出一个新函数在产物里是 `undefined` 的版本）
- `bun run lint` exit 0 · `bun run format:check` → All matched files use the correct format
- `bun run lint:boundary` → 越界依赖 0 处、测试跨包相对路径 0 处
- `bun run docs:gen-reference` → `website/ref/env.md` 已更新
  （新增 `SID_CODE_TRACE_NO_RAW`；改了 `config/` 与 `help.ts` 必跑，pre-commit 有 `--check`）

**⑥ 尚未证明的部分，说清楚免得被当成已验证。** 三件事没有真实会话数据支撑：
（a）防线 metric 在真实会话里的曲线 —— 按上面第⑧条，预期仍是全零，
本 PR 只证明"真触发时有增量"；（b）TTFT/turns histogram 经 OTLP 到后端聚合后的
分位是否与 `digest.ts` 的报告层对得上 —— 需要一个真实 collector 端点做双跑对账；
（c）`attempt` 是否真的把 `20260806-182533-a927c544` 那 7 组序列切干净 ——
需要用新版本跑出一批带 `attempt` 的新轨迹才能验，老轨迹没有这个字段。
