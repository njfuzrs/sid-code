# 插件市场客户端（P5）：url 源、/plugin market|install|update、安全解包、锁定后只认市场来源

## 决定了什么

- `MarketplaceSource{source:"url"}` 第一次有实现（`packages/cli/src/plugin/market.ts`）。市场地址只从 `backend.url` 推出，新增前缀型通道 `marketplace`（`endpoints.ts`，契约快照同步）。index 拉取是 fail-static：网络错 / 5xx / 坏 JSON 时退回本地缓存。401 / 403 不退回，否则吊销不生效。制品下载是 fail-closed：sha256 只和 index 里登记的值比，不信响应头；边读边卡 20 MiB 上限；`redirect: "error"`；同源才带凭据。
- `/plugin market [关键词]`、`/plugin install <name>@company`、`/plugin update [name]`（`market-operations.ts`）。流程是：解包到 `.staging-*` → 核对 manifest 的 name / version 与 index 一致、组件路径是包内相对路径 → rename 换到正式位置 → 写 installed.json 的 `market` 段（index 地址、sha256、目录指纹）→ 发 `plugin_installed`。更新时旧目录先挪开，换失败就挪回来，新包校验失败时保留旧版本。
- 自写 ustar 解析（`archive.ts`），不调用系统 tar。只接受普通文件和目录，pax 与 GNU 长名只用来取名字。拒绝链接、设备文件、FIFO、`..`、绝对路径、盘符、反斜杠、重复条目、文件和目录同名。gunzip 时设 `maxOutputLength` 防炸弹。`writeEntries` 写盘前再核一遍落点，用 `wx` 标志。
- 锁定只认市场来源（`plugin-only-policy.ts` 的 `evaluatePluginOrigin`）。锁定的定义是 `strictPluginOnlyCustomization` 锁了任意一个面，或下发了 `strictKnownMarketplaces`。锁定后本地目录安装与 `--plugin-dir` 一律拒绝。市场插件有白名单时必须在白名单内；没有白名单时必须是本机 `backend.url` 推出的那个市场。空数组表示除内置外全部禁用。加载时会复核市场插件的目录指纹（`tree-hash.ts`）。
- 新策略字段 `strictKnownMarketplaces: [{source:"url", url}]`，与 agent-backend PR #49 同形。`applyLoadedPolicy` 每次都会写这个字段，策略为 null 时也写，防止上次下发的白名单残留在进程里。
- 接线：插件加载时调用 `setMarketPlugins`，`tool_invoked` 归因从这里取数（PR #168 的 core 侧）。安装和更新流程会调用 `logPluginInstalled`。PR #168 里 sentinel 给 `logPluginInstalled` 加的临时豁免已删除。

## 放弃了什么（以及为什么不选）

- **调用系统 `tar -xzf` 解包**：解包本身就是授予信任的一步。系统 tar 默认会照单全收符号链接，并允许后续条目写穿链接。「先解到磁盘再检查」等于事故已经发生。
- **只看 installed.json 的 `market` 段判定来源**：这是本机文件，手改一行 JSON 就能把本地目录冒充成市场插件。所以加了目录指纹复核。它能拦住两种情况：装好后被改了内容；本地目录挂上一个伪造的 market 段。拦不住照着算法刻意伪造的人，这一点已写进 `types.ts` 注释和文档，没有对外夸大。
- **安装前弹信任确认**：上架审核是管理员的职责（方案 §5.5）。客户端重复确认只会让用户养成闭眼点「是」的习惯。改为展示组件清单，hooks 一项单独醒目标出。
- **锁定且没有白名单时放行任意市场**：等于锁不住，换一个 index URL 就能绕开。所以默认只信 `backend.url`，项目级 settings 改不了它。
- **按插件统计时放开 stripProtected**：会把用户自己配的 MCP 服务名一起放出去。结论是改发专门的 `tool_invoked` 事件（PR #168）。

## 拿什么证明它生效了

- `packages/cli/tests/plugin/archive.test.ts` 21 条：12 类恶意条目各一条；链接加写穿组合，断言目标目录和外部目录都是空的；gzip 炸弹；系统 tar 打出的真包能解。
- `packages/cli/tests/plugin/market.test.ts` 20 条：真实 127.0.0.1 假后端加真实落盘（SID_CONFIG_DIR 隔离）。覆盖 market / install / update 全链路、sha256 篡改无残留、包名不符、`..` 条目、绝对路径 hooks、401 不退缓存、5xx 退缓存、锁定判定表各格、篡改 hooks.json 后拒绝加载、伪造 market 段拒绝、换 backend.url 后不再信任，以及 `plugin_installed` 与归因表接线。
- `packages/core/tests/config/known-marketplaces.test.ts`：解析、注入、null 拨回、URL 规范化、判定表。
- 变异自证：
  - 去掉 sha256 比较 → 「sha256 不一致」「新版本校验失败保留旧版本」2 条变红。
  - 去掉目录指纹复核 → 「篡改 hooks.json」「伪造 market 段」2 条变红。
  - 让解包对非文件 / 目录类型也放行 → 「符号链接」「硬链接」「字符设备」「FIFO」4 条变红。
  - 只去掉链接分支时 0 条变红，因为兜底 else 也会拒绝。说明是两道独立的判据。
