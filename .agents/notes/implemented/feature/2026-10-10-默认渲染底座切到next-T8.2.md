# 默认渲染底座切到 next，legacy 保留为 `SID_TUI_RENDERER=legacy` 回退（B9 / T8.2）

## 决定了什么

- `packages/cli/src/ui/render-port/select.ts`：`DEFAULT_RENDERER` 从 `"legacy"` 改为 `"next"`。
  未设置、空串、拼错的值都落到 next；`SID_TUI_RENDERER=legacy` 仍能回到旧底座，留到 T9 删除旧底座时再去掉。
- `next-switch.test.ts` 的默认值断言随之改成 next；`ui/CLAUDE.md` L5.3 第 4 条、`render-port/README.md` 同步口径。
- `ShortcutsHelp.test.tsx` 改为传 `{ columns: 200 }` 渲染。80 列下每项占 33% 宽，legacy 每行排 2 项、next 排 3 项，
  描述折行的位置不同，`toContain("切换 Markdown 渲染")` 实际在测布局，不是在测「不丢项」。
- 合并 origin/main 时带进来的 `footer-release-channel.test.tsx` 直连了旧底座的 testing shim，改走端口（`lint:boundary` 拦下的）。

**T8.1d 人工终端矩阵没走完就切了默认值**，这是维护者的决定：本人已在日常终端里用 next 跑过，能正常用，
后面边用边记问题、单独修。回退成本是一个环境变量，不用降版本。

## 放弃了什么（以及为什么不选）

- **等 T8.1d 五个终端 × 主屏 / alt 全部走完再切**：维护者选择不等。矩阵里剩下的项（tmux、Ghostty、Remote-SSH 链接单击等）
  改为切默认后在真实使用中验证，出现差异再补场景。
- **ShortcutsHelp 断言改成按 next 的折行写**：那会把测试绑定到某一套底座的列数算法上，T9 之前两套都要能跑这条测试。
  用宽终端让描述不折行，测的仍是原本的意图。
- **两套底座 2 列 / 3 列的差异当缺陷修**：这次没查是谁对。T8.1d 矩阵本来就要求「两边不一样就记一条」，记在下面留给后续。

## 拿什么证明它生效了

- 全量 `bun test`（合并 origin/main 之后、切默认值之后）：15634 pass / 1 fail，唯一的失败就是上面的 ShortcutsHelp；
  修后该文件 next 与 `SID_TUI_RENDERER=legacy` 下都 2/2 通过。
- `next-switch.test.ts` 子进程用例：未设置 → `renderer=next`，`bogus` → next 并告警，`legacy` → legacy。
- `make build` exit 0，输出里没有 `will always be undefined`；`lint` / `lint:boundary` / `format:check` / `docs:gen-reference --check` 通过。
- **待观察**：80 列下 ShortcutsHelp legacy 排 2 列、next 排 3 列（`33%` 宽 + `flexWrap` 的取整差异），属于 T8.1d 该记的那类差异，尚未判定哪边对。
