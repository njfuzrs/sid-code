# 删除旧渲染底座 `tui-renderer`，端口只接 next，`SID_TUI_RENDERER` 开关整个删除（B9 / T9.1）

## 决定了什么

从这个 PR 起仓库里只有一套渲染底座 `packages/tui`（以 MIT ink@7.1.1 为起点），一种构建，一种二进制。

- **先冻结、后删除**：趁 legacy 还在，把以它为现场基线的结果冻结成入库 fixture：
  - A 类（legacy 现场基线 ↔ next）：`term-bench/baseline/{E1..E10,C1..C3}.json`、`fixtures/rss-legacy-baseline.json`。
    `rss.test.ts` 判据不变（比值 ≤ 1.2），#211 的 Linux `skipIf` 保持原样。
  - B 类（同一契约在两套底座上各跑一遍）：legacy 那一侧换成 `fixtures/legacy-frozen/*.json`，
    由 `fixtures/legacy-frozen.ts` 读取。冻结跑了两次，两次输出一致。
  - C 类（从 legacy 生成数据的脚本）：`scripts/tui-{frame,screen,input,selection,text}-vectors.ts`、
    `tui-similarity.ts`、`tui-surface.ts` 连同测试和 `package.json` 条目一起删除。已入库的 fixture 保留，从此是冻结基线。
- **端口**：删掉 `render-port/select.ts`（唯一读开关的地方）、`legacy/` 7 个文件、`next/not-implemented.ts`；
  7 个切换模块改成静态导出 next，类型锚点也从 legacy 换到 next。`next/` 本 PR 不改名。
- **删包与依赖**：`git rm packages/tui-renderer`（4 个入库文件），删除本地 `.vendor-src/tui-renderer-src/`；
  根 `package.json` 删掉 `@sid-code/tui-renderer` 和 18 个只有旧底座在用的依赖（含两个 `@types/*`，以及随相似度门禁退役的 `jscpd`）。
  `packages/tui` 自己声明的依赖不受影响。
- **旧底座自己的 2 个测试**：`terminal-response-fragment` 由 `stdin-response-fragment.test.tsx` 覆盖；
  `yoga-layout-cache-positions` 移植成 `packages/tui/tests/yoga-layout-cache-positions.test.ts`，
  测的是行为，不是旧实现的内部结构。
- **vendor**：`fetch-vendor-src.ts` 解包时只取 claude-api reference。服务器 tarball 不动（里面同时装着它）。
- **门禁与配置**：包 rank 表、pre-commit 提示、边界测试、测试根清单、`.gitignore` / `tsconfig` / `.oxlintrc` /
  `.oxfmtrc` / `.editorconfig`、`docs-gen-reference` 的扫描根全部跟改；
  `ui/CLAUDE.md` L5.3、`render-port/{README,SPEC,SURFACE}.md`、`CONTRIBUTING` / `README` 的 vendor 段落改成完成态。
  `SURFACE.md` 的生成脚本没了，文件头改成「T9.1 时的冻结快照」。
- **防回退**：新增 `tests/build/no-legacy-renderer.test.ts`。仓库内除历史记录外，不许出现 `@sid-code/tui-renderer` 导入或依赖、
  `packages/tui-renderer` 目录，也不许读 `SID_TUI_RENDERER`。

## 放弃了什么（以及为什么不选）

- **保留本地 legacy 构建**（`make build-legacy` 加编译期 define 剪枝）：要维护两套打包方式、两种二进制、一组 define 断言，
  而这些复杂度只为「随时能对照旧行为」服务。这个需求已经由 A / B 类冻结基线加入库 fixture 覆盖了。
- **默认打包两套、保留运行时开关**：发布产物会继续分发泄露衍生代码。二进制里旧底座的特征串实测有 110 处，
  删掉之后是 0 处。
- **分两步删**（先移出构建，观察期后再删分支）：观察期没有明确的结束判据，第二套实现容易无限期挂着。
- **`next/` 顺手改名**：会让 diff 膨胀到难以 review，留到以后单独处理。
- **把 claude-api reference 单独重打包**：属于 vendor 治理，不挂在 B9 下。
