# 无头放行扩到「形态 + 子命令」两个维度，并放行 A2 档 4 个只读子命令

对应《20261106-无头模式斜杠命令放行-现状缺陷与分档方案》§六 **T4b**（缺陷 D13）。

## 决定了什么

`CommandBase.headless` 从 `boolean` 扩成 `boolean | HeadlessAllowlist`：

```ts
export type HeadlessModality = "p" | "stream-json" | "bridge";
export interface HeadlessAllowlist {
  modes?: HeadlessModality[];
  subcommands?: string[];
}
```

判定实现仍在唯一一处 `command/headless-dispatch.ts` 的 `headlessRefusal`，但它现在拿到
**形态**（`HeadlessGateContext.mode`）与**参数串**（`HeadlessGateContext.args`）两个维度：

- `true`：三形态、全部子命令放行（`/init` 与 A 档 22 个，**一行声明都没改**）；
- `{ modes }`：只放这些形态（`modes` 缺省 = 不限制形态）；
- `{ subcommands }`：只放参数首词命中白名单的调用；**无参调用始终放行**（查看状态/用法，
  不构成写操作；无参返回 `dialog` 的命令由分发层明确报错非 0）；
- 两个维度同时给出时必须都满足，任一不满足即拒绝（fail-closed）。

配套改动：

- `resolveHeadlessSlash` 的 opts 增加**必填** `mode` 参数；新增纯函数
  `resolveHeadlessModality({ inputFormat, outputFormat, bridge })` 做形态推断
  （Bridge 优先于 stream-json 格式字段，`-p` 文本/JSON 是兜底）。
- `app.ts` 的 `resolveHeadlessSlash` 方法调用点传
  `mode: resolveHeadlessModality({ ..., bridge: isBridgeSession() })`。三形态共用
  `submitHeadlessInput`，形态信号此前已存在，不需要新铺管线。
- A2 档 4 个命令按只读子命令放行：`cron` `{ subcommands: ["list"] }`、
  `lsp` `{ subcommands: ["status", "ls"] }`、`worktree` `{ subcommands: ["list"] }`、
  `hooks` `{ subcommands: ["list"] }`。`export` **不放**：它整条都是写
  （文件 / 剪贴板 OSC52），方案 §五 A2 表的「可放行」列写的就是「无」。
- 门禁 `headless-allowed-commands.test.ts` 拆成两组清单断言（`headless === true` 的
  23 个 vs 结构体声明的 4 个），新增 A2 档「放行 / 写子命令仍拒 / 行为不触碰未注入字段」
  三组用例，以及「结构体声明必须真的收窄（空对象等价 true）」。

`modes` 维度本次没有生产消费者 —— 它是 T6（`/compact`、`/loop` 按形态放行）的前置契约。
方案 §八.5 拍板「两个维度一次改完」，避免把 `CommandBase.headless` 改两遍（T3 落地后
声明点已从 1 个变 23 个）。

## 放弃了什么（以及为什么不选）

- **谓词方案（`headless?: boolean | ((ctx) => boolean)`）——否决**（方案 §八.5）。
  命令是数据不是逻辑：结构体可静态枚举、可参数化回归测试、可进参考页；谓词把判定藏进
  闭包，静态不可见，后续会被塞任意逻辑，口径分散。
- **形态维度留给 T6 再加——否决**。契约字段改两遍意味着 23 个声明点要再扫一次，
  而两维度本就同属「放行粒度」一件事。T6 落地时只需在命令上写 `modes`，不再动类型。
- **A2 档整条放行（`headless: true`）——否决**。放行粒度是顶层命令，整条放行会连带放开
  `/cron delete`（删 durable 任务并写盘）、`/worktree clean`（删目录）、
  `/hooks enable -p`（写 settings）、`/lsp reload`（重启全部语言服务器）。
  方案 §五.6 明确：这是「更好用」换「更安全」，不接受。
- **`export` 按 `{ subcommands: [...] }` 放行——否决**。它没有只读子命令：任何一次调用
  不是写文件就是写剪贴板（OSC52 还会污染 stdout 结果通道）。
- **无参也纳入子命令白名单（用 `""` 表示无参）——否决**。无参是查看状态/用法，不构成写
  操作；要求每个命令写 `""` 只是仪式感，漏写就变成「命令明明该能用却被拒」的意外。
  判定上无参始终放行，安全性由现有 `dialog` → 明确报错（非 0）兜住。
- **`mode` 参数给默认值——否决**。默认哪个形态都会让调用方忘传时静默走错分支，
  而「声明的放行粒度与实现不符」正是本方案要防的那类假成功。

## 拿什么证明它生效了

- **单测**：`bun test ./packages/cli/tests/command/headless-dispatch.test.ts` → **37 pass**
  （新增结构体 modes 4 条、subcommands 5 条、`resolveHeadlessModality` 4 条）；
  `headless-allowed-commands.test.ts` → **72 pass**（清单拆分、A2 放行/拒绝/行为、
  `/hooks` 无参 dialog 翻非 0）；`local-result-error-branch.test.ts` → **9 pass**。
- **变异自证（三轮，都确认报出了正确的命令/用例）**：
  ① 给 `/exit` 加 `headless: true` → 「headless:true 的清单 = A 档 22 个 + /init」变红；
  ② 给 `cron` 的 `subcommands` 加 `delete` → 「/cron delete abc 仍被拒绝」变红；
  ③ 把 `resolveHeadlessModality` 的 Bridge 判断挪到 stream-json 之后 →
  「Bridge 优先于 stream-json 格式字段」变红。三轮恢复后全绿。
- **八道门禁**：`typecheck:gate` 0 错误、`lint` 0 warn/0 error、`format:check` 通过、
  `lint:boundary` 通过、`lint:command-system` 通过（初版把 `HeadlessGateContext` 导出，
  G1 死导出 8→9，已改为不导出；与 T3 的 `HeadlessCommandContextDeps` 同处理）、
  `lint:legacy-tool` 通过。
- **构建**：`make build` exit 0，无 `will always be undefined` warning。
- **选测**：`bun run affected-tests:run` → 2952 pass / 9 skip / **1 fail**。唯一失败是
  `M4 / 点击禁用`（子进程内 5022ms 超时），三条举证与本次改动无关：
  ① `git diff origin/main -- packages/cli/tests/render-port/ packages/cli/src/ui/` 为空，
  且该测试不 import 命令体系（只 import render-port 组件/hooks）；
  ② 清宿主 TERM 变量重跑该文件 → **9 pass / 0 fail**（该用例 10s 通过）；
  ③ 5022ms 正是 bun 默认 5s 单测超时，CLAUDE.md 记载的时序 flake 形态。
- **参考页**：`bun run docs:gen-reference` 生成 6 页 + llms.txt，`git status` 中
  `website/` **无 diff**（该字段不进参考页）。
- **端到端**（worktree 构建产物 + 隔离 `SID_CONFIG_DIR` 指向本机配置副本）：
  `-p "/cron list"` `/lsp status` `/worktree list` `/hooks list` → **exit 0**；
  `-p "/cron delete x"` `/lsp reload` `/worktree clean` `/hooks enable x` → **exit 1**，
  拒绝文案为「/cron delete 在无头模式下不可用（该命令只放行子命令：list）。」
  ——与声明的白名单一致，且不是「整条命令不可用」的笼统文案。
