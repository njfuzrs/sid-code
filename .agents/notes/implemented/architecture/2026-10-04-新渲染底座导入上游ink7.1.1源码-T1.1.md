# 新渲染底座 packages/tui 以上游 ink@7.1.1 源码原样入库（B9 / T1.1）

## 决定了什么

- 上游 `vadimdemedes/ink` tag `v7.1.1` 的 `src/`（62 个文件）原样复制到 `packages/tui/src/`，`license` 复制为 `packages/tui/LICENSE`。这个提交里没有任何修改。
- tag 有两个 SHA，都记下来：tag 对象 `46db5c74…`（整体设计 D-1 写的就是它），指向的 commit `70af033d…`。用 `git clone --depth 1 --branch v7.1.1` 拿到的 HEAD 是后者。两个都写进 `UPSTREAM-DIFF.md`，以后不会有人以为 SHA 对不上。
- 新增 `packages/tui/UPSTREAM-DIFF.md`：记录上游基线和复核命令，差异表先留空。以后相对上游的每个改动都在表里记一行。
- `.oxfmtrc.json` 排除 `packages/tui/src/**`；`.editorconfig` 给这个目录单独一段，取值照抄上游自己的 `.editorconfig`（tab 缩进），而不是关掉风格规则。否则编辑器一保存就会把 tab 换成空格。
- 这一步不写 `package.json`、不接入 workspace，也不进 `pkg-boundary-scan` 的 `PACKAGES`，这些归 T1.2。

## 放弃了什么（以及为什么不选）

- **npm 依赖 `ink@7.1.1`**：内核要改（cell 级 diff、选区、scrollback 策略），上游没有这些扩展点（D-1）。
- **导入 npm build 产物（JS）**：产物不是源码，以后同步上游修复时没法逐文件 diff。
- **导入后顺手跑一次 oxfmt**：62 个文件会被一次性重排，「导入提交与上游逐字节一致 → 之后每个提交就是一处差异」这条证据链当场断掉。
- **oxlint 也排除**：不需要。实测上游源码 oxlint rc=0，留在扫描里，能让后续自研代码的真错误被拦下。

## 拿什么证明它生效了

- `diff -r /tmp/ink-v711/src packages/tui/src` 无输出，`cmp license LICENSE` 一致（导入时实跑）。
- `git ls-remote … 'refs/tags/v7.1.1*'` 输出 `46db5c74… refs/tags/v7.1.1` 与 `70af033d… refs/tags/v7.1.1^{}`。
- 加排除前 `oxfmt --check packages/tui` 报 62 个文件有排版问题，加排除后全仓 `bun run format:check` 通过。
- `bun run lint` rc=0，`bun run lint:boundary` 0 处违规。
