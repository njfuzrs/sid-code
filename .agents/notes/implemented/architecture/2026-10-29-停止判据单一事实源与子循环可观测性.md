# 停止判据收敛为 classifyStopReason，terminal 出口与子循环补齐可观测性

## 决定了什么

**逻辑层**

- 新建 `query/stop-reason-policy.ts` 的 `classifyStopReason(stopReason, hasToolUse, hasAnyContent) → StopAction`，主循环 `loop.ts` 和子循环 `agentic-loop.ts` 的停止分支都从它派生，不再各自比较 stopReason 字面量。白名单 fail-closed：未知值只会落 `unknown` 或 `terminal`。
- `stop_reason=tool_use` 但没有任何 tool_use 块时，判 `unknown`，如实收尾。以前会 `executeTools([])` 再 continue，白烧一次往返，`LoopTransition` 还记成一次工具轮。
- 所有 terminal 出口（refusal、pause_turn、未识别、空流、ctx_window）都调 `query/terminal-finalize.ts` 的 `settleOrphanToolUses`，就地补占位 tool_result，文案写明是哪种停止原因。以前只有 ctx_window 就地结算，其余出口靠下次发送前的 `finalizeMessagesForSend` 兜底。
- F1 把截断纳入退化判据。主循环的 stream-processor 在半截 JSON 解出非空对象时另打 `_partial`，`isTruncatedToolUse`（`_truncated` 或 `_partial`）优先于 schema 判退化。缺字段的参数不再被当完整参数执行。
- 子循环顺带对齐主循环的 P1-4：`max_tokens` 带完整 tool_use 时先执行工具。以前直接续写，已入史的 tool_use 成了孤儿，要靠发送前兜底补。

**可观测性 / 数据层**

- `LoopState.incompleteReason` 是 `done.incompleteReason` 与 `TurnComplete.incomplete_reason` 的唯一写入点。闭集新增 `empty_param_exhausted / empty_stream / refusal / pause_turn / unknown_stop_reason`，SDK 文案同步。F1 耗尽以前不带这个字段，SDK 和无头模式会把模型退化记成 success。
- `TurnComplete` 加 `stop_reason_kind: "normalized"`，`AfterModelRaw` 加 `stop_reason_kind: "raw"`，另加 4 个 `tool_use_*` 聚合整数。新增 `EmptyParamRetry` 事件，带 `compact_level` 作为「为什么没压」的决策依据。`SessionStart` 带 `trace_schema_version: 2`。
- 子循环通过进程级 sink（`agent/loop-trace-sink.ts`，在 app.ts 注册）发 `SubagentLoopTurn / StopReasonMismatch / EmptyParamRetry`，都带 `agent_id`。`SubagentStop` 带 `stop_action / last_stop_reason / f2_mismatch_count / f1_retry_count`。custom 路径以前连 success/turns 都不带，这次一并补上。
- `trace/digest.ts` 新增 `stopAttribution` 聚合。v1 会话缺字段时返回 undefined，不当成 0。

**门禁**

- `doc-claim-consistency.test.ts`：done 出口数用区间 [20, 40]；注释里不许写死出口数；empty-param.ts 不许再声称「每次重试前先压缩」；P0-2 白名单理由注释必须保留。
- `scripts/verify-doc-claims.ts`（`bun run verify:doc-claims`）：跨仓校验 docs-research 引用的 `MAX_/MIN_` 常量与源码是否一致。

## 放弃了什么（以及为什么不选）

- **子循环复用 `AfterModelRaw` / `TurnComplete` 事件名**（方案 L2-A 原文）。没采用：cost-recompute、provider-health、digest 都按 `AfterModelRaw` 累加成本与调用次数，而子代理成本已经走自己的账本路径入账，同名事件会造成重复计费。`TurnComplete` 的语义是「一条用户消息结束」，子代理没有这个边界。所以改用独立事件名 `SubagentLoopTurn`，字段口径与 AfterModelRaw 对齐。
- **透传父循环的 `traceAppendEvent` 到 sub-agent.ts**。子代理实例按调用新建，链路上拿不到 QueryDeps。改用与 `setRetryTelemetryObserver` 同一取向的进程级 sink，`AgentLoopConfig.traceAppendEvent` 保留给测试显式注入。
- **新建 `incomplete-reason.ts` 单独放枚举**。已有 `DoneIncompleteReason` 闭集，而且 SDK、headless-exit 都在消费它。另起一个同义类型就是两份口径，所以直接扩这个闭集。
- **`loop.ts` 整段改成 `switch(stopAction.kind)`**。各分支体之间夹着闸门链、F2 遥测、续写阶梯等大段逻辑，整体搬进 switch 等于重写 2000 行。这次只把每个分支的**进入条件**换成从 `stopAction` 派生，分支体原位不动。单一事实源在分类器里成立，控制流结构不变。
- **SubagentStop 带归一 `stop_reason` + `incomplete_reason`**（方案 L2-D 原文）。子循环没有 TurnStopReason 归一化，也没有 incompleteReason 闭集，硬凑会造出第三套口径。改用 `stop_action`（classifyStopReason 的 kind，或 max_turns/aborted/error）加原始 `last_stop_reason`。
- **截断判据不打 `_partial`、直接把 `_truncated` 改成「凡未收尾都是 true」**。`replaceEmptyParamToolUses` 的归因文案依赖 `_truncated` 的既有语义（input 仍是 {}），所以另打一个标记更稳。

## 拿什么证明它生效了

- `tests/query/stop-reason-policy.test.ts`：25 行规则表 + fail-closed 遍历；refusal、pause_turn、content_filter 带 2 个 tool_use 时都不执行、无孤儿，占位文案带停止原因，done 与 TurnComplete 带同一个 incompleteReason；tool_use 无块时只调一次模型；正常 end_turn 两处都**不落**字段；`_partial` 写入的 write 不执行，重试后完整参数才执行；F1 耗尽带 `empty_param_exhausted`。
- `tests/agent/agentic-loop-stop-policy.test.ts`：子循环 F2/F1/max_tokens 带工具/未识别四条路径的事件与 `AgentLoopResult` 归因；源码哨兵检查子循环不再自比字面量。
- `tests/query/compaction-trigger-coverage.test.ts`：`empty_param_retry` / `ctx_window_exceeded` 两条 trigger 各落一条 CompactionAttempt。本机 470 会话里这两条都是 0，以前没有对比基线。
- `tests/trace/stop-attribution-digest.test.ts`、`tests/scripts/verify-doc-claims.test.ts`。
- 变异自证（逐条改坏，确认变红后恢复）：分类器 tool_use 无块改回 execute_tools → 3 红；删截断判据 → 2 红；refusal 不结算孤儿 → 1 红；TurnComplete 不读 state → 5 红；子循环删 F2 计数 / sink 早退 → 各 2 红；子循环 max_tokens 分支改回字面量 → 哨兵红；注释改回「22 处」/ 恢复「每次重试前先压缩」→ 各 1 红；verify-doc-claims 比较恒等 → 2 红。

**牺牲**：截断参数从「执行」改为「重试」，多一次模型往返，用「更省」换「更准」。子循环事件量按方案估算约增 10%–15%。全量数据里 refusal、pause_turn、ctx_window 都是 0 实例，这批改动是「低频高危」的路径不变量，曲线上不会立刻看到变化。上线后用 digest 的 `stopAttribution` 和附录 A 的命令复核。
