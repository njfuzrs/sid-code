# 端口实例能力面 `getRenderInstance` + 测试出帧开关 `enableFrameThrottle`（B9 / T0.5 遗留）

## 决定了什么

- `render-port/runtime.ts` 不再导出旧底座的 `inkInstances` Map，改为：
  - `RenderInstance` 接口：只列真实调用点用到的 8 个方法。CLI 生产代码用 3 个（`forceRedraw`、`enter/exitAlternateScreen`），契约测试用另外 5 个（`setAltScreenActive`、`setSelectionBgColor`、`copySelectionNoClear`、`clearTextSelection`、`detachForShutdown`）。
  - `RENDER_INSTANCE_METHODS`：同一组方法名的运行时清单，`satisfies readonly (keyof RenderInstance)[]`。
  - `getRenderInstance(stdout = process.stdout)`：CLI 与测试拿实例的唯一入口。
- CLI 两处调用点（`App.tsx` Ctrl+L、`external-editor.ts`）和 term-bench 场景改用 `getRenderInstance`。测试里的 `LegacyInk` 类型删掉了。
- `render-port/testing.ts` 新增两个函数：
  - `enableFrameThrottle()`：打开真实帧调度，返回恢复函数。legacy 实现是切 `NODE_ENV`，现在收在端口里，测试不再直接碰这个实现细节。
  - `forgetRenderInstance(stdout)`：`detachForShutdown` 之后 unmount 会早退，不会把实例从注册表摘掉，测试收尾要手动摘。
- M5 测试不再直接改 `ink.selection` 内部状态，改成往 stdin 写真实 SGR 鼠标拖选。实测与原写法输出一致。
- SPEC 新增两条契约：**X7**（实例能力面）、**R13**（测试环境默认同步出帧，`enableFrameThrottle` 打开后合并、恢复后回到同步）。测试都在新文件 `render-instance.test.tsx` 里。

## 放弃了什么（以及为什么不选）

- **保留 `inkInstances` 再加一个类型断言**：Map 暴露的是旧 Ink 类的全部公开方法，`SURFACE.md` 里只能看到「用了 inkInstances」，看不到用了哪些方法。新底座只能照抄整个类，或者猜。
- **只靠 TypeScript 接口约束**：CI 里没有 `tsc`，CLI 的调用又都是可选链 `?.forceRedraw()`。新底座少实现一个方法时**不会报错，只会静默变成 no-op**。所以加了运行时清单，X7 逐个核对实例上真有这个函数，并从源码反查接口与清单一致。
- **R2 继续在测试里直接 `process.env.NODE_ENV = "production"`**：能用，但这个开关只在 legacy 的 `reconciler.ts:292` 生效。新底座换别的机制，测试会**静默测不到节流却照样全绿**（不出帧 ≠ 合并了帧）。R13 的「恢复后回到同步」断言就是防这个的。
- **把 `enableFrameThrottle` 放进 `runtime.ts`**：它只给测试用，生产代码不该看得见。

## 拿什么证明它生效了

- 端口测试 104 pass（新增 X7 三条、R13 两条）；全量 13480 pass / 0 fail；`make build` 自检通过，没有 undefined 警告。
- `tui:surface --check` 签名更新：`inkInstances` 移除，`getRenderInstance` 加入。`tests/scripts/tui-surface.test.ts` 同步改了，并新增一条反向断言「`inkInstances` 不在端口面」。
- `lint` / `lint:boundary` / `format:check` / `tui:spec`（56 条，52 条已测）/ `docs:gen-reference --check` 全绿。
- 变异自证：
  - 接口加方法但不进清单 → X7「一一对应」红
  - 接口和清单都加一个实例上不存在的方法 → X7「每个方法都是函数」红
  - `enableFrameThrottle` 不切开关 → R13 与 R2 都红
