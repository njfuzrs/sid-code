# 子代理轨迹补「委派形态」与「结束状态」两个字段（06H1 T3）

## 决定了什么

`SubagentStart` 增加 `delegation_mode`（`isolated` / `fork` / `team`），fork 时再带
`inherited_messages`（继承的父对话条数）与 `parent_messages`（父对话总条数）；
`SubagentStop` 增加 `end_status`（`completed` / `failed` / `aborted`），与 sidechain_end 的
status 同值。四个字段都经 `collector.ts` 的显式白名单写进轨迹（collector 不做通用透传，
不加就永远读不到）。

关键取舍落在三处实现细节：

- **所有路径都显式写 `delegation_mode`，含 custom 的 `isolated`**。缺字段与「真的是
  隔离子代理」必须能区分，否则统计「fork 用了几次」时分母又回到猜。
- **`end_status` 由执行路径按 `sidechainStatus` 填**（`SubAgentResult.endStatus`），
  catch 等拿不到该变量的出口由 `execute()` 按 `signal.aborted` 兜底推导——推导判据与
  `classifySubAgentFailure` 的 `parentAborted` 同源，不造第三套口径。
- **旧 `status` 字段原样保留**（completed/error/unknown）。已有分析脚本按它统计，
  改它的口径等于静默打断下游。

## 放弃了什么（以及为什么不选）

- **不把 `delegation_mode` 做成可选、只在 fork 时写**。否：那样 isolated 子代理没有
  字段，`delegation_mode != "fork"` 与「老版本没有这个字段」混在一起。
- **不用 `success` 布尔推导 `end_status`**。否：`success=false` 分不出 failed 与 aborted，
  而 sidechain 里本来就有准确的 `sidechainStatus`；推导出来的值会与 sidechain_end 出现
  两套互相矛盾的状态。
- **不改 spawn 协议补 `stopAttribution`**。本次排查确认了 `stop_action` /
  `last_stop_reason` 在 420 条 SubagentStop 里只有 149 条有值的根因：spawn 的
  `ChildResultMessage` 只带 `success/output/usage/turns/toolUseCount/model/provider`，
  不带停止归因，而 spawn 是编译产物的默认执行路径。按 06H1 的约定「查清前不改」——
  这是独立缺口，补它要动跨进程协议，不与本次的零行为变更混在一个 PR。
- **不做成 `delegation_mode=background` 的第 4 个值**。否：后台/同步是执行时机，
  与委派形态正交；混进一个字段会让「后台 fork 被丢弃」这类缺陷在统计上消失。

## 拿什么证明它生效了

新增 `packages/core/tests/agent/subagent-delegation-mode.test.ts`，7 个用例：isolated /
fork（含两个计数）/ team / custom 四形态，completed / failed / aborted 三终态，
并断言旧 `status` 字段口径不变。

变异自证（两次都把被测代码改坏确认断言变红，再恢复）：

- `delegationMode` 写死 `"isolated"` → fork 与 team 两个用例红（5 pass / 2 fail）。
- `end_status` 写死 `"completed"` → failed 与 aborted 两个用例红（5 pass / 2 fail）。

门禁实测：

- `bun run typecheck:gate` → 「✓ 无新增类型错误」（62 处 / 基线 64）。
- `bun run format` + `bun run lint` → 0 warnings 0 errors。
- `bun run affected-tests:run` → 2109 pass / 1 fail；唯一失败是
  `isolated-subagent-cwd.test.ts > 未绑定 cwd 时不出现隔离提示`，成因是**在隔离 worktree
  目录内跑测试**（`getIsolatedWorktree()` 按进程 cwd 判定），主仓目录下同文件 12 pass / 0 fail，
  该测试文件本次未改动。
- `make build` → 编译产物自检五项全过。
- `bun run docs:gen-reference` → 生成后工作区无参考页改动（hook 输入字段不进参考页）。
