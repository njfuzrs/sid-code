# 静态区段落归属全量审计：11 段的层级 / 注入条件 / 归属理由，及 D-00 之后的更新点

## 决定了什么

把 `packages/core/src/config/system-prompt.ts` 里 `buildSystemPrompt` 的静态核心区
（`coreParts.push(...)` 序列）逐段核过一遍，产出一张「段 / 行 / 注入条件 / 归属理由」表，
落在这里而不是代码里 —— 按方案原文，L-1 的产出形态是「段落清单 + 归属理由表」的 Note。

行号以**当前源码为准**（方案文档给的是另一个时间点的行号，且另一单元正在改
`prompt-sections-en.ts` / `system-prompt.ts`，抄行号必然漂）。这里的行号只做定位用，
**判据一律回符号**（`grep -n 'coreParts.push' packages/core/src/config/system-prompt.ts`）。

### 动态区（`DYNAMIC_BOUNDARY` 之后，不属于本次审计面）

`<mcp-tools>` 是**动态附件**（`DANGEROUS_dynamicAttachment("mcpToolGuide", …, PRIORITY.DATE_CONTEXT + 1)`），
无 MCP 时整段不注入。它不在静态前缀里，归属理由是另一件事（MCP 工具随 server 连断变化，
进静态区会击穿 cache），本 Note 不重复展开。

## 放弃了什么（以及为什么不选）

1. **不按「该不该常驻」逐段给结论、不在本 Note 里裁决哪几段改成条件注入。**
   L-1 是审计，不是改造。改哪几段由 D-11 第一步的度量报告决定（同 PR 的
   `scripts/prompt-section-signal-rate.ts`），拿理论上的「这段看起来用不上」当依据去删段，
   是本仓反复踩过的坑（`waiting-capability` 段注释记着 monitor 无引导时 0 次、有引导的
   `schedule_wakeup` 18 次 —— 删段会让 0 变成常态而不是修复）。
2. **不动 `buildConstraintsSection` 的拆分。** 段表里第 4 行三段同函数产出，是 D-00 的已知
   实现难点（优先级链要插在红线之前，只能插在函数之前或拆函数）。本次 L-1 只登记这个事实，
   拆函数属于 D-00 那个单元的改动面，本单元边界是「不改任何提示词行为」。
3. **不把行号写进代码注释/断言。** 另一单元正在改同一文件，行号会漂；表里的行号只是阅读辅助，
   判据回符号。这也解释了为什么这份表落在 Note 而不是 `system-prompt.ts` 里。

## D-00 引入 `<precedence-chain>` 之后，这张表要更新的位置

D-00 把 `<precedence-chain>` 插在 `:456`，落在 `<constraints>` 之前。它影响本表的三处**结构**
（不只是加一行）：

1. **第 2 行（tool-guide）之后、第 4 行（constraints 家族）之前**多了一层。
   方案原表把 identity / tool-guide 与 constraints 相邻排列，现在中间夹了优先级链；
   任何「按相邻关系推理」的判据（例如「约束段第一条指回上方的语言规则」）都要重新确认。
2. **第 4 行必须拆成「链」与「三段家族」两行。** D-00 之后它们不再是同一个注入单元：
   链是无条件、且**位置敏感**（必须早于红线）；三段由 `buildConstraintsSection` 一次产出、
   位置也敏感（在链之后）。将来若有人想把 `<constraints>` 拆成条件注入，链的位置判据会失效 ——
   这条要写进 D-00 的 Note 里互相对照。
3. **en 档的对应点**：`prompt-sections-en.ts` 里与之对应的是
   `buildConstraintsSectionEn`（`:36`）与优先级链的英文版；中英双档铁律要求两档同时有链、
   同时排在同一位置。只改一档会被 `prompt-redline-sentinel.test.ts` 之类的双档哨兵拦住，
   但「链的位置」不在哨兵覆盖范围内，只能靠这张表人工对。

另外，`<precedence-chain>` 本身也是**静态区无条件段**，新增一行后本表从 12 行变 13 行；
它的可度量信号和 identity / external-content 一样定义不出来（它约束的是「冲突时信哪一条」，
不产生专属行为），度量脚本里按「不可度量」列出，不得算零触发。
