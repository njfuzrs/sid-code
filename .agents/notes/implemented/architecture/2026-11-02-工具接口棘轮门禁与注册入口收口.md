# 工具接口迁移加棘轮门禁，注册入口直接接受新 Tool

## 决定了什么

- 新增 `scripts/legacy-tool-gate.ts`（`bun run lint:legacy-tool`，接进 CI lint job）：数 `packages/*/src` 下引用 `LegacyTool` / `LegacyToolResult` 的非测试文件，只允许减少。基线放在 `scripts/legacy-tool-gate.baseline.json`，接入时是 58，`--update-baseline` 只能往下调。口径：去掉注释，按词边界匹配。`toLegacyTool` 不算，测试不算。
- `Registry.register()` 改成同时接受 `LegacyTool` 和新版 `Tool`，靠 `typeof name === "string"` 区分，新 Tool 在入口处走 `toLegacyTool` 转换。内部存储和所有消费方都不动。
- `think.ts` 删掉 `createThinkTool()`，`cli.ts` 直接调 `register(thinkTool)`。从这里开始，用新接口写的工具文件不再需要碰旧接口和 bridge。
- `LegacyTool` 上的 `@deprecated` 改成按实际情况写的说明：它是当前唯一的运行时形态，新工具怎么写，迁移由门禁来约束。
- B2：bridge 合成的 `fileStateCache` 原来是 `null as any`，改成一个空的 `FileStateCache` 实例，并在注释里写明其余字段都是占位值。

## 放弃了什么（以及为什么不选）

- **在一个 PR 里迁完全部工具、删掉 `LegacyTool` 和 bridge**：生产代码有 122 处 `.name()`、21 处 `.execute(`，涉及 40 多个工具类，和并行在做的工作冲突面太大，也没法一次 review 完（方案 §3.3「不选」）。按工具逐个迁移，每迁一个基线就降一点。
- **按 `implements LegacyTool` 计数**：全仓一处都没有，这样数会恒为 0，门禁永远是绿的。
- **把注释里的提及也算进去**：会让只剩解释性注释的文件永远减不下来，等于逼人去删有用的注释（实测有 4 个文件只在注释里提到它）。
- **保留 `@deprecated`**：几十个文件都在正当地引用它，满屏删除线只会让人习惯性忽略。真正阻止新增的是门禁。
- **低于基线时放行，不强制收紧**：这段余量会被下一个新增的旧接口文件悄悄吃掉。所以测试断言实测值必须等于基线。

## 拿什么证明它生效了

- `bun run lint:legacy-tool` 输出 `引用 LegacyTool 的生产文件: 58  基线 58`，✓ 通过。用同一口径扫 main @ d92c990c 是 58，本 PR 删掉 think.ts 的旧接口依赖后降到 57；合入 main 时 #524 新增的 `query/run-tool-use.ts` 又加回 1，接入时刻实测值是 58。
- 变异自证 1：往 `think.ts` 追加 `export type _Mut = import("./types.ts").LegacyTool;`，门禁报「引用旧接口的生产文件比基线多 1」、退出码 1；恢复后通过。
- 变异自证 2：把 `isNewTool` 改成恒为 false，`think.test.ts` 的直接注册用例报 `TypeError: tool.name is not a function` 并变红；恢复后 4 pass。
- `bun test ./tests/scripts/legacy-tool-gate.test.ts ./packages/core/tests/tool/`：1232 pass / 0 fail。`bun run typecheck:gate`：66/66，没有新增。
