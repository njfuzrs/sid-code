# Static 语义定案 A：已完成区的项可以原地重渲，钉成契约 R11（B9 / T0.3，D-3）

## 决定了什么

新底座的 `Static`（端口 `render-port/components.ts` 导出名不变）**保持旧底座语义**：
它只是一个 memo 过的竖向 Box，items 引用不变时跳过重渲，项内容变了照常 reconcile；
不是上游 ink 那种「打印一次就进 scrollback、此后不再管」的 `<Static>`。

写进 `render-port/SPEC.md` 的 R11，由 `packages/cli/tests/render-port/static-reconcile.test.tsx` 钉住三件事：
已渲染项从「执行中」变「完成」会反映到输出；新增项追加在后且已有项不重复；移除项会从输出消失。
同文件的 R12 钉住非 TTY 每帧整帧输出（测试 shim 取 `lastFrame` 依赖它）。

## 放弃了什么（以及为什么不选）

- **B：改用上游 print-once `<Static>`**。CLI 的 `MainScreenLayout` 把执行中的 tool_group 直接放进 staticItems，
  完成时靠原地 reconcile 变成终态（`MainScreenLayout.tsx:49-50` 注释）。换成 print-once，工具行会永远停在「执行中」，
  要连带重写 CLI 的历史区拆分 —— 那正是被删掉的「静动拆分」那套，B9 的范围是换底座，不是重做 UI 结构。
- **C：两种都提供、按组件选**。没有调用方需要 print-once，多一个语义只会多一套要维护的契约和差分场景。
- **把组件改名成 `Completed` / `HistoryBox` 以免和上游混淆**。会让 T0.2 刚收口的端口面再动一次；
  名字的误导用 SPEC 的一句话和端口文件里的注释解决。T9 删旧底座时可再考虑。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/render-port/static-reconcile.test.tsx`：4 pass，在 legacy 上跑。
- 来源核对：`_vendor/Static.tsx` 文件头注释写明它是「一个普通竖向 Box 承载全部 items」，导出是 `React.memo(StaticInner)`。
- `bun run tui:spec` 变异自证：把三条 `R11:` 测试名改成 `R99/R98/R97`，脚本报「R11 找不到片段」+ 三条孤儿测试，rc=1；恢复后通过。
