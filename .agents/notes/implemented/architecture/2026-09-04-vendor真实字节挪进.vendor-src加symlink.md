# vendor 真实字节挪进 `.vendor-src/` + symlink，消除「被 checkout 删掉」的可能

## 决定了什么

把两个不入库的编译期依赖目录改成**指向仓库内 `.vendor-src/` 的相对 symlink**，
真实字节只存在缓存里一份：

```
packages/tui-renderer/src                              → ../../.vendor-src/tui-renderer-src
packages/cli/src/command/commands/claude-api/reference → ../../../../../../.vendor-src/claude-api-reference
```

治的是一次真实事故（125 个文件曾从磁盘消失）：`.gitignore` 只挡「未追踪文件不被 add」，
**不挡「已记录删除的文件不被 checkout 删掉」**，而仓库里 37+ 个分支仍把这两个路径
记为已追踪。`.vendor-src/` 在**全部 371 个 ref 里都不存在**，于是 git 的任何
checkout / merge / reset 都碰不到它。

改动落在 5 处：

| 文件 | 改了什么 |
| --- | --- |
| `scripts/fetch-vendor-src.ts` | 缓存布局 + `ensureLink()`（幂等，含老克隆就地迁移）+ 解包改走 stage + `--pack` 加 `-h` 并自证包内文件数 + `--check` 区分「字节缺失」与「链没接上」 |
| `.gitignore` | 两条规则去掉尾斜杠（否则挡不住 symlink），新增 `/.vendor-src/` |
| `tests/build/vendor-location.test.ts` | 新增 5 条断言（4 条做了变异自证） |
| `CONTRIBUTING.md` | 新增一节讲机理、实测表与三条不能破的约束 |
| `README.md` / `README.zh-CN.md` | 各加一段指向 CONTRIBUTING |

**这条防线的准确边界是「真实字节不会丢」，不是「symlink 不会被动」。**
`git checkout -f` 实测**会**把 symlink 换成空真目录 —— 但字节仍在缓存里，
`vendor:fetch` 不联网即复原。别把它说成后者。

## 放弃了什么（以及为什么不选）

**① 交接文档原方案「挪到仓库外（如 `~/.sid-code-vendor/`）」—— 实测不可行，已否决。**
这是 §9.9 留下的原话，也是我第一次尝试的方案。真跑一次 `make build` 当场失败：

```
error: Could not resolve: "react"
    at /Users/zhourusheng/.cache/sid-code/vendor-src/20260904/tui-renderer-src/Ansi.tsx:2:19
```

根因是 bun 按 **realpath** 向上找 `node_modules`，而 `~/.cache` 那条链路上一个都没有
（逐级验过：`~/.cache/sid-code/vendor-src/`、`~/.cache/sid-code/`、`~/.cache/`、`~` 全无）。
bun 也没有 `--preserve-symlinks`（`bun build --help` 零命中）。
⇒ **「挪出仓库」这个直觉在 bun workspace 下不成立**，缓存必须留在仓库树内，
realpath 才仍落在能解析到 `node_modules` 的路径上。下一个人不必再试一遍。

**② 不用 symlink、改为「每次构建从缓存复制一份进规范路径」。** 否决：
那等于让规范路径重新变成真目录，`checkout` 照样能删它，只是多一次复制 ——
防线的价值恰恰来自「git 能动的东西」与「真实字节」在物理上不是同一份。

**③ 把两个目录重新入库。** 否决：它们正是 §2.1 那个封号第一嫌疑因素（第三方代码），
刚在这一轮清掉，不能倒回去。

**④ 顺手把 `.gitignore` 换成 `git update-index --skip-worktree`。** 否决：
skip-worktree 是**每份克隆的本地索引状态**，不随仓库分发，新克隆完全不受保护 ——
解决不了「fresh clone / CI」这条主路径，还多一个只有本机知道的隐式状态。

## 拿什么证明它生效了

**① fresh clone 端到端（这是唯一真正要紧的场景）**：`git clone` → `vendor:fetch`
→ `bun install` → `make build`：

```
✓ sha256 校验通过
✓ packages/tui-renderer/src → .vendor-src/tui-renderer-src（123 个文件，经 symlink 可读）
✓ packages/cli/src/command/commands/claude-api/reference → .vendor-src/claude-api-reference（2 个文件，经 symlink 可读）
[114ms]  bundle  1697 modules   →  自检通过：关键修复已内联进二进制。
```

**② 事故复现 —— 直接对着当初那条链路打**（在一份临时克隆里，不在工作区）：

| 操作 | 规范路径 | `.vendor-src/` 字节 |
| --- | --- | --- |
| `git checkout <仍追踪该路径的分支>` | git **直接拒绝**并中止（"请在切换分支前提交或储藏"） | 54 项完好 |
| `git checkout -f` 强制 | 被替换成真目录，切回 main 后 **0 文件** | **54 项完好** |
| 之后 `vendor:fetch`（`SID_VENDOR_SRC_BASE_URL` 指向 `127.0.0.1:1`） | `✓ symlink 已重建` | 完好 |

第三行用**打不通的 base url** 跑，证明复原路径真的没联网 —— 而不是"看起来很快"。

**③ 老克隆迁移路径 + 幂等**：造一个字节以真目录形态躺在规范路径、无 `.vendor-src/`
的克隆，同样断网跑：`✓ 已搬入 .vendor-src/ 并建立 symlink`（125 文件）；再跑一次
变成 `✓ 本地已有，跳过下载`，不重复搬。

**④ 四条门禁断言逐条变异自证**（判据是「红的是哪一条」，不是「有东西红了」）：

| 变异 | 期望红的断言 | 实测 |
| --- | --- | --- |
| 从 `--pack` 参数表摘掉 `-h` | `-h` 那条 | ✅ 只它红（10 pass / 1 fail） |
| `.gitignore` 尾斜杠加回来 | 尾斜杠形态那条 | ✅ 只它红 |
| 解包目标 `stage` 改回 `ROOT` | 解包不穿 symlink 那条 | ✅ 只它红 |
| 在临时克隆里把 `.vendor-src/` 入库 | ref 污染那条 | ✅ 对照组 3 fail → 变异组 4 fail，增量正是它 |

第 4 条必须与对照组比：clone 拿的是 HEAD，不含本次未提交改动，所以另外 3 条在
**任何**克隆里都会红 —— 只看"红了 4 条"会把这个假信号读成成功。

**⑤ `--pack` 自证**：`✓ 包内 125 个文件（与磁盘一致）`。少了 `-h` 时包内是 **2** 个，
而 tar 退出码 0、sha256 算得出、上传照样成功 —— 这个断言把静默错误变成当场失败。

**⑥ 门禁与构建**：`bun test ./tests/build/vendor-location.test.ts` 11 pass / 0 fail；
`bun run affected-tests:run` 与 `make build` 见 PR 正文。
