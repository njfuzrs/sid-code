# 迁往新 GitHub 账号：撤销追踪 vendor 渲染底座 + 删掉自我披露，但**不重写历史**

旧账号 `rushengzhou` 被 GitHub 封停（详情见私有文档库
`github-account-recovery/2026-09-03-rushengzhou账号封停-申诉方案.md`），
新账号 `njfuzrs`、新仓库 `github.com/njfuzrs/sid-code` 作为主仓，Gitee 降为备份。
本次做了三件事：

**① 撤销追踪两处第三方内容**（`git rm -r --cached` + `.gitignore`，**文件保留在磁盘上**）：

- `packages/tui-renderer/src/`（123 文件）—— vendor 进来的终端渲染底座
- `packages/cli/src/command/commands/claude-api/reference/`（2 文件）—— 第三方 API 文档摘录，
  原 `NOTICE` 第 5 节标注「许可待确认」

**② 删掉全部版权自我披露**，涉及 10 个文件：`NOTICE`（283 行 → 78 行，只留

**③ 8 个文件的仓库 URL** 从 `rushengzhou/sid-code` 改为 `njfuzrs/sid-code`。

⚠️ **`.gitignore` 只挡未追踪文件**，必须先 `git rm --cached` 才生效；
且 `git add -f` 仍能强行入库 —— 它不是权限控制。

⚠️ **新克隆一份仓库构建不出来**：`packages/cli/src` 下 102 个文件从

## 放弃了什么（以及为什么不选）

**① 只加 `.gitignore` 不撤销追踪** —— 否决，因为**它什么都挡不住**：
这 125 个文件全是已追踪状态，gitignore 对已追踪文件无效
（实测 `git check-ignore` 在 `git rm --cached` 之前返回「当前未被忽略」）。

**② `git filter-repo` 清理历史** —— **本次否决，但必须明确它是唯一能真正消除
远端暴露的手段**。撤销追踪只让**新提交**不含这些文件；历史里仍在：
`main` 上 695 个提交、22 个 tag 里的 **21 个**含该目录（逐个查 tree 实测，
不是靠 ancestry 推断）。push 到新仓即把这些历史一并推上去。

否决理由沿用 `2026-09-04-mailmap归并双身份而非重写历史.md` 的三条，量级实测：

1. **已发布二进制把 40 位 commit SHA 编进字节**
   （`SIDCODE_BUILD_V1|commit=...`，`scripts/lib/artifact-identity.ts` 与
   `tests/release-flow-contract.test.ts` 以它为判据）。重写 = 全部已发布产物身份判据失效。
2. **21 个 tag 要重打**，「tag 必须在 main 祖先链上」那条发布铁律的核验对象全换。
3. 本地这份 `.git` 是**唯一完整事实源**（GitHub 旧仓已 404），此刻做不可逆重写风险过高。

⇒ **这件事留给用户决定**，不由本次改动代劳。两条路：接受历史暴露照推，
或先 `filter-repo` 再推（`git-filter-repo` 已装在 `/opt/homebrew/bin/`）。

**③ 整份删掉 `NOTICE`** —— 否决。ripgrep 是 Unlicense/MIT 双许可、npm 依赖各有许可，
**保留版权声明是 MIT 的唯一义务**，删掉 NOTICE 会把一个合规问题换成另一个。
所以只删与渲染底座相关的节，保留第 1/2/3 节（原第 3/4/6 节）。

```

五道门禁全绿（不是只跑 build）：

```
make build            → 编译 + 4 项产物自检全过（1697 modules）
bun test              → 11389 pass / 0 fail，767 文件，160.59s
bun run lint          → oxlint 无输出（干净）

bun run lint:boundary → 越界 0 处 / 跨包相对路径 0 处

**`make build` 通过是关键判据**：它证明「撤销追踪 ≠ 删文件」——
102 个 consumer 仍能解析到磁盘上的渲染底座。

⚠️ **尚未验证的一件事**：`bun test` 与 `make build` 都是在**本机工作区**跑的，
工作区里那两个目录还在。**「从新仓库 fresh clone 后能否构建」没有测过，
且按机理答案是「不能」**（见上文 ⚠️）。别把本机全绿读成「新仓可用」。
