# 术语表按源码事实校准（3 处事实错误 + 1 处死锚点）

## 决定了什么

`website/ref/glossary.md` 逐条回源码核过再改，共 14 处。三处是**事实错误**，其余是措辞精确化与补全：

- **Skill 数量**（原文「8 个目录型 + 8 个命令型」）：实际是 3 个目录型
  （`claude-code-migration` / `code-review` / `skill-creator`，见 `packages/core/src/skill/builtin/`）
  与 6 个命令型（`packages/core/src/skill/bundled/index.ts:25-35` 的 `REGISTRARS`）。改后与
  `website/extend/skills.md:104` 的「六个」一致——改前两页自相矛盾。
- **DeepSeek 档位**（原文「只认 `high`/`max`」）：改成认 `low`/`high`/`max`，`medium`/`xhigh`
  按 `high` 下发（`packages/core/src/llm/dialect/deepseek.ts:14-25`）。
- **权限模式**（原文「从只读一侧的 `deny-write` / `plan` 到最宽」，八档只解释了七档）：
  补上 `dontAsk`（静默拒绝，`checker.ts:1608-1635`），并把宽严排序改成「最严 `plan`、
  其次 `deny-write`」——原文把两者并列成「只读一侧」不成立：`deny-write` 只拦写，
  读与普通 bash 照常（`checker.ts:1150-1160`）。
- **死锚点**：原文标题是「轨迹（trajectory / trace）」，按 VitePress 实际 slugify
  （`@mdit-vue/shared`，实跑确认）生成的是 `#轨迹-trajectory-trace`，而快速表引用的是
  `#轨迹`——点击只落到页顶。改法选了**简化标题**（`#### 轨迹`，英文对照移进正文第一句），
  而不是改引用为那个长 slug：标题与锚点都变短，后续也不会再因标题措辞漂移。
- 措辞精确化：checkpoint 触发范围补 `notebook_edit` 与破坏性 bash；无头模式「会直接失败」
  改成「自动拒绝并返回 tool_result，进程不中断」；`--resume <id>` 改成 `[id]`（不带值开选择器）；
  prompt cache 的「60–70% 结构性上限」改成受控实测口径 + 账本下界口径。
- 补全：microcompact 的 200/500 字符与「未登记工具不压缩」、轨迹目录其余文件、
  `~/` 路径前缀、plan 模式计划文件例外、HITL 的 `a`/`Shift+A` 语义、自定义 agent 的 `model` 例外。

## 放弃了什么（以及为什么不选）

- **没把「44 个内置工具」改成引用**。它确实是会漂的数字，但 `website/ref/tools.md` 是
  `--dump-tools` 生成页、且有门禁对账（`tests/website/gen-reference.test.ts:123`），
  数字本身恒正确；这页写死它只是重复维护，不是错误。同理没动「八档」「30 个回退点」
  ——它们当前都对，改成引用反而降低可读性。
- **没改 `packages/core/src/llm/effort.ts:599` 那句过期注释**。它正是本次「DeepSeek 只认
  high/max」错误的来源，但改注释属于代码侧改动，已单独记进缺陷文档
  （`docs-research/sid-code/bugfixes/todo/20261021-术语表核验核出的代码侧缺陷.md` 的 D1），
  不塞进这个文档 PR——否则 review 的人分不清哪些改动是必要的。
- **没有把「mermaid 式」的宽表加回来**。原文的快速表已经够用，只补正确性不扩结构。
- **没动 frontmatter**（标题 / description）。动了就得重跑 `docs:gen-reference` 重生成
  `website/public/llms.txt`，而本次改的都是正文事实，不需要那条链路。
