# README 与官网「和 Claude Code 的关系」补代码来源比对数据

## 决定了什么

在 `website/start/index.md` 的「和 Claude Code 的关系」下新增「代码来源」小节，
`README.md` / `README.en.md` 的差异化能力段后各加一段摘要并链过去。内容三块：

- 结论：兼容的是接口（配置名、Hook 事件名、CLI 参数、SDK 字段），实现是自己写的。
- 数据（2026-10-16，`7556df3c`，git 追踪的 `packages/*/src` 1,156 个文件，对照 Claude Code 源码 `src/`）：
  连续 6 行一致的代码 48 / 125,529 行（0.04%，其中 32 行 `git blame` 归到 ink 导入提交 `8fd9048d`）；
  逐字一致句子 7 / 12,315；`tengu_*` 事件名、`/tmp/claude` 残留 0。
- 边界：比对查得出逐字照抄，查不出改写；改写由「CC 源码里没有可改写的实现」那几条差异来回应。

动机：WorkBuddy 被用同一套方法（长字符串比对 + 改名残留）曝出移植 CC，
不了解的读者看到「CC 的能力面这里都有 + 迁移零成本」会做同样的怀疑。

## 放弃了什么（以及为什么不选）

- **只写结论不给数字**：「没有抄」是读者最不信的一句话，必须给可复核的口径。
- **把比对脚本放进本仓并写「可复算」**：运行它需要 Claude Code 源码，本仓不应引导读者去取得它；
  脚本留在维护者私有文档库（`docs-research/.../_workspace/cc-overlap.py`），正文不写「可复算」。
- **英文版单独再写一份详细小节**：官网只有中文，README.en 给摘要 + 链到中文页并标注 (Chinese)。

## 拿什么证明它生效了

- 数字来自 `python3 -I cc-overlap.py <sid-code> <claude-code/src>` 在 `7556df3c` 上的实跑输出；
  tui 32 行逐文件跑过 `git blame -s`，`insertBeforeNode` 等命中行均为 `8fd9048d`。
- 一处假 0 已排除：`git ls-files 'packages/*/src'` 返回 0 个文件且退出 0，
  首轮句子比对因此报过「0 命中」；脚本改为 `git ls-files -- packages` + 正则过滤并断言非空后为 7。
- `bun run website:build` 通过（死链检测在此），产物 `dist/start/index.html` 含 `id="代码来源"`，README 里的锚点链接有落点。
- ⚠️ 数字会随代码演进漂移，没有门禁看着它；下次大改提示词或 SDK schema 后要重跑并更新取数日期。
