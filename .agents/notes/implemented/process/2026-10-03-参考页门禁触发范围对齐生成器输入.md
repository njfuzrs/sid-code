# 参考页门禁的触发范围对齐生成器的真实输入，叙述覆盖度改为阻断

## 决定了什么

- `scripts/git-hooks/pre-commit.sh` 的 T-3.8 段：触发条件从 6 个目录（help.ts / cli.ts / tool / command / config / hook）
  放宽为生成器真实读取的全部输入 —— `packages/*/src/`、`scripts/docs-gen-reference.ts`、`website/**/*.md`、
  `website/public/llms.txt`；`--diff-filter` 补上 `D`（删除也会改变生成结果）。
- 叙述覆盖度：补齐最后两个只出现在 ref/ 的命令（`/commands` → `use/interactive.md`，`/lsp` → `extend/lsp.md`），
  存量 18 → 0；pre-commit 从 `--coverage || true` 改为 `--coverage-strict` 阻断；测试基线 18 → 0。
- `ci.yml` 汇聚门上方那句「文档门禁不在这里」改写：全量 `bun test` 含 `tests/website/gen-reference.test.ts`，
  它跑 `--check` 与 `--coverage-strict`，CI 本来就是兜底。
- `tests/website/gen-reference.test.ts` 新增「pre-commit 接线」一组：直接从 hook 里抽 grep 正则，
  对真实路径求值（不读注释），并核对 `PKG_SRC_DIRS` 的每个包都在触发范围内。

## 放弃了什么（以及为什么不选）

- **每次提交都跑 `--check`**：最简单，但纯测试 / evals 提交也要多起 bun 进程；按输入路径触发已经无漏判，
  没必要让无关提交付成本。
- **从生成器导出一份「输入路径清单」给 hook 读**：最"同源"，但 hook 是 sh，要么起 bun 求值（每次提交都付），
  要么生成一份清单文件入库（又多一个会漂移的产物）。改用测试把 hook 正则与 `PKG_SRC_DIRS` 对账，同样锁住漂移，零运行时成本。
- **保留告警模式、只更新基线数字**：告警模式下存量从 0 回涨不会有任何东西报错，等于没有门禁。
- **只修 pre-commit、不改 CI 注释**：那句注释会让人以为绕过 pre-commit 就没兜底，属于文档骗人。

## 拿什么证明它生效了

- `bun test ./tests/website/gen-reference.test.ts`：46 → 52 pass / 0 fail。
- 四项变异各自转红：① 触发正则改回旧 6 目录 → 「每一类输入都会触发」「覆盖 PKG_SRC_DIRS」2 fail；
  ② 覆盖度改回 `--coverage || true` → 「阻断模式」1 fail；③ 去掉 `D` → 「删除也触发」1 fail；
  ④ 删掉 `extend/lsp.md` 里的 `/lsp` 叙述 → 「存量已清零」「--coverage-strict 退 0」2 fail。
- `--coverage-strict`：62 个命令（豁免 2），62 覆盖，0 仅在 ref/，退 0。`--check` 退 0。
- 范围外文件计数：`fire*Event` 调用点 + 直接 `process.env` 读取点在旧正则外的文件 78 个（兜底的字面量匹配会更多）。
- 实测 `--check` 0.58s、`--coverage-strict` 0.10s。
