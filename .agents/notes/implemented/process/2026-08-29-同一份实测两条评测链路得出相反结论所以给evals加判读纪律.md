# 同一份实测，两条评测链路得出相反结论 —— 所以给 `evals/` 加一份判读纪律

## 决定了什么

新增 **`evals/CLAUDE.md`**（412 行）+ **`tests/eval/evals-claude-md-citations.test.ts`**
（出处门禁，23 个断言）。

**作用域选 `evals/` 而不是 `evals/external-benchmarks/`**，判据是：
**同一个错误类在这个目录下已出现三次，跨了两个子目录**，放深一层就覆盖不到第三处。

| 时间 | 位置 | 状态 |
| --- | --- | --- |
| 2026-08-25 | `external-benchmarks/swe-bench/` | 113 次权限拒绝 → **已修**（换 `--dangerously-skip-permissions`） |
| 2026-08-29 | `external-benchmarks/harbor/` | 同一档、144 次拒绝，**而它引用的正是那份 113 的实测**，结论却相反 |
| 至今未修 | `providers/` `bench-runner/adapters/` | 对照 agent 默认 `skipPermissions=true`，我们这侧**连这个选项都没有** |

**文件的第一层刻意不是坑的清单，是判读纪律（§1）** —— 因为第二次那个错误的本质
不是「不知道这个坑」，而是**读同一份数据得出了相反解释**：swe-bench 说
「113 次证明这档不能用」，harbor 说「113 次证明这档能观察到防线」，
后者把一个**已被判定为污染能力账的配置重新解释成了特性**，还配了一道门禁
（`tests/eval/harbor-agent-contract.test.ts:259`）把正确做法钉死 ——
**而那道门禁的注释理由读起来完全正当**。坑可以逐条修，判读方式错了会源源不断造出新坑。

结构：§0 三次同型错误 → §1 判读纪律（8 条元规则）→ §2 跨链路对齐清单
→ §3 静默失效目录（13 条，按代价排序）→ §4 写门禁的五条硬要求 → §5 环境
→ §6 自检三问 → §7 出处索引。

## 放弃了什么（以及为什么不选）

- **⛔ 放 `evals/external-benchmarks/`。** 作用域更聚焦、文件更短，但**覆盖不到
  `providers/sid-code-live.ts` 那处不对称** —— 而那正是同一个错误的第三次复发，
  且它是「多 provider 横评」的取数源。
- **⛔ 拆成两份（`evals/` 放元规则 + `external-benchmarks/` 放细节）。**
  分层更干净，但**要维护两份、且要防两边规则漂移** ——
  本仓刚吃过「同一事实两处解释相反」的教训，两份文档正是它的温床。
- **⛔ 精简成命令式清单、不带 `file:line` 出处。** 短、加载便宜，但没有出处的规则
  会在下次重构时被当成过时约定删掉。而这次的教训恰恰是**「门禁理由正当但判据是错的」**——
  没有出处就无法核验一条规则是否还成立。
- **⛔ 只写文档不加门禁。** 那样「出处失效的规则要么更新要么删掉」这句话就是空话：
  行号会随任何重构静默漂移，而**漂移不会让任何测试变红**（规则还在、读起来照样正当，
  只是追不到源头了）。
- **⛔ 门禁做逐字比对。** 那会让任何一次无害措辞调整都变红 → 很快被加豁免、被跳过
  → 变成死功能（本仓「伪配置/死功能」同型）。改成**锚点关键词 + ±12 行容差**。

## 拿什么证明它生效了

**① 门禁在写的过程中就抓出我自己三处引用错误**（这是它最直接的价值证明）：

| 错误 | 抓法 |
| --- | --- |
| `sid_code_agent.py:575` 指向了成本兜底代码，真实位置是 `:486` | 锚点关键词不在 ±12 行窗口内 |
| `harbor-agent-contract.test.ts:259` 引用了但没登记 | 「文中每个仓内出处都必须登记」那条 |
| `sid_code_agent.py:706` 同上 | 同上 |

**② 变异自证 4 处**（照 `evals/CLAUDE.md` §4.3 自己定的四类，不然这道门禁自己就违规），
每处都确认**「红的是哪一条」**而非「有东西红了」：

| 变异 | 结果 |
| --- | --- |
| 出处行号漂移 40 行（超出 ±12 容差） | 精确点名 `⛔ harbor 权限档 → sid_code_agent.py:220` |
| **在 CLAUDE.md 里加一条没登记的新出处** | 点名 `["evals/bench-runner/runner.ts:145"]` ← **证明它拦下一条新出处，不只已知的** |
| 出处提取正则改成只认 `.rs`（抠出空集） | `cited.size > 10` 翻红（防门禁**绿着失效**） |
| **模拟「harbor 权限档缺陷被修好了」** | 2 条红 ← **缺陷修好时提醒来人回来改文档**，避免文档把已修缺陷写成现存 |

第四条尤其重要：一份把已修缺陷写成「现存」的文档，会让下一个人**重新"修"一遍**。

变异全部改完即还原，`shasum -a 256 -c` 逐个核过复原（含 `sid_code_agent.py`）。

**③ 门禁**：`affected-tests:run` **1236 pass / 0 fail**（53 文件）、`make build` 通过且
产物自检 4 项全绿、`lint` / `format:check` / `lint:boundary`（越界 0 处）全绿。

⚠️ **一处环境坑值得记**：worktree 里首次跑 `affected-tests:run` 有 1 条 fail
（`scripts-deps-manifest.test.ts` 的「根 node_modules 能解析到外部包」）——
**worktree 没有 `node_modules`**，那条断言查的正是 `REPO_ROOT/node_modules`。
`bun install` 后 0 fail。**它不是本次改动引入的**，但形态值得记：
worktree 隔离会让「查仓库根目录状态」的门禁误报。
