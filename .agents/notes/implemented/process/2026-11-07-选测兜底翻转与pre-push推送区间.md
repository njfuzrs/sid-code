# 选测兜底翻转为「全量」，pre-push 的站点构建触发改为读 stdin 推送区间（X3-01 + X3-02）

## 决定了什么

修《20260927-工程化与交付-顺着sc-x3核出的缺陷》里的 X3-01 与 X3-02，两者同属
「门禁静默失效、失效形态是绿的」，合成一个 PR。

**X3-01（`scripts/affected-tests.ts`）—— 兜底方向翻转。**
`mapPathToTests` 末尾的 `return []` 改为 `return "full"`，并新增两份显式清单：

- `ROOT_FILE_TESTS`：被测试**真实读取**的仓库根文件 → 精确测试目标
  （`.bun-version` → 全量；`CLAUDE.md` / `CONTRIBUTING.md` / `CHANGELOG.md` / `.gitignore` /
  `.agents/` / `.pr-batch/` / `northstar/` / `README.md` → 各自命中集）。
- `NO_TEST_PATHS`：机械确认**零读取者**的根路径（`LICENSE`、`NOTICE`、`README.en.md`、
  `SECURITY.md`、`CODE_OF_CONDUCT.md`、`.mailmap`、`.git-blame-ignore-revs`、
  `.editorconfig`、`.gitattributes`、`.claude/skills/`），只有它们返回 `[]`。

漏登记的后果因此从「零测试且全绿」变成「多跑一次全量」——代价方向反了过来。

**X3-02（`scripts/git-hooks/pre-push.sh` + 新增 `scripts/git-hooks/push-scope.sh`）——
推送区间从 stdin 读。**
原先站点构建的触发条件是 `git diff --quiet HEAD~1 HEAD -- 'website/'`，只看**最后一个提交**：
分支上第 2 个提交改 `website/` 引入死链、后面几个只改 `packages/` 时构建不跑，
终端上也没有一行「跳过」。现在抽出 `push-scope.sh` 读 git 喂给 pre-push 的
`<local_ref> <local_sha> <remote_ref> <remote_sha>`，按「remote_sha..local_sha」求变更集合；
新分支与基线求 merge-base；判不出范围（远端 sha 本地不存在 / 没有基线）输出 `__UNKNOWN__`
并按「跑」处理。跳过时**打印一行**——静默跳过看起来和「检查通过」一样。
附带的北极星陈旧检测改为 `git grep`（只搜已追踪文件），不再扫别人未提交的在途 md。

## 放弃了什么（以及为什么不选）

1. **没把「被测试读取的文档」一律塞进全量。** 最省事但最贵：改一句 `CLAUDE.md` 跑 127s，
   门禁贵到一定程度人就会绕过它（这正是本仓反复踩到的失效路径）。改用精确命中集，
   由 `tests/scripts/affected-tests.test.ts` 的「映射目标必须真实存在」+「根文件不得判空集」守着。
2. **没把白名单判据做成「grep 命中数阈值」或人工豁免。** 判据必须机械可执行，
   否则白名单会慢慢变成垃圾桶。采用「`grep -rlF '"<路径>"' tests packages/<pkg>/tests`
   零命中」，只排除判据自身的测试文件（它必然提到白名单项）。
3. **没让白名单覆盖已映射的路径。** 白名单在 `mapPathToTests` 末尾生效，`ROOT_FILE_TESTS`
   先命中——两者互斥，且加了一条「白名单项必须真的返回空集」的自洽断言，
   防止「写了白名单却不生效」这类最难发现的空转。
4. **没把推送区间判定内联在 `pre-push.sh`。** `pre-push.sh` 是被 `cp` 到 `.git/hooks/`
   的快照（X3-11 未修前如此），内联逻辑没法在 tmpdir 仓库里单独跑测试。抽成独立脚本后，
   「多提交 push」「新分支」「远端被更新过」都能用真实 git 历史求值。
5. **没用 `git ls-files -z '*.md' | xargs -0 grep -l`。** BSD `xargs` 无输入时会执行
   一次不带参数的 `grep`，在 hook 里可能读到终端 stdin 而挂住。`git grep -l` 只搜已追踪文件，
   语义相同且没有这个陷阱。
6. **没让 `push-scope.sh` 在 stdin 是终端时去 `read`。** 手动执行 hook 时会一直等输入，
   等于把「假绿」换成「挂死」。判不出范围就输出 `__UNKNOWN__`，按「跑」处理。

## 拿什么证明它生效了

**X3-01**

```
$ bun test ./tests/scripts/affected-tests.test.ts   → 48 pass / 0 fail
$ bun -e '…mapPathToTests…'
  .bun-version        → "full"
  CLAUDE.md           → ["./tests/build-target-naming.test.ts","./tests/release-channel.test.ts"]
  LICENSE             → []
  some/unknown/path.txt → "full"        ← 兜底方向已翻转
```

变异自证（两次，均恢复后重跑回绿）：
- 兜底改回 `return []` → **1 fail**（「未登记的未知路径 → full」）；
- 往 `NO_TEST_PATHS` 加 `"CLAUDE.md"` → **2 fail**（白名单项必须返回空集 / git ls-files 空集覆盖面）。

**X3-02**

```
$ bun test ./tests/scripts/pre-push-scope.test.ts    → 11 pass / 0 fail
```

覆盖：3 个提交中第 2 个改 `website/`、第 3 个只改 `packages/`（原实现必漏）、
重命名同时看到旧路径、remote_sha 本地不存在 → `__UNKNOWN__`、新分支与基线求差、
删除远端分支 → 空输出、空 stdin → 空输出、`pre-push.sh` 接线反漂移。

变异自证：把 `push-scope.sh` 的 `git diff "$base" "$lsha"` 改回 `HEAD~1` →
**1 fail**（多提交用例），恢复后 11 pass。

**全量门禁（worktree 内）**

```
$ bun run affected-tests:run   → 1818 pass / 1 skip / 2 fail
$ make build                   → 自检通过（关键修复已内联进二进制）
$ bun run lint / format:check / lint:boundary / lint:command-system / lint:legacy-tool / typecheck:gate → 全 exit 0
```

那 2 fail 是 `tests/build/rules-paths-scope-nonempty.test.ts` 的 worktree 环境假失败，
已按 CLAUDE.md「判定与我无关必须举证」三条核实：① 该测试只 import
`@sid-code/core/config/rules.ts`，不 import 本次改动模块；② 父仓 main 上单跑 3 pass；
③ worktree 里 `ruleOwnerDir` 解析到主仓根，`relative(REPO, owner) = ../../..`，
candidates 恒空。未改该测试、未放宽断言。
