# beta 泡制期采用「一修一号」，并补齐促升合并说明、Release 通道标记、beta 自动跟随

## 决定了什么

beta 期发现 bug 时**不在原版本号里修**，而是发下一个构建号，验收通过后 promote **最后那个号**。
稳定版用户会跳号（0.1.606 → 0.1.609）。这次补齐了五件配套（T1–T5）：

- **T1 促升合并说明**：`scripts/lib/changelog-stable.ts`（纯函数）+ `scripts/changelog-stable.ts`（CLI）。
  `--promote` 把 **(当前 latest, 目标]**（左开右闭）区间的 curated 合并成
  `changelog/curated/stable/v<ver>.json`（独立文件，带 `covers`）。破坏性变更完整保留在首组，
  `betaOnly` 版本整份丢弃。合并稿要**交互确认**才写 latest.txt，**非交互直接拒绝**促升。
  区间只有一个版本（快车道）时原样返回、不写文件，行为零变化。
- **T2 通道标记**：`--upload` 建的 Release 带 `--prerelease --latest=false`，正文首行写明是 beta 预发布。
  `--promote` 只把目标版本改成正式 + Latest，正文换成合并稿，中间号保持 pre-release。
  `changelog/channel.json` 记录当前稳定版（promote 时写），`changelog.json` 每个版本带
  `channel`、`mergedInto`、`covers`、`betaNote`。官网对 beta 版本显示「预发布」徽标，默认隐藏、可展开。
  `rollback.sh` 不改 Release 标记，输出里提示一句。
- **T3 beta 修复号轻量发布**：`release.sh --upload --beta-fix --beta-note "<一句话>"` 在缺 curated 时
  自动写最小形态（`betaOnly:true / userFacing:false / betaNote`），不交互。**不跳过任何门禁**。
  校验器新增反向约束：已经成为正式版、又没被别的稳定版说明覆盖的号，不能标 betaOnly。
- **T4 beta 自动跟随**：自动更新按 `getReleaseChannel()` 读对应指针（beta 读 beta.txt），
  安装子进程的 `SID_CODE_CHANNEL` 跟随当前通道，不再写死 stable。dev 构建不自动更新。
  `sid-code update` 缺省沿用当前通道，显式变量优先。
- **T5 积压可见**：`--promote` 和 `rollback.sh`（无参数）打印 stable → beta 之间积压的 beta 号及各自摘要，只读。

## 放弃了什么（以及为什么不选）

- **在原版本号里原地修（同号换字节）**：install.sh 会复用已存在的版本目录，归档不可覆盖，
  promote 说不清哪份字节被测过，tag 和轨迹 `app_version` 也定位不了。四处会同时静默失效。
- **预发布后缀 `0.1.607-beta.N`**：版本号是编译期内联的。正式版要显示 `0.1.607` 就得重建，
  稳定版用户拿到的就是**没被 beta 测过的字节**，破坏 promote 不变量（决定性理由）。
  另外它要改版本解析的全链路（versions.ts、install、rollback、archive、bump、changelog）。
  下一个提这个方案的人，先回答「正式版的字节是不是 beta 期测过的那一份」。
- **非交互 promote 降级放行**：放行的后果是稳定版说明缺了跳过版本，而这是对外信息、不可逆。
- **合并结果改写已入库的 `v<ver>.json`（加 covers 字段）**：会改变已过目文件的语义，所以选了独立的 stable/ 目录。
- **自动更新时自动从 stable 切到 beta（或反向）**：通道切换必须显式。自动更新只在当前通道内升级。

## 拿什么证明它生效了

- 单测 / 契约：`tests/scripts/changelog-stable.test.ts`（合并规则、快车道逐字节相同、区间下界变异自证、
  最小形态校验、通道判定、积压、CLI 真跑），`tests/release-flow-contract.test.ts`
  （--prerelease / --promote 契约及变异自证、合并在写指针之前、非交互 fail、--beta-fix 不碰门禁），
  `packages/core/tests/update/*`（beta 读 beta.txt、子进程通道跟随、dev 跳过），
  `tests/update-auto-e2e.test.ts`（beta 装完 `.channel=beta` → 再次安装读 beta.txt）。
- 线上验收**尚未发生**，等下一次真实 beta 修复：
  ① `--upload` 之后 `gh release view v<ver> --json isPrerelease` 应为 `true`；
  ② 积累 ≥2 个 beta 号再 promote 时，官网和 Release 的稳定版条目要包含全部跳过版本的用户可见变更（人工逐条对照）；
  ③ beta 测试人员不手动操作，24h 内自动升到新的 beta 号（看 `~/.sid-code/updates/state.json` 的 `lastAttempt`）。
- 已知边界：0.1.608 之前发布的 beta 二进制仍写死 stable，它们升级的第一跳要手动带 `SID_CODE_CHANNEL=beta`。
