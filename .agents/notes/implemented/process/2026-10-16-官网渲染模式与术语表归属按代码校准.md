# 官网渲染模式与术语表归属按代码校准

## 决定了什么

修掉官网三页 + llms.txt 生成器模板里与当前代码不符的表述。根因是两处「实现变了、文档没跟上」：

1. **渲染模式默认值反转**（2026-09-26 `db6c11fe`「配置回到单一真相源，TUI 默认改回主屏」/ ADR-040 之后）：
   - `website/start/next.md`：删「含 `--inline` 逃生舱」，改「含全屏 / 内联渲染模式的切换」。
   - `website/use/interactive.md` 的 Copy Mode 小节：原以「默认是全屏」为前提（「用 `--inline` 逃生舱回到旧的主屏」「全屏模式正是为根治这个才成了默认」），整节改写为——默认即主屏内联（鼠标原生选中可用）；全屏经 `--alternate-buffer` / `/tui on` 显式开启；全屏下 `Ctrl+S` 进 Copy Mode 或切回主屏；主屏的残行问题已由 Static 同步折叠收敛。
   - `website/use/troubleshooting.md` 两处同源表述：「鼠标划不中」限定为仅全屏模式；「花屏 / 残行」删「全屏视口成为默认要解决的问题——确认你没有用 `--inline`」，改写为主屏路径已用 Static 同步折叠收敛。
   - 依据：`packages/core/src/config/config.ts:373`（「false（默认，ADR-040）：主屏 Static 渲染」）、`config.ts:1002`（`alternateBuffer: false`）、`packages/cli/src/help.ts:115`（「现已是默认……显式写出只为兼容旧脚本」）。

2. **参考页生成归属说错**：`website/start/next.md` 写「这几页全部由脚本从源码生成」，但 `/ref/glossary` 是人工维护——生成器只产 6 页（`scripts/docs-gen-reference.ts` 的文件写入清单），且 `--stale` 复核逻辑显式把 glossary 排除在「脚本生成天然不漂移」集合之外（`rel !== "ref/glossary.md"` 分支）。改「除术语表外全部由脚本从源码生成」。
   - 同源修正生成器模板 `scripts/docs-gen-reference.ts`：导语句补「除术语表外」、`SECTION_NAMES.ref` 从「参考（脚本生成）」改为「参考」（与顶栏 nav 一致）；重新生成 `website/public/llms.txt`。

## 放弃了什么（以及为什么不选）

- **不把术语表纳入生成器**（消灭例外）：glossary 的内容是人工判断的术语定义与取舍，生成不出来；正确做法是如实标注归属，而不是硬凑「全部生成」。
- **不改扫描命中但语境正确的几处**：`website/extend/headless.md:402`（「`-p` 下 TUI 相关的东西全不生效（键位、Copy Mode、`--inline`）」——举例本身正确）；`website/ref/glossary.md:439`（「这六页由脚本生成」——指的就是 6 个生成页，不含自身）；`website/use/interactive.md` 的 `/tui` 表格行（「`/tui off` 切到内联（= `--inline`）」——等价关系仍成立）。
- **不删 `--inline` 的用法示例**：它仍是有效参数（显式覆盖配置用），只是不再是「逃生舱」——保留其正确用法而不是从文档里抹掉。
- **不给「默认值反转」立机械化门禁**：这类漂移没有稳定断言可写（要靠人读源码 / help 判断语义），本次以全站关键词扫描（逃生舱 / 默认是全屏 / 脚本生成）兜底，残留归零。

- `make build` 退 0（产物自检全过）；lint / format:check / lint:boundary / typecheck:gate（66 / 66）全绿。
