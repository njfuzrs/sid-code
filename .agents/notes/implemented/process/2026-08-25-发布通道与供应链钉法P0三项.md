# 发布从「一写 latest.txt 全量放量」改成「beta 泡制 → promote 促升」，并把 18 处 action 钉成 SHA

## 决定了什么

方案 `20260820-分支模型与发布通道` §5.1 的 P0 三项，一个 PR 落地（互不依赖，但共享
「发布安全」这一个 review 上下文，拆三个 PR 只会让 reviewer 三次重建同样的背景）。

**A1 供应链（`.github/workflows/*` + `.github/dependabot.yml`）**
18 处 `uses:` 全部从可移动 tag 换成 40 位 commit SHA + `# vX.Y.Z` 注释；
6 个 workflow 全部补顶层 `permissions:`。只有 `judge-calibration.yml` 给
`contents: write`（它真的 `git push` 月度校准报告），其余一律 `contents: read`。

**A2 发布通道（`scripts/release.sh` + `scripts/install-template.sh`）**
服务器顶层现在两个指针文件，**共用同一批版本目录**：
`--upload` 只写 `beta.txt`；`latest.txt` 由新的 `--promote <version>` 独占。
用户侧 `SID_CODE_CHANNEL=beta` 读 beta 指针，缺省 stable。
配套改了旧版本清理：额外豁免两个指针指向的版本。

**A3 回滚（新增 `scripts/rollback.sh`）**
不带参数打印两个通道现指向谁 + 有哪些版本可回；带版本号则改指针。
回滚前校验目标版本 4 平台产物齐全，写完回读自证。

三处文档同步：`CLAUDE.md` 发布上线段（新增「发布通道」小节）、
`website/start/install.md`（新增「抢先版」段）、`help.ts` 环境变量段
（经 `docs:gen-reference` 落进 `website/ref/env.md`）。

## 放弃了什么（以及为什么不选）

**加一条 `develop` 分支** —— 方案 §0.1 已用 18 仓库实测否决（跑 GitFlow develop 的 0 个），
本次只是执行那个结论。机制性理由：develop 隔离的是**代码**，而 bug 在**真实使用**中暴露；
代码待在 develop 上不会自己暴露 UX 回归。`openclaw` 那条零独有提交的死 develop 是实证。

**给 beta 单独一套版本目录** —— 否决。那样 promote 就得复制或重建，
"泡制期测的字节 = 用户拿到的字节"这个**唯一价值**当场消失。共用目录让 promote 退化成
纯指针操作，这是刻意的设计而不是省事。

**`--promote` 加一道「CUJ 清单已勾」的机械门禁** —— 本轮不做。清单本身是 B1 的范围，
没有载体时硬加门禁只会得到一个人人 `--skip` 的空勾选框（同 `release.sh` 里
「指标退步只报告不拦」那条注释的理由）。现在只在 promote 开头打印一句提醒。

**在 `update.ts` 里解析/校验通道** —— 否决。install.sh 是唯一事实源，两处都解析会立刻
产生两份要同步的通道清单，加第三个通道时必漏一处。`update.ts` 只回显，不判断。

**把 `latest.txt` 从本地 `dist/release/` 里也删掉** —— 没删。它是 `file://` 本地验证路径
的必需品（不带 channel 变量时读它），只是**不上传**。

## 拿什么证明它生效了

**A1**（全仓扫描，不是抽样）：
- tag 钉住 `grep -rhoE 'uses: [^ ]+@v[0-9]+' | wc -l` → **0**（改前 18）
- SHA 钉住 → **18**；顶层 `permissions:` 声明 → **6/6**（改前 0/6）
- 反漂移门禁 8 条落在 `tests/release-flow-contract.test.ts` 的
  「A1 供应链」describe，含**空集自证**（workflow 目录非空）与**清单锁定**
  （带 write 的 workflow 必须恰好等于 `["judge-calibration.yml"]`，新出现一个就红）。

**A2 通道解析是真跑出来的，不是读正则读出来的**（`tests/release-channel.test.ts`，
走 install-template.sh 自带的 `file://` 本地验证路径）：
```
不带变量      → 目标版本: v0.1.699（通道: stable）
CHANNEL=beta  → 目标版本: v0.1.700（通道: beta）
CHANNEL=Beta  → ❌ 未知通道 SID_CODE_CHANNEL=Beta（可选：stable / beta），exit≠0
```
第三条是变异自证：大小写写错必须报错而不是静默按 stable 装 ——
静默回落的失效形态是「用户以为自己在跑 beta」，而这个误解只在
「beta 期没发现任何回归」时才暴露，那时归因已经做不了。

清理豁免那条也是**行为级**的，不是只匹配 `CLEANUP_CMD` 字符串：造 6 个版本目录、
保留窗口 2、stable 指向**最旧**那个，真跑一遍清理脚本后断言
701（stable 指向）与 706/705（窗口内）都在、702-704 被删。
「702-704 被删」这半边不可省 —— 少了它，一个什么都没删的实现也能让这条测试全绿。

途中真炸出一个 bug 并修掉：`info "目标版本: v$VERSION（通道...）"` 在 macOS 自带
bash 3.2 上直接 `VERSION（: unbound variable`（全角字符被当成变量名的一部分）。
这正是 `release.sh` 的 `on_exit` 里那条 `$code）` 注释记的同一个坑，改成 `${VERSION}`。
仓库里已有的那条「没有裸 `$var` 紧跟全角字符」断言也当场抓到了我在 `CLEANUP_CMD`
里犯的同一个错 —— 一条老门禁在新代码上真触发了一次。

**A3**：`/bin/bash -n`（3.2）语法通过；8 条断言含「不碰 git / 不 `rm -rf` / 不重新构建」
的负向断言 —— 回滚的是「用户拿到哪一版」，不是「仓库停在哪一版」。

**全仓门禁**：`bun test` 10892 pass / 1 fail，`make build` 通过（无
`will always be undefined` 警告），lint / format / boundary / `docs:gen-reference --check` 全绿。

那 1 个 fail 是 **worktree 环境产物，不是本次回归**，三条证据：
① 失败断言 `expect(reason).toContain("计划模式")`，实收
`"非交互模式下自动拒绝: [安全检查] Claude 配置目录"` —— worktree 路径
（`.claude/worktrees/...`）命中 `checker.ts:198` 的 `.claude/` 敏感路径规则，
在 plan mode 判定**之前**就拒了；
② 同一文件在主 checkout 上 `bun test --cwd <主仓>` 是 **6 pass / 0 fail**；
③ 该测试不 import 本次改动的任何文件（权限子系统与发布脚本零交集）。

**⚠️ 尚未证明、也不该假装已证明的部分**：本次没有真发布过，
所以「服务器上真有两个指针文件」「promote 真能挪指针」「rollback 真能回滚」
都只到脚本逻辑与本地验证为止 —— 服务器侧要等下一次真实发版才算验完。
更重要的是 A2 的**真判据不是「通道能用」，而是「至少有一次真实回归在 beta 期被发现、
没有流到 latest」**。建好而没人装 beta，它就退化成第二个「防线全在、调用全 0」
（见 `scripts/defense-trigger-rate.ts` 那次实测 0% 触发的教训）。这条判据已写进
`CLAUDE.md` 的发布通道小节，等下一次发版之后回来核。
