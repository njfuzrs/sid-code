# NOTICE 补渲染底座来源与旧底座版本界线（B9 / T9.2）

## 决定了什么

- `NOTICE` 新增第 4 节「`packages/tui/` —— 以 ink@7.1.1 为起点的渲染底座（MIT）」：上游地址与 tag commit、导入 commit `8fd9048d`、版权行原样照抄 `packages/tui/LICENSE`、修改范围指向 `packages/tui/UPSTREAM-DIFF.md`、布局引擎 `yoga-layout@3.2.1` 点名并归第 2 节；第 3 节补 ink 的 MIT 原文。
- 第 4 节末尾写明旧底座的来源与**版本界线**：旧底座自 `5954159b`（T9.1）起从仓库与产物删除，**v0.1.608 是第一个不含它的发布版**，v0.1.607 及更早含该代码。界线由 `git merge-base --is-ancestor 5954159b v0.1.607`（否）与 `… v0.1.608`（是）判定。
- README 中英文、CONTRIBUTING 的定位与第三方资产清单同步改为「以 MIT 的 ink 为起点重写（`packages/tui`），来源见 NOTICE」。
- 博客 `sc-20-tui.md` 正文不改，文首加带日期按语指向新底座与 NOTICE。

## 放弃了什么（以及为什么不选）

- **写「其余均为自研」**：不写。CLI 层有 52 个文件提到 gemini-cli（Apache-2.0），是「参考思路」还是「改写代码」尚未核实，NOTICE 里写满等于替一个没核过的事实背书。
- **在 NOTICE 里不提旧底座**（反正已经删了）：不选。已发出去的 v0.1.607 及更早的二进制里仍有它，删掉代码不等于删掉分发事实；NOTICE 自己的原则是「宁愿披露过度」。
- **把 ink 原文只放在 `packages/tui/LICENSE`、NOTICE 只给链接**：不选。NOTICE 第 3 节对 ripgrep 是贴原文的，保持同一种做法，读 NOTICE 的人不必再跳文件。

## 拿什么证明它生效了

- 版权行一致：`diff <(sed -n '/Copyright/p' packages/tui/LICENSE) <(sed -n '/^ink —— MIT/,/^====/p' NOTICE | grep '^Copyright')` 无输出。
- 版本界线：`git merge-base --is-ancestor 5954159b v0.1.607` 退出 1，`… v0.1.608` 退出 0；线上 `latest.txt` = `beta.txt` = `0.1.608`（2026-10-12 curl）。
- `website/ref/env.md` 中 `SID_TUI_RENDERER` / `CLAUDE_CODE_COMMIT_LOG` / `CLAUDE_CODE_DEBUG_REPAINTS` 的 `grep -c` 均为 0；`CLAUDE_CODE_TMUX_TRUECOLOR`、`CLAUDE_CODE_ACCESSIBILITY` 仍为 1，读取点在新底座 `packages/tui/src/{colorize,cursor-helpers}.ts`（D125 留的旧名别名）。
