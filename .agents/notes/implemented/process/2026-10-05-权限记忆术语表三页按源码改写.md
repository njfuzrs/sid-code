# 权限 / 记忆 / 术语表三页按当前源码改写（D29–D42、D95–D105）

## 决定了什么

`website/use/permissions.md`、`website/use/memory.md`、`website/ref/glossary.md` 三页逐条回源码核过再改：

- permissions：`--dangerously-skip-permissions` 改成如实写「跳过全部检查，只留审计」（`checker.ts` 进门就早退），页首承诺和节标题都改了；`-y` 与 skip 分开写，always-allow 进 Shift+Tab 循环的判据改成 skipPermissions（`app.ts` 的 `bypassAvailableAtLaunch`）；配置层级按 `RULE_SOURCE_PRIORITY` 重写成 8 个来源，企业策略路径改成 `managed-settings.json` 候选链，并写明 `policy.json` 已废弃；沙箱一节改成真实存在的两个字段（`enableSandbox` / `sandboxAutoAllowBash`，默认都是 false），把「内核已兜底」这条已被源码否定的理由换成改默认值的真实原因；去掉旧 `src/` 路径和行号。
- memory：save_memory 写成自动存、无人工确认；层级补上 managed/rules、`.sid-code/rules`、managed 平台路径、5 个固定文件名候选；用户规则目录改成「两个都加载」；`/memory` 子命令按源码补齐到 10 个（含无参开面板）；团队记忆补上「必须配共享目录」这个前提。
- glossary：agentic loop 的结束条件、Hook 事件名写法、权限模式排序和 Shift+Tab 轮转、team-defaults 升级补键、fallback 只告警不拦截、CLAUDE.md 层数、Skill 计数、microcompact、provider 去掉 Azure 并写明 OpenAI 族包含 Responses。

## 放弃了什么（以及为什么不选）

- 清单 D31 原本建议把 JSON 示例里的 `sandbox.autoAllowBashIfSandboxed` 改成 `false`。我没照做：settings.json 里并没有 `sandbox` 对象，`allowedHosts` / `allowedWritePaths` 也没有从配置读入的入口，真实字段是 `sandboxAutoAllowBash`。只改值会留下一个照抄了也不生效的示例。
- D43 在 `use/context.md`，不在本次的三页范围内，留给负责那页的人。
- D101 已随 B18 改成「取更严」（`resolveEffectiveCostLimit` 取两者中的较小正数），术语表已经是这个写法，所以没改。
