# 把 25 篇「从零到一」入门文机械导入博客，并让博客与 summary 解耦

## 决定了什么

**1）一次性机械导入，博客侧从此是独立事实源。**

`docs-research/sid-code/summary/` 下 21 个模块 + 4 条横切能力各一篇入门文（共 25 篇，
102,361 行）导入 `website/blog/`，产出 `sc-01-agentic-loop.md` … `sc-x4-enterprise.md`，
输出 85,978 行（切除 16%）。

**导入脚本落在 `docs-research/scripts/import-summary-docs.ts`，不在本仓。**
与 `resume-metrics.ts` 同一条判据：sid-code 是**公开**仓库，而这个脚本的输入是一个
未开源的私有文档库，代码里必然写着它的绝对路径与用户名 —— 放进公开仓的 `scripts/`
等于把私有库的目录结构一起发布，且它对任何 sid-code 的使用者与贡献者都不可执行。
也不删：那 25 篇的来历、切了什么、脱敏了什么，只记录在那个脚本里。

导入后**不回流、不做双向同步**。溯源靠每篇文首的 `::: info 这是一份快照` 块
（写明该篇 `last_verified` 日期），与 `cc-*` 21 篇标「2026-03-31 源码快照」同一个做法。

**2）新增受控词 `Agent Runtime 从零到一`（`blog-meta.ts` 的 SERIES，order 8）。**

25 篇一个系列，不按领域拆成五六个。判据：这批共享的是**体裁**（一模块一篇、有编号、
从「不做它会怎样」讲起、教学向、彼此无严格依赖），不是领域。横切 X1–X4 也不单开第二个
系列，语义差别由文件名 `sc-x1-` 与标题「（横切一）」表达。

不标 `external: true` —— 讲的是自家实现，文中 `packages/*/src/` 路径是真实存在的源文件，
「N 处源码引证」这个指标在这里成立。

**3）机械切除四类内容**（`CUT_HEADING` 命中标题即整段切除，块根判定避免父子重复）：
面试题库 / 面试怎么答 / 自我介绍 / 反问 · 打印版速记与速览 · 指回未开源私有文档的
「原始文档导航」「回到原始文档」「延伸阅读」附录。切了 25 篇共 16,383 行。

**4）四条机械脱敏规则**：`/Users/zhourusheng/Code/person/` → `~/`（11 处）、
打平的会话目录名 `Users-zhourusheng-` → `Users-me-`（1 处）、内部网关代号
`ppchat`/`luna` → `网关 A`/`网关 B`（4 处）、`docs-research/...` 私有文档引用 → 描述性文字（1 处）。

**5）顺带修了 `countEvidenceFiles` 的一个静默失效**（详见下方证据段）。

## 放弃了什么（以及为什么不选）

**放弃「导入脚本 + `--check` 反漂移门禁」这个形态。** 原打算复用
`docs-gen-reference --check` 那套幂等转换器 + 门禁。否决理由：它与博客侧的任何人工编辑
直接冲突 —— 脚本一复跑就覆盖掉改写结果。而博客那份从落地起就不是同一份东西了
（切了 16%、重写了 frontmatter、降了标题层级），硬维持一致只会两头都不自由。

换成 `--audit`：只读体检 `website/blog/sc-*.md`，守的是「不出现面试腔与私有信息」
这个**内容性质**，而不是「与私有源文档一致」。这条才该长期存在。

**放弃按领域拆成 5–6 个新系列。** 受控词表会从 9 涨到 14 以上，筛选器平铺成两行 ——
正是 `blog-meta.ts` 里那段论证要防的形态（「20 篇时会平铺成三四十个」）。

**放弃塞进已有六个自家系列。** 实测只有 8 篇有归属（Loop/Multi-Agent/Session/Goal →
Agent 架构，Context → 上下文工程，Permission → 安全与权限，TUI → TUI，X1/X2 → 数据与度量），
剩下 17 篇没有一个装得下。硬塞会把「上下文工程」这种有明确边界的受控词撑成
「所有跟 agent 沾边的东西」。

**放弃用各篇自己的 `last_verified` 当 `date`。** 那些日期跨 08-15 … 09-03，而
`blog-meta.ts` 的系列内排序是「日期升序，同日再按 url 升序」——用它会让「企业级」
（08-15 最早）排到系列第 1 位、Agentic Loop 掉到中间。25 篇统一 `2026-09-03`，
真实核验日期落在文首快照块里。`cc-*` 21 篇共用一个日期正是同一个原因。

**放弃按「面试」逐词清洗正文。** 整段章节切干净，正文里零散的「面试常问」这类措辞保留
（用户明确要求）。`--audit` 对这一项**报数而不判失败**，作用是给出可见基线：
哪天某篇数字异常跳高，说明有整段内容漏切了。

**放弃「不认 monorepo 前缀」的旧 evidence 正则**，见下段。

## 拿什么证明它生效了

**导入结果**（`bun run scripts/import-summary-docs.ts`）：

```
25 篇：102361 → 85978 行（切除 16383 行 = 16%）
机械替换：私有路径→~/ 11 处 / 打平的会话目录名 1 处 / 私有文档引用 1 处 / 网关代号脱敏 4 处
```

**私有信息实查为零**（`grep -l` 全 25 篇）：`zhourusheng` 0 命中、`ppchat`/`luna` 0 命中、
`docs-research` 0 命中。留下的 `/Users/x/.env`、`/Users/me/code` 是文档原本就写成的占位
形态（minimatch 行为演示、MCP 配置样例），刻意不动 —— 改成 `~/` 会让那些例子失去意义。

**`--audit` 做了变异自证**（不是「有东西红了就算过」）。往 `sc-14` 分别塞回三种东西，
每次只有对应那一条亮：

```
塞回 /Users/zhourusheng/... → 面试腔残留 1 / 私有绝对路径 1      ← 只有「私有绝对路径」新增
塞回 claude-sonnet-5-ppchat → 面试腔残留 1 / 内部网关代号 1      ← 只有「内部网关代号」新增
塞回 ## 面试题库（28 题）   → 面试腔残留 2                        ← 基线 1 跳到 2
还原                       → 面试腔残留 1                        ← 回到基线
```

还原后与重跑导入的产物 `diff -q` **字节一致**。

**顺带修的静默失效（`countEvidenceFiles`）**：本仓是 monorepo，根目录**没有** `src/`，
源码在 `packages/{core,cli,shared,tui-renderer,eval-framework}/src/` 下。旧正则不锚定左界，
于是 `packages/core/src/query/loop.ts` 被从中间切成 `src/query/loop.ts` —— 不存在的路径，
`existsSync` 静默判掉、计数记 0。后果是一篇引了二十个真实源文件的文章，卡片上显示
「0 处源码引证」，而这个数字存在的意义恰恰是支撑「带 file 级证据」这个主张。

加 `(?<![A-Za-z0-9_./-])` 左界断言 + 可选 `packages/<包>/` 前缀后，全站 68 篇实测：

```
修前合计 19 → 修后 251，且没有任何一篇的计数变小
sc-01-agentic-loop  1 → 19      sc-17-sdk-plugins  0 → 27
sc-03-tools         0 → 22      sc-18-ide-bridge   1 → 24
```

「没有一篇变小」是关键判据 —— 只放宽前缀、不放宽后缀与存在性校验，所以不会引入虚高。
左界断言不可省：少了它，非锚定匹配依旧能从中间起头切出裸 `src/...`，
同一处引用会同时产出真假两个命中。

**门禁全绿**：

```
bun run affected-tests:run   1301 pass / 0 fail / 5662 expect（56 文件，14.83s）
make build                   编译产物自检 4 项全过
bun run website:build        68 篇，ignoreDeadLinks: false 下构建成功（27.5s）
bun run lint                 无输出（通过）
bun run format:check         All matched files use the correct format
```

`website:build` 这一条是本次最要紧的门禁：`ignoreDeadLinks: false` 是刻意的死链门禁，
25 篇 8.6 万行一次并入若有任何断链或 Vue 语法冲突，构建即失败。

**渲染产物实查**：`dist/blog/` 下 25 个 html、sitemap 收录 25 条、feed 68 篇。
快照块渲染为 `<div class="info custom-block">`，与老文章 `::: tip` 的
`<div class="tip custom-block">` 同一形态。

**系列接线实查**（跑 `loadBlogPosts()`）：25 篇全部归入新系列、`seriesIndex` 1→25
与文件名序号一致（`sc-01` 是第 1 篇，不是被 `readdirSync` 顺序打乱）、无孤儿文章、
SERIES 的 `order` 无重复（新词占 8，两个 external 顺推 9/10）。

**一个已知的待定项，不算已解决**：特色大卡现在是 `sc-01-agentic-loop`（`loadBlogPosts`
在无人工 `featured` 时把最新一篇置顶）。25 篇同日并入会把 8 篇自家实测文压到列表后段。
是否要把 `featured` 钉回某篇实测文，留给内容决策，本 PR 不擅自定。
