# 环境变量该进 `--help` 正表还是留在页尾清单，判据是「面向用户 + 语义稳定」而非「有没有默认值」

## 决定了什么

给 `website/ref/env.md` 的两类分区定了一条可复用判据，并按它把 9 个变量从页尾
「未列入上表的读取点」移进 `packages/cli/src/help.ts` 的环境变量正表（73 → 82，页尾 45 → 36）。

**判据（三条同时成立才进正表）**：

1. **面向用户/运维有意提供的覆盖点** —— 源码注释里写明它的用途是让部署方/用户调，
   而不是让测试夹具调；
2. **语义稳定** —— 有明确默认值与解析规则（非法值如何回退是确定的），不是临时开关；
3. **不是内部实现细节的旋钮** —— 用户不需要读源码就能判断该设成什么。

**据此补进正表的 9 个**：

| 变量 | 进正表的理由 |
| --- | --- |
| `SID_MODEL_CATALOG_TTL_MS` | 本次的起因。`model-capabilities.ts:144-158` 用整段注释讲清默认 1 天的取值依据，且修复方案的验收步骤直接用 `=0` 强制重采 —— 它是正规覆盖点，被归进「不建议依赖」等于文档骗人 |
| `SID_CODE_DISABLE_MOUSE_CLICKS` | **本来就在 help 里**（原 `:227`），但变量名与说明之间只有 **1 个空格**，`parseHelpEnvVars` 要求 `\s{2,}` → 被静默丢出正表。这是解析漂移，不是登记缺失 |
| `SID_RIPGREP_PATH` | `ripgrep.ts:45` 把它列为解析链第 1 优先级并注明「用户/测试显式指定」；`doctor.ts:138` 还把它作为来源显示给用户 —— 已经是用户可见契约 |
| `SID_GREP_TIMEOUT_SECONDS` | `ripgrep.ts:79-86` 注释给出平台相关默认值（20s / WSL 60s），是典型的环境适配旋钮 |
| `SID_MAX_TURNS` | `soft-turn-limit.ts:19` 明写「env 门控：显式开启」，且整个模块的设计前提是把决策权交给用户 |
| `SID_CODE_AUTO_MEMORY` | `paths.ts:252-256` 明确它**优先于 `settings.autoMemory`** —— 一个能覆盖 settings 字段的 env 必须与那个 settings 字段同等可见 |
| `SID_CODE_MAX_MCP_OUTPUT_TOKENS` | `mcp-output-limit.ts:31-37` 给出完整优先级链与默认 25000，并刻意兼容 CC 的无前缀名 |
| `SID_CODE_SUBAGENT_TIMEOUT_MS` | `timeout-budget.ts:131` 原文即「运维/测试的**统一覆盖入口**」 |
| `SID_TOOL_MAX_CONCURRENT` | `tool-orchestration.ts:58-60` 对标 CC `getMaxToolUseConcurrency()`，默认 10 |

## 放弃了什么（以及为什么不选）

**放弃「把页尾清单当待办列表清空」**。那个清单本身是有价值的分类（明示「不保证向后兼容」），
不是欠债。剩余 36 个逐个过判据后**刻意保留**，按不通过的条数分三类：

- **纯内部/测试夹具**：`SIDCODE_NO_SPAWN`、`SID_CODE_SESSION_INDEX`、`SID_CODE_USAGE_FILE`、
  `SID_CODE_CACHE_BREAKS`、`SID_CODE_HOME`、`SIDCODE_SSE_EVENT_SHIM` —— 存在目的是测试隔离，
  写进用户文档等于承诺一个我们不想承诺的契约（破判据 1）。
- **休眠/实验性 flag**：`SID_ENABLE_NESTED_SUBAGENT`、`SID_ENABLE_AGENT_TEAMS`、
  `SID_ENABLE_MIDTURN_DRAIN`、`SID_ENABLE_OUTPUT_STALL`、`SID_ENABLE_THINKING_DIVERGENCE`、
  `SID_ENABLE_STREAMING_TOOL_EXEC`、`SID_ENABLE_GOAL_HARD_STOP`、`SID_TEAMMATE_MODE`、
  `SID_CODE_MEMORY_RECALL` —— 语义还会变（破判据 2）。`SID_CODE_MEMORY_RECALL` 是最接近边界的一个：
  它有清晰注释和默认值，但 `recall.ts:26` 自己写着「**未接通期间不要在文档里宣称**
  记忆走语义召回」—— 源码里已有一条针对本次这种动作的显式禁令，写进正表就是承诺一个
  当前不生效的开关。
- **实现细节旋钮**：`SID_CODE_OPENAI_PROTOCOL`（`openai.ts:1255` 明说用途是「灰度/回滚」）、
  `SID_CODE_CHANNEL_TRUST`、`SID_CODE_PAIRING_TIMEOUT_MS`、`SID_SUBAGENT_MAX_DEPTH`
  （被 `MAX_AGENT_DEPTH` 硬封顶，用户设了也可能无效 → 破判据 3）、
  `SID_CODE_ALERT_WEBHOOK_URL`、`SID_CODE_RELEASE_HOST`、`SID_CODE_INSTALL_URL`。

**也放弃「把 `parseHelpEnvVars` 的 `\s{2,}` 放宽成 `\s+`」**，虽然那才是
`SID_CODE_DISABLE_MOUSE_CLICKS` 掉队的直接原因。放宽会让「说明文字里含空格的续行」
和「变量名后紧跟一个空格」两种形态都能匹配，正表反而更容易吃进噪声；
把 help.ts 那一行补成 2 空格既修了问题，也保持了该段本来就有的对齐风格
（实测该段 67/73 行的说明列都在第 32 列）。

**没有把判据写成机械门禁**。它需要读源码注释判断「这个 env 的意图是给谁用的」，
是语义判断 —— 硬做成脚本只会得到一个按前缀/有无默认值分类的错判器。
`scanSourceEnvVars` 的注释本来就写着「只用来算差集列在页尾，不当门禁」，本次维持这个边界。

- `bun run docs:gen-reference` → `✓ 已更新 website/ref/env.md`；`git status --porcelain`
  只有 `packages/cli/src/help.ts` 与 `website/ref/env.md` 两个文件，
  `website/public/llms.txt` **未变**（它的摘要不含 env 计数），无无关漂移。
- `git diff website/ref/env.md` 逐行核对：正表 `共 73 → 82`，页尾
  `未列入上表的读取点（45）→（36）`，新增 9 行正是上表 9 个变量，无其他改动。
- **对齐没被破坏的实证**：跑 `./sid-code --help` 看真实渲染 —— 9 个变量全部出现在正表
  且说明列对齐（`SID_MODEL_CATALOG_TTL_MS` 在 `:156`、`SID_CODE_DISABLE_MOUSE_CLICKS` 在 `:230`）。
  这一步是必要的：只看 `env.md` 生成成功不能证明 help 段的列对齐还在，
  因为解析器容忍度比人眼宽。
- `bun run docs:gen-reference --check` → `✓ 参考页与源码一致，CLI 双源对账通过`（EXIT=0，pre-commit 拦的就是这条）。

  **1480 pass / 0 fail**，129 个文件 31.30s。
- `make build` → 编译产物自检 4 项全 ✓；显式 `grep -c "will always be undefined"` = **0**
  （worktree 已跑过 `bun install`，无向上解析导致的假成功）。
