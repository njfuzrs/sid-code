# PR 模板补「回归由哪一层守」，Agent Note 补可选的方案来源字段

## 决定了什么

质量防线分层专项 M6 左移四项里，能在本仓用模板和字段落地的两项：

- **PR 模板**（`.github/pull_request_template.md`）在「怎么验证的」前面加一节「本改动的回归由哪一层守」：填守护层和具体用例/测试，或写「不需要：<原因>」。修 bug 时要求写「之前为什么没拦住、现在由哪条拦」。
- **CONTRIBUTING.md** 加「防线分层」一节：G1–G5 的归层判据（停在第一个「是」）和「功能拆两半」原则，是 PR 模板那一问的判据来源。原判据只在私有总纲 §3.2 里，贡献者读不到。
- **Agent Note** 加可选的 frontmatter 字段 `Source:`：方案出自私有文档库时，写文档标题和日期，**不写路径**。`_template.md`、`.agents/notes/README.md`、CONTRIBUTING 都写了。校验器不查这个字段。
- `tests/build/agent-note-gate.test.ts` 加 3 条：带 `Source:` 的 Note 不报红；模板保留 `Source:` 行，文档写明「不写路径」；PR 模板有这一节，且它指向的 CONTRIBUTING 小节存在。

这样做的目的：专项主指标「逃逸率」的分母，是写了「本该在哪层被拦住」的复盘数。PR 模板里这一问，是这项数据在写代码之前的来源。

M6 另外两项不在本 PR：「非平凡改动缺 Note 时提醒」要动 CI，单独做（PR-8）；复盘模板在私有文档库里改。

**牺牲**：PR 模板多一节，所有 PR 作者多花约 30 秒（更省 → 更准）。

## 放弃了什么（以及为什么不选）

- **把「回归由哪一层守」做成 CI 检查（PR 正文没填就红）**：判据要语义判断，做成阻断会逼人填「G1」敷衍过闸，等于奖励重贴标签。总纲 §3.6 明确只做「写代码前要回答的问题」。
- **`Source:` 写私有文档路径**：开源仓里点不开，还泄露私有库的目录结构。标题加日期足够人工检索。
- **`Source:` 设为必填，或让校验器查它的格式**：方案在 PR 里讨论出来的改动没有外部来源，必填只会产出 `Source: 无`。校验器的定位是只查形态，可选字段不在其中。
- **PR 模板只写「见总纲 §3.2」**：总纲在私有库，外部贡献者读不到，所以判据搬进 CONTRIBUTING。
