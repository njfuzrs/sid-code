# 控制变量与题集版本从字段升格为判据

## 决定了什么

把「控制变量」「题集版本」从字段 / 局部脚本升级成判据 / 共享闸。

- `check-controlled-vars.py`：从 `lock.json` `trials[0]` 读全部五个 multiplier，
  **先断言键存在，再断言跨臂相等**。资源项一并比。扫描面含 W3 三臂（含 A3）。
- `taskset_fp.py` + `taskset-fp.sh`：指纹改为 `题数:题名sha16:digest_sha16`。
  四个跑法脚本（`w3-run.sh` / `run-claude-code-contrast.sh` /
  `run-model-switch.sh` / `run-permission-switch.sh`）共用。
  旧两段文件比对只核前两段，避免在途 job 被新格式误杀。
  W3-54 的 digest 钉死值写在 `CANONICAL`（有 lock 才核第三段）。

为什么它只是 P2：`controlled_variables` 字段一直在、数据 56/56 一直在，
而真跑一遍三组跨臂全一致 ⇒ **缺的是回归保护，不是修错**。
有字段就以为有保障；反过来，没判据 ≠ 现在就错了。11 号初稿两个方向都踩过。

## 放弃了什么（以及为什么不选）

放弃只比「两臂都有的键」（交集）：A10-smoke 那格的一致是两个键在三臂上一起缺席，
删掉一臂的键会让闸继续绿。放弃只哈希题名：题内容变了看不见。
放弃把 canonical 期望值留到下一轮：83 个 digest 已在证据里，成本是几行。

## 拿什么证明它生效了

- `python3 test-check-controlled-vars.py`：改一臂 `agent_timeout_multiplier` → 红且点名臂与字段；
  删一臂某个键 → 红且报「键缺失」。
- `python3 test-taskset-fp.py`：同名改 digest → 第三段变；旧两段与新三段兼容。
- `tests/eval/harbor-eval-gates.test.ts`：四条 runner 的代码行含 `source ./taskset-fp.sh`
  与 `taskset_fp_gate`；CI 上跑上述两个 .py（不 skip）。
