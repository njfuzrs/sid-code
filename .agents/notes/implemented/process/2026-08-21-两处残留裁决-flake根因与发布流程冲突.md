# 两处残留裁决：statusline flake 的根因修复 + 发布流程与分支保护冲突定案

## 决定了什么

### ① run-statusline flake：超时改为可注入参数，但验证超时的那条刻意不放宽

`runStatusLine` 新增第 4 个参数 `timeoutMs`，默认 `STATUSLINE_TIMEOUT_MS`。
生产调用方（`useCustomStatusLine.ts:59`）不传，行为完全不变；测试里 8 条中的 7 条传
`TEST_TIMEOUT_MS = 15_000`，**唯独** `超时 → 回退 null` 那条继续走生产默认值。

**这个坑已经踩到第三次**，而前两次的修法都只治了单条用例：

| 时间 | 平台 | 用例 | 当时的修法 |
| --- | --- | --- | --- |
| 2026-08-13 | ubuntu | `node -e` 读 stdin，**1002.91ms 精确撞线** | 换成 `cat` |
| 2026-08-21 | ubuntu | `同指纹 + 窗口内 → 复用缓存` | 重跑 |
| 2026-08-21 | macOS | `脚本 stdout 透传（去尾换行）` | 重跑 |

根因在旧注释里其实已经写明了（`STATUSLINE_TIMEOUT_MS` 是生产常量、测试直接受它约束），
但只换了那一条的命令 —— 于是换个用例、换个平台又复发。
**这些用例验证的不是超时**（是 stdout 透传 / 退出码 / 节流缓存），成败却取决于
runner 负载，与被测行为无关。

另加一条反向断言 `超时用的就是生产常量`：断言 `STATUSLINE_TIMEOUT_MS === 1000`
且小于 `TEST_TIMEOUT_MS`，防止有人日后给那条也塞宽超时、或把默认值调到 UI 会卡顿的量级。

### ② 发布流程 ↔ 分支保护：改文档 + 脚本给能跑通的指引，不开 bypass

CLAUDE.md 标准顺序第 4 步原本是裸 `git push`，而 main 受 ruleset `protect-main` 保护
（PR + `all-checks-passed`），那条命令**必然被 GH013 拒**。撞上时的状态是
「制品已上线 + tag 已推送 + bump 提交还在本地」—— 正是同一份文档上方那条铁律要防的
「已发布但未提交」窗口，只不过成因从人的疏忽变成了门禁冲突。

- CLAUDE.md 第 4 步改为建分支 → PR → `gh pr merge --auto --merge`，第 5 步才是官网发布；
  并写明 GH013 的成因、bypass 的否决理由、squash 陷阱与核验命令、`northstar/` 不是脏数据。
- `release.sh` 收尾处按**实际保护状态**打印能跑通的命令（检测当前在 main 且远端有该分支），
  不再让人照着一条注定失败的指引走。

**新发现一个此前没人记的陷阱**：合并**必须用 merge 不能 squash**。tag 已经打在 bump
提交上，squash 会另造提交、原提交不进 main，于是 tag 指向一个游离提交 ——
`git checkout <tag>` 仍能用，但 `git merge-base --is-ancestor <tag> main` 会失败，
「产物对应确切 commit」这条铁律退化成「对应一个不在主线上的 commit」。
本仓 `allow_squash_merge=true`，所以这个错**随时可能被误点**。

## 放弃了什么（以及为什么不选）

**① 统一放宽所有断言 / 把 sleep 那条也调宽 —— 否决。** `超时 → 回退 null` 是
「坏脚本不卡死 UI」这道保护的**唯一**覆盖，放宽等于把保护测没了。
变异自证证实了这个判断（见下）。

**② 把超时调到 2~3s 就算了 —— 否决。** 那只是降低撞线概率，没有消除它，
而下一次复发依然是一次误导性的红（看着像功能坏了，其实是环境慢）。
目标是「大到与 runner 负载无关」，不是「刚好够用」。

**③ 给 `release.sh` 开 ruleset bypass 让它能直推 —— 否决。** bypass 是给
「人/应用」开的口子而非给某个提交，一旦开了**任何**直推都能绕过汇聚门 ——
而全量 CI 与刚补的 GitHub Release 步骤都挂在那道门上。用它换掉「每次发版一个 PR」
的成本不值。

**④ 只改文档不动脚本 —— 否决。** 铁律那一段自己写着「现在由脚本机械化执行，
不再只靠人记」，而这一环恰恰只靠人记。脚本已经知道自己刚推了 tag，
让它顺手把正确命令打出来是最低成本的机械化。

## 拿什么证明它生效了

**① flake 修复的变异自证**（关键，证的是「保护没被测没」）：
把超时保护废掉（`}, timeoutMs)` → `}, 999_999_999)`，即「坏脚本能卡死 UI」这个真实缺陷），
`超时 → 回退 null` 那条**照样报红**（5016.75ms 后失败，8 pass / 1 fail）；还原后 9 pass / 0 fail。
如果当初选了「统一放宽断言」，这个缺陷会静默溜过 —— 这就是那个选择的真实代价。

**② 流程修复的变异自证**：把 CLAUDE.md 收尾退回裸 `git push` 并删掉说明段，
**3 条断言报红**（收尾步骤 / squash 判据 / northstar 说明）；还原后 53 pass / 0 fail。

**③ 生产行为未变**：`timeoutMs` 有默认值，`useCustomStatusLine.ts:59` 那个唯一的生产
调用点不传（`grep` 确认全仓只有它调 `runStatusLine`），走的还是 1000ms。

**门禁**：全量 **10474 pass / 0 fail**（改了 `release.sh` 触发仓库级判定，130.21s）；
`bun run lint` 无输出；`format:check` 起初红（新写的排版）、`bun run format` 后全绿；
`bash -n scripts/release.sh` OK；`make build` 四项自检全过。
