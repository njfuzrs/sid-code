# 用 `.mailmap` 归并同一人的两个 author 身份，而不是重写历史

## 决定了什么

新增仓库根 `.mailmap` 一行，把
`rushengzhou <272990952+rushengzhou@users.noreply.github.com>`（928 条，本地直接提交）
归并到 `周如生 <rushengzhou3@gmail.com>`（138 条，GitHub 网页端合并 PR 生成）。

两者是同一个人，成因是**两条不同的提交路径**而非配置错误：后者的 committer 一律是
`GitHub <noreply@github.com>`，author 取账号主邮箱。归并方向选 gmail 那个，
因为 `users.noreply.github.com` 是 **GitHub 私有域，任何非 GitHub 平台都无法绑定**，
而 Gitee 的贡献度统计要求 commit 邮箱是本账号已确认绑定的邮箱。

`.mailmap` 只改**读取时的展示**（`git shortlog` / `%aN` / `%aE` / blame），
不改写任何 commit 对象。实测：`git shortlog -sne main` 从 `928 + 138` 变成 `1066` 一行，
而 `main` HEAD 仍是 `7df27f81`、`rev-list --count --all` 仍是 1148。

## 放弃了什么（以及为什么不选）

**方案 A：`git filter-repo` / `filter-branch` 改写全部 1148 个 commit 的 author email。**
这是搜到的教程里的标准答案（也是 Gitee 帮助中心那篇「修改 commit 中的邮箱」给的做法），
也是**唯一能让平台侧贡献者列表真正合并的办法**。否决，理由按代价排序：

1. **已发布的二进制把 40 位 commit SHA 编进了字节里**（`packages/shared/src/build-info.ts`，
   实测线上产物含 `SIDCODE_BUILD_V1|commit=320be42b...`）。重写历史 = 所有已发布产物的
   身份判据当场失效，而 `scripts/lib/artifact-identity.ts` 与
   `tests/release-flow-contract.test.ts` 都以它为判据。
2. **22 个 tag 全部要重打**，且 `git merge-base --is-ancestor v<ver> main` 这条发布铁律
   的核验对象会全部换掉（`release.sh --promote` 依赖它）。
3. 本地这份 `.git` 目前是**唯一完整事实源**（GitHub 账号封停、仓库匿名 404），
   重写历史是不可逆操作，此刻做它风险与收益完全不成比例。

**方案 B：把两个邮箱都绑到 Gitee 账号上，让平台自己合并。**
Gitee 官方博客明确说「绑定多个邮箱后，通过不同邮箱提交代码产生的贡献值会统一纳入贡献度统计」——
听起来正好。但 ① 那个域名是 GitHub 私有域，**绑不上**，所以这条对 928 条提交无效。
（对 `rushengzhou3@gmail.com` 那 138 条有效，值得单独去绑。）

**因此这个 Note 的诚实结论是：平台网页上的两条身份，`.mailmap` 消不掉。**
Gitee / GitHub 的贡献者列表不读 `.mailmap`，它们按 commit 里的 author email 自行归并。
`.mailmap` 修好的是**本地与所有读 git 的工具链**这一侧。不要把它宣传成修好了平台展示。

## 拿什么证明它生效了

```
$ git shortlog -sne main | head -3
   1066  周如生 <rushengzhou3@gmail.com>          ← 归并前是 928 + 138 两行
     13  dependabot[bot] <...>
      1  tyli_official <...>

$ git rev-parse main
7df27f819ea6d4e7fa21c65f50330fbf978efedf         ← 与归并前逐字节相同

$ git rev-list --count --all
1148                                              ← 未变
```

**反向确认改动没有溢出**：`scripts/generate-changelog.ts` 与
`scripts/lib/changelog-git.ts` 的取数格式实测只有 `%h` / `%s` / `%b` / `%ai`，
**不含任何作者字段**，所以 changelog 产物不受影响（`git log --first-parent --pretty=format:'%h|%s'`
三条输出与改动前一致）。

**已知未验证**：Gitee 网页贡献者列表是否真的不读 `.mailmap` —— 这一条来自
「平台按 author email 归并」的公开说明与本仓无法自证，**要等推送后看页面才算实测**。
在此之前不要声称平台侧已修好。
