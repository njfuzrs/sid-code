# 官网「跑通第一个任务」等 3 页与代码事实核对，修正 8 处表述

## 决定了什么

对 `website/start/first-task.md`（官网入门第一篇）逐句对照当前源码核对，修正 6 处与代码行为不符的表述；
其中「会话摘要打印时机」这一事实错误同时存在于 `website/use/cost.md`、`website/team/quota.md`，
三处一并改齐，共 8 处。清单与依据（源码行号为改动时的行号）：

1. **摘要打印时机**：「任务结束会打印一份会话摘要」→「退出 sid-code 时（`Ctrl+C` 两次 / `Ctrl+D` / `/exit`）会打印」。
   `getSummary()` 全仓只有两个调用点、都在退出路径：TUI 退出 `packages/cli/src/app.ts:10833`、
   headless 退出 `app.ts:7803`——每轮任务结束并不打印。`first-task.md` 的标题同步改
   「结束时的那份摘要」→「退出时的那份摘要」；`use/cost.md:42`、`team/quota.md:236` 的同源表述一并修正。
2. **「按 `n` 拒掉」的时序**：「按 `n` 拒掉」→「按 `Esc` 打断，或在它下一次请求权限时按 `n` 拒掉」。
   `n` 只在权限确认框（工具执行**前**）有效（`packages/cli/src/ui/components/DialogManager.tsx:143-147`），
   而 diff 是执行**后**的结果展示——看到超范围 diff 时那个框早已关闭，按 `n` 没有对象。
3. **双击 Esc 的回退前提**：「连按两次 Esc 走的是回退」补「空闲时」。escape-escape 只在空闲态
   打开回退选择器（`packages/cli/src/ui/App.tsx:1078-1101`），忙时第一个 Esc 已被中断 handler 消费。
   措辞与 `website/use/interactive.md` 的「空闲时打开回退选择器」对齐。
4. **`acceptEdits` 的白名单**：「自动接受文件修改，但跑命令仍然问」补全为「工作目录内的
   `mkdir` / `touch` / `cp` / `sed` 等文件操作也放行；其余命令仍然问」
   （`packages/core/src/permission/checker.ts:273`、`:1256-1274`；`rm` / `rmdir` / `mv` 始终不放行）。
5. **正文里混入的编辑注**：删除文末「（同上，不写个数）」——它是 `first-task.md` 里
   写给维护者的 HTML 注释约束，不该出现在读者可见的正文中。
6. **HTML 注释里的源码路径**：`src/permission/mode.ts` 补全为 `packages/core/src/permission/mode.ts`
   （同注释里「八种」本身是对的——`packages/core/src/permission/mode.ts:7-15` 恰为 8 种）。

## 放弃了什么（以及为什么不选）

- **不改代码去迎合文档**：8 处全部是文档描述偏差，行为本身是设计意图（忙时 Esc 中断、
  权限框先于执行、acceptEdits 白名单可枚举）；修正方向统一为「文档对齐代码」，不动实现。
- **「摘要时机」三处拆成多个 PR**：同一事实若只改一处，站内会留下「此处说退出时、彼处说任务结束」
  的自相矛盾；按关注点合到一个 PR（首任务页为主，连带两处同源修正）。
- **在入门页展开完整判定细节**（如 acceptEdits 白名单还要求「路径参数都在 cwd 内」、
  双击 Esc 的完整前置「无弹窗、非流式、非工具执行」）：入门页只给「能记住的结论」，
  完整条件留在权限页 / 键位页。
- **给这类手写页造自动反漂移门禁**：官网手写页的事实正确性无法像 `website/ref/` 那样
  由源码生成器机械校验，本次靠人工逐句核对；单次发现量（3 个文件 8 处）不足以论证门禁成本。
