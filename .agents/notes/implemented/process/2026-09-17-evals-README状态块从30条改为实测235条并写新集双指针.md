# `evals/README.md` 状态块从"30 条"改成实测数，并写上新题集的两个 URL

## 决定了什么

只改 `evals/README.md` 一个文件（`git status --porcelain` 全程只有这一行 `M`），落四件事：

1. **状态块换成 2026-09-17 的实测数并逐格可复算**。旧块停在 2026-05-25 的
   `p0-core 10 + p1-common 9 + p2-edge 6 + holdout 5 = 30 条`，磁盘上是四组 **222** + holdout **13** = **235**。
   ⚠️ **同口径比要连 holdout 一起算**：旧值 30 是**含** holdout 的，所以差是 **205**，
   ⛔ 不是「222 − 30 = 192」—— 那是拿"不含 holdout"减"含 holdout"。表里因此写了三行
   （四组小计 222 / holdout 13 / 含 holdout 235），并显式标注"222 不含 holdout"。
2. **写新题集的两个 URL，⛔ 不是二选一**：GitHub `njfuzrs/agent-traj-bench`（题集本体，`tasks/` 39 个题目录）
   + HF dataset 同名（快照仓，`tasks.jsonl` / `snapshots.jsonl` 不入 git）。只写一个读者拿不到另一半。
   并写明**两边判据不兼容、分数不互比**（过程评测 vs 结果评测，0–5 分制 vs `pass@1`）。
3. **删掉三处过期技术描述**：`eval-runner.ts` / `eval-judge.ts` / `_types.ts` 早已迁到
   `packages/eval-framework/core/{runner,judge,types}.ts`，`evals/` 根下零命中。
   目录树整个重画成入库快照（**681** 个文件，各目录数字两侧闭合：675 + 顶层 6 = 681）。
4. **顺带修了三处同类失效**（同一个文件、同一个"README 数字与磁盘不符"的关注点）：
   `跑评测` 那句「25 条非 holdout」实测 `eval:run` 扫 **168** 条；
   `目录边界` 那节「25 个 `.ts`」实测 **29**、「6 处测试 import」实测 **11 个文件 / 12 条路径**；
   `出处索引` 里 4 个 `docs/eval/*` 路径**不在本仓**（维护者私有库），改成标注在不在仓内而非删除。

**措辞纪律**（三条都实测过，写进正文）：`capability/` 那格写
`frozen → 待删除`，⛔ 不写 `pending-review`（03 号方案用过这个词，实测挂了三个半月没落点）；
`capability/` 的死因写"**死于实现，不死于不可重建**"（`seed`/`env`/`repo_commit` 实测全 0，
54 条里只有 7 条断言真腐烂、45 条仍可跑）⇒ ⛔ 不许写成"因断言腐烂而删"；
`real-tasks` 写「31/31 的 `REPO_URL` 是假值（30 条 TODO 占位 + 1 条 example.com）」，
⛔ 不照抄上游的「31/31 是 TODO 占位」—— 那句会被复算推翻。

  的一项，$0、零风险、完全可逆，不该被 PR2–PR3d 的删除动作拖住。

  删掉等于抹掉设计决策的唯一溯源线索」⇒ 改成在表里标 `❌ 仓外` 并说明为什么点不开。

## 拿什么证明它生效了

**判据不是"README 改了"，是"块里每个数字都能一行命令复算，且与磁盘一致"。** 逐条实跑：

```
$ for d in general architecture capability real-tasks holdout; do
    printf "%-14s %s\n" "$d" "$(git ls-files "evals/$d" | grep -c '\.yaml$')"; done
general        28      architecture   113     capability     54
real-tasks     27      holdout        13              ← 与状态块逐格相等
$ git ls-files evals | wc -l                                    → 681   ← 树的标题数
$ git ls-files evals | awk -F/ 'NF==2' | wc -l                   → 6     ← 顶层文件
  目录合计 675 + 顶层 6 = 681                                            ← 树两侧闭合
$ grep -rl "lifecycle:" evals/ --include="*.yaml" | wc -l        → 0     ← 未假称已冻结
$ grep -rho 'REPO_URL=.*' evals/real-tasks/ | sort | uniq -c
  30 REPO_URL="# TODO: fill repo_url for unknown"
   1 REPO_URL="https://github.com/example/repo.git"                      ← 30+1 而非 31/31
$ git ls-files evals/general evals/architecture evals/real-tasks | grep -c '\.yaml$'
  168                                    ← eval:run 实际扫到的（capability 不在 CASE_DIRS）
$ git ls-files evals | grep -c '\.ts$'                           → 29    ← 旧值 25
$ grep -rlE 'from "(\.\./)+evals/' --include='*.ts' tests/ packages/ | wc -l → 11  ← 旧值 6
$ git ls-files evals | grep -c '\.yaml$'                         → 486（含 _scores 等，非 case 口径）
```
