# 官网 LSP 文档按源码事实校准

## 决定了什么

校准 `website/extend/lsp.md` 与当前实现不符或范围含混的内容：将无法工作的 `-p` 快速示例改为交互式流程；把参数名改成工具 schema 中的 `file_path`；修正诊断注入示例中 Hint 被过滤的事实；说明 `/lsp reload`、language server 懒启动、配置整条覆盖、codeAction 只读语义、无头命令边界，以及结果截断和 `.gitignore` 过滤的具体范围。同步更新页面 description，并生成 `website/public/llms.txt` 的新摘要。

另在仓外 `docs-research/sid-code/bugfixes/todo/20261021-LSP诊断重载后快照残留-官网核查发现的代码缺陷.md` 记录一项确认的代码缺陷：编辑后 `clearForFile()` 未清除 `latest` 快照，导致 `codeAction` 在收到新诊断前仍可能使用编辑前诊断。本 PR 不改该实现。

## 放弃了什么（以及为什么不选）

不在本次官网文档 PR 中修改 LSP 实现、测试或 CLI 行为。诊断快照缺陷会让修复范围跨入注册表生命周期和 codeAction 请求时序，应作为独立 bug-fix 评估与验证；本次把它单独写入指定 todo 文档，不将行为改动和文档校准混在一起。

不把所有具体 language server 的输出宣称为跨服务器保证；保留真实 TypeScript 示例，并明确引用位置、符号层级和 codeAction 都取决于 server 响应。也不声称启动探测零开销：本机以隔离 PATH 和 10ms 探测替身测得 10 个内置命令探测耗时约 211ms，事件循环定时器延迟同为约 211ms；该数值只用于证明同步探测会阻塞，不代表所有机器的固定启动时间。
