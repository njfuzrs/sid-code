# /perf --by-version 的三处改动补上回归测试，数据靠合成索引行造而不是等真实样本

## 决定了什么

PR-B（#783）的 `--by-version` 视图有三处改动只有实现、没有任何断言：

- **D14**：非窄终端补「生成 P95」「工具/会话 P50」两列（`render.ts:558`）
- **D12**：`incomplete` 占比 > 30% 的版本加一行脚注（`perf-report.ts:657` 的 `VERSION_INCOMPLETE_NOTE_RATIO` + `render.ts:586-593`）
- **A8**：有旧口径行的版本被点名「含旧口径会话，不可直接比」（`render.ts:600-605`）

原方案 5.2 的 T-B1…T-B11 覆盖的全是**会话视图**，5.3 第 6 步对 `--by-version` 只要求一次人工端到端，而 PR #783 正文里那次取证也没留输出。也就是说这三处坏了不会有任何东西变红。

本次在 `packages/cli/tests/command/perf-panel.test.ts` 补 7 个用例，用**合成的 `session-index.jsonl` 行**（新增 `idxRow()` 助手）走 `buildByVersion` → `renderByVersion` 全链路：

- D14 三条：非窄终端出两列且值取自 `gen_p95` / `tool_duration_ms`；窄终端省略；整列无样本给「—」并说明「不是 0」
- D12 两条：50% 出脚注并报出分子分母、25% 不出；`incomplete` 行不计入 `sessions`（被 `settled()` 剔除）
- A8 一条：有旧口径行时点名版本，全 `perf_scope: "main"` 时不出现

顺带把 `website/use/performance.md:98` 口径表里的「首字延迟 TTFT」改成「首字 TTFT」，与面板 `render.ts:304` 的叫法统一——原方案 5.2 的 ⚠️ 要求这个文件「一起改」，PR-B 只改了面板示例那一处。

## 放弃了什么（以及为什么不选）

**等真实数据攒出触发条件**：没选。D12 的判据是「某版本 incomplete 占比 > 30%」——本机 1525 行索引里确实有 4 个版本满足（0.1.607–0.1.610），但这只是当前机器的历史遗留，早期写入缺陷修掉之后新版本不会再产生这种比例。把回归测试建在「碰巧攒够畸形数据」上，等于让它随时间自然失效：真实数据一旦干净，测试要么永远绿得没有意义，要么直接跳过。这三项判据都是**开关型**的（出没出两列、加没加脚注），合成数据完全够表达。

**放到 `perf-report.test.ts`（core 侧）**：没选。D14/D12/A8 的判据都在**渲染**上（列标题、脚注文案），`buildByVersion` 只负责算数。放 core 只能断言 `incompleteSessions` 的值，断言不到「有没有那一行字」。现有 `perf-report.test.ts` 的 `buildByVersion` 用例（`:157`）正是这个层次，保留它，新增的渲染断言放 cli 侧。

**给 `--by-version` 补一张整帧快照**：没选。`renderByVersion` 的输出宽度随版本数增长，快照会随任意一个真实版本落地就失效，维护成本高于收益；断言关键字符串已经把三处判据锁住了。

## 拿什么证明它生效了

**三项变异自证**（改坏被测代码 → 对应断言变红 → 用备份恢复）：

```text
变异 1  render.ts:558  if (!narrow) → if (false)
        → (fail) D14 > 非窄终端出这两列        2 pass / 1 fail
变异 2  perf-report.ts:657  VERSION_INCOMPLETE_NOTE_RATIO = 0.3 → 0.99
        → (fail) D12 > 50% 出脚注且报出分子分母  1 pass / 1 fail
变异 3  render.ts:604  旧口径提示整段去掉
        → (fail) A8 > 有旧口径行时点名版本       0 pass / 1 fail
```

恢复后 `git diff --stat` 只剩测试文件，两个被测源码文件零改动。

**新增用例全绿**：

```text
bun test ./packages/cli/tests/command/perf-panel.test.ts
  → 39 pass / 0 fail（原 32 + 新增 7），1 snapshot, 133 expect()
```
