# 会话级回放门禁：多轮请求前缀逐字节稳定 + 整会话计费恒等（评测接入 CI/CD 方案 P1）

## 决定了什么

- 新增 `packages/core/tests/llm/vcr/session-replay.test.ts`，配套 `session-harness.ts` 与 `tests/fixtures/vcr/sessions/` 两份会话夹具（Anthropic 族 6 主轮、OpenAI 族 5 主轮，**都含一次 2 轮的子代理调用**）。
  跑的是真实 `queryLoop` + 真实 `AnthropicProvider` / `OpenAIProvider` + 真实 `SubAgentTool` + 生产计费 sink，只替换最底层 `fetch`。
- 请求在 **fetch 边界**（provider 序列化之后）捕获，按 host 分主循环 / 子代理两条回放队列。不带工具的请求判为辅助调用，不消耗夹具轮次。断言五组：
  ① system 稳定段跨轮字节相同，且两个不同时刻启动的会话也相同；② 工具定义跨轮字节相同且按字典序；
  ③ 第 k 轮消息历史是第 k−1 轮的前缀，合法改写枚举成白名单 W1–W3（reminder 注入 / OpenAI 族动态区后置 / cache_control 漂移），白名单外一律判红；
  ④ Anthropic 族每个请求 cache_control ≤ 4；⑤ 整会话 token 与成本 = 夹具逐轮 usage 之和（含子代理）。
- 子代理 usage sink 从 `cli/src/app.ts` 私有方法下沉为 `core/src/agent/usage-sink.ts`（逐行搬迁，行为不变），否则测试只能复制一份，对「生产那份被注释掉」无感。
- 新增 `scripts/vcr-session-record.ts`：把真实 raw.jsonl 转成会话夹具。只留 response 的 text/tool_use 与 usage，丢弃请求侧与 thinking，并脱敏密钥、内网 IP、home 路径和邮箱。测试见 `tests/scripts/vcr-session-record.test.ts`。

## 放弃了什么（以及为什么不选）

- **从 raw.jsonl 读每轮请求做断言**：只有 index=1 带完整 messages/system/tools，后续是增量；而且 cache_control 打标、动态区后置都发生在 provider 内部，SendParams 层看不到。
- **用 ReplayProvider 驱动**：它替掉的正是要被测的 provider 序列化层。
- **直接入库真实会话**：raw.jsonl 分不出哪一行是子代理发的，请求侧又带内网地址、项目规则、记忆。本次入库的两份夹具是**按真实会话形状手工构造**的，录制脚本已就位，可以后续替换或追加真实录制。这一点与方案原文「录真实会话」有偏差，如实记录。
- **断言 `cache_read` 的实际值**：那是服务端行为，不确定，属于 L1/L2 附带指标，不进 L0。

## 拿什么证明它生效了

变异自证（evals/CLAUDE.md §4），每种破坏都跑 `bun test packages/core/tests/llm/vcr/session-replay.test.ts`：

| 变异 | 变红的用例 |
| --- | --- |
| M1 `system-prompt.ts` 稳定段末尾拼 `new Date().toISOString()` | ① × 2 族 |
| M2 `registry.ts` `toDefinitions` 返回 `defs.reverse()` | ② × 2 族 |
| M3 `anthropic.ts` 给每条消息首块多打 cache_control | 非生产：`assertCacheBreakpointBudget` 抛错，Anthropic 族 6 条全红；`NODE_ENV=production` 下护栏只打日志，④ 单独变红 |
| M4 `usage-sink.ts` 注释掉 `updateUsage` | ⑤ × 2 族 |

恢复后 12/12 全绿。整个 `tests/llm/vcr/` 目录 44 条用例 0.27s，远低于方案要求的 < 10s 增量。不依赖任何 secret 和网络（fetch 全替换；Anthropic 显式给 baseURL，以免本机的 `ANTHROPIC_BASE_URL` 让请求绕过 shim，这个坑实测踩过）。
