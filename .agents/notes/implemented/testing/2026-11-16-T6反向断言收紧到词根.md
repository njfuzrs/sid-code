# T6 反向断言从「一种长句」收紧到词根，让被否掉的第二条真的加不回来

## 决定了什么

`packages/core/tests/agent/subagent-result-synthesis.test.ts` 的反向断言由
`expect(guide).not.toContain("动手修改前先自己读")` 改为 `expect(guide).not.toContain("先自己读")`，
并补一条同向对照 `expect(guide).toContain("由你自己综合")`（防止 guide 取到空串而恒绿）。

起因是复核 T6 落地时做的变异实测：把方案原文措辞「引用子代理给的 `文件:行号` 做修改前，
先自己读那一处」加回 `usageGuide()`，**旧断言 4 pass / 0 fail 存活**——它拦的是「动手修改前
先自己读」，而方案与 Agent Note 里被否掉的第二条从头到尾没出现过这个短语。这条门禁此前
只在防一个不存在的写法。

## 放弃了什么（以及为什么不选）

- **保留长句断言、在测试注释里注明覆盖范围**：注释不执行，回退照样绿。测试名写的是
  「不包含被抽样否掉的第二条」，名实不符本身就是隐患。
- **改成正则同时匹配多种句式**（如 `/先(自己)?读(一遍|那一处)?/`）：过拟合到当前能想到的
  改写形态，下一个措辞又漏。取词根「先自己读」覆盖「先自己读那一处 / 先自己读一遍」等
  同义改写，且 `usageGuide()` 的返回值里当前不含该串（全文件唯一命中在 `tool.ts:417`，
  是代码注释，不进返回值），不会误伤。
- **连「引用子代理给的文件:行号」一起断言**：那条短语在方案原文里也出现在合法的
  `usageGuide()` 文案之外，容易误命中；词根更稳。

## 拿什么证明它生效了

变异自证（先改坏被测代码，确认断言变红，再恢复）：

```
# 探针：在 usageGuide() 的「嵌套限制」之前插入方案原文措辞
$ bun test ./packages/core/tests/agent/subagent-result-synthesis.test.ts
error: expect(received).not.toContain(expected)
Expected to not contain: "先自己读"
(fail) 不包含被抽样否掉的「先自己读那一处」第二条（避免重复喂 read 预算）
 3 pass
 1 fail

# 移除探针后
$ bun test ./packages/core/tests/agent/subagent-result-synthesis.test.ts
 4 pass
 0 fail
```

同一探针下旧断言是绿的（本 Note 第一段记录的 4 pass / 0 fail），所以这次收紧把一条空门禁
变成了真门禁，不是换个写法。
