# G1 变异抽样 20 例：18 例 killed，2 例空心，本 PR 补实

## 决定了什么

从 `packages/core/tests/{query,tool,permission,hook}/` 抽了 20 个用例（总体 3187 例，固定种子 20261107 的 mulberry32 随机抽样，不挑不换）。对每例，按**用例名**声称的行为改坏实现，看用例是否变红：18 例 killed，2 例 survived（各试了两种不同的改坏都没红），存活率 10%。

两例都按「改测试、不改实现」修，因为实现是对的，是测试没守住：

1. `packages/core/tests/tool/shell-snapshot.test.ts`「POSIX 平台：用真实 shell 创建快照文件」：断言全部包在 `if (result)` 里，创建失败返回 undefined 时一条断言都不跑，照样绿。改成先断言 `result` 是字符串，再查文件内容。「降级返回 undefined」的语义，由同文件「不存在的 shell 路径 → 降级 undefined」单独守护。
2. `packages/core/tests/permission/allow-list-pipeline-filter.test.ts`「过滤器在首段：不算过滤器」：输入 `tail -5 /etc/passwd` 带文件操作数，`isPipelineFilterStage` 本身就返回 false，根本走不到 `checker.ts` 的位置判定 `s > 0`。原用例保留不动，新增一条：首段 `tail -5`（先断言它确实是纯过滤器形态），必须被拒。

## 放弃了什么（以及为什么不选）

- **在 shell-snapshot 用例里把 `if (result)` 改成 `if (!result) return`**：形态不同，问题相同，一样是静默跳过。
- **改原用例的输入，而不是新增一条**：原用例守的是「带文件操作数的首段不被当过滤器」，这条行为也成立，删掉就丢了覆盖。新增一条专门守位置规则，两条各管一件事。
- **静态扫描弱匹配器来找空心测试**：专项早期试过（`toBeDefined` / `not.toBeNull` 计数），会冤枉好测试（`bash-security.ts` 约定 null = 未命中，所以 `not.toBeNull()` 正是「命中」断言），也会放过这次这两类坏测试（它们用的都是强匹配器）。只认变异。

## 拿什么证明它生效了

修复后，用当初让它们存活的那几种改坏逐一复验，全部变红，还原后通过：

- shell-snapshot ① `createAndSaveSnapshot` 开头直接 `return undefined` → 0 pass / 1 fail
- shell-snapshot ② `execFile(shellPath, …)` → `execFile("/nonexistent-shell", …)` → 0 pass / 1 fail
- pipeline ① `s > 0 && isPipelineFilterStage(stage)` → 去掉 `s > 0` → 0 pass / 1 fail
- pipeline ② → `(s > 0 || p === 0) && …`（首个管道放行首段）→ 0 pass / 1 fail
- 还原后两个文件 113 pass / 0 fail；`git status -- packages/*/src` 为空。

其余 18 例的改坏方式与结果逐条记录在专项台账 §五（私有文档库「质量防线分层专项」），这里不重复。值得一提的是 #15（`stall-escalation`）：后台 shell 运行时不升 L2 有两道冗余保护，只拆一道用例不红，两道都拆才红。这属于纵深防御，不是空心测试。
