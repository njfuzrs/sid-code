# Harbor 跑前闸 0 与闸 1：跑的是不是那个包 + 链路够不够快

## 决定了什么

两道跑前闸，都是"评测跑完了、有分数、但那分数没有意义"这一类的防线。

### 闸 1：uv 下载速率（原来**只是一段注释**）

§21.9 交接写着「跑前那两道闸**脚本会自己跑**」——**那句话不准**：
自动跑的只有闸 2（上游错误率），闸 1 一直只是文件头的注释。
本棒开跑前手动探它，第一次拿到 **38KB/s**（判据 ≥500KB/s）——
比 2026-08-29 烧掉 $3.12 那次的 70KB/s **还差**，30s 只下到 1.15MB/17.8MB。
那次的形态是 verifier 在 103/243/413s 后放弃、reward 全写 0，
而 `sid_subtype` 照样 `success` —— 一轮"绿着坏掉"的假数据。

现在 `preflight_uv_speed()` 真的会跑，**在容器内探**（verifier 是在容器里下 uv 的），
且**拦**（与闸 0 不同）：没有任何正当理由在 70KB/s 上开跑，那只会产出假数据。

### 闸 0：二进制新鲜度

给 `evals/external-benchmarks/harbor/run-permission-switch.sh` 加**闸 0**
（`preflight_binary_freshness`），在闸 2（上游错误率）之前跑：
把 `SID_HARBOR_BINARY_ARM64/_X64` 点名的产物里**内联的 40 位 commit** 与当前 HEAD 比，
落后就告警并打出重编命令。

三个设计决定：

1. **判据取产物字节，不取文件名**。走仓库既有的 `scripts/artifact-identity.ts`
   （与 `sid_code_agent.py::_write_build_info` 同一口径，不另写嗅探正则）。
   路径里那串 `sid-code-x64-<commit12>` 是人写的、会撒谎；字节不会。
2. **只告警不拦**。故意跑旧版做 A/B 是正当用法（本棒就用它做了前后对照），
   拦死会把正当用法变成必须绕过的门，而"学会绕过一道门"之后那道门就永久失效了。
3. **未点名时明说"本闸未生效"**，不报绿。见下方证据第 4 条。

## 放弃了什么（以及为什么不选）

- **放弃"让脚本自己 rebuild + 改写那两行"**。发布路径同型铁律：评测跑前闸必须
  确定性、只读、可离线复算。让闸自己动构建产物，一次失败的重编会把
  「上游健康检查」变成「构建系统故障」，且此刻已经无法区分两者。
- **放弃"硬拦（exit 1）"**。理由见上方第 2 条。
- **放弃只在 README 写一段"记得重编"**。这条已经以注释形式写在那两行上方
  （`⚠️ 必须指向当前 HEAD 编出来的包`），而本棒**照样差点踩下去** ——
  一条只靠人记得看的注释，在忘记看的那一次恰好是最需要它的那一次。
- **放弃比对 `binary_sha256`**。sha 只能答"是不是同一个文件"，答不出
  "落后几个提交、要不要紧"，而后者才是人要做的判断。

## 拿什么证明它生效了

### 闸 1（3 个方向，都真跑）

1. **正向**：真实链路 → `✅ 1900805B/s ≥ 500000B/s`，rc=0。
2. **慢链路**（把阈值调到 99MB/s 模拟）→ `⛔ … < …`，rc=1，文案指向"等链路恢复"。
3. **探针连不上**（URL 打死）→ **第一版报 `⛔ 0B/s < 500000B/s` 并说"等链路恢复再跑"**
   —— 那是**归因错误**：真相是探针没连上（URL 变了 / 容器无外网 / DNS），
   下一步动作是查网络而不是等。改为速率与 `http_code` 一起取后，现在报
   `⛔ 探针未取到文件(http=000)——**这不是「链路慢」**`。
   （错误归因比没有归因更坏，本仓反复记的教训；它虽然两版都 rc=1 拦住了，
   但拦住不等于说对了。）

### 闸 0（5 个方向）

四个方向的变异自证（把函数抽到 `/tmp/gate0-run.sh` 单跑，不干扰在跑的 r5）：

1. **正向**：指向 HEAD 产物 → `✅ 已点名的 2 个产物都与 HEAD 对齐`。
2. **陈旧**（本棒真实撞到的那一形态）：指回脚本原本写死的
   `sid-code-{arm64,x64}-7f437eb84e7a` →
   `⛔ 是**陈旧产物**:7f437eb84e7a 落后 HEAD(30586ff003c9) 22 个提交` + 重编命令。
   这就是它要拦的事：HEAD 含 P1-1 入账修复而那两行指着修复前的包，
   照跑那一次 $7 会拿到「三个数仍是 41/40/40」→ 误判成「②那条修复是错的」。
3. **文件不存在** → `⛔ 指向的文件不存在`（不静默跳过）。
4. **一个变量都不设** → **第一版报了
   `✅ 两个架构的产物都与 HEAD 对齐`，它一个文件都没读却报绿** ——
   这是变异 ④ 揪出的、我自己写的 bug（§21.5-1 同型：假绿比不做更坏）。
   改为 `checked` 计数后现在打 `⚠️ 未点名任何 SID_HARBOR_BINARY_*(本闸未生效)`。
5. **无内联身份的文件** → `⚠️ 读不出内联 commit——无法判新鲜度`（不冒充强判据）。

五道门禁：`affected-tests:run` **680 pass / 0 fail**、`make build`（含产物自检 4 项）、
`lint`、`format:check`、`lint:boundary` 全绿。

⚠️ **本 Note 的边界**：闸 0 拦的是「跑的是不是你以为的那个包」，
拦不了「这个包里的改动对不对」。后者要靠端到端判据（见同日 §22 的 A/B 记录）。
