# 启动门禁的首帧阈值在 macOS 上放宽到 300ms，ubuntu / 本机保持 150ms

`packages/cli/tests/startup/large-data-startup-gate.test.ts`。起因：同一天上一份 note
[《启动门禁的差值改成逐轮配对》](./2026-11-04-启动门禁差值改逐轮配对.md) 修完口径后，
macOS 上**仍然**继续红，且有一轮只超 0.7ms。

## 决定了什么

**1. 首帧差值阈值按平台分档：`darwin` → 300ms，其他 → 150ms**

抽出 `frameDeltaLimitMs(platform)` 纯函数 + `FRAME_DELTA_LIMIT_MS` 常量，两处断言
（「首帧」与「补传 U1–U4」的 Δframe）都用它。**事件循环阻塞的 100ms 阈值未动** ——
这次只处置首帧这条噪声最大的断言。

**2. 失败消息与测试名带上实际生效的阈值**

`逐轮 Δframe=[a / b / c]（中位数 Xms，阈值 Yms）`。原先名字里写死「不超过 150ms」，
分档后会在 macOS 上产生「测试名叫 150、实际判定 300」的谎报。

**3. 补一条分档本身的防漂移断言**

`frameDeltaLimitMs("darwin") === 300`、`"linux"/"win32" === 150`、常量与
`process.platform` 一致。没有这条，把两档写成同一个数字（或把 `"darwin"` 拼错）时，
macOS 会悄悄退回 150ms —— 而性能断言在噪声没冒头的那几次仍然全绿，退化看不见。

## 放弃了什么（以及为什么不选）

**这一节要正面回答上一份 note 的否决策略，因为那次明确否决过「抬阈值」。**

上一份 note 写的是：「把阈值抬到 250/300ms：能让 macOS 立刻变绿，但会把 +200ms 级的真实回归
一起放过去。假红的根因是口径，不是阈值太小——只调阈值等于把问题盖住。」

那个判断在**当时**成立，但今天的新证据把它推翻了：**口径修完之后它还在红**，而且红在阈值边缘。
同一小时内同一份 main 代码的实测：

```text
run 41787902045   逐轮 Δframe=[343 / -85 / 671]  中位数 343.3ms
run 41791475745   逐轮 Δframe=[156.7 / ...]       中位数 156.7ms
run 41791475745 第二次重跑  逐轮 Δframe=[151 / 31 / 214]  中位数 150.7ms（超 0.7ms）
同批绝对值：空目录 first_frame 624 / 667 / 772 —— 分母自己就波动 148ms
```

分母（空目录）自带 ~150ms 抖动，而判据阈值正是 150ms —— 此时「中位数压噪声」已经没有余量，
绿/红由运气决定。所以这次的结论不是「改口径」，而是承认 **macOS 共享 runner 上这条指标的信噪比
本身不足**。main 上近 40 次 CI 的 12 次 failure 里至少 5 次是这条，PR #575 / #578 / #579 各踩过
（#578 连续红两次才过），代价已经从「偶发」变成「每次改动的固定税」。

其余否决掉的候选：

- **采样 3 轮 → 6 轮**：只减小方差，不改中心。实测中位数已经稳定压在 150 附近（150.7 / 151），
  加轮次解决不了系统性偏移，而测试时长翻倍（约 35s → 70s+，每轮 3 次启动）。
- **macOS 上整条跳过差值断言**：最彻底，但 macOS 恰恰是首帧更容易被放大的平台（见上一份 note 的
  同一否决）。且变异 T1/T2 +353ms、C1 +698ms 在 300ms 下仍能检出，没必要放弃整个平台。
- **改用 p25 / 最小值**：稳定回归只要有一轮侥幸快就漏；而且它改的是「统计量语义」，比换一个
  明确的平台阈值更难向后来者解释。
- **顺手把 Δblock 也分档**：它今天红过（PR #575 的 Δblock 150ms 超 100ms），但样本量不足以标定
  macOS 上的新阈值。这次只动证据最足的一条，避免用一次失败顺手改两道门禁。

## 拿什么证明它生效了

**分档断言的变异自证**（改坏 → 断言变红 → 恢复）：把 `frameDeltaLimitMs` 的
`platform === "darwin" ? 300 : 150` 改成 `platform === "darwin" ? 150 : 150`：

```text
$ bun test ./packages/cli/tests/startup/large-data-startup-gate.test.ts
(fail) 首帧阈值确实按平台分档（macOS 300 / 其他 150）  Expected: 300  Received: 150
 7 pass / 1 fail
恢复后 8 pass / 0 fail
```

**本机实测（macOS，`process.platform === "darwin"` → 生效阈值 300ms）**：

```text
[gate] 每轮配对差值：轮0 大−空 19/0  轮1 大−空 565/20  轮2 大−空 128/-3
[gate] upload 逐轮 Δframe=[109 / -99 / 175] Δblock=[102 / -23 / 14]
8 pass / 0 fail
```

注意轮 1 出现了 565ms 的单轮离群 —— 本机也有，只是这次被中位数（128ms）吸收了。这条数据同时
说明「本机稳过」不等于「门禁松」：中位数没被那一轮带偏。

**没有证明的（局限，如实写）**：

- 300ms 在 macOS 上会不会**仍然**偶尔红，需要靠后续 CI 的真实分布回答。已知最坏的一次离群是
  343ms（run 41787902045）。如果按平台分档后仍出现 macOS 红，下一个动作是取更大样本重新标定
  macOS 档位，而不是继续上调。
- macOS 上 150–300ms 的真实回归会**漏检**。这是主动放弃的灵敏度，换的是「判定不再由噪声决定」。
