# 启动门禁的差值改成逐轮配对，测量顺序三轮轮转

`packages/cli/tests/startup/large-data-startup-gate.test.ts`。起因：2026-11-04 PR #568 与 main `4ac97563`
在 macOS runner 上先后假红同一条门禁（首帧差值 192.9ms / 156ms，阈值 150ms）。

## 决定了什么

**1. 差值口径：两组各自的中位数相减 → 逐轮配对差值的中位数**

新增 `pairedDelta(runs, which, probe)`：同一轮内「被测配置 − 空目录」，再对这 3 个差值取中位数。
原来的 `firstFrame(large) - firstFrame(empty)` 拿的是空目录 3 轮中位数与大目录 3 轮中位数相减，
**两个数来自不同的轮次**，轮间整机漂移（机器变慢、邻居抢 CPU）直接进了差值。

**2. 每轮启动顺序改成三轮轮转**

`ROUND_ORDER`：轮 0 空→大→传、轮 1 大→传→空、轮 2 传→空→大。三种配置在「先测 / 中测 / 后测」
三个位置上各坐一次，轮内位置偏差在轮转中被抵消。原来固定「空→大→传」，大目录永远吃
「同一轮内越晚测越慢」的亏。

**3. 阈值一个都没动**

首帧 150ms、事件循环阻塞 100ms 保持原值。这次只换测量口径，不调灵敏度。

**4. 失败信息与日志改为输出逐轮配对差值**

`[gate]` 日志新增一段「每轮配对差值（同一轮内 被测−空）」，断言消息里也带
`逐轮 Δframe=[a / b / c]`。原来只有两组各自的中位数，看不出是「单次离群」还是「整组偏移」。

## 放弃了什么（以及为什么不选）

- **把阈值抬到 250/300ms**：能让 macOS 立刻变绿，但会把「+200ms 级的真实回归」一起放过去。
  假红的根因是口径（拿两份轮间漂移做差），不是阈值太小——只调阈值等于把问题盖住。
- **取逐轮差值的最小值当判据**：最小值会被「某一轮特别快」拉低，稳定回归只要有一轮侥幸快就漏。
  3 样本下中位数等价于「取中间那一轮」，抗单次离群，也不吃单向偏差。
- **门禁只在 ubuntu 上跑**：macOS 恰恰是首帧更容易被放大的平台，去掉它等于去掉最该测的环境。
- **把 RUNS 加到 5**：测试时长 +33%（每轮 3 次启动 ≈ 11s，外加维护子进程等待）。本轮先用配对
  消掉可解释的那部分噪声；若配对后仍不稳，再谈加轮次。
- **丢弃轮 0 当预热轮**：会改变语义——门禁量的是「真实首次启动」的首帧，而且「维护子进程在轮 0
  起」这条既有断言依赖它。预热是 `warmHome` 的职责，不该混进测量轮。

## 拿什么证明它生效了

**变异自证（改坏被测代码 → 断言变红 → 恢复）**：在 `bootstrap.ts` 的 `__maintenance` 快速路径之后
临时插入 env-gated 注入——首帧前同步扫 `~/.sid-code/trajectories/sessions` 下 1500 个目录 × 20 个
文件并 stat，复现 C1/T1/T2 的「数据量相关同步工作放回主线程」形态：

```
$ SID_GATE_MUTATION=1 bun test ./packages/cli/tests/startup/large-data-startup-gate.test.ts
[gate]   轮0 大−空 909/166 传−空 -279/-45
[gate]   轮1 大−空 187/51  传−空 -8/-22
[gate]   轮2 大−空 278/200 传−空 -92/-4
error: 逐轮 Δframe=[909 / 187 / 278]（中位数 278.3ms）；first_frame 空=[732 / 458 / 530] 大=[1642 / 646 / 809]
Expected: < 150  Received: 278.3
error: 逐轮 Δblock=[166 / 51 / 200]（中位数 166ms）
Expected: < 100  Received: 166
 5 pass / 2 fail
```

注入已删除：`grep -rn SID_GATE_MUTATION packages/` 无命中，`git status` 只剩本测试文件。

**恢复后的本机实测**（macOS，3 轮）：7 pass / 0 fail。
`逐轮 Δframe=[-693 / -458 / 65]`、`Δblock=[-74 / 9 / -18]`——配对差值全为负或接近零，
说明本机没有「大数据多做活」，门禁不是靠阈值松紧保绿。

**两次 CI 假红的原始数据**（旧口径）：PR #568 空=[552/818/638]、大=[689/998/831] → 192.9ms；
main `4ac97563` 空=[1472/1225/833]、大=[1409/1381/1162] → 156ms。空目录首帧绝对值在两次 run 之间
从 552 跳到 1472（2.7 倍），这就是「两组中位数各自收敛不了再相减」的具体形态。

**没有证明的（局限，如实写）**：3 轮样本 + 本机单次首帧方差仍有 700ms 级（空目录三轮回 1186 / 1142 / 510），
对「只在单轮出现的回归」不敏感。这是原设计既有性质（中位数就是为吸收单次离群），不是本次改动引入；
本次改的是「轮间漂移污染差值」这一条可解释的假红来源。
