# G2 无头回放冒烟骨架：真二进制 `-p` + replay provider + 轨迹断言，带可复跑的变异配方

## 决定了什么

新增一层介于单测与评测之间的门禁（质量防线分层专项的 G2，tracking issue #618）：

- `tests/smoke/lib/`：用例类型（`types.ts`）、夹具占位符替换与越界拦截（`fixture.ts`）、轨迹断言（`assert.ts`）、运行器（`runner.ts`）。
- `tests/smoke/cases/<ID>/{case.ts,replay.jsonl}`：首批 3 个试点 A2（hook 追加动作）、A7（花费上限）、A9（结构化输出）。
- `scripts/smoke/run.ts`（`bun run smoke`）：默认跑仓库根的构建产物 `./sid-code`，`--source` 跑源码入口；设了 `GITHUB_STEP_SUMMARY` 时写汇总表，skip 也看得见。
- `scripts/smoke/mutate.ts`（`bun run smoke:mutate`）：对每条 `mutation` 配方改坏源码 → 跑用例 → 必须变红 → 用读到的原文还原（不用 git 还原）。结果 `killed` / `survived` / `stale`，后两种退出 1。
- `tests/smoke/smoke-lib.test.ts`：运行器纯函数的单测，随 `bun test` 跑。用例本身**不**进 `bun test`，入 CI 是 M2 的事。

运行器的隔离约束，每条都是实测出来的：

1. **夹具路径一律 `${CASE_ROOT}`，越界就拒绝执行。** replay 的语义是「模型响应回放、工具真实执行」。2026-11-06 拿真实录制做探针时，`read` 真的读到了录制时的 `/private/tmp/a2-e2e/hello.txt`。
2. **`env -i` + 假 `HOME`**，跑完断言假 HOME 下没有 `.sid-code/`。2026-11-06 用 marker 法核过：账本、遥测、审计全部跟随 `SID_CONFIG_DIR`。这条断言防的是以后新增一个不跟随它的落盘点。
3. **价格写死在 settings.json 的 `availableModels[].pricing`。** 这是定价解析的第 2 优先级（`cost-tracker.ts` `resolvePricing`），不依赖网关价格缓存，CI 上也能算出同一个数，A7 才是确定性的。
4. **`SID_CODE_AUTO_MEMORY=0`。** 后台记忆提取在退出前会 `drainPending(5_000)`。同一份夹具开着它是 5.3s，关掉是 0.27s。
5. **预置维护水位线。** 维护子进程是 detached + unref，比主进程活得久。不预置的话，A7 0.3s 退出后，子进程会把 `state/maintenance-*.json` 写回已经删掉的临时目录，留下孤儿目录。
6. **默认不看退出码。** 无头命令失败曾经一律退 0（#622 刚修）。只有 A7 显式断言 `exitCode: 1`，因为「预算硬停非 0」是 `app.ts` 收尾处写明的契约。

用例格式用 TS 对象，不用 YAML：事件名直接 import 源码常量（`HOOK_EXECUTED_EVENT_NAME`、`HookEventName.*`、`STRUCTURED_OUTPUT_TOOL_NAME`）。常量改名时 import 会直接报错；YAML 字符串只会静默匹配 0 条。

## 放弃了什么（以及为什么不选）

- **直接拿真实会话的 raw.jsonl 当夹具**：录制里带 thinking 块、内网模型名和绝对路径，体积约 100KB/例，而且要靠脱敏脚本兜底。改成手写最小夹具，只保留 `ReplayProvider.parseRawJsonl` 读的四个字段（index / response.content / stop_reason / usage），每例 3–4 行，review 时能一眼看完。期望值仍然取自触发清单里人工 `jq` 核过的那条，而不是从实现反推。
- **用 `bun test` 直接 spawn 用例**：G2 测的是构建产物，`bun test` 阶段还没有二进制。而且根 `bunfig.toml` 的 preload 会改写 `SID_CONFIG_DIR` 等环境变量，与运行器自己的隔离叠在一起不好推理。所以单独做脚本，CI 接在 `make build` 之后（M2）。
- **变异复跑也用构建产物**：每条变异都要 `make build` 一次（约 1 分钟），5 条就是 5 分钟。源码入口跑的是同一份代码，「测装好的东西」由 `run.ts` 负责。
- **把 A9 第 1 轮写成伪造 `_agentId` 并期望被拒**：这是第一版夹具，实测被接受了。`stripInternalFields`（`tool-executor.ts:1496`）在校验前就把它剥掉了，代码是对的，是期望写错了。改成两轮各守一条接线：普通多余字段 `extra` 必须被拒；伪造的 `_agentId` 必须被剥掉，从而被接受。

## 拿什么证明它生效了

- `bun run smoke`（构建产物）连跑 10 次：3 例全过，单例 0.3–0.4s，跑完 `$TMPDIR` 下无 `sid-smoke-*` 残留。
- `bun run smoke:mutate`：5 条配方全部 `killed`，跑完 `git status -- packages/` 为空（源码已还原）。逐条的红法：
  - A2 · `runner.ts` 去掉 `this.emitExecutedTelemetry(` → `HookExecuted` 0 条
  - A2 · `planner.ts` matcher 恒真 → `HookExecuted` 3 条（read 也触发）
  - A7 · `quota.ts` `isExceeded` 恒 false → 没有 `budget_exceeded`
  - A9 · `structured-output-tool.ts` 跳过校验 → 没有 `is_error=true`
  - A9 · `internal-fields.ts` 名单去掉 `_agentId` → `is_error=true` 变成 2 条
- 变异脚本自身的变异自证：把 A7 配方的 `find` 改成不存在的字符串 → `[STALE]`、退出 1；把 `replace` 改成语义等价的写法 → `[SURVIVED]`、退出 1。
- 运行器单测的变异自证：把越界判定 `startsWith(root)`（带尾斜杠）改成 `startsWith(caseRoot)` → 「前缀相同的兄弟目录被拦」这条变红（13 pass / 1 fail），还原后 14 pass。
- `bun run lint` / `format:check` 通过；`typecheck:gate` 无新增错误（62 / 基线 64）；`make build` 通过且无 `will always be undefined`。
