# 上下文估算基线脚本是 E0/E1 的唯一定义，口径写死三条分母铁律

## 决定了什么

新增 `scripts/context-estimate-baseline.ts` + `tests/scripts/context-estimate-baseline.test.ts`，
把方案 §8.3 的 M1 / M2 / M3 / M4 四个指标做成**一份可复算的实现**，E0（修复前基线）
与 E1（修复后复测）都跑它。脚本只读 `~/.sid-code/trajectories/`（或 `--root` 指定的轨迹根），
不写盘、不调模型。

四个指标各自的源字段：

- `pred = BeforeModel.ctx_estimated_tokens − ctx_freed_tokens`
- `actual = normalizeCacheUsage(AfterModel.usage, provider).promptTotal`（与 `stockPromptTokens` 同一个归一化函数）
- M1 = `|pred−actual|/actual` 的 p95；M2 = 带符号同一比值的 p5
- M3 = 上下文超限类错误数（`TurnError` / `Error` / `errors.jsonl` 文案）+ blocking 强制截断数
- M4 = `messages.json` 中 `_meta.compact_boundary` 的出现次数

分母写死三条：**只算 `ctx_calibrated === true`**、**`reason:"aborted"` 的补记不计**、
**子代理按 `agent_id` 单独成组**。这三条直接决定「通过 / 不通过」的数值，所以它们是代码里的
显式过滤条件 + 三条单测，而不是文档里的口头约定。

## 放弃了什么（以及为什么不选）

1. **不复用 `trace/digest.ts` 的派生指标**。digest 算的是会话级的峰值 / 累计，
   没有「逐次调用的 pred 与 actual 配对」这个维度；在这上面加会污染 digest 的公共口径。
   脚本自己配对，但归一化函数仍 import core 的 `normalizeCacheUsage`，避免第二份口径。
2. **不用 `AfterModelRaw.context_window` 判断是否 blocking**。该字段由
   `collector.computeContextUsage` 计算，它调 `tokenEstimator.getContextLimit(model)` 时
   **没传 `availableModels`**，所以用户在 settings 里声明的 `contextWindow` 覆盖不到它
   （E0 实测：S3 场景把别名窗口设成 128000，该字段仍报 1000000）。
   拿它当判据会把「窗口压力到底触发在哪」算错。改用 `messages.json` 的压缩边界文案前缀
   （`blocking` 档的横幅在 `loop.ts` 是「阻塞级压缩：…」），并在单测里钉死这个前缀。
3. **不把场景编排（造 S1/S2/S3、跑 `-p`、每场景 3 次）放进仓库脚本**。场景需要真实模型、
   消耗额度、且 prompt 会随验收轮次调整；放进仓库等于把「评测数据」与「量具」耦合。
   E0 的场景定义与命令记在方案文档里，脚本只负责**分析已有轨迹**。
4. **不做 `--scenario` 之类的自动分组**。轨迹里没有场景字段，硬编码场景名会让 E1 改场景时
   静默失配。改用 `--run <label>=<id|路径>`，label 由调用方给，脚本只做算术。

## 拿什么证明它生效了

- `bun test ./tests/scripts/context-estimate-baseline.test.ts` → **15 pass / 0 fail**
  （覆盖：百分位插值、snake→camel、anthropic 与 openai 两种 promptTotal 口径、
  未校准排除、aborted 排除、重试计数、子代理分组、老轨迹缺字段单独计数、
  blocking 横幅识别、端到端读盘）。
- `bun run typecheck:gate` → **62 处错误 / 基线 62 处，无新增**（脚本自身类型干净）。
- 对真实会话 `20261118-104518-25d7a11b`（S1 第 1 次）：
  ```
  运行      会话                        分母  排除(未校准/作废)  M1 |err|p95  M2 err p5  M3 越界/blocking  M4 压缩
  S1-run1   20261118-104518-25d7a11b    12    1/0              4.0%         -4.0%      0/0              0
  ```
  与人工核对一致：该会话 13 次模型调用，首个请求 `ctx_calibrated=false`（被排除），
  余 12 次进分母；无重试、无压缩。
