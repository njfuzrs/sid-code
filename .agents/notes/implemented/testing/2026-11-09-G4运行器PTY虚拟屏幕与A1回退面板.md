# G4 TUI e2e 运行器（PTY + 虚拟屏幕）与首个用例 A1-dialog；修复回退结果页 Esc 要按两次

## 决定了什么

- **G4 复用 G2 的用例格式与运行器**，不另起一套：`SmokeCase` 加 `tui?: TuiStep[]` 字段，带剧本的用例就是 G4。隔离（`env -i` 白名单、假 HOME、隔离 `SID_CONFIG_DIR`、P-3 断言）、`${CASE_ROOT}` 夹具改写、轨迹断言、`mutations` 变异复跑、`expect-guard` 期望守卫全部原样适用。
- **PTY 驱动**（`tests/smoke/lib/tui.ts`）：`Bun.spawn({ terminal })` 起构建产物的交互模式，字节喂给 `@xterm/headless`（仓库已有的 devDependency）还原网格，只读**视口**、去空白后匹配（主屏按列宽硬折行，中文会被拆行）。
- **剧本四种步骤**：`type`（写字 + 等回显）、`key`、`wait`（等屏幕出现文本，超时即失败——这就是 G4 的屏幕断言）、`pause`（只许用于时间本身是被测对象的场景）。剧本走完运行器统一「Ctrl+C → 等二次确认提示 → Ctrl+C」退出，10s 不退判失败，「退出不挂」成为每个 G4 用例的隐含断言。
- **屏幕上出现「按任意键关闭」立即判失败**，并给 G4 的 settings 显式写 `subAgentModels: {}`、`fallbackModel: ""`：团队默认配置补全会补进引用 deepseek-* 的这两个键，TUI 启动就弹警告、吞掉第一个按键（探针实测）。只给 G4 加，G2 的 A10 迁移链用例断言的正是补全结果。
- **G2/G4 分开跑**：`bun run smoke` 缺省只跑 G2，`bun run smoke:tui` 跑 G4；CI test job shard 1 各一步，都 `continue-on-error`。合约测试锁住 G4 步骤存在且排在 `make build` 之后。
- **用例 A1-dialog**：Esc、隔 200ms、Esc（人手慢路径，不是一次写 `\x1b\x1b` 的解析层快路径）→ 回退面板 → 选点 → 仅代码 → `Rewind{via=dialog,outcome=ok,mode=code,messages_dropped=0,files_restored=1,…}` 恰 1 条 + `hello.txt` 回到改前 → 按一次 Esc 回到输入框。期望取自触发清单 A1 的人工实测（2026-11-06 两个 TUI 会话的 `Rewind` 字段）。
- **缺陷修复**：回退结果页写「Esc 关闭」，实际要按两次。`RewindDialog` 的 Esc 处理先判 `selectedPoint`（阶段 2 → 阶段 1），渲染先判 `result`；结果页里 `selectedPoint` 仍非空，第一次 Esc 只清掉它、画面不变。改为与渲染同序（结果页 → 阶段 2 → 阶段 1），补组件单测 `rewind-dialog-escape.test.tsx`。

## 放弃了什么（以及为什么不选）

- **另建 `tests/tui-cases/` 目录和独立运行器**：两层的隔离、断言、变异、期望守卫完全相同，分开就要维护两份；期望守卫按 `tests/smoke/cases/` 前缀扫描，放进同一目录才能免改直接覆盖 G4 剧本（剧本里的 `wait` 就是期望）。
- **G4 混进 `bun run smoke` 一起跑**：G2 正处于转正观察期（到 2026-11-21，判据是「0 次非代码原因的红」），G4 时序敏感、稳定期另算（M5：CI 连续 20 次全绿才转必需）。混跑会让 G4 的抖动记到 G2 头上。
- **沿用 `main-screen-shrink-e2e.test.ts` 的做法（源码入口 + OpenAI 兼容 mock SSE 服务 + `settle` 等输出静默）**：那是渲染层门禁，测字节；G4 要测「装好的二进制」，模型侧用 replay 夹具与 G2 同源。按「输出静默多久」同步正是 §3.5 禁止的 sleep 式同步。
- **改 `smokeSettings()` 公共缺省来消启动警告**：会改掉 A10 三个迁移链用例的输入。
- **A4-loop-tui 本次不做**：`/loop` 最小粒度 1 分钟（cron），调度器 30s 轮询，真等一次触发要 30–96s。要压到秒级只能给调度器加测试用的轮询间隔开关或时钟注入，属于产品代码改动，单独评估。

## 拿什么证明它生效了

- 构建产物（`make build` 后）本机连跑 20 次：`pass=20 fail=0`，单次 1.2–1.3s。
- `bun run smoke:mutate A1-dialog`：`4 条变异：4 killed`，各红在该红的那一步——慢路径双击失效 → 「回退面板打开」等不到；文件不恢复但埋点照报 ok → `hello.txt` 内容不等；`emitDialogRewind` 断开 → `Rewind` 期望 1 条实际 0 条；结果页 Esc 退回旧判断顺序 → 「面板关闭、回到输入框」等不到。
- 缺陷单测先红后绿：修复前 `结果页按一次 Esc 就关闭面板` 断言 `closed=1` 实际 `0`（1 pass / 1 fail），修复后 2 pass。
- 合约测试 `tests/release-flow-contract.test.ts`：正常 90 pass；把 G4 步骤命令改掉、把它挪到 `make build` 之前，各只让新断言变红（89 pass / 1 fail），还原后 90 pass。
- 首跑实测纠正两处剧本写法：剧本最后的 Esc 若紧跟运行器的 Ctrl+C，50ms（`ESC_TIMEOUT`）内会被解析成一个 Meta 组合键，所以剧本必须先 `wait` 回到输入框；屏幕等待文本不能用「会话回退」，第一次 Esc 的引导提示也含这四个字。
