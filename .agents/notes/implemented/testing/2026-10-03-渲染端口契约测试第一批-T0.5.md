# 渲染端口契约测试第一批：17 条 T0.5 待办全部落地（B9 / T0.5）

## 决定了什么

- 新增三个文件，都在 `packages/cli/tests/render-port/`，只经端口 API 驱动：
  - `contracts-layout-text.test.tsx`：L1（SURFACE.md §2 的 Box props 逐个有用例，28 条）/ L4 / T1 / T2 / T5 / O4，走 testing shim（非 TTY 整帧），比可视文本不比字节。
  - `contracts-runtime.test.tsx`：R2 / R10 / L5 / I1b / I1c / I5 / I6 / M5 / O5 / E3 / X4。这些都在 TTY 分支或进程级信号里，shim 覆盖不到。
  - `tty-streams.ts`：假 TTY 流 + `mountTTY`。**卸载前先把 `isTTY` 置假**，否则 TTY 卸载的 `writeSync(1, …)`（契约 X3）会写进测试进程自己的 stdout。全量跑时这两个文件 0 处泄漏 `?2004h`。
- 期望值全部是 2026-10-03 在 legacy 上实测的输出，不是照源码注释写的。
- 几个测法选择：
  - **R2** 临时把 `NODE_ENV` 切成 `production`：test 环境下 reconciler 走 `onImmediateRender`，没有节流，不切就测不到调度。用 `rerender`（同步提交）而不是 `setState`，后者自己会被 React 批处理，测出来的合并不是底座的。
  - **I1c** mock `Date.now` 造 6s / 1s 两个间隔，并断言重申**不擦屏**。
  - **E3** 放进子进程：处理器绑死 `process.stdout`，进程内测会毁掉测试进程的 stdout。另加一个不注册的对照组，证明「进程没崩」不是空测；再从源码断言 `fullscreen.ts` 里注册在 `await render(` 之前。
  - **M5 / R10 / X4** 需要实例方法（`setAltScreenActive`、`setSelectionBgColor`、`detachForShutdown` 等）。端口只导出 `inkInstances`，CLI 本来就这么拿实例，所以测试里把用到的方法列成显式类型 `LegacyInk`，next 必须提供同名能力。
- `verify-tui-spec` 不再接受 `⏳ T0.5`（同 T0.4 的做法），阶段 0 的待办全部关闭，新契约不能再挂回阶段 0。
- 覆盖率（`bun run tui:spec --report`）：54 条中 50 条已有测试，其余 4 条（M4、P1、P3、P4）挂后续任务。

## 放弃了什么（以及为什么不选）

- **全部走 testing shim**：shim 的 stdout 是非 TTY。底座在非 TTY 下不挂 SIGCONT、不隐藏光标、不进增量 diff，R10 / L5 / O5 / X4 / I1c 根本走不到。
- **把 R10 / I1c 等放进 T0.4 的 xterm 测试台**：这几条断言的是「写了哪段序列」，不是「屏幕长什么样」。子进程 + xterm 绕一圈换不来更多信号，进程内假 TTY 更直接，也更快（runtime 文件 1.1s）。
- **给端口加一个 `getInstance()` 正式 API 来拿实例方法**：属于 T1.x 设计端口类型的范围，现在加会抢先定接口。测试里用显式类型列出依赖面，到时候按这张单子设计即可。
- **E3 断言 `stdout.destroyed === true`**：Bun 子进程里 `stdout` 是 pipe，`destroy()` 之后 `destroyed` 仍读到 `false`。契约要的是「不变成 uncaughtException」，所以只断言进程活着，用对照组兜住空测风险。
