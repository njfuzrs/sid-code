# W2②：换模型验证 —— shim 支持双协议族 + 判据是机理不是分数

## 决定了什么

**买「harness 的修复在另一族协议上还成立吗」这个当前完全空白的维度**，
而不是买「12 个缺陷的净效果总数」（后者在当前 commit 结构下买不到，见 `rejected` 理由）。

三件落地物：

1. **`gateway.py` 支持双协议族**（宿主侧 shim，刻意不入库）。原版只支持 anthropic 族，
   openai 族的 `/v1/chat/completions` 会撞 `_deny_non_model_endpoint` 拿到 403。改了四处：
   - 白名单**按族分开**（`FAMILY_ENDPOINTS`），不合并成一个大集合；
   - **协议族的权威来源是 settings.json 的 `provider`，不是请求路径**；
   - 认证头分族注入（`x-api-key` vs `Bearer`），不"两个都发"；
   - `_upstream_url()` 去重 `/v1`。
2. **`run-model-switch.sh`**：四道跑前闸（沿用 permission-switch 的同源判据），
   `SID_MODELSWITCH_FAMILY` 一个开关切 deepseek/sonnet 两侧，`-n 6`（W0 定档），
   真 agent 首次上 `-n 6` 加了内存采样。
3. **`analyze-model-switch.py`**：判据全部机理型，取数一律复用 `verifier_health.py`。
   **并排前先核同档**（`-n`、题目集、wire model 各自唯一且两侧不同），任一不满足就拒绝并排。

4. **补 `verifier_health.llm_fatal` 的上游硬拒判据**（`UPSTREAM_HARD_REJECT_CODES`）。
   这不在原计划里 —— 是跑完后 `trace-digest` 揪出来的：`llm_fatal` 只认 anthropic
   降级链的中文措辞（`主模型请求失败`），而 **402 是一次性硬拒、不走降级链**，
   于是一次 deepseek 余额耗尽被记进了能力账，报告写着「重试链打空 0/10」。

**判据是机理，不是分数**：`144 deny → 0` 这类修复**应当与模型无关**，
若 deepseek 侧冒出新失败形态那才是真发现。reward 只报不判，成本也不直接比
（两家定价不同，差额里混着单价差）。

## 放弃了什么（以及为什么不选）

- **⛔ 放弃「12 个缺陷净效果总数」**（原计划 ~$13 的 `7f437eb8` vs `30586ff0`）。
  实测两条事实使它买不到：① 五个 A 类修复（#138/#119/#126/#125/#139）
  **全都已在 control 里**；② #141/#142 只改 `sid_code_agent.py`、**不在二进制里**。
  两侧唯一真实差异只剩 #143，而它已被 $0.21 证明过 —— 照跑会拿到「无显著差异」，
  然后被误读成「修复没用」。
- **⛔ 放弃把两族白名单合并成一个集合**。合并只需一行且看起来更简洁，
  但那会让配成 anthropic 的上游也放行 `/v1/chat/completions`，
  请求带着错误族的凭据打过去，回来的报错与真因（族配错）毫无关系。
- **⛔ 放弃「靠请求路径猜协议族」**。那等于让调用方决定注入什么凭据。
- **⛔ 放弃用 reward 差值当判据**。换模型同时换掉了「模型能力」这个我们控制不了的变量，
  n=10 时 SE≈15pp —— 拿它比大小就从 harness 验证跑偏成模型横评。
- **⛔ 放弃把 5xx/429 放进 `UPSTREAM_HARD_REJECT_CODES`**。它们**可重试**，
  耗尽后会正常落 `LLM_FATAL_MARK`，由原判据管 —— 放进来是**重复判据**，迟早分叉。
- **⛔ 放弃把 400 放进去**。那是请求本身不合法（**我们自己发错了**），
  属真实缺陷**必须计分**。排除它比不排除更坏。
- **⛔ 放弃只用状态码判硬拒**，要求语义标记 `API 错误` 同时成立 ——
  只看数字会被题目输出里恰好出现的 `402` 命中。
- **暂缓 ①‴ 加 claude-code 对照**：结构性前置已核通（`MODEL_CONNECTION` 声明
  `base_url_envs=("ANTHROPIC_BASE_URL",)`，`_env_sources` = `(_extra_env, os.environ)`
  ⇒ 选项 A「也走我们的 shim」在代码层面成立），但 🔴 **B8 那笔 key 轮换是它的前置纪律**，
  未做完不动它。

## 拿什么证明它生效了

**① shim 纯函数层 + 变异自证**（`_upstream_url` 去重、两族白名单无交集）：
把去重逻辑改成 `if False` 后，`uniapi` 那条确实产出 `/v1/v1/chat/completions`
—— **证明这条判据真的在拦，而不是恰好都通过**。

**② shim 端到端四条行为**（新起 4101/openai 与 4102/anthropic 两实例实测）：

| 请求 | openai 实例 | anthropic 实例 |
| 占位 token + 本族端点 | **200**（deepseek 真回流） | **200** |
| 错误 token | **401** | — |
| 另一族端点 | **403 族不匹配** | **403 族不匹配** |
| 非模型端点 | **403 端点不在白名单** | — |

`/__stats` 里两种 403 **分开计数**（`403_family_mismatch_*` vs `403_POST_*`）：
混在一起会让人以为容器在乱打端点（安全问题），而真因是配置问题。

**③ 分析脚本在真实 run 上自证 + 两条变异**（`runs/permswitch-r5`）：
- 正向：`0 deny / 259 allow`、撞满 3/10、零调用 3/10，与该 run 已知结论一致；
- 变异 A（两侧 `-n` 不同：r5 是 1、recheck-nop-n6 是 6）→ **rc=1 拒绝并排**；
- 变异 B（同 job 自比 ⇒ 模型没换成）→ **rc=1 拒绝**。
  ⚠️ 变异 B **揪出一个我自己写的真 bug**：第一版只在"仅供参考"区打一行提醒，
  而「一句话结论」照样打 ✅「修复在另一族成立」—— 一个自相矛盾的假绿，
  且恰好出现在最该拦的场景。已升级为 blocker。

**④ 两个探针 bug（冒烟输出暴露，都会造假红）**：
- 闸 2 的 `curl ... || echo 000`：流式响应被 `-o /dev/null` 提前断开时 curl
  **既打印 `200` 又非零退出**，拼成 `200000` → 判为非 200。
  冒烟 20 连里 4 次这样，**失败率虚报 20%（真值 0%），恰好压在拒绝阈值上**。
  形态与本仓 `grep -c ... || echo 0` 那条完全同源。
- 闸 3 用 `$([ ... ] && echo -H '...')` 拼头：未加引号的命令替换被词分割，
  多出来的词被 curl 当成**额外 URL** → 发了 4 次请求、`http_code` 拼成 `401000000000`。
  修后实测：`http_code` 干净 3 位，shim 计数增量 = 1（不再多发）。

**⑤ 单题冒烟通链路**（`runs/modelswitch-smoke`，deepseek 全新链路首次跑通）：
`regex-log` **reward=1.0 / deny=0 / turns=10 / $0.1166 / 8m30s**，
容器内存峰值 **1754 MiB**（W0 的 nop 基线 714 MiB —— 真 agent 确实更吃内存，
但离 15.58 GiB 很远）。digest 高危 0 条。

**⑥ 402 判据修正的干净性证明**（用 `git show HEAD:` 取改动前实现，
在**全部历史 run** 上逐题对照，而不是"跑一遍看着对"）：

```
新增命中：['modelswitch-ds/qemu-alpine-ssh']   ← 恰好只有 402 那一题
丢失命中：[]                                    ← 零回归
```

四条变异全过：清空码表 → 重新漏判（证明确实靠它命中）；改坏语义标记 → 不命中
（证明两条都是必要条件）；`400` → 不命中；裸数字 `402` → 不命中。

⚠️ **我在这一步算错过一次**：以为「期望 9 题」，实际 7 题。差异**不是**改坏了 ——
8 是「仅看 `sid_errors`」的数，而 `llm_fatal` 还要求重试链佐证，两题 smoke
被佐证步骤挡掉，**改前改后都挡**。
⇒ **对照要用同一个函数的前后版本，不能拿某个中间量当基线。**

**⑦ 全量 deepseek 10 题**（`runs/modelswitch-ds`，24 min，$1.2195）：
`0 deny / 240 allow`（10/10 题有审计日志，`allow>0` 是反向自证）、
仪器自证 10/10 题一致 0 处不符、撞满 40 轮 1/10、零调用 0/10、
**重试链打空 1/10（就是那个 402，修判据后才读出来）**。

**⑧ 同档 sonnet 基线 + 并排（`runs/modelswitch-base`，$8.4955，85 min）—— 结论成立**：

| 判据 | control(sonnet) | treat(deepseek) |
| --- | --- | --- |
| **权限 deny 总数** | **0** | **0** |
| allow（反向自证） | **329** | **240** |
| 撞满 40 轮 | 3 | 1 |
| 重试链打空 | 0 | 1（402） |
| 零调用 | 1（`regex-log`） | 0 |
| 仪器落盘（5 项） | 0 缺失 | 0 缺失 |

⇒ **`#141` 那条 `144 deny → 0` 在两族协议、两个厂商的模型上表现一致。**

**⑨ 并排时揪出第二个自己写的 bug**：不对称检查**只比数量**。两侧各排除 1 题，
但 deepseek 排 `qemu-alpine-ssh`（402）、sonnet 排 `regex-log`（40 次 502、
零成功调用）—— **1 vs 1 会被报成「对称，不构成偏倚」放行**，而真相是两侧分母
装的不是同一批题（`0.100 → 0.750` 假数的成因）。已改为比**题名集合**，
数量相同但集合不同时额外警告，并算出可比的公共分母（本轮 8 题）。
五个分支逐个驱动验过（含反方向不对称）。

> **形态：用一个「看起来等价」的代理量（数量）替代真正的判据（集合）** ——
> 代理量在多数情况下巧合正确，而它出错的那次恰好就是最该拦的那次。

⚠️ **两条不许由本轮数据推出的结论**：任何 reward 比较（公共子集 `5/8 vs 2/8` 也不行，
n=8、SE≈18pp，且换模型同时换掉了模型能力）、成本 9.4×（混着单价差与峰谷价）。

⚠️ **两条运维前提留给下一棒**：deepseek 官方端点**余额已耗尽**（实测仍回 402）；
ppchat 上游阵发性 502（基线侧 `__stats` 累计 `upstream_error=67`）——
**判据用网关计数器，不是「再试一次」**：`regex-log` 容器内连吃 40 次 502 时，
宿主直探同一个 shim 3/3 都是 200。

⚠️ **仍欠 B8**（key 轮换，已九棒），
所以「修复与模型无关」这个结论**现在还不能写** —— 只有冒烟证明了链路通。
