# 迁移告警的模块级全局跨测试文件泄漏，顶红 3 个无关用例

## 决定了什么

给 `packages/core/tests/migrations/team-defaults-rerun.test.ts` 的 `afterEach` 补一次
`resetMigrationWarnings()`（原来只在 `beforeEach` 清）。

`migrations/warnings.ts` 的 `warnings` 数组是**模块级全局**，`bun test` 同批文件共享一个进程。
只在 `beforeEach` 清，意味着本文件最后一个用例（`失败告警经 loadConfig 进启动诊断`，`:162` 写入
「迁移 x (v9) 失败，测试用」）的残留会留给后面的文件。
后跑的 `tests/config/permission-default-mode.test.ts` 用例 1 / 5 / 10 断言
`warningsOf(config)` 为空，就被这条残留顶红。

失败形态刻意记一下：**单跑两个文件都绿**（`./packages/core/tests/config/` 925 pass），
只有同进程且顺序在后时才红。CI 按 shard 分片，两者落在不同片上就不会暴露 ——
这是「本地全量红、CI 绿」的一个真实来源。

## 放弃了什么（以及为什么不选）

- **改 `permission-default-mode.test.ts`，让它过滤掉 migrations 来源的告警**：那是让被污染方
  迁就污染方。它断言「无诊断」是真实意图，放宽等于削弱断言。
- **把 `warnings` 改成按 `SID_CONFIG_DIR` 分桶或用 AsyncLocalStorage**：生产侧没有这个需求
  （`runMigrations` 一个进程只跑一次），为测试隔离改生产数据结构是倒置。
- **在 `bunfig.toml` 的 preload 里统一清**：preload 只在文件加载前跑一次，清不掉用例执行期间写入的值；
  而且会掩盖「哪个文件漏了清理」。
- 顺手发现于 PR #887（删 fork 参数）的全量跑，按 CONTRIBUTING **单独开 PR**，不塞进那个功能 PR。

## 拿什么证明它生效了

```
$ bun test ./packages/core/tests/migrations/team-defaults-rerun.test.ts \
           ./packages/core/tests/config/permission-default-mode.test.ts
32 pass / 0 fail        # 修复后

# 变异自证：删掉新加的 resetMigrationWarnings() 再跑同一条命令
3 fail                  # 断言确实在守这件事，不是恒绿
```

修复前在父仓 main `768bc0df` 上跑同一条命令也是 3 fail，确认是既存问题而非 PR #887 引入。
