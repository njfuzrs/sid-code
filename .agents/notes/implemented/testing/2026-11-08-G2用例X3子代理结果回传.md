# G2 用例 X3-subagent-result：子代理输出真的回到主会话，对话落 sidechain

## 决定了什么

新增用例 `X3-subagent-result`（台账 §三 X3），运行器不用改。子代理和主会话共用一个 ReplayProvider 游标，所以夹具按调用顺序录三条：主会话调 `sub_agent`，子代理回答（带标记串 `SMOKE-X3-MARKER`），主会话汇总。

断言：

- `SubagentStart` 1 条，`SubagentStop{status=completed}` 1 条，`PostToolUse{sub_agent,is_error=false}` 1 条；
- 主会话 JSONL 的 tool_result 含标记串；
- 同目录恰好 1 个 `<sessionId>-<agentId>.jsonl`，首行 `sidechain_start`，末行 `sidechain_end{completed}`，内容含标记串。

## 放弃了什么（以及为什么不选）

- **只断言 Subagent 事件**：不够。子代理跑完了、结果却没拼进 tool_result 时，回放的汇总轮照样会产出，事件全对但主会话拿不到结论。所以主判据是标记串到达主会话。
- **断言 stdout 的 `result` 含标记串**：不选。汇总轮是录好的文本，和子代理输出无关，断言它测不到回传。
- **守「子代理绕过 Fallback」**：不在本用例内。台账依赖列引用了这条记忆，但它是降级链的另一条判据，需要主模型失败构造（A8 那套），放在一起会把两个功能缠在一个用例里。

## 拿什么证明它生效了

- `bun run smoke -- X3-subagent-result`：PASS（0.3s）。
- `bun run smoke:mutate -- X3-subagent-result`：2/2 killed。
  - `tool.ts` 不把 `result.output` 拼进 summary → 「主会话的 tool_result 里没有子代理输出」；
  - `sub-agent.ts` 不创建 SidechainWriter → 「sidechain 文件期望 1 个，实际 0 个」。
- 期望取自 2026-11-08 构建产物探针，没有人工 TUI 实测，台账已注明。
