# 补强 /context 面板的四道验收门禁，让「声称守住的」真能变红

## 决定了什么

二次核验 PR #914–#928 的落地情况时，发现四处**声称已验收、实际恒绿或漏检**的门禁，本次把它们改成真能捕获缺陷：

1. **归零门禁的注释判据**（`packages/core/tests/context/context-size-api-gate.test.ts`）：
   旧判据是「`trimStart` 后以 `//` / `*` / `/*` 开头就跳过整行」，于是
   `/* 说明 */ ctx.estimateTokens();` 与 `*/ const x = ctx.estimateTokens();` 两类真实调用
   会被整行跳过。改为 `codePartForGate()`：维护跨行块注释状态、按引号状态跳过字符串内容，
   只对「真正会被执行的字符」匹配。另加 5 条判据自证用例（行内块注释、块结束行、纯注释、
   跨行块注释、字符串里的 `//`）。
2. **跨层对账**（`packages/cli/tests/command/context-render.test.ts`）：旧断言只比
   `report.percentOfWindow === footerPercent` 与「结论」行，**完全不读渲染出来的「已用」行**；
   且夹具没有锚点抬升（`subtotal === used`），把「已用」改读 subtotal 也会输出同一串数字。
   现在新增「已用」行数字 === footer `used` 的断言，并给该用例造出锚点抬升，
   同时断言 `subtotal !== used` 作为前提。
3. **逐类估算分项**（`packages/core/tests/context/breakdown-same-source.test.ts`）：
   夹具里虽有 `mediaBlocks` 与 30+ 字符的长工具名，但没有任何断言覆盖它们——
   删掉 `token.ts` 的 name / mediaBlocks 分支，测试仍全绿。新增
   `estimateBlockTokens` 逐类分项精确断言（tool_use = name + input JSON；mediaBlocks 差值 = base64 估算）。
4. **`estimateBlockTokens` 的穷尽检查**（`packages/core/src/context/token.ts`）：
   `default: return 0` 会让未来新增的 `ContentBlock` 成员**静默漏算**（估算偏低 → 压缩/遮罩晚触发）。
   改成 `const exhaustive: never = block`，新增类型时 typecheck 直接报错；运行时仍返回 0 保持防御。

另补 B6/B7/B9 三条渲染断言：释放明细逐策略 label + 条数、四档阈值逐行 label + 触发点数字、
面板文本不含竖线（复制粘贴可直接用）。这三条此前在方案 §8.1 里被列为验收项，实际无断言。

## 放弃了什么（以及为什么不选）

- **不改 `fixed-overhead.ts` 的负残差钳 0**：`Σ sources + residual === memoryFiles` 在负残差时
  不成立，但注释明确说明这是有意为之（残差为负说明来源重复计数，钳 0 并留日志），
  改它会动到「固定开销」的产品口径，不属于本次「门禁补强」范围。
- **不改 B5 的 `percentOfTrigger`**：渲染层确实不消费该字段，但「距触发多远」已由
  `toTrigger`（结论行）+ `triggerPercentOfWindow`（进度条尾）呈现，信息没有缺失；
  再加一行百分比属于产品决策，不在「实际性错误」内。
- **不修文档漂移**（方案文档 §4.1「两处共用同一个值」、BeforeModel 单测 3 例 vs 4 例、
  §8.2 变异数字过期、`hook/types.ts` 注释口径等）：按用户要求本次只修实际性错误。
- **不修 `rejected/` 缺 R2 独立 Note**：论证已存在于 PR1 Note 与 2026-11-12 的 implemented Note，
  只缺独立归档文件，属流程留痕而非门禁失效。
