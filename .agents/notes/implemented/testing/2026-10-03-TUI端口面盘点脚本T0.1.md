# TUI 渲染端口面改由脚本盘点，签名只取集合（B9 / T0.1）

## 决定了什么

新增 `scripts/tui-surface.ts`（`bun run tui:surface`），从源码机械扫出 CLI 对渲染底座的全部依赖，
生成 `packages/cli/src/ui/render-port/SURFACE.md`：

1. CLI 消费的底座符号（静态 / 动态 `await import()` 解构 / inline 类型），按引用文件数排序；
2. 宿主组件（Box / Text / Static / RawAnsi …）上实际出现的 JSX props 与字面量取值；
3. 底座源码读取的环境变量（含 `const env = process.env` 之后的 `env.X` 别名形态）；
4. CLI 绕过底座的 `stdout.write` / `writeSync(stdout.fd)`，按「终端序列 / 普通输出」分开。

`--check` 只比对**签名**：符号、props、环境变量三个**集合**的哈希。计数不进签名。
符号的签名键对默认导出取本地名（`import Box from …/Box.tsx` → `Box`），
所以 T0.2 把它改成 `import { Box } from "render-port"` 之后签名不变 —— 这是 T0.2 「端口面零变化」的判据。
端口层目录 `ui/render-port/` 自身不计入消费者。

## 放弃了什么（以及为什么不选）

- **手工维护 §1.2 那张表**：初稿已经错过一次（把注释里的 ScrollBox 计成依赖）。脚本先剥注释再匹配。
- **用 TypeScript 编译器 API 解析**：仓库根没有装 `typescript`，为一个盘点脚本加依赖不值；
  正则 + 花括号配平对本仓的导入与 JSX 写法够用，并由单测逐形态钉住。
- **签名包含计数**：计数随日常 UI 改动天天变，做门禁只会逼人反复重生成、最后不看。
  集合变了才是端口面真的变了。
- **现在就接进 pre-commit / CI**：T0.2 之前端口还不存在，接了只会在每次 UI 改动时增加噪音。
  T0.2 落地 `lint:boundary` 规则时再决定是否把 `--check` 一起接上。

## 拿什么证明它生效了

- `bun run tui:surface`：44 个符号 / 51 种 props / 38 个环境变量 / 16 处终端直写 / 101 个源码文件 / 19 个测试文件。
  与设计文档 §1.2 一致：101 个源码文件、19 个测试文件、`Box` 70 / `Text` 68 个文件、`useStdout` 13、`Static` / `AlternateScreen` / `RawAnsi` 各 1；`ScrollBox` 不在清单里。
  §1.2 写的「35 种 props」是手工估计，脚本实测 Box/Text 共 46 种（另有 RawAnsi 2、Static 1、spread 2 行）。
  §1.5 的「11 处 stdout.write」实际是 16 处终端序列：多出 `terminalCapabilityManager.ts:40` 的 `writeSync` 清理序列，以及 bug / copy / export / debug 四个命令的 OSC52 直写。
- 变异自证（真实仓库）：临时新建 `packages/cli/src/ui/__mutation_probe.tsx` import 一个 ScrollBox →
  `bun run tui:surface --check` 打出 `❌ 渲染端口面变了`，rc=1；删除后 rc=0。
- `bun test ./tests/scripts/tui-surface.test.ts`：16 pass，覆盖四种导入形态、注释剥离、JSX 表达式含 `>`、
  env 别名、直写分类，以及「多一个符号 / prop / 环境变量签名都变、计数变化签名不变」。
- 全量 `bun test`：13357 pass / 0 fail；`make build` rc=0，`will always be undefined` 0 处。
