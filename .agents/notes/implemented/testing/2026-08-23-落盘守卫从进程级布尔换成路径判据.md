# 能力缓存落盘守卫从「进程级布尔」换成「路径判据」，写盘路径由此可测（issue #65）

`packages/core/src/llm/model-capabilities.ts` 原先用一个单向布尔 `persistDisabled` 兜住
「测试进程不得写用户真实 `~/.sid-code/model-capabilities.json`」（那次事故把开发机上已采集
的 2919 条抹成 1 条）。它防住了事故，但代价是反过来的：`bun test` 同批多文件跑在同一进程里，
任何测试文件调一次 `__resetCapabilityCacheForTest()` 就永久置位它，于是 **`persist()` 的写盘
路径在整个测试套件里从来没被执行过** —— D7 丢更新 bug 能潜伏到 PR #63 才被发现，部分原因
就是「不方便测，于是没测」。PR #63 加 `__enablePersistForTest()` 绕过，又引入「复位靠 afterEach
自觉」（漏写即泄漏到同批后续文件，正是当年事故的形态）和「同一开关两种相反语义」。

## 决定了什么

采纳 issue #65 的**方案 A**，并按它自己提的那条警告修正了判据方向。

1. `packages/core/src/config/paths.ts` 新增 `isRealUserSidHome()`：判断当前解析出的配置根
   目录是否**正好等于** `join(homedir(), ".sid-code")`。判据是**相等**而非前缀 ——
   `SID_CONFIG_DIR=~/.sid-code/sandbox` 写的是另一份文件，没有理由拦它。
2. `model-capabilities.ts` 删掉 `persistDisabled`，换成无状态的
   `isPersistBlocked() = NODE_ENV==="test" && isRealUserSidHome()`。测试态且未重定向 → 拒写；
   测试态但已重定向到 tmpdir → **照写**（写盘路径因此天然可测，且不需要任何后门）；
   生产态 → 永远写（生产二进制里 `--define process.env.NODE_ENV='"production"'`
   把这个比较编译期折成 `false`，见 `tests/build/node-env-define.test.ts`）。
3. **拆开两个曾被同一个布尔绑在一起的不变量**。`maybeTriggerMissRefresh()` 原先也读
   `persistDisabled` 来实现「单测不得发真实 HTTP」。这两件事没有共同判据：一个判**路径**，
   一个判**测试态本身**。共用一个开关的后果是测试为了验证写盘就顺带打开了触网（反之亦然）。
   现在触网许可独立成 `missRefreshTestOptIn`，由 `__allowMissRefreshInTest()` 打开、由
   **语义相干的** `__resetMissRefreshStateForTest()` 关闭 —— 后者是验证防抖/退避的测试
   本来就必须在 beforeEach 调的，所以复位不新增任何「记得清理」的负担。
4. 测试专用导出收敛：`__enablePersistForTest` → `__setCatalogMetaForTest`（只注入元数据，
   不再兼任开关），新增 `__isPersistBlockedForTest()` 供门禁直接断言判据本身。
   `__resetCapabilityCacheForTest()` 不再兼任写盘开关。
5. 新门禁 `packages/core/tests/llm/model-capabilities-persist-guard.test.ts`（5 个用例）。
   受检文件**动态发现**（扫 `packages/core/tests/` 下 import 了该模块的文件），不写死清单 ——
   写死的话新增测试忘登记就不覆盖，而且没有任何东西会红。

## 放弃了什么（以及为什么不选）

**issue #65 的方案 B（保留布尔 + 静态门禁扫「调了 `__enablePersistForTest` 的文件必须设
`SID_CONFIG_DIR`」）**：改动面确实更小，但它把两个新问题都留着 —— 复位仍靠自觉，一个开关
仍有两种相反语义。而且静态扫描在这里格外弱：`no-real-path-writes.test.ts` 自己的注释已经
写明「白名单是穷举式防线，每漏一个类就多一个缺口」，再加一条穷举项等于把已知缺陷复制一遍。

**「设了 `SID_CONFIG_DIR` 就允许写」这个更简单的判据**：issue 正文自己就点了这个雷，实测
确认它是真雷 —— 把判据改成 `!process.env.SID_CONFIG_DIR` 后，新门禁的场景 3 立刻报红
（一个 `SID_CONFIG_DIR=$HOME/.sid-code` 的测试会被判成"已隔离"，照样抹掉用户数据）。

**只用路径判据、不要 `NODE_ENV` 那一半**：测试**默认**就安全（preload 已重定向），看着够用。
但一个显式 `delete process.env.SID_CONFIG_DIR` 的测试会立刻恢复成能写用户真实文件 ——
那正是事故的原始形态。两个条件都要，实测见下面场景 1。

**扩 `no-real-path-writes.test.ts` 的静态扫描来覆盖这里**（issue 验收里提的一个可能路径）：
不选。该文件自己的注释说明了这个手法对**间接**落盘结构性无效，而这里的落盘正是间接的
（测试只调 `learnFromError` / `syncExternalCatalogs`，内部才 `persist()`）。按判据式而非
穷举式立门禁，所以新门禁走「假 HOME 起子进程 + 观察副作用」，与
`tests/build/no-real-trajectory-writes-runtime.test.ts` 同源。

**在本进程内断言，不起子进程**：做不到。实测 `homedir()` 在进程内**不随
`process.env.HOME` 改变**（`bun -e '改HOME后再调homedir()'` 仍返回原值），只有以新 HOME
**启动**的进程才会变。所以"目标等于真实家目录"这一支在本进程里根本构造不出来，
除非真去写用户家目录 —— 那正是要防的事。

**把 `model-capabilities-concurrent-write.test.ts` 里那条「persistDisabled 为真时一个字节都
不写」原样留着**：它断言的是**旧守卫的机制**，而正是那个机制造成了 issue #65。改成断言
「普通单测路径（只 reset、不做任何解锁）也能落盘」。原不变量没丢，搬进了新门禁的场景 1
（在那里才验得了它）。

## 拿什么证明它生效了

**六次变异自证**（逐条把生产代码改坏，确认门禁报红，然后从备份恢复并核对 `MUTATION` 计数归零）：

| 变异 | 报红情况 |
| --- | --- |
| `isPersistBlocked()` 恒 `false` | 场景 1、场景 3 双红（`2 fail`） |
| `persist()` 里守卫早返回改成 `if (false)` | 同上两条，且是**副作用断言**报的（`守卫失效：… 写进了真实家目录路径`），不只是 stderr 探针 |
| 判据换成错的 `!process.env.SID_CONFIG_DIR`（issue 点名的误写法） | 场景 3 单红（`4 pass 1 fail`）—— 这条正是为它存在的 |
| miss 触网守卫忽略许可（恒拦） | catalog-strategy `2 fail`（触发 + 防抖两条），证明它们不是 false gate |
| 去掉 miss 刷新的退避检查 | catalog-strategy `1 fail`（退避那条） |
| 让命中也触发刷新 | catalog-strategy `1 fail`（「命中不触发」那条） |

**正向**：新门禁 `5 pass 0 fail`（0.54s）。场景 4（`NODE_ENV=production` + 未重定向 → 应当
写进假家目录）是门禁的自证项，它绿说明"检测假家目录有没有 `model-capabilities.json`"这套
逻辑真的能观察到污染，场景 1 的绿因此不是恒真的。

**回归**：`bun run affected-tests:run`（判定 selective，选中 `config/` + `llm/`）
→ `2161 pass 0 fail`（21.03s）。`make build` 通过并过自检；按 CLAUDE.md 的 worktree 教训
显式 grep 了 `will always be undefined`，**零命中**（新增导出 `isRealUserSidHome` 真的进了产物）。
`bun run lint` / `format:check` / `lint:boundary` 三条全绿（format 首次报了新文件排版，
跑 `bun run format` 后复检通过）。

**方向自检**：这次服务「更准」（消灭一类不可测路径 = 减少同类 bug 潜伏）与「可观测」；
用「更安全」换来的不是妥协 —— 拒写不变量一条没松，只是判据从进程状态换成路径事实。
代价诚实记在门禁注释里：受检面限于 `packages/core/tests/` 下 import 该模块的文件
（实测 10 个，0.4s），不扫整个 `llm/`（37s，翻进门禁不划算）。
