# G2 用例 A10-restart-no-readd：运行器加 `print` 步骤，守住「删掉已补入的键，重启不再加回」

## 决定了什么

运行器的 `after` 从 `DaemonStep[]` 扩成 `AfterStep[]`（`DaemonStep | PrintStep`）。`PrintStep` 在同一隔离环境里再跑一次 `-p`，相当于一次重启，可以带 `prepare` 先改磁盘状态。各步骤的 `exitCode` / `stderr` 按顺序放进 `RunOutput.steps`。步骤夹具和主夹具走同一套 `${CASE_ROOT}` 替换与越界校验，抽成 `prepareStepFixture`，daemon 步骤也改用它。

用例 `A10-restart-no-readd`：
1. 预置 3 键配置后首次启动，触发补全（作为前置检查：必须打印补全提示，并补入 `effortLevel`）；
2. `prepare` 删掉 `effortLevel`；
3. 重启。

断言重启后不再打印补全提示，`effortLevel` 也没被加回。判据取自触发清单 A10 人工实测 ④（2026-11-05）。

这补上了 PR #638 Note 里记为未覆盖的那一半。

## 放弃了什么（以及为什么不选）

- **单点变异「去掉 `known.has(key)` 过滤」**：作废。2026-11-07 实测这条 survived。原因是 `backfillNewTemplateKeys` 有两道串联保护：模板哈希没变就直接返回，以及只补新增的键。只拆一道，另一道照样挡住。这说明配方选错了，不是测试空心。改成在 `runner.ts` 里把每次启动的增量补全换成全量补全 `backfillTeamDefaults()`，这条能杀死，而且对应的是更真实的退化形态。
- **做通用的「N 步脚本」DSL**：不做。两种步骤够用了，等第三种需求出现再抽象。

## 拿什么证明它生效了

- 步骤重构后 A5 的变异复跑仍然 2/2 killed，说明 daemon 步骤的行为没变。
- `bun test ./tests/smoke/`：15 pass。
