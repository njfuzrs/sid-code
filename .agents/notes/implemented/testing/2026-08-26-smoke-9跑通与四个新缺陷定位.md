# smoke-9 跑通：权限修复实测生效（113 → 0 denials），但暴露出「容器无外网却没关 web 工具」

## 决定了什么

跑完 SWE-bench Verified smoke-9（10 题，串行，85.2 min，agent 自报成本 ≈ $7.91），
入库两份报告（`evals/_reports/external/swe-bench-verified.smoke-9.{json,md}`）。
连续三轮（ZZZZ / ZZZZZ / ZZZZZZ）因「仪器有 bug」而没跑，本轮跑通。

**本次不改任何代码**，只做执行、验收与缺陷定位。三个必控变量的修复全部实测生效：

| 修复项 | smoke-8 | smoke-9 |
| --- | --- | --- |
| `permission_denials`（`--dangerously-skip-permissions`） | 113 | **0** |
| `llm_fatal`（429 重试修复） | 2 条 | **0** |
| `已补全团队默认配置字段`（占位 20 键） | 有 | **一行都没有** |

`solved_count` 5 → 8，但 10 条里 **6 条结论变了**（含 1 条退步），所以那个 8
不是可汇报的数 —— 判读仍按「先第一类指标、再分数」的顺序。

定位到四个缺陷，全部交下一棒修（理由见「放弃了什么」）：

1. **P0 容器无外网却没关 web 工具** —— 唯一的退步 `django-13964` 由它造成：
   40 轮跑满、**零编辑工具调用**、7/80 步（8.8%）打在必然失败的
   `web_search`/`web_fetch` 上，连试 5 个 Django ticket 编号想找上游 fix diff。
   修法：`build_agent_script` 的 PYCFG 里 `disallowedTools` 加这两个工具
   （占位键已在，改值即可）。**顺带一条设计问题**：SWE-bench 本来就不该允许查上游
   （查到 fix 就是看答案），现在查不到只是因为容器无外网 —— 那是运气不是设计。
2. **P1 judge 判分默认联网** —— `HF_HUB_OFFLINE=1` 只加在取题面处
   （`exec-swebench.sh:702`），判分那条 `$SWEBENCH eval` 没有，导致首次判分
   卡死 25 分钟零输出（`lsof` 显示 `104.244.43.229:https SYN_SENT`，
   而 dataset 本地已缓存）。加上后 8 分钟跑完。
3. **P1 轮次用尽被记成 `exit_status: user_interrupt`** ——
   `collector.ts:1656-1664` 用 `stop_reason !== "end_turn"` 做兜底，
   而 max-turns 收尾时最后的 `stop_reason` 是 `tool_use` → 落进 `user_interrupt`。
   `digest.ts:1138` 把它算进 `abnormal`，于是排查时看到「会话被中断」，
   真相是「预算花完了」。这两件事的处置完全不同。**这条影响所有真实用户会话，
   不只是评测。**
4. **P2 未加引号 heredoc 里的反引号被宿主求值** ——
   `exec-swebench.sh:1004/1009/1010` 三行 Python 注释带反引号，每题固定刷 5 行
   `行 955: quota.ts: 未找到命令`。本轮未造成实际损坏（容器内 20 键实测齐全），
   但最小复现证实同型能做到「命令真被执行」与「整段被静默吞掉」两种形态。

**最重要的一条判据教训**（写进文档 A7.5）：
**一个约束在被解除之前，可能正意外地承担着另一个约束的职责。**
smoke-8 那 113 次权限拒绝**碰巧**把 agent 逼回「只读本地代码库」这条正确路径，
所以 django-13964 反而 `solved`；权限一放开，它就有余力去走那条注定失败的路。
派生判据：修好一个必控变量后**必须逐题读轨迹**看「省下来的轮数花到哪了」，
只看总数会让「429 修复的 +3」和「新缺陷的 −1」互相掩盖。

## 放弃了什么（以及为什么不选）

- **放弃「本轮顺手把四个缺陷修掉」。** 理由有两条：① 缺陷 ③ 要动
  `trace/collector.ts` 的 exit_status 推断，而那片区域刚在 PR #122 立了
  20 条变异自证，混在一个「跑评测」的改动里 review 不了；② 按 CONTRIBUTING
  的 PR 单元判据，缺陷 ①②④ 是评测基建（`fix(evals):`）、③ 是产品侧归因
  （`fix(trace):`），本来就是两个可独立上线/回滚的单元。
- **放弃调 `SWE_MAX_TURNS`**（ZZZZZ.10 第 3 条一直挂着的 P1）。
  实测预判被证实：matplotlib 两条权限修好后**根本不撞顶**（23 轮 /
  40 轮但 `end_turn` 自然收尾）。`hit_max_turns` 只剩 django 两条，
  而 13964 的成因是白烧外网工具，**调轮数只会给白烧的轮数续命**。
  等 web 工具禁掉后再看新的 `hit_max_turns` 才有意义。
- **放弃优化 harness 搬运。** 三段计时第一次跑出真数：
  搬运 0.09 min + 收尾 0.23 min = **0.37%**，85 分钟里 84.9 分钟是模型在想。
  ZZZZZZ.5 立这三个字段时担心的「cp 40MB 掉在字段之外」确实存在过，
  但量级上从来不是问题 —— 这正是「先量再优化」省下的一次错误优化。
- **放弃开 `SWE_JOBS` 并发。** smoke-9 的用处是与串行的 smoke-8 并排读，
  这是判断「113 次拒绝没了」「429 不再终止整轮」的唯一方式。
  串行代价实测 5.3×（85.2 min ÷ 最慢 16.1 min），上界比 smoke-8 的 4.2× 更高，
  但那是拿到第二个干净基线之后才该花的。
- **放弃动工作区里那个 untracked 的 `.txt`**（另一路并行工作在写的）。
  代价是 `git_dirty=true`，报告因此标了「只可自比，不可外比」。
  按 CLAUDE.md §0 铁律，删错一个文件的代价远大于留着它。
  **顺带发现这个判据的一个副作用**：多任务并行的仓库里 `git_dirty` 几乎恒为 true，
  于是「只可自比」等于永久生效 —— 要做严格外比得在干净 worktree 里跑，
  **而不是去放宽这个判据**。

```bash

docker exec <x86 容器> sid-code --version

SWE_ARTIFACT=/tmp/sc-baseline/sid-code ./exec-swebench.sh run smoke-9   # SWE_JOBS 默认 1
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 SWE_GRADE_JOBS=4 ./exec-swebench.sh grade smoke-9
```

验收表 9 项里 **8 项通过**，唯一不达标的是 `hit_max_turns`（1 条，已归因到缺陷 ①）：

- `permission_denials` 总和 = **0**（smoke-8 是 113）
- `已补全团队默认配置字段` / `✗ permissionMode: 无效值`：**10 份日志各 0 次**
  （`grep -c` 逐份核过，不是抽样）
- `llm_fatal` = **0**；smoke-8 被 429 打断的 xarray-6461 与 pytest-10081
  这轮都 **solved**
- `<iid>.trajectories/`：**10 个目录全在**
- `run-meta`：`git_commit=454cf79c` / `cost_limit_usd=0.0` / `jobs=1` /
  `effort_level=max` / `artifact_sha256=b634e8f9…`
- 三段计时不变量 `setup + agent + extract === wall`：**10/10 逐题成立**
- `graded_ok=PASS`、`gold_ok=PASS`、`link_ok=FAIL`（django-13964 零 patch 所致）

四个缺陷各自的举证（都不是「机理上讲得通」）：

- **①** `trace-digest` 逐条工具序列：django-13964 共 80 步，
  bash 18 / grep 11 / read 4 / **web_search 5 + web_fetch 2** /
  **edit+write 0**。轨迹里能读到它连试 32335/32340/32360/32365/32369
  五个 ticket 编号，还试了 `pip download django==3.2.13`。
- **②** `lsof -p 46323` → `TCP 192.168.0.124:65513->104.244.43.229:https (SYN_SENT)`；
  加两个 `HF_*_OFFLINE=1` 后判分 8 分钟跑完（此前 25 分钟零输出、零 eval 容器）。
  失败形态难归因的原因也查清了：`cmd_grade` 把输出接到 `| tail -30`，
  buffer 满之前一个字不出来 → 「卡住」被伪装成「慢」。
- **③** 两条撞顶题 metadata 里 `exit_status=user_interrupt`，
  而 `grep -c 达到最大轮次限制` = 2；同时 matplotlib-26466 也跑了 40 轮但
  `exit_status=end_turn`、`hit_max_turns=False` —— 说明 record 那边的
  字符串判据是**对的**，错的是 collector 的兜底推断。成因定位到
  `collector.ts:1656-1664`。
- **④** 写了最小复现脚本，两种形态都跑出来了：
  `` `echo INJECTED` `` 在未加引号 heredoc 里真的执行；
  `` 判 `costLimit <= 0` 为错 `` 整段被吞成「判  为错」。
  同时实测容器内 `settings.json` 20 个顶层键齐全、
  `costLimit=0.0`/`quota.costLimit=0.0`/`effortLevel=max` 值全对
  —— 所以判 P2 不判 P0。
