# G2 用例 A11-remote-policy：运行器加 `services:` 桩服务，守住「远程策略下发的 deny 真的生效」

## 决定了什么

运行器实现了总纲 §3.3 预留的 `services:`。新增三个字段：

- `SmokeCase.services: Record<name, { handler }>`：运行器在进程内用 `Bun.serve({ port: 0, hostname: "127.0.0.1" })` 起桩服务。地址通过 `SettingsContext.services` 交给用例；收到的请求只记方法、路径和是否带 Authorization，不记 token 本身，放在 `RunOutput.services`。不论用例成败，都在 `finally` 里 `stop(true)`。
- `SmokeCase.config`：往隔离配置目录预置文件，比如设备凭据，权限 0600。写 `settings.json` 会被拒绝，避免和 `settings` 字段各写一份。

用例 `A11-remote-policy` 的流程：桩后端的 `/api/v1/ctl/policy` 返回 `{source:"remote", permissions:{deny:["Bash(rm *)"]}}` 并带 ETag，其余路径返回 204；`backend.url` 指向桩服务；预置一份设备凭据；回放 `rm -f trash.txt`。断言四项：

- `PermissionDecision{bash, outcome=deny, source=rule, step=skip-deny-rule}` 恰好 1 条；
- `trash.txt` 没被删；
- 策略接口恰好被请求 1 次，且带 Authorization；
- `policy-cache.json` 的 `last_status=200`，etag 与 deny 和下发的一致。

运行器默认带 `--dangerously-skip-permissions`，deny 照样生效。企业策略要守的正是这一点：用户自己跳过权限检查，也绕不开管理员下发的 deny。

## 放弃了什么（以及为什么不选）

- **§3.3 草案里的「就绪探针」和「端口经环境变量注入」**：不照搬。桩服务跑在运行器进程内，`Bun.serve` 返回时已经在监听，不需要探针。A11 的地址要写进 settings.json 的 `backend.url`，环境变量传不到那里，所以改成用回调参数传递。服务日志并入失败输出这一条，用 `RunOutput.services` 的请求记录代替。
- **独立子进程起桩服务**：不选。会多出端口回传、进程回收、日志收集三件事，A11 / A12 的桩只需要几行 handler。
- **同时守远程预算**：本次不做，预算接口返回 204。预算越线要构造 used ≥ limit，并断言提示或硬停的行为，那是另一条判据，等触发清单 A11 预算那一半实测后再加。

**期望来源的缺口（必须点破）**：触发清单 A11 还没有人工实测通过，它依赖企业后端。这条用例的期望来自 2026-11-07 用桩后端跑真二进制的探针，语义已经回源码核对过（`RemotePolicyLoader`、`setPolicyRules`）。这违背了「期望取自人工实测」的约定，台账里已标注，等 A11 人工实测完要回来对一遍。

## 拿什么证明它生效了

- `make build && bun run smoke`：14 例全过；A11 单例 0.3s。
- `bun run smoke:mutate -- A11-remote-policy`：2/2 killed。
  - `policy.ts` 启动时不再拉远程策略：deny 那条 `PermissionDecision` 变成 0 条。
  - `rule-loader.ts` 的 `setPolicyRules` 不注入规则：策略拉到了、缓存也写了，但执行层不认。这是「下发成功、执行不认」的形态，只断言缓存文件是抓不到的。
- 写用例前的探针：真二进制依次请求 `/api/v1/ctl/{policy,budget,whoami}`，都带 Bearer；`SessionStart.permission_config.rules.deny={policySettings:1}`。
