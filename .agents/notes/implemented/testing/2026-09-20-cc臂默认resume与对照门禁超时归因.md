# cc 臂默认 resume；对照门禁不再把超时未落盘当成权限档不同源

## 决定了什么

三件事，都是 A3（cc + sonnet，54 题）开跑/收尾时踩到的、会让对照数字不可用的缺口：

1. **`run-claude-code-contrast.sh` 默认不再 `rm -rf "runs/$JOB"`。**
   harbor 对同名 job 是 resume（有 `result.json` 的 trial 跳过）。
   旧行在每一轮（含 `w3-run.sh` classify 后再跑、含额度中断后续跑）把已计分题连同分母清掉。
   只有显式 `SID_CC_WIPE=1` 才整目录清空。A3 实测：第 2/3 轮删的是 classify 挑出的坏 trial，已计分的 43 题 checksum 未动。

2. **`check-comparison-parity.py`：cc 无 `type=result` 事件（超时/被杀，`cc_denials=None` 但 token 非 0）改为 skip，不算「权限档不同源」。**
   A3 的 `feal-linear-cryptanalysis` 跑了 2h 被 `AgentTimeoutError` 杀掉，txt 有 517 行 assistant 消息、就是没有 result 事件。旧版结论是「1/54 题权限档不同源，分数不可互比」——归因错。

3. **「分数不可互比」现在非 0 退出**（rc=1 档位不同源 / rc=2 零样本对照）。以前只打印 ⛔、exit 0，CI 与串联脚本会当成功。

归档 A3 单臂 `results/w3-cc-sonnet-54.json` 与配对 `results/w3-sid-sonnet-66__w3-cc-sonnet-54.json`（`runs/` 不入库）。

## 放弃了什么（以及为什么不选）

- **给 cc 加一层「超时也从 txt 推断 denials」** —— 没有 result 事件就没有 `permission_denials` 数组，猜 0 会把「没采到」写成「零拒绝」，正是 08 号 §4.1.1 警告的形态。skip 出对照分母更诚实。
- **把 feal 那题从能力账里排除** —— 它调过模型（token 非 0）、verifier 判了 0 分，是真实超时，不是安装失败。排除它会缩小分母且方向对我们有利。
- **开跑前修 Node/npm 本地镜像** —— 用户明确要求先跑、问题落盘后修。第 1 轮 11 题装失败已被 classify 自动重跑进分母，镜像化仍该做，但不挡本轮对照。
- **改 sid 臂对齐「无条件清空」** —— 那是在拆 A1/A2 已经验证过的 resume。

## 拿什么证明它生效了

```text
python3 test-check-comparison-parity.py
  → 通过 12 / 失败 0
  ① 两侧 denials=0 + sid allow>0 ⇒ rc=0
  ② 超时无 result + 一题正常对照 ⇒ 超时 skip、其余无反证、rc=0、不写「权限档不同源」
  ③ cc 真有拒绝 ⇒ rc=1 且结论含「不可互比」
  ④ 全部 skip ⇒ rc=2（零样本对照，不是全绿）

python3 check-comparison-parity.py runs/w3-sid-sonnet-66 runs/w3-cc-sonnet-54
  → rc=0
  → ➖ 1 题不参与权限档对照: feal-linear-cryptanalysis
  → ✅ 53/53 题无反证（cc 侧无 allow 计数，弱于 mswea 同档判定）

python3 w3-summary.py runs/w3-sid-sonnet-66 runs/w3-cc-sonnet-54
  → 配对 n=54，sid 46.3% vs cc 50.0%，95% CI 重叠
  → ⛔ 别把点估计之差讲成「我们更好」

python3 test-w3-classify.py → 通过 24 / 失败 0
```
