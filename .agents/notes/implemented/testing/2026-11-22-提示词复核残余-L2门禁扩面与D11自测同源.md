# 提示词复核残余落地：L-2 门禁扩面、D-11 自测同源、D-06 补评测数据

## 决定了什么

对 2026-11-19 那份缺陷清单做了逐项复核后的**残余修复**，共四件事：

1. **L-2 门禁覆盖面从 6 个工具扩到 13 个**（`tests/scripts/system-prompt-schema-parity.test.ts`）。
   原实现只覆盖 bash/read/write/edit/glob/grep，而 `tool_search` / `team_message` /
   `team_create` / `structured_task_get` / `structured_task_create` / `send_message` /
   `schedule_wakeup` 同样声明 `zodSchema`、同样有 `.optional()` 参数，属于「漂移了也看不见」
   的盲区。补入后 13 个工具的 optional 参数全部纳入「提示词是否说成必须」的对账。
2. **D-11 度量脚本消除「注释说同一段代码、实现是两份复制」**（`scripts/prompt-section-signal-rate.ts`）。
   抽出 `applyEventLine(ctx, line)`，`scanEvents`（读真实轨迹）与 `selfTest`（喂合成事件）
   改为共用它。这样 self-test 才真的在验证扫描口径，而不是验证一份副本。
   同时补两条断言：`--days` 缺省必须是 30（口径写死）、`<precedence-chain>` 必须显式列为
   「不可度量」（不得从报告里消失）。
3. **三处文档/注释漂移**：`packages/core/src/tool/registry.ts` 别名表注释（原写「表为空」，
   实际已有 `bg_task_get → task_output`）、`plugins/compliance/skills/governance/SKILL.md`
   的「七大输出红线」（主段标题已去掉计数）、L-1 审计 Note 声称
   `<precedence-chain>` 已在度量脚本里按不可度量列出（实际没有，本轮补进 `SIGNALS`）。
4. **D-06 补评测数据**：在 `evals/_judge/gold-cases/` 新增 3 个单根因诊断 case
   （`case_021/022/023`），分别覆盖「`/context` 缺行是守卫不满足而非未接线」、
   「`bun test tests/` 比 `./tests/` 慢是位置参数子串匹配」、「CI 5000ms 超时是 bun 默认 5s
   flake 而非回归」。每个 case 都写明了唯一根因 + 需要排除的竞争解释，
   用来验证模型在「候选根因默认 ≥2」与「RL-007 禁止凑数」冲突时不会硬凑第二个。

另外两处**判定为不需要改**，理由记在下面「放弃了什么」里。

## 放弃了什么（以及为什么不选）

- **不为 D-07 改代码**。上一轮复核曾判它「只接了 northstar、没接 `/context`」，
  回源码核对后是**误判**：`packages/cli/src/command/commands/context/context.ts`
  已把 `ctx.traceCollector.getAckOpenerStats()` 传给 `renderContextReport`，
  `context-render.ts:471` 也有 `totalTurns > 0` 的渲染守卫（0 表示「没发生过」，不显示是设计）。
  误判的成因是我只 grep 了 `ack_opener`（下划线字段名），而接线用的是 camelCase 的
  `ackOpener` option。**这条写进 Note，提醒下一个复核者按 option 名而不是数据字段名查接线。**
- **L-2 不改成「扫目录自动发现全部工具」**。工具构造参数各不相同（需要 fake 依赖），
  Bun 没有 `import.meta.glob`；而 `zodSchema = xxxSchema()` 是间接定义，
  正则解析必然漏解。手工清单 + 注释写明「新增工具必须补进来」是当前成本/可靠性最优解；
  13 个已覆盖本次普查中真正相关的面（7 个补入工具当前均无漂移）。
- **D-13 仍不改身份段**。身份段（`system-prompt.ts:933-946`）保持三档共用四行，
  不加多 agent 编排差异化标签——理由与代价见
  `.agents/notes/rejected/feature/2026-11-19-身份段不加多agent编排差异化标签.md`
  （本轮补的 rejected note）。
- **不给身份段加机械门禁**。唯一能写的是「断言不含某些词」，会在合理措辞调整时误报，
  而它要防的「诱导过度使用」恰恰是措辞级判据测不出来的。约束落在 Note + review。

## 拿什么证明它生效了

- `bun test ./tests/scripts/system-prompt-schema-parity.test.ts` →
  **5 pass / 0 fail**（13 个工具的扩面没有引入误报）。
- `bun test ./tests/scripts/prompt-section-signal-rate.test.ts` →
  **12 pass / 0 fail**（含新增的「缺省 30 天」与「`<precedence-chain>` 必须不可度量」两条）。
- 身份段未改的取证：`grep -rn "workflow\|team_create\|multi-agent\|多 agent"
  packages/core/src/config/system-prompt.ts` 在身份段区间（`:933-946`）零命中。
- `bun run verify:agent-note` 通过（Note 形态：路径、Status、三段齐全）。
- 本轮改动不触碰提示词文本与工具行为，因此不需要跑 G2/G4 冒烟；回归由上述 G1 单测守住。
