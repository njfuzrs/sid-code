# G2 用例 A10：团队默认配置的首次启动迁移链（20 → 14 键、预置配置补 17 键不覆盖）

## 决定了什么

新增两条 G2 用例，覆盖台账 A10 的「首装 + 首次启动的整条迁移链」：

- `A10-first-launch-chain`：settings.json 是首装后的模板（只把 `model` / `availableModels` 换成 replay 模型）。首次启动后键集合 = 模板 20 键去掉 6 个空占位键（v4/v5 按「值等于代码默认」清掉）= 14 键；`state/migrations.json` 记 `migrationVersion=7`，`teamDefaults.keys` 为 20 个。
- `A10-preset-backfill`：预置 3 键配置（`model`、1 条 `availableModels`，其 `apiKey: "${MY_KEY}"`、`quota: {}`）。stderr 的补全提示恰好列出 17 个键，与模板差集一致；`model` / `availableModels`（含占位符原文）/ `quota` 原样保留，`language` 补成 `zh`；落盘 3 + 17 − 6 = 14 键。

两条的判据都取自触发清单 A10 的人工实测（2026-11-05，HEAD `0b6b2d0e`）①③ 和「留余地 (a)」。期望键集合从模板 import 后现场计算，模板顶层键数不是 20 时直接红，提示回触发清单核对，不会因为模板改了就静默跟着变。

运行器给 `RunOutput` 补了 `configDir`，断言启动后的 settings.json / state 文件要用。

放 G2 的理由与台账一致：每个迁移的单测都在，但「20 → 14」是 v1 补全加 v4/v5 清理按 runner 顺序叠加出来的结果。

## 放弃了什么（以及为什么不选）

- **覆盖「删掉已补入的键，重启后不再加回」**：本次不做。这需要同一配置目录跑两次进程，运行器目前只支持单次。要做就得给运行器加多步用例，等到有第二个需要多步的用例再一起设计。
- **覆盖 install-template.sh 的首装写文件**：不在 G2 做。首装是 shell 片段，会下载二进制、写 RC 文件，用例由运行器直接写入「首装后的文件」。
- **第一版变异配方**（把模板 quota 换成 `{costLimit:1}` 再补全）：作废。`mergeMissingTopLevelKeys` 本来就跳过已有键，这条变异什么也没改坏，结果 survived 是配方无效，不是测试空心。改成把 `settings.ts` 里 `if (!(key in raw))` 换成 `if (true)`，即「补全退化成覆盖」。

## 拿什么证明它生效了

- `make build && bun run smoke -- A10-first-launch-chain A10-preset-backfill`：两条都通过。
- `bun run smoke:mutate -- A10-first-launch-chain A10-preset-backfill`：3/3 killed。
  - `move-stray-app-config-keys.ts` 不删灌入键：首次启动后仍是 20 键。
  - `settings.ts` 补全不跳过已有键：用户的 model 被模板值覆盖，模板占位 key 让启动 exit 1。这是真实用户会遇到的症状。
  - `runner.ts` 注册表丢了 v1：stderr 里没有补全提示。
- 写用例前用真二进制做过两次隔离探针，分别得到 20 → 14 键，以及补全 17 键、原值保留，与触发清单一致。
