# 恒思考门禁补上「族级不变量」与判定链上游扫描，单向缺口不再靠人肉比对

## 决定了什么

复核 #818 的落地情况时发现两条门禁各有**一处覆盖缺口**，都不构成本次修复的错，
但都会让下一次同型缺陷静默通过。两条都在 `packages/core/tests/llm/thinking-off-floor.test.ts`：

**① 「always-on ⇒ 有非空档位表」是单向的，缺的方向补成族级不变量。**

原门禁只查「声明了 `always-on` 却没有档位表」。反方向（有档位表、但模型其实恒思考却没标
`thinkingMode`）没有任何覆盖 —— `o3` / `o3-pro` 就是这样漏过去的（`c4f8c297` 才补上）。

按要求的方向补，但**不能**用「双向恒等式」（该修法已否决，反例与理由见
`rejected/testing/2026-11-14-恒思考与档位表不是双向恒等.md`）。落地的是**族级不变量**：

```ts
// protocolKind === "o-series" ⇒ thinkingMode === "always-on"
const oSeries = getRegistryEntries().filter(([, e]) => e.protocolKind === "o-series");
expect(oSeries.length).toBeGreaterThanOrEqual(5);   // 防空集：判据形同虚设也要红
```

只对 `o-series` 立这条，因为它是注册表里**唯一「族 = 恒思考」的封闭集合**
（`o1` / `o3` / `o3-pro` / `o3-mini` / `o4-mini` 五个全部不接受关闭思考）。
`glm-openai`（17 条里只有 3 条恒思考）与 `grok-openai`（6 条里 3 条）都是混合族，
对它们立族级判据会把 `glm-5.2` / `glm-4.7` 这批能关思考的模型误判。

**② 防耦合扫描补上判定链上游 `finalizeThinkingControl`。**

原门禁只扫 `dialect/thinking-off-floor.ts` 与 `dialect/always-thinking.ts` 两个文件。
但 `locked-on` 真正落地的地方在 `effort.ts` 的 `finalizeThinkingControl`——有人在那个函数里
写 `if (model.startsWith("glm"))` 就能绕过两个入口的规则，而门禁不会红。

扫描目标从一个文件列表改成 `{ rel, fn? }` 数组，`fn` 存在时**按函数体扫**（大括号配平截取）。
`effort.ts` 只能按函数体扫：整文件扫会命中合法的 env 变量名 `CLAUDE_CODE_EFFORT_LEVEL`
（`/claude/i` 直接命中），加行级豁免注释会让门禁变松 —— 按函数体扫是范围最紧的做法。
`catalog.ts` 不扫：它只是 re-export，且含合法的族标识（`"deepseek-openai": deepseekOpenAIDialect`）。

## 放弃了什么（以及为什么不选）

- **双向恒等式 `always-on ⇔ 有非空档位表`**（方案 §4.3/§4.4 原本的建议）——
  「支持 effort 档位」与「思考能否关闭」正交，注册表里现有 4 条有档位表但能关思考的条目，
  照做会误判或恒红。完整反例见 rejected note。
- **`effort.ts` 整文件扫** —— 会命中 `CLAUDE_CODE_EFFORT_LEVEL`，只能靠豁免机制放行；
  豁免机制本身是门禁的松口（明天一个 `// ignore` 就能绕过扫描）。
- **给 `finalizeThinkingControl` 加行级豁免注释** —— 同上，能不用豁免就不用。
- **把族级判据推广到 `glm-openai` / `grok-openai`** —— 它们是混合族，判据不成立（见上）。
- **扩大扫描到 `catalog.ts` / `model-capability-filter.ts`** —— 前者是纯 re-export，
  后者的族名是合法标识；扫它们只会产出假红，进而诱发「把断言删掉」。

## 拿什么证明它生效了

**变异自证两条（CLAUDE.md 要求：先改坏，看它报什么）**：

```
删 o3 的 thinkingMode
  → error: o3 属于 o-series 却没声明 always-on
  → 24 pass / 1 fail

finalizeThinkingControl 里加 if (model.startsWith("glm")) return cap;
  → error: effort.ts 的 finalizeThinkingControl 出现了模型名字面量
  → 22 pass / 3 fail
```

两处变异都用 `cp` 备份 + `trap` 恢复，恢复后校验：`thinkingMode: "always-on"` 计数仍为 17，
`effort.ts` 中 `model.startsWith("glm")` 计数为 0。

**正常态**：`bun test ./packages/core/tests/llm/thinking-off-floor.test.ts` → 25 pass / 0 fail。
