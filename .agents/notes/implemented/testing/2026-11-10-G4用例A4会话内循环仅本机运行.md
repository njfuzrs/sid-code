# G4 用例 A4-loop-tui：TUI 里等一次真实的 /loop 触发，只在本机跑

## 决定了什么

- **新用例 `tests/smoke/cases/A4-loop-tui/`**（G4）：真 TUI 里 `/loop 1m 检查一下 git status`，看到「已创建循环任务（每1 分钟」后不再有任何输入，等调度器到点注入、回放夹具跑完一轮（`bash git status` → 结束语）。断言：`ScheduledFire{origin:loop, recurring, durable:false, dispatch:inject, outcome:fired}`、`ScheduledInject{queued:false}`；两者 `task_id` 对得上；任务文本的 `UserPromptSubmit` 恰 1 条且晚于 `ScheduledInject`（证明那一轮是注入出来的，不是输入框提交的）。期望取自核心功能触发清单 A4 的人工实测（2026-11-05，TUI 会话 `20261105-191734-b2249982`），`5m` 换成 cron 最小粒度 `1m`。`ScheduledInject.outcome` 是那次实测之后才加的字段，不断言。
- **运行器两个字段**（`tests/smoke/lib/types.ts` / `runner.ts`）：
  - `localOnly?: string`：`CI` 环境变量非空且不是 `false`/`0` 时输出 skip，原因是 `仅本机运行：<这段文字>`，进 step summary。本机 `smoke:tui` / `smoke:mutate` 照常跑。判 CI 的逻辑抽成 `isCI()`。
  - `timeoutMs?: number`：覆盖单例总超时（缺省 60s）。A4 设 180s，「到点跑完一轮」那一步的 `wait` 设 120s（60s 周期 + ≤6s 抖动 + 30s 轮询 + 余量）。
- 三条变异配方：宿主不接 `onFire`、注入器不跑主循环、TUI 会话不启动调度器。
- 这是后续规划 §6 裁决 2 的落地（PR-3）。

**牺牲了什么**：「更准」换「更快」——PR 上没有 TUI 注入链路的守护，从合入到下一次本机运行之间最长有 7 天窗口（每周调度是 PR-9，还没落地；在那之前靠手动跑）。进程内那段链路仍由 G1 单测守（`scheduled-fire-telemetry` / `scheduled-inject` / `loop-every`）。

## 放弃了什么（以及为什么不选）

- **给调度器加只用于测试的轮询间隔开关**：总纲「不做什么」里的「为了上冒烟改产品行为」。裁决 2 已否，理由不重复。
- **用 `CI` 之外的专用变量（如 `SID_SMOKE_LOCAL=1`）开本机用例**：本机每周调度、手动 `smoke:tui` 都得记得带它，忘了就永远 skip——保鲜静默失效，和要防的失效形态一样。反过来依赖 `CI`：GitHub Actions 恒设 `CI=true`，ci.yml 没有覆盖它。
- **用 `platforms` 字段表达「仅本机」**：CI 的 macOS runner 也是 darwin，平台判不出「是不是 CI」。
- **把 `localOnly` 写成布尔**：skip 原因要写清「为什么 CI 不守」，布尔只能让运行器打印一句通用文案，读 step summary 的人还得去翻裁决。

## 拿什么证明它生效了

（worktree `sid-code-wt/a4-loop-tui`，`make build` 产物）

- 本机实跑：`bun run scripts/smoke/run.ts A4-loop-tui` → `[PASS] A4-loop-tui (30.6s)`；再跑一次 `--keep` → `(60.6s)`，轨迹顺序 `ScheduledInject{task_id:a7e5fb28, queued:false, outcome:injected}` → `UserPromptSubmit{prompt:"检查一下 git status"}` → `ScheduledFire{origin:loop, lag_ms:14217, outcome:fired}` → `PreToolUse{bash}` → `TurnComplete`。两次耗时落在裁决预估的 30–96s 内。
  - 注意 `ScheduledFire` 在文件里排在 `ScheduledInject` **之后**（同一毫秒级先后）：调度器先调 `onFire`、再发 `ScheduledFire`。所以断言只要求「Inject 早于 UserPromptSubmit」，不要求 Fire 早于 Inject——那样会锁住一个想象中的顺序。
- CI 形态：`CI=true GITHUB_STEP_SUMMARY=… bun run scripts/smoke/run.ts --layer G4` → `[PASS] A1-dialog`、`[SKIP] A4-loop-tui — 仅本机运行：真等一次 cron 触发要 30–96s…`，summary 表里 A4 一行带原因。
- 运行器单测（`tests/smoke/smoke-lib.test.ts`）21 pass；变异自证：去掉 `localOnly` 分支 → 「CI=true → skip」红；`isCI` 不排除 `false`/`0` → 「判为本机」红。还原后 21 pass。
- 用例变异自证：`bun run smoke:mutate A4-loop-tui` → **3/3 killed**（宿主不接 `onFire`、注入器不跑主循环、TUI 不启动调度器，三条都在「到点自动跑完一轮」的 120s 等待上红）。复跑后 `git status` 无源码改动。
- 全量冒烟本机：`bun run smoke:tui` → `2 例：2 通过`（A1-dialog 1.5s、A4-loop-tui 60.6s）；`bun run smoke` → `22 例：22 通过`（G2 不受影响）。
