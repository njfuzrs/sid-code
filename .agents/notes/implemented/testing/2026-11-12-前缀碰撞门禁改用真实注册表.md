# 前缀碰撞门禁改用真实注册表（T6 / D8）——一条恒绿了三个月的门禁重新生效

## 决定了什么

把「常驻 × 延迟不得共享 ≥4 字符前缀」这条断言从
`packages/core/tests/tool/worktree-tools-not-deferred.test.ts` 挪到仓库根的
`tests/tool/prefix-collision-gate.test.ts`，取数改为 T0 的隐藏出口
`--dump-tool-meta`（经 `tests/helpers/builtin-tool-meta.ts`，spawn 一次、进程内缓存、
`SID_CONFIG_DIR` 指向 tmpdir）。断言本身四条：

- **两组都非空**：`live` / `deferred` 任一边为空时笛卡尔积退化成空集，门禁会重新恒绿，
  所以它要能自己先红。这一条正是原实现缺失的——原来的 registry 里
  `deferredToolNames()` 恒为空，`live × deferred` 断言从写下来那天起就没红过。
- **小写化后公共前缀 ≥4 的 live × deferred 组合为 0**。名字里混着 snake_case 与
  PascalCase，区分大小写会漏掉 `read` vs `ReadMcpResource` 这类碰撞；2026-08-17 的
  坍缩事故证明模型不按命名约定坍缩，门禁也就不能按命名约定给自己开豁免。
- **worktree / plan 四个工具在真实注册表里都是常驻**：`enter_`(6) / `exit_`(5) 两对是
  2026-08-17 事故的前缀对，任何一个被延迟，上面的笛卡尔积就会命中；这条先给出更直白的失败信息。
- **豁免名单的每条都真实存在碰撞且写了理由**：豁免键是「小写 + 字典序」的工具对，
  当前**为空**。改名或分层变化后失效的豁免会变红，避免它变成永久垃圾。

原文件保留两条**实例级**断言（`enter_worktree` / `exit_worktree` 的 `shouldDefer` 字段为
falsy、4 工具 Registry 的 `activeDefinitions` 全含且延迟名单为空），并在原处留了指明新位置的
注释：字段被加回去时那里先红，注册路径/分层变了（`alwaysLoad`、`keepLoaded`、MCP 前缀）
新门禁红，两层互补。

## 放弃了什么（以及为什么不选）

**不在 core 里重建一份注册表。** 那要么搬 44 处 `register()` 与它们依赖的会话对象
（T0 已否决的跨包重构），要么在测试里逐个 `new` 工具——后者正是原实现的失败模式：
手工清单只能覆盖「作者想到的工具」，漏掉的那部分不会让任何东西变红。

**不放宽小写化规则，也不预置豁免。** 小写化会让 `ReadMcpResource` 一旦延迟就同时撞上
`read` 和 `read_many`（T7 因此裁决「只加 `isEnabled`、保持常驻」）。为放过某个具体工具
而放宽规则，等于让门禁重演「为了不红而失明」的老路；豁免表留空、要求每条带理由与证据，
才让「放过」这个动作在 review 里可见。

**不把前缀阈值从 4 调大。** 调到 5 会让 `web_`（`web_fetch` vs `web_search`）这类
真实风险面漏网——而它正是本次变异自证命中的那一对；调到 3 会把大量正常同名族工具算成
碰撞，门禁天天红，最后一定被人关掉。

**不在本 PR 顺手做 T5（strict 预算门禁）。** 方案里 T5 + T6 合成 PR-B，但 T5 要改
`anthropic.ts` 的两个调用点并新增降级事件，与「把一条恒绿门禁修好」不是同一关注点；
本 PR 只做门禁改口径，可独立上线、独立回滚。
