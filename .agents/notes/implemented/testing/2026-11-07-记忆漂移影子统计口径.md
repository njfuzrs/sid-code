# 记忆漂移影子统计：口径固化成脚本，四档阈值与锚点多根判定

## 决定了什么

新增 `scripts/memory-drift-shadow-stats.ts` + `tests/scripts/memory-drift-shadow-stats.test.ts`，
为《20261102-07H2-漂移与维护-落地方案》的 T2/T3 提供上线前的影子统计。四处口径变更：

1. **年龄分四档（1 / 7 / 30 / 90 天）**，不只方案写的 7 / 30。理由是实测 7 / 30 两档在
   所有库都达不到方案的「覆盖率 ≤30%」（见验证段），没有更高一档就无法回答「N 取多少」。
2. **双口径分母**：`索引行口径`（`MEMORY.md` 里真实会被注入的行，与 `annotateIndexAges`
   的处理范围一致）+ `文件口径`（目录下全部记忆，参考值）。只给文件口径会系统性低估
   覆盖率——截断线外的文件根本不进 prompt。
3. **锚点多根判定**：`--extra-root` 可重复，任一候选根命中即算存在。monorepo 的记忆常写成
   包内相对路径（`src/api/x.ts` 实际在 `anka-app/packages/ontology-studio/src/api/x.ts`），
   只按仓库根判会把这批全部误判成失效。
4. **项目目录名派生直接调 `sanitizeProjectKey(resolveProjectRoot(root))`**，不手写 sanitize。

## 放弃了什么（以及为什么不选）

- **自动发现 workspace 包根**（读 `pnpm-workspace.yaml` / `package.json` workspaces 自动加候选根）：
  要把 pnpm / yarn / npm 三套配置都实现，且 `--all` 模式没有仓库根可发现。这次只需要
  对两三个已知仓库跑一次，手工传 `--extra-root` 成本更低、行为更可预期。
- **复用 `annotateIndexAges` 而不是内联正则**：它需要构造 `MemoryEntry`（key / value / scope /
  createdAt / updatedAt 五个必填字段），而统计只需要 `updated`。内联的索引行正则与它逐字
  一致，年龄走 `memoryAgeDays`（同一实现），口径不漂移的点由单测锁住。
- **据此外推 T3 可以上线**：数据不支持。iam-studio-fe 单根 37/38 条「全部失效」，加一个
  包根仍 27/38；抽查证明剩下的既包含「路径基准不同」（`VariableRichInput.tsx` 实际在
  `tag-studio` 下，文件存在）也包含真失效（`ux.md`、`sonarqube-feedback-report.md` 全仓
  不存在）。`existsSync` 本身无法区分这两种，方案 T3 的「全部不存在才标 ⚠」在真实数据上
  误报率过高。这一点写回方案文档，不在这条 PR 里改产品行为。
- **把统计结果写进脚本注释当"事实"**：数字会随记忆库变化，方案文档才是它们的落点。
  脚本只负责每次重新算。
- **给脚本加 `--self-test` 供 CI 跑**：口径已经由单测覆盖；聚合真实用量在 CI runner 上
  没有 `~/.sid-code/`，只会产出 n=0 的报告，而 n=0 看起来像数据（同 northstar 的既定结论）。

## 拿什么证明它生效了

**单测**：`bun test ./tests/scripts/memory-drift-shadow-stats.test.ts` → **8 pass / 0 fail**。
覆盖三类口径：路径提取的正例与五种排除（URL / 绝对路径 / 家目录 / node_modules / 裸文件名）、
空样本给 0 而非 NaN、`projectKeyFor` 与内核 `sanitizeProjectKey` 同口径（含中文路径的
6 位哈希后缀断言——这条防的是有人把手写 sanitize 改回来）。

**真实数据（本机 2026-11-07，索引行口径）**

| 记忆库 | 条数 | ≥7 天 | ≥30 天 | ≥90 天 | 锚点全部失效 |
| --- | --- | --- | --- | --- | --- |
| sid-code 项目 | 197 | 46.7% | 0.0% | 0.0% | 19/104（单根） |
| iam-studio-fe | 138 | 90.6% | 63.8% | 57.2% | 37/38（单根）→ 27/38（+1 包根） |
| docs-research | 116 | 82.6% | 2.6% | 1.7% | 11/59 |
| 全局（`~/.sid-code/memory`） | 11 | 90.9% | 81.8% | 72.7% | — |

结论：**「单一阈值 N + 覆盖率 ≤30%」在所有库都不可达**——记忆年龄分布两极分化
（要么一周内写的，要么几个月没动），任何单档阈值要么标 0% 要么标 50% 以上。
方案的参数设计需要改成「分档标注」或「只标最旧的一批」，这条已写回方案文档。

**门禁**：`bun run format` / `bun run lint`（0 warning 0 error）/ `bun run typecheck:gate`
（62 处，基线 64，无新增）/ `bun run affected-tests:run`（1804 pass / 0 fail，95 文件）/
`make build`（产物自检通过）全绿。

**人工核实**（不是脚本自证）：对 `iam-studio-fe` 抽查三条路径，确认
`src/api/agentChat.ts` 真实位于 `anka-app/packages/ontology-studio/src/api/agentChat.ts`，
而 `ux.md` 全仓不存在——即「全部失效」里两种成因确实混在一起。
