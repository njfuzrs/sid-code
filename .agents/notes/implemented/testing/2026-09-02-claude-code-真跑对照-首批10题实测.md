# ①‴ claude-code 真跑对照：首批 10 题跑完（$7.34）—— **cc 侧 10/10 verifier 真判分，而 sid 基线只有 5/10**

## 决定了什么

7b 从「可跑，未跑」推进到**跑完**。这是前 13 棒全 $0 之后**第一次真花钱**：
`runs/ccrun-n6`，10/10 trial 落盘，墙钟 **33m34s**，实付 **$7.3422**。

⚠️ **本轮唯一能对外说的结论不是分数，是「对照本身现在成立了」**，
以及一条比分数更值钱的发现：**两侧的 verifier 健康度不对等**。

## 🔴 本轮最值钱的发现：sid 基线的 5 个 0 分是**假 0**

`compare-paired.py` 只配出 **n=5**，逼我去看为什么。真因：

```
[基线] chess-best-move / sqlite-with-gcov / polyglot-c-py / fix-code-vulnerability
  verifier/test-stdout.txt:  /root/.local/bin/env: No such file or directory
                             uv: command not found          ← verifier 压根没跑
  verifier/reward.txt:       0                              ← 但这里写着 0
[基线] regex-log            agent n_input_tokens=0          ← 零调用
```

| 侧 | verifier 真判分 | 说明 |
| --- | --- | --- |
| **cc（本轮）** | **10/10** | 全部有 pytest 结论行 |
| **sid（`modelswitch-base` 基线）** | **5/10** | 4 题 `uv: command not found` + 1 题 agent 零调用 |

⇒ ⛔ **我最初那句「sid 解出 2/9」是错的**：那 9 里塞了 4 个 verifier 没跑出来的假 0。
`reward.txt=0` 有两种完全不同的含义（真判 0 分 / 没判成），**文件本身不区分**。
唯一可靠判据是 `verifier_health.verifier_ran()`（找 pytest 结论行）——
本仓已经把它单列成模块，本轮实证了它的价值。

## 放弃了什么（以及为什么不选）

- ⛔ **没有为了让分数好看去调 `max_turns`**。3 题烧满 40 轮，提到 80 大概率能多解
  一两题 —— 但那会同时改掉 sid 侧的预算才叫公平，而两侧一起改就变成了另一个实验。
  ①‴ 买的是「同预算下我们 vs 参考实现」，**预算本身是必控变量，不是调参旋钮**。
- ⛔ **没有先修 sid 基线那 5 个假 0 再跑 cc**。看起来更划算（修完一次跑出 n=10），
  但 cc 侧至今 0 样本，先证明「对照链路能通」比先优化分母更要紧 ——
  链路不通的话，修好的基线也没有对手可比。⇒ 修基线排到下一棒，**理由是排序，不是不做**。
- ⛔ **没有给 `check-comparison-parity.py` 加 cc 分支**。本轮改它等于在解读数据的
  同一时刻改判据工具，两件事混在一棒里，出了偏差分不清是数据问题还是工具问题。
  本轮改用「两侧各取自己的数据源」手工核，把工具改动留给下一棒。
- ⛔ **没有重跑那 3 个 `max_turns` 题**。它们不是故障，重跑只会再花 $4 拿到同样的
  结论；`terminal_reason` 已经把真因说清了。

## ⚠️ 五条不许从本轮推出的结论

1. ⛔ **不许说「cc 3/10 vs sid 2/10，我们更差/更好」**。基线有 5 个假 0，
   两个数的分母装的不是同一批题（本仓「分母比分子重要」的对照形态）。
2. ⛔ **配对后 n=5，不许当 10 报**：`sid 2/5 vs cc 1/5`，唯一变化是
   `configure-git-webserver` 1→0。**n=5 时 95%CI 半宽极宽，一题就能翻转均值** ⇒
   逐题表才是结论。
3. ⛔ **不许把 `max_turns` 记进「能力不行」**：40 轮是我们设的预算。
   cc 在 3 题上烧到 1.6M+ token 仍未收敛，正确表述是
   「**在 40 轮预算下未完成**」，换预算结论可能变。
4. ⛔ **不许拿 `check-comparison-parity.py` 的输出当 cc 侧判据**：
   它 glob `mini-swe-agent.trajectory.json`，cc 不产这个文件 ⇒ 会报
   「两侧没有同名题目」。**那是工具限制，不是事实**（10 个题名手工核过全同）。
   要么给它加 cc 分支，要么按本 Note 的方式两侧各取自己的数据源。
5. ⛔ **不许把 cache 70.9% 与 sid 侧直接比**：cc 的 input_tokens 量级比 sid 大
   一个数量级（1.6M vs 20K），两侧上下文工程完全不同，同一个比率不同义。
