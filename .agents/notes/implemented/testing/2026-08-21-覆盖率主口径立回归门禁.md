# catalog-coverage 主口径抽成纯函数并立回归门禁

## 决定了什么

给 `scripts/catalog-coverage.ts` 的口径逻辑立了回归门禁，做了两件事：

**1. 最小重构：把口径逻辑从顶层语句抽成可导出、可注入的纯函数。**

脚本原先从 `:139` 起就是顶层 `await` + 顶层语句，没有 `import.meta.main` 守卫、不导出任何函数——
直接 `import` 它会联网、读真实 `~/.sid-code/gateway-pricing.json`、打印一堆东西，测不了。
现在按 `scripts/affected-tests.ts` / `scripts/change-scope.ts` 的同款做法收口：

- `gatewayModels(file?)` —— 参数是已解析的 `GatewayPricingFile`，不传才读本机缓存。测试喂 fixture。
- `denominators(all)` —— 分母对（全量 + 排除非对话），把 `NON_CHAT_RE` 的应用点收成一处。
- `hits` / `coverageOf` —— 命中判据与两个分子。
- `truthOf` / `aggregate` / `scoreRule` / `voteAccuracy` —— 投票计分，其中 `scoreRule` 是把原先
  嵌在三重 for 里的那段计分逻辑原样提出来（分母 ≥2、钳制、容差三件事都在它里面）。
- 顶层执行、`--json` / `--gaps` / `--offline` 的解析与全部 `console.log` 收进 `if (import.meta.main)`。

`scoreRule` 多了一个 `tolerance` 参数（默认 `TOLERANCE`）。**加它的唯一理由是让一条耦合可测**：
「ok 带宽」与「under/over 分界」必须是同一个容差，而 `0.95` 与 `1 - TOLERANCE` 在 0.05 上完全等价，
不换容差值就没有任何断言能区分这两种写法（这一点是变异 M10 首轮全绿才暴露的，见下）。

**2. 新增 `tests/scripts/catalog-coverage.test.ts`（35 个用例）**，覆盖四块口径：
跨桶去重 / 非对话排除 / 命中判据走运行时同一套归一化 / 投票计分（含 `maxOutputTokens` 钳制、
≥2 候选阈值、5% 容差）。

## 放弃了什么（以及为什么不选）

**放弃：给脚本做端到端联网测试。** 它验的是那三个上游目录当天可不可达，不是我们的口径逻辑；
慢、不确定，且失败时第一反应是"网络问题"而不是"口径坏了"——一个会被习惯性忽略的红灯比没有更糟。

**放弃：锁数字（把当天的 135/113、82.2% 写进期望值）。** 这是本次最重要的一条边界：
**这道门禁只保护口径逻辑，不保护数字本身。** 数字随上游三个目录的数据天天变，锁它等于每天红一次，
最后一定被人改期望值糊过去；更糟的是快照式断言在分母逻辑被改坏时**恰好还是绿的**
（它锁的是数字，不是算出这个数字的逻辑）。所以断言一律构造 fixture、锁「改坏前后结果可区分」。

**放弃：读本机 `~/.sid-code/gateway-pricing.json` 做断言。** 分母口径的正确性与本机恰好有几个模型无关，
读真实文件只会让断言随机器变化——正是脚本头部那条「不是可跨机器比较的绝对指标」的注释在说的事。

**放弃：把 `NON_CHAT_RE` 换成按 `supported_endpoint_types` 字段判。** 脚本注释已论证过为什么不换
（实测 5 条带 `embeddings` 的条目里有同时带 `openai` 的，用它当判据会误伤），本次只给现有判据立门禁，
不动判据本身。

**放弃：把脚本改成 CLI 参数注入 fixture 路径（如 `--pricing <path>`）。** 那会把测试用的口子变成
用户可见的参数，还得给它写文档与反漂移；导出函数 + `import.meta.main` 是仓库已有的成熟做法，零外部表面。

## 拿什么证明它生效了

**行为不变（重构的验收判据）。** 重构前后各跑三种输出模式，逐字比对：

```
$ diff /tmp/cov-before.txt      /tmp/cov-after.txt        → IDENTICAL
$ diff /tmp/cov-before-gaps.txt /tmp/cov-after-gaps.txt   → IDENTICAL
$ diff <(grep -v measured_at cov-before.json) <(grep -v measured_at cov-after.json) → IDENTICAL
```

三种模式全部**字节一致**（`--json` 只排除 `measured_at`，它是时间戳）。分母仍是「全量 135 / 对话 113」，
两个字段 × 两个源组合 × 三条规则共 12 行准确率、8 个真实缺口，数字与标签一字未动。
`--offline` 单独跑过一次，exit 0 且输出同上。

**变异自证（本次核心交付）。** 每种变异 → 跑一次新测试 → 确认 ≥1 fail → 改回。基线 35 pass / 0 fail：

| # | 变异 | 结果 |
| --- | --- | --- |
| M1 | `gatewayModels` 只遍历第一个桶 | 2 fail ✅ |
| M2 | `gatewayModels` 去掉去重（数组替 Set） | 2 fail ✅ |
| M3 | `gatewayModels` 去掉 `.toLowerCase()` | 2 fail ✅ |
| M4 | `NON_CHAT_RE` 去掉 `rerank` 分支 | 2 fail ✅ |
| M5 | `hits` 改成只比对原样键（不走 `normalizeCandidates`） | 4 fail ✅ |
| M6 | 去掉 `maxOutputTokens` 的「不超过窗口」钳制 | 1 fail ✅ |
| M7 | 5% 容差改成 0 | 3 fail ✅ |
| M8 | 「≥2 候选值」阈值改成 ≥1 | 1 fail ✅ |
| M9 | `aggregate` 收敛分布（同键只留第一个值） | 1 fail ✅ |
| M10 | under/over 分界写死 `0.95`（与容差脱钩） | **首轮 0 fail ❌ → 补断言后 1 fail ✅** |
| M11 | 钳制退化成 `Math.min(got, w ?? 0)` | 1 fail ✅ |
| M12 | `denominators` 不做非对话排除 | 2 fail ✅ |
| M13 | `gatewayModels` 不排序 | 1 fail ✅ |
| M14 | `tolerance` 参数被忽略（恒用 `TOLERANCE`） | 1 fail ✅ |

**M10 是这次唯一真正学到东西的一格，值得单独记。** 它首轮全绿，原因不是断言不够多，而是
`0.95` 与 `1 - TOLERANCE` 在默认容差 0.05 上**语义完全等价**——不给容差换个值，这条耦合
在数学上不可观测。这正是仓库那条「有调用点 + 有字段 ≠ 值有区分度」的同形：
我当时已经写好一条名字叫「分界与 TOLERANCE 联动」的断言，它读起来在测这件事，实际什么都没测。
补法是把 `tolerance` 做成参数，用 1% 容差构造区分点（真值 100000、got 97000：
正确分界 0.99t 判 under，写死 0.95t 判 over）。**若不做变异自证，这条假断言会作为"已覆盖"长期存在。**

改坏验证后已全部改回，`diff /tmp/cov-orig.ts scripts/catalog-coverage.ts` → RESTORED，
最终工作区只有本次两个有意的文件（`git status`：`M scripts/catalog-coverage.ts` + 新测试）。
