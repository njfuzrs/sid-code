# Harbor 跑前环境：三条「硬约束」实测全部推翻，但挖出一条更大的失真源（并发）

## 决定了什么

第四棒的第一优先是「把 13.1 的测量搬到真实 benchmark 上」。**本次刻意没有跑真实评测**，
只做跑前环境复核 —— 因为 `02-Harbor接入方案设计.md` §13.5 列的三条本机硬约束
如果仍然成立，那一跑就是白跑（verifier 随机坏掉 → 假 reward=0）。

四件事，全部落在 `evals/external-benchmarks/harbor/`：

1. **三条旧硬约束逐条实测，三条全部不再成立**（宿主开全局代理 + TUN 之后）。
   README「宿主网络三条硬约束的现状」一节列了新旧对照与判据命令。
   - Docker Hub：**治因是给 dockerd 配 proxy**，不是网络慢。
     根因两条叠加：① `registry-1.docker.io` DNS 被污染到 `199.59.150.45`（Twitter 段），
     TCP 通但 TLS 无响应 —— 所以 `nc -z` 会报 OPEN；
     ② **lima 把代理写进 `/etc/environment`，而 systemd 服务不读那个文件**，
     于是 VM 里 curl 走代理正常、dockerd 完全没代理。落点
     `/etc/systemd/system/docker.service.d/http-proxy.conf`（ext4，跨 VM 重启保留）。
     `ghcr.io` 与 `*.githubusercontent.com` **进 NO_PROXY**：两条都通，
     但直连 blob 3.3MB/s vs 走代理 2.6MB/s，而 terminal-bench 全部镜像在 ghcr。
   - `downloads.claude.ai`：**已通**。二进制 278MB @ 0.93MB/s ≈ 300s。
   - `releases/download/`：**单发已稳**（容器内 10/10、5/5），但见第 3 条。

2. **新增坑 ④：Harbor 数据集注册中心会随机在第 0 秒杀掉整个 run。**
   报错 `ValueError: Error getting dataset <name>@<version>` 长得像「名字写错」，
   实际是 Supabase RPC 网络失败：**15 次采样 14 通 1 挂（约 7%），且 harbor 无重试**，
   `registry/client/harbor/harbor.py:128` 把原始异常整个吞掉。
   治法：`registry.local.json` + `--registry-path`，完全绕开远端。**本次已入库该文件。**

3. **新增坑 ⑤（本次最重要的产出）：`-n`（并发）直接决定 verifier 坏掉的比例。**
   四轮 `nop` 对照（`nop` 不解题 → reward 必然全 0，唯一观测量是 verifier 有没有跑成）：
   `-n 1` → **1/10 坏**；`-n 3` → **4/10 坏**；`-n 3` + 容器走宿主代理 → **6/10 坏**。
   **Harbor 的 `-n` 默认是 4**，不显式写 `-n 1` 就等于默认踩坑。

4. 顺带核实：`~/.local/share/sid-harbor-gateway/` 的 shim **存活**，三条行为
   （占位 token 200 / 错 token 401 / 非模型端点 403）逐条实测通过；
   现有 linux 二进制 `abb8233e9cd8` **仍然有效** ——
   `git diff --stat abb8233e9cd8..HEAD -- packages/` 为空，那 6 个 commit 全是 evals/docs。

## 放弃了什么（以及为什么不选）

**两条治法被自己的实测否决，各花了半小时，写下来是为了不再试：**

- ❌ **容器走宿主 HTTP 代理**（`--extra-docker-compose` 注入 `*_proxy`）。
  我为此写了 `compose-host-proxy.yaml` 并已删除。
  小规模探针**看着很好**：6 路 6/6、8 路 8/8、累计 14/14 零失败。
  **真跑却是四种配置里最差的 6/10。**
  > **形态教训：探针的并发形态与真实 run 不同。** 真实 run 里同时还有镜像拉取、
  > agent 自己的模型调用、多个容器的 apt；探针只测了下载这一条。
  > **「小规模探针全绿」不能外推到真实 run** —— 这次差点因此把一个让情况变糟
  > 一倍的配置写进 README 当推荐做法。
- ❌ **squid 缓存代理**（想让 10 个任务共享同一份 uv tarball，17MB × 10）。
  下载走 HTTPS，squid 只看得到 `CONNECT` 隧道、**缓存不了隧道内容**；
  要缓存就得 MITM，那需要往**每一个任务镜像**里塞 CA ——
  改被测环境去迁就基础设施，不做。

**没做的事（刻意）**：没有跑真实评测。三条硬约束复核完 + 挖出并发这条之后，
`-n` 的取值直接决定数据可信度，先把它定下来再跑才不白跑。

**残余误差不掩饰**：`-n 1` 仍有 1/10 的 verifier 会坏。真治法是一台网络干净的机器，
或在镜像里预装 uv（要改上游任务，破坏「同题同 verifier」可比性，不做）。
**在本机上这是已知残余误差，不是已解决问题。**

## 拿什么证明它生效了

全部是命令 + 输出，没有一条是推论：

- **Docker Hub**：配 proxy 前 `docker pull alpine:latest` →
  `net/http: TLS handshake timeout`；配后 → `Status: Downloaded newer image`。
  ghcr 未被拖累：`NO_PROXY` 生效后 `docker pull .../qemu-alpine-ssh:2.0`（260MB+ 层）成功。
- **`downloads.claude.ai`**：容器内 `curl .../claude-code-releases/bootstrap.sh` → **200 / 9704 字节**。
  ⚠️ 一开始拿一个**猜的** URL 测得 404，一度误读成「不可达」——
  正确 URL 从 `harbor/agents/installed/claude_code.py:456` 取。
- **uv 下载**：容器内单发 10/10 200；ubuntu:24.04 里跑**真实 installer** →
  `uv 0.12.7 (aarch64-unknown-linux-gnu)`。
- **registry 7% 失败率**：15 次 RPC 采样 → `ok=14 fail=1`（失败是 curl 000）。
- **本地 registry 可用**：`--registry-path registry.local.json` 起了 10 个 trial、无 traceback。
  ⚠️ 格式是**裸 JSON 数组**，写成带 `datasets` 键的对象会得到一个 pydantic
  `Input should be a valid dictionary ... input_value='name'` —— 它在报数组元素类型，
  读起来像在说字段名。第一版就是这么错的。
- **并发那条（核心判据）**：四轮完整 `nop` run，每轮 10 个 trial，
  判据是 `grep -E "uv: command not found|failed to download|curl: command not found"`
  命中的 trial 数：`-n 1` 1/10、`-n 1`+本地 registry 1/10（复现）、
  `-n 3` 4/10、`-n 3`+代理 6/10。
  失败散布在**三个域名**（github.com / releases.astral.sh / archive.ubuntu.com）、
  **三个 curl 错误码**（7/18/35）—— 这个多域名多错误码的形态本身就是带宽争抢的指纹，
  不是某个域名被墙。
  > ⚠️ 中途有一次差点误判：第一次 `-n 3`+代理 得 6/10、而基线是 `-n 1` 的 1/10，
  > **两个变量同时变了**。补跑 `-n 3` 直连（4/10）才把「代理」与「并发」分开。
- **门禁**：`bun run affected-tests:run` → **637 pass / 0 fail**；
  `make build` → 自检 4 项全过（含内嵌 skill hash 与 ripgrep 平台匹配）。
  ⚠️ 本次两个改动都是 `evals/` 下的文档与数据文件，**门禁覆盖不到它们**
  （README 的 5 个坑、registry.local.json 的格式都靠上面那些实测断言，不靠 CI）。

**没有改任何产品代码**（`packages/` 零改动），所以「更准/更省」四条曲线本次不动 ——
本次的产出是**让下一次测量不失真**，它服务的是「可观测」而不是四个方向本身。
