# G2 用例批 1：X1 `-p` 致命错误退出码、X2 default 档 git 写形态、X5 无头命令真落盘；运行器加 `realPermissions`

## 决定了什么

台账 §三 里三条不依赖新设施的 G2 用例一次落地（无头斜杠命令方案 T1–T8 与 Harness 厚薄归位 B1 #621 合入后解除阻塞）：

- **X1-print-fatal-exit**：夹具只录第一轮 bash，第二轮 ReplayProvider 无响应可放 → 重试耗尽 → `fatal_error`。断言 exit 1、`SessionEnd{reason=error,exit_status=error}` 恰 1 条、第一轮 bash 正常执行。压低重试四个环境变量（不压时实测 120s 未退出）。
- **X2-default-mode-git-write**：真实权限默认档下回放 `git remote add`、`git stash -u`、`git branch --show-current`。断言 bash 的 `PermissionDecision` deny 2 条 / allow 1 条、读形态那条 `PostToolUse` 正常、未跟踪文件 `wip.txt` 仍在（stash -u 一旦执行会被收走）。读形态是对照：整个权限层把 bash 全判拒时两条 deny 断言也会过，这条防假绿。
- **X5-headless-cmd-persist**：主运行一次普通提问（只跑斜杠命令的进程不调模型、不建轨迹目录，运行器的事件断言依赖那个目录），`after` 依次跑 `/effort high -p`、`/think off -p`、`/cron delete x`。断言 settings.json 落盘 `effortLevel=high`、`thinkingEnabled=false`，`/cron delete` 退非 0 且 stderr 含「只放行子命令：list」。

运行器新增 `SmokeCase.realPermissions`：置 true 时不补 `--dangerously-skip-permissions`。只加在主运行上，`after` 的 print 步骤仍跳过权限——目前没有用例需要，加了就是无调用方的分支。

## 放弃了什么（以及为什么不选）

- **X5 对 A 档 23 个命令逐个建 G2**：不做。放行判定与注入表已由 G1 `headless-allowed-commands.test.ts`（104 例）逐个守住；G2 补的是 G1 守不到的一层——app.ts 真把 deps 接到了真实 setter。挑有落盘副作用的代表即可，变异配方正是「注入表漏一个 setter」。
- **X2 断言 `PermissionDecision.step`（如 `headless:14`）**：不断言。期望只能取自人工核过的口径，B1 方案 §6.4 的手动验收只说「要确认 / 不要确认」，step 是实现细节。
- **X4 resume id 放进本批**：拆出去。探针发现 `-c` 之后 stdout 的 `trajectory_path` 指向一个不存在的目录（轨迹写进 `resumed_from` 那个旧目录，stdout 却拼进程新 id），这是一个真缺陷，不是用例问题。按 CLAUDE.md「修缺陷前先回源码核实」另立，不在测试 PR 里顺手修。
