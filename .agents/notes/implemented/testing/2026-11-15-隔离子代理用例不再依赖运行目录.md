# 隔离子代理「未绑定 cwd」用例不再依赖跑测试的目录

## 决定了什么

- `packages/core/tests/agent/isolated-subagent-cwd.test.ts` 的「未绑定 cwd 时不出现隔离提示
  （主仓子代理行为不变）」改为显式把会话启动目录钉到模拟主仓：`setCwd(mainRepo)` + `finally`
  恢复，不再依赖「跑测试的进程 cwd 恰好在隔离 worktree 之外」这个隐藏前提。
- **产品代码零改动**：子代理在隔离 worktree 里继承 worktree cwd 并给出【隔离环境提示】
  是正确行为，缺陷只在测试的隐式前提。

## 放弃了什么（以及为什么不选）

- **改判定入口**：把「是否提示隔离」从「继承的 cwd」改成「是否有显式 ALS 绑定」。
  会直接破坏真实需求 —— 用户 `/worktree` 进入、或 agent 本身在 worktree 里跑时，
  子代理继承的就是 worktree cwd，**就该**提示。
- **在 worktree 里跳过该用例 / 放宽成 `toContain` 取反的软断言**：等于把哨兵关掉。
  它守的是「未绑定 cwd 不该凭空判定成隔离环境」，在任何 checkout 路径下都成立，
  只是原实现顺带依赖了运行目录。
- **用 `withAgentCwd(mainRepo, ...)` 代替 `setCwd`**：语义上会被读成「这个子代理绑定了
  cwd」，而本用例测的恰恰是**未绑定**；`setCwd` 表达的是「会话启动目录在主仓」，更贴切。

## 拿什么证明它生效了

- **复现**（本 PR 的 worktree 本身就在 `.sid-code/worktrees/subagent-cwd-test-env` 下，
  是天然复现环境）：`bun test ./packages/core/tests/agent/isolated-subagent-cwd.test.ts`
  → `11 pass / 1 fail`，红的正是目标用例，报错为
  `expect(received).not.toContain("【隔离环境提示】")` 且提示正文里的根目录 = 该 worktree。
- **修复后**：同一命令 `12 pass / 0 fail`。
- **变异自证**：把 `setCwd(mainRepo)` 改成 `setCwd(worktree)`（等价于不修）→ 重新
  `11 pass / 1 fail`；恢复后 `12 pass / 0 fail`。证明是这一行在起作用，不是别的东西。
- **门禁**：`bun run affected-tests:run` → **713 pass / 0 fail**（78 文件）；
  `make build` 成功且 `will always be undefined` 计数 **0**；
  `bun run lint` / `format:check` / `lint:boundary` / `lint:command-system` /
  `lint:legacy-tool` 全绿；`bun run typecheck:gate` → `当前 62 处 / 基线 62 处，无新增`。
- **同批另 3 条（`permission-default-mode`）为什么不改**：核实到该测试文件由
  `afb32770`（2026-11-15）新建 —— `git show afb32770^:packages/core/tests/config/permission-default-mode.test.ts`
  报「不在 afb32770^ 中」，即 main 上不存在它的旧版本；当前版本文件头自带
  `SID_CONFIG_DIR` + cwd 双 tmpdir 隔离，实测 `24 pass / 0 fail`。记忆里 2026-11-13 记的
  那 3 条属于该文件在 PR 分支上的早期版本，已随重写消失，无需再改。
