# 清掉生产源码与 tui 的 tsc 存量错误，基线 87 → 66

## 决定了什么

只清「生产源码 + `packages/tui/src`」两块，测试侧 64 条暂不动：

- `tsconfig.json` 的 `include` 显式加入 `packages/tui/src/**/*`。tui 源码原本只作为 cli 的 import 被顺带检查，
  `global.d.ts`（声明 `ink-box` / `ink-text` 两个 JSX 内置元素）不被任何文件 import，于是不进编译单元，
  每用一次内置元素报一条 TS2339（12 条）。
- 根 devDependencies 以**精确版本**补 `@types/signal-exit@3.0.4`、`@types/ws@8.18.1`、`@types/scheduler@0.26.0`，
  与 tui 锁定的运行时版本（signal-exit 3.0.7 / ws 8.22.0 / scheduler 0.27.0）同代。
- 两处 `React.RefObject` 改为具名导入 `RefObject`（tui `use-animation-frame.ts`、cli `useFlickerDetector.ts`）。
- `piped-stdin.ts`：注入的 `Readable` 没有 `isTTY`，用 `"isTTY" in stdin` 收窄，mock 流按非 TTY 处理，与原运行时行为一致。
- `checkpoint/manager.ts`：`Bun.gzipSync` 只收 ArrayBuffer 背书的 Uint8Array，此处字节不会来自共享内存，做类型收窄。

全部是类型层改动，不改任何运行时逻辑。

## 放弃了什么（以及为什么不选）

- **同时清测试侧 64 条**：收益最低（不影响运行），且散在几十个测试文件里，混进来会让这个 PR 无法一次 review 完。
  它唯一的价值是清零后能把棘轮换成裸 `tsc --noEmit`，留到单独决策。
- **给 tui 单独配 tsconfig**：根 tsconfig 注释已明确「单个编译单元」，拆开只增加维护面。
- **`gzipSync(new Uint8Array(content))` 拷贝一份过类型**：大文件白付一次复制，换不到任何正确性。
- **在 tui 源码里写 `declare module 'signal-exit'`**：手写声明会和上游代码绑死且无人维护，用 DefinitelyTyped 的包更稳。

## 拿什么证明它生效了

- `bun run typecheck:gate`：`当前 66 处错误 / 基线 87 处`、`✓ 无新增类型错误`；`--update-baseline` 后 `基线已收紧：87 → 66 处`。
- 生产源码（`packages/*/src`）剩余 0 条真实错误（`model-catalog-snapshot-embedded.ts` 的 TS2307 是 gitignore 的构建产物缺失，
  门禁脚本跑 tsc 前会补占位，不计入）。
- 顺带消除了本机主仓门禁假红：`ink.tsx` 的 TS1192 来自根 `node_modules` 残留的 signal-exit 4.1.0（lock 里没有 4.x），
  装上 `@types/signal-exit` 后 tsc 不再落到那份残留的 `.d.ts`。
- affected-tests / lint / format / boundary / make build 结果见 PR 正文。
