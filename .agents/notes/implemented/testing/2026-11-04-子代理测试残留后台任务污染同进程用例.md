# 子代理测试残留的 running 后台任务污染同进程其它用例

## 决定了什么

`packages/core/tests/agent/subagent-no-limits-pr-b.test.ts` 加文件级
`afterEach(() => clearAllTasks())`，把本文件造的后台 agent 任务在用例结束时从 task registry 清掉。

根因：该文件有 4 处 `createAgentTask`，其中 3 个任务（`a` / `b` / `never-exit`）在
`abortAllAgentTasks()` 之后**仍是 running** —— abort 只发信号并摘掉 `activeAgentControllers`，
真正把任务写成 completed / failed 的是子代理执行方的出口，而这些用例根本没有执行方。
task registry 是模块级单例，`bun test` 又把多个测试文件跑在同一进程里，于是后续任何
`hasAwaitedBackgroundTasks()` / `getRunningTasks()` 的判断恒为 true。

表现（PR #564 的 CI：`test (ubuntu-latest, 3/3)` 6 条用例集体红，单独跑全绿）：

- `todo-plan-part5-wiring.test.ts` T2 两条：`gateRetries` 恒为 0；
- `todo-gate-forgot-mark-loop.test.ts` 两条：收尾文案变成「清单还有 1 项未完成，正在等待后台任务回报」；
- `continue-path-caps.test.ts`：`GateExhausted(todo)` 不再产生；
- `background-await.test.ts` 端到端：`hasAwaitedBackgroundTasks()` 期望 false 收到 true。

## 放弃了什么（以及为什么不选）

1. **把清理散到各个受害文件（给 todo gate / background-await 的用例加 `beforeEach(clearAllTasks)`）** ——
   不选。污染源只有一个，兜底加在下游会让下一个漏清理的测试继续以「别的文件莫名变红」的形态出现，
   归因成本极高（这次从 CI 日志到定位根因花了十几轮）。下游只保留它们本来就有的
   `__resetBackgroundAwaitForTest()` / `__resetQueueForTest()`。
2. **改 `abortAllAgentTasks`，让它 abort 后顺手把任务标 killed** —— 不选。生产语义上这是错的：
   abort 是「请求停止」，终态必须由真正持有执行方的那一层写（`failAgentTask`），
   否则「abort 了但子代理还在写结果」的竞态会变成状态机自相矛盾。测试里的残留是测试没模拟出口，
   不该让生产代码迁就测试。
3. **在 `bunfig.toml` 的 preload 里挂全局 `afterEach` 清 registry** —— 不选。影响面覆盖全部
   9000+ 用例，跨 test 共享 registry 状态的用例（有的文件靠 `beforeEach` 自己清、有的刻意跨
   test 保留任务）会被无差别打断；这类兜底应该只在确认存在系统性残留后才上，本次只有一个源头。

## 拿什么证明它生效了

修复前后各跑一次相同的两文件组合（本地 worktree，bun 1.4.2）：

```
bun test ./packages/core/tests/agent/subagent-no-limits-pr-b.test.ts \
         ./packages/core/tests/query/todo-plan-part5-wiring.test.ts
# 修复前：14 pass / 2 fail（T2 两条 gateRetries 期望 > 0 收到 0）
# 修复后：14 pass / 0 fail
```

再把 CI 上红掉的 5 个文件放一起跑：

```
bun test ./packages/core/tests/agent/subagent-no-limits-pr-b.test.ts \
         ./packages/core/tests/query/todo-plan-part5-wiring.test.ts \
         ./packages/core/tests/query/todo-gate-forgot-mark-loop.test.ts \
         ./packages/core/tests/query/continue-path-caps.test.ts \
         ./packages/core/tests/task/background-await.test.ts
# 36 pass / 0 fail
```

变异自证：把 `afterEach(clearAllTasks)` 去掉即回到 2 fail（上面第一条就是变异态实测值），
恢复后转绿 —— 断言确实由这处清理驱动，不是环境抖动。

另外本地 `bun test --shard=3/3` 端到端重跑，确认原先红掉的 6 条全部转绿（本地唯一残留的
`isolated-subagent-cwd` 失败是「在 worktree 里跑测试」导致的环境差异，CI 上不出现）。
