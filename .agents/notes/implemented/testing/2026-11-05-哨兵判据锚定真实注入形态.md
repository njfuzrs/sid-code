# 两处哨兵判据锚定真实注入形态，不靠字段名或纯文本近似匹配

## 决定了什么

修 PR #600 CI 里的两处哨兵误报（另外两类失败是同根因的连带失败与一个 macOS 环境 flake，不在本 note 范围）：

1. `packages/core/tests/context/internal-message-sentinel.test.ts`：origin 扫描从裸
   `/origin:\s*["']…["']/` 收窄到 **`_meta: { … }` 对象字面量内部**（新 helper
   `collectMetaOrigins`）。本 PR 给 `CronTask` 新增了领域字段 `origin`
   （`cron_create` / `schedule_wakeup` / `loop`），旧正则把它们误报成未登记的**内部消息** origin。
2. `packages/core/tests/telemetry/no-real-path-writes.test.ts`：判定「测试文件用到了落盘导出」
   原本是纯文本匹配，**注释里提到类名也算**。新增 `stripComments` 后只匹配代码
   （字符串/模板串原样保留）。`session/rewind-telemetry.test.ts` 文件头解释
   「埋在 CheckpointManager 层会让一次面板回滚记两条」，它本身只 new RewindManager（不落盘），
   却因这行注释被要求声明隔离。同一次改动顺带修掉 `isolated` 判据的假阴性：
   注释里写 `process.env.SID_CONFIG_DIR` 原本也会被当成已隔离。

## 放弃了什么（以及为什么不选）

- **把 cron_create / schedule_wakeup / loop 登记进 INTERNAL_ORIGINS**：否决。
  它们是 `CronTask.origin`（调度任务的来源），不是消息来源。登记的后果是
  `isHiddenFromDisplay` 会把这些值也算作「整条隐藏」的判据，单一事实源的语义被污染，
  下一个读 `INTERNAL_ORIGINS` 的人会以为存在三种定时相关的内部消息。
- **把 `CronTask.origin` 改名（如 `triggerSource`）**：可行但治标。`origin` 是通用词，
  下一个领域字段（HTTP origin、数据库 origin、错误来源）仍会撞上同一个过宽正则 ——
  `llm/error-normalize.ts:204` 已经为绕开它把 `origin: "network"` 拆成先声明变量再写键。
  那条绕行注释可以留着，但判据本身不该继续要求人绕。
- **改 `rewind-telemetry.test.ts` 的注释措辞避开 `CheckpointManager`**：否决，那是把
  「注释被当成调用」这个错误判据原地留着，下一个在注释里解释规则的测试还会踩。
- **给 `rewind-telemetry.test.ts` 加 `SID_CONFIG_DIR` 隔离**：能过门禁，但是错误信号 ——
  它根本不落盘，而「声明隔离」本身是「该文件有落盘副作用」的标记，滥用会让这个标记失去信息量。

## 拿什么证明它生效了

- 两处哨兵单跑：`bun test ./packages/core/tests/context/internal-message-sentinel.test.ts ./packages/core/tests/telemetry/no-real-path-writes.test.ts`
  → `15 pass / 0 fail`。
- 运行时落盘门禁（此前因 origin 哨兵同一个失败而 exit 1）：
  `bun test ./tests/build/no-real-trajectory-writes-runtime.test.ts` → `3 pass / 0 fail`。
- 变异自证（改坏 → 必须报红 → 恢复）：
  - `context/manager.ts` 的 `_meta: { origin: "compact-summary" }` 改成 `bogus_variant_probe`
    → 哨兵报红并指出 `packages/core/src/context/manager.ts`。
  - 新建一个真实 `import { CheckpointManager }` 但不声明隔离的临时探针测试
    → 落盘哨兵报红并指出该探针文件；删除探针后恢复绿。
  - 反向验证「不再误报」：把 `schedule-wakeup.ts` 的 `CronTask.origin` 改成未登记值
    → 哨兵保持绿（这正是修复目标：它不是消息 origin）。
- 判据自证 3 条已随测试入库：领域字段不误报 / 跨对象边界不误报 / 多行 `_meta` 仍能抓到。
- 全量门禁：`affected-tests:run` → `6881 pass / 0 fail`；`make build` 产物自检通过；
  `lint` / `format:check` / `lint:boundary` / `lint:command-system` / `lint:legacy-tool` /
  `typecheck:gate` 全绿。
