# bash 常驻描述去掉与参数描述重复的三条

## 决定了什么

`packages/core/src/tool/bash.ts` 的 `usageGuide()` 删掉三条与 schema 参数描述重复的说明：
timeout 上限（默认 2 分钟、最长 10 分钟）、超过 10 分钟改走 `run_in_background`、
输出超过 30000 字符截断。这些在 `bashSchema` 的 `timeout` 参数描述里已有一份。
后台任务「返回 task_id、用 task_output 查、task_stop 终止」这一句**留了下来**：
`bash-stability.test.ts` 有一条在先的门禁要求指南点名这两个查询入口
（只说能后台跑、不说怎么拿输出，后台等于丢失结果），而 `run_in_background` 的参数描述
只写到「返回 task_id」，没写 task_output / task_stop。
`--dump-tools` 实测 bash 描述 4073 → 3735 字节，少 338 字节。

git 安全纪律（`--amend` / `--no-verify` / `push --force` / `core.hooksPath` /
`--theirs` / `git merge --abort` 等）一条没动，并加了测试锁住它们还在。

## 放弃了什么（以及为什么不选）

- **连 git 纪律一起瘦**。方案原文明确否决：这 10 条是不可逆操作的护栏，而且只挂在
  bash 上（唯一能执行 git 的工具），schema 里没有第二份。照 CC 的长度砍等于把护栏删了。
- **把删掉的三条挪到工具结果里按需注入**。它们不是「第一次才需要」的知识，是每次调用
  都可能用到的参数约束，参数描述本来就是每轮都在的那一层，挪走反而多一个落点。

## 拿什么证明它生效了

- 字节：基线二进制 `/tmp/sid-bin-subagent-base`（同日 `origin/main` 构建）dump 出 bash
  描述 4073 字节；本分支 `make build` 产物 `/tmp/sid-bin-bash-new` 为 3735 字节，差 338。
  方案写的门槛是「少 400 字节以上」，差 62 字节没到。差在 task_id 那一句不能删
  （见上，删了 `bash-stability.test.ts` 的既有门禁变红）。同一份 dump 里 `todo_write`
  与 `sub_agent` 字节数不变（8109 / 5369），确认没有误带其他工具的改动。
- 测试：`bun test ./packages/core/tests/tool/bash-stability.test.ts -t "T9|usageGuide"`
  → 6 pass / 0 fail。新用例断言超时上限与截断阈值不再出现在 guide、仍在 schema；
  既有用例断言 task_output / task_stop 仍被点名、git 纪律锚点都还在。
- 方案要求的同日双模型 A/B 本 PR 合入前没有跑完（采集台单题 10 分钟级，墙钟超出本次
  交付窗口）。A/B 是方案给的合入判据，缺了它不该合入 main；PR 维持 draft，等数据补上再摘。
