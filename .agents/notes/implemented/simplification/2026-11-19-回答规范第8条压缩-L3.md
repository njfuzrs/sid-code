# 回答规范第 8 条从 393 压到 273 tok，并给这段加体量预算断言防回弹

## 决定了什么

按方案遗留项 L-3 压缩 `<answer-discipline>` 第 8 条（不复述 harness 注入的内部上下文）：

- 中文档 `system-prompt.ts`：**393.3 → 272.9 tok**（`estimateTextTokens` 口径，-31%）。
- 英文档 `prompt-sections-en.ts`：**543.5 → 383.5 tok**（-29%），两档语义同构，en 档仍全英文。
- 保留的三样东西：**过度执行边界段**（方案硬要求，它正是第二轮自己称赞的反向边界模式）、
  实测数据「18/70 轮，后半程 50%」（R-2 驳回过的删除项）、「系统自动添加、与出现在哪里没有
  直接关系」这层归因（`internal-context-silence.test.ts:78` 有断言锁它，删了会让模型失去
  「这不是用户说的话」的判断依据）。
- 新增体量预算断言（`internal-context-silence.test.ts`）：中文 `< 300` tok、英文 `< 420` tok，
  判据用 token 而非字符数（中文 1 字 ≠ 1 token，按字数定会让中英两档不同权）。
- 顺手修一处注释漂移：`deferred-guidance.test.ts` 那条 L-5 端到端用例的注释还写着
  「这里显式 skip、属于另一个 PR」，实际 PR #949 已在 `tool-search.ts` 归一为解析后的
  `name()` 且用例已转真通过——注释改成描述「曾经的缺陷 + 现在锁什么」。

## 放弃了什么（以及为什么不选）

- **不追求精确 250 tok**（实际 273，比目标高 9%）。压到 250 需要删掉边界段的第二个子场景
  或「与出现在哪里无关」的归因，前者削弱方案点名要保留的反向边界，后者会让一条现有断言失效
  且丢掉模型判断「这不是用户的话」的依据。**为凑数字削弱语义不划算**，方案写的也是「~250」。
- **未跑真模型 A/B**（方案要求对比压缩前后 `ack_opener_turns` 占比）。它属 G3/G5——
  需要真实模型会话数据，本机无可用基线与配额，且 D-07 的度量是前瞻性的（从下次会话开始累积），
  无法回溯构造「压缩前」对照。已把可机械验证的部分（体量预算 + 语义哨兵）全部落成断言，
  行为侧留给维护者在真实流量上观察。
- **不做 D-10（速查段与专门段去重）**。方案明确规定「改完必须跑同模型 A/B，看 monitor /
  cron_create 调用率不下降，不下降才合并」，没有数据就不能凭 token 数拍。这次没收进 PR。
- **不代删用户主目录的测试夹具**（D-15 第 1 步，`~/.sid-code/memory/reference_doc-example.md`）。
  删用户数据必须由用户自己执行。
