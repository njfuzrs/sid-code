# 命令体系收口：剩余 34 条旧命令迁到 commands/，删除 adapter / builtins / 旧 Registry / 旧类型

## 决定了什么

斜杠命令只剩一种形态：`UnifiedCommand` + `CommandContext`（方案 §4.3 第二、三步合成一个 PR）。

- `builtins.ts` 等 10 个文件里的 34 条旧命令全部迁到 `commands/<name>/`：`index.ts` 放元数据和门控字段（原 `loaders.ts` 的 `LEGACY_BUILTIN_GATES` 按名并入），`<name>.ts` 放实现类（`implements LocalCommandModule`，`execute` 改名为 `call`）。子命令族（mcp / ide / lsp / skills / agents）的子命令在 `index.ts` 的 `subCommands` 里声明，实现类具名导出。被多条命令共用的辅助函数放在 `commands/shared/`。
- 删除 `adapter.ts`、`builtins.ts`、`registry.ts`、`skill-command.ts`（零生产调用），以及 `types.ts` 里的 `Command` / `CommandResult` / `AppContext`。`app.ts` 的两处（交互 / 无头）直接构造 `CommandContext`。
- `CustomCommand` 保留为类，新增 `toUnifiedCommand(source)`；自定义命令和插件命令都经它进统一注册表。
- **修掉一个真实缺陷**：旧链路是 `AppContext → toCommandContext → toAppContext`，而 `CommandContext` 上没有 `checkpointSessionId`、`setAutoMemory`、`getAutoMemoryState`、`setExternalImportsApproved`、`getExternalImportsState`、`skillManager` 这 6 个字段，它们在往返中被静默丢弃。结果是：`/memory auto|external` 在生产中恒报「运行环境未接线」；`/undo` `/restore` `/checkpoints` 在 `-c` 恢复后够不到 resume 之前的检查点；`/reload-plugins` 不刷新插件 skill。这 6 个字段已补进 core 的 `CommandContext`。
- 旧 `kind: "error"` 经 `convertResult` 的输出是 `{ type: "text", value: "错误: …" }`。迁移后命令改用 `command/result.ts` 的 `errorText()` 直接产出同一形态，用户看到的文本逐字不变。
- 门禁：G2 改为「旧体系文件里的 `registry.register` 条数 + 复活的旧文件数」，基线 34 → 0；G4 原先查新旧同名，旧体系删除后改查后继形态：内置命令之间名字 / 别名撞车。G1 基线 29 → 8，tsc 基线 66 → 64。

## 放弃了什么（以及为什么不选）

- **§4.3 第二步「给 adapter 加编译期字段穷举」**：本 PR 把 adapter 整个删掉，只剩一份 `CommandContext`，不存在两份手抄就无所谓穷举，「漏抄一个字段」这类问题从结构上消失。先加断言、再连同 adapter 一起删，是白做。
- **按方案拆成多个小 PR 逐条迁移**：用户要求合成一个 PR。为了让 review 可控，迁移用 AST codemod 机械完成（按位置改文本、原注释保留），没有手改业务逻辑；正确性用元数据快照逐字段比对来证明（见下）。
- **把 `CustomCommand` 也拆进 commands/**：它是运行时按 .md 生成的实例，不是内置命令，留在 `custom.ts` 并给出 `toUnifiedCommand`。

## 拿什么证明它生效了

- **元数据零漂移**：迁移前后各跑一次 `loadBuiltinCommands()`，导出 67 条命令及子命令的 type / name / aliases / description / argumentHint / source 和全部门控字段，两份 JSON 逐字段、按顺序 `diff` 一致。`docs:gen-reference` 重新生成后无 diff。
- **缺陷回归 + 变异自证**：新增 `context-fields-reach-command.test.ts`，经 `CommandExecutor` 和真实命令表跑 `/memory auto|external`。同一份测试放在 main（d92c990c）上 4/4 红，本分支 4/4 绿。
- **G2 / G4 变异自证**：门禁测试里临时复活 `adapter.ts`，计数 > 0；给 `/cost` 加别名 `q`（与 `/exit` 冲突），报 `✗ G4 … q`，恢复后「四道门禁通过」。
- `bun run lint`、`typecheck:gate`（64 / 基线 66）、`lint:command-system`、`make build`（含二进制自检）全部通过。全量 `bun test`：18635 pass / 3 fail。这 3 条（`rules-paths-scope-nonempty` 两条、`isolated-subagent-cwd` 一条）与本改动无关：把未改动的 d92c990c 检出到同一位置（`.sid-code/worktrees/` 下）复跑也同样 3 红，在主仓检出下是绿的。原因是测试对「当前目录是 worktree」敏感。
