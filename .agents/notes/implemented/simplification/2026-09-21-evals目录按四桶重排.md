# evals 目录按四桶重排，只归档 inspect/

## 决定了什么

`git mv evals/inspect evals/_archive/inspect-spike`。顶层仍是 **11** 个目录
（PR-C 已建 `_archive/`，本 PR −`inspect/`，净零）。
`evals/README.md` 写下划线四桶规则：`_archive/` / `_data/`（逻辑桶，物理未迁）/
`_reports/` / `_judge/`。去向表每个消失的目录都有一行。
`_archive/README.md` 分母是 **2**：`judge-prompts/` + `inspect-spike/`，每行写清谁可能来查。

活引用切到新路径（spike README / `run_spike.py` / `sid_code_understanding.py` /
`swe-bench/接入计划.md`）。否决 Note 把原路径当史实保留，并注明已迁。

## 放弃了什么（以及为什么不选）

① 放弃 `_runs/` / `raw-outputs/` 的物理搬迁 —— 跨包边界，且改的是
`packages/eval-framework/core/runner.ts` 写给外部使用者的产物目录名
⇒ **顶层是 11 不是 9**。`.gitignore` 的 `/evals/raw-outputs/` 两行必须原样。

② 放弃把 `_diagnoses/` / `cross-provider/` 归档 —— 实测它们是活的
（`eval:diagnose` / `eval:verify-diagnosis` 两个入口；
`cross-provider-report.test.ts` 4 pass）。把活的东西放进「死了但要留」的桶是分类错。
`_archive/` 最终只有 2 个子项。

推翻条件：① eval-framework 下一次本就要做破坏性版本变更时，把那两个目录一起改掉；
② `_diagnoses/` / `cross-provider/` 的活入口哪天下线了，再单独判归档。

## 拿什么证明它生效了

- `ls -d evals/*/` 与 README 目录树逐项相等，无顶层 `inspect/`，有 `_archive/`。
- `git ls-files evals | wc -l` 相对 PR-C 基线 146：本 PR 只 mv + 新增 harbor 闸文件。
- `sh scripts/eval/check-holdout-real-tasks-sealed.sh` 退出 0（holdout 一字节未动）。
- `_archive/README.md` 说明行数 = 子目录数 = 2。
- `git diff .gitignore` 无输出。
