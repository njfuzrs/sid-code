# 账本行构造从 app.ts 下沉到 core（D1）+ 三处 require("fs") 改顶层 import（D2）

## 决定了什么

**D1**：把 `packages/cli/src/app.ts` 里 App 私有的 `buildLedgerEntry` + `buildLedgerSideUsage`
（约 76 行）搬成 core 的纯函数 `buildUsageLedgerEntry`（新文件
`packages/core/src/telemetry/usage-ledger-entry.ts`）。签名收 4 个入参：`sessionState`、
`fallbackModel`、`fallbackProvider`、`now`（测试注入时间）；`getIdentity` / `getRawVersion` /
`getPeakRatio` / `getSessionSideStats` 由新文件直接 import。**行为零变化**——原注释
（P0-1 / P0-4 / P2-1 / N12 / D1 的事故说明）逐条原样搬过去，一条没删。`app.ts` 侧
`buildLedgerEntry()` 留一行委托（`appendSessionToLedger` / `flushSessionLedgerIncremental`
两处调用点不动），因此不再使用的三个 import（`getIdentity` / `getRawVersion` / `getPeakRatio`）一并删掉。

**D2**：`app.ts` 三处 `const { ... } = require("fs")`（`countPlanSteps` 的计划文件读取、
Plan 审批对话框的读取、settings 回填的读取）改为顶层
`import { existsSync, readFileSync } from "fs"`，与文件里其他 node 内置模块的 import 写法一致。

**连带（超出卡片文件清单的一处必要改动）**：`packages/cli/tests/app/side-call-stats-resume-wiring.test.ts`
里那条静态门禁（锁「账本落盘与账本行都取会话维度 `getSessionSideStats`，不用进程维度
`getSideStats`」）的扫描目标跟随搬迁走：`buildLedgerSideUsage` 已不在 app.ts，
门禁改为扫描 core 新文件，并补一条锁 `app.ts → buildUsageLedgerEntry` 委托接线的断言。
**语义强度未降低**——原来的三条断言全部保留（其中一条换了扫描文件），只多了一条。

## 放弃了什么（以及为什么不选）

- **一次性拆分 `app.ts`**：风险太大。它是一个 10,384 行的单类，测试比（测试行数 ÷ 源文件行数）
  只有 0.46，绝大多数路径没有行为层接缝（`restoreSession` 这类私有方法只能靠
  `side-call-stats-resume-wiring.test.ts` 那种静态扫描门禁兜底）。没有对拍测试就大拆，
  等于把「重构」做成「静默行为漂移」。先拿纯逻辑（本卡的账本行构造）开刀，
  用「搬迁 + 逐字保留 + 新单测」验证手法，再谈下一块。
- **把 `appendSessionToLedger` / `flushSessionLedgerIncremental` 一起搬走**：它们耦合 App 的
  生命周期（退出路径 / 每轮 done 钩子）与 logger，搬走要连带设计新的注入面；
  而它们的逻辑就是「调 buildLedgerEntry → upsertUsageLedger」，收益（新增测试覆盖）极小。
  留在 app.ts 只做委托，是刻意的边界。
- **D2 顺手改掉第四处 `require("node:fs")`（`app.ts:2956`，`const fs = require("node:fs")`
  的命名空间写法）**：卡片范围是「三处 `require("fs")`」（验收命令也是
  `grep -c 'require("fs")' → 0`），且那一处用 `fs.existsSync(...)` 命名空间调用形式，
  与解构写法不同。克制在卡片范围内，不让「摘低垂果实」变成「顺手的重构」；
  代码检索方式与位置已在本 Note 记录，后续要改有据可查。
- **把纯函数并入既有的 `usage-ledger.ts`（而不是新开文件）**：`usage-ledger.ts` 已承载
  读写 + 剪枝 + 去重，被 aggregator / remote 多处 import；并入会让「落盘 IO 路径」与
  「构造纯函数」的依赖面绑在一起，也让新单测不得不 import 一个含 `node:fs` 的模块。
  独立文件保证纯函数能单独被测、单独演进。
