# 已加载工具的使用指南只发一份（tools[].description），system 不再重复

## 决定了什么

`buildToolGuideSection`（`config/system-prompt.ts`）不再给**已加载**的工具渲染「### X 工具使用指南」段，中英文档都一样。英文外壳 `buildToolGuideSectionEn` 也去掉了 `customGuides` 参数。

根因是同一段文字发了两遍。`toolToDefinition`（`tool/registry.ts`）已经把 `usageGuide()` 拼进了 `tools[].description`，system `<tool-guide>` 又用同一个 `usageGuide()` 渲染一遍，两份同源，正文逐字相同。

保留不变的：

- 延迟工具的整段指南，仍然放在延迟分区。它们首轮不在 tools[] 里，system 这一份是唯一能看到的。
- 「可用工具」的一行摘要。
- 「未加载的工具」名单，它防的是 2026-08-17 的 `enter_worktree` → `enter_plan_mode` 事故。
- MCP 工具段，它走的是 `buildMcpToolGuideSection`，不在本次范围内。

**opus 没有验证过**。这次 A/B 只跑了 deepseek-v4-1-flash，因为 opus 额度不够，这一点偏离了 F5「双模型都要通过」的规则。opus 额度恢复后补测 R2 + L3f，每臂 2 次。如果 opus 的召回或子代理派发明显下降，就回滚，或者只把 `sub_agent` 的指南放回 system（bench_fix 06a §7 丙案）。

## 放弃了什么（以及为什么不选）

- **删 description 那份、留 system 这份**：子代理的工具定义走 `registry.definitionsForTools()`，延迟工具激活后也走 `toolToDefinition`，两条路径都只认 description。删掉 description 那份，子代理和激活后的工具就看不到指南了。cc 也只在 tools[] 里放一份。
- **保留 `sub_agent` 的指南在 system，其余去重（06a 丙案）**：flash 上开关臂派子代理的次数变少（L3f 有派发的样本从 2/5 降到 1/5，R2 从 2/5 降到 0/5），但召回和覆盖率都没降。维护者决定按结果判通过，不为过程指标多跑一轮。等 opus 补测时再看要不要拆。
- **按 06a §4 的字面条件判不通过**：§4 写的是「子代理派发不少于对照臂」。写这条时以为 flash 对照臂是 0（F3 两次都是 0），本意是盯 opus。派子代理是手段，结果指标没退步，所以判通过。
- **顺手做 Q5-b（延迟工具完整指南）和 Q5-d（bundled `skill__*` 合并）**：一项一个 A/B，否则退步了没法归因。这两项排在后面。

## 拿什么证明它生效了

- **A/B**：同一个冻结二进制（`8b665f8a`，用环境开关区分两臂），每臂 R2 / S2v / L3f 各 5 次，共 30 个样本，全部 exit 0、`end_turn`、隔离生效。R2、S2v 是盲判：答案随机编号，每批每题混入 1 份 F3 已判过的样本作锚点。4 个锚点的复现结果是 10/10、16/17、13/13、12/12，判分口径没有漂移。

  | 指标 | 对照臂（system 有指南） | 改动臂 | 差 |
  |---|---|---|---|
  | R2 召回（原清单，n=5） | 0.450 | 0.492 | +0.042（95% 区间约 [−0.043, +0.127]） |
  | S2v 召回（原清单，n=5） | 0.433 | 0.467 | +0.033（[−0.064, +0.131]） |
  | L3f 覆盖（29 个应读文件） | 4/5 次读满 | 4/5 次读满 | 相同 |
  | 首调 input（真实题） | 38,019 | 34,703 | −3,316（−8.7%） |
  | ΣP 中位 R2 / L3f | 2.53M / 4.93M | 1.54M / 3.75M | 下降 |
  | 派了子代理的样本 L3f / R2 | 2/5 / 2/5 | 1/5 / 0/5 | 变少 |

  两题召回的置换检验 p 分别是 0.46 和 0.60，也就是召回分不出两臂差异，通过线（−0.05）以上。
- **单测**：`packages/core/tests/config/tool-guide-dedup.test.ts` 4 条：system 里不再有已加载工具的指南；`registry.definitions()` 的 description 里仍然有；延迟工具的指南保留；英文档同样生效。另外改了 3 条断言旧行为的既有用例（`system-prompt.test.ts`、`deferred-tools-in-prompt.test.ts`、`system-prompt-cache-key.test.ts`）。缓存键那条改成直接断言 `generateCacheKey`，因为已加载工具的指南不再进文本，但仍然要进键。
- **变异自证**：把已加载工具的指南重新渲染进 system，3 条用例变红。
- **回归**：`affected-tests:run` 1693 pass / 0 fail；term-bench 16 pass；lint 四件套、`typecheck:gate`、`docs:gen-reference-check`、`make build` 自检全部通过。
- **默认行为实测**：本分支构建的二进制，空 git 仓库，flash，首调 inputTokens 22,076（改动前 25,391）。
- 复现材料在 docs-research `sid-code/summary/00-Introduction/bench_fix/06a-F5-Q5-工具指南去重.md` §6–§7，采集与判分脚本在 `harness-bench/bin/q5a/`。
