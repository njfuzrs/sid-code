# sub_agent 常驻描述瘦身：类型行改短标签，「何时不该派」4 条并成 2 条

## 决定了什么

`packages/core/src/agent/tool.ts` 的 `sub_agent` 常驻文本（description + usageGuide，
每轮随工具定义下发）从 5369 字节省到 4551 字节，少 818 字节。两处改动：

1. `renderAgentTypeLines()` 的类型行不再逐字拼 `whenToUse` 全句，改用
   `AGENT_TYPE_SHORT_LABELS` 里的短标签（如 explore 的「只读探查（搜代码、读模块、定位实现）」）。
   自定义 / 插件类型没有登记时回退到 `whenToUse` 全句，不裁用户自己写的说明。
   这个函数同时供 `/context` 分类记账使用，记账口径随文案一起变，是两处同源的预期结果。
2. usageGuide 的「何时不该派」从 4 条各自带一段解释合并成 2 条。判别锚点一个没丢：
   同源错误、相邻文件、上下文读得完、全量验证（tsc），这些是
   `subagent-divide-criteria.test.ts` 的门禁字面量。

## 放弃了什么（以及为什么不选）

- **把 `whenToUse` 全句挪进 usageGuide 的「怎么选类型」**（方案原文的写法）。试过：
  usageGuide 那一条本来就是短标签口径的选择指引，再拼六条全句是把类型行省下的字节
  原样搬回来，合计反而几乎不降。全句（含 explore 的 quick/medium/very thorough 搜索深度说明）
  不再进每轮常驻文本；它仍是 `AgentDefinition.whenToUse`，展示面继续用。
- **删「何时不该派」的任何一条判据**。这四条是 2026-08-11「139 个类型错误派 3 个子代理
  各改一份互相影响的定义」那次事故后补的反面判据，门禁锁的就是它们还在。合并可以，删不行。
- **按模型下发不同描述**。方案 R8 明确否决：模型能力会漂移，写死分级本身就是隐患。

  差 818，超过方案定的 800 字节门槛。

  字面量在合并后的 2 条里全部还在。
- `bun run docs:gen-reference` 对 `website/ref/` 与 `llms.txt` 零漂移
  （`tools.md` 只取描述首句，首句没变）。
