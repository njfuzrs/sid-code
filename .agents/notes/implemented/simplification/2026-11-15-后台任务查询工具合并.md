# 后台任务查询工具合并：bg_task_get 并入 task_output

## 决定了什么

1. **工具合并**：`bg_task_get` 退役，它的独有字段并入 `task_output` ——
   `<retrieval_status>`（success / timeout / not_ready）、`<duration>`、
   agent 的 `<progress tools tokens>` + `<last_activity>` + `<progress_summary>`、
   shell 的 `<interrupted>`、monitor 的 `<command>`（截断 500），以及
   timeout / not_ready 的 `<hint>`（与旧 bg_task_get 逐字同源，不新增文案）。
   `task_output` 自己的增量读取、通知撤回、`<output>` 全部保留。
2. **旧名兼容两层**：`Registry.aliases` 登记 `bg_task_get → task_output`
   （模型仍调旧名时 `get()` 能解析）；`tool-name-aliases.ts` 新增
   `RETIRED_INTERNAL_TOOL_NAMES`（权限规则 / hook matcher / 子代理黑名单按内部名
   比较，旧名必须归一）。
3. **子代理里禁后台 bash**：`bash.ts` 在 `getAgentRoot() !== undefined` 时对
   `run_in_background=true` 直接拒绝，理由是可行动的（「去掉它前台执行」）。

## 放弃了什么（以及为什么不选）

- **按任务归属建查询机制**（bash 传 agentId、task_output 只允许查自己的任务、
  从 `ALL_AGENT_DISALLOWED_TOOLS` 移除 task_output）：方案 §T8 的另一条路。
  前置核对数据不支持它——30 天 1155 个事件文件、97,187 次 PreToolUse 里
  `bg_task_get` 只有 **20 次**调用，`bash run_in_background` 351 次；
  `events.jsonl` 的 PreToolUse 没有 sidechain 字段，无法进一步切分主/子代理，
  但总量本身说明这不是一个值得新增整套归属查询机制的场景。为一个几乎不发生的
  场景引入跨 agent 的权限模型，代价远大于收益。
- **两个工具都留、只修子代理禁用名单**：方案 §五 R2 已否决——成对写在
  `background-poll-guard` / `loop-detection` / `digest` 的逻辑还在，下一次新增
  后台任务规则还要记得写两遍；而且「把 bg_task_get 也禁掉」会让子代理查不到自己
  起的后台任务。
- **合并后保留 `bg_task_get` 的 block 默认值/超时语义差异**：两个工具的默认值本来就
  一致（`block` 默认 true、timeout 默认 30000、上限 600000），没有需要保留的差异。

  （`tests/tool/builtin-tool-meta.test.ts` 的硬编码基线同步改 41/17，属契约变更）。

  ./packages/core/tests/config/deferred-tools-in-prompt.test.ts ./tests/tool/`
