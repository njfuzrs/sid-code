# 删除 CostTracker 与两份零调用的 totalAPIDuration 累加器

## 决定了什么

**删掉 `CostTracker` 类**（`packages/core/src/api/cost-tracker.ts`）。它生产代码零调用，
唯一使用方是自己那份测试；`formatSummary()` 还是旧版 /cost 文案（用末次值当累计输入），
留着就是第三个「/cost 该长什么样」的落点。连带删掉只被它引用的 `ModelUsageEntry` 接口
与本文件内的私有 `formatTokens`。
`calculateUSDCost` / `calculateCostBreakdown` / `resolvePricing` / `effectivePricing`
**全部保留** —— `trace/cost-recompute.ts` 与 `trace/digest.ts` 在用。

**删掉两份 `totalAPIDuration` 累加器**（`packages/core/src/bootstrap/state.ts` 与
`packages/cli/src/state/bootstrap.ts` 各一套）。删的是字段 + 初始化 + 读写函数：
`addAPIDuration` / `getTotalAPIDuration`（core）、`addToAPIDuration` /
`getTotalAPIDuration`（cli）。

**连带处置 `turnAPIDurationMs` / `turnAPICount`**：这两个字段的唯一写入者就是
`addToAPIDuration`（`STATE.turnAPIDurationMs += durationMs`），删掉写入者后它们会变成
「只被 `getTurnMetrics` 读出 0、被 `resetTurnMetrics` 写回 0」的恒 0 死字段 ——
那正是 D21 要治的形态（「下一个改 API 耗时的人接到死字段上，看到恒为 0」）。
所以一起删，`getTurnMetrics()` 相应只返回 `toolDurationMs` / `toolCount`，
`resetTurnMetrics()` 去掉两行重置。`getTurnMetrics` 本身生产零调用，唯一消费者是测试。

API 耗时的**唯一来源**是 `SessionState.totalAPIDuration`
（`packages/core/src/session/state.ts`），`/cost` 经 `buildCostReport` 的
`apiMainMs` 读它（`packages/core/src/session/cost-report.ts:313`）。

## 放弃了什么（以及为什么不选）

- **连 `SessionState.totalAPIDuration` 一起删**。它是真数据源，不是死字段：有生产写入
  （`state.ts:461`）、有持久化快照回灌（`state.ts:636/654`）、被 `/cost` 与 trace 读。
  方案里 D21 点名的死字段只有「bootstrap 里的那两份」，删真数据源是另一个 bug。
- **把 `CostTracker` 保留并改成 `SessionState` 的薄包装**。它没有任何调用方，
  包一层不会产生新读者，只会让「两套账」看起来仍然合法。
- **顺手删掉 cli bootstrap 整个累加器区**（`addToToolDuration` / `getTotalToolDuration` /
  `addToCost` / `getTotalCostUSD` / `getModelUsage` / `getStartTime`）。这几个同样生产零调用，
  但它们共享同一层「进程级状态访问器」的形状、且测试在用；一次删光是跨包重组，
  不是「删 D21 点名的死字段」。要做需要单独一份方案，别混进来。
- **保留 `turnAPIDurationMs` 字段但不再赋值**。编译合法，但留下恒 0 字段 ——
  与 D21 的动因完全相反。

## 拿什么证明它生效了

  `addToAPIDuration` / `getTotalAPIDuration` / `turnAPIDurationMs` / `turnAPICount`
  **零命中**（只余 `cost-tracker.ts` 顶部一行解释性注释，指向本 Note）。

  → 22 pass / 0 fail（`CostTracker` 的 5 例随类删除，其余 22 例全绿）。
- `bun run affected-tests:run`、`make build`、`bun run lint`、`format:check`、
  `typecheck:gate`、`lint:boundary`、`lint:command-system`、`lint:legacy-tool`、
  `docs:gen-reference --check`、`verify:agent-note` 的结果见 PR 正文。
