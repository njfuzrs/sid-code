# 思考开关关不掉与展示不诚实：线上 `off` 显式 disabled + 能力位 thinkingControl

## 决定了什么

对应排查文档 `20261016-思考开关不生效与切换模型异常` 的 PR-1 + PR-2（合一个 PR）。

**PR-1（线上，D1 D1′ D2 D3 D4 D3b）**
- 注册表补 `claude-opus-5` / `claude-sonnet-5`（adaptive，1M / 128K，Opus 5 $5/$25、Sonnet 5 $2/$10），新字段 `thinkingOmitMeans:"on"`；Haiku 5.5 也补这一位（v3 实测不传 = 思考）。
- 新增 `dialect/thinking-off-wire.ts`：判「关」在 Anthropic 协议线上写 `{type:"disabled"}` 还是不发。只对**注册表精确命中** `thinkingOmitMeans:"on"` 的模型和 DeepSeek Anthropic 兼容端点发 disabled；恒思考、旧 Claude、未注册、仅模糊命中的一律不发。
- `anthropic.ts` 流式 / 非流式两处收成 `buildThinkingWire`；发 disabled 时不带 `output_config.effort`（Opus 5 + max 实测 400）。side-call 的 `SIDE_CALL_NO_THINK` 也走这里。
- `dialect/anthropic.ts` applier 改按真名（`pickWireModel`）查注册表。

**PR-2（展示，D5 D6 D7）**
- `EffortCapability` 新增 `thinkingControl: toggle | locked-on | none`，`thinkingDefaultOn` 改为「auto 时服务端实际是否思考」，由 `finalizeThinkingControl` 按真名算。locked-on 判据与两处线格式降级同口径（注册表 always-on / `isThinkingAlwaysOn` / compat `thinking_always_on`）。
- `resolveThinkingState` 返回 `{intent, effective, control}`，作为状态栏、`/think`、Alt+T、ThinkDialog 的唯一取数源。状态栏 locked-on 显示 `✻·不可关`，none 显示 `✧内置`（此前不显示，被读成已关）；`/model` 详情行加「思考 可开关 / 恒开 / 内置」。
- `/think off` 在恒思考模型上照存意图（切回可关闭的模型自动生效），并如实提示本模型上不生效；Alt+T 在恒思考模型上不翻转，只提示。

## 放弃了什么（以及为什么不选）

- **按版本号判「5.x 不传 = 开」**：违反「不按模型名硬编码分档」，而且 5.5 一代全是恒思考（disabled 会 400），外推必错。
- **线格式层用 `lookupRegistry`（含模糊匹配）**：加了 `claude-opus-5` 键后，`claude-opus-5-6` 等未来小版本都会命中、继承 `"on"` → 发 disabled。如果新版本是恒思考，`off` 和全部 side-call 都会 400。所以只认精确命中，不知道就不猜。
- **400 自愈兜底**：Anthropic 路径没有可复用的自愈（排查 §8.7）。代价是注册表写错时会出一次响亮的 400，影响范围限定在手写的那几个键。
- **把判定放进各族 applier**：side-call 不经过 applier，修不到 D3。
- **让 `resolveThinking` 直接返回 effective**：GLM-5.3 在 `/think off` 时会改发 `enabled` 加 effort 档位，用户说关反而多下发一个强度。下发意图和展示值分成两个函数。
- **locked-on 时把 `supportsThinkingToggle` 置 false**：这一位还驱动 `ThinkingManager` 的 ultrathink 提级，会把它一起关掉。
- **无开关族的 `off` 映射到 effort 最低档**：需要逐模型的服务端证据，目前没有（排查 §6）。

## 拿什么证明它生效了

- `tests/llm/thinking-off-wire.test.ts`：5 一代 / DeepSeek 端点发 disabled，恒思考 / 旧模型 / 模糊命中的未来小版本不发；side-call 路径；disabled 剥 effort；别名不同形时 applier 仍走 adaptive。
- `tests/llm/thinking-state.test.ts`：**「展示 == 实发」不变量**，遍历注册表全部 Anthropic 条目 × on/off/auto，`resolveThinkingState().effective` 必须等于经真实 applier 和 `buildThinkingWire` 之后线上是否思考。
- 变异自证：把 `thinkingOffWire` 改回恒 `"omit"` → 不变量里 5 一代 × off 变红；把精确匹配改成 `lookupRegistry` → 「模糊命中不发」那条变红。
- 线上验收（合入后）：`sc-dev` 对 `claude-sonnet-5` 走真网关 `/think off`，响应里不应再有 thinking 块（排查 §9 第 4 条）。轨迹口径的「关闭泄漏率」要等 PR-5 补埋点后才能复算。
- 行为变化要在发版说明里写明：Opus 5 / Sonnet 5 的窗口和定价从兜底值改为注册表值；这两个模型及 Haiku 5.5 的 `auto` 态展示由「关」改为「开」（服务端本来就在思考）。
- **原方案 §9.3 变异表补记（2026-10-18 复审 T6，逐行实跑，判据是红的是哪一条）**：
  1. `buildThinkingWire` 的 off 分支改为恒不发 → 8 条红：不变量 `claude-sonnet-5 / opus-5 / haiku-5-5 × off`、「Sonnet 5 主循环 off → disabled」「side-call 在 Sonnet 5 上也发 disabled」「disabled 时剥 effort」。
  2. 注册表 `claude-sonnet-5` 键改名（等于删条目）→ 11 条红：「Sonnet 5 / Opus 5 on → adaptive」「Sonnet 5 off → disabled」、D7 auto 默认值、两个覆盖面哨兵。
  3. `thinkingOffWire` 对恒思考返回 `disabled` → 2 条红：「恒思考模型 → 不发」「恒思考 off 线上不出现 disabled」。
  4. `resolveThinkingState` 对 locked-on 返回意图 → 6 条红：不变量 5 个恒思考条目 × off、「locked-on 下 intent 报 off、effective 报 on」。
  5. `thinkingOffWire` 对未注册 `claude-*` 返回 disabled → 3 条红：「旧 Claude 不发」「模糊命中的未来小版本不发」「旧模型 off 不发」。
  6. `lookupRegistryExact` 改为 `lookupRegistry`（含模糊）→ 1 条红：「仅模糊命中的未来小版本 → 不发」。
- **不变量的边界（复审 T8）**：「展示 == 实发」在「不发」分支读的是注册表 `thinkingOmitMeans`，与被测代码同源，锁得住两处一致，锁不住数据对。2026-10-18 补了一张手写矩阵哨兵（注册表每个 `claude-(opus|sonnet|fable|mythos|haiku)-\d` 键的 control / omitMeans），让改注册表必须同时改测试进 review；数据本身是否对，只能靠真网关验收（复审 V1）。
