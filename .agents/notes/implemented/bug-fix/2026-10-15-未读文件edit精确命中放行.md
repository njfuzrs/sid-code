# 未读文件的 edit 改为「精确命中放行、近似匹配拒绝」，write 不变

## 决定了什么

`edit` 对从没 `read` 过的文件，不再在入口一刀切拒绝。改为把判定推迟到匹配之后：

- old_string 在磁盘全文里**精确命中**（含 1:1 引号规范化）→ 放行，埋点 `allowed_unread_exact`
- 只能靠灵活 / 正则 / 模糊匹配命中，或完全未命中 → 拒绝，埋点 `rejected_unread` 并附 `match_strategy`

不变的部分：

- `write` 覆盖已有文件：照旧必须先读（`validateForWrite`）
- 读后被外部修改（`rejected_modified`）：不变
- `old_string=''` 的创建 / 填充：不变

改动在 `packages/core/src/tool/edit.ts`（延后判定）与 `file-read-tracker.ts`（`rejectUnread` / `noteUnreadExactEdit` 单一出口）。

判据不是「模型会不会犯错」，而是**「犯错时有没有别的东西兜底」**：

- 精确匹配有兜底：匹配不上就报错，不会改错，所以 read 前置是多余的一层。
- 4 级降级匹配没有兜底：没看过文件、凭印象拼的 old_string 可能被模糊匹配静默落到相似的错误块上。read 前置是这条路上唯一的防线。
- write 整文件覆盖：会丢掉模型没见过的内容，同样没有兜底。

## 放弃了什么（以及为什么不选）

- **整条规则删掉（对齐「harness 校验应减少」）**：sid-code 的 edit 与 CC 不同，带 Levenshtein 模糊匹配。CC 能更薄，是因为它只做精确匹配。删掉等于拆掉模糊匹配唯一的前置防线，故否决。
- **识别 bash `cat`/`head`/`sed -n`，把文件标成已读**：要解析 shell 命令（管道、重定向、变量、cd），脆弱且永远补不全。还会漏掉另外 8/38 不经 bash 的情形（例如凭对话里的 diff 或之前的输出直接改）。精确命中这个判据和读取途径无关，更简单也覆盖更全，故否决。
- **只靠提示词让模型先 read**：`bash.ts`、`edit.ts` 的提示词早就写了不要 cat、要先 read，实测仍有 30/38 违反，压不住，故否决。

## 拿什么证明它生效了

轨迹基线（2026-10-15，本机 188 会话）：

- edit/write 共 863 次，「未读」拒绝 38 次（4.4%），分布在 16 个会话
- 其中 30 次在 bash 里 cat 过同名文件
- 20 次补读后 old_string / new_string 原样重发，即纯空转

本 PR 验证：

- 新增 5 条用例：精确命中放行、灵活匹配拒绝且不落盘、读过后同一灵活匹配放行（对照组）、未命中报先读、精确多处照常报错
- 变异自证：把延后判定改成恒放行后，3 条用例变红（灵活拒绝、未命中、子代理 tracker 隔离），恢复后全绿
- `affected-tests:run` 1668 pass / 0 fail；`make build` 通过，无 `will always be undefined`

上线后看 `file_freshness` 事件：

- `allowed_unread_exact ÷ (allowed_unread_exact + rejected_unread)` 应接近原样重发占比（≈50%+）
- `rejected_unread` 应只剩带 `match_strategy` 的近似 / 未命中，以及 write
- 同时看 northstar `edit_first_try_rate` 是否上升，不只看代理指标

需要留意的退步信号：精确命中放行之后，紧跟着出现「模型改完立刻改回」的返工。
