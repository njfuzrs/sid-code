# 能力自愈：结构兜底只重试不记账，学到的能力在 7 天内压过目录

## 决定了什么

- **T1 归因收紧**（`model-capabilities.ts::recordHealOutcome`，流式 `withCapabilityHealing` 与非流式 `sendMessageNonStreaming` 共用）：
  错误措辞点名 `reasoning_effort` 且重试成功才立即记账 `effortValues: []`；只凭 HTTP 4xx 的结构兜底
  **照常剥字段重试**，但只累加进程内计数，同进程连续 3 次成功才升级落盘；任一次重试失败清零计数。
  重试行为本身不变（「措辞匹配不到也必须自愈」的既有用例保留）。
- **T2 学习结果优先**（`learnedOutranksCatalog` / `restoreLearnedFields`）：已有条目是 `healed` / `probe`
  且 `fetchedAt` 在 7 天内时，`source: "catalog"` 的 patch 不覆盖 `effortValues` / `supportsReasoning` /
  `maxOutputTokens`、不改 `source` 与 `fetchedAt`，只补空缺字段（`contextWindow` 等照常更新）。
  `persist()` 的跨进程「内存盖磁盘」用同一判据：磁盘是有效期内学习结果、内存是目录时不覆盖。
- **T3 可观测**：新增本地轨迹事件 `CapabilityHealed`（`model` / `trigger: wording|structural` /
  `status_code` / `stripped` / `recorded` / `retry_ok`），经 `llm/capability-heal-telemetry.ts` 模块级观察者
  由 `TraceCollector.registerHooks` 注入。只进本地 events.jsonl，不进外发遥测 `EVENT_NAMES`。
- **T4**：`model-compat.ts` 头注释改为 8 位 / openclaw 36 位，`openai.ts:650` 改成标识符引用（`config.ts` 同一处漂移一并改）。

## 放弃了什么（以及为什么不选）

- **去掉结构兜底**：漏判一种措辞 = 用户看到修复前不存在的 400（实测 11 种措辞漏 5 种），代价大于多一跳。
- **结构兜底也立即记账、靠「已有非空档位」守卫兜底**：轨迹两例（glm-5.3-uniapi MaaS 400、gpt-6-luna 回放解密失败）
  只是碰巧被守卫挡住；目录里没有档位的模型会被一次偶发 400 永久记成不支持 effort。
- **进程内计数落盘 / 跨进程累积**：结构兜底是弱证据，跨进程累积会把多次独立的偶发网关错误拼成「连续」。
- **学习结果永久压过目录**：学错了就永远撤不回；7 天过期是唯一撤回路径。7 天与阈值 3 都没有实测依据。
- **把 `CapabilityHealed` 加进外发遥测**：服务端事件名是 fail-closed 白名单，要同步 agent-backend；本次需求是本地轨迹可复算。
