# 上下文工程五条 P0：静态区漏标、聚合预算接错时机、KEEP_RECENT 改写前缀、白名单写错名、守卫零调用

## 决定了什么

修的是 sc-02-context 核出的五条 **P0**（P1/P2 不动）。同一 PR：

1. **P0-1** `generateClaudeMdAttachment` / `generateDenyRulesAttachment` / `generateSkillListingAttachment` / `generateGitStatusAttachment` 包 `stableAttachment()`。未标记默认进动态区，CLAUDE.md 跟日期拼成一块。改规则仍走已有 `clearPromptCache()`。
2. **P0-2** `addMessage`（含同角色合并）调 `applyToolResultBudgetToContent`。聚合预算不再只等 hard 档。read/edit/write/read_many 用 `skipToolUseIds` 豁免，跟入队持久化同一份名单。先单块持久化再聚合，避免把可落盘的超大 bash 误截成不可恢复占位。
3. **P0-3** `sentIntactToolResultIds`：某 `tool_use_id` 完整出现在一次 `getCleanedMessages` 返回值后，后续轮次禁止再改成占位符。KEEP_RECENT 窗口前移不再改写已发送前缀。已经进过 `replacementState` 的 id 必须继续贴同一份占位，否则下一轮会把上一轮清掉的内容还原回原文。
4. **P0-4** `NON_DISCARDABLE_TOOLS` 改成真实规范化名 `savememory` / `askuserquestion`。门禁用 `EditTool`/`WriteTool`/`MemoryTool`/`AskUserQuestionTool` 的 `name()` 对名单。
5. **P0-5** `isCompactSourceMessage` 接到 `getCompactionLevel` 与 `findCompressSplitPoint` / snip 跳过首条；`TokenFreedTracker` 实例化在 Manager，首次改写大输出时记账，触发决策从 used 里扣。压缩/截断/`setMessages`/`clear` 走 `resetLocalCompactState()`。

## 放弃了什么（以及为什么不选）

- **P0-1 顺手拆动态区多块（P1-8）**：本 PR 只修漏标。拆块是另一条放大器，不挤这次。
- **P0-2 挂在 tool-executor 批次完成处**：真正入历史的是 `addMessage`，含取消/异常补 result 与同角色合并。挂执行器会漏合并后的第二条。
- **P0-3 把 KEEP_RECENT 改成「永不清理已发送」之外再加时间窗**：冻结已发送内容会让占用上升、hard 更早触发——这是「更省 cache ↔ 更省 token」的内部互斥，主口径看 token-per-task。再加时间窗会重新引入前缀改写。
- **P0-4 顺手收 `notebook_edit`（P2-16）**：文档明确降为 P2，不挤本条。
- **P0-5 删掉两个符号承认不做**：写入已经补上，删了就再也接不上。接到触发决策比「只进 digest」便宜，也比「硬拦所有二次 compact」安全——有新对话时守卫放开。
