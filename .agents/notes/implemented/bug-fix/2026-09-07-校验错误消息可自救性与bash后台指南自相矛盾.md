# 让参数校验错误消息「读完就知道改什么」；修掉 bash 指南推荐已废弃参数

## 决定了什么

报障文档列了 4 处失败，逐条回源码 + 轨迹核过之后，**只有 2 处是 sid-code 的缺陷**，
另 2 处不是（见下一节）。修的是这 2 处，外加核查时撞见的第 3 处。

判据统一：**不是「有没有报错」，而是模型读完这条消息知不知道下一步该改什么**。
报错本身是对的，问题在于它把模型推向错误的修法。

### ① `todo_write` 传 camelCase → 报「你漏传了」，真相是「名字写错了」

实测 `20260907-155904-69998cf1`（`toolu_bdrk_01Bu1b5yfCdPu19Nkvw8MTPj`）：模型传
`activeForm`，schema 要 `active_form`，5 个 todo 项全中，连报 5 条：

```
- todos.0.active_form: 期望 string，实际收到 unknown（... received undefined）
```

根因是 **zod 对未识别键是静默剥离，不报 `unrecognized_keys`**
（实测 `z.object({a}).safeParse({a,bogus})` → success，data 里没有 bogus）。
于是「传错名字」与「根本没传」产生**逐字相同**的报错，而这两句话指向完全不同的修法：
模型照着「实际收到 undefined」会去补一个它以为漏掉的字段，而不是改名。

新增 `findNearMissKey`：沿 `issue.path` 走到父容器，找归一化后（去下划线/连字符、
转小写）与期望键相等的实际键，命中就把修法直接写出来（「你传的是 X，参数名是 Y，
改名重试，不要新增字段」）。

**刻意不做模糊距离匹配**——那会在 `offset`/`limit` 这类短名之间乱指，
把一条准确的错误变成误导。只认命名风格差异（snake_case ↔ camelCase ↔ kebab-case）。

### ② `ask_user_question` 数量越界 → 只说「太少了」，不说底线、不说怎么办

实测同一会话（`toolu_bdrk_01EsjySCE828Pc3EEXLAW9VA`，`options_per_q=[1, 2, 2]`，
只有第 0 题违规）：模型看到的全部信息是

```
- questions.0.options: Too small: expected array to have >=2 items
```

一句英文原文，不含上限（4）、不含单位、不含修法。`translateIssue` 原先只处理
`invalid_type` 与 `unrecognized_keys` 两个 code，`too_small`/`too_big`/`invalid_value`
全部落到「直接透传 zod 的 message」兜底。现补三个分支：数量/长度/范围越界带出边界数字
与量词（个元素/个字符/数值），枚举非法直接列出合法取值。

### ③ 核查时撞见：bash `usageGuide` 推荐的是**已废弃**参数

`bash.ts:56` 的 schema 写着 `is_background: [已废弃，请用 run_in_background]`，
而 `bash.ts:502` 的 usageGuide 写着「可设置 **is_background**=true 后台运行」——
**指南与 schema 自相矛盾**，模型照指南走就落进旧通道（不进 Task 系统、无 task_id、
无完成通知，见 `bash.ts:747` 注释自己写的）。顺带补两条超时后的出路
（转后台 / 缩小范围优先用 glob·grep），因为实测那两条 bash 超时后模型只是干等，
没有转后台。

## 放弃了什么（以及为什么不选）

**④ 报障文档里的两条 bash 超时 —— 判定不是缺陷，不改超时逻辑**

```
find /Users/.../iam-studio-fe -type d -name "utils" ...   → 120s 超时（墙钟 337s）
grep -rl "tags/promote" ~/Code ...                        → 120s 超时
```

第一条命令是 `find` 扫整个 monorepo + `find / -maxdepth 10`，第二条是 `grep -r ~/Code`
全盘扫——**这两条本来就该超时**，超时保护正确工作了。而且那条「实际墙钟 337s
远超设定 120s，期间系统很可能进入过休眠」的提示也已经在了（`bash.ts:1041-1050`，
挂钟兜底是 20260801 事故的既有修复）。

真正缺的不是超时机制，是**指南没告诉模型「别全盘扫」和「超时后怎么办」**——
所以修法落在 ③ 的 usageGuide，不动超时代码。给全盘搜索自动加 `run_in_background`
的想法**否决**：模型的意图是"现在就要这个答案"，静默转后台会让它拿到一个 task_id
然后不知道该等谁，比超时更糟。

**⑤ 报障文档里的 grep 路径不存在 —— 判定不是缺陷，错误消息已经是最优的**

```
错误: 文件不存在: .../packages/libs/request/src
当前工作目录: .../packages/base
注意: 父目录 ".../packages/libs/request" 也不存在，路径可能整体有误
```

模型凭猜想拼了一个不存在的路径。这条消息**已经**给了当前 cwd、已经逐级回溯指出
父目录也不存在、已经点明「路径可能整体有误」——比"文件不存在"强得多，
没有可改进的地方。这是模型该用 glob 先确认路径而没用，不是 harness 的洞。

**⑥ 给 `active_form` 加 camelCase 别名（`.or()` / preprocess 接受两种写法）—— 否决**

看着比改错误消息省事，但它把一个字段变成两个合法名字：schema 是给模型的契约，
契约里同一个东西有两个名字，下一个模型就会两个都传，或者在不同工具间混用
（19 个 snake_case 字段全都要考虑加别名）。**错误消息教它改名是一次性成本，
别名是永久的契约债**。

**⑦ 把 `edit` 缺 `file_path` 也算进本次 —— 不做**

顺手统计全部 50 个会话时发现 `edit → file_path` 缺失 5 次（4 个会话），
比本次两条都高频。但核过之后：`stop_reason=tool_use`（不是截断）、
input 里只有 `old_string`/`new_string`，**模型是真的没传**，没有近似键可指——
①的机制对它无效，报「实际收到 undefined」已经是准确的。
它需要的是别的东西（可能是 edit 描述里强调 file_path 必填），
**不属于本次范围，也不该塞进来凑数**。已记在这里，不是遗漏。

## 拿什么证明它生效了

**新增测试全部走真实 `validateToolInput` 入口**（不是测纯函数），
喂的就是轨迹里那两条原始入参：

```
$ bun test ./packages/core/tests/tool/input-validator-self-recovery.test.ts
 17 pass / 0 fail / 52 expect() calls
```

**变异自证（4 次，拆掉任一条都必须变红）** ——

| 变异 | 结果 |
| --- | --- |
| `findNearMissKey` 恒返 undefined（拆改名识别） | **5 fail** |
| `formatZodError(...)` 不传 `normalized`（模块在但没接线） | **5 fail** |
| 停用 `too_small`/`too_big` 分支 | **4 fail** |
| 停用枚举取值列举 | **1 fail** |
| 还原后复跑 | 17 pass / 0 fail |

第 2 个变异特意只拆接线、不删函数——它拦的是「代码写好了但没接进真实入口」
这种零报错的失效形态（上一个 PR 也用了同一招）。

**③ 的反漂移断言**（`bash-stability.test.ts` 新增 4 条）：指南必须推荐
`run_in_background`、不得出现「设置 is_background=true」、必须点名 task_output/task_stop，
且**点名的工具名要与真实注册名一致**（防"指南教模型调一个不存在的工具"）。

**门禁** ——

```
$ bun run affected-tests            # 判定 selective → packages/core/tests/tool/
$ bun test ./packages/core/tests/tool/ --test-name-pattern '^(?!.*\[slow\])'
 1048 pass / 0 fail / 22270 expect() calls
$ bun run lint / format:check / lint:boundary      # 全绿，越界 0 处
$ make build                        # 自检 5 项通过；grep 'will always be undefined' → 无
$ bun run docs:gen-reference --check # 参考页与源码一致
```

⚠️ 一次 `bash-stability.test.ts` 单跑时 `缺口1: 超时机制真正生效` 报
`elapsed 3754ms < 3000` 失败。核过：该断言是墙钟阈值（`sleep 5` + timeout=1s，
余量 3s），并发负载下会抖；**我对 `bash.ts` 的改动只有 `usageGuide()` 里的字符串
字面量，那条用例根本不调 usageGuide**。单独重跑 3/3 通过、整文件重跑 3 次 26/26 通过。
如实记在这里而不是当没看见。

**朝向北极星哪个方向**：**更准**（②工具层：把「必然失败 + 修法误导」变成
「失败但一次改对」）+ **更省**（少一轮白烧往返；③还消灭了"落进旧后台通道
拿不到输出"这个死角）。
**牺牲了什么**：错误消息变长（近似键提示 + 边界数字），多占几十 token；
换的是模型不必再猜修法。近似键检测刻意只认命名风格、不做模糊匹配，
就是不愿用"更能猜"去换"猜错时误导"。
