# 首屏对话框里的按键不再被早期输入捕获回填成 NUL

## 决定了什么

进入带未信任项目扩展的目录，信任框里按 ↑ + 回车后，输入框多出看不见的字符，用户删掉才能正常输入。
真 pty 复现时提交文本是 `"\x00\x00\x00bc"`（敲的是 `abc`）。多出来的不是空格，是 NUL。

两个缺陷叠在一起：

1. **捕获停得太晚**：`early-input.ts` 的早期按键捕获只在 `InputArea` 挂载时才停。首屏弹信任框 /
   MCP 审批框时 `InputArea` 不挂载，捕获就和 `KeypressContext` 一起读 stdin。对话框里的 ↑、回车，
   加上关框后的第一个字符，都被它吞进缓冲；`InputArea` 挂载后又回填进输入框。
2. **字符串被当成字节处理**：`KeypressContext` 调过 `setEncoding("utf8")` 之后，`read()` 返回的是字符串。
   旧实现按字节遍历，`String.fromCharCode("a")` 得到 NaN，也就是 `"\x00"`，所以每个字符都变成了 NUL。

改法：

- `KeypressProvider` 接管 stdin 时调用 `stopCapturingEarlyInput()`。它只停捕获，已缓冲的内容保留，留给 `InputArea` 取。
- 新增 `appendEarlyInputData()`，统一按字符处理 Buffer 和字符串。ESC 序列整段跳过（旧实现只跳 ESC 一个字节，会把 `[A` 留下），退格按码点删除。

## 放弃了什么（以及为什么不选）

- **只在 `InputArea` 回填时过滤 NUL**：这只盖住了症状。对话框里的回车仍会变成输入框里的换行，第一个字符照样被吞（修复前提交的是 `bc`，丢了 `a`）。
- **对话框打开期间不消费 early-input**：两个读者同时读 stdin 这件事本身就是错的，按哪种时序 hack 都会漏。停止点要放在「键盘层接管 stdin」这个唯一的时刻。

## 拿什么证明它生效了

- 真 pty 复现（python `pty.fork()`，隔离 `SID_CONFIG_DIR`，父目录 `.claude/commands/` 下放未信任命令，选信任后输入 `abc` 再回车）：
  - 修复前（开发版二进制）：`提交输入: "\x00\x00\x00bc"`
  - 修复后（worktree 构建）：信任组为 `提交输入: "bc"`，不信任组为 `"bc"`，不弹框对照组为 `"bc"`
  - 首字符 `a` 在三组里都丢了，修复前的二进制在不弹框目录下也一样，说明这是另一条独立现象（启动完成前的按键时序），不属于本次范围。
- `bun test ./packages/cli/tests/ui/early-input.test.ts`：7 pass / 0 fail
- `bun run affected-tests:run`：2382 pass / 0 fail；`bun run lint`、`format:check` 通过；`make build` 通过，没有 `will always be undefined` 警告。
- `typecheck:gate` 在 worktree 里报新增 21 项，都不涉及本次改动的文件。成因是 worktree 的 `node_modules` 软链到主仓，同一类型被解析成 `<root>` 和主仓绝对路径两份。
