# save_memory 显式 type、提取代理与权限层同口径、写入质量可观测

## 决定了什么

对照《Agent 记忆系统入门》§3「拒绝器比提取器重要」核代码，再用本机轨迹 / 遥测 / 磁盘数据逐条验证，修六处：

1. **save_memory 加必填 `type`**（`tool/memory.ts`）。此前类型全靠 `inferMemoryType` 关键词猜，缺 type 时直接拒绝，不再回退猜测。
2. **提取提示词删掉 team 分流段**（`extract/prompts.ts`、`extractor.ts`、`app.ts`）。权限层只放行 project，提示词却在团队记忆开启时引导写 `scope=team`，两边不一致，统一以权限层为准。
3. **类型名填进 scope 单独归类**（`extract/permissions.ts`）。新增 `memory_guard.kind=scope_type_confusion`，拒绝信息直接告诉模型改成 `type="..."`。
4. **`inferMemoryType` 的 reference 判据收窄**（`store.ts`），只认「正文有真 URL」或「key 点名外部系统」。`agent-store.ts` 原先复制了一份正则，改为复用这个判据。这个函数现在只服务没有显式 type 的兜底路径。
5. **写入提示判据修正、覆盖面补齐**（`tool/memory.ts`）：
   - Why 和 How to apply 改为认「标签」，不再认疑问词「为什么」，并且两个都检查；
   - 相对日期补上星期；
   - 新增「reference 无 URL」「进度快照形态」两条提示；
   - team 和 agent 两条路径也走提示（之前存完直接 return）。
6. **新增 `memory_write` 埋点和读数脚本**（`analytics/events.ts`、`scripts/memory-quality-report.ts`）。埋点只记枚举和布尔，不记 key 与内容。脚本给出存量和增量两个口径，判据与写入侧共用 `assessMemoryWrite`。

dream 和主会话提示词同步说明 type 必填，官网 `website/use/memory.md` 同步更新。

## 放弃了什么（以及为什么不选）

- **给权限层开 team 通道，保留提示词的分流段**：team 记忆会同步给所有协作者，误判的结果是全团队上下文被污染，而且没人察觉；后台提取代理又恰好无人监督。P1-9 当初收窄权限也是这个理由。团队约定改由主会话（有人在场）显式写入。
- **只改 `inferMemoryType` 的正则，不加 type 参数**：关键词猜测在两头都会失败。一头是正文提一句「文档」就被判成 reference；另一头是模型想表达类型却没有参数可填，只能塞进 scope（遥测里 28 次 scope_denied，有 20 次是这种）。类型是模型最清楚的语义，应该让它显式给。
- **把写入提示做成硬拒绝**：关键词判断有误判率，比如「每周写周报」、引用原话。硬拒绝会让一次合法的保存失败，模型也绕不过去。软提示 + `hint_count` 埋点已经能量化效果。
- **脚本自动修正存量记忆的类型**：一条 reference 该改成 feedback 还是 project 属于语义判断，而且记忆是用户数据。延续 `memory-dup-report.ts`「只列不改」的做法，存量交给 autoDream（它的提示词已要求合并时纠正无 URL 的 reference）或人工处理。
- **把 `scope_type_confusion` 并进 `scope_denied` 计数**：两类混在一起的话，修好 type 参数后曲线降了，分不清是哪一类在降。

## 拿什么证明它生效了

修复前的基线（本机，2026-10-24，`bun run scripts/memory-quality-report.ts` 实跑）：

```text
存量 408 条：reference 无 URL 85.1%（172/202）· 缺 Why 标签 14.5%（22/152）· 缺 How 8.6%（13/152）· 快照形态 10.8%（44/408）
遥测 memory_guard：scope_denied 28 次，其中 scope=feedback/user/reference 20 次
```

测试与变异自证（`bun test ./packages/core/tests/memory/write-quality-gates.test.ts`，22 pass）。七处修复各自改回旧逻辑后，对应断言都会变红：

```text
A 类型推断回退旧正则: 1 红 · B 去掉类型混淆分支: 1 红 · B' 缺 type 不拒绝: 1 红
C Why 回退宽松正则: 3 红 · D 去掉星期: 2 红 · E agent 不走提示: 1 红 · F 去掉埋点: 1 红
```

上线后看哪些数：
- `memory_guard.scope_type_confusion` 应该接近 0（基线约 20）；
- `memory_write` 里 `memory_type=reference` 且 `reference_no_url=true` 的占比，应明显低于存量的 85%；
- `missing_why` 占 feedback/project 写入的比例应低于 14.5%。

这几项要等新版本跑过会话才有数据，本 PR 只能证明埋点接通、判据正确，指标是否改善要等后续数据。
