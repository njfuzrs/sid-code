# 宿主休眠同时污染 `agent_ms` 与静默给超时闸门续命：既防止发生，也让发生了能被看见

## 决定了什么

`evals/external-benchmarks/swe-bench/` 三个文件，两件事：

**① 防止发生** —— `exec-swebench.sh` 新增 `start_sleep_inhibitor` / `stop_sleep_inhibitor`，
在 `cmd_run` 起第一个容器之前拉起 `caffeinate -dims`（macOS）或
`systemd-inhibit --what=sleep:idle`（Linux），并用 `trap ... EXIT INT TERM` 收掉。
起不来不中止本轮，只打一条警告 —— 那种场合交给 ②。

**② 发生了能被看见** —— 新增 `awake_ms()` / `slept_ms_since()`，在 **agent 段**
（`t_setup_done` → `t_agent_done`）测宿主休眠毫秒数，经 `--host-slept-ms`
落进 record 的新字段 `host_slept_ms`；单题 >1s 即打断言，全轮结束再汇总一次。

三处口径是这次改动的实质，不是实现细节：

- **`null` ≠ `0`**。null = 没量到（旧 run / 取不到时钟），0 = 量到了确实没睡。
  缺省成 0 会把所有旧 run 伪装成"已验证没休眠"—— 正是这个缺陷第一次逃过验收的形态。
  ⚠️ 这与同文件三段耗时那条「0 表示没量」**语义相反**，因为 0 在这里是有效值。
- **只在 agent 段测**。setup/extract 是秒级搬运，睡在那里不影响任何结论；
  `agent_ms` 才是北极星「更快」的取数源。
- **`host_slept_ms` 不进 `setup+agent+extract===wall` 那条不变量**。
  它是 `agent_ms` 的成分说明，不是第四段；从 `agent_ms` 里减掉会破掉不变量，
  而墙钟耗时本身也是要看的数。

根因（smoke-10 实测）：`django-13964` 的 `agent_ms=2009007`（33.5min）超过
`SWE_TIMEOUT=1800` 而 `timed_out=false`，看起来像闸门坏了。逐层排掉后闸门是好的
（perl-alarm 兜底与隔着 `docker exec` 都实测 exit 124），真凶是 `pmset -g log` 里
**宿主中途睡了 717 秒**。`alarm()` 按可运行时间计、`now_ms()` 取墙钟，
于是同一段休眠**同时**污染耗时并给闸门续命（一题可跑到墙钟 2× 上限还不被杀）。

与记忆 `sleep-deduction-only-in-loop-fallback-false-kills` 同源反向：
那条是"休眠扣减只在一处做 → 误杀健康流"，这条是"休眠不扣减 → 漏杀超长题"。
**同一个「墙钟 vs 可运行时间」的分裂，两个方向各产生一个缺陷。**

## 放弃了什么（以及为什么不选）

**只做 ①（起守卫）不做 ②** —— 否决。跑在别人机器上、`caffeinate` 被系统忽略、
或 Linux 上没有 `systemd-inhibit` 时，问题会**静默复发**，而报告里的耗时数字
看起来完全正常。A7.11.5 已经点过这条，这里照办。

**只做 ②（记字段）不做 ①** —— 否决。它诚实但不解决闸门续命：
超长题仍然逃过超时，只是事后能看出来。

**从 `agent_ms` 里直接减掉休眠时长** —— 否决。会破掉
`setup + agent + extract === wall` 那条有单测守着的不变量，
而且"这一题墙钟花了多久"本身也是要看的数（用户等待是真的等了）。
正确形态是并列一个成分字段，让读的人自己决定看哪个。

**在 macOS 上用 `CLOCK_MONOTONIC` 当"不含休眠"的时钟**（照 Linux 写法）—— 否决，
这是本次最容易做错的一处：**两个平台语义正好相反**。
macOS：`CLOCK_MONOTONIC` **含**休眠 / `CLOCK_UPTIME_RAW` **不含**；
Linux：`CLOCK_BOOTTIME` **含** / `CLOCK_MONOTONIC` **不含**。
用错的后果是差值恒 0 —— 字段在、有值、值是废的，而报告显示"宿主未休眠 ✅"
（记忆 `metric-exists-but-value-is-junk` 那一类）。已用单测锁住 darwin 分支
不许出现裸 `CLOCK_MONOTONIC`。

**把休眠当"每题起一个守卫"** —— 否决。题间空隙同样会触发空闲睡眠，
而守卫本身没有成本，放在整轮外层更简单也更严。

## 拿什么证明它生效了

**计算逻辑（5 条受控注入，含变异自证）**：

```
① 无休眠（墙钟/可运行同步 +5000）        → 0          ✅
② 睡 717s（墙钟 +722000, 可运行 +5000）  → 717000     ✅
③ 时钟抖动（可运行比墙钟多 3ms）          → 0（clamp）  ✅
④ 没量到（awake 空串）                    → ''（非 0）  ✅
⑤ 变异：误用含休眠的时钟当 awake          → 恒 0        ← 失败形态确实存在
```

**`awake_ms` 取到的是不含休眠的时钟**（本机实测）：
`awake_ms=1337588048` vs `CLOCK_MONOTONIC=3107061927` —— 差 1769473s
就是这台机器累计睡过的时间。若两者相等，说明用错了时钟。

**record 落盘 4 个语义分支**（真跑 `bun run record.ts`，读回 JSON）：

```
--host-slept-ms 717000  → 717000   （agent_ms=2009007 不变）
--host-slept-ms ""      → None     （没量到，不是 0）
不传该参数（旧 run）    → None
--host-slept-ms 0       → 0        （量到了没睡，不是 null）
```

**汇总段 4 个分支**（独立 python 逻辑，单独验）：

```
[717000, 0, 0]     → tot=717000 worst=717000   ← 单题不被 10 题平摊稀释
[null, null]       → "- -"  → 走"可信度未知"分支
[0, 0]             → tot=0 worst=0 → "口径干净"
[null, 5000]       → tot=5000（null 不参与，也不当 0）
```

**守卫起停实测**：`start_sleep_inhibitor` 起到 `caffeinate` pid=57854（`ps` 确认存活），
`stop_sleep_inhibitor` 后进程消失。核过唯一残留的 `caffeinate -i -t 300` 是**别人的进程**
（ppid=12860、自带 300s 过期），不是我们泄漏的。

**单测 3 条变异自证**（`tests/eval/swe-bench-runner.test.ts`，各让 1 条失败、还原后全绿）：

```
变异① macOS 用错时钟（UPTIME_RAW→MONOTONIC）  → 137 pass / 1 fail  ✅ 被拦
变异② 去掉 trap 收守卫                        → 137 pass / 1 fail  ✅ 被拦
变异③ record.ts 改成 `?? 0` 缺省              → 137 pass / 1 fail  ✅ 被拦
还原                                          → 138 pass / 0 fail
```

**门禁**：`bun run affected-tests:run` **1113 pass / 0 fail**；
`bun run lint` 与 `bun run format:check` 通过；`make build` 通过且自检 4 项全过、
无 `will always be undefined`。

⚠️ **中途被既有门禁拦下一次，是真违规不是误报**：`shell-fullwidth-var.test.ts` 红了 ——
我写的 `info "…pid=$SLEEP_INHIBITOR_PID）"` 里全角右括号会被 bash 吃进变量名，
`set -u` 下直接退出。改成 `${SLEEP_INHIBITOR_PID}` 后绿。
**这是本仓第五次踩同一个坑**（前四次记在 ZZ.2d），门禁工作正常。

⚠️ **一个诚实的边界：没有做真实休眠的端到端验证。** 触发真实休眠要把这台机器睡下去、
会中断会话。上面验的是「计算逻辑 + 落盘链路 + 时钟选择」三段，
真实休眠下的数字要等下一轮评测（若发生）才能实证。
**已知的实证只有一条**：本机累计休眠 1769473s 能被这套时钟差正确读出。
