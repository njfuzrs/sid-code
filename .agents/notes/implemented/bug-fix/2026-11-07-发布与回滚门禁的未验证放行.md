# 「判据没能跑」一律不算通过：promote 的两处未验证放行改为拒绝，平台清单收敛为单一事实源

对应缺陷：`docs-research/sid-code/bugfixes/todo/20260927-工程化与交付-顺着sc-x3核出的缺陷.md`
的 X3-03（P1）与 X3-04（P0），合成一个 PR（同一关注点：`--promote` / `rollback.sh`
这条「把稳定通道指过去」的判据链）。

⚠️ 落地期间 main 上合入了 #655（X3-05 / X3-06 同族修复），它已经把 X3-03(b)
（`isAncestorOfMain === null` → 拒）一并做掉，并给 `judgePromote` 补了 origin / dirty /
无身份按版本边界三条判据。**本 PR 不与它重复**，覆盖的是 X3-03 的剩余部分与 X3-04：

- X3-03(a)：tag 缺失只 warn（#655 未动）；
- `unverified` 标记 + `--promote-unverified` 显式逃生口 + Release 正文留痕 ——
  #655 把「没量到」判成拒，但没有区分「判据没跑」与「判据判负」，也就无法给离线发版机
  留任何出口；本 PR 把这两者分开，并让放行成为命令行上可见的声明；
- X3-04：平台清单收敛（#655 未动）。

## 决定了什么

**X3-03：`--promote` 的两处「没量到」从放行改为拒绝。**

1. `scripts/release.sh` 的 tag 判据：本地没有 tag 时从 `warn`（随后照常写 `latest.txt`）
   改为 `fail`（`latest.txt` 不动），提示 `git fetch origin main --tags` 后重跑。
2. `scripts/lib/artifact-identity.ts` 的 `judgePromote`：**#655 已把**
   `isAncestorOfMain === null` 从 `ok: true` 判成 `ok: false`；本 PR 在其上补
   `unverified: true` —— 没有这个字段时，「判据没跑」与「判据判负」在返回值上不可区分，
   调用方只能靠匹配 reason 文本区分（改一句文案就静默失效），也就无法给离线发版机留出口。
3. `ReleaseGateResult` 新增 `unverified?: boolean`；CLI `promote-gate` 在这一种拒绝时
   额外输出一行 `__PROMOTE_UNVERIFIED__`。`release.sh` 只在**显式** `--promote-unverified`
   时对该标记放行，`isAncestorOfMain === false`（分支包）这类**判负**永不放行。
4. 新增 `--promote-unverified`（只能与 `--promote` 同用，单独出现直接报错）。
   放行时：促升段开头、两处放行点各打一条 warn；并经 `github-release.ts --unverified`
   在 GitHub Release 正文末尾追加一行留痕 —— 放弃校验需要有仓库之外的记录。

**X3-04：平台清单与「版本目录完整性检查」收敛为单一事实源。**

1. 新增 `scripts/lib/targets.sh`：`TARGETS`（5 个，含 `linux-x64-baseline`）、
   `release_platforms()`、`release_dir_check_cmd <dir> <ver>`（输出
   `__NO_DIR__` / `__MISSING__` / `__COMPLETE__` 三种哨兵）。
2. `scripts/release.sh` 与 `scripts/rollback.sh` 都 `source` 它，删掉各自的清单与
   检查命令副本；`rollback.sh` 日志里的平台数从 `${#TARGETS[@]}` 派生。
3. 不改 `release.sh` 的 ripgrep 上传清单（`rg-<platform>` 是另一套产物集合，
   方案文档明确排除）。

## 放弃了什么（以及为什么不选）

- **不选「保持放行 + 把日志写得更醒目」。** 那是原状：自我描述诚实（「这一条没能校验」），
  行为却是按通过处理 —— 写 `latest.txt` 之后一切照旧。日志里的图标不改变行为。
- **不选「一律硬拒、不提供逃生口」。** `release.sh` 的注释明确把「离线发版机 / fork 里没有
  origin」当作必须支持的场景；硬拒会逼人直接改脚本或手工 scp 指针，那比显式 flag 更糟。
  选择「显式 flag + 日志与 Release 正文留痕」：放弃必须是一次命令行上可见的声明，
  而不是由环境副作用（有没有 tty、能否 fetch）决定的隐性放行。
- **不选「用环境变量/自动探测降级」。** 那正是被修的形态本身：放行与否不可见。
- **不选「只在 release.sh 日志里留痕，不动 Release 正文」。** 终端日志会滚掉、不进仓库；
  Release 正文是仓库之外的公开记录，事后复盘「当时这条校验是被主动放弃的」只能靠它。
  代价是 `renderReleaseBody` 多了一个可选参数（契约变更），已同步 `renderReleaseBody`
  的测试（默认不出现、显式传才出现）。
- **X3-04 不选「只把 rollback.sh 的数字从 4 改成 5」。** 那样下一次平台增减还会漂，
  而漂移的那天不会红。选共享文件，让「两边各写一份」在结构上不可能。
- **不选「把 ripgrep 的 4 平台清单也并进 targets.sh」。** ripgrep 是独立产物集合
  （`rg-<platform>`），不是 sid-code 的发布目标；并进来会让两件事重新耦合。
- **X3-06（`judgePromote` 比 `judgeReleaseUpload` 松：无身份放行 / 不查 origin / 不查 dirty）
  本 PR 不做。** 它要合并的是身份判据的语义（含「首个带身份的发布版本」边界），
  与 X3-03 的「未验证 ≠ 通过」是两件事，单独 PR 更易 review 与回滚。

## 拿什么证明它生效了

- 合并 main（含 #655）后的相关测试集：`bun test ./tests/eval/artifact-identity.test.ts
  ./tests/release-channel.test.ts ./tests/release-flow-contract.test.ts
  ./tests/release-archive.test.ts ./tests/release-remote-sha.test.ts` →
  **218 pass / 0 fail**（合并前主体四个文件是 198 pass / 0 fail）。
- 全量（**合并 main 之前**跑；合并后的全量以 CI 分片为准）：
  `affected-tests` 判定为 **full**（`scripts/release.sh` 属仓库级文件）→
  `bun run affected-tests:run` 跑出 **19931 pass / 10 skip / 5 fail**，5 条 fail 全部归因：
  - **2 条是本次改动的契约变更，已同步测试**（`tests/release-archive.test.ts`
    的 `ARCHIVE_PLATFORMS` 与 promote 段 `echo __NO_DIR__` 两处锚点；
    改为锚 `release_platforms` 与 `release_dir_check_cmd` 后该文件 **27 pass / 0 fail**）。
    这两条属于「实现有意改了、测试前提随之更新」，不是为凑绿。
  - **3 条是 worktree 路径导致的环境性假失败**，三条证据齐全：
    ① 不 import 本次改动的任何模块（`tests/build/rules-paths-scope-nonempty.test.ts`
    只读 `@sid-code/core/config/rules.ts` 与 `git ls-files`；
    `packages/core/tests/agent/isolated-subagent-cwd.test.ts` 只测子代理 prompt 构造）；
    ② 在**父仓 main** 上单跑 → **15 pass / 0 fail**；
    ③ 成因：`ruleOwnerDir`（`packages/core/src/config/rules.ts:411`）按「路径里最后
    一个 `.claude` / `.sid-code` 段」判定规则归属目录，而 worktree 路径是
    `<主仓>/.sid-code/worktrees/<name>/...` —— `.sid-code` 段被误认成规则容器，归属目录
    被算成主仓根，`ownerAbs.slice(REPO.length + 1)` 切出空候选集 → `hit=null`。
    另一条同理：进程 cwd 在 worktree 内时 prompt 注入【隔离环境提示】，
    而用例断言的是「未绑定 cwd 时不出现」。CI 在正常 checkout 路径（不含 `.sid-code`）
    上跑，不会命中这两类环境差异。
- **变异自证三次（均先红后恢复）**：
  - `release_dir_check_cmd` 在 tmpdir 真跑：5 平台齐全 → `__COMPLETE__`；
    只删 baseline 的 tarball → `__MISSING__` 且**点名**
    `sid-code-<ver>-linux-x64-baseline.tar.gz`；目录不存在 → `__NO_DIR__`；
    平台清单本身从 `lib/targets.sh` 读（测试不抄一份）。
  - tag 判据从 `release.sh` 抠出**真实分支**，在空 git 仓库（无 origin、无 tag）真跑：
    默认 → 非 0 退出且输出含「tag 判据无法验证」「拒绝促升」；
    `--promote-unverified` → 0 且输出含「未验证即放行」。
- **变异自证三次（均先红后恢复）**：
  1. 从 `scripts/lib/targets.sh` 删掉 `linux-x64-baseline` → X3-04 两条用例红
     （断言基线红 + 构造 baseline 产物时 `ENOENT` 红）。

     与「两种拒绝可区分」两条红（`Expected: false, Received: true`）。
  3. `release.sh` 的 tag 缺失分支改成 `if true`（永远走 warn 放行）→
     「无 tag → 非 0 退出」红（`Expected: not 0, Received: 0`）。
