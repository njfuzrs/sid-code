# compact 降级阈值按工具类型分档：shell 类取 1 行，其余保持 5 行

## 决定了什么

修 PR #808（`b00616e9`）合入后暴露的一处不统一：**输出越少的 bash 反而越占屏**。

初版把「正文 ≤5 行就降级为原样展示」统一套在所有工具上。对 `read` / `grep` / `glob` 成立
（卡片只有 header + 正文，不折叠只多占那几行），对 `bash` 不成立：bash 不折叠时除正文，
还要多出一整块命令行区（`$ 命令` + 命令超 160 字符时的「… N 字符已折叠」提示）。
实测同一轮里正文 4 行 / 3 行 / 1 行的 bash 全部降级、各占 4~6 行，而正文 86 行的 bash
折成 1 行。用户观感：有些不折有些不折，完全随机。

三条改动（`packages/cli/src/ui/`）：

1. **降级阈值分档**（`history-adapter.ts`）：新增 `COMPACT_MAX_INLINE_LINES_SHELL = 1`，
   `buildCompletedToolCall` 里用 `isShellTool(toolName)` 二选一。shell 类只在正文 ≤1 行时
   不折叠（`git status` 干净、`grep` 无匹配这类一句话结论），2 行起一律折叠。
   非 shell 工具行为完全不变。
2. **`isShellTool` 下沉到 `ui-utils.ts`**（纯 TS）。它原本定义在 `components/messages/ToolShared.tsx`，
   而数据层 `history-adapter.ts` 不能 import React 组件。不复制一份判据是刻意的：
   `danger-detect.ts` 与 `permission-choices.ts` 就各写了一份 `/bash|shell|exec|command/i`，
   靠两边注释约定「口径保持一致」——同一判据存在两处，改一处忘另一处不会报错。
   这次不给 compact 降级再加第三份。`ToolShared.tsx` 保留 `export { isShellTool }`（re-export），
   既有 4 个引用点零改动。
3. **行数口径收口**（`ui-utils.ts` 的 `countEffectiveLines`）：`getResultSummary` 的
   「N 行输出」原先用朴素 `content.split("\n").length`，尾部换行会**多算一行**——
   实测把 86 行的 `ls` 输出报成「87 行输出」。现在与降级判据共用同一个 trim 后计数函数，
   同一张卡片上「标题说的行数」与「为什么折叠」不再各说各话。`read` 的「N 行」同改。

## 放弃了什么（以及为什么不选）

- **不把降级判据改成「按视觉行（wrap 后）」**。这是治本的方案：数据层数逻辑行、渲染层
  `SlicingMaxSizedBox` 按视觉行截断，两套口径会让同一张卡片同时出现「没折叠」与
  「… 3 行已折叠」（实测到的 131 字符长行 + 逻辑 4 行那条）。但数据层拿不到 `terminalWidth`，
  要按视觉行判就得把降级搬到渲染层，而 PR #808 特意把 `displayMode` 的语义锁成
  「带 compact 的卡片 = 默认折叠有收益」、渲染层不重复判行数。为一个观感问题推翻这条
  契约，代价大于收益。留作后续：真要做，应连同 `displayMode` 的语义一起重新设计。
- **不按「卡片总高度」判**。命令行区的提示行数取决于命令长度与终端宽度，都是渲染期信息，
  数据层同样拿不到。用正文行数近似是当前信息量下唯一可行的口径。
- **不动折叠态的命令行区**（用户明确否决的方案）。曾考虑把它从「命令 + 折叠提示」两行压成
  一行：能再省 1 行，但去掉「… N 字符已折叠 · ctrl+o 展开」就丢了展开线索，
  与 L3.3「折叠时必须给可展开提示」冲突。
- **不给 bash 单独再加一个「执行中占位」这类补救**。PR #808 已否决过同一思路，理由不变。

## 拿什么证明它生效了

- **用户实测轨迹对账**（改前）：从 `~/.sid-code/sessions/.../2026111*.jsonl` 里取出截图那
  11 条 bash，逐条比对 `resultDisplayMode` 与 `content` 有效行数——11 条档位**全是**
  `compact`，不折叠的 3 条行数为 4 / 3 / 1（全部 ≤5），折叠的 8 条为 6 ~ 86 行，
  判据与现象完全对应，证明问题不在档位判定而在降级阈值。
- **新增 4 条审计断言**（`packages/cli/tests/ui/tool-result-display-mode-audit.test.ts`）：
  bash 2/3/4/5 行 → `compact`；bash 1 行 → `undefined`；grep 5 行 → `undefined` 而
  同样内容的 bash → `compact`（反向锁阈值分流没误伤非 shell）；5 行带尾部换行的 grep
  仍 `undefined`（锁 trim 口径）。
- `bun test ./packages/cli/tests/ui/tool-result-display-mode-audit.test.ts ./packages/cli/tests/ui/ui-utils.test.ts`
  → 54 pass / 0 fail。
- `bun run affected-tests:run` + `make build` 结果见 PR 正文。
