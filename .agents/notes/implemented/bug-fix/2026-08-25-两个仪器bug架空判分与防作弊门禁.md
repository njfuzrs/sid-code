# 两个仪器 bug：一个让正确 patch 被拒收，一个让「禁改测试文件」门禁恒为 false

## 决定了什么

修两个**上一轮的修复自己引入 / 一直没被发现**的仪器 bug，都在 SWE-bench 阶段 A
的 patch 提取链路上，形态相同：**harness 侧的工具链故障伪装成被测对象的能力问题**
（ZZ.5 第 4 条那条判据在同一批代码上第三、第四次兑现）。

### bug ①：`normalizePatch` 的 `trimEnd()` 剥掉了合法的上下文行

`runner.ts` 的 `normalizePatch` 原写 `diff.trimEnd()` 再补一个 `\n`。
`trimEnd()` 剥的是**全部尾部空白**，于是把 diff 末尾那些**内容只有一个空格的行**
一起吃掉了 —— 而在 unified diff 里 `" "` 开头的行是**合法上下文行**，
仅含单空格的行就是「上下文里的空行」。

吃掉它 → hunk body 比 `@@ -a,b +c,d @@` 声明的行数**少** → patch 自相矛盾 →
`git apply` 报 `corrupt patch`（exit=128）。

改为只塌陷末尾的**换行符本身**（`/\n+$/`），不动任何其他字符。
不变量是「**除末尾换行之外逐字不变**」，不是「末尾清干净」。
空/纯空白 diff 仍归零（否则 `patchBytes` 0→1，`deriveOutcome` 把 no_patch
误判成 patch_produced）。

### bug ②：bash 命令替换吃掉 NUL，`patch_touches_tests` 因此恒为 false

提取那步是 `extract_out="$(docker exec ...)"`，而 **bash 命令替换丢弃 NUL 字节**
（POSIX 行为；bash 打的 warning 被 `2>&1` 一起吞了）。于是
`git diff --numstat -z` 的多条记录落盘时**首尾相接、没有分隔符**：

    5<TAB>0<TAB>src/foo.py3<TAB>1<TAB>tests/test_foo.py2<TAB>0<TAB>src/bar.py

旧 `parseNumstatZ` 按 NUL 切 → 只得 **1 条**，path 是把后面全部记录粘成的怪串 →
`isTestPath` 匹配不上 → **`patch_touches_tests` 恒为 false**，
D17 第 2 条那道「软约束必须配硬检查」的防作弊检查被静默架空。

两处都改：容器侧 `tr '\0' '\036'`（RS 活得过命令替换，且不可能出现在 git 路径里）；
TS 侧改为不依赖分隔符——按记录头形态 `<数字或->TAB<数字或->TAB` 切，
三种输入都收（NUL / RS / 粘连的旧数据）。

### 顺带三项（都由上面两条派生）

- 新增 `patch_only_adds_files` 观测字段（`newFilePaths` / `patchOnlyAddsFiles`）：
  标出「只新建文件、一行既有源码没改」= agent 卡在复现阶段。**只标注，不改判定**。
- `link_ok` 口径写进类型注释与**报告正文**：它是「单次跑完」不是「重试后」。
- `evals/scripts/run-external-baseline.ts` 两条轨的 `pass: 0` 改为**直接抛**，
  落点从仓库根 `_reports/` 改到 `evals/_reports/external/`。

## 放弃了什么（以及为什么不选）

**① 否决「只在末尾补一个换行」（即上一轮那个修法）。**
它是 ZZZ.3 记录的修复，但**实测没修好**：三格变异自证里它仍然 exit=128。
上一轮之所以判定"修好了"，是因为看的是 `resolved_ids` 而不是打补丁日志 ——
官方 harness 的打补丁是**四级回落**（`git apply` → `--3way` → `--reject` →
`patch --fuzz=5`），最后那级带模糊匹配，会把行数不对的 hunk 硬塞进去
（日志里 `Hunk #1 succeeded at 242 with fuzz 2`）。
实测 smoke-2 那 6 条 solved **全部**是这么进去的 —— 它们不是"恰好没踩到"，
是**踩到了但被最后一级兜住**。所以文档里「那 6 条的 patch 恰好都有尾换行」这句是错的
（实测 10 条**没有一条**以换行结尾）。
**判据教训：「解出来了」推不出「patch 是好的」，要看 `git apply` 那一级。**

**② 否决「numstat 改成不带 `-z`」来绕开 NUL 问题。**
不带 `-z` 时含空格/中文的路径会被 quote 成 `"a\tb"`，按 TAB 切就切错 ——
`-z` 本来就是为此而用的。用一个新错换掉旧错。

**③ 否决「提取时把 agent 自建的调试脚本滤掉」**（ZZZ.5 第 3 条的另一个候选）。
滤掉后那两条会变成干净的 `no_patch`，而 `no_patch` 读起来像「没想出办法」——
与「想了、试了、**卡在复现阶段**」是两件不同的事。提取时替 agent 打扫会掩盖
它的行为特征，那是在伪造一个更好看的过程。所以改成加一个**观测字段**。

**④ 否决「改 prompt-v1 加一句『不要留调试文件』」（至少现在不改）。**
`prompt-v1` 是入库写死不再改的契约（D17 第 3 条），改它意味着起 `prompt-v2`，
**之前所有跑分结果不可与新结果并排比较** —— 成本是「重跑一轮基线」而不是「改一句话」。
先用 `patch_only_adds_files` 量出这个形态多常见，再决定值不值得付那个代价。

**⑤ 否决「`pass: 0` 加一行 warning」（原实现就是这样）。**
`pass: 0` / `pass_rate: 0` 都是**合法取值**，落盘后渲染与下游 gap 计算全都照跑，
而 warning 只在终端 —— 只看 md/json 的人看不到。于是「链路没接」被读成「能力差」，
与被否决的路径 A 那个 `Score(value=0)` 同型。
**产不出真数字时唯一正确的行为是拒绝产出。**

**⑥ 否决「为了让 link_ok 变绿而合并复跑结果」。**
那会让「跑三次才成一次」的链路显示 PASS，而链路不稳恰恰是阶段 A 要发现的东西。
复跑结论写进正文，不改字段。

## 拿什么证明它生效了

**bug ① —— 容器内三格变异自证**（同一份 astropy-12907 patch、同一个官方镜像）：

| 版本 | `git apply` |
| --- | --- |
| `trimEnd()`（原实现） | exit=128 `corrupt patch at line 12` |
| `trimEnd()` + 补 `\n`（上一轮的"修复"） | exit=128 `corrupt patch at line 13` |
| 只规范换行、保留末尾上下文行（现在） | **exit=0** `Applied patch ... cleanly` |

**全量复算**：拿 smoke-2 的 8 份非空 `extract.raw` 用修好的代码重新派生，
逐条送进**各自的官方镜像**跑 `git apply` —— **8/8 exit=0**。
修复前同样 4 条抽样全部 exit=128。差异只有那一处代码。

同时用脚本核对了 hunk 自洽性：修复前 `astropy-12907` / `pytest-7982` /
`pytest-10081` 三条的 hunk body 比 header 声明**少 1 行**（`header wants old=7 new=7;
body has old=6 new=6`），修复后不再出现。

**bug ② —— 门禁真的从「不触发」变成「触发」**：

```
同一份输入   NUL 完好 → 判 patch_touches_tests = true
             NUL 丢失 → 判 patch_touches_tests = false   ← 门禁被架空
```

端到端（真容器、真 `tr`、真命令替换）：故意改一个源文件 + 建一个
`tests_probe/test_probe.py`，落盘后 `NUL=0 / RS=2`（分隔符活下来了），
`parseNumstatZ` 解析出 **2 条**，`patch_touches_tests = true`。

**实测代价已确认**：smoke-2 报告里 `patch_touches_tests: 0` 是个**假阴性** ——
`matplotlib-20488` 的 patch 里确实有 `repro_test.py`（`isTestPath` 判 true）。
用修好的代码重跑该条数据，`files` 从 1 变 6（django-15128）、
`tests` 从 0 变 1（matplotlib-20488）。

**两条修复都做了变异自证**（把实现改回旧写法，确认新断言转红）：

- bug ①：还原 `trimEnd()` → **3 fail**（含「不变量：除尾部换行外逐字相同」），改回 → 95 pass
- bug ②：还原按 NUL 切 → **3 fail**（含「NUL 被 shell 吃掉后仍能切对」），改回 → 95 pass

**`patch_only_adds_files` 在真数据上验过判别力**：smoke-2 十条里**恰好**命中
`django-15128`（6 个 repro 文件）与 `matplotlib-20488`（repro_test.py）两条 ——
就是人工读 diff 找出来的那两条，其余 8 条为 false。

**`run-external-baseline.ts` 两条轨**：`--validate` 仍 exit 0 三项前置全 ✅；
实跑 exec / report 轨都 **exit=1** 且**没有产出任何占位报告文件**。

**门禁**：`bun test ./tests/eval/swe-bench-runner.test.ts` **95 pass / 0 fail**（245 expect）；
`bun run affected-tests:run` **995 pass / 0 fail**（45 文件）；
`make build` 通过含产物自检 4 项；`bun run lint` 与 `bun run format:check` 全绿。

**未完成项（诚实标注）**：用修好的代码跑满 10 题的那份干净报告
（`smoke-7`）在写这份 Note 时**仍在跑**，约 3 小时。
在它出来之前，**不要**把 smoke-2 的 `solved: 6` 当作基线 ——
那 6 条全部依赖 `patch --fuzz=5` 兜底，且 `patch_touches_tests: 0` 已证明是假阴性。
