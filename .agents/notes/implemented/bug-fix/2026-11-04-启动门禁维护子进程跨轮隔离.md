# 启动门禁每轮开头等干净三个目录的维护子进程，并补每轮原始值与子进程时间线

## 决定了什么

`packages/cli/tests/startup/large-data-startup-gate.test.ts` 两处改动：

1. **隔离**：每轮测量开始前，先等 `emptyHome` / `largeHome` / `uploadHome` 三个目录的维护子进程
   彻底退出（轮 0 之前不等——那时三个目录都还没起过子进程，等是白等）。
   原来只在轮末等 `uploadHome`，大数据目录首轮拉起的那批（扫 300 个会话、读 200MB 巨型会话、
   扫 1500 个轨迹目录 × 20 文件）无人等，`detached + unref` 会一路压到下一轮的 e1/l1。
2. **观测**：每轮的 e/l/u 首帧与 `max_loop_block` 原始值、以及大数据目录维护子进程的
   `startedAt` / `finishedAt` / 各任务 `durationMs` / 当时 `maintenance.lock` 在不在，
   一并打进 `[gate]` 日志；断言失败消息也从「只给中位数」换成「给整组单次值」。

配套给 `waitMaintenanceIdle` 加了 15s 宽限期：大数据目录只有第一轮会跑维护任务（跑完写水位线，
之后 24h 内不再到期），死等结果文件会出现 90s 超时。锁一旦出现过就说明子进程确实在跑，
仍然一路等到结果落盘。

## 放弃了什么（以及为什么不选）

- **不放宽 150ms 阈值、不给 macOS 跳过**。变异自证数据：C1 +698ms、T1/T2 +353ms（本次复测
  +405.1ms / +280ms），放宽到 300ms 就抓不住 T1/T2 这一档退化了。macOS 跳过则等于这道门禁
  在最需要它保护的平台上不存在。
- **不改 `RUNS`**。加轮数线性拉长一条已经 45s 的测试，而且治不了跨轮干扰——它对「子进程占用
  第一轮之外的时间」不敏感，只对「哪一轮被污染」做平均。
- **不做文档里的 T3（热身也碰大数据目录）**。它会把第 1 轮维护任务的到期状态提前消耗掉，
  「维护任务确实在子进程里跑了」那条用例的前提就不成立了，要连带改断言。而候选 B（l0 冷读）
  本来只是次假设，没有数据支持它之前不值得付出这个代价。
- **不把观测做成断言**（如「子进程时段不得与测量轮重叠」）。文档明确定位 T1 是纯观测；
  在慢 runner 上偶尔重叠是可能的，加断言会把一个诊断通道变成新的 flake 来源。

## 拿什么证明它生效了

- **本机基线**：`bun test ./packages/cli/tests/startup/large-data-startup-gate.test.ts`
  → 7 pass / 0 fail（47.66s）。日志新增输出形如
  `[gate]   轮0 [+0..+10816] 空 520/158 大 470/109 传 442/101 | 大目录子进程 起=闲 止=闲`
  与 `[gate]   大目录维护子进程时段 [+4197..+5633] 共 1436ms：session-cleanup=89ms trace-prune=771ms housekeeping=575ms`。
- **变异自证（不吞真实退化）**：把 T1/T2 扫描用 `require("./startup-prune.ts")` 临时放回
  `TraceCollector` 构造函数（即回到首帧前的主线程），门禁两条断言同时变红：
  - 首帧差值 `Received: 405.1`（阈值 150）
  - `max_loop_block 空=[110 / 85 / 114] 大=[385 / 496 / 390]（中位数差 280ms）`（阈值 100）
  恢复后重新跑回 7 pass。
- **隔离有效性：本机验不出，这是一个必须记住的负面结果**。在 `maintenance/runner.ts` 的
  housekeeping 里插 12s CPU 忙等（`Bun.sleep` 不占 CPU，第一版用它是无效变异），
  跑「有隔离」与「注释掉等待」两组，**两组都是 7 pass**。原因：本机是 M 系列多核，
  单个子进程还被 `os.setPriority(pid, 10)` 降了优先级，压不住被测进程；macos-latest 是
  3 vCPU，CPU 争抢才可能显现。所以这条修复的最终效力只能由 macOS CI 的连续绿来判定，
  日志里「起=跑/闲」两列就是判定依据。
- **有隔离时等待确实发生**：同一组变异下，轮 1 的墙钟窗口从正常的 ~11s 拉长到
  `[+11097..+32165]`（21s），`起=跑` 说明轮 1 开始时子进程还在跑、被等完了才开始测——
  这是隔离真的生效（而非空转）的直接证据。
