# /perf 趋势会话数文案对齐 settled() 口径，生成耗时注释改为「响应头之后」起算

## 决定了什么

修掉 Performance 页文档核查登记的两项观测口径缺陷（B1、B2），**只改文案和注释，不改任何过滤与计算逻辑**：

1. **B1（趋势会话数文案）**：`perf-report.ts` 的 `settled()` 只排除 `exit_status === "incomplete"`，但趋势视图写的是「不含未正常结束的会话」，会被读成中断、报错会话都已剔除。改为「不含还在跑或崩溃未收尾的会话；中断、报错收尾的仍计入」。同文件「本期没有已结束的会话」「没有带版本号的已结束会话」两处同源措辞改为「已收尾」。`settled()` 补注释，说明为什么刻意不排除 user_interrupt / abort / error / max_turns / budget_exceeded。
   - 核查时补正了缺陷文档的一处取值错误：SIGINT/SIGTERM 映射到 `abort`（`app.ts` 的 `sessionEndReasonForSignal`），不是 `user_interrupt`。所以计入趋势的还包括 `abort`，官网 `website/use/performance.md` 的口径说明同步补上 Ctrl-C、外部 kill 和预算上限。
2. **B2（生成耗时口径注释）**：`stream_completed.elapsedMs` 的起点是 `createStreamLifecycle()` 被调用的时刻，在 fetch 返回、响应头到达之后（`stream-lifecycle.ts` 的 `startedAt`），不含握手和 TTFB。原注释写「从连接到流结束 / 不含握手」，自相矛盾。缺陷文档只登记了 `collector.ts` 一处，实际有 5 处同样的错误表述，全部改掉：`collector.ts` 两处、`builder.ts` 一处、`digest.ts` 两处。
   - `collector.ts` 原注释还断言重试时「分子分母口径一致」。这一点没有核实（`total_tokens_received` 有 AfterModelRaw 累加和 SessionEnd 时 SessionState 覆盖两条写入路径），改为如实标「尚未核实」，不再写成结论。

## 放弃了什么（以及为什么不选）

- **不选「收紧 settled() 为白名单，只留 end_turn / terminal_closed」**：所有趋势指标的分母都会变，历史对比全部失效；也和 `query/turn-complete.ts`「异常轮次也必须发」的契约相悖。慢样本往往正是被打断的那些，筛掉会让 p95 系统性偏低。所以该改的是文案，不是过滤。
- **不选「把 lifecycle 起点前移到 fetch 之前，让注释里的『从连接』成真」**：分母会静默变大，tok/s 曲线整体平移、前后不可比。TTFB 已经有独立口径（`headers_received` 的 `ttfb_ms`），没有理由塞进生成耗时。
- **不在本 PR 定性「重试时分子是否含丢弃流的 token」**：要走读 SessionState 的累加路径并用真实轨迹验证，超出「注释校准」的范围。注释里留了待核标记，避免下一个人把它当已证结论引用。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/trace/perf-report.test.ts`：18 pass / 0 fail，新增 2 条用例。
- 变异自证：把 `settled()` 改成 `end_turn || terminal_closed` 白名单后，新用例「已收尾的中断/报错/撞顶会话仍进趋势」变红（1 fail）；把文案改回「不含未正常结束的会话」后，用例「会话数括注与 settled() 口径一致」变红（1 fail）。两处都已恢复。
- `grep -rn "从连接到流结束" packages/` 无命中。
- 过滤逻辑没动，所以同一份 `session-index.jsonl` 改前改后的趋势数字不变，只有括注文字不同。
