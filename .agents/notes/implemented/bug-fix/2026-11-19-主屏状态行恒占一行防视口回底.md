# 主屏 Composer 状态行恒占 1 行，消除回合末帧收缩导致的整帧重画

## 决定了什么

**主屏下 `Composer` 状态行恒占 1 行——有内容显示内容，无内容留 1 行空白；全屏（alt-buffer）布局不变。**

`packages/cli/src/ui/components/Composer.tsx:288-296`：

```tsx
const heldRowsPolicy = useHeldRowsPolicy();
const statusRowMinHeight = useHeldRows(
  heldRowsPolicy.enabled ? 1 : statusRowHasContent ? 1 : 0,
  !isIdle,
  { releaseWhenIdle: true },
);
```

`heldRowsPolicy.enabled` 只在主屏为 true（`MainScreenLayout.tsx:71` 传 `{enabled: true, ...}`）；
全屏布局传 `FULLSCREEN_HELD_ROWS = {enabled: false}`（`DefaultAppLayout.tsx:46`），高度固定、
不会整帧重画，多占一行只浪费空间。

**根因（已实测确认）**：回合结束那一帧同时发生三件事——`streamingText` 清空并把 assistant 消息
提交进 `historyItems`（`epoch` 变化）、`streamingState` 变 Idle（`busy` 变 false，`releaseWhenIdle`
成立）、spinner 消失（`rows` 1→0）。`useHeldRows` 的两条释放条件同时成立，水位 1→0，
状态行不再占位，帧从 85 缩到 84 行。此时帧已溢出视口（`p=85 ≥ H=30`），命中
`main-screen.ts:116` 的「溢出后收缩一律 full reset」→ `2J 3J` → scrollback 清空、视口回底。

关键在于：**那一帧的「历史新增」是从动态区搬进 Static 的同一份正文，帧高并未增长**
（`MainScreenLayout.tsx:136` 的 `StreamingMessage` → `Static` 的 `HistoryItemDisplay`）。
所以 `useHeldRows.ts:11` 那条「历史新增一项 ⟹ 帧同样在变高」的假设在这条路径上不成立，
水位释放没有任何补偿。

- `packages/cli/tests/render-port/main-screen-shrink-e2e.test.ts`：`resets["第二轮"]` 由
  `toBeLessThanOrEqual(1)` 改为 `toBe(0)`；`blanks` 由 1 改为 2；第二轮 submit 判据由
  `完成。` 放宽为 `完成`（帧 diff 可能在两次流式块之间插入状态行更新，去 CSI 后两字不再连续）。
- `packages/cli/tests/ui/components/__snapshots__/layout-bottom-region-snapshot.test.tsx.snap`：
  `main：瞬态块齐全` +1 行；`fullscreen` 版本不变。

## 放弃了什么（以及为什么不选）

- **只修 `epoch` 或只修 `idle` 其中一条**：2×2 变异实验（`SID_DEBUG_HELD_OFF=epoch,idle`）
  实测两条互为兜底——只关 `epoch` 仍有 1 次 full reset（`idle` 顶上），只关 `idle` 仍有 1 次
  （`epoch` 顶上），两条都关才是 0。任何单条修复都不生效。
- **只去掉 `releaseWhenIdle`**：回到 2026-11-05 之前的旧行为（空闲时状态行常驻占位），
  用户当时截图明确反对过。本次决策是用户 2026-11-19 重新拍板，接受空闲留 1 行空白，
  换取流式期间视口不被拉回底部。
- **空闲时渲染有意义的内容（权限模式 / 快捷键提示）**：用户明确不要额外常驻内容，
  选择「没内容就留白」。
- **帧层对「收缩 ≤ N 行」补空行撑住而非 full reset**：`main-screen.ts` 文件头已论证
  「补空行撑高度会把空白留在历史尾与动态区之间，之后的流式正文贴着输入框从下往上长」
  （#390/#402/#556），改动面大且引入新的视觉债，本次不动帧层。
- **帧层感知「用户已上翻」后跳过 full reset**：主屏下鼠标事件是关的
  （`App.tsx` 的 `mouseEventsEnabled={props.alternateBuffer === true}`），拿不到滚轮事件，
  只能靠 PgUp/PgDn 推断，覆盖不到「用终端原生滚动条拖上去」这一主要操作路径。
- **修 `epoch` 语义（把「流式正文搬家」排除出历史增高）**：方案 A 落地后行高恒 1，
  `epoch` 变化不再造成收缩，已非必要条件。保留为前端语义改进（§4 方案 B），本次不做。
