# 交互模式项目级扩展改为首次加载须确认（B20 / D63 闭环）

## 决定了什么

此前 `cli.ts` 的 `onUntrusted` 在交互模式下直接返回全部文件、打一条「已自动信任」，随后
`extension/loader.ts` 调 `trustBatch` 持久化 —— 打开任何目录都会静默信任它带的 skill /
命令 / agent（本机 `trusted-extensions.json` 曾累计 102 个目录，含临时目录与家目录）。
官网三处却写「交互模式会弹确认」。

- 新增 `packages/core/src/extension/trust-prompt.ts` 的 `createTrustPrompt`：
  启动阶段（TUI 起来之前）走 stdin `y/N` 确认，列出相对路径与类型；**只返回确认过的那批**，
  loader 只持久化返回值，所以拒绝天然不落盘、下次启动再问；内容 hash 变了也再问（`TrustManager` 已按 hash 存）。
- fail-closed：无 TTY、Bridge 模式、`runTUI` 之前调 `closePrompting()` 之后（stdin 归 Ink，热重载新出现的文件）
  一律不加载、只记日志。空回车 / EOF 视为拒绝（复用 `promptYesNo`）。
- 同一进程内拒绝过的（路径 + hash）不重复问：commands / skills / agents 与 reload 会多次扫描。
- `-p` 维持跳过；用户级 `trust_project_extensions: true` 维持逃生口（项目层写不进去这条不变）。
- 官网 `extend/index.md`、`extend/skills.md` 共三处改为「首次加载要确认」，并写明拒绝 / 无终端的行为。

## 放弃了什么（以及为什么不选）

- **在 TUI 里做 Ink 确认组件**：扩展扫描发生在 `runTUI` 之前，那时 Ink 还没起来；把扫描挪到 TUI 之后
  会改变 skill 摘要进首轮 system prompt 的时序，影响面远大于这次修复。stdin 确认与 Bridge 准入同一做法。
- **热重载时也弹确认**：stdin 已归 Ink，再起 readline 会抢输入。改为不加载 + 日志，下次启动再问 ——
  宁可少加载一次，也不留一条「会话中途静默信任」的口子。
- **清掉已被自动信任的存量记录**：清掉会让每个旧项目首开都弹一次；存量照旧生效，只对新文件 / 改过的文件生效。
  需要彻底重来的用户可以自己删 `~/.sid-code/state/trusted-extensions.json`。
- **逐文件确认**：一个仓库常带几个到十几个文件，逐个问会被一路回车拒绝或一路 y，没有增加判断质量；按批（每种扩展类型一批）确认。

## 拿什么证明它生效了

- `packages/core/tests/extension/trust-prompt.test.ts` 8 条，走真实 `ExtensionLoader` + `TrustManager`（落盘重定向 tmpdir），
  断言加载结果与信任文件内容：拒绝不持久化且下次再问 / 确认持久化且下次不问 / 内容改了再问 / `-p` 跳过 /
  无 TTY fail-closed / `closePrompting` 后不问 / 同进程不重复问 / 存量不受影响。
- 变异自证：把 `onUntrusted` 改回「直接返回全部文件」，8 条中 5 条转红。
- 真实会话（`make build` 产物，`expect` 驱动真实 TTY）：临时仓库放 1 个 skill + 1 个命令，启动后两次弹出
  「当前项目带有 1 个未信任的项目级扩展…继续吗？[y/N]」；回车拒绝后信任文件里该目录 0 条；
  答 `y` 后写入 1 个目录 2 个文件；再次启动不再询问。验证完已删除探针目录及其信任记录。
