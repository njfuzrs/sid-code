# 无头三形态放行 `/btw`（T8），并把它的两个失败分支从 text 改成 error

## 决定了什么

方案《20261106-无头模式斜杠命令放行》的 T8——67 个内置命令里最后一个待评估项。落地三件事：

1. **`/btw` 声明 `headless: true`（三形态全放行）**，而不是像 T6 那样用 `modes` 收窄。
   判据（全部回源码核实，`btw.ts`）：
   - 依赖面 `ctxMgr` / `provider` / `toolRegistry` / `config` **全部已在无头 cmdCtx 注入**
     （`headless-command-context.ts`），没有 `?.()` 静默跳过后仍报成功的字段；
   - 结果类型只有 `text`，没有 `dialog` / `confirm` / `clear` / `quit`；
   - 三形态都有价值：`-p` 无 `-c` 时 `ctxMgr.getMessages()` 为空 → **不调 LLM**，只回
     「当前还没有对话上下文」；`-p -c` 时 resume 已把历史灌进 ctxMgr（`app.ts`
     `deserializeMessagesWithInterruptDetection`），旁路提问有真实历史；stream-json / Bridge
     多轮同理。与 `/compact` 的净亏场景不同：btw 不产生「付了钱但结果没落盘」的浪费，
     它是用户主动换一条答案，且失败时不产出噪音历史。
   - 额外一次 LLM 调用已在 T8 评估中确认可接受（§五.5）；无上下文时连这次调用都不发生。

2. **两个失败分支改 `errorText()`**（`btw.ts`）：forked agent 没产出文本、以及 forked
   agent 抛错，原先都返回 `{ type: "text", value: "…失败…" }`，无头下 `mapExecutionResult`
   把它翻成 `output` → **退出码 0**——CI 拿到假成功（D2 的同型残留，T2 只收口了
   `errorText` 的调用方，btw 是手写的）。现在走 `error` 分支 → 无头退非 0。
   无参用法提示、无上下文的诚实提示**保持 `text`**（不是执行失败，是给用户的用法/前提说明）。

3. **门禁把 `/btw` 纳入 A 档清单**（`headless-allowed-commands.test.ts` 的 `A_TIER_PROBES`）：
   `headless: true` 的清单断言变成「A 档 22 + /btw + B 档 6 + /init」，同时新增
   「放行生效」「不产出交互请求、不碰注入表外字段」两组用例。探针用**无参**：空问题分支
   直接返回用法、不碰任何 ctx、不调 LLM，门禁不产生副作用。

## 放弃了什么（以及为什么不选）

- **按 T6 用 `modes: ["stream-json", "bridge"]` 只放长驻形态**：否决。T6 的判据是「`-p`
  单轮下净亏或哑操作」，`/compact` 的压缩结果不落盘、`/loop` 的定时任务进程退出即丢，
  两者都成立。btw 在 `-p` 下不成立：无 `-c` 时**根本不调 LLM**（零成本，只给提示）；
  有 `-c` 时基于恢复的历史回答，答案本身有信息量，不存在「付钱买垃圾」。按形态收窄会把
  一个真实有用的场景（CI 里 `-p "/btw …" -c` 插问）一并拒掉。

- **无参调用也改 `errorText()`**：否决。理由是两条：① 无参是「用法提示」，与
  `/memory` 的缺参 error 语义不同——btw 的 `requiresArgs` 只是补全行为，用户看到用法
  本身就是目的；② 门禁的放行探针必须用无参（有参会调真实模型），若它返回 `error`，
  `resolveHeadlessSlash` 的「不再拒绝」断言无法区分「命令自己失败」与「分发层拒绝」。
  无头下 `/btw` 无参退 0 打印用法，与 TUI 行为一致。

- **顺手把 `btw` 的 `headless` 声明成结构体只放 `subcommands`**：否决。btw 没有子命令，
  args 就是问题文本；结构体的子命令维度对它不成立，形态维度又没有必要收窄（见上）。

- **给失败路径补一条「provider 抛错」单测**：做了又删。实测 `streamWithResilience` 会
  先重试（maxRetries: 2 + 退避），单条用例耗时 13.8s 且最终仍可能落成「空流」走空答案
  分支，稳定性和耗时都不划算；空答案用例已覆盖 `errorText` 的结果类型，catch 分支的
  行为由同一处 `errorText` 保证。
