# 后台回程的全文指针指向不会被删除的持久副本（X3）

## 决定了什么

`completeAgentTask` 在结论超过 `NOTIFICATION_OUTPUT_MAX_CHARS` 时，另存一份全文到会话目录
`trajectories/sessions/<会话>/tool-outputs/`（复用 `persistLargeOutput`，与同步回程
`buildSyncSubagentSummary` 同一个落点、同一套命名规则、同一个阈值口径），并把路径记进
`LocalAgentTaskState.resultFile`。完成通知与 `task_output` 里「完整内容见 …」的指针改指这份
持久副本，不再指向 `task.outputFile`（`.output`）。

落盘失败（磁盘满 / 权限）时任务状态记 `resultPersistFailed: true`，截断正文追加
`[全文落盘失败，以上不是完整内容]`，**不退回**指向 `.output` —— 那是一个必定失效的路径，
比一句诚实的「没留下来」更糟（父代理会再撞一次墓碑 / ENOENT）。

三处出口（同步回程 / 后台通知 / `task_output`）共用一份实现 `truncateResultForDelivery`
（`packages/core/src/task/notification.ts`），口径与失败文案只有一处。

改到的文件：

- `packages/core/src/task/agent-task.ts`：`createAgentTask` 记 `parentSessionId`（`completeAgentTask`
  是模块级函数，拿不到 `SubAgentTool.parentSessionId`）；`completeAgentTask` 落持久副本并写入状态与通知。
- `packages/core/src/task/types.ts`：`LocalAgentTaskState` 加 `parentSessionId` / `resultFile` / `resultPersistFailed`。
- `packages/core/src/task/notification.ts`：`TaskNotification` 加 `resultFile` / `resultPersistFailed`；
  新增 `truncateResultForDelivery`（超长 → 持久副本指针 / 落盘失败标记 / 旧指针三态）。
- `packages/core/src/tool/task-output.ts`：终态 `<result>` 的截断提示走同一个函数。
- `packages/core/src/agent/tool.ts`：`runAsync` 传 `parentSessionId`；`buildSyncSubagentSummary`
  改调 `truncateResultForDelivery`（原来它自己拼串，是同一口径的第二份实现）。

## 放弃了什么（以及为什么不选）

- **不改 `.output` 的按回合驱逐**。S3 的修法是对的：`.output` 是流式工作文件，随回合回收是它的
  设计目的，问题只在「把它当成完整结论的落点」。改驱逐窗口只会把死链推迟，不会消除。
- **不把 `<output-file>` 标签也改指持久副本**。该标签的语义是「任务输出文件」（shell / monitor
  也用它，那里的内容是流式日志、不适用持久副本）。改动它会让三种任务类型的同一标签含义分叉，
  而模型取全文靠的是 `<result>` 的截断提示，不是这个标签。所以本 PR 只改「完整内容见 …」这一句。
- **不在所有路径都落副本**：前台子代理（`notify=false`）的结果走 tool_result 出口，
  `buildSyncSubagentSummary` 已在同一落点落过一份；`completeAgentTask` 再落一次就是同一结论写两遍磁盘。
  代价是前台任务经 `task_output` 重读超长结论时指针仍指向 `.output`（结果本就在它的窗口里，
  读它属于显式重读），这是本 PR 已知残留，归 PR11 统一收尾。
- **不动 `<error>` 分支**（失败残卷的「完整内容见 …」仍指向 `.output`）。失败残卷的持久化属于
  PR11 的 salvage 补强范围，混进来会让这个 PR 的验收边界变模糊。
- **不新建一个「会话结果目录」**。复用 `trajectories/sessions/<id>/tool-outputs/` 意味着清理策略、
  目录权限、命名规则全部沿用现成的那套，少一处需要单独验证的落盘路径。
- **`send-message` / `swarm` 的 `createAgentTask` 调用暂不传 `parentSessionId`**：它们落盘到
  `unknown/` 子目录，副本照样可读，只是不按会话分目录。补齐需要各自改调用点的签名，
  与本缺陷的病灶（后台子代理完成通知）无关。

## 拿什么证明它生效了

1. **新增 G1 回归** `packages/core/tests/task/background-result-pointer.test.ts`，5 例：
   - 通知指针位于 `trajectories/sessions/<会话>/tool-outputs/`，且不是 `.output`；
   - 不超长的结论不落副本、不给指针；
   - `markNotificationsDelivered` + 跑完两个回合 + `evictTerminalTasks` 后，`.output` 确实被删、
     持久副本仍在且内容与原始结论**逐字一致**；
   - 落盘失败（`sessions` 占位成普通文件 → ENOTDIR）时正文带「全文落盘失败」且不给出指针；
   - `task_output` 的 `<result>` 截断提示给出同一个 `resultFile`。
   - 结果：`bun test ./packages/core/tests/task/background-result-pointer.test.ts` → 5 pass / 0 fail。

   同一文件 **4 例变红**（唯一仍绿的是「不超长不落副本」，与预期一致）；恢复后 5 例全绿。
