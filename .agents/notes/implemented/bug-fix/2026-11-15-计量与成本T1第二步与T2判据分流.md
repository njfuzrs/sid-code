# prompt 计量全部归一化，并把「金额不一致」按 token 是否对得上拆成价差/漏记两类

## 决定了什么

T1 第二步 + T2 + T4 三件事在同一个 PR 落地（同一关注点：量出来的数要能互相对得上）。

**T1 第二步：三个 prompt 字段统一到归一化口径。**

- `packages/core/src/trace/collector.ts`：`total_tokens_sent`（stock）与
  `total_cumulative_prompt_tokens`（flow）都改 `normalizeCacheUsage().promptTotal`。
  此前写的是 provider 原始 `input_tokens`：Anthropic 是未命中余量、OpenAI 族是全量，
  同一真实用量在两种 provider 下必然不等。`prompt_total` 保留独立字段（存量看板在读，
  老轨迹也靠它区分「归一化之前写的」）。
- `packages/core/src/trace/builder.ts`：metadata 统计为 0 时从 pairs 重算的 fallback
  同样归一化。不补这里，同一会话会因「有没有 metadata」得到两种口径。
- `packages/core/src/trace/cost-recompute.ts`：`RecomputedCost` 新增 `lastPromptTotal`
  / `cumulativePromptTokens`，补落轨迹用它们写 `tokens_sent` / `prompt_total` /
  `total_cumulative_prompt_tokens`。老字段 `lastInputTokens` / `cumulativeInputTokens`
  保留（其他调用方还在用），语义标为 provider 原始口径。

**T2：`billing_amount_mismatch` 按 token 是否逐项对得上拆成两类。**

- `checkBillingAmountConsistency` 增加 `tokenMatched`：用 `normalizeCacheUsage`
  汇总事件侧 prompt / output，与账本 `promptTotal` / `output` 逐项比。
- token 对得上、只有金额不同 → 新增 `billing_price_mismatch`，**low**（两边单价不同，
  账本自己是对的）；token 也对不上 → 保持 `billing_amount_mismatch`，**high**（真漏记/双记）。
- 老账本没有 token 字段时 `tokenMatched` 恒 `false`，保持原 high 判据 ——
  宁可报 high，也不因为「拿不到证据」就静默降级。

**T4：补「已知价差」样本。** 双记/漏记两个样本已存在（`digest-billing-amount.test.ts`
与 `digest-harness-actions-not-faults.test.ts`），本 PR 新增 5 条 T2 分流用例，
其中第一条就是价差样本。

## 放弃了什么（以及为什么不选）

- **不把 `prompt_total` 直接替换掉旧字段**：旧字段已流进看板与外部查询，改名/删除会让
  读侧静默取到 undefined。保留两个字段、注释写清「同口径、来源不同」的成本更低。
- **不让 `tokenMatched` 在「账本没 token 字段」时也降级为 low**：那等于用「没有证据」
  换「没有告警」。老账本的价差与漏记无法区分，保持 high 是唯一不丢信号的选择。
- **不在 T2 里同时改「事件侧该不该含子代理」**：`checkBillingAmountConsistency` 现在
  汇总全部 BilledRequest，而账本 `cost_scope` 可能是 `main`（不含子代理）。这是既有
  行为，动它会让原有 13 条断言的口径一起漂移。本次只加 token 分流，范围外的问题单独开。
- **不给 `billing_price_mismatch` 注册 `ANOMALY_CRITERION`**：该表只登记「成对推入的
  L0/L1」，单条推入由 `?? a.kind` 兜底；登记了反而会让 criterion 与 kind 混成一个概念。

```
         ./packages/core/tests/trace/cost-recompute.test.ts \

```

**变异自证**（改坏被测代码 → 确认断言变红 → 还原）：

- 把 `total_cumulative_prompt_tokens += promptTotalThisTurn` 改回 `+= inputTokens`
  → `prompt-total-normalized` 的「三个 prompt 字段同一归一化口径」红。
- 把 `tokenMatched` 前置 `false &&` → T2 的 5 条用例全红。
- 把 `BILLING_AMOUNT_TOLERANCE` 改成 `1.0` → 双记 3 条红。
- 合计 **9 fail**，证明新断言不是恒绿。还原后 `grep -rn MUTATION packages/` 只剩
  三处历史遗留注释（与本 PR 无关）。

**真实数据侧证**（只读本机轨迹，不进仓库）：`~/.sid-code/usage-ledger.jsonl` 里
账本行的 `promptTotal` 与 `cacheHit`+`cacheWrite`+`uncachedInput` 恒等，
说明 token 分流比的两边确实同源，不是拿两个不同口径在比。
