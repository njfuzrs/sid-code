# 主屏历史项「无法重渲」的前提是错的：改掉规范源头，清掉 5 处派生注释

## 决定了什么

`packages/cli/src/ui/CLAUDE.md` 的 L3.3 原文是「**Static 安全铁律**：工具结果一完成即被 `<Static>` 一次性打印进终端 scrollback，**此后无法重渲**」。这个前提**不成立**：

- 端口的 `Static`（`render-port/components.ts` 转出的 `History`，实现见 `packages/tui/src/components/History.tsx`）是 memo Box，项是普通子树、内容变了照常 reconcile，**不是**上游 ink 的 print-once `<Static>`。
- 同一份 CLAUDE.md 的 **L5.3 表格**早就写着「已完成区（memo Box，**项可原地重渲**）」——**规范内部自相矛盾**，L3.3 与 L5.3 两条并存了很久。
- 实证：`App.tsx` 把 `thinkCollapsed` 按 `expandLevel` 同步、`MainScreenLayout` 再传给 `HistoryItemDisplay` → ctrl+o 确实会展开主屏历史里的思考块。若「无法重渲」，这个行为根本不可能存在。

改动分两块：

1. **规范源头** `src/ui/CLAUDE.md` L3.3 → 改成「**Static 折叠必须同步一次成型**（项可重渲，但重渲代价是整帧重画）」。约束本身（折叠同步成型、不许用异步测高的 `MaxSizedBox`）**保留不变**，只把错误的理由换正确的。
2. **5 处派生注释**（都基于旧前提写了错的「为什么」）：
   - `App.tsx` — ctrl+o 的作用域说明
   - `MainScreenLayout.tsx` ×4 — 头注释的「print-and-forget」、`thinkCollapsed` 的「Static 模式始终 false」、历史区行内注释、流式思考区那段**错位**的理由（流式区是动态区，压根不在 Static 里）
   - `HistoryItemDisplay.tsx` / `ThinkingMessage.tsx` — `thinkExpandable` / `showExpandHint` 的「主屏无法重渲 → 传 false 避免误导」
   - `CodeColorizer.tsx` / `DiffRenderer.tsx` — 「污染回滚区且擦不掉」

**行为零变化**。`thinkExpandable={false}` / `showExpandHint={false}` 保留现状，只把理由改成真实的（L4-C：历史区一屏几十条思考，逐条挂提示是唠叨），并写明「要让提示可见应接 `shouldShowHint` 衰减，而不是直接传 true」。

## 放弃了什么（以及为什么不选）

1. **只改下游注释、不动 CLAUDE.md L3.3** —— 不选。这 5 处是**同源**的，源头在 L3.3；只清下游等于留着一个会继续生产同样错误注释的模板（本次正是它批量生产出来的）。
2. **顺手把 `thinkExpandable` 改成 true，让提示真的显示** —— 不选。历史区一屏可能几十条思考，逐条挂「ctrl+o 展开」违反 L4-C 的衰减要求。真要让提示可见，正确做法是接 `shouldShowHint(key, N)` 衰减，那是独立的行为改动、需要自己的整帧验证与产品判断，不该塞进一次注释修正里。
3. **只删「无法重渲」、保留「污染回滚区且擦不掉」** —— 不选。后半句同样建立在「项不能重渲」上：既然能重渲，第二帧折叠后的内容会覆盖第一帧。真正的问题是**一次没必要的整帧重画**（`2J 3J` + 重写全部历史，长会话几百 KB，并把用户上翻的位置拉回底部），不是「擦不掉」。理由不写准，下一个人会照旧误解。
4. **改 `MainScreenLayout` 的 `thinkCollapsed` 传参** —— 不选。它本来就正确（跟随 `expandLevel`），错的只是注释描述。
