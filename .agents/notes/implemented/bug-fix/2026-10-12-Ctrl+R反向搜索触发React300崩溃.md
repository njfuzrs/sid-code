# Ctrl+R 反向搜索的提前 return 挪到所有 hook 之后，修复 React #300 崩溃

## 决定了什么

`packages/cli/src/ui/InputArea.tsx` 里反向搜索模式的 `if (reverseSearch.state.active) return ...`
原本写在队列提示、Shell 提示两组 `useRef`/`useEffect` 之前。按下 Ctrl+R 后那一帧少调 6 个 hook
（4 useRef + 2 useEffect），React 抛 #300（Rendered fewer hooks than expected），整个 TUI 崩溃退出。

改法：把这段提前 return 原样挪到最后一个 hook 之后、`if (isEmpty)` 之前，渲染内容不变。
并加了注释：新 hook 一律写在这行之上。

新增 `packages/cli/tests/ui/input-area-hooks-order.test.ts`：静态扫描 InputArea 组件体，
断言第一个顶层提前 return 之后不再出现任何 `useXxx(` 调用；另有一条检测器自证用例。

## 放弃了什么（以及为什么不选）

- **把反向搜索 UI 拆成独立子组件、父组件条件渲染**：结构上更干净，但改动面更大，
  而且 hook 写在提前 return 之后这个风险在 InputArea 其它模式分支上照样存在。
  挪位置加静态守卫是能修根因的最小改动。
- **真渲染 InputArea 按 Ctrl+R 的 e2e 测试**：要搭 Keypress / Keybinding / UIState / Settings
  四个 Provider，harness 的成本远高于要守的这条不变量。静态扫描能覆盖到所有分支，
  代价是依赖源码缩进形态（oxfmt 固定了缩进，形态是稳定的）。
- **启用 eslint-plugin-react-hooks 的 rules-of-hooks**：仓库用 oxlint，只开了 correctness 档，
  另起一套规则集不在这次范围内。

  识别出提前 return 之后有 `useRef( ×4, useEffect( ×2`；对修复后的文件结果为 `[]`。
- `bun test ./packages/cli/tests/ui/input-area-hooks-order.test.ts`：2 pass / 0 fail。
- `bun run affected-tests:run`：2273 pass / 0 fail（212 个文件）。
- `bun run lint` 0 warnings / 0 errors，`bun run format:check` 通过，`make build` 自检通过，
  且没有 `will always be undefined` 告警（worktree 已单独 `bun install`，不再链到主仓 node_modules）。
