# 权限页核查的 3 项代码缺陷：沙箱观测改为真实归因、持久化文案与来源计数对齐代码

## 决定了什么

修掉 `docs-research` 缺陷文档（2026-10-16 权限页核查）登记的三项，**并按实测结论改写了 B1 的修复方案**：

1. **B1（沙箱违规观测）**：删除 `SandboxViolation` / `violations` / `getViolations()` / `recordViolation()`（全仓零调用的假 API），新增 `SandboxManager.noteCommandFailure(command, stderr)`——沙箱启用、命令失败、stderr 出现 `Operation not permitted` / `Permission denied` 时打一条 `[SANDBOX]` 归因日志，前台路径在 `bash.ts` 的失败分支接线。
   - 缺陷文档原方案 A 要求「解析 stderr 中 sandbox-exec 的 denial 行（形如 `deny(...)`）」。**该前提经本机实测为假**（见下一节），所以没有照做。
   - 措辞刻意是「可能是沙箱拦截，也可能是文件权限/只读文件系统」：这条日志只能提示相关性，不声称规则级归属。
2. **B2（持久化文案漂移）**：UI 选项「持久化到项目配置 / 写入 project settings」改为「持久化到本地配置 / 写入 settings.local.json（不入 git）」，与实际写入 `persistRule("local", ...)` 一致。同时修掉 4 处同源漂移：`permission-choices.ts` 模块注释、`app.ts` 的 `persistBashAllowRule` JSDoc 与行内注释、`DialogManager.tsx` 注释、`website/start/first-task.md` 的选项表；测试断言同步改（`HotkeyChoiceList.test.tsx` 3 处）。
3. **B3（来源计数注释）**：`types.ts` 的「规则来源（8 种）」改为 9 种并点明 commandScoped 是唯一负优先级档；`rule-loader.ts` 的「从 8 种来源加载」同步改为 9 种（原注释第 3 行写 8、第 4 行列 9，同段自相矛盾）。

## 放弃了什么（以及为什么不选）

- **不选「解析 stderr 里的 denial 行」（文档原方案 A）**：本机（Darwin 27）实测，`sandbox-exec` 用 `(deny file-read* (subpath ~/.ssh))` 拒绝 `ls ~/.ssh` 时，stderr 只有 `ls: ...: Operation not permitted`；profile 里加 `(debug deny)` 也一样。denial 明细只出现在内核统一日志：`kernel[0] (Sandbox) Sandbox: ls(6299) deny(1) file-read-metadata /Users/x/.ssh`。所以「解析 stderr 拿规则/路径」在这个平台上没有数据来源。
- **不选「常驻 `log stream` 采集统一日志」**：技术上可行，但要起常驻子进程、按 pid 树归因、处理日志格式随系统版本变化，而沙箱默认关闭（`enableSandbox` 默认 false），成本与收益不匹配。留在未来需要时再做，本 PR 不做。
- **不选「纯删除、不补任何观测」**：删掉假 API 只解决了「代码骗人」，用户仍然拿不到任何沙箱相关线索。补一条启发式日志成本低、且措辞诚实，能回答「这条失败是否可能与沙箱有关」。
- **不删「持久化」这一档 UI**：功能真实存在（写 local settings 并热更新 checker），错的只是文案与注释，删档会拿走用户能力。

## 拿什么证明它生效了

- **平台行为实测（B1 方案改写的依据）**：
  - `sandbox-exec -f profile /bin/sh -c 'ls ~/.ssh/'` → stderr：`ls: ~/.ssh/: Operation not permitted`；
  - 加 `(debug deny)` 后重跑，stderr 不变；
  - `/usr/bin/log show --last 20s --predicate 'eventMessage CONTAINS "deny"'` → `kernel[0] (Sandbox) Sandbox: ls(6299) deny(1) file-read-metadata ~/.ssh`。
- **单测**：`bun test ./packages/core/tests/permission/p2-wiring-and-sandbox.test.ts ./packages/cli/tests/ui/components/HotkeyChoiceList.test.tsx` → 35 pass / 0 fail。新增 2 条 `noteCommandFailure` 用例，按 `isEnabled()` 真实取值分流（macOS 验证 true、其它平台验证 false，不用平台 if 包住断言）。
- **回归与构建**：`bun run affected-tests:run`、`make build`、`bun run lint` / `format:check` / `lint:boundary` / `lint:command-system` / `typecheck:gate` 结果见 PR 正文。
- **残留检查**：`grep -rn "持久化到项目配置\|violations 列表尚未接线" packages website` 零命中（改后）。
- **未覆盖的边界（明确说明，不假装覆盖）**：后台命令（`executeWithTaskSystem` → `spawnShellTask`）的 stderr 直接写 task 输出文件，不经过 bash 工具的字符串通道，因此归因日志只覆盖前台路径；`sandbox.ts` 的 `noteCommandFailure` 注释里写了这一点。
