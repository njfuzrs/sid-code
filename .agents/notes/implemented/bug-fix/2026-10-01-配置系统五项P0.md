# 配置系统：修掉 D1 / D3 / D6 / D8 / D10 五项 P0

## 决定了什么

修掉 `20260927-配置系统-顺着sc-13-settings-config核出的缺陷.md` 的全部 P0。P1/P2（D2 主体除外、D4/D5/D7/D9/D11/D12）留给后续。

- **D1 被 git 追踪的 `settings.local.json` 按不可信处理**：新增 `security.ts` 的
  `isGitTrackedFile` / `isUntrustedSettingsFile`，settings 加载链、`rule-loader` 的注入告警 +
  自我授权剥离、`trust.ts` 的危险配置扫描与信任 hash 三处共用这一个判据。
  判据是 `git ls-files --error-unmatch`（剥掉 `GIT_*` 环境变量，防 hook 里指到别的仓库）；
  git 不可用但向上找得到 `.git` 时 fail-closed 按追踪处理。追踪时额外产出一条诊断，提示 `git rm --cached`。
- **D3 未信任工作区不跑 Phase 2 全量 env**：`trust.ts` 新增 `setWorkspaceUntrusted / isWorkspaceUntrusted`，
  cli.ts 信任门控判未信任时置位；`applyAllConfigEnvironmentVariables` 在函数内部读它直接返回。
  信任扫描也纳入被追踪的 local 文件（D3「连带」一节）。cli.ts 那段过时注释改掉。
- **D6 企业策略路径统一成一条候选链**：`paths.ts` 新增 `managedSettingsSystemDir()`（平台目录）与
  `resolveManagedPolicyFile()`；`managedPolicyCandidates` 首位改为平台系统路径（此前硬编码 `/etc`）。
  settings 链 `policySettings`、`ManagedFileLoader`、`rule-loader`、identity 读取四个消费方都走它。
- **D8 app.json 冷启动 + 截断不丢数据**：写入改 tmp + rename 原子写；读到损坏文件（含空文件、`null`、
  非对象）时先留损坏副本、再从最近一份**能解析的**时间戳备份恢复，没有才回默认值；
  时间戳备份只备份能解析的内容；截断成「恰好合法的 JSON」（如 `{}`）且比最近备份少了
  onboarding / projects 时按损坏处理。`saveAppConfig` 冷进程路径同样走恢复。
- **D10 字段类型错只丢那个值**：`parseSettingsFile` 在 Zod 失败时用 `removeInvalidValues` 按 issue 路径
  摘掉出错值后重试（缺必填字段时向上退一级摘整个元素），最多 10 轮；只有根本身不是对象才整份判失败。
  为让这条错误有出口：L2 缓存改存带 errors 的 `ParsedSettings`、L3 命中返回 errors 副本（D2 中与本条
  直接相关的部分），并在 `loadConfig` 末尾把链 B 的 errors 挂进 `_validationDiagnostics.warnings`
  （TUI 启动横幅与 `--print` stderr 都能看到）。
- 博客 `sc-13-settings-config.md` §5.2 那段「gitignored 所以只可能是你写的」与 Phase 2 时序图改为实现后的事实。

## 放弃了什么（以及为什么不选）

- **D1 把 `localSettings` 一律纳入过滤**：会伤正当用法（本机 `settings.local.json` 放 `permissionMode`
  是常见做法，`rule-persistence.ts` 也往里写会话规则）。判据应是「会不会跟着仓库来」，不是文件名。
- **D1 只告警不改信任模型**：静默变可见仍依赖用户看提示，而这条攻击链的特点就是受害者无可见信号。
- **D3 把 Phase 2 挪到 TrustDialog 确认之后热应用**：hooks / MCP 都不热加载，信任语义是「下次启动」；
  env 单独热应用会让同一会话里三类配置口径不一，且 env 在 LLM 客户端构造后改动也不一定生效。
- **D6 把 `~/.sid-code/managed-settings.json` 从候选链删掉**：会静默打断既有只放在用户目录的部署。
  保留为回退，但系统级一旦存在即优先——不可篡改性在管理员真正部署时成立。
- **D8 引入跨进程文件锁**：原子写已消除「读到半截文件」这一根因，锁的复杂度（陈旧锁、NFS）不值。
- **D10 给每个字段写 `.catch()`**：schema 字段几十个，逐个包会与 schema 形状耦合，新增字段又会漏；
  按 issue 路径摘值对任意字段通用。
