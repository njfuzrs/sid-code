# ↑/↓ 输入历史从 history.jsonl 按当前项目灌入，关掉会话后仍能翻到

## 决定了什么

根因不在写盘：`~/.sid-code/history.jsonl` 一直在追加（本机实测 926 行，带 project/sessionId）。
问题在读取侧断了线——`useInputHistoryStore` 读出的持久化历史只喂给了 Ctrl+R 反向搜索，
而 ↑/↓ 走的是 `useTextBuffer` 内部的 `state.history`，它恒从 `[]` 起步，只装本会话 reset 时推进去的条目。

改动：

- `text-buffer.ts`：`useTextBuffer` 新增 `initialHistory`，挂载时经 `createInitialState(text, history)` 初始化（hook 与测试共用一个入口）；`reset` 改为去重置顶，与持久化侧「最新在前、去重」口径一致。
- `useInputHistoryStore.ts`：新增 `projectHistory`（`readHistoryDisplays({ project: getProjectRoot() })`），project 取不到时退化为全局。
- `InputArea.tsx`：把 `projectHistory` 传给 `useTextBuffer`。

结果：↑/↓ 按目录隔离（对齐 CC），Ctrl+R 仍是跨项目全局搜索。

## 放弃了什么（以及为什么不选）

- **↑/↓ 也用全局历史**：在 A 项目按 ↑ 翻出 B 项目的输入，与 CC 行为不一致，也是用户明确提到的「区分目录」。
- **让 TextBuffer 订阅 store 的 history 实时同步**：本会话新提交已由 reducer 的 `reset` 推入，再同步一次会双写/抖动；挂载时读一次就够。
- **改 history-index 写入格式**：写盘本来就对，动它没有收益。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/hooks/input-history-arrow-persist.test.tsx`：reducer 带初始历史时 ↑/↓ 能翻、reset 去重、hook 按 project 过滤（SID_CONFIG_DIR 重定向到 tmpdir）。3 pass。
- `bun run affected-tests:run`：2192 pass / 0 fail；`make build` exit 0 且无 `will always be undefined`；`bun run lint` / `format:check` 通过。
