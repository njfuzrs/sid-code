# 补上 PR #899 漏掉的三处：`wait_ids`、必做的真实轨迹回放、P2 的成对注释

## 决定了什么

PR #899（`9a9c10c6`）把 P1–P5 的五层识别都落了地，但 2026-11-17 的二次核验发现
方案里还有三条要求没兑现，外加一处死代码。本 PR 只补这四处，不改任何判据：

1. **`WaitPollEscalated` 两档事件补 `wait_ids`**（`status-poll-guard.ts`）。
   方案 §7.2/§4.10 第 3 条要求带 `level` / `count` / `wait_ids`，实现只有前两个 +
   `subject` / `kind`。后果是离线对账只能按 P1 的对象签名聚合，看不到「升级那一刻
   有几个等待源在盯」。而同一批改动的 PR-A **是**带 `wait_ids` 的
   （`goal-gate.ts` 的 `GoalGateDecision reason:"waiting"`），两处口径不一致。
   `ctx.listWaits()` 在硬拦分支本来就调过（拼回执用），字段是白拿的。

2. **P5 第 5 次的提示改为「没送出去就不算送过」**（同一文件）。
   原实现里 `escalation.hinted = true` 在**决定走哪条分支之前**就置位了，
   而 `tool-executor.ts` 只消费 `!intercept` 时的 `hint`。所以第 5 次查询一旦落在
   P1 的拦截分支，提示被丢弃、`hinted` 又已烧掉 → **此后永远不再提示**。
   改成：达标时只**准备**文案，`hinted` 与 `level:1` 事件都留到 `pass()` 真正送达时再落。
   顺带解决事件重复落的问题（原设计若延后置位而不搬事件，第 5、6、7… 次每次
   重算 hint 都会重复落一条）。

3. **§7.2 的「真实轨迹回放用例（必做）」补上**（新增
   `tests/task/wait-poll-real-trajectory.test.ts` + `fixtures/goal-idle-poll-20261116.json`）。
   夹具是会话 `20261116-010710-b38e91d0` 里 `tool_name === "bash"` 的**末 140 条**
   命令与结果，脱敏只做「私有 checkout 路径 → `<repo>`、owner → `<owner>`」两件事。
   方案原本要求这条「必做」，PR #899 只交了 §7.4 的阈值校准（n=134），没交回放用例；
   仓库里既有的两个 `status-poll-replay-*.json` 是 **2026-11-12** 的旧会话（PR #780 / #661），
   与本方案无关。

4. **P2 第 3 条的成对注释 + 删一条死正则**（`status-query-commands.ts`）。
   方案要求在命令侧说明「放行 `date` 段」与「输出侧抹掉它产生的时间戳」是一对、
   改一边必须改另一边。实测该要求整体被跳过：方案点的 `:401` 已因 PR #899 自身改动
   漂移成 `gh_api_pulls` 的注释，命令侧 `isHarmlessSegment` 的 `date` 注释只写了
   「`-s` 是改系统时钟」。另外 `HM_CLOCK_LINE_RE` 是**永不命中**的死正则
   （`HM_CLOCK_RE` 带 `m` 且含 `^`，任何满足整行形态的行都会先被它改写成 `<clock>`），
   删掉并在 `HM_CLOCK_RE` 的注释里写明整行形态由 `^` 分支覆盖。

## 放弃了什么（以及为什么不选）

1. **放弃方案 §4.10 第 4 条字面要求的「拦截回执前加一句前缀」**，
   改成「延后到下次放行再送」。这是本 PR 唯一一处偏离方案文字的决定，理由是被既有
   契约否掉了：`P1-intervened-true` 这个 G2 用例（以及 `query/unchanged-observation.ts`
   的整条判据）靠「连续相同的工具返回值」计数。第 5 次回执一旦多出前缀，
   观察序列 `O,O,R,R,R` 就变成 `O,O,R,R,R'`，第 5 次的 `run` 停在 2，
   `UnchangedObservationRun.intervened` 永远不置 true。
   **实测证据**：加前缀 → `bun run smoke P1-intervened-true` 红（`期望 1 条，实际 0 条`）；
   仅把拦截分支的 `output` 恢复成恒定 `receipt`（其它不动）→ 立刻绿。
   两害相权：「提示晚一轮」远轻于「空转检测的核心埋点失效」。
   完整论证另见 `rejected/bug-fix/2026-11-17-拦截回执加P5前缀.md`。

2. **放弃「改 `P1-intervened-true` 的期望来容纳前缀」这条路**。
   它是既有用例、守护的是另一个已上线能力，为一个新加的提示去改它的语义，
   等于让旧契约给新功能让路；何况 `expect-reviewed` 只能由人加，agent 不得给自己加。

3. **放弃「用 `sc-dev` 真跑 §7.5 端到端」作为本 PR 的交付条件**。
   §7.5 要求「开 2–3 个只改文档的 PR + `/goal` 盯它们合并 + 取轨迹统计 6 条通过线」，
   需要真实 PR 与 15 分钟以上的模型会话。本 PR 用**真实轨迹回放**替代其中可离线判定的
   部分（识别率、实际执行次数、变化可见性），其余如实留给人工，理由见第三段。
