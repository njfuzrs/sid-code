# 子代理成本双记：改为由持有 usage-sink 的调用实例声明入账（S13 / PR-8）

## 决定了什么

- 子代理 fetch 原来走两条入账路：`usage-sink` 按 `SubAgentResult.usage` 记一次 `updateUsage`；provider 发出的 `BilledRequest`（`accounted=false`）又被 app.ts 的 billing observer 记一次。事故会话 `agent:builtin` 的 118 条全部双记，`/debug` 和账本因此高估约 10%。
- 新增 `UsageSinkTicket`（`llm/billing-sink.ts`）。只有**这次执行确实持有 sink** 的调用方（`agent/tool.ts` 前台和后台、`agent/custom.ts`、`tool/workflow.ts` 经 `SubAgentRunner.accountsUsage`）才开票据，然后由 `SubAgent.setUsageAccounting` 和 `buildBaseLoopConfig` 带到 `runAgentLoop`，主流和总结轮再透传给漏斗，最后写进 ALS 的 `RequestContext.usageAccounting`。
- `recordBilledRequest` 统一负责认领：带票据的 fetch 记成 `accounted=true, accountedBy="usage-sink"`，落盘写 `accounted_by`，观察者不再加钱。provider 里的三处 `accounted` 判据都没改，判据只保留一份。
- 执行结束时调用 `settle(sinkCharged)`。sink 真入了账就什么都不做；没入账（usage 全 0、sink 抛错、异常出口）就把认领过的 fetch 补交给观察者，按旧路径计费。finally 里兜底 `settle(false)`，调用是幂等的。结算后才到达的 fetch（detach 之后续跑）不再认领。
- digest 新增金额一致性核对 `checkBillingAmountConsistency`：比较 `|账本 costUSD − Σ BilledRequest@事件时刻价| / 总额`，超过 1% 记为 L0 high `billing_amount_mismatch`。B47 原有的恒等式只核条数，对双记看不出问题。
- traj/metadata 新增 `cost_scope`。运行中是 `main`，SessionEnd 用 `SessionState.totalCostUSD` 覆盖后改成 `main+subagent`，同名字段换口径时有据可查。

## 放弃了什么（以及为什么不选）

- **往 `BILLING_SELF_REPORTED_LABELS` 补 `agent:builtin/custom/summary`**：`agent:custom`、`agent:summary` 被内置、自定义、hook 三条链共用，而 hook 子代理执行器（app.ts `setAgentHookExecutor`）丢掉了 `result.usage`，不经 sink。按标签豁免会让 hook 子代理全部漏记。sink 也有不触发的时候，同样会漏。
- **只设一个静态 `accountedBy` 标志、不做结算补交**：usage 全 0 或异常出口时 sink 不触发，已声明入账的 fetch 就静默漏记。漏记比高估更难发现。
- **豁免 `agent:fork`**：fork 不走 usage-sink，豁免就等于漏记。这次不碰 fork。
- **删 `usage-sink.ts` 的成本入账、只保留 token**：会改动 `modelUsage` 的 stock 口径，影响面大。
- **digest 里注入用户 availableModels 精确计价**：digest 拿不到用户配置。改成「任一模型查不到内置价就不判」，宁可不判也不误报。代价是自配私有模型的会话没有这条核对。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/llm/billing-usage-sink-ticket.test.ts`：9 pass。正向：持票据的 `agent:builtin/summary` 零加钱。反向：不持票据的 hook 链 `agent:custom/summary` 和 `agent:fork` 照常计费。另覆盖 sink 未入账时补交且幂等、结算后的 fetch 不认领、主循环不受影响，并有门禁扫描三处 sink 调用方必须开票据、两条透传链路不能断、hook 执行器不能开票据。
- 变异自证：去掉 `recordBilledRequest` 里的认领，2 条用例红；去掉 `buildBaseLoopConfig` 透传，门禁 1 条红。恢复后全绿。
- `bun test ./packages/core/tests/trace/digest-billing-amount.test.ts`：7 pass，覆盖双记形态必报、1% 内不报、账本时刻之后的事件不计、查不到价不判、老轨迹不判。
- `bun test ./packages/core/tests/{llm,agent,workflow,trace}`：3405 pass / 0 fail。`bun run typecheck:gate` 没有新增错误，`bun run lint` 和 `lint:boundary` 都干净。
- **真实会话判据（尚未验证，合并后观察）**：用过子代理的新会话里，`ledger.costUSD − Σ BilledRequest@event` 应接近 0（方案 §6 PR-8），`events.jsonl` 中 `agent:builtin` 的 `BilledRequest` 应为 `accounted_by:"usage-sink", charged:false`，digest 不再报 `billing_amount_mismatch`。
