# 关闭对话框 / 补全菜单时主屏整帧重画，复原被顶进 scrollback 的历史

## 决定了什么

现象：长对话（帧已溢出视口）里打开 `/model` 等对话框，再按 Esc 关掉，历史消息被顶上去下不来，
最后一条消息与输入框之间留下一整块与对话框等高的空白。

根因不是新 bug，是 #390 / #402 补空行机制的必然结果：对话框打开时帧变高 k 行，最上面 k 行历史滚进终端
scrollback——主屏下光标够不着、也没有指令能把 scrollback 拉回视口；关闭时帧收缩 k 行，`diffMainScreen`
按 #402 规则在历史区下沿补 k 行空行撑住高度。spinner 消失这种 1–2 行的收缩，空行会被下一次增长填掉；
对话框一次缩 7–20 行且之后没有内容来填，就成了大块空白。物理上只有「整帧重画」能复原（History 在帧里，
清屏后 scrollback 照样重建）。

修法（方案 D：显式标记，不在帧层猜）：

- 底座新组件 `Transient`（`packages/tui/src/components/Transient.tsx`）：竖排 Box，样式与
  `<Box flexDirection="column">` 一致，节点带 `internal_transient`。标记**走 props**，在 `createInstance`
  时就标上并登记到根节点 `transientNodes`；不走 ref，因为 ref 在 commit 的 layout 阶段才挂，
  打开浮层的那一帧可能已经出了。
- `dom.hasMountedTransient(root)`：按 parentNode 链判定登记的节点是否仍挂在树上，顺手剔掉已脱离的。
  不维护计数，因为 reconciler 删除子树时只摘顶层节点，子孙收不到回调。`resetAfterCommit` 每次也剔一遍，
  免得 alt-screen 下（不走 diffFrame）登记只增不减。
- `ink.tsx` `diffFrame`：记住上一主屏帧有没有浮层。**上一帧有、这一帧没有、帧变矮、上一帧 p ≥ H**
  四条同时成立 → `resetMainScreen(..., 'offscreen')`；任一条不成立，原样走 `diffMainScreen`。
  条件与补空行分支相同，只把「浮层消失」这一类收缩从补空行改成重画。
- CLI 接线两处：`DialogSwitch` 把非 Composer 的返回统一包一层 `Transient`（权限 / Shell 确认、Plan 审批、
  AskUserQuestion、冲突框、全部 `/` 面板、命令输出面板一次覆盖）；`InputArea` 的补全菜单
  `SuggestionsDisplay` 也包一层（同类问题：输入 `/` 弹菜单再收起）。
  Composer **不能包**：它常驻，包了等于帧里恒有浮层，判定永远不成立。按返回元素的类型判，
  覆盖 `activeDialog` 缺依赖时落回 Composer 的分支。

影响面：不用 `Transient` 的调用方行为一字节不变，`frame-vectors.json` 与 term-bench 基线未改动。
spinner 消失、输入框变矮、TodoPanel 收起、流式结束仍走补空行，不闪。

牺牲的方向：**更快**。关闭浮层那一帧重写整段历史（`2J 3J H` + 整帧），长会话一次写出的字节多；
`3J` 清掉 scrollback 里 sid-code 启动前的 shell 输出，用户上翻位置回到底部（与 resize 同口径）。
支持 DEC 2026 同步输出的终端不闪，Terminal.app 会闪一下，但只在用户主动关浮层时发生。

## 放弃了什么（以及为什么不选）

- **按收缩幅度阈值（> N 行就 full reset）**：TodoPanel 收起、错误面板关闭也会命中；N 没有依据，拍脑袋；
  而且又回到「帧层按内容猜」——#390 → #402 → 本次三连修的教训正是帧层看不到组件边界。
- **对话框改进 alt-screen**：零重画最干净，但对话框变全屏、交互形态变了；要动 `setAltScreenActive` 冻结契约；
  对话框打开期间还有流式输出要处理。范围远超这个 bug。
- **CLI 关闭对话框时调新 API 请求重画**：要改 render-port 接口与契约 X7；且时序有坑——React commit 后、
  effect 前就可能出帧，请求晚到一帧就没用。另外只覆盖对话框，补全菜单照样留白。
- **把被顶走的行重画回视口顶部（不清 scrollback）**：没有闪屏，但这些行在 scrollback 里会重复出现一遍。
- **继续改进补空行插入点**：空行数量 = 收缩行数，换插在哪里都还是一块空白，问题不在插入点。
- **把 Composer 一起包进 Transient**：判定变成恒不成立，见上文。

## 拿什么证明它生效了

- xterm 复现（W=30、H=12、历史 20 行、7 行对话框）。修复前关闭后视口：
  `["","","","","","","","────",">","────","status",""]`；修复后与打开前逐行相同
  `["hist13",…,"hist19","────",">","────","status",""]`，`baseY` 13 → 20 → 13。
- `packages/tui/tests/frame.test.ts` 新增 describe「关闭临时浮层（Transient）」4 例，走真实 `render` +
  `History` + `Transient`，断言 xterm 画面与 scrollback（不断言字节）：关闭后复原且 scrollback 无重复、
  浮层内变化不重画只在关闭帧重画一次、同高度非浮层块消失照旧补空行（0 次 reset）、未溢出的短会话不重画。
  全文件 113 pass / 0 fail。
- 变异自证：`ink.tsx` 判定里 `hadTransient` 前加 `false &&` → 2 例红（复原、只重画一次）；
  把 `!hasTransient` 改成 `true` → 「浮层内变化不重画」红。恢复后全绿。
- `packages/cli/tests/ui/components/dialog-switch-transient.test.tsx` 4 例锁接线：`/model` 与命令输出面板包
  Transient、Composer（含缺依赖落回）不包、空队列返回 null。变异：去掉包裹 → 2 例红；去掉 Composer 判断 → 1 例红。
- `make build` 自检通过且无 `will always be undefined`；`lint` / `format:check` / `lint:boundary` /
  `lint:command-system` 通过；`typecheck:gate` 66/66 无新增。affected-tests 结果见 PR 正文。
- 未验证：真实终端（iTerm2 / Terminal.app）里的闪屏观感与长会话重画耗时，需要在 `sc-dev` 上人工走查。
