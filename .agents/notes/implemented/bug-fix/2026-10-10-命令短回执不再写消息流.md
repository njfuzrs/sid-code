# 命令短回执不再写消息流

## 决定了什么

#223/#228 只收了「多行报告进面板」那一半，< 3 行的回执与错误仍走 `appendCommandOutput`：
`/model claude-opus-5-5` 之后历史区留下 `> /model …` + 「主模型已切换为 …」。人工走查判为同类噪音。

- 斜杠命令结果在 `app.ts` 只剩一个出口 `presentCommandResult`，判据抽成纯函数 `ui/command-result-route.ts`：
  多行（≥ `PANEL_MIN_LINES`，或显式 `panel`）→ 输出面板；短回执 → 底部状态栏临时提示 4s；错误加 `✗`、停留 8s；空输出不显示。
- 未声明 `outputPanel` 的命令输出 ≥ 3 行也进面板：消息流不再兜底，状态栏只有一行放不下。
- 覆盖的分支：新体系 `handleCommandExecutionResult` 的 message / default / error / confirm / quit，
  旧体系回退路径的 message / error / quit，未知命令与「命令执行失败」，`/export` 异步回执。
- `passthrough` 不再先写一条空命令项：随后 `onUserInput` 会把同一段文字作为用户消息上屏，原来是重复一行。
- 刻意保留在消息流的：`/bash`（shell 输出是对话素材）、`/compact` 摘要、`submit_prompt` 的命令行（本身就是一轮对话）。

## 放弃了什么（以及为什么不选）

- **短回执也进面板**：为一行「已切换」按一次 Esc，这正是 #223 定下行数下限要避免的。
- **短回执完全静默**：`/model xxx` 是否生效、错误是什么，用户需要立刻看到；状态栏临时提示既可见又不留痕。
- **只给 `/model` 特判**：同一问题在 /theme /allow /vim /cron delete、未知命令上都存在，按命令打补丁会再漏。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/ui/command-result-route.test.ts`：6 pass。锁住 `/model` 回执 → status、
  错误 → `✗` + 8s、未声明的多行 → 面板、显式 panel 不受下限约束、空输出 → none。
  首版有一条红：前导空行被算进行数，两行回执误判成面板；改为两端 trim 后转绿。
- `grep -n "appendCommandOutput(" packages/cli/src/app.ts` 只剩 `/bash` 两处与 `/compact` 一处。
- **未验证**：真实终端目测（headless 不执行斜杠命令）。建议 `sc-dev` 里 `/model <id>`、`/theme`、`/xx`（未知命令）
  各敲一次，确认历史区无残留、底部状态栏有提示并自动消失。
