# rg 探测加超时并把解析缓存改成 Promise，消除 grep/glob 的静默挂起与探测风暴

## 决定了什么

`packages/core/src/tool/ripgrep.ts` 两处行为变更，同属「rg 命令解析」这一个关注点：

1. **`probeRg` 加超时**：`DEFAULT_PROBE_TIMEOUT_MS = 5_000`，超时后 SIGTERM，
   再过 2s 未退出升级 SIGKILL（与搜索路径 `ripGrepInternal` 的两级终止同构）。
   超时按「探测失败」处理，返回 `false`，由调用方回退。
2. **`resolveRgCommand` 缓存 Promise 而不是结果**：新增模块级 `cachedResolve`，
   首个调用创建 `doResolveRgCommand()` 的 Promise 并同步写入，其余并发调用复用它。
   解析意外抛错时清空缓存，保持原实现「失败不缓存」的语义。

配套：新增 `packages/core/tests/tool/ripgrep-probe-cache.test.ts` 三个用例；
导出 `__setProbeTimeoutForTest`（测试专用，`__` 前缀与既有 `__resetRgCommandCacheForTest` 同风格）
用于在不引入环境变量的前提下缩短探测超时。

## 放弃了什么（以及为什么不选）

- **只修缓存竞态、不修超时**：竞态把 N 次 spawn 收敛成 1 次，但那一次仍可能永久挂起，
  `hasRipgrep()` → grep/glob 工具会一起静默卡死且没有任何报错。两个缺陷叠加才是
  缺陷文档描述的现象，必须一起修。
- **只修超时、不修缓存**：单个调用不再挂死，但并发首次调用仍会各 spawn 一次探测，
  cache stampede 未消除。
- **把探测超时做成环境变量 `SID_RG_PROBE_TIMEOUT_MS`**：第一版这么做了，`docs:gen-reference --check`
  立刻报 `website/ref/env.md` 漂移 —— 该生成器会扫描源码里的 `SID_*` 读取点。探测正常 <100ms、
  5s 已极宽松，用户没有调它的场景，多一条「不建议依赖」的参考页条目只是认知负担。
  改为模块内测试钩子后参考页回到零漂移。
- **换 `node:child_process` / 用 `execFile` 的 timeout 选项**：本仓统一用 Bun 的 `spawn`
  （ReadableStream API），换实现会让 `collectOutput` 等既有代码分叉，收益不值。
- **给 `SID_RIPGREP_PATH` 也加探测**：现有语义是「用户显式指定，直接返回不探测」，
  已有测试断言该行为；改它既多一次 spawn，也违背用户显式指定的意图。

## 拿什么证明它生效了

**变异自证（三次都确认对应断言变红后才恢复，恢复后无 MUTATION 残留）**：

1. 把探测超时改成 `10_000_000`（等价无超时）→ `(fail) probeRg 探测超时（§6.1）...`，
   两个并发用例仍 `(pass)`。
2. 把 `resolveRgCommand` 改回「await 前检查、await 后写入」的值缓存 →
   两个并发用例红且打印真实 spawn 次数：`Expected: 1 / Received: 5`、`Expected: 1 / Received: 4`；
   超时用例仍绿。
3. 让测试钩子失效（`getProbeTimeoutMs` 忽略 override）→ 超时用例再次红，并发用例仍绿。

**恢复后**：`bun test ./packages/core/tests/tool/ripgrep-probe-cache.test.ts` → `3 pass / 0 fail`。

**选测**：`bun run affected-tests:run` → `1596 pass / 0 fail`，105 files，41.24s。

**构建**：`make build` 成功，产物自检 5 项全 ✓（含内嵌 ripgrep 平台匹配）。

**参考页**：`bun run docs:gen-reference --check` → `✓ 参考页与源码一致，CLI 双源对账通过`。

**测试写法上踩到并写进注释的一个事实**：Bun 的 `spawn` 只按**进程启动时**的 `PATH` 解析
可执行文件 —— 父测试里改 `process.env.PATH` 对 `spawn(["rg", ...])` 不生效
（`Bun.which` 同样不跟随），只有显式给 spawn 传 `env` 选项才生效（2026-11-14 实测）。
所以测试用子进程注入 `PATH`，而不是直接改父进程 env；否则测的其实是本机真实 rg。
