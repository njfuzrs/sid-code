# OpenAI 兼容路径：正文末尾孤立的工具调用标记残片先记录再剥离

## 决定了什么

会话 `20261020-130145-4898833d`（glm-5.3-uniapi）的最终文本末尾多了一个孤立的 `</arg_value>`。raw.jsonl 显示它是上游吐出来的 GLM XML 工具调用格式残片，原样进了 `-p --output-format json` 的 `content`。

处置口径（用户 2026-10-30 拍板）是**记录 + 剥掉末尾孤立标签**：

- `packages/core/src/llm/tool-markup-residue.ts`：闭集 `</arg_value>` / `</arg_key>` / `</tool_call>`。只有「在末尾、孤立（正文里没有对应开标签）、是闭合标签」三个条件同时成立才剥。另有流式暂扣函数：可能发展成残片的尾巴先扣住，等后续分片到达或流收尾时再判定。
- `openai.ts` 流式（`parseSSE` 的 `closeOpenBlocks`）和非流式两条出口都接上。**本响应有结构化 tool_calls 时不剥**，暂扣的文本原样放回。
- 命中后落 `protocol-violations/protocol-violation-<ts>-tool-markup-residue.json`（含 provider / model / tag / 前文 200 字），和消息历史违例共用目录与 500 条 LRU。同时发 `SseAnomaly{kind:"tool_markup_residue"}`。

## 放弃了什么（以及为什么不选）

- **只剥不记**：上游吐了半个工具调用协议，说明适配层可能漏解析。静默删掉之后，这条防线有没有触发过就再也回答不了。
- **只记不剥**（文档原先倾向的选项）：`content` 会照旧被污染，下游 bug2mr 等调用方还得各自清洗。用户选了剥离。
- **全文正则删所有残片标签**：正文中间出现的同名字面量多半是模型在讲解这个格式，删了就是改写正文。
- **有 tool_calls 时也剥**：这种情况下文本只是前言，残片的语义不同，目前没有样本，先不碰。
- **把 XML 残片解析成工具调用**：只有 1/128 次请求、1 个会话的证据，看不出完整格式，属于过度设计。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/llm/tool-markup-residue.test.ts`：15 pass。覆盖标签切成 3 片、EOF 无 `[DONE]`、成对标签、正文中间、有 tool_calls、非流式这几种情形。
- 变异自证：把流式、非流式两处判定都改成 `false &&`，「多片剥离」「EOF 剥离」「非流式剥离」3 条断言变红（12 pass / 3 fail），恢复后全绿。
- `bun run affected-tests:run`：3070 pass / 0 fail；`make build` 自检通过；lint / format:check / typecheck:gate 均无新增问题。
- 真实效果待观察：之后用 `SseAnomaly` 的 `kind=tool_markup_residue` 统计触发频率；频率上来了，再考虑适配层是否需要解析这种格式。
