# 无头模式（-p / stream-json / Bridge）分发斜杠命令，插件管理改走 `sid-code plugin`

## 决定了什么

修复前三种无头形态都把输入直接交给 `queryEngine.submitMessage`，只有 TUI 的 `onSlashCommand`
分发命令。`-p "/plugin market"` 被原样当成提示词，模型自己去 strings 二进制、读源码
（实测 110s 未结束）；`-p "/某skill"` 也不展开，能用上只是模型碰巧认出了名字。
`--disable-slash-commands` 的帮助文本写着「headless/受限场景」，实际只在 TUI 生效。

改法：

1. **一个无头提交入口** `App.submitHeadlessInput`（`packages/cli/src/app.ts`）：runHeadless、
   runHeadlessSDK（`buildSDKDriver.submitMessage`，stdin 后续每条消息同样经过）、runBridge
   三处都改调它。它把分发结果翻成引擎事件，三种形态各自的消费循环一行没改：
   - 提示词类命令 → 展开后 `submitMessage(prompt, { displayCommand })`，带本轮 allowed-tools；
   - 本地已产出回答（fork skill / 文本结果）→ 写进上下文与会话落盘，经 `emitStreamText`
     输出，补一条 `done`；
   - 拒绝 / 失败 → `fatal_error`（text/json 退出码 1；stream-json 为 `error_during_execution`）。
2. **判定与映射是纯函数** `packages/cli/src/command/headless-dispatch.ts`，执行仍走 TUI 同一个
   `CommandExecutor`（未知命令 / `/tmp` 路径 passthrough / 门控只有一份实现）。
   放行口径：非 builtin 来源（自定义命令、skill、插件、MCP prompt）放行；builtin 缺省拒绝，
   显式 `headless: true` 才放行——目前只有 `/init`。契约字段 `CommandBase.headless`。
   拒绝时指向真实存在的 CLI 子命令（`/plugin` → `sid-code plugin`，`/mcp` → `sid-code mcp`）。
3. **`sid-code plugin <子命令>`**（`command/plugin-cli.ts`，bootstrap 快速路径）：直接复用
   `PluginCommand.execute`，不启动 App、不调模型，退出码确定。供 CI / 脚本装插件。
4. `--disable-slash-commands` 接进无头分发，与 TUI 同口径（`/xxx` 原样作为提示词）。
5. `QueryEngine.emitStreamText`：本地命令的文本结果走与模型回答同一个流式出口，
   三种形态挂的回调（拼 stdout / 转 stream_event / 发给远端）不需要知道来源。

## 放弃了什么（以及为什么不选）

- **无头全量走 executor**：AppContext 里大量回调依赖 TUI（beginForkedRun 的 spinner、dialog、
  confirm、状态栏 notify、各种 `set*` 的 updateState）。全量放行的结果是一半命令能跑、
  一半静默失效——正是「死接线零报错」。宁可明确拒绝，让 CI 拿到退出码 1，也不给假成功。
- **在 `-p` 里支持 `/plugin install`**：插件管理是写配置的操作，不需要会话、不需要模型。
  放进 `-p` 要先起一整个 App（MCP 连接、权限、轨迹），再在一条不调模型的路径上收尾，
  而 `sid-code mcp` 已经证明「管理类 = CLI 子命令」这条路更干净。对齐 CC 的 `claude plugin`。
- **按 builtin 名单列「哪些不可用」**：默认放行、黑名单拒绝的话，新加的交互 builtin 会默认
  漏进无头路径。反过来缺省拒绝、白名单放行（`headless: true`），新命令不声明就安全。
- **未知命令原样交给模型**（旧行为）：模型拿到 `/xyz` 只会去猜它是什么，110s 那次就是这个。
  现在与 TUI 一致报「未知命令」；真实路径（`/tmp`）仍由 executor 的 stat 判定放行。

## 拿什么证明它生效了

`make build` 后用编译产物实测（临时命令 / skill 放在用户级目录，验证后已删除）：

| 输入 | 退出码 | 结果 |
| --- | --- | --- |
| `sid-code -p "/plugin market"` | 1 | stderr 报「/plugin 是交互命令…请改用 sid-code plugin …」，`LLM: 0 次请求` |
| `sid-code -p "/definitely-unknown-xyz"` | 1 | 「未知命令」，`LLM: 0 次请求` |
| `sid-code -p "/hsc-echo-marker hello" --output-format json`（用户级自定义命令） | 0 | `"text": "MARKER-7731 参数=hello"`，`LLM: 1 次请求` |
| `sid-code -p "/hsc-marker"`（用户级 skill） | 0 | `"text": "SKILL-MARKER-4419"`，`LLM: 1 次请求`、`工具: 0 次调用`——确定性展开，不靠模型调 Skill 工具 |
| `sid-code -p --disable-slash-commands "/plugin 这个词…"` | 0 | 原样交给模型回答，`LLM: 1 次请求` |
| `sid-code -p "/plugin market" --output-format stream-json --verbose` | 0 | `system/init` 后一条 `result/error_during_execution`，errors 为拒绝原因 |
| `sid-code plugin marketplaces` / `plugin list` / `plugin bogus` | 0 / 0 / 1 | 与 TUI `/plugin` 同输出 |

单测：`packages/cli/tests/command/headless-dispatch.test.ts`、`plugin-cli.test.ts`（27 pass）。
`bun run affected-tests:run`：3261 pass / 0 fail。`tsc --noEmit` 对本次改动文件零报错
（`typecheck:gate` 唯一新增项是 worktree 里 `signal-exit` 解析到 3.0.7 导致的
`packages/tui/src/ink.tsx` TS1192，与本改动无关）。

**已知未覆盖**：

- Bridge 路径只改了入口（与另两处同一函数），没有端到端连远端实测。
- stream-json 下任何 `error_during_execution`（含本次的拒绝）进程退出码都是 0：
  `runHeadlessSDK` 只看 `runError || budgetExceeded`。这是存量行为，不是本次引入；
  多轮宿主会话里「某一轮失败 = 进程失败」并不显然，改它要单独定口径，本次不动。
- 项目级 `.sid-code/commands/` 在未信任目录下 `-p` 不加载（信任门 fail-closed），
  所以项目命令在 `-p` 下报「未知命令」是预期；需要时用 `trust_project_extensions`。
