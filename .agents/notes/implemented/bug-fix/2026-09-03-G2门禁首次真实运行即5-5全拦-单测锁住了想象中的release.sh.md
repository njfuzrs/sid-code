# G2 产物身份门禁首次真实运行即 5/5 全拦 —— 单测锁住的是想象中的 release.sh

## 决定了什么

把 `judgeReleaseUpload` 的 dirty 白名单从硬编码的 `f !== "package.json"` 换成新常量
`RELEASE_COMMIT_PATHS`（`scripts/lib/artifact-identity.ts`），它等于 `scripts/release.sh`
的 `RELEASE_COMMIT_FILES` —— 即 bump 提交实际会收进历史的那 4 个文件。

判据的正确形态不是「脏文件只有 package.json」，而是**「这些脏改动有没有 git 引用能重建」**。
release.sh 在构建**之前**生成 changelog 产物（`:718` changelog、`:723` 内嵌 skill），
在构建**之后**的第 6 步把它们随 bump 一起 commit。所以它们在构建时必然脏，
却照样有 git 引用可重建 —— 就是 `v<ver>` 本身。

配套改了 3 处测试（`tests/eval/artifact-identity.test.ts`）：
- 原「真实执行顺序」用例的 `dirty_files` 从 `"package.json"` 改成产物字节里的真实值
  `CHANGELOG.md+package.json+website/.vitepress/data/changelog.json`；
- 新增「真带着未提交代码发版 → 拒」，锁住白名单放宽后**真问题仍被拦**；
- 新增 T8 漂移哨兵：机械比对白名单与 release.sh 的 `RELEASE_COMMIT_FILES` 逐条相等。

## 放弃了什么（以及为什么不选）

**① `--allow-dirty` / 加 flag 绕过（否决）。** 这正是 `judgeReleaseUpload` 文件头
已经写下的警告：「照直觉写的后果不是『报个错』—— 是每次发版都被拦、然后被人加 flag 绕过，
那就又变成『误报训练人绕过门禁』」。用 flag 绕过等于让这道门禁在第一次真实运行时就死掉。

**② 把 changelog 生成挪到构建之后（否决）。** changelog 产物本就不进二进制字节
（`grep` 全源码零引用，命中项全是 eval fixtures 的 yaml 文本），挪它不解决判据错这个根因，
反而动了发布流程的既有顺序，风险大于收益。

**③ 只把这 3 个文件加进白名单（否决）。** 那是照着报错信息补，下次 `RELEASE_COMMIT_FILES`
再加一项照样再红一次。单一事实源 + T8 漂移哨兵才治得住。

**④ 白名单改成"只要在 tag tree 里就放行"这种动态判据（未采纳）。** 更严谨，但要在门禁里跑
git 命令、引入新的失败模式；而 `RELEASE_COMMIT_FILES` 是个静态清单，逐条相等已经够。

## 拿什么证明它生效了

**根因取自产物字节，不是推测。** 从 `dist/build/darwin-arm64/sid-code` 里 strings 出来的身份行：
`dirty_files=CHANGELOG.md+package.json+website/.vitepress/data/changelog.json` —— 恰好 2 个
文件超出旧白名单，与日志里 5/5 个产物的拒绝理由逐字对得上。

**为什么此前没被发现**：G2 引入于 `58d7dc84`（#128），
`git merge-base --is-ancestor 58d7dc84 v0.1.601` 失败 ⇒ 它不在 v0.1.601 里，
**这是它第一次真实运行**。单测一直是绿的，因为它锁的假设与 release.sh 真实产出不同。

**变异自证三条，判据是「红的是哪一条」而非「有东西红了」**（`bun test tests/eval/artifact-identity.test.ts`，
基线 45 pass / 0 fail）：

| 变异 | 汇总 | 红的是哪一条 |
| --- | --- | --- |
| 白名单改回 `f !== "package.json"` | 44 pass / 1 fail | 「按 release.sh 真实执行顺序的产物」✅ |
| 删掉 `unexpected` 判据整段 | 43 pass / 2 fail | 「真带着未提交代码发版 → 拒」+ 既有那条 ✅ |
| 往白名单塞一条 release.sh 没有的路径 | 44 pass / 1 fail | 「T8 漂移哨兵」✅ |

三次变异后两个文件均逐字节还原（脚本断言 `== orig`，通过）。

**T8 的取数源独立复算过**，防「正则没匹配到 → 空集上假绿」：从 release.sh 解析出 4 条
`['package.json', 'CHANGELOG.md', 'website/.vitepress/data/changelog.json',
'packages/core/src/skill/builtin-embedded.generated.ts']`，非空且与常量一致。

⚠️ **尚未证明的那一半**：本 note 写作时**还没有一次真实 `--upload` 通过 G2**。
按本仓已有的教训（「新增防线的验收判据不是 build 过 + 单测过，而是真实会话里被触发过」），
这条修复的验收判据是**下一次真实发布走完 G2 并上传成功** —— 在那之前它只是"单测认为对"。
