# 项目级路由字段被忽略时给启动告警；`update --version` 命中本地版本时离线切换

## 决定了什么

1. `loadConfig` 末尾新增 `recordIgnoredProjectRoutingKeys`（`packages/core/src/config/config.ts`）：
   项目级 / 本地级 settings 里出现 `PROJECT_IGNORED_ROUTING_KEYS`（model / availableModels / baseURL /
   provider / apiKey 等，含 snake_case）时，按文件记一条 `recordStartupWarning`，列出命中键并指向
   `~/.sid-code/settings.json`。丢弃行为本身不变，只是不再静默。
2. 回滚离线可用，两层都改：
   - `install-template.sh`：显式 `SID_CODE_VERSION` 且 `versions/<v>/sid-code --version` 跑得通时，
     跳过下载 + sha256，直接写 `.channel` + 切软链。下载路径里的「已存在即复用」也加了能跑通的前提，
     坏目录会被刚校验过的 tarball 覆盖。
   - `update.ts`：`--version` 先试 `tryLocalSwitch`（同样只做写标记 + 原子切软链），排在查清单之前；
     否则 `curl install.sh | bash` 这一步离线就拉不到脚本，只改 install.sh 不够。
3. first-task FAQ：补「bash 次数 > 0 不等于验过，展开看真实输出」。

## 放弃了什么（以及为什么不选）

- **把 env 也列进告警键**：不选。env 走 managed-env 两阶段，白名单变量信任前就生效，并非被丢弃，
  列进去是误报。
- **在 update.ts 里用 TS 重写下载/校验**：不选。文件头已定下下载链路只有 install.sh 一份实现；
  本地快速路径只做最后两步（标记 + 切链），不引入第二份下载/校验实现。
- **复用前重新校验 sha256**：不选。校验需要远端 .sha256，离线拿不到；目录在首次安装时已校验，
  用 `--version` 冒烟兜本地损坏，跑不通就退回联网重装。
- **未锁版本（装最新）也走本地**：不选。最新版本号本身要联网解析 latest.txt。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/config/project-routing-keys-warning.test.ts`：2 pass；
  注释掉 `recordIgnoredProjectRoutingKeys` 调用 → `Expected length: 1` 红，恢复后绿。
- `bun test ./tests/scripts/install-offline-reuse.test.ts`：file:// 指向**空**发布目录真跑 install.sh，
  锁版本 + 本地二进制可跑 → rc=0、输出「跳过下载」、软链指向本地目录；把复用条件改成 `if false`
  → 该用例红（脚本去下载并失败）。
- `bun test ./packages/cli/tests/command/update.test.ts`：19 pass；把 `tryLocalSwitch` 短路为 false
  → 「切软链，不查清单、不跑 install.sh」用例红。现有 `--version` 用例显式传 tmpdir 安装路径，
  避免默认值指向真实 `~/.local` 切掉本机软链。
