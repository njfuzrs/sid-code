# Footer 的 `≈$` 前缀按「价格有没有换过汇」判断，不再看模型名

## 决定了什么

修的是 D7（P1 误导）：`deriveCost` 原来用 `/deepseek/i.test(model)` 决定写 `≈$` 还是 `$`，
把「是不是 DeepSeek」当成了「价格有没有做过汇率折算」。两者只在一种渠道组合下恰好一致，
真实会话里两边都错：

- 网关 `billing_expr` 的系数已经是 USD/1M（`source: "gateway:expr"`），模型名仍叫
  `origin-deepseek-v4-1-flash` → 没换汇却加了 `≈`；
- 内置注册表里 CNY 计价（`currency: "CNY"` + `fxToUSD: 1/7.1`）的模型，如果配成不带
  `deepseek` 的别名 → 换过汇却不加 `≈`。

改动落在三处，判据统一为「本会话入账价里有没有非 USD 币种真被 `fxToUSD` 折算过」：

1. **数据源**（`packages/core/src/session/state.ts`）：
   - `ModelUsageStats` 新增 `priceCurrency?: string` 与 `priceFxToUSD?: number`，
     在 `updateUsage` 里取 `resolvePricing(...)` 的**原始值**（不是 `effectivePricing`
     折算后的值 —— 后者会把 `currency` 改写成 `"USD"`，拿它永远判不出「换过汇」）；
   - `hydrateUsage` 显式回灌这两个字段（漏了 resume 后判据静默丢失）；
   - 新增 `isCostFxConverted()`（Footer//cost//debug 共用的唯一判据）与
     `getCurrencyConversions()`（/cost 的换算说明用）。
2. **Footer**：`Footer` / `BottomRegion` / `TUIState` 增加 `costFxConverted` 透传，
   `deriveCost(costUSD, costLimit, fxConverted)` 不再接收模型名；`app.ts` 六处推送
   （初始 + 5 个刷新点）与 `/clear` 补丁都带这个值。
3. **/cost、/debug**：金额前缀改读同一个 `isCostFxConverted()`；/cost 末尾在有折算时
   加一行「币种换算: 1 USD = 7.1 CNY（固定汇率；≈ 表示按此折算的估算值）」，
   汇率取入账时的 `1 / fxToUSD`，不写死 7.1。

## 放弃了什么（以及为什么不选）

- **不在 UI 层继续按模型名推断**（哪怕加几个别名正则）：模型名与计价渠道是两个维度，
  网关价可以让任何名字成为 USD 价，注册表也能让别名成为 CNY 价。判据必须指向价格数据本身，
  这也是 `src/ui` 与 CLAUDE.md「禁按模型硬编码分级」的要求。
- **不只记 `priceCurrency`、不记汇率**：`/cost` 的换算说明要写出「1 USD = 7.1 CNY」，
  不存 `fxToUSD` 就只能写死一个常数或重查一次定价（重查可能与会话内实际计价时段/渠道不一致）。
  多存一个数值字段的代价远低于写死汇率。
- **不在 `calculateCost` 里顺手记录字段**：它是公开的重算入口（`trace/cost-recompute.ts`
  也走同一套公式），塞入展示字段会污染纯计算职责；宁可在 `updateUsage` 里多调一次
  `resolvePricing`（内存查表）。
- **不改 `forked-agent.ts` 的 `querySource`**：那是 D10 的修法，且 `BILLING_SELF_REPORTED_LABELS`
  与重试漏斗按它判断，改它会动计费去重（本 PR 只修 D7，不扩大范围）。
- **不做 `Currency` 抽象 / 多币种展示**：当前只有 USD/CNY 两种，且计价结果一律折算成 USD
  存储；把币种提到展示层做多币种换算属于新功能，不在 D7 范围内。

## 拿什么证明它生效了

- 新增 `packages/core/tests/session/cost-fx-currency.test.ts`（6 条）：
  - CNY + `fxToUSD` → `isCostFxConverted()` 真、`1/fx = 7.1`；
  - **T-A6 反向**：模型名 `deepseek-chat` 但价是 USD → 判据假（旧实现在这里会误标 `≈`）；
  - CNY 缺 `fxToUSD` → 假（`effectivePricing` 不猜汇率，钱没换汇）；
  - **T-A7**：serialize → hydrate 后判据与汇率不丢（resume 回归）；
  - `/clear`（`resetCounters`）后判据归零；
  - 多模型混价：有一条折算过即真。
- 改 `packages/cli/tests/ui/status-line-data.test.ts` 的 `deriveCost` 用例为新签名，
  锁住「折算过 → `≈$`、没折算 → `$`」两个方向。
- 变异自证（要求先红后绿，均已实测）：
  1. `deriveCost` 改成永远 `"$"` → 「折算过 → ≈$」用例红；
  2. `isCostFxConverted` 改回 `/deepseek/i.test(模型名)` → 6 条中 5 条红；
  3. 恢复后 `bun test ./packages/core/tests/session/cost-fx-currency.test.ts
     ./packages/cli/tests/ui/status-line-data.test.ts` → 41 pass / 0 fail。
- `bun run affected-tests:run`（cli + core/session，3443 个用例）：3432 pass / 2 fail。
  两个失败单跑均通过（`bun test <两文件>` → 17 pass / 0 fail），成因是真实计时器在
  全量并发负载下的抖动（其一失败于 5113ms = bun 默认 5s 单测超时），与本次改动无关。
