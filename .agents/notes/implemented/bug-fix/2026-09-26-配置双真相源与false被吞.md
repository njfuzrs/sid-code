# 配置加载不再有两个真相源，显式的 false 不再被当成「没设」

## 决定了什么

三处一起改，缺一不可：

1. `mergeConfig` 只跳过 `undefined`，不再跳过 `false` 和 `""`。
   `false` 是「关掉」的表态，以前被当成没给，文件里显式写的 `false` 会被更高层的缺省盖掉。
2. `app.json` 只贡献 `AppConfig` 声明过的字段。`loadNewFormatAsConfig` 读它时丢弃清单外的键，
   `readFromDisk` 同样过滤，否则 `saveAppConfig` 的「读出再整份写回」会把残留键写回去。
   项目级 / 本地级覆盖改为只取 `projectSettings` 与 `localSettings` 两个来源——
   PR #99 取的是 `getSettings()` 的合并结果，而它包含用户级 settings，等于把
   `~/.sid-code/settings.json` 读两遍再盖一次。
3. 迁移 v4 处理存量：`app.json` 的越界键搬回 `settings.json`（settings 已有的不覆盖，
   值等于默认的不搬），并删除 `settings.json` 里那批「整份默认配置被灌进文件、
   值仍等于默认」的键（`DUMPED_DEFAULT_KEYS`）。值与默认不同的不删。

## 放弃了什么（以及为什么不选）

- 保留全屏默认。最初没改，理由是 2026-07-23 `3094a379` 用它根治幽灵行、之后没有
  替代修复。这个理由被实际使用否定了：主屏路径此后修过 Static 同步折叠，长期在主屏
  使用并无幽灵行，而全屏的代价（鼠标上报吃掉拖选）是每次启动都发生的。`fullscreen.ts`
  与 settings schema 的注释本来就写着缺省主屏（ADR-040），`defaultConfig` 的 `true`
  与它们矛盾。所以默认改回 `false`，全屏留作 `--alternate-buffer` / `/tui on`。
- 把 `app.json` 的越界键直接删掉。其中 `ide`、`sanitizeEnv`、`jitContext` 的值与默认不同，
  是用户设过的，只存在于 `app.json`，删了就丢。所以是搬而不是删。
- 用「键在不在默认里」判断灌入残留。`model`、`effortLevel` 也在默认里但用户改过值，
  判据必须是「值与 `defaultConfig()` 相同」，不能是「键名重合」。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/config/ ./packages/core/tests/migrations/ --test-name-pattern '^(?!.*\[slow\])'`：
  700 pass / 0 fail。新增断言覆盖「文件里的 `false` 与 `""` 存活」「`app.json` 越界键不覆盖
  settings 且回写后不再出现」「值等于默认的灌入键被删、改过的保留」「迁移幂等」。
- 默认改回主屏后重跑：`bun test` cli + config + migrations 2261 pass / 0 fail；
  `make build` 退出 0，产物自检通过，无 warning。用 v4 迁移之后的真实配置副本跑
  `loadConfig({})`，得到 `alternateBuffer=false`，`model` 与 `effortLevel` 不变，
  v5 迁移对该配置不删不改任何键。
- 用真实 `~/.sid-code/` 的副本演练迁移：删除 19 个灌入键（含 `alternateBuffer`），
  新增 7 个只存在于 `app.json` 的真值键，`model` / `effortLevel` / `fallbackModel` /
  `language` 原值不变，无任何键被改值；`app.json` 只剩 `AppConfig` 声明内的 12 个键。
