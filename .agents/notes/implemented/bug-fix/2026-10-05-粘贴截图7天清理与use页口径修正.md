# 粘贴截图按 7 天自动清理，use/ 八页按源码修正口径

## 决定了什么

- 新增 `cleanupStalePastedImages`（`packages/core/src/config/startup-housekeeping.ts`）：启动清理按 mtime 删除 `{sidTemp}/pasted-images/` 下超过 7 天的截图，复用 masked-outputs 的判据与水位线节流。此前全仓没有任何代码删这个目录，而 `use/interactive.md` 承诺「会话结束后清理」，路径也写成了不存在的 `~/.sid-code/tmp/`。截图常含敏感内容，所以选择把承诺做成功能，而不是只删掉这句话。
- 文档改成真实行为：路径写 `/tmp/sid-code-<uid>/pasted-images/`，会话结束时不删，启动时清理 7 天以上的截图。
- use/ 八页按当前 main 源码修正（整改清单 D18/D19/D21/D22/D28/D29/D34/D37/D44–D55/D97/D104）：旧 `src/` 路径改成 `packages/*/src/...` 并去掉行号；`/compact` 失败后果按模式分别写；worktree 归因 hook 在共享 hooks 目录下不装；自动更新的两种失败提示时机；团队默认 `autoUpdate` 按「首装拷贝 + 升级只补缺失键」写；`--list-sessions` 样例换成虚构标题；删掉「对齐 claude-code」类表述。

## 放弃了什么（以及为什么不选）

- **会话退出时删除本会话的截图**：要追踪哪张截图属于哪个会话，而截图在粘贴当轮就已经以 base64 读进消息，磁盘文件只是中转。崩溃或 kill -9 时退出钩子也不会跑，最后还得靠启动清理兜底。直接用启动清理一条路就够了。
- **只改文档、不做功能**：「会自动清理」这句话删掉之后，截图会无限期留在共享 /tmp 里。这是隐私问题，而功能本身大约 30 行。
- **递归删除子目录**：写入方只会生成扁平的文件，没有必要递归；不递归能避免将来有人往这个目录放别的东西时被一起删掉。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/config/startup-housekeeping-pasted-images.test.ts`：4 pass / 0 fail。用例同时断言「超过 7 天的删、7 天内的留」，并先断言临时根目录已重定向到 mkdtemp（`SID_CODE_TMPDIR` 指过去，再加 `__resetSidTempDirCache`）。
- 变异自证：把接线改成 `const pastedCleaned = 0;` 后，「超 7 天的删、7 天内的留」这条用例变红（3 pass / 1 fail），恢复后转绿。
