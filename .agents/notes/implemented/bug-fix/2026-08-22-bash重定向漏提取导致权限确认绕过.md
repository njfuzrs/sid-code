# bash 重定向漏提取让 `2>` 类写盘命令绕过权限确认，修解析层两处根因

## 决定了什么

修 `packages/core/src/tool/bash/parser.ts` 的重定向解析，让 `extractRedirectTargets`
不再漏掉写入目标。三处改动：

1. **重定向解析从"尾部单次正则"改为"引号感知的全量扫描"**（新增 `scanRedirects`）。
   旧实现 `/^(.+?)\s+(>>|2>|>)\s*(\S+)\s*$/` 有三个独立缺陷叠在一起：
   操作符白名单缺 `1>` `3>` `&>` `&>>` `>|`；`\s+` 强制前导空白；`$` 锚死行尾。
   且一条命令可以有**多个**重定向（`cat f 1>/tmp/o 2>/tmp/e`），单次匹配结构上拿不全。
2. **`collectRedirects` 的 mode 判断改走 `WRITE_REDIRECT_MODES` 集合**，
   不再写第二份字面量白名单。旧代码 `mode === ">" || mode === ">>"` 会把已经
   解析成 redirect 节点的 `2>` 又丢掉——**解析认识、收集不认识**。
3. **管道拆分正则加后顾断言 `(?<!>)`**，让 `>|` 里的 `|` 不被当管道符；
   配套把 `splitOutsideQuotes` 从 `str.slice(i).match()` 改为**粘性匹配**
   （否则后顾断言在切片首位恒真，静默失效）。

同时豁免 `/dev/null` / `/dev/zero`（`DISCARD_TARGETS`），因为修复的正确副作用会让
`cat f 2>/dev/null` 这类极常见纯读命令第一次被判非只读 → 白弹确认。
豁免用**精确相等**而非 `startsWith`，吸收 `permission/bash-security.ts:119` 记的
`/dev/nullo` 前缀命中坑。

新增 `packages/core/tests/tool/bash-redirect-extraction.test.ts`（125 用例）。

### 缺陷的严重性：不是"解析不精确"，是权限确认绕过

```
extractRedirectTargets 漏目标      parser.ts:156
  → isReadOnlyCommand 误判只读      read-only-validation.ts:308-312
    → checkPermissions → allow      bash.ts:499-511  ← 免确认直接放行
```

实测裁决：

```
⚠️ ALLOW(免确认)  ls 2> ~/.ssh/authorized_keys
   passthrough    ls >  ~/.ssh/authorized_keys      ← 同一命令、同一目标，只换操作符
```

`parser.ts` 有 5 个 src 侧消费方（3 个做安全判定），**自己零直接测试**
（修复前 `grep -rl "bash/parser"` 在测试目录返回空）。

## 放弃了什么（以及为什么不选）

**① 放弃「只在 `isReadOnlyCommand` 层打补丁」。**
最省事的做法是在 `read-only-validation.ts` 里加一条 `/2>/` 正则兜住。不选，
因为漏提取的后果不止一个消费方：`isConcurrencySafe`（写命令被当并发安全）、
`checkpoint/bash-affected-files`（少记受影响文件）都受影响。
补在下游只修一个症状，parser 仍然是错的，下一个消费方接上去还会中一次。

**② 放弃 fuzz（随机输入 + "永不抛"类不变量）。**
先按方案原计划跑了 20000 轮随机 bash 片段：**0 抛异常、`$(` 嵌套 5 万层不栈溢出**。
零发现。根因是 `parseBashCommand` 外层有 `try/catch` 兜到 `{type:"unknown"}`，
"永不抛"是**结构上保证的**——测它等于测一条语法事实，是恒绿测试。
改用 **metamorphic**（34 条构造命令，每条埋 sentinel 路径当 oracle）→ 抓到 10 条。
**oracle 比输入量重要**：34 条带 oracle 胜过 20000 条无 oracle，
因为本仓缺陷形态是"不报错、结果错"，无 oracle 的 fuzz 只能抓"报错"。

**③ 放弃差分测试 + tree-sitter-bash wasm 参考实现。**
三条理由：收益已被 metamorphic 吃掉（我们自己就能当 oracle）；wasm 是运行时产物依赖，
与「构建发布离线优先」有实质张力；tree-sitter 解析**完整 bash 语法**而 `parser.ts`
刻意只做权限判定所需的近似解析，拿它当 oracle 会产出海量"已知偏差"——
**需要建 registry 压噪本身就是 oracle 选错的症状**。

**④ 放弃把 `tee` / `dd of=` / `sed -i` 一起收进本 PR。**
实测 `cat a | tee /tmp/x` 同样被判只读，但根因在 `read-only-validation.ts` 的
**命令白名单**，不在 parser 的**解析层**。两个关注点混进一个 PR 会让 review
分不清哪些改动是必要的（CONTRIBUTING 的 PR 单元判据）。已在方案文档 §九 记为独立待办。

**⑤ 放弃把 `/dev/stdout` `/dev/fd/*` 也加进豁免集。**
它们在某些用法下确实是持久写入（`/dev/stdout` 被重定向到文件时）。
豁免集保持最小、偏保守侧——多弹一次确认的代价远小于漏放一次。

### 2. 变异自证 —— 三处根因分别改回旧行为，确认测试报红

不做这一步就可能建出一个恒绿的门禁（`s2-cooldown-clear-test-is-false-gate` 教训）。

| 变异 | 改动 | 结果 |
|---|---|---|
| M1 | `collectRedirects` 退回 `mode === ">" \|\| ">>"` | **21 fail** / 104 pass |
| M2 | 管道正则去掉 `(?<!>)` | **3 fail** / 122 pass |
| M3 | `splitOutsideQuotes` 退回 `str.slice(i).match()` | **4 fail** / 121 pass |

三处全部报红，改回后 125 pass 0 fail。

**M3 顺带暴露一个性能问题**：`slice` 版本在 2000 个重定向的用例上是 O(n²)，
单文件耗时从 **0.29s 涨到 137.21s**。粘性匹配把它一并修掉了（这不是本 PR 的目标，
是改法的副产品，记在这里以免以后有人"简化"回 slice）。

## 朝向感与代价（北极星自检）

- **更安全 ✅ 主要收益**。堵的是一个静默的权限确认绕过：不报错、命令照跑、
  用户看不到确认框。归到「防线触发率」那一格。
- **更快 🟡 有代价但已压到最小**。修复的正确副作用会让 `2>/dev/null` 这类
  纯读命令开始白弹确认——用 `DISCARD_TARGETS` 豁免掉了，实测 22 条纯读命令
  0 过度提取。若不豁免，这就是一次用户立刻能感知的体验退步。
- **更省 ⬜ 无影响。**
- **更准 🟡 间接**。`checkpoint/bash-affected-files` 现在能记全受影响文件。

代价点破：`scanRedirects` 是逐字符扫描，比单次正则慢。但它跑在权限判定路径上
（每条 bash 命令一次），2000 个重定向的极端用例仍在毫秒级，实测 `tests/tool/`
整体 11.62s 与修复前同量级。
