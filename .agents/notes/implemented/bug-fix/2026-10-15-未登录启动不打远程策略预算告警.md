# 未登录时启动不再往 CLI 打远程策略 / 预算 WARN

## 决定了什么

未登录（无设备凭据）是正常状态，不是故障。`packages/core/src/config/policy.ts` 的
`RemotePolicyLoader.load()` 无凭据分支、`packages/core/src/telemetry/remote-budget.ts` 的
`loadRemoteBudget()` 无凭据分支，原先各自 `log.warn`，再加上 `usableCachedSettings(cache, "no_credential")`
的一条 WARN，共 3 行。logger 未启用时 WARN 会兜底写 stderr（`debug/logger.ts` OBSERV-4），
所以这 3 行印在 TUI 首屏之前。

改法：这两条路径降为 `log.debug`；`usableCachedSettings` 加一个 `level` 参数，
只有 `no_credential` 调用方传 `"debug"`，网络错 / 5xx / 401 等真异常默认仍是 `"warn"`。

## 放弃了什么（以及为什么不选）

- **把 POLICY / BUDGET 分类整体 mute**：会把已登录时的网络失败、缓存过期停用约束这些真异常一起吞掉，
  企业策略失效变成静默。否决。
- **改 logger 兜底，不让 WARN 写 stderr**：影响全仓所有早期告警（OBSERV-4 专门为留痕加的），
  爆炸半径远大于本问题。否决。
- **删掉日志**：debug 级别仍落盘（`--debug` 时可见），排查「为什么策略没生效」还要用。保留。

「是否登录」由 `sid-code auth status` / 状态栏表达，不靠启动日志。

## 拿什么证明它生效了

- 新增 3 条测试：无凭据时 POLICY / BUDGET 不调 `warn`；已登录但 503 且无缓存时 POLICY 仍调 `warn`
  （防降级过头）。`bun test ./packages/core/tests/config/remote-policy.test.ts ./packages/core/tests/telemetry/remote-budget.test.ts`
  55 pass / 0 fail；`affected-tests:run` 1281 pass / 0 fail。
- 真 pty 端到端：空 `SID_CONFIG_DIR` + 配好 policy/budget endpoint，启动后抓首屏 6s 输出。
  主仓旧二进制出现 3 行 `[POLICY]`/`[BUDGET]` ⚠；本次构建的二进制 0 行。
