# S3 复审遗留：送达标记只认终态，回合纪元只在模型真返回后推进

## 决定了什么

修复复审清单「修-2」（B2 + M5 + L1–L4 + T1）：

- **B2**：`markNotificationsDelivered`（`task/registry.ts`）只对终态任务置送达回合；`injectPendingNotifications`（`query/loop.ts`）只把 `structured.status` 为终态的通知的 taskId 传进去。两道都留——shell 停滞检测给**运行中**任务发的「疑似等输入」通知以前会提前记送达，任务完成后驻留期一过就删 `.output`，而真正的完成通知还在队列里。
- **M5**：`queryLoop` 新增局部 `modelRespondedSinceTurnMark`，只在拿到模型响应后置真；轮开头与 finally 两处推进回合纪元都要求它为真。PTL 压缩重试、超时重试、调用抛错、流式中 ESC 都不再推进。
- **L1**：`taskIdFromOutputPath` 比较目录前先 `realpath`，macOS/Windows 上再折叠大小写。
- **L2**：`clearInactiveTasks` / `clearAllTasks` 删终态任务文件前登记 `reason=cleared` 的墓碑，说明文本区分「/clear 清理」。
- **L3**：抽出 `deliveredTurnPassed()`，`evictDecision` 与 `hasPendingEviction` 同源调用。
- **L4**：前台子代理（`notify=false`）送达回合记 `N+1`。
- **T1**：新增 `packages/core/tests/task/task-lifecycle-s3-followups.test.ts`，用真实 `queryLoop` 锁住「先推进、再注入」与 M5。

## 放弃了什么（以及为什么不选）

- **M5 用「送达后成功响应计数 ≥1」挂在任务上**：要给每个任务加字段、在响应路径遍历 registry；纪元本身只有一个调用方（queryLoop），在推进点加门更小且对所有任务一致。
- **B2 只在调用侧过滤**：registry 的注释早就写了「只认终态」，结果代码没做，就是这次的 bug；只修一侧，下一个调用方又会漏。
- **L4 改为 tool_result 入上下文时再置位**：要把 taskId 从 runSync 透传回 loop 的 tool_result 拼装点，跨 agent/tool/query 三层；记 `N+1` 语义等价且只改一行。
- **clearAllTasks 对运行中任务也留墓碑**：会话结束时运行中任务没有「完成后被清理」的语义，留墓碑会误导成「任务已完成」。
