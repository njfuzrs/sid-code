# skip 档子代理继承工作区外非敏感路径，flag 混淆判据改看「能否构成 flag」

## 决定了什么

两个权限层误拦（会话 `20261103-114056-3b4f9ca7` 复盘 A1/A2）同批改完，同属「只读调研被无谓拦住、多烧轮次」。

**A1：skip 档主会话派生的子代理，不再被 Step 4 拦在工作区外。**

- `permission/sub-agent-checker.ts` 的 live config 新增计算字段 `inheritedFromSkip`：主会话
  `permissionMode === "dangerously-skip-permissions"` 且调用方开启 `inheritBypassMode` 时为 true，
  随主会话切档实时变化（与既有 `permissionMode` / `skipPermissions` 共用同一套 Proxy get trap，
  三处反射路径 get / descriptor / ownKeys 一起改）。
- `permission/checker.ts` Step 4：`pathResult.outsideWorkingDirs === true` 且
  `pathResult.sensitiveFile !== true` 且 `config.inheritedFromSkip === true` 时**不返回拒绝**，
  继续走后面的 Step 5 ask 规则、Step 6 safetyCheck、Step 8 always-allow。
- Step 8 放行时 `decisionReason` 记成 `{ type: "mode", mode: "always-allow", via: "skip-inherit-outside-workdir" }`，
  为此 `permission/types.ts` 的 mode 类型加了可选 `via`。
- `Config` 上加可选字段 `inheritedFromSkip`（只有子代理 live 视图会给出值，主 config 上恒 undefined）。

**A2：`obfuscated-flags` 不再把 `---` 这类分隔符判成 flag 混淆。**

- `permission/bash-security.ts` 第 5 段的判据从 `insideQuote.startsWith("-")` 改为
  `/^-{1,2}[A-Za-z0-9]/`，并且把**引号后紧邻的字符**一起参与判定——bash 的 word 拼接会把
  `"-"exec` 拼成 `-exec`，只看引号内会漏掉这个真绕过形态。
- echo / printf 豁免改为**按子命令**生效：`tool/bash/parser.ts` 新增 `splitShellSubcommands`
  （引号外按 `&&` / `||` / `;` / `|` / `&` 拆、**保留原文**，AST 不适用因为 token 已被 unquote），
  `validateObfuscatedFlags` 逐段扫描，`echo` / `printf` 段整体跳过。

## 放弃了什么（以及为什么不选）

A1：

- **子代理直接继承 `skipPermissions = true`**：那个开关的消费点在 `check()` 最顶端早退，
  排在危险命令 / safetyCheck 之前，复刻过去等于子代理连 `rm -rf /` 都不拦。
  `sub-agent-checker.ts` 的注释里已经否过一次，理由不变。
- **把工作区外检查从 read 上整体拿掉**：会改变 default / always-allow 档的语义，
  `path-validator.ts` 第 6 步注释写明「读也查」是对齐 Claude Code 的有意决定。
- **给 explore 加回 bash**：只读代理的边界靠工具白名单兑现（#538 刚把这件事修对），
  加回 bash 等于又把边界打开，而且会盖掉这次修的动机（子代理原本就是靠 bash 绕过被拒的）。
- **把子代理 cwd 设成目标仓**：多仓调研（本任务 6 个仓）无解，且改变 worktree 语义。

A2：

- **整条规则降为 info / 只记录不拦截**：CC 对标里有对应实现，`find . "-exec"` 是真实绕过，不能拿掉。
- **只做 echo 按子命令豁免**：`sed -n '1,5p' f; "---"` 这种非 echo 的分隔写法仍会误报。
  第 1 条（能否构成 flag）才是根因，第 2 条是配套。
- **只改第 1 条正则，不做子命令拆分**：`echo "-exec"` / `printf -- '--force\n'` 这类
  引号内确实是合法 flag 形态、但属于 echo 参数的命令会继续被拒。两条修法覆盖的命令集不重叠，
  变异自证时已实测：去掉任一条都会留下未覆盖的场景（见下）。
