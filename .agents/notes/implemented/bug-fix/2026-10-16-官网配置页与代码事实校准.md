# 官网配置页与代码事实校准（10 处表述修正）

## 决定了什么

对 `website/start/configure.md` 逐条做「文档 vs 代码」审计后，修正 10 处与当前实现不符、或会让用户照着操作失败的表述（纯文档改动，无代码变更，+22/−14 行）：

1. **auth status 示例**：输出标题实为「模型认证:」（完整输出分三段：`企业登录:` → `企业通道（…）:` → `模型认证:`），原文写的「认证状态:」在全仓与 git 历史中都不存在；并补上网关场景下真实存在的 `⚠ 注意` 行。依据 `packages/cli/src/command/auth.ts:217-243`、`packages/core/src/identity/login-status.ts:102-105`。
2. **openai 协议自动选择**：补全四级优先级——env 强制（最高）→ 模型目录声明 → 非官方端点 → 官方端点 `gpt-5.x` 启发式。原文只写了两档，且把最高优先级的 env 开关只当「回退手段」。依据 `packages/core/src/llm/openai.ts:1407-1436`。
3. **安装脚本默认配置来源**：注明是安装时从发布服务器拉取的 `team-defaults.json`（不随常规发版上传，只能 `--upload-team-defaults` 显式推送）。依据 `scripts/install-template.sh:350-355`、`scripts/release.sh:160-161`。
4. **项目级 settings 限制（新增说明）**：模型相关字段只在用户级生效；两份项目级文件只收行为类字段，写模型配置会被忽略——防「信任前劫持」的刻意设计。依据 `packages/core/src/config/config.ts:1309-1332`。
5. **目录基准表格拆分**：`settings.local.json`/权限规则 → worktree 自己的根；工作区信任 / MCP 审批 / 禁用 / local 作用域 → 主仓根。原文把四类混在一行并统注「按主仓根记」。依据 `packages/core/src/config/project-bases.ts:4-13`、`packages/core/src/config/settings/constants.ts:66-89`。
6. **`mcp add -s project` → `mcp add --scope project`**：CLI 没有 `-s` 短名（`-s` 会被解析成服务器名）。依据 `packages/cli/src/command/mcp-cli.ts:34-37,161`。
7. **snake_case 声明**：「跟团队默认配置一致」说反了——团队默认配置（安装脚本写入那份）用的是 camelCase。依据 `scripts/team-defaults.template.json:8-11`。
8. **手动配置路径注（新增）**：走「其他（手动配置）」会把 `availableModels` 覆盖成单条，不保留模板里的其它模型条目。依据 `packages/cli/src/app.ts:10582`。
9. **model_id 注**：`name` 默认原样发出；条目配了 `model_id` 时，发给厂商的是 `model_id`。依据 `packages/core/src/llm/wire-model.ts`（`resolveWireModel` / `pickWireModel`）。
10. **`/model` 与日志**：`/model` 只在启动时已加载的清单内切换、不重读配置文件（改配置必须重启）；`[FALLBACK] 流式阶段尝试` 是 DEBUG 级，默认审计日志看不到，需 `--debug`。依据 `packages/cli/src/command/commands/model/model.ts:117-127`、`packages/cli/src/app.ts:2362-2464`、`packages/core/src/llm/fallback.ts:1090`、`packages/core/src/debug/logger.ts:93,359`。

## 放弃了什么（以及为什么不选）

- **不改代码，只让文档对齐现状**：审计发现的都是「文档没跟上实现」。唯一可争议的是 `/model` 不重读配置——让 `/model` 支持重载是产品行为变更，超出文档校准范围；先让文档不再误导，产品侧要做另开任务。
- **不动四个地域 / 套餐变体 URL**（GLM Coding、Z.ai、Kimi 国际站、千问新加坡）：仓库内无独立出处、无法从代码核验，保持原样；要对官方文档核验后单独修。
- **不在本页写入代码路径**：保持面向用户的视角；证据留在本 Note 与 PR 描述里，不塞进正文。
- **不扫其它页面**：已 grep 全站确认同类问题只出现在本页（`team/login.md` 对 auth status 的描述与代码一致，无需改）。
