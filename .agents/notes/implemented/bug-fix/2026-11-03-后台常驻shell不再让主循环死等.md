# 后台任务分「在跑」与「值得等」：静默的后台 shell 不再豁免收尾闸门，空闲主循环保证会被唤醒

## 决定了什么

事故 20261103-130950-00ef059c：模型 `run_in_background` 起了一个常驻假服务器，e2e 跑完后 end_turn，
清单还剩 2 项。todo 闸门 T2 判 `unfinished>0 && runningBg` → 放行不续跑，前提是「后台任务完成时通知会把
循环叫醒」。shell 任务只在退出 / 被 kill / 卡在交互提示时入队通知，常驻服务三者都不满足，所以会话静默停住，
面板上一直显示「1 运行中」。

所有「有后台任务就别催 / 别退」的判断都共用一个隐含前提：**它会回报**。子代理 / workflow 满足，后台 shell
不满足。新模块 `packages/core/src/task/background-await.ts` 把这个前提补成两条机制：

1. **等待口径** `hasAwaitedBackgroundTasks`：后台 shell 连续 `SHELL_QUIESCENT_MS`（60s）没有新输出，
   记为静默，不再算「值得等」。下面四个消费方由 `hasRunningBackgroundTasks` 切到这个口径：
   - `loop.ts` 收尾处的 `runningBg`（T2 与 promise-nudge 共用）
   - 停滞阶梯的 `backgroundRunning`
   - `waitForBackgroundNotification`（`-p` 无头等待）
   - stream-json driver 的 `hasRunningBackgroundTasks`（headless-runner 在 stdin 关闭后是否继续等）
2. **唤醒保证**：`queryLoop` 外包一层 `beginMainLoopTurn` / `endMainLoopTurn`。收尾时登记此刻仍值得等的
   后台 shell；之后其中任一转入静默，shell 看门狗（复用停滞检测的 5s tick 与同一个字节数）投一条
   `status=running` 的 `<task-notification>`，把空闲主循环叫醒重判。于是「因为后台任务而放行」之后，
   一定会有下一次唤醒：要么任务退出（已有的完成通知），要么它静默（本次新增）。

面板与 `hasRunningTasks`（Ctrl+F）不变：任务确实在跑，「1 运行中」如实显示。

## 放弃了什么（以及为什么不选）

- **按命令文本识别常驻服务**（`bun run server` / `npm run dev` / `--watch`…）：词表列不全，漏一个就是同样的死等。
  「长时间无输出」是可观测的行为事实，与命令怎么写无关。
- **T2 放行后定时回唤醒（N 分钟一次）**：正在稳定输出的长构建也会被反复叫醒，而且唤醒频率与任务行为无关，
  属于临时折中。改按任务自身的静默事实触发：同一次等待只唤醒一次，且只针对收尾时在等的任务。
- **只改 TUI 文案，提示用户「不会自动继续」**：止住了误导，但会话照样停住，没有修复根因。
- **让 bash 工具多一个 `daemon: true` 声明**：依赖模型主动声明，弱模型不会填。可以作为将来的补充信号，
  但不能当作唯一判据。
- **静默即 kill**：用户 / 模型起的服务可能还要接着用，杀掉是越权。只撤销它的「豁免权」，是否停掉交给模型
  （通知文案提示用 `task_stop`）。

代价（更准 ↔ 更省）：静默但最终会退出的长命令（不打日志的构建、`sleep 600 && …`）会多一次唤醒轮，它退出时
照常有完成通知。

## 拿什么证明它生效了

- 新测试 `packages/core/tests/task/background-await.test.ts`（5 pass）：真实 `spawnShellTask("sleep 30")` 加
  真实看门狗 tick，收尾登记后把静默锚点拨到阈值前，`waitForBackgroundNotification()` 返回 `notification`，
  队列里正好 1 条含 `<status>running</status>` 的通知；之后再等立刻返回 `idle`，不会挂住。
- `packages/core/tests/query/todo-plan-part5-wiring.test.ts` 新增用例：在真实 `queryLoop` 上注册一个已静默的
  后台 shell，断言 `todo_gate_retry > 0` 且 `EndTurnShape.running_background_tasks=false`；原有「后台子代理
  在跑 → 不续跑」的用例保持绿。
- 变异自证（三处各自改坏，各自变红，然后恢复）：
  - M1：`loop.ts` 回退为 `hasRunningBackgroundTasks` → wiring 用例 1 fail
  - M2：看门狗不投静默唤醒 → 端到端用例 1 fail（15s 超时）
  - M3：`waitForBackgroundNotification` 回退口径 → 端到端用例 1 fail
- 端到端真实指标：发版后在轨迹里看 `EndTurnShape.running_background_tasks=true` 且之后无任何主代理事件的
  会话数（本事故形态），应降为 0；静默唤醒的通知可按 summary 文案「不会再自动回报」计数。
