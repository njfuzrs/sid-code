# 纯文本短 end_turn「说了要做却没做」：常驻提示 + 每 prompt 封顶 1 次续跑（S1 / S4 / PR-1）

## 决定了什么

- 新文件 `query/promise-nudge.ts` 只放纯函数：形态判定 `classifyEndTurnShape`、词面消歧 `classifyPromiseText`、续跑决策 `decidePromiseNudge`。只有 `query/loop.ts` 主循环收尾链调用它们，判据**没有**写进 `detectUnansweredEndTurn`，因为子代理以纯文本收尾是正常形态。
- L1 可见性：每次 end_turn 落一条 `EndTurnShape` 事件，字段包括 kind / text_len / prev_turn_had_tool_use / 后台任务与待投递通知，以及 S4 的本 prompt 累计 reasoning_share / 写入数 / 只读数。digest 新增 `short_text_end_turns` / `end_turn_n`，并加一行「疑似静默收尾」带证据指针；session-index 只在 SessionEnd 路径落这两个键，增量路径不落（缺失 ≠ 0）。
- TUI 常驻提示：loop 给 `system` 事件加 `persistent: true`。app.ts 把它写成 hint 历史项，并登记进 `localCommandItems` 侧表，`done` 不会清，全量重建时也不会丢。只对「承诺形」收尾提示，回放里 8 条短完成陈述 / 求助不提示。
- L2 续跑：结构信号全部 AND（end_turn ∧ 无 tool_use ∧ 上一次含 tool_use ∧ 可见文本 ≤ 80 字 ∧ 无运行中后台任务 ∧ 无待投递通知），再加中文词表做二次消歧，命中后注入一条 `promise-nudge` origin 的用户消息。这条消息同时写 `ctxMgr` 和 `sessionStore`，因此 `-c` 恢复后仍在，且 TUI 隐藏。计数器 `promiseNudgeCount` 独立，每 prompt 最多 1 次，工具执行不清零。transition 也独立：`promise_nudge`。英文命中只记 `en_measure_only`，不续跑。`SID_DISABLE_PROMISE_NUDGE=1` 关 L2，L1 照常。
- 验收事件 `PromiseNudge{fired, lang, outcome, skip_reason}`。fired=true 时 outcome 取下一轮的结果（tool_use / text / no_response）；未触发时写明原因（capped / background_running / pending_notifications / disabled / en_measure_only）。

## 放弃了什么（以及为什么不选）

- 复用 `unansweredRetryCount`：它在工具执行时清零、上限 2，复用后会形成「承诺 → nudge → 工具 → 再承诺」循环。
- 按 `output_tokens ≤ 80` 判：OpenAI 族的 output 含 reasoning，「长推理 + 短承诺」会漏判，所以改用可见文本长度。
- 对所有工具后短文本都弹 TUI 提示：回放里 8/9 是正常收尾，每次都弹就是噪声。
- 提示走 `system:transient` 状态条：同一轮 `done` 会清掉它。
