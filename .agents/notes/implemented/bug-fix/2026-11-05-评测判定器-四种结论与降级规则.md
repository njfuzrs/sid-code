# 评测判定器落地：四种结论 + 降级规则，配对对照补上双向题集检查

## 决定了什么

落地方案 T12（`20261003-评测接入CI-CD-分层门禁与基线闭环.md` §6.6 泳道 B）与外部评测缺陷 28。

**新增 `evals/external-benchmarks/harbor/eval-verdict.py`**：把一次 L2 run 判成 §5.2 的四种结论
（`PASS` / `WARN` / `REGRESSION` / `INVALID`），判据全部写死为模块常量：

- `INVALID`：基线不自洽（reward 非二值 / 声明 S 与复算不一致 / 冻结 m 与现算不一致）、
  外部阻断（预算账本 / oracle-nop 预检，由调用方以 `--block` 传入）、指纹非 VALID
  （含 `INCOMPLETE` —— 它是「无法证明一致」，不是通过）、任一题没跑（**双向**）、
  infra 故障率 > 10%；
- `REGRESSION`：稳定必过子集 S′ 中失败题数 ≥ m′；
- `WARN`：S′ 有失败但 < m′、全集配对净回退 > 0、缓存命中率下降 > 10pp、成本上涨 > 30%；
- `PASS`：以上都不满足。

**降级规则按 §7.1 D3 预先登记落进代码**：`|S′| < 6` 时 `REGRESSION` 停用，改用
「S′ 通过率 < 50%」兜底拦截；兜底仍输出 `REGRESSION` + `degraded=true`，不新增第五种结论 ——
下游（T20/T21 的 `release.sh`）只认「阻断 / 放行」，多一个必须记得处理的分支
就是本仓「防线在、调用点漏」的同型。

**新增 `trial_outcomes.py`**：逐题结局（reward + 排除原因）的**唯一取数处**。
`compare-paired.py` 原来的排除判据链整段搬进去（顺序与 `is False` / `is not` 的区分
一字未改），判定器与配对脚本都从它取 —— 两份实现分叉的形态是「同一题一个脚本报 ✅
一个报 ⛔」，`verifier_health.py` 文件头记着这个坑。

**改 `compare-paired.py`（外部评测缺陷 28）**：原来只算 `base − new`，
`new − base`（换档后多出来的题）连一行输出都没有。现在两个方向都报，
默认**拒绝给结论**（rc=2）；`--allow-extra` 只放行 new 独有题（补跑语义下新增题正常），
`base − new` 刻意没有放行开关 —— 那是「尚未跑」，不存在合法的忽略场景。

**改 `run_fingerprint.py` 一行语义**：`VERDICT_RULE_VERSION` 的注释里原来写「T12 落地后
复用这一个常量」，现在真的复用了（`eval-verdict.py` 直接赋值，不另立字符串）。

## 放弃了什么（以及为什么不选）

**不把 `compare-paired.py` 改造判定器**。方案原文给了两个选项（改造它，或新写）。
选新写的理由：两者的输出契约不同 —— 配对脚本要「逐题表 + 均值 + n」，判定器要
「结论 + 可复算的中间量 + 退出码」。塞进一个文件会让 `release.sh` 依赖一个
同时被人当分析工具跑的脚本；而分析工具的正常用法（中途取数、`--allow-extra`）
不应该能改变发布闸门的语义。

**不在判定器里重算 m 之外的统计量**。S 由 `per_task`（k 次逐题 reward）复算，
而不是读基线里声明的 `stable_set` 当唯一来源 —— 声明值与复算不一致时判 `INVALID`。
选这个的理由：基线被手改的形态是「声明的 S 比实际小」，那会把阻断阈值悄悄放宽，
而报告照样漂亮。代价是多一份复算逻辑，收益是「基线可复算」这条纪律真的被执行。

**不用浮点算二项尾概率**。`|S|=10、ε=0.15` 恰好落在边界上（P(X≥4)=0.04997，
离 5% 只有 3e-5），浮点实现的成败取决于累加顺序 —— 同一个基线在两台机器上可能算出
不同的 m，而 m 差 1 就是「阻断」与「放行」的差别。所以 `binomial_tail` 全用
`Fraction` 精确算，并与 T13 冻结的 15 格 m 表逐格对账。

**不在判定器里读预算账本**。账本是 TS 侧 `scripts/eval/lib/eval-budget.ts`（T19）的事；
判定器只消费 `--block "预算账本拒绝…"`。跨语言重复实现一份账本解析，迟早分叉成
两套「这个月还能不能跑」的口径 —— 而那种分叉在两边都自洽，只有对账时才发现。

**不把「成本采不到」当 0 参与判定**。缺成本的题按 0 求和会让 current 偏低，
于是「成本上涨 > 30%」这条判据永远不触发 —— 那是朝放行方向的失真。现在采不到就
记 `unavailable` + caveat，明确写「没触发 WARN 不等于成本没涨」。

**不给 `base − new` 加显式忽略开关**。`new − base` 有（补跑时新增题是正常操作），
`base − new` 没有 —— 后者是「尚未跑」，允许忽略等于允许引用一个中途快照。

## 拿什么证明它生效了

**P2 验收的 6 组人造产物全部判对**（`evals/external-benchmarks/harbor/test-eval-verdict.py`，
81 通过 / 0 失败）：

| 组 | 造的数据 | 断言 |
| --- | --- | --- |
| ① | S 中 3 题失败（\|S\|=8，m=3） | `REGRESSION`，且 `n_prime=8` / `m_prime=3` / `failed` 长度 3 |
| ② | S 中 2 题失败（m−1） | `WARN`，且同时命中「S′ 失败」与「净回退」两条信号 |
| ③ | binary sha256 改一位 | `INVALID`，`differing_fields` 精确等于 `sid_binary_sha256` |
| ④ | current 少一题 | `INVALID`，`invalid_reasons` 点名「尚未跑」 |
| ⑤ | 与基线完全相同 | `PASS`，无失败、无翻转 |
| ⑥ | \|S\|=5 + S 全失败 | `REGRESSION` + `degraded=true`（降级拦截） |

补充覆盖：降级但通过率 60% 不拦截（`WARN`）、`current` 多出题 → `INVALID`、
infra 故障率 12.5% → `INVALID` 而恰好 10% 不判、`--block` → `INVALID`、
基线声明 S / 非二值 reward / `schema_version` / 冻结 m 四种不自洽 → `INVALID`、
缓存下降 → `WARN`、成本上涨 → `WARN`、`total_usd` 按 k 折算（不拿三轮合计比一轮）、
成本缺失不按 0 记账。

**外部缺陷 28 的回归测试**（`test-compare-paired.py`，25 通过 / 0 失败）：
`new` 侧多一道 `t-extra` 时，它必须出现在输出里，且默认 rc=2；
`--allow-extra` 下仍打印但 `n=3` 不含它；`base_only` 没有任何开关能放行。

**变异自证**（判据是红的是哪一条）：
- Python 侧 4 类：删 `if n_fail >= m` 分支 → 结论翻转；`MIN_STABLE_FOR_BLOCKING` 6→5 →
  `degraded` 消失；`stable_set` 恒返回 `[]` → `PASS` 翻转；语法坏掉 → `SyntaxError`。
- TS 侧 5 类：删 `INFRA_FAULT_MAX_RATIO` → 事实缺失；0.10→0.20 → 「等于 0.10」红；
  `VERDICTS` 抠成空集 → 「四种结论齐备」红；`VERDICT_RULE_VERSION` 改成自写字符串 →
  「复用」红；语法坏掉 → checker 非 0 退出。

**TS 侧门禁**（`tests/eval/harbor-eval-verdict.test.ts`，21 pass / 0 fail，无 skip）：
L1 用 stdlib `ast` 锁形态（四种结论闭集、退出码、§5.2 的 6 个阈值、`Fraction` 精确常量、
函数齐备、复用 `trial_outcomes` / `run_fingerprint`），并真跑两个 Python 测试文件。

**门禁**：`bun test tests/eval/harbor-eval-verdict.test.ts`、`bun run fmt`、
`bun run lint`、`bun run typecheck:gate`、`make build` 全绿（详见 PR 正文）。

⚠️ **边界（如实登记）**：本 PR 只证明判定逻辑与配对检查正确，**不证明「基线可比了」** ——
那要等 T15 真跑 k=3、T16 样本外一轮、T17 冻结 S/ε/m。当前 `ε` 缺省按 0.10 取并留 caveat，
基线 `per_task` 的真实格式也由 T15 的生成器负责产出；本 PR 只定义并消费它。
