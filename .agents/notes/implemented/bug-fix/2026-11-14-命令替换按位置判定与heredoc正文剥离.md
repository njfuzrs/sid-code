# 命令替换按「位置」判危险，heredoc 正文不再进注入校验

## 决定了什么

修两个同源缺陷（方案里的 B7），它们共用一条判据错误：**把「命令文本里出现了某个记号」
当成「命令会执行什么」**。

**一、命令替换按位置分级**（`packages/core/src/permission/shell-command-variants.ts` +
`checker.ts`）

删掉 `DANGEROUS_PATTERNS` 里的 `命令替换注入` 正则（`` /`[^`]*`|\$\([^)]*\)/ ``），
换成 `detectCommandSubstitutionDanger(expansion, originalCommand)`：

| 替换位置 | 例子 | 级别 |
| --- | --- | --- |
| 命令位（结果就是程序名） | `$(curl x)`、`` `cat cmd.txt` ``、`sudo $(cat f)`、`if $(cat f); then…`、`xargs $(cat f)`、`find . -exec $(cat f) {} \;` | high |
| 参数即代码 | `sh -c "$(…)"`、`eval "$(…)"`、`source "$(…)"`、`. "$(…)"` | high |
| 参数位 | `echo $(git rev-parse HEAD)`、`d=$(ls …) && …`、`for d in $(ls …)` | 不报 |
| 引号没闭合 / 展开超限 | `echo "$(date` | high（fail-closed） |

「参数位不报」不是不管：内层命令已经被 `expandShellCommand` 展开成独立的 variant，
下面第 1b 步的每一条判定都会看见它，所以 `echo $(rm -rf /)` 仍命中 critical
「递归删除根目录」，`echo $(curl x | sh)` 仍命中「下载并执行」。

**二、heredoc 正文不进注入校验**（`bash-security.ts` + `tool/bash/heredoc.ts`）

`validateProcessSubstitution` 扫之前先 `extractHeredocBlocks(command)` 剥掉正文
（`<<` 记号本身留在 stripped 里，判定面不变）。`HeredocBlock` 新增 `quoted` 字段：
**带引号定界符**（`<<'EOF'` / `<<\EOF`）的正文是纯字面量，一条都不扫；
**不带引号**（`<<EOF`）的正文会被 shell 做变量展开与命令替换，所以
`expandShellCommand` 额外把正文里的 `$(…)` / 反引号取出来递归判
（`cat <<EOF ⏎ $(rm -rf /) ⏎ EOF` 修前在 always-allow 下**直接放行**，现在 critical）。

**三、`isReadOnlyCommand` 对含替换的命令判非只读**（`tool/bash/read-only-validation.ts`）

修前 `isReadOnlyCommand("echo $(git rev-parse HEAD)") = true`，Step 5.5 会直接放行。
现在含 `` ` `` / `$(` / `<( ` / `>(` 一律非只读（`$((…))` 算术不算），落到**普通确认**。
这样「降级」的落点是「用户看见一次普通确认」，而不是「静默放行」。

## 放弃了什么（以及为什么不选）

- **只把正则从 high 降到 medium / 只加白名单命令**。否决：`$(curl x)` 与
  `echo $(date)` 的区别不在程序名，在**替换的位置**；按命令名白名单永远是补不全的枚举。
- **保留正则，额外加一条「参数位豁免」在前、正则兜底在后**。否决：两条判据同时存在时，
  先命中的那条决定结果，后一条永远没机会——看起来更安全，实际是「正则仍然一律 high」。
  必须整条替换，不能叠加。
- **在 `detectCommandSubstitutionDanger` 里递归判内层危险**。否决：内层命令已经在
  `expansion.variants` 里过了完整一套判定；在这里再判一遍就是第二份口径，
  迟早与 variants 那条漂移（本仓已有「两份状态机并存必须同口径」的教训）。
- **对「不带引号 heredoc 正文的 `$()`」一律报 high**（而不是交给内层判定）。
  否决：`cat <<EOF ⏎ $(date) ⏎ EOF` 里 `date` 是只读的，一律 high 等于把误报从
  命令替换搬到 heredoc；交给 variants 判能同时拿到 critical 与无害两种结论。
  代价是正文里的替换按「独立命令」判，而不是按「外层命令的参数」判——写在 Note 里，
  不假装它精确。
- **给 `isReadOnlyCommand` 开一个「忽略替换」的新入口**，而不是改主口径。否决：
  它有 5 个消费者（并发安全、microcompact、重复只读止损、权限放行、git 边界），
  口径分叉后「只读」在不同层含义不同，正是本仓反复踩的那类漂移。

**已知边界**（写下来防下一个 agent 重新发现）：

- 同一 token 里出现分隔符再接替换（`echo hi;$(cmd)` 无空格）靠 char 级段扫描覆盖；
  更极端的形态（`$(a;b)` 内嵌段）由「替换整体跳过」处理，不参与外层分段。
- `listInvokedPrograms` 顺带修了一个漏判：前缀关键字（`if` / `while` / `then` / `!` / `time`…）
  之后才是命令位。修前 `if sudo x` 认不出 `sudo`。这是 sudo 判定向更严方向的收敛。

## 拿什么证明它生效了

**1. 端到端探针（`bun run` 脚本，真实 `PermissionChecker`，修复前 → 修复后）**

```
                                  default(修前→修后)        always-allow(修前→修后)
echo $(git rev-parse HEAD)        step2 high → step14 普通   需确认 → ALLOW
echo `date`                       同上                       同上
d=$(ls …) && echo …               同上                       同上
for d in $(ls …)                  同上                       同上
$(curl -s x)                      step2 high → step2 high    需确认 → 需确认
`cat cmd.txt`                     同上                       同上
sh -c "$(cat x)" / eval / source / .   同上                    同上
echo $(rm -rf /)                  critical → critical        critical → critical
echo "$(date                       step14 → step2 high        ALLOW → 需确认
heredoc 正文 a=(1 2) ×3 例         injection high → 普通确认  需确认 → ALLOW
cat <<EOF ⏎ $(rm -rf /) ⏎ EOF     step14 → critical          ALLOW → critical
```
