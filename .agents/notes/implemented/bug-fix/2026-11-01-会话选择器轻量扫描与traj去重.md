# 会话列表改走轻量扫描器、恢复巨型会话前可见提示、traj 的 user_prompts 不再复制巨型输入

## 决定了什么

对应方案文档的 PR-E（R1、R2）与 PR-F（R3），合成一个 PR：三项都是「巨型会话把非启动路径拖垮」这一个关注点，而且都能各自回滚。

- **R1**：会话列表（`/resume` 选择器、`-r` 选择器、`--list-sessions`、`-r <id>` 解析 id 走的 `SessionSelector.listSessions`）
  从 `getSessionFiles` 改为 `light-scan.ts` 新增的 `lightListSessions`。
  - ≤1MB 的文件仍走 `buildSessionFileEntry`，与全量版逐字段一致，搜索时也照常加载正文。
  - 更大的文件复用 PR-B 的流式回放。标题只取短行（≤64KB，回放时本来就会 parse）里的 session_name / summary / 首条用户消息；
    首条是巨型行时显示 `（首条消息内容过大）`，不为一个标题去读全文。
    巨型行如果以 `tool_result` 块开头，就认定为工具回传、不能当标题（实测 2/517 个会话需要这条，不加就会多出 2 个占位标题）。
  - 选择器搜索（`includeFullContent`）对 >1MB 的会话只按标题和 id 命中，不加载正文。
    `-r` 选择器一进来就是搜索模式，旧实现等于每次打开都把全部会话整份 parse 两遍。
  - `finalizeSessionList`（过滤 / 去重 / 排序 / 编号）与 `isTitleCandidateMessage`（标题候选规则）从 utils.ts 导出、两条路径共用，列表口径只有一处。
- **R2**：`-r` / 选择器恢复会话前先 `stat`。≥50MB 时在 stderr 打出「体积 + 预计耗时 + Ctrl+C 取消」，加载完在 TTY 上擦掉这一行。
  选择器路径上 early-input 已经停止捕获，raw 模式下 Ctrl+C 不产生 SIGINT，所以加载窗口内补了一个 stdin 监听，保证提示里说的「可取消」是真的。
  加载本身的流式化不在范围内（方案 4.7）。`-p` 不提示。
- **R3**：`metadata.user_prompts` 每条截到 8K 字符，末尾注明原长和「全文见 history」。字段和 `string[]` 类型都不变，旧 traj 照常可读。

## 放弃了什么（以及为什么不选）

- **R3 改成「引用 / 只存摘要」或删掉字段**：方案原话是「metadata 不再存 history 的全量副本」。
  实测副本只来自 `user_prompts` 一个字段（445MB 的 traj 里 metadata 有 177.9MB，`user_prompts` 占 177.86MB）。
  读方 digest 只截取前 160/300 字，`scripts/verify-hypothesis-guide.ts` 读首条做判据，都只需要前缀。
  删字段或改结构会破坏格式契约，读方要写两套分支。截断前缀能达到同样的减半效果，契约不动。
- **R3 用「history 下标引用」代替文本**：history 里的 user 条目是首轮请求和后续增量消息，和 UserPromptSubmit 的次序不是一一对应（含工具结果、注入），下标对不上。
- **R1 列表复用全量扫描器再加缓存**：缓存要处理失效，而且首次打开照样整份 parse；轻量回放已经存在（PR-B），判据同源。
- **R1 巨型首条读前 N KB 拼标题**：要在 JSON 字符串中间截断再解码转义，复杂度和出错面都不值。只影响 2 个会话的标题，占位就够了。
- **R2 弹确认框（是否继续）**：多一次交互，而大多数时候用户就是要恢复它。可见 + 可取消已经满足「不静默卡住」。

## 拿什么证明它生效了

真实 `~/.sid-code`（517 个有效会话，最大一个 222MB）：

- 列表一致性：`getSessionFiles` vs `lightListSessions` 对比 id / index / 时间 / 消息数 / displayName / firstUserMessage / summary / cwd / model / dirPath，**517/517 一致，diff 0**。加 tool_result 判别前 diff 2。
- 列表耗时与内存（源码版，各跑 2 次）：全量 725–830ms、RSS 1243–1353MB；轻量 388–413ms、RSS 173–233MB。搜索模式（includeFullContent）同量级。
- `--list-sessions` 二进制：旧 `sid-code-dev` 0.90s / 最大 RSS 1.31GB；本分支 `make build` 产物 0.50–0.74s / 196–243MB。
  方案验收「选择器打开 < 500ms」：暖缓存时满足（~400ms），冷缓存首次 ~700ms。
- R3：把 445MB 那份 traj 的 `user_prompts` 套上截断后重新序列化，445,209,370 → 223,720,266 字节，比例 0.503。
- 变异自证（改坏 → 断言变红 → 恢复）：占位改成「跳过巨型行」红 4 条；撤回不弹 titles 红 1 条；collector 不截断红 1 条；关掉 tool_result 判别红 1 条。
- 单测：`packages/core/tests/session/` 278+ 全绿，含 PR-B 的判删对照测试（轻量 ↔ 全量判定逐条一致）。
