# digest「原地打转」改按完整入参判，异常按判据计数

## 决定了什么

改动在 `packages/core/src/trace/digest.ts` 和 `collector.ts`，只改事后判读与 summary 字段。

- **`repeated_tool_shape_run`（L0）**：判据不变（工具名 + 首个参数片段连续 ≥ 4 次），严重度上限从 high 降为 medium。形状太粗，30+ 次也可能是 30 条不同命令，所以不能凭它给 high。
- **`hypothesis_stuck_loop`（L1）**：不再跟着形状段推。新增导出函数 `maxIdenticalCallRun`，同一完整指纹（`tool + stableStringify(tool_input)`）连续 ≥ 3 次才推。1 秒内同指纹视为并行派发跳过。
  - 段内返回值在变，或返回值含进行中状态（pending / in_progress / running / 仍在运行 等），判为轮询：low，≥ 10 次 medium。
  - 否则判为打转：medium，≥ 10 次 high。
  - 进行中状态匹配原始文本，不匹配 JSON 序列化后的文本。序列化会把制表符变成字面量 `\t`，`gh pr checks` 的 `…\tpending\t…` 就匹配不上了，验收时实测踩到。
- **判据 id**：`Anomaly` 加 `criterion`。新增导出表 `ANOMALY_CRITERION`，把 8 组成对推入的 L0 / L1 映射到同一 id，`buildDigest` 排序前统一填写，未登记的等于 kind。summary 新增 `anomaly_criteria`（按判据去重），`anomalies[]` 里与 kind 不同的才写 `criterion`。`anomaly_kinds` 保留不动。

## 放弃了什么（以及为什么不选）

- **复用运行时侧 `loop-detection.ts` 的 `shapeKey`**：离线重放 158 次命中只降到 115 次。bash 的 shapeKey 是 `keys=[command,description]`，不含命令内容。
- **要求 `observation_entropy_zero` 同时成立**：轮询时状态没变，返回值本来就相同，会把合法轮询判成空转。
- **轮询完全豁免**：轮询本身可能是该用后台任务完成通知却在空等（复核样本 84f153dd：后台测试跑着，模型轮询 29 次），所以降级不删。
- **改动 `anomaly_kinds` 的语义**：旧脚本按 kind 读，改了会静默变数。新开字段。
- **在推入处手写 criterion**：38 处推入，漏写一处就回到按 kind 计。改成集中登记表，加源码扫描测试兜底。
