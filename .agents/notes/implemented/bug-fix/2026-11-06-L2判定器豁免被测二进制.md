# L2 判定器的指纹比对豁免被测二进制，否则每个新 beta 都判 INVALID

对应《评测接入 CI/CD》§6.6「T17 前待决项」Q-A，是 T20 发版闸的前置。

## 决定了什么

`run_fingerprint.compare()` 新增关键字参数 `under_test: tuple[str, ...] = ()`：

- 列在里面的字段，「值不同」不进 `diffs`，改记到新返回字段 `under_test_diffs`；
- **单边缺失、两边都缺照常判**（INVALID / INCOMPLETE）—— 裁决必须说得清测的是哪一版；
- 传入 `FIELDS` 之外的键直接 `ValueError`；
- 缺省为空，T11 / T16 的「两次 run 全字段严格相等」用法不变。

`eval-verdict.py` 新增常量 `UNDER_TEST_FIELDS = ("sid_binary_sha256", "sid_commit")`，
基线 vs 当前 run 的那一次比对传进去。补跑合并时 run 之间的比对仍是严格模式（同一版二进制）。

根因：L2 比的就是「新二进制 vs 基线」，二进制 sha / commit 不同是前提。原实现把它当配置漂移，
`test-eval-verdict.py` 的验收 ③ 还恰好用「sha 不同」造指纹差异并断言 INVALID ——
测试把这个缺陷固化成了预期行为。

## 放弃了什么（以及为什么不选）

- **基线指纹里把 sha 置空**：会变成「单边缺失 → INVALID」，或者要再给缺失开豁免，
  后者会让「当前侧没采到 sha」也被放行 —— 那正是不能放的形态。
- **在判定器里比对前把两侧的 sha 删掉**：等价于豁免缺失，同上；而且 `under_test_diffs`
  里看不到这次测的是哪两版。
- **把豁免范围放宽到 `harbor_version` 等**：那些变了结果就不能比，必须重建基线（§3.4）。

## 拿什么证明它生效了

- `python3 evals/external-benchmarks/harbor/test-eval-verdict.py` → `通过 87 / 失败 0`。
  验收 ③ 改为用 `model_id` 造差异；新增 ⑬ 组：新二进制 + 同结果 → PASS；
  新二进制 + S 掉 3 题 → REGRESSION；当前侧缺 sha → INVALID；新二进制 + 换模型 → 只点名 `model_id`。
- `python3 evals/external-benchmarks/harbor/test-run-fingerprint.py` → `通过 62 / 失败 0`（新增 ⑭ 组 5 条）。
- 变异自证：在 tmpdir 副本里把 `under_test=UNDER_TEST_FIELDS` 删掉，⑬ 组 5 条变红（`通过 82 / 失败 5`）。
