# 子代理工具结果走 processToolResult 落盘（D9）

来源：`docs-research/sid-code/bugfixes/todo/20260920-工具调用层-写入门文档时核出的缺陷.md` 的 D1 + D9。建议「同 PR」；D1（分区 + 并发上限）已由 #73 合入，本 PR 只补 D9 仍活着的半截。

## 决定了什么

子代理两条执行路径不再 `ContextManager.truncateToolOutput`（只截断、原文丢掉），改调主循环同一份 `processToolResult`：

1. **进程内** `agent/tool-executor.ts`：`executeTools` 多一个可选 `sessionId`，`runAgentLoop` 从 `ctxMgr.getSessionId()` 传入（与 masking 派生 id 同源）。
2. **spawn** `executeToolForChild`：父进程执行工具时同样落盘，带 `msg.id` + `deriveSubAgentSessionId(taskId)`。
3. 阈值、`read` 的 Infinity 豁免、`maxResultSizeChars` 优先于常量表，全部复用 `result-storage.ts`，不在子代理再抄一份截断。
4. `ContextManager.getSessionId()` 补上，避免执行器伸进私有字段。

## 放弃了什么（以及为什么不选）

- **在子代理再写一份 truncate+save**：正是 D1–D9 的共同根因——主循环漂一次子代理再漂。落盘路径、摘要文案、read 豁免必须同一处。
- **本 PR 重做 D1 分区**：`executeTools` 已经走 `partitionToolCalls` + `getMaxToolConcurrency()`（#73），再改是空 diff。D9 文档里「并发上限随 D1 一起消失」那半截已经落地。
- **把 spawn 路径留给下一 PR**：工具在父进程执行，截断丢掉原文的形态与进程内完全一样；只接 `executeTools` 会留下「走 spawn 的自定义子代理」那条口子。
- **给 executeTools 换成 options 对象**：现有调用全是位置参数，本 PR 只加一个可选尾参，不顺手改契约。
