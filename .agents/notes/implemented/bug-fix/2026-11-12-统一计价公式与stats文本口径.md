# 计价公式收成一份，`/stats text` 的 token 补千分位与口径

## 决定了什么

**D20：两条计价入口合并到唯一实现。**

- `packages/core/src/api/cost-tracker.ts`：新增 `calculateCostBreakdown(model, usage, availableModels?, provider?, baseURL?, at?)`，
  返回四项费用（未命中 / 命中 / 写入 / 输出）+ `totalUSD` + `source`（`pricing` / `fallback` / `local`）。
  `calculateUSDCost` 改为只对它取合计。
- `packages/core/src/session/state.ts`：`SessionState.calculateCost` 同样只调 `calculateCostBreakdown`，
  自己只保留「按模型推断 provider」和「未知模型按模型去重告警」两件事。
  兜底告警的判据改成 `breakdown.source === "fallback"`，不再自己 `resolvePricing` 一次。
- 本地 provider 判断从 `SessionState.isLocalProvider` 的私有实现移到
  `packages/core/src/llm/provider-infer.ts` 的 `isLocalProvider`（`SessionState` 的静态方法改为委托），
  `calculateCostBreakdown` 内部调用它 —— 这补上了 `calculateUSDCost` 此前缺失的本地判断。
- 兜底价只留一份：`cost-tracker.ts` 的 `FALLBACK_PRICING` 改为导出，删除 `SessionState.FALLBACK_PRICING`；
  `calculateSavings` 与告警文案都引用导出的那一份。

**D19：`/stats text` 的 token 数加千分位并标口径。**

- `packages/cli/src/command/commands/stats/stats.ts`：`fmtTok` 用与 `/debug` 相同的
  `toLocaleString("en-US")`；`Token 用量` 行标 `（累计发送，flow）` / `（累计）`；
  新增 `当前上下文（stock）` 行并点明「状态栏 ↑ 同一口径」。
- 官网 `website/use/sessions.md`：`/stats text` 示例输出同步新版式，补一段说明 flow 与 stock
  是两个不同口径、两者必然不等。

## 放弃了什么（以及为什么不选）

- **没有删 `CostTracker`**。方案文档明确把它归为后续独立的 `refactor` PR（D20 后半），
  本次只做「合并公式」；删类会改变 `packages/core/tests/api/cost-tracker.test.ts` 的存在理由，
  混进来会让这个 PR 的回滚面变大。
- **没有顺手给 `/cost` 的 token 加千分位**。那属于 D5（`/cost` 三段拆分 + 千分位）的范围，
  本次不动 `/cost`，避免与 PR-B 的版式重做冲突；`/stats text` 是 D19 自己的交付面。
- **没有把 `/stats text` 改成读 `buildCostReport`**。方案里那是 PR-B 的数据层重做（D11–D15），
  本次没有 `buildCostReport`，硬引会变成半成品。这里只做格式化与口径标注。
- **没有在 `SessionState.calculateCost` 里再判一次本地 provider**。判据留在
  `calculateCostBreakdown` 里，两条入口共用；再写一次就回到了「两处判据会漂移」的老问题。
- **没有把 `source` 做成 `pricingTier` 之类的细分枚举**。D11 要的分时段展示还没做，
  现在多造字段没有消费方；三项（pricing / fallback / local）已经够本 PR 的告警与测试用。
