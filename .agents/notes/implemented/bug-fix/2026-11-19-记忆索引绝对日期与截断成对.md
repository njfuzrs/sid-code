# 记忆索引改绝对日期 + 截断不残缺：读者要能回答「这是什么时候的」

## 决定了什么

两处都是**注入 system prompt 的那一份索引**的形态变化：

1. `memory/freshness.ts` 的 `memoryAge()` 由 `today` / `yesterday` / `N days ago`
   改为 `YYYY-MM-DD（N 天前）`（`days<=0` → `（今天）`、`days==1` → `（昨天）`）。
   原来的相对日期在一份冻结的索引里没有参照点：读到「3 days ago」的模型和读到它的
   真人，都无法回答「对应哪个绝对日期」。用户机器上实测 146 天前的条目仍在注入，
   而「146 天前」只有配上绝对日期才可回溯。
2. `memory/index-budget.ts` 的 `truncateIndexDesc()` 截断时补 `…`，并在超长且反引号
   未闭合、且落在**后半段**时退到反引号之前。补 `…` 是为了让读者分辨「原文就到这里」
   与「后面还有」（旧实现切在冒号上时看起来像一句完整的话）；退反引号是为了避免
   索引进 prompt 被 Markdown 解析时，半个代码片段和同段别的反引号错配、把大段正常
   文本吞进 inline code。

## 放弃了什么（以及为什么不选）

- **保留相对日期、只在文件头加一行「今天是什么日子」**：索引是冻结的，文件头的日期
  与它的生成时刻绑定，读到的人还是没法换算；且多一行就多占 25KB 预算。
- **让反引号落在任何位置都退回**：位置靠前时退回会把描述砍掉一半以上，条目失去信息量。
  只对 `lastTick > cut / 2`（后半段）退回，代价是位置很靠前时仍留半个片段——
  这一条刻意保留，并用「太靠前就不退」的用例锁住。
- **截断时直接砍掉所有反引号**：会把正常的行内代码标识符一起删掉，比半个片段更糟。

## 拿什么证明它生效了

- `bun test packages/core/tests/memory/`（整目录）→ 523 pass / 0 fail；
  其中 `freshness.test.ts` 新增 5 条：文档验收示例 `2026-06-26（146 天前）` 精确匹配、
  不含 `days ago`/`today`/`yesterday`、`days<=0` 不出现负天数、日期取记忆自身而非 now。
- 变异自证（D-18）：删掉 `+ "…"` → 6 个用例红；把退回判据改成 `false` → 反引号未闭合
  那条红（Expected 0 / Received 1）。
- 变异自证（D-12）：`memoryAge` 改回旧实现 → 6 条红（freshness 5 + paths-scan 1）。
- `bun run affected-tests` 选测三批共 10701 pass / 0 fail，含 memory 与 tool 两侧
  消费 `memoryAge` 的路径（`store.ts`、`team/store.ts`、`read-memory-freshness`）。
- `⏳` 只标最旧约 30% 的性质未变：本次只换括号内的格式，没有改「每轮标注量恒定」的口径。
