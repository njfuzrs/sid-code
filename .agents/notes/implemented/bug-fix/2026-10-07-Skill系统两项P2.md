# 修复 Skill 系统两项 P2：MCP discovery 字段映射收敛、安全白名单 fail-safe 方向

## 决定了什么

来源：`20260927-Skill系统-顺着sc-10-skills核出的缺陷` 的 P2-1 / P2-2（P0 见 #127、P1 见 #131）。

- **P2-1**：frontmatter → SkillDefinition 的来源无关字段映射抽成 `loader.ts` 导出的
  `parseSkillFrontmatterFields(fm)`，loader 与 `mcp/skill-discovery.ts` 共用。MCP 侧只覆盖
  `name`（带 server 前缀）/ `description` / `source` / `loadedFrom` / `filePath`，并显式把
  `hooks` / `shell` / `skillRoot` 置 undefined（executor 拒 MCP hooks、prompt-processor 禁 MCP
  内联 shell，解析了也用不上）。未声明 context/mode 时保持 MCP 历史默认 `inline`。
  `disabled: true` 与 loader 同语义跳过。
- **P2-1 连带**：MCP skill 开始解析 `paths` 后，迟到 skill 不经 `init()`，会在 MCP 路径重现
  P0-6。新增 `SkillActivationCoordinator.gateLateConditionalSkills()`，`cli.ts` 在
  `addPluginSkills` 之前调用；之后 `enqueueListingForNewSkills` 按 `isGated` 跳过它们，
  碰到匹配文件时走既有条件激活路径。
- **P2-2**：`permission.ts` 改成单张 `Record<keyof SkillDefinition, "safe" | "sensitive">`
  分级表，`SAFE_SKILL_PROPERTIES` 由它派生；`skillHasOnlySafeProperties` 改为遍历 skill
  **自身全部属性**、按白名单判定——未分类的新属性有值即需审批（此前只遍历敏感表，新属性默认放行，
  与文件头注释方向相反）。

## 放弃了什么（以及为什么不选）

- **P2-1 让 MCP 直接走 `SkillLoader.buildSkillDefinition`**：它绑定 `ParsedExtensionFile`
  （本地路径、`dirname` 算 skillRoot、名称 sanitize 会把 `server:name` 的冒号改成 `-`），
  MCP 资源三条都不适用。只共享字段映射是最小且不改既有行为的切分。
- **P2-1 MCP 带 paths 的 skill 不 gate、直接进 listing**：等于把 P0-6 修过的门在另一条入口拆掉。
- **P2-2 只加文档建议的类型体操 `_Exhaustive`**：CI 刻意不跑 `tsc --noEmit`，纯类型约束在本仓
  不构成门禁。`Record<keyof ...>` 保留编译期缺键报错（对跑 tsc 的人有效），再加一条测试从
  `types.ts` 源码抽字段名与分级表比对，作为 CI 里真正会红的那道。
