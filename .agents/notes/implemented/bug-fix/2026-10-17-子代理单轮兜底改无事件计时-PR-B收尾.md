# 子代理单轮兜底改为「无事件」计时，并补齐 PR-B 遗漏项

## 决定了什么

PR-B（#322）review 后发现的问题全部在此修复：

- **单轮兜底从「总耗时」改为「连续无流事件」计时**（`agent/turn-hard-timeout.ts` 新增 `tapStreamActivity`，
  agentic-loop 主轮 / 总结轮、headless 子进程三处接入）。PR-B 初版按本轮总耗时计 90min，而漏斗在路由挂掉时
  自己会重试 10 × 600s ≈ 110min ——兜底会打断仍在正常重试的漏斗再起一组 10 次，两层相乘，最坏 ≈ 11 × 90min。
  它要防的「abort 链路失效」指纹是**一个事件都收不到**；漏斗只要活着，600s 内必然 abort → 重试 → 发事件。
  改后两层不再相乘，最坏耗时回到方案 §6.5 的 ≈ 100min 量级。阈值仍是主循环同一个 `maxTurnDurationMs`。
- **删除 `LIFECYCLE_PRESETS.subAgent`**：PR-B 后它唯一的生产读者是 side-call 缺省值，名字与读者错位。
  `DEFAULT_SIDE_STREAM_TIMEOUT_MS` 改为 `resilient-stream.ts` 自有常量 180s（行为不变）。
- **删除 `"agent-stream-timeout"` abort reason** 与 `AGENT_STREAM_TIMEOUT_REASON`：src 零调用点。
- **内置 skill 一律不声明 maxTurns**：`simplify` 30、`review` 30、`verify` 20 都是 S4b 漏网
  （PR-B 提交说明写「review 不再声明」，实际只删了 `timeoutMins`）。加源码哨兵锁住 `bundled/*.ts`。
- **后台 fork 的轮次上限按轨迹逐个定**（`runForkedAgent` 的 `maxTurns` 改为可选，省略即 `Infinity`，对齐 CC）：

  | 调用方 | 原上限 | 轨迹（本机 261 会话，按 60s 间隔切 run） | 处理 |
  | --- | --- | --- | --- |
  | session-memory | 5 | 166 次 run，**65 次（39%）恰好停在 5 轮**，0 次超过 → 是被截断，不是自然收尾 | **删上限**（CC 也不设）+ 提示词补「所有 Edit 一条消息并行发出、发完即停」（CC 原话） |
  | auto-dream | 10 | 0 次 run，无数据 | **删上限**（CC autoDream 不设）；巩固要逐条处理，条目多时 10 轮不够 |
  | memory-extract | 5 | 207 次 run，p95=3、max=6，撞线 2 次（1%） | 保留 5（CC 同值，原注释「正常 2–4 轮」与数据一致） |
  | `/btw` | 1 | 0 次 run | 保留 1（CC 同值；该功能禁用一切工具，1 轮即一次问答，不存在截断） |
  | `/goal` | 150 | 0 次 `turns_limited` | 不动：它是主循环的目标预算、不是子代理；默认无 token 预算时它是唯一硬顶，可 `/goal turns <n>` 调整 |

  后台 fork 仍有各自的 `timeoutMs`（60s / 120s），去掉轮数不会让它们无限跑。
- **S5 回收改为等待收尾**：`abortAllAgentTasks` 等每个被 abort 的子代理进入终态（上限 2s），
  pre-flush 钩子 await 它，`SubagentStop` 不再被 flush 阶段越过。核实过 `--print` / stream-json /
  bridge / TUI 四个出口都调 `runShutdownSequence`。
- **过时注释与哨兵**：`sub-agent.ts` 的超时分工注释改写为现状；两个哨兵从断言「180s」改为断言
  「子代理给漏斗传的是 `fallbackStreamTimeoutMs`」（顺带补上方案 T7）。

**§8 第 6 条裁决：选 (b)，接受无人值守零防空转。** 官网 subagents 页写明「无人值守请在外层自设超时」。
理由：0 例已证实的子代理空转；循环检测已有因 shape 假阳性被默认关掉的前科，再加一个检测器大概率重蹈覆辙。
**重开条件**：§8 第 7 条（那 8 例停在 30 轮的子代理）核出真实空转，届时只做严格相等判据
（同工具 + 同输入 + 同输出连续 N 次 → 强制总结），不做 shape 匹配。

## 放弃了什么（以及为什么不选）

| 方案 | 为什么不选 |
| --- | --- |
| 兜底保持总耗时口径，只把阈值调大到 > 110min | 仍是「过了多久」判据；漏斗重试次数或退避一改，相乘关系又回来 |
| 兜底触发时不计入 `retryStats` | 计数会漏掉真实发生的重发，「这个子代理一共重试了几次」答不准 |
| 主循环 `query/loop.ts` turn_hard 同批改成无事件口径 | 主循环风险更高、调用链更深；先在子代理上 beta 验证，再单独开 PR 搬过去（另开 issue） |
| 现在就上「无进展检测」 | 见上方 §8 第 6 条裁决 |
| `abortAllAgentTasks` 不等待、只 abort | `SubagentStop` 是异步 hook，pre-flush 之后就是 flush，不等即大概率丢 |
