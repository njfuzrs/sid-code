# macOS CI 反复红的两个根因：任务输出落盘的未处理拒绝 + useKeypress 订阅晚于帧可见

## 决定了什么

2026-11-11 main（492fcc86 / a1575d48 / 6ecfbad4 三次 push）与 PR #745、#746 的 macOS 分片
反复红，重跑仍红。归因为两个**生产代码**缺陷，不是测试超时不够：

1. **`packages/core/src/task/disk-output.ts` `#drain()` 会 reject，而它是 `append()` 发起、无人 await 的后台 promise。**
   写入失败（目录被删 / 磁盘满 / 权限）就成了未处理拒绝：
   - 生产：CLI 全局 `unhandledRejection` 兜底对非 abort 错误 `process.exit(1)`，
     一次「取证日志写不进去」就能带走整个会话（违背 monitor 的 T-M1-12「落盘失败不影响任务」）。
   - 测试：`monitor-task.test.ts` 的 afterEach 恢复 `SID_CONFIG_DIR` 并删 tmpdir 时，上一个用例
     子进程的迟到 stdout 还在 append → ENOENT。bun 把它记为「Unhandled error between tests」
     判红**当前**用例，而被判红用例的 async 体仍在后台跑，它的 `waitFor` 抢走下一个用例的通知，
     于是一处 ENOENT 连锁成 2–3 条看似无关的失败（T-M1-11 收到别人的「监控到期」、T-M1-6/T-M1-7
     等 3000ms 超时、D5 用例红）。五次失败日志里**每一次**都有同一条 `ENOENT ... tasks/<id>.output`。
   修法：`#drain` 整体 try/catch，失败时丢弃本批、同一实例只 warn 一次，永不 reject。

2. **`packages/cli/src/ui/contexts/KeypressContext.tsx` `useKeypress` 用 `useEffect` 订阅。**
   渲染器在 commit 阶段就把帧写出，passive effect 推迟到后续宏任务；其间到达的按键被 broadcast
   给空订阅表，静默丢失。PR #746 的 `PluginsDialog`「面板整帧」用例就是：看到列表帧立即按 Enter，
   帧一直停在列表。用户侧同样存在：对话框刚弹出时的预输入被吃。
   修法：改为 `useLayoutEffect`（在 commit 阶段同步订阅，与帧写出同一时刻生效）。

## 放弃了什么（以及为什么不选）

- **调大 `waitFor` 超时 / 给 afterEach 加 sleep**：前一个 agent 的判断（「慢 runner 3 秒不够」）
  是把连锁失败的**症状**当根因。超时用例失败于 3005ms 是因为它等的通知被上一个失控用例抢了，
  多等多久都等不到；sleep 只是缩小窗口，生产里的 `process.exit(1)` 风险原样还在。
- **在测试 afterEach 里先 flush 所有输出再删目录**：只修测试，生产缺陷保留；而且子进程被 SIGKILL
  后 stdout 管道里剩余的 data 事件仍可能在 flush 之后到达，窗口关不死。
- **`#drain` 的 mkdir 改成 `dirname(filePath)` 让它自愈**：会在测试里把已删除的 tmpdir 重新建出来
  （泄漏临时目录），且对磁盘满 / 权限错误无效。保留原有 `mkdir(getOutputDir())` 语义不动。
- **PluginsDialog 测试在首帧后加固定等待**：同上，掩盖的是真实的输入丢失。
- **重跑失败 job**：#745 连续两次 attempt 都红，main 当天红了 3 次，不是低概率 flake。

## 拿什么证明它生效了

- 复现 ①：独立脚本 initTaskOutput → 切 `SID_CONFIG_DIR` → 删旧目录 → append，修复前输出
  `UNHANDLED: ENOENT ...`，即 CI 日志里的同一条错误。
- 回归 ①：`disk-output-dir-ready.test.ts` 新增「落盘失败不产生未处理拒绝，flush 也不抛」。
  变异自证：在 catch 里加 `throw err` → 该用例红（报 ENOENT），恢复后 5 pass / 0 fail。
- 复现 ②：PluginsDialog 测试把首帧等待改为 setImmediate 轮询（压窄窗口），原代码 3/3 红；
  仅把 useKeypress 改 useLayoutEffect 后通过。
- 回归 ②：新增 `packages/cli/tests/ui/contexts/keypress-subscribe-timing.test.tsx`
  （订阅者在异步更新后挂载，帧一出现立刻按 Enter）。变异自证：改回 useEffect → 5/5 红
  （`Expected to contain: "已按下"`），修复后 5/5 绿。
- `bun test ./packages/core/tests/task/` 连跑 3 次 374 pass / 0 fail；
  `bun run affected-tests:run`（cli 全包 + core task 域，CI 等价 env）3478 pass / 0 fail；
  typecheck:gate 无新增、lint / format:check / make build 通过。
- 最终判据是合入后 macOS 分片不再出现 `ENOENT ... tasks/<id>.output` 与「Unhandled error between tests」。
