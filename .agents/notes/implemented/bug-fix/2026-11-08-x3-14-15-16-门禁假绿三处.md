# X3-14/15/16：三处「门禁绿着但没在判」的假绿，改成行为断言 + 分母口径前移

## 决定了什么

三个缺陷同一个失效形态：**失败时是绿的**。合成一个 PR 修，因为它们都不改产品行为，
改的是「这道门禁到底判不判」。

**X3-15（P0）—— `affected-tests:run` 不再吞退出码。**
`package.json` 那条接线从

```json
"affected-tests:run": "eval \"$(bun run scripts/affected-tests.ts | grep -v '^#')\""
```

改为先把输出存进变量、用 `&&` 串联：

```json
"affected-tests:run": "out=\"$(bun run scripts/affected-tests.ts)\" && eval \"$(printf '%s\\n' \"$out\" | grep -v '^#')\""
```

旧写法里命令替换丢弃内部退出码：base 解析失败时 stdout 为空、`eval ""` 返回 0 ——
零测试、exit 0，与「没有改动」长得一样。影响所有改动、不限文件类型。
配套给 `change-scope.ts` 增加 `AFFECTED_TESTS_BASE` 环境变量注入点（优先级
`--base` > 环境变量 > `origin/main`），否则「接线在 base 失败时是否非 0」这条
无法在不改 `package.json` 的前提下测。

**X3-14（P2）—— 完整性检查的断言从「数标记串」改成「真跑分支」。**
`tests/release-channel.test.ts` 里两处 `toContain("__NO_DIR__")/toContain("__MISSING__")`
只能证明作者写过那段文字：`PLATFORMS` 从 5 写成 4、写成空串（循环零次、恒判齐全），
断言照样绿。现在从 `release.sh` / `rollback.sh` 里**抠出真实的
`case "$_check_out" in … esac` 段**（不手抄副本），stub 掉 `fail`/`ok`，对
三种哨兵 + 未知输出真跑，断言退出码与点名的文件名。平台数从 `lib/targets.sh` 派生。

**X3-16（P1）—— 防线触发率的分类前移到写入侧，分母改成审计核查类会话。**
- 判据收进 `packages/core/src/trace/audit-task.ts`（`AUDIT_KEYWORDS` + `isAuditTaskPrompt`），
  原来只在 `scripts/defense-trigger-rate.ts` 里有一份；
- `digest.ts` 的 `aggregateSessionMetrics` 在**同一遍事件扫描**里按首个
  `UserPromptSubmit` 算出 `isAudit`（与分子 `defenseTriggered` 同源），
  `collector.ts` 写进 session-index 的新字段 `is_audit`；
- `northstar-snapshot.ts` 的分母与 `n` 都改为 `is_audit === true` 的行数，
  `source` 串同步改成 `${IDX}:defense_triggered ÷ is_audit（仅已检测行 · 分母=审计核查类会话）`；
- `northstar/README.md` 的取数源改指向 snapshot，并标注 2026-11-08 前的快照口径不同、不可直接连线。

`is_audit` 做成**三态**（`true` / `false` / 键不存在）：键不存在 = 未检测
（headless 增量行、没跑完的会话），消费侧排除出分母。这与 `traj_corrupt` 是同一条理由，
但方向相反 —— 那个字段怕把「未检测」压成「未损坏」，这个字段怕把「未检测」压成「非审计」。

## 放弃了什么（以及为什么不选）

**X3-15：不新增 `--run` 子命令。** 把「执行选出的命令」搬进 TypeScript 脚本里更"干净"，
但那会把一个 shell 层的退出码问题换成一个新的进程编排问题（信号传递、stdio 透传、
`bun test` 的退出码在这里要自己转译）。`&&` 串联是一行改动、语义与原来完全一致。

**X3-15：不给接线加 `set -o pipefail`。** 旧写法的管道在命令替换里，
`pipefail` 只影响管道自身退出码，命令替换仍然丢弃它 —— 加了也不会修好，
反而让人以为已经修了。这正是「改了一个看起来相关但不相干的地方」。

**X3-14：不把整段检查抽成独立脚本。** 抽成 `scripts/checks/dir-complete.sh` 会让
`release.sh`/`rollback.sh` 多一层 fork（远端执行是 `run_ssh`，本地抽脚本对远端无意义），
而 `lib/targets.sh` 已经把检查命令和清单收成一份。这里真正缺的是**测得到分派逻辑**，
不是再拆一层文件。

**X3-16：不在 snapshot 里重新实现关键词匹配。** 那是「判定逻辑多处各写一份」的老路，
正是 X3-16 本身和 X3-10、X3-04 的共同病灶。前移到写入侧的代价是 session-index
多一个字段（≈10B/行），收益是两个消费方（snapshot / defense-trigger-rate）
从此不可能各判一套。

**X3-16：不把「未检测」压成 `false`。** 那会让分母随崩溃会话数变化 ——
崩溃的会话恰恰是没有 `SessionEnd`、只有增量行的那些，它们会全部被算成「非审计」，
把分母撑大。宁可分母小一点、只含有结论的行，也不要一个随故障率漂移的分母。

**X3-16：不下线 `defense-trigger-rate.ts`。** 它仍有独立价值：`--list-audit`
列出「被判为审计类且零触发」的会话供人工抽查误分类，这是 snapshot 的聚合数字给不了的。
现在它复用共享判据，不会漂移。

**未做（刻意）：`northstar/v*.json` 历史快照不回填 `is_audit`。** 旧快照没有这个字段，
回填需要重算全部历史会话的 prompt —— 数据已 LRU 清理，回填不出来。断点靠
`northstar/README.md` 的标注和 source 串变化来表达。

## 拿什么证明它生效了

**X3-15**
```
$ bash -c 'eval "$(bun run scripts/affected-tests.ts --base does-not-exist-xyz 2>/dev/null | grep -v "^#")"'; echo $?
0                                    # 旧写法：缺陷成立
$ # 改后（真跑 package.json 里那条 script，注入 AFFECTED_TESTS_BASE=no-such-ref-zzz-for-x3-15）
接线 exit=1，stderr 含 no-such-ref-zzz-for-x3-15
```
变异自证：把 `package.json` 改回旧写法 → `base 解析失败时…` 断言红（实测 1 fail）；
恢复后 `tests/scripts/affected-tests.test.ts` 50 pass。

**X3-14**
```
$ bun test tests/release-channel.test.ts --test-name-pattern 'X3-14'
8 pass                                                     # 两个脚本 × 四种输入
```
变异自证：把 `rollback.sh` 的 `${#TARGETS[@]}` 改成字面量 `4` →
`rollback.sh：齐全 → 成功，平台数从共享清单派生` 红（实测 1 fail）；恢复后 8 pass。

**X3-16**
```
$ bun test packages/core/tests/trace/audit-task.test.ts packages/core/tests/trace/session-index.test.ts
62 pass
$ bun test tests/scripts/northstar-snapshot.test.ts
81 pass
$ bun run typecheck:gate
当前 62 处错误 / 基线 64 处 —— ✓ 无新增类型错误
```
变异自证：把 snapshot 的分母从 `auditSessions.length` 改回 `index.length` →
「非审计行不进分母」与「n 不虚报」两条红。

**整体门禁**：`bun run affected-tests:run`、`make build`、`bun run lint`、
`bun run format:check`、`bun run lint:boundary`、`bun run typecheck:gate` 全绿（见 PR 正文）。

**trade-off 点破**：X3-16 的 `AUDIT_KEYWORDS` 是基于首个 prompt 的关键词代理量，
会有误分类（把「检查一下这个按钮为什么没反应」判成审计类，或漏判口语化的审计请求）。
这是「更准」方向拿可解释性换覆盖面 —— 关键词表可复核（`--list-audit` 抽查）、
可调整，而分类器中枢会得到一个自己定义、自己达标的数字。
