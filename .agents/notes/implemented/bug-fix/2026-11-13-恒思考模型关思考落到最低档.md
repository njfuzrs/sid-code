# 关不掉思考的模型上，`/think off` 改为落到该模型最低档，而不是「什么都不发」

## 决定了什么

**「关思考」在关不掉思考的模型上，统一翻译成「开思考 + 该模型档位表里最低的一档」**，
单一判定入口是 `packages/core/src/llm/dialect/thinking-off-floor.ts` 的
`thinkingOffEffortFloor(model, compat)`。

修复前各层只做到「别发会 400 的值」，没有任何一层回答「那该发什么」：

- side-call 什么都不发（`openai.ts` 的 `alwaysThinking` 分支）→ 服务端按**自己的默认档**跑，
  GLM-5.3 / Kimi K3 的默认是 `max`。用户敲 `/think off` 想省，结果**比不敲更贵**；
- 无 `thinking.type` 开关字段的族（Kimi / Grok / o 系列）连降级都没有，`off` 被直接忽略；
- Anthropic 恒思考族的「关也按低 effort 下发」只写在注释里，代码里从未实现。

落地分四层，每层只做一件事：

| 层 | 文件 | 行为 |
| --- | --- | --- |
| 判定入口 | `dialect/thinking-off-floor.ts`（新增） | 规则进代码、模型事实进数据；**不出现任何模型名** |
| 线格式（side-call 出口） | `openai.ts` / `llm/anthropic.ts` | GLM 发 `enabled + low`；Anthropic 发 `adaptive + low`；无开关字段族只发 `reasoning_effort: low` |
| capability（主循环出口） | `effort.ts` 的 `withThinkingOffFloor` 包一层 `applyToSendParams` | 各族 applier **一行不改**，`thinking=false` 时改传 `(floor, true)` |
| 展示 | `getDisplayedEffort` 加思考意图入参 / `ThinkDialog` / `EffortDialog` | 显示**实发档**而不是用户选的档；面板文案由 `cap.defaultEffort` / `cap.thinkingOffFloor` 生成 |

配套数据改动（`model-registry.ts`）：

- `glm-5.3` / `glm-5.3-flash` / `glm-5.3-flashx`、`kimi-k3`、`grok-4.5/4.6/4.7`、
  `o1` / `o3-mini` / `o4-mini` 补 `thinkingMode: "always-on"`；
- 5 个始终思考的 Claude（opus/sonnet 5-5、fable 5/5-1、mythos 5）补 `reasoningEffortValues`；
- **`always-on` 与 `reasoningEffortValues` 必须成对**，由门禁断言（见下）。

同时把 `isThinkingAlwaysOn` 从代码里的正则名单改为查注册表 `thinkingMode`：
「能不能关」是模型事实，不该写在代码里；模糊查找还顺带覆盖了网关改名（`origin-glm-5.3`）。

**取舍点破**：这次改动牺牲「更省」换「更准」。`/think off` 在恒思考模型上不再等于最省费用
（思考 token 仍会产生），但它从此**是一个确定的、比默认更低的行为**，而不是把决定权交给
服务端默认档。用户想真正关掉思考只能换模型 —— 这是模型能力边界，不是配置问题。

## 放弃了什么（以及为什么不选）

1. **只在 `openai.ts` 里补一句 `reasoning_effort: "low"`**。
   Anthropic（`buildThinkingWire`）、capability 层、展示层三处照旧说「关」/「没生效」，
   用户看到的与实际请求相反 —— 那正是这次要修的病（20261016 思考排查 §0 同型）。

2. **保留正则名单，只往里加 `kimi-k3` / `grok-4.7` / `o3` 几条**。
   加一条模型改一次代码，而且和注册表分叉：同一个模型的「有哪几档」在数据里、「能不能关」在
   代码里，新增模型漏一处就静默错。判定入口的「不含模型名」门禁从机制上堵住这条回头路。

3. **把 `resolveThinking` 改成对 `locked-on` 返回 `true`**。
   它返回的是**下发意图**，`loop.ts` 的 `thinkingIntent` 与 fallback 复算都读它。
   改成 `true` 有两个后果：轨迹里记的意图与用户选择脱节；fallback 换到能关思考的备用模型时
   `off` 再也不生效。所以只在 applier 包装层做翻译，意图层不动。

4. **恒思考 + 无档位表时猜一个档发出去**。
   发一个模型不认的 `reasoning_effort` 是**确定 400**，而不下发只是回到旧行为（服务端默认）。
   代价不对称，所以 `thinkingOffEffortFloor` 在「没档位表」和「compat 声明不吃 effort」两种情况下
   都返回 `undefined`，维持原下发。

5. **让 `off` 与用户显式档位并存（`off` 时仍发 `/effort max`）**。
   等于「关思考 + 拉满档」这种自相矛盾的请求。`off` 是「要不要思考」的上游决定，
   冲突时以 `off` 为准；想深度思考请 `/think on`。这一条写进了 applier 包装与两处断言的注释。

```bash
bun test ./packages/core/tests/llm/thinking-off-wire.test.ts ./packages/core/tests/llm/fallback-thinking.test.ts ./packages/core/tests/llm/thinking-observation-wiring.test.ts
# → 39 pass / 0 fail

# → 8 pass / 0 fail（整帧渲染，含 70 列窄终端不塌版）
```

覆盖的关键行为：`glm-5.3` + `SIDE_CALL_NO_THINK` → `thinking:{type:"enabled"}` +
`reasoning_effort:"low"`；`/think off` + `/effort max` → 实发 `low`；Kimi K3 / Grok 4.7 /
o3-mini → 只发 `reasoning_effort:"low"`；能关的模型（glm-5.2 / deepseek-v4 / grok-4.3 /
claude-haiku-5-5）**行为完全不变**；Anthropic 恒思考 → `adaptive` + `effortFloor:"low"`
（且**不是** manual `budget_tokens`）。

**变异自证**（CLAUDE.md 硬要求）：把 `thinkingOffEffortFloor` 改成恒返回 `undefined`
（= 修复前「什么都不发」的行为），上述测试 **14 处变红**（线格式层 4、capability 层 4、
展示层 3、面板 2、PR3 回归 2）；恢复后全绿 35 pass。证明断言真的在守这条行为，不是恒绿。
