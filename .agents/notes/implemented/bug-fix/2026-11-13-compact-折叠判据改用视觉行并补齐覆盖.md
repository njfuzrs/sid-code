# compact 折叠判据改用视觉行，并补齐长输出工具的折叠覆盖

## 决定了什么

1. **降级判据从「逻辑行数」改为「视觉行数」**：`packages/cli/src/ui/ui-utils.ts` 新增
   `countVisualLines`（按 80 列把超宽单行折开，宽度用 `stringWidth` 算，遵守 L2.3），
   `history-adapter.ts:653` 的 compact 降级改用它。
   原判据 `countEffectiveLines(content) <= 5` 按 `\n` 切分，对**单行超长输出完全失效**：
   `grep` 把结果 `JSON.stringify` 成一行紧凑 JSON（`core/tool/grep.ts:592` 的
   `formatStructuredOutput`），实测命中 23 个文件时 **3081 字符 / 逻辑行 1**，
   `<= 5` 恒成立 → **grep 永不折叠**——PR #808 / #810 落地的折叠对 grep 实际没生效。
   `read` 读 minified 文件、`bash` 单行超长输出同型。
2. **补五个工具的 compact 声明**：`ls` / `read_many` / `web_fetch` / `web_search` / `lsp`。
   它们此前完全没声明档位，输出规模却早已远超一屏（`ls` 实测 85 行 / 2185 字符、
   `web_fetch` 上限 100000 字符、`lsp` 最多 50 条）。
3. **审计补「未声明清单」双向对账**：`EXPECTED_UNDECLARED` + `scanAllToolNames`。
   原审计只做「已声明的必须对上」，新工具不声明档位是**静默通过**——
   这正是上面五个工具被漏掉的机制原因。
4. **修 `getResultSummary` 的 grep 假指标**：同样按 `\n` 数行，单行 JSON 恒为 1 →
   命中 23 个文件也显示「1 个结果」。改为解析 JSON 的 `numFiles` / `numLines` / `numMatches`。
5. **补折叠后的信息出口**：给新增的 compact 工具补 header 摘要（`ls` 的路径、`read_many` 的
   pattern、`web_fetch` 的 URL、`web_search` 的 query）与结果摘要（`ls`「N 项」、
   `read_many`「N 个文件」、`web_search`「N 条结果」）。折叠后标题行是唯一信息出口，
   不能退回 `N 字符` 这种量长度的假指标。

## 放弃了什么（以及为什么不选）

- **不把降级判据搬到渲染层用真实 `terminalWidth` 判**：PR #810 的 Note 已否决（会让
  `displayMode` 含义分裂成「数据层说折叠 / 渲染层说不折」）。这里改为数据层用固定 80 列
  估算视觉行，只识别「逻辑行很少但视觉很长」这一型，`displayMode` 契约不变。
- **不把 grep 输出改成多行格式**：结构化紧凑 JSON 是喂给模型读的 tool_result 正文，
  改成多行会动到 token 与解析契约，代价远大于 UI 收益。
- **不给 `sub_agent` / `workflow` / `task_*` 加 compact**：它们各有专属摘要或结果形态未核
  （`task_output` / `bg_task_list` 分别走 `extractTaskOutputDisplay` / `extractTaskListDisplay`），
  本次先记进 `EXPECTED_UNDECLARED` 显式表态，不扩大范围。
- **不把 `countEffectiveLines` 直接替换掉**：`read` 的「N 行」、`bash` 的「N 行输出」
  语义是**文件行数 / 命令输出行数**，逻辑行才是用户认知口径；只有折叠判据需要视觉行。

## 拿什么证明它生效了

**改前实测（复现根因）**：

```bash
bun /tmp/probe-grep.ts   # 直接 new GrepTool().execute({pattern:"sid-wait|sid_wait|sidWait", path:"."})
# 逻辑行数(countEffectiveLines): 1
# 字符长度: 3081
```

**改后行为（新增回归用例，`tool-result-display-mode-audit.test.ts`）**：

- `单行超长正文照样折叠：逻辑行 1 ≠ 视觉行 1（真实 grep JSON 形态）` —— 用 23 个文件的
  `JSON.stringify` 输出，断言 `displayMode === "compact"`、正文未丢失、
  `resultSummary === "23 个文件"`（改前会是「1 个结果」）。
- `单行短结论仍降级：视觉行口径没有矫枉过正` —— 43 字符单行 JSON 仍 `undefined`。
- `read 单行大文件` / `bash 单行超长输出` —— 同一口径覆盖另两个工具。
