# bash 的 description 从 schema optional 改成 .min(1) 必填，提示词与校验契约同源

## 决定了什么

`packages/core/src/tool/bash.ts` 的 zod schema 里 `description` 由 `.optional()` 改为
`.min(1)`。改之前提示词三处（工具 description、usageGuide、RL 边界）都写「必须提供
description 参数」，而 schema 允许省略——模型只要不传，就能绕过「它会显示给用户审批」
这条设计。改之后缺参数或传空串都会被 `validateToolInput` 拒绝，JSON Schema 的
`required` 也含 description。

连带两处必须同步，否则「改完测试全绿」是假象：

1. `packages/core/tests/tool/input-alias.test.ts` 的 bash 别名用例原本省略 description，
   改为必填后它先被必填校验拦下、到不了改名那一层。补上 `description: "打印 hi"`，
   断言意图（旧名被改写成协议字段）不变。
2. `tests/smoke/cases/` 下 10 个 `replay.jsonl` 共 21 条 bash 入参缺 description，
   改后 schema 校验失败 → 工具不执行 → `PostToolUse` 成功事件为 0。冒烟 9 例失败。
   只补夹具、**不动任何 `case.ts` 的 expect**（按 #618 规则，改夹具不改期望不触红线）。

## 放弃了什么（以及为什么不选）

- **保持 optional、只改提示词措辞**：那是把缺陷留在原地。「提示词说必须、schema 不拦」
  正是 D-08 本身；退回去等于承认这个不一致长期存在。
- **运行时兜底自动填一个默认 description**：会让审批面板出现模型没写过的文案，
  且掩盖「模型没按契约输出」这个信号。CC 的 Bash tool 也是 required，不选兜底。
- **只改夹具里失败的 9 个用例**：其余 11 个 replay 同样缺参数，只是断言没覆盖到工具
  输出（例如断言的是 PreToolUse 拦截）。留给下次是定时炸弹，所以 21 条一次补齐。

## 拿什么证明它生效了

- `bun test packages/core/tests/tool/`（含 bash-stability、input-alias）→ 0 fail。
- 变异自证：schema 改回 `.optional()` → 5 条断言里 4 条红（缺参数 / 空串 / null /
  required 数组），带合法 description 那条仍绿；只改成 `.string()` 不加 `.min(1)` →
  仅「空串被拒绝」变红，证明 `.min(1)` 由独立断言守住。
- `bun run smoke`：改夹具前 43 例 34 通过 9 失败；补齐 21 条后 **43 例 43 通过 0 失败**。
- `bun run smoke:tui` 5/5；`make build` 二进制自检通过。
- 静态排查：`packages/core/src/` 内无「程序化构造 bash 入参且不传 description」的调用点
  （meta-tool 与 policy-probe 走权限判定，不经 `validateToolInput`；shell-input 本就带
  description；MCP serve 原样转发 schema 由客户端校验）。
