# 斜杠补全去掉 20 条硬上限，skill 命令不再被藏

## 决定了什么

`useSlashCompletion` 调 `rankCommandInfos(commands, query, 20)`，而当前命令集是 30 条内置 + 8 个 bundled skill + 磁盘 skill（本机共 82 条）。输入 `/` 时列表恒显示「20 条结果」，按使用频率 + 字母序排在后面的命令 ↑↓ 永远翻不到。skill 命令本来就已注册为斜杠命令（`loadSkillCommands` → `UnifiedCommandRegistry`，`/bug-fix` 可直接执行），但 17 个 skill 里只有 1 个落进前 20，于是看起来像「skill 没变成命令」。

改动：`rankCommandInfos` 的 `limit` 缺省改为 `Infinity`，hook 不再传 20。可见行数仍由 `SuggestionsDisplay` 的 `MAX_VISIBLE=8` 虚拟滚动控制，与 `useAtCompletion` 的「数据层不截断」口径一致。

## 放弃了什么（以及为什么不选）

- 把上限调大（如 100）：命令数随 skill / 插件 / MCP prompt 增长，任何固定值都会在某天复现同一个问题。
- 给 skill 单独开一个补全分组或提升排序：排序不是 bug，截断才是；动排序会改变内置命令的既有位置。

## 拿什么证明它生效了

- 本机探针：82 条候选，旧实现空查询下 skill 可见 1/17，新实现 17/17；`findCommand("bug-fix")` 返回 `type=prompt source=skill`，执行路径本来就通。
- `packages/cli/tests/command/slash-completion-no-cap.test.ts` 4 条用例；把两处改回 20 后全部变红（变异自证），恢复后转绿。
- `bun run affected-tests:run`（判定为全量）2288 pass / 0 fail；`make build` 自检通过；`bun run lint`、`format:check` 绿。
