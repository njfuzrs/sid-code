# 停滞 L2 判据排除「交付 / 验证轮」：把 commit / push / 建 PR / 跑门禁从停滞窗口里摘出去

## 决定了什么

- `query/stall-escalation.ts`：`StallState` 新增 `deliveryTurns`，`StallTurnObservation` 新增 `deliveryAction`；`l2Turns` 从 `toolTurns - bgWaitTurns` 改为再扣 `deliveryTurns`。L1 与停滞窗口**不**排除（L1 只是一句提示），只排除 L2 的「L1 后满 K 轮」。
- 新增 `isDeliveryActionCommand`：只看命令**首行**，识别 `git commit|push`、`gh pr create|merge`、`bun test`、`bun run format|lint|typecheck|build|affected-tests`、`make build`。**不含** `gh pr view|checks` / `gh run view|rerun|list` / `gh api` / `tail .output`——轮询形态恰恰是 L2 该抓的。
- `query/loop.ts`：`collectStallObservation` 在 bash 分支判 `!failed && isDeliveryActionCommand(cmd)`，结果随观测传给判据；失败的命令不算交付（commit 被 hook 拦住、门禁没跑起来都不产生新信息）。
- 删掉了一条原本以为必需的早退 `if (obs.backgroundRunning || obs.deliveryAction) return level 0`——变异自证时发现它**冗余**：交付轮已从 `l2Turns` 扣掉，不可能成为「第一个凑满 K 轮」的轮次。保留它等于两处事实源，且测试锁不住（删掉前后测试全绿）。

## 放弃了什么（以及为什么不选）

- **把判据改成「连续 N 轮命令完全相同且输出无变化」**：本轮不选。更根本，但要重做观测层（bash 命令与输出进账本），影响面大。先用「排除交付轮」把 5 条误伤消掉，看新影子数据再决定要不要上这套。
- **把 `gh pr view|checks` / `gh run view` 也算交付**：不选。这些正是 `20261102-151143` 两条命中样本的形态（L2 后 51 / 31 轮 0 次写入、bash 重复 25 / 14 次，最终 `stop=abort` 用户 ESC）。算成交付等于把真停滞也放走。
- **在 `observeStallTurn` 里重置停滞窗口**：不选。交付轮不改变工作区，重置窗口等于让「连续 20 轮门禁」永不触发 L1；而 L1 只是提示，保留观测价值。
- **`bun test` 失败也算交付轮**：不选。失败的门禁没产生新信息，不该排掉停滞窗口。
- **把 `git mv` / `git add` 算交付**：不选。它们不产生外部可见状态，也不属于验证；`git mv` 改的是工作区（走 rehash 路径）。

## 拿什么证明它生效了

- 单测：`stall-escalation.test.ts` 新增 6 个用例（识别交付命令 / 轮询不算 / heredoc 正文不算 / 交付轮不计入 L2 / 照常推进 L1 / 不预支轮数）；`stall-escalation-loop.test.ts` 新增 2 个接线用例（每轮跑 `bun test` 时 L2 不触发、每轮轮询 `gh pr view` 时 L2 照常触发）。
- 跑：`bun test ./packages/core/tests/query/stall-escalation.test.ts ./packages/core/tests/query/stall-escalation-loop.test.ts` → **56 pass / 0 fail**。
- 变异自证 3 次全红：
  1. 不累计 `deliveryTurns`（`+= 0`）→「交付轮不计入 L2」红；
  2. `isDeliveryActionCommand` 恒 `false` →「识别交付 / 验证命令」红；
  3. `collectStallObservation` 恒返回 `deliveryAction: false` → 接线用例「L1 后一直跑 bun test」红。
- 第 4 次变异（去掉 L2 早退里的 `|| obs.deliveryAction`）**没红**，据此确认该早退冗余并删除——这正是变异自证要抓的「恒绿断言」。
- 18 条影子样本按新判据重算（估算，忽略逐轮 `bgWait` 状态）：误伤 **5 → 1**。`20261105-142651` #1 仍是同点位——它的交付动作在 L2 之后才开始，新判据管不到；`20261105-142651` #2 不再触发；`20261103-142302` / `20261106-192316` / `20261105-163629` 各延后 2–3 轮越过收尾动作；6 条真停滞样本全部保留（同点位或延后）。
- 全量门禁：`bun run affected-tests:run` → **1188 pass / 0 fail**；`bun run typecheck:gate` → 无新增类型错误；`make build` → 自检通过。
