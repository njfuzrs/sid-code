# 压缩成败判据同源、目标线下移、masking 校准同源 + 粘滞、prefix_break 带来源

## 决定了什么

来源是 20261020-110542-ce7ea52e 会话评估的发现 3、4、14（issue #386）。一份 1.05M 窗口长会话里，hard 压缩把 input 从 865K 压到 250K 却报 `success:false`；masking 区间 15 个隔轮翻转点，cache_read 每次跌到约 6 万，约占会话成本 25%。

- **3a/3c 判据同源**（`query/loop.ts` `settleCompaction` 与三个阈值分支）：成功 = 消息数减少 **或** 同源 token 估算下降。before/after 都用 `estimateTokensFor(getMessages())`（不套 `lastActualInputTokens` 锚点；压缩会清零锚点，套了就是两把尺子）。hard 分支的 after 在 `addCompactBoundary` **之前**取，边界消息不计入。blocking/emergency 也换成同一把尺子，不再用 `emergencyTruncate` 返回的 tokensBefore（套锚点）/tokensAfter（锚点已清零）。横幅与 `types.ts` 的不变式同步放宽，横幅文案补「约省 NK token」。
- **3b 目标线**（`query/compact/index.ts` `pipelineTargetRatioFrom`）：`min(hard 触发点, masking 进入线 − 5% 窗口)`。1M 窗口 82% → 73%。小窗口无 masking 档，沿用触发点。取 min 防 `SID_CODE_AUTOCOMPACT_PCT` 把 hard 线设到 masking 线以下时目标反而高过触发点。
- **4a 校准同源**（`context/manager.ts` `recordActualTokens`）：采用评估报告里的「精确版」。`getCleanedMessages` 记下 `{full, sent}` 快照，校准分母改为发送副本的 raw 估算；锚点换算回全量空间 `actual + (rawFull − rawSent) × factor`，本地减量仍由 `getCompactionLevel` 统一从 `tokenFreedTracker` 扣。
- **4b 粘滞**：新增 `maskedState`（tool_use_id → 首次遮罩时的占位全文）。之后每轮按同一份字节发送，level 回落不撤销，`resetLocalCompactState` 统一清空。
- **4c 记账**：首次遮罩时释放量按 chars/4 记入 `tokenFreedTracker`（与 cleanedMessages 同口径，只记一次）。
- **14**：`ContextManager.consumeSendMutationCauses()` 报出 compact / masking / cleaned 三类本地改写，主循环经 BeforeModel 的 `send_mutation_causes` 交给采集器，`prefix_break` 在 broken 时落 `cause`；本地没改写落 `["none_local"]`，未上报（子代理、老版本）不落字段。
- `website/use/context.md` 补「压缩后落到遮罩线以下 5%」「遮罩一旦发出就保持」「成败判据」。

## 放弃了什么（以及为什么不选）

- **4a 简单版（masking 轮冻结因子与锚点）**：评估报告推荐的是它。实现时发现它和 4c 冲突：4c 让遮罩释放量从 used 里扣掉后，冻结的锚点仍停在上一次全量 usage，「锚点 − freed」的口径和「全量 raw × factor − freed」不一致。精确版的换算只多一行，且保证两支 max 在同一空间，所以选精确版，并用「因子恒≈1」「锚点不被钉低」两条单测锁住换算。
- **4d 进出滞回**：按决策 5 不做。4a+4b 之后估算不再被遮罩后的 usage 拉低，边界抖动也不再改写前缀，多一个阈值只是多余状态。另落 rejected 的事由评估报告 §6 统一处理，本 PR 不重复。
- **二次 hard 升级摘要**：按决策 3 不做（按次数的经验规则，会把可恢复的截断换成不可恢复的摘要）。
- **cause 枚举覆盖 reminder / todo / jit / system_dynamic**：评估报告列了七类。这几类不是 ContextManager 改写的，`first_changed_kind` 已经能区分 system_dynamic；reminder 注入只改最后一条 user，属于尾部追加，本来就不会判 broken。只落能确证的三类加 `none_local`，不猜。
- **单测稳定在 soft**：评估报告的验证写的是「修复后稳定在 soft」。实测修复后稳定在 **none**：4c 已经把遮罩释放量扣掉，发送量确实低于 soft 线，这是正确结果；粘滞保证已遮罩条目不会因此恢复原文。断言改成「档位不再交替 + 遮罩集合单调不减 + 因子恒≈1」。

trade-off：3b 截得更深（更省 ↔ 更准），截的是保护窗口外的旧工具输出，可按占位提示重读；4b 让模型持续看不到已遮罩内容，代价是可能多几次重读工具调用。两者换来的是前缀不再来回改写（更省）。3a 让 `notifyCompaction` 真正被调用，北极星「更省」曲线的 cache 归因会有一次口径跳变，发版说明要写明。
