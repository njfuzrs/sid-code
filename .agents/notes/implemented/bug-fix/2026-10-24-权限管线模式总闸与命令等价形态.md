# 权限管线：plan/deny-write 改为出口总闸，safetyCheck 跟随 symlink，deny 规则覆盖命令等价形态

## 决定了什么

按《Agent 权限系统从零到一》§4「顺序即安全」逐步审 `permission/checker.ts`，实测出的绕过全部改成结构性修复：

1. **模式硬约束总闸**（`checker.check` → `enforceModeHardConstraint`）。所有放行都从 `check()` 出去，
   plan / deny-write 在出口统一判一次；计划文件（Step 3.5）是唯一豁免。修前实测绕过口：
   Step 8 allow 规则、Step 4 敏感文件逃生舱 `Write(.env)`、Step 12 `--allowed-tools`、会话记忆、
   yesMode、PreToolUse hook allow、skipPermissions + enter_plan_mode。阶段一里原有的逐处判断保留（日志更具体）。
2. **safetyCheck 判字面路径 + symlink 解析链 + realpath，取最严格命中**。`innocent -> .git/hooks` 后写
   `innocent/pre-commit` 修前在 always-allow / acceptEdits 下静默放行。取「最严格」而非「第一个」：
   解析链中间一环 `.git/hooks`（目录）只命中宽泛的 `.git/`（classifierApprovable=true）。
3. **bash 写入目标进 Step 6**（`extractBashWriteTargets`：cp/mv/tee/sed -i/curl -o/wget -O/dd of=/重定向，含 sh -c 内层）。
   修前 `cp x .git/hooks/pre-commit` / `tee …` / `sed -i …` 在 always-allow 下放行，Step 2 只认 `>`。
4. **deny / ask 规则与危险命令检测改用 `expandShellCommand`**（新模块 `permission/shell-command-variants.ts`）：
   前导空白、绝对路径、`FOO=1` 前缀、env/command/nohup/timeout/xargs/sudo 等包装、转义与引号拼接、
   `sh -c` / `eval` / 命令替换递归。修前 `Bash(curl *)` 被这些形态全部绕过，`sh -c 'rm -rf /'` 与 `r\m -rf /` 在 always-allow 下放行。
5. **disallowedTools 比较收口到 `isToolNameListed`**（CC 名 / 大小写 / 规则写法），子代理 tool-filter Layer 3 同口径。
   修前 CLAUDE.md 里的 `Bash` / `WebFetch` 静默不生效（CLI 入口的 removeByNames 归一掩盖了它）。
6. **硬拒绝熔断不再转成确认**：第 4 次仍是硬拒，reason 说明「重试不会改变结果」，防线记 `blocked`。
   修前第 4 次读 `.env` / `rm -rf /` / 撞 deny 规则都会弹出可点穿的确认。
7. **可观测性**：`Decision.step` / `.mode` 进 `PermissionDecision`；SessionStart 记 `sid_permission_mode` 与
   `permission_config`（规则条数 × 来源、开关，不含规则文本）；session-index 加 `by_step` / `by_mode` /
   `mode_guard_breaches`；北极星快照加模式越权哨兵、决策可归因率、规则暴露会话占比。

牺牲的方向：**更安全 ↔ 更快**。plan 下原本被 allow 规则直放的写入现在是硬拒；熔断后不再给弹窗放行的机会；
`sh -c` 里的 deny 命中会多拦（宁拦勿放）。本机 400 会话的暴露面为 0（见下），对现有工作流无可见影响。

## 放弃了什么（以及为什么不选）

- **在 Step 8 / 12 / 记忆 / yes / hook 各处逐个补 plan 判断**：这正是 P0-3 在 Step 5.5、Step 7 的做法，
  结果漏了五个放行口。逐处补的缺陷形态是「下一个新放行口照样漏」，总闸挂在唯一出口上结构性地堵住。
- **把 Step 9 plan 挪到 Step 8 之前**：只能堵 allow 规则一个口，挡不住阶段二的会话记忆 / yes / hook / skip。
- **allow 规则也用展开形态匹配**：会把「拦」的宽口径借给「放」（剥掉包装后放行原本不该放的整条命令）。拦宽放窄 = fail-closed。
- **把整条命令去引号再匹配危险模式**：`git commit -m "rm -rf /"` 会变成删根目录误报。只规范化命令头，参数保持原文；
  真正「参数即代码」的 sh -c / eval / 命令替换单独递归。注：`git commit -m "rm -rf /"` 修前在 main 上就被
  「递归删除根目录」模式误报（原文正则匹配），本 PR 未改变它，留作已知误报。
- **熔断后 dontAsk/非交互之外仍转确认**：硬拒绝全是配置级决定，「模型重试三次」不该成为推翻配置的条件；
  凭证文件硬 deny 的理由（弹窗最容易被点穿）在这里同样成立。
- **用轨迹证明缺陷存在 / 修复生效**：本机 400 会话触发前提为 0（无规则配置，288/400 bypass 且约 219 个 skip 早退），
  轨迹天然给不出证据；存在性与修复都靠矩阵测试，轨迹只负责暴露面与回归哨兵。

## 拿什么证明它生效了

- `packages/core/tests/permission/pipeline-order-matrix.test.ts`（79 例）：修前探针的每一个绕过形态都写成断言。
- **变异自证**：逐项把修复改回旧逻辑，矩阵必须变红——symlink 链 6 fail / bash 写目标 15 / 精确比较 6 / 去总闸 15 /
  deny 回拆分 12 / 危险检测回拆分 4 / 熔断回确认 8 / 取首个命中 3。
- `packages/core/tests/trace/permission-step-mode-observability.test.ts`：真实 checker 决策经门面到 collector，
  `events.jsonl` 带 step/mode、SessionStart 带 sid_permission_mode=deny-write（CC 映射值为 default）与 permission_config。
- `tests/scripts/northstar-snapshot.test.ts`：三个新指标的分母口径与「旧行不进分母、全旧行为 null」。
- 权限 / trace / analytics / agent 全部测试绿；`bun run typecheck:gate` 66/66 无新增。
- 上线后的轨迹信号：`mode_guard_breaches` 恒 0（非零即出现绕过总闸的新放行口）；`step_attribution_rate` 应从
  修前约 13.6%（3524/25933 条带 reason_type）升到接近 100%；`rule_exposed_session_rate` 给出规则类缺陷的真实暴露面。
