# git 输出选项进写目标；多个写目标取最严格的 safetyCheck 命中

## 决定了什么

两处改动，同属 safetyCheck（Step 6，bypass-immune）对 bash 写入的保护：

1. **`extractBashWriteTargets` 新增 git 分支**（`permission/shell-command-variants.ts` `gitOutputTargets`）。修前没有 git 分支，`git diff --output=.git/hooks/pre-commit`、`git format-patch -o .git/hooks HEAD~1` 在 always-allow、yesMode，以及 allow 规则 `Bash(git *)` 下都能直接放行；`cp` 写同一路径则会被拦。新增识别：
   - `--output=<f>` / `--output <f>`：diff 族选项，不按子命令限定，宁多勿少。
   - format-patch 的 `-o <dir>`、`-o<dir>`、`--output-directory[=]<dir>`：目录本身加上一个 `<dir>/_` 占位，让 safetyCheck 的目录模式能命中目录下真正落盘的文件。
   - 跳过 `-C`、`-c`、`--git-dir` 等带取值的全局选项再找子命令；`--` 之后一律不当选项。
2. **Step 6 多个写目标取最严格的命中**（`permission/checker.ts`）。修前按顺序首中即返：`tee .git/config .git/hooks/pre-commit` 先命中宽泛的 `.git/`（`classifierApprovable: true`），auto 分类器就有权放行一次 hook 写入；参数换个顺序结果就不同。format-patch 的目录目标同样会先命中 `.git/`。这和 `safetyCheck()` 内部对 symlink 解析链取最严命中是同一个理由，现在两处口径一致。

## 放弃了什么

| 方案 | 不选的理由 |
|---|---|
| allow 规则匹配时剔除 git 输出选项（`Bash(git diff *)` 遇到 `--output` 视为不命中） | 会多出一条只针对 git 的隐式例外，和 `Bash(cp *)` 放行 `cp x /tmp/y` 不是同一口径。以后 `sort -o`、`uniq a b` 等都要逐个问一遍要不要例外。受保护路径已经由 1 兜住；规则作者想要只读，可以不写规则，交给只读集判断（#459 已经认 `--output`） |
| Step 4 路径验证覆盖所有 bash 写目标（工作区外需确认） | 影响面远超本条：`cp x /tmp/y`、`curl -o /tmp/f` 全都要确认，需要单独立项并做 A/B |
| 在只读集、写目标两张表之外再加一张「git 写选项」表 | 同一件事三处维护，正是 N6 和 E4 分叉的原因。写目标提取是 safetyCheck 唯一的输入，放这里就够了 |
| 修正 `git -C <dir>` 的相对基准 | 列为已知局限，写在函数注释里。`-C` 加相对 `--output` 的组合罕见，修正需要在提取层引入 cwd 语义 |
| `--ext-diff`、`-c core.pager=…` 等代码执行通道 | 属于「不可信仓库配置」这一类威胁，另外立项 |

## 拿什么证明它生效了

- `packages/core/tests/permission/pipeline-order-matrix.test.ts` 新增两组：
  - F 组：7 种 git 写 hook 的写法 × 3 种模式（always-allow、yesMode、default + allow 规则），全部要求 `safetyCheck` 加 `classifierApprovable=false`；allow 规则下 `--output` 写普通路径照旧放行；写目标提取形态 9 条断言。
  - G 组：`tee` 两个写目标的两种顺序都必须是 `false`。
- 结果 104 pass / 0 fail。
- 变异自证：
  - M1 删 git 分支 → 22 fail
  - M2 不处理 `--` → 1 fail
  - M3 只认 `--output=` → 4 fail
  - M4 目录不加占位 → 10 fail
  - M5 写目标首中即返 → 10 fail
  - 恢复后全绿。
- 牺牲：几乎没有。只多出几个写目标候选，函数头约定多出来的候选只会被判一次是不是受保护路径。
- 来源：bench_fix 03-F2 §6.8 E4；方案见 bench_fix 02g。
