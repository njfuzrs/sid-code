# 触发事件进轨迹：review #600 后的口径补强与消费侧测试

## 决定了什么

PR #600（`HookExecuted` / `Rewind` / `ScheduledFire` + `ScheduledInject` 进轨迹）合入后
review 发现的问题，按「先修口径、再补覆盖」合成一个 follow-up PR：

1. **合并两节同名的「触发计数」**：PR #599（bridge）与 #600 各自在 digest 里渲染了一节
   `触发计数:`，一个既有远程接管又有本地回滚/hook 的会话会输出两段同名小节、各只有部分字段。
   把 `TriggerCountsStats` 并入 `TriggerDigestStats`，只留一个聚合函数与一个渲染点；
   `bridgeInbound` 作为其中一个字段，只在 > 0 时渲染一行（本地会话不该多一行恒 0）。
2. **命令层的 `error` 覆盖到「抛错」**：`/rewind`、`/undo`、`/undo <file>`、`/restore` 原先
   只把「返回 null」记成 `outcome=error`；磁盘错 / 索引损坏这类真实失败走抛错路径，
   轨迹里**零事件**，于是回滚成功率的分母偏向非失败路径。四处都补 catch（记 `error_name`
   后 rethrow，不吞异常）。
3. **`hook_p95_ms` 排除 `async_started`**：async hook 的 `duration_ms` 只是「启动并交给
   registry」的耗时，真实执行在后台（由 `HookAsyncCompleted` 单独记）。混进同一个 p95 会让
   「hook 很快」在 async 用得越多时越假。同时把 `ScheduledInject.queue_wait_ms` 聚合进来
   （`scheduledQueueWaitP95Ms`，只统计 `queued=true`）——「会话忙导致的两段延迟」原先只有
   调度器那一半有分位数。
4. **埋点兜底**：`emitExecutedTelemetry` 的字段派生（`describeHookId` → `sha12`）可能抛错，
   原先会把「一个返回 error 结果的 hook」变成「抛异常给调用方」，与 `hook-telemetry.ts`
   头注释的承诺相反。调用点包 try/catch，`sha12` 加兜底（与 `rewind-telemetry.ts` 同口径）。
5. **补消费侧与命令层测试**：review 的两个 high —— 设计 §4.1 要求的
   `packages/cli/tests/command/rewind-undo-restore-telemetry.test.ts` 整行缺失；
   `aggregateTriggerStats` 115 行零测试。

顺带收紧三条弱断言：app 层 sink 接线要求出现 `traceCollectorInstance`（原
`toContain("setXxxSink(")` 会被 `setXxxSink(null)` 通过）；digest 的 `触发计数:` 标题必须
恰好一处；三个创建入口的 `origin` 走真实 tool/command 路径断言（原测试只断言 fixture 透传，
删掉 `loop.ts` 的 origin 也不会红）。

## 放弃了什么（以及为什么不选）

1. **用 `mock.module` 注入抛错来测命令层 `error`**：否决。bun 的模块 mock 是**进程级**的，
   会污染同批其他测试文件（本仓现有 `mock.module` 只出现在 spawn 的子进程脚本里）。
   改为走真实 `CheckpointManager` 覆盖 ok/nothing 分支，「catch 里必须有
   `emitRewind(... "error" ...)`」用门禁断言防回退，真实抛错的注入成本高于收益。
2. **把 `queue_wait_ms` 与 `lag_ms` 合成一个「定时延迟」**：否决。两段延迟的成因不同
   （调度器被会话忙推迟 vs 提示词排队等空闲），合成一个数就分不出该修哪一段——这正是
   原方案 T3 把 `ScheduledFire` / `ScheduledInject` 分开记的理由。
3. **给 `hook_p95_ms` 按 outcome 分多桶**：只排除 async 就够。分桶会让「样本 < 5 不给 p95」
   更容易触发，产出一堆 `n/a`，反而没有可比较的数。
4. **让 `bridgeInbound` 恒显示（含 0）**：否决。普通本地会话会多一行恒 0 的「远程接管」，
   把「没被遥控过」与「埋点没接线」混成同一个数。
