# 官网自动更新页与 CLI 参考页按代码事实校准

## 决定了什么

对 `website/use/auto-update.md` 做「文档 vs 代码」审计后，修正 3 处表述、补齐 2 处参考页数据源缺口（另 1 处白名单配套），共动 4 个源文件 + 2 个生成产物：

1. **补参考页数据源：`update` 子命令在 `/ref/cli` 长出选项小节**。auto-update.md 的「相关」承诺「`sid-code update` 的完整选项」，但 cli.md 里没有——`help.ts` 子命令段里 `update` 是唯一没有「用法:」续行的条目，而生成器只对带 detail 的子命令渲染小节。在 `packages/cli/src/help.ts:146-148` 补用法行（`[--version x.y.z] [--list]`）后，cli.md 生成出 `### sid-code update` 小节。
2. **补参考页数据源：`SID_CODE_AUTO_UPDATE` 登记进 `/ref/env` 正式表**。该变量是正式功能（`packages/core/src/update/config.ts:42` 读取；`packages/cli/src/command/update.ts:31` 与 `manifest.ts` 的用户文案都在引导用它），但从未写进 `--help` 环境变量段，导致 env.md 把它列进页尾「未列入上表……不建议依赖」。在 `help.ts:230` 的「安装与更新」段登记后进入正式表（表内 124→125，页尾清单 62→61）。
3. **auto-update.md 三处表述修正**：
   - `:43`「装指定稳定版」→「装指定版本」（可装任意归档版本，且 beta 机器装完仍保持 beta 标记；官方帮助措辞是「安装指定版本」）。
   - `:51`「写在版本目录旁」→「写在二进制旁」（`.channel` 与二进制同目录：`packages/shared/src/release-channel.ts:37-39` 从二进制所在目录读、`scripts/install-template.sh:227` 写入 `$NEW_DIR/.channel`）。
   - `:131-135`「每台机器只补一次」→「每个键只会被补一次、绝不覆盖已写的值，模板后续新增的键会在之后启动时补进来」。原文会让读者以为升级后再也不接收新增字段；实际是两段补全——v1 迁移（首次升级全量补缺失键）+ 每次启动的增量补全（`packages/core/src/migrations/backfill-team-defaults.ts:9-12`）。
4. **配套**：`scripts/docs-gen-reference.ts:925` 的 `HELP_ONLY_WHITELIST` 补 `list`（update 子命令参数，与 diff/webhook 等同口径），否则 CLI 双源对账会把新用法行里的 `--list` 判成「help 写了但 parseArgs 没声明」。

## 放弃了什么（以及为什么不选）

- **不改 auto-update.md 的链接措辞、而去补 cli.md 数据源**：`update` 是 7 个子命令里唯一没有用法小节的（review/daemon/agents/plugin/mcp/auth 都有），缺的是参考页内容而不是文档承诺；补 help.ts 让承诺成真，也顺带让 `--help` 本身更完整。改文档措辞只是把缺口藏起来。
- **不把 `SID_CODE_AUTO_UPDATE` 从 auto-update.md 里删掉**：它是正式功能（见上），矛盾的正确解法是把它登记进 `--help` 段，让 help / 参考页 / 指南三处口径一致；删文档是掩盖矛盾。
- **不改「0.1.599 及更早」「0.1.602 起都在归档里」等版本口径**：与 `packages/core/src/update/release-manifest.ts` 的 KNOWN_ISSUES 区间（0.1.582–0.1.599）及服务器 versions.json 实测（archive_since=0.1.602）一致，不需要动。
- **不扩大改动面**：审计中发现但经复核属可接受表述、或已与代码一致的段落（24h 节流、锁、原子切换、失败提示、无头模式等）一律不动。
