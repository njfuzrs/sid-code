# 辅助调用入账即刷新状态栏：把入账观察者从单槽位扩成多订阅者

## 决定了什么

修 D1（P0）：**Footer 费用列漏掉「一轮结束之后」发生的辅助调用费用**。实测一次会话
Footer 停在 `$0.0856`（只有主循环）、真实总花费 `$0.1501`（少报 43%），而且用户不再输入
就**永不更新**，要等下一轮第一个工具结束才一次性跳上去。

根因不是计价口径（三处显示都读同一个 `getEffectiveTotalCostUSD()`），而是**通知通道
只有一个槽位**：`SessionState.setCostChangeListener` 是覆盖式赋值，被 `app.ts` 的
账本落盘占用（构造 SessionState 后立刻挂上）。UI 想「每笔入账都刷新」就无处可挂，
只能返回五个固定时机重新读值（tool_end / done / 轮末 finally / 中断 catch / 首帧），
而辅助调用（后台记忆 fork、标题生成、SessionEnd 前的收尾）全部发生在一轮结束之后 ——
那五个时机都已经过去了。

落地四处：

1. **`packages/core/src/session/state.ts`**：新增 `addCostChangeListener(fn): () => void`
   （内部 `Set`，返回幂等的反注册函数）。`setCostChangeListener` **保持原覆盖式语义不动**，
   两者并存。`notifyCostChanged` 先调旧槽位、再遍历订阅者，**逐个独立 `try/catch`** ——
   账本写盘抛错不该阻断界面刷新，反之亦然。
2. **新文件 `packages/cli/src/ui/cost-bridge.ts`**：`subscribeCostToBridge(session, bridge)`
   把入账推成 TUI 字段（`costUSD` / `cacheSavingsUSD` / `usage` / `totalRequests` /
   `discardedRequests`），走 `bridge.updateStreaming`（32ms 固定窗口合帧、尾沿必触发）。
3. **`packages/cli/src/app.ts`**：`runTUI` 里 bridge 建好后订阅，`await app.waitUntilExit()`
   之后反注册。
4. **测试**：`packages/core/tests/session/cost-change-listeners.test.ts`（5 条，多订阅者语义）
   与 `packages/cli/tests/ui/cost-bridge.test.ts`（5 条，用真实的 SessionState + StateBridge +
   生产订阅函数复刻接线）。

## 放弃了什么（以及为什么不选）

- **不把 `setCostChangeListener` 直接改成多订阅者集合**：全仓唯一生产调用点是账本落盘那一行，
  而且 `packages/core/tests/telemetry/ledger-flush-throttle.test.ts` 有源码断言锁着它的字面形态
  （`§④ app.ts 接线（源码断言）`）。改语义的收益为零（新接口已经能共存），牵连却按跨层算：
  那条线一旦被挤掉，账本会**静默**停止落盘 —— 形态是「费用数字对、账本查不到」，比 D1 更难归因。
- **不把辅助调用并进 `modelUsage`**：那会让 `getStockPromptTokens()`（状态栏 ↑ 的「当前上下文大小」）
  把影子调用的 prompt 也算进去，显示一个不存在的上下文。`state.ts` 的 `sideCostUSD` 注释里
  早就写死了这条（"避免污染 stock 口径"），D1 的修法不能绕回去。
- **不用 `updateState` 推送**：主循环每个请求也会触发入账，逐笔 `emit` 会让整棵 App 树
  reconcile（`state-bridge.ts` 的 `updateStreaming` 注释记录了实测数字：3600 token 一轮
  3615 次 update / 16.3s profile）。用 32ms 合帧，尾沿必触发，不会漏最后一笔。
- **不在订阅里推 `stockInputTokens`**：辅助调用不改上下文，推它只会让状态栏 ↑ 在唯一
  该稳定的时刻抖动。有专门的用例锁这一条（变异验证见下）。
- **不写 G2 无头回放冒烟用例**：T-A2 用真实 `SessionState` + 真实 `StateBridge` + 生产订阅函数
  跑在了 G1，判据是纯确定性的（入账 → 32ms 后状态里的 costUSD），没有「模型自己选择」的成分，
  按 CONTRIBUTING 的分层判据停在 G1 即可。
- **不动 `deriveCost` 的 `≈$` 判据（D7）、`/stats` 命中率（D9）、辅助调用 label（D10）、
  Footer 命中率（D18）**：方案文档把 D1/D7/D9/D10/D18 归在同一个 PR-A，但 D1 是 P0
  且改动自洽可独立上线/回滚（D7/D9/D10/D18 各自要动 `ModelUsageStats` 快照字段、面板算法、
  billing label 语义），按「一个 PR = 可独立回滚的单元」拆开做，避免 D1 的上线速度被其余四项决定。

## 拿什么证明它生效了

- **新增测试 10 pass / 0 fail**（`packages/core/tests/session/cost-change-listeners.test.ts`
  5 条 + `packages/cli/tests/ui/cost-bridge.test.ts` 5 条）。核心那条是「一轮结束后才发生的
  辅助调用入账，同样推到状态」：先 `updateUsage`（主循环）→ 等合帧 → 记下 `costUSD` →
  用户不再输入 → `addSideCost(0.0645)`（本次会话真实数字）→ 等合帧 → 断言
  `bridge.current.costUSD === getEffectiveTotalCostUSD()` 且大于只算主循环的值。
- **变异自证 2 轮**（每轮改坏 → 确认断言变红 → 恢复后复跑 10 pass）：
  1. 把 `notifyCostChanged` 里「遍历订阅者」整段去掉 → **9 fail / 1 pass**（唯一通过的是
     「反注册后不再推状态」，它在变异下自然仍通过）。红的第一条就是 D1 核心用例。
  2. 在 `cost-bridge.ts` 的 patch 里加 `stockInputTokens: 999_999` →
     「辅助入账不改当前上下文大小」用例变红（`Expected: 0, Received: 999999`）。
- 门禁结果见 PR 正文（`affected-tests:run` / `make build` / `lint` / `format:check` /
  `typecheck:gate` / `lint:boundary`）。
- **端到端验证仍待做**（本机没有能触发 5 次以上后台记忆 fork 的真实会话）：方案 5.3 节要求
  `make build` 后用 `sc-dev` 跑一轮含工具调用的对话，之后**不再输入**、等 30 秒，
  确认 Footer 费用自行涨到与 `/debug` 累计费用一致。PR 正文里如实标注为「待维护者本机复验」。
