# 提取代理每 N 轮回头核实一条「很久没人读」的记忆

## 决定了什么

记忆只写不校。一条记忆的前提可能早就变了（「这个仓库用 A 方案」→ 后来改成 B），但提取
提示词明确写着「不要为确认旧记忆是否仍然准确去读代码」——它没有核实通道，于是过期记忆一直
躺在索引里，每轮随 system prompt 注入，误导后续会话（MD5）。

新增 `packages/core/src/memory/extract/verify.ts`，并在 `extractor.ts` 里接线：

- **选谁**：超过 `staleDays`（缺省 7 天）没被读过的条目，`lastRead` 取 `.read-stats.json`；
  从没被读过的按写入 mtime 算，且**优先**——它连一次都没被验证过。
- **多久一次**：每 `verifyEvery`（缺省 5）次**真跑**的提取一次。`0` = 关闭
  （`SID_CODE_MEMORY_VERIFY_EVERY=0` 就是回滚开关）。
- **怎么核实**：那一轮 `maxTurns` 5 → 6，提示词把「不要验证」段**整段替换**成核实段，
  只对这一个条目放开 `grep` / `read` / `git`。
- **写回**：前提已不成立 → 用同一 key 覆盖，正文以 `纠正：<为什么不成立>` 开头；
  仍成立 → **什么都不做**（不重写文件，避免把 mtime 推新污染新鲜度判断）。

三处排除：`source: agent_action` 不进索引（模型看不见，核实没人受益）、不到 `staleDays`
不算候选、计数用 `ranCount`（真跑次数）而不是 `end_turn` 序号（节流时两者会错位）。

## 放弃了什么（以及为什么不选）

**① 不做「默认开着每轮都核实」。** 每轮多一轮核实 = 每轮多一份 token 成本，而记忆过期是
低频事件。每 5 轮一次、且只在真有超期条目时才多给一轮，是「更省 ↔ 更准」里偏保守的一侧。

**② 不碰 `settings.autoDream` 的默认值。** 方案原文列了两个选项（改 dream 推荐值 / extract 自检），
这里选后者：改默认值是**波及所有用户**的行为翻转，而 dream 默认关闭是刻意的产品决定
（`dream/dream.ts`）。用一个 bug 的修复去推翻一个设计决策，应该单开方案讨论。

**③ 提示词用「替换」而不是「追加允许」。** 如果核实段和原来的「不要为了确认旧记忆是否仍然
准确去读代码」同时存在，模型会选保守那条（少做一件事不吃亏），核实永远不会发生。
这条是实现时**真的踩到了**：第一版就是两段并存，测试里那条 `not.toContain` 立刻变红。
所以那句硬禁止在有核实目标时整段消失，换成「其它条目仍然不要验证」。

**④ 只走 env，不加 settings 字段。** 加 settings 要同步 config schema + 参考页生成，
而在它被真实数据验证之前，一个环境变量够了。`resolveVerifyEvery()` 因此没有 `settingValue` 参数。

**⑤ 核实结果不写「核实过」的标记。** 一旦写标记就要重写文件，mtime 被推新，
`buildFreshnessWarning` 会把它当成「最近改过」——那会让这条记忆看起来新鲜，恰好掩盖了
它真正的问题（前提过期）。所以「仍成立 → 什么都不做」，代价是下轮可能又选中它，
但那只是多花一轮，不会污染数据。

## 拿什么证明它生效了

新增 `packages/core/tests/memory/extract/verify-p1-2.test.ts`（17 个用例）：选目标的六条边界
（未到天数不选 / `agent_action` 排除 / 从未读过优先 / 空清单 / `staleDays` 可调 / 子目录相对路径）、
频率与 env 解析、提示词二选一的四条、extractor 集成的两条（`verifyEvery=2` 时第 2 次
`maxTurns=6` 且带核实段、`verifyEvery=0` 时永不带）。

**变异自证**（三次注入，每次都先恢复再下一轮）：

| 注入 | 结果 |
| --- | --- |
| `pickVerifyTarget` 去掉 `staleDays` 判据 | 「未到天数不选」+「staleDays 可调」**2 个红** |
| 核实段之后仍保留原「不要验证」硬禁止 | 「二选一」用例 **1 个红** |
| `maxTurns` 恒 5 | 「核实轮次预算」用例 **1 个红** |

命令与输出：

```
$ bun test ./packages/core/tests/memory/extract/verify-p1-2.test.ts
 17 pass
 0 fail
 53 expect() calls
```

⚠️ 第一版实现（核实段 + 原「不要验证」段并存）被自己写的测试挡住了一次 —— 那条
`not.toContain("不要为了确认旧记忆是否仍然准确去读代码")` 直接报错。记在这里是因为它正好
印证了「追加允许」这条设计判断：**提示词里两句话冲突时，模型不会按你的意图折中**。
