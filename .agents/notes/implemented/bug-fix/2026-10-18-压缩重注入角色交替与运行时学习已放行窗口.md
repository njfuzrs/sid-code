# 压缩后重注入按尾部插桥且不跨内部 origin 合并；从 prompt-too-long 学习按路由的已放行输入上限（S5/S6）

## 决定了什么

**S5**（全库 3/3 压缩会话命中 `ROLE_NOT_ALTERNATING`）：
- `ContextManager.addMessage`：同角色相邻且任一方带内部 origin 时**不合并**，中间补一条同 origin 的反角色桥消息。根治「真实响应继承 `compact-reattach` origin 被 TUI 隐藏 / strip 剥离」。
- `appendReattachMessages`（唯一写入口）尾部感知插桥：tail 与首条同角色时先插桥，**保留末尾 ack**。
- 删 `app.ts runEmergencyFileReattach` 自带的错位补 ack（ack 被 push 在 user 之后，注释声称的保护从未生效），交给 sink。
- loop 发请求前 `stripTrailingInternalAck`：只剥请求副本末尾的内部 ack，避免 Anthropic 族把它当预填。

**S6**（配置窗口 1M、网关墙 ≈0.665×，5/5 次溢出全靠 reactive 兜底）：
- 新模块 `llm/learned-window.ts`，独立文件 `~/.sid-code/learned-input-ceiling.json`，键 `(原始 model 名, base_url)`、不经名字归一；同键 7 天内 ≥2 次溢出才写入，取较大的已放行值；TTL 7 天。
- 接线在 `query/loop.ts` 两处 prompt-too-long 分支、`reactiveCompact` **之前**（压缩会清零 `lastActualInputTokens`），学到即 `ctxMgr.setMaxTokens`，本会话生效。
- `TokenEstimator.resolveContextLimit` 新增 `learned` 来源：用户显式 `contextWindow` 最高优先不参与取 min，否则取 min；`/model` 面板标注来源。

## 放弃了什么（以及为什么不选）

- tail=user 时丢 ack、以 `user(files)` 收尾：下一轮无 `_meta` 的用户输入 / 任务通知会被合并进去，用户输入继承 origin 被隐藏。
- 写进 `learnFromError` / `contextWindow` 字段 / 能力缓存单 model 键：Anthropic 族不经 `learnFromError`；`contextWindow` 被每日目录同步覆盖；单键 + `origin-` 前缀归一会串路由。
- 一次溢出即写入：`isPromptTooLong` 是措辞匹配，误判会把窗口锁小，压缩后永远等不来上调样本。
- 叠加安全系数 / 按比例硬编码折减 0.66：违反「禁止按模型硬编码分级」，0.665 成因未证。
- 主动二分探测：一次约 ¥1.3，二分 ¥10+。
- 诚实边界：前两次撞墙仍会发生，之后同路由不再撞——不是「消灭 400」。
