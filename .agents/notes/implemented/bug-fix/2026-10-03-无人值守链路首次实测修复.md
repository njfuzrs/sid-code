# 无人值守链路（durable + daemon + webhook）首次真实运行，修掉 9 处缺陷

## 决定了什么

B43 要求在本机真跑一遍 durable 定时任务、daemon、webhook。核查和实测里查出这些问题，全部修掉：

**durable 任务（`src/cron/`）**

1. **写盘被调度锁卡住，工具却回「已持久化」**：`persistIfDurable` 只在 `hasDurableLock` 时写盘。
   三种常见情况会抢不到锁：项目里没有 `.sid-code/`（`lock.ts` 用 `wx` 写，没先 mkdir，ENOENT 被吞）、
   同项目已有会话、daemon 在场。这时任务只活在内存，会话一关就没了。
   修法：新增 `durable-store.ts`，以磁盘为唯一事实源，所有写走「文件互斥 → 读最新 → 改 → 原子写」，
   与驱动权脱钩；`lock.ts` 抢锁前先 mkdir。
2. **全量覆盖互吞**：各进程拿启动时那份内存 Map 整体覆盖写盘，后写的会抹掉别人新建的任务。修法同上。
3. **daemon 只在启动时读一次任务**：运行期间新建的任务永远不会触发。修法：驱动者每轮 `refreshDurable()` 重读。
4. **交接窗口可能双触发**：触发前改为在互斥内比对 `lastFiredAt` 认领，一次性任务认领即删除。
   驱动者身份每轮重判：daemon 起来，会话就让出；daemon 停了，会话就接回。
5. **`-p` / bridge 会话会抢驱动权**：它们没有提示词注入器，认领了任务却执行不了，等于静默丢任务。
   新增 `driveDurable: false`。
6. **项目文件自己给自己授权**：`scheduled_tasks.json` 在项目目录里（可能随 git 进来，也可能被脚本改写），
   而 daemon 会按文件里的 prompt / allowedTools 无人值守地执行。
   修法：新增 `durable-grants.ts`，创建时把内容指纹记进用户级 `~/.sid-code/state/durable-task-grants.json`；
   触发前比对，对不上就跳过并告警一次，不删任务。
7. 顺带：durable 循环任务改成「不论谁驱动都不过期」（之前只有 daemon 驱动时不过期，同一任务的寿命取决于这一刻谁在驱动）；
   `durable-projects` 的登记从 `cron_create` 挪进 `addDurableTask`，失败抛错，不再吞掉，注册表的读改写加了互斥和原子写；
   `cron_create` 回包写明真实文件路径和「触发方」，取值有四种：daemon / 当前会话 / 另一个会话 / 暂无。

**daemon / webhook（`src/daemon/`、`cli/src/command/daemon*.ts`）**

8. **只设 `SID_CODE_WEBHOOK_SECRET` 时 webhook 起不来**：CLI 解析时 `webhook: !!values.webhook` 把「没传」变成了 `false`，
   压过了 `webhookEnabled ?? secret !== ""` 这条兜底（实测 3847 端口没监听）。
   参数解析拆到 `daemon-args.ts`，没传时为 `undefined`；显式 `--webhook` 但没 secret 时不开端口。
9. **webhook job 在 fork 之前必然失败**：浅克隆（`--depth 1`）里没有 merge-base，`origin/base...HEAD` 报错，
   兜底的 `HEAD~1` 在单提交历史里也不存在。改成 `--filter=blob:none` 克隆，fetch 去掉 depth，去掉兜底，失败就报错。
   同时修了：prompt 里嵌着整个 PR diff，原来走 argv，超过 ARG_MAX 会 E2BIG，改为经 stdin 传入；
   验签通过但 body 不是 JSON 时返回 400（原来抛未捕获异常）。

**无头输出（`src/debug/logger.ts`、`cli.ts`）**

10. `config.debug` 默认为 `true`，`-p` 模式下 INFO / DEBUG 日志走 `console.log`，打到 stdout。
    daemon 落盘的 job `output` 于是是 2 万多字符的日志，而不是模型的答复。
    新增 `consoleToStderr`，无头模式开启，stdout 只留结果。

官网 `team/scheduled.md` 按实现重写了相关段落（D147–D151 一并修正）。

## 放弃了什么（以及为什么不选）

- **只给 `lock.ts` 补 mkdir**：只能修好第 1 条里的一种情况。daemon 在场、同项目多会话这两种情况依然不写盘，第 2–4 条也都还在。
  根因是「写权」和「触发权」共用一把锁，必须拆开。
- **把 durable 任务挪到 `~/.sid-code/` 下**：确实能顺带解决第 6 条，但会破坏「同项目协调」的锁语义（`lock.ts` 头注有论证），
  也和 claude-code 的 `<project>/.claude/scheduled_tasks.json` 惯例不一致。改为数据留在项目里、授权放在用户目录。
- **未授权的任务直接删除**：那是用户的文件，可能是团队有意提交的，不该替用户删。跳过加告警就够了。
- **webhook 继续浅克隆，再加 `--deepen` 循环找 merge-base**：要猜深度，复杂又不稳定。
  blob:none 实测克隆本仓约 12s，三点 diff 和指定 commit checkout 都能用。
- **在 daemon 侧从混着日志的 stdout 里找最后一个 JSON**：这是治标。所有 `--output-format json` 的消费方（`/review`、脚本）都会踩同一个坑，
  应该在源头保证 stdout 干净。

## 拿什么证明它生效了

- 单测：新增 `tests/cron/durable-persistence.test.ts`（18 条）、`tests/daemon/unattended-pipeline.test.ts`（真实 git 仓库的三点 diff、
  2MB prompt 经 stdin 传入、坏 JSON 返回 400、consoleToStderr）、`cli/tests/command/daemon-args.test.ts`。
  全量 `bun run test` 结果是 13229 pass / 0 fail；tsc 错误数和 main 一致（65 vs 65，没有新增）；lint、lint:boundary、
  lint:command-system、docs:gen-reference-check 全部通过。
- 变异自证 12 处，每处都能让测试变红：lock 不 mkdir、去掉认领比对、去掉授权检查、去掉每轮 refresh、durable 恢复按 daemon 过期、
  去掉 driveDurable、去掉 register、恢复浅克隆、prompt 改回 argv、坏 JSON 抛错、webhook 恢复 `!!`、去掉 consoleToStderr。
- 端到端（编译产物，真实模型，临时项目 `/tmp/b43-e2e/proj`，事先没有 `.sid-code/`）：
  - `-p` 建了一个 durable 一次性任务，`scheduled_tasks.json` 和 `durable-projects.json` 都落盘了；修复前这种情况不会写盘。
  - `daemon start` 之后又在别的会话里建了第二个任务。daemon **在运行期间**发现了它，14:04:01 和 14:05:01 两个任务都按时触发，
    `daemon-jobs/` 下有两份结果，任务文件随后被清空。
  - `kill -9` 之后 `daemon status` 显示「stale 锁已回收」；手写一个死 PID 的锁再 `start`，能直接启动；第二个 `start` 被拒绝。
  - 往任务文件里手工注入一个外来任务 `foreign1`，daemon 日志里出现「跳过未授权的 durable 任务 foreign1」，它没有执行；
    同一轮里本机建的任务正常执行，落盘 `output` 是 `README.md 共 **1 行**。`（纯答复，不再是日志）。
  - webhook：对真实 PR njfuzrs/sid-code#152 构造 payload，错误签名 401、无签名 401、坏 JSON 400、正确签名 202；
    `ps` 能看到 `sid-code -p --output-format json --permission-mode plan` 子进程，178.8s 后 exit 0，
    产出了完整的 code review，工作区临时目录随后被清理。
