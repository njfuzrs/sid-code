# 辅助调用归因标签回退到具体任务名，不再全塌进 agent:fork

## 决定了什么

`BilledRequest` → `recordSideCall` 的归因标签改由新的纯函数
`sideCallLabelOf(req)`（`packages/core/src/llm/billing-sink.ts`）决定，`app.ts` 的
billing 观察者改调它（原先内联 `req.callerLabel ?? "agent:" + req.agentId ...`）。

判据：`callerLabel` 属于「泛化通道标签」且 `agentId` 有值时，用 `agentId`
（`fork:memory-extract` / `fork:session-memory-update` / `fork:auto-dream`）；
其余情况沿用原语义（`title_generation` 等具体标签不变；只有 `agentId` 时仍
`agent:<agentId>`；都没有时仍 `provider-billed`）。

「泛化通道标签」是一个显式白名单 `GENERIC_CALLER_LABELS`，当前只登记 `agent:fork`
一项。原因是 `runForkedAgent` 把 `querySource` 写死成 `agent:fork`，任务身份只放在
`agentId` 里；不修的话 `getSideStats().byLabel` 只有 `agent:fork: 5` 一个桶，
记忆抽取 / 会话记忆 / 记忆巩固 / 旁路问答全塌在一起 —— 而实测一次会话里
辅助调用占了 43% 的费用，塌了就完全看不出钱是哪个任务花的。

## 放弃了什么（以及为什么不选）

- **改 `forked-agent.ts` 的 `querySource` 为任务名**（如 `memory-extract`）。否决：
  `querySource` 同时是两套判据的键 —— `BILLING_SELF_REPORTED_LABELS`
  （决定这条链是否已自报、要不要跳过入账，改错会双记或漏记）和
  `FOREGROUND_SOURCES` / 重试漏斗（决定 529 是否重试）。为改一个展示标签去动计费
  去重与重试语义，是把一个 P1 标签问题换成一个 P0 记账问题。
- **把所有 `agent:*` 都替换成 `agentId`**。否决：`agent:builtin` / `agent:custom` /
  `agent:summary` 是稳定分类标签（表示子代理类型，不是任务名），其 `agentId`
  不比标签本身更好读；替换会整体平移 `byLabel` 与 digest 的分组口径，
  而本次缺陷只发生在 `agent:fork`。
- **只在展示层（/cost、digest）拼接具体名字**。否决：`byLabel` 会随 `SessionEnd`
  落进轨迹并作为 digest 的取数源，只在展示层拼会让「界面」与「轨迹」两处对不上；
  判据只能有一份实现。

## 拿什么证明它生效了

- 新增 `packages/core/tests/llm/side-call-label.test.ts`（5 个用例，12 条断言）：
  fork 回退到 `agentId`、具体标签不变、其余 `agent:*` 不替换、只有 `agentId`
  时退化、都没有时 `provider-billed`。`bun test ./packages/core/tests/llm/side-call-label.test.ts`
  → `5 pass / 0 fail`。
- **变异自证**（CLAUDE.md 要求）：把 `sideCallLabelOf` 里的泛化标签回退那一行删掉后
  重跑，断言输出 `Expected: "fork:memory-extract" / Received: "agent:fork"` 并 fail；
  恢复后复跑 5 pass。断言确实咬住了旧逻辑，不是恒绿。
- 相关测试集（billing-sink-structural / billing-usage-sink-ticket /
  billing-self-reported-labels / stream-attribution-s10 / side-call-observability /
  p2-side-call-session-baseline + 新文件）一起跑：`55 pass / 0 fail`。
  其中 `billing-self-reported-labels` 是静态门禁（既 import `recordSideCall`
  又走漏斗的链必须在白名单里），本次不动 `querySource`，它仍然绿。
- **真实轨迹对账**（取证会话 `20261110-142303-21c3a481`，截断到
  `2026-11-10T06:28:50Z`，37 条 `BilledRequest`）。用两条算法分别算 byLabel：

  ```text
  旧：provider-billed 31 / agent:fork 5 / title_generation 1
  新：provider-billed 31 / fork:session-memory-update 3 / fork:memory-extract 2 / title_generation 1
  ```

  5 条 fork 的事件全是 `caller=agent:fork` + `agent_id=fork:*`，新算法逐条落到
  `fork:session-memory-update`（3 条）/ `fork:memory-extract`（2 条），
  与本文档 2.3 节的时间线一一对应。非 fork 条目（主循环 31 条 + 标题生成 1 条）不变。
