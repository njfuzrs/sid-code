# plan 模式放行只读 bash，审批时当场选执行模式

## 决定了什么

PR-3（M4 + M5）落地两件事，改的都是「plan 模式在用户侧的手感」，不碰权限判定的其它层。

**M4：plan 放行只读 bash（`packages/core/src/permission/checker.ts` 的 `checkPlanMode`）**

在「只读工具直接放行」之后加一条：`bash` 且 `isReadOnlyCommand(command)` 为真 → 放行。
plan 的承诺是「不改任何东西」，而 `git log` / `git diff` / `ls` / `rg` 不写任何东西。
此前 bash 不在只读工具名单里，规划阶段最常用的命令全被拒，模型只能改用 read/grep 去拼
`.git` 目录——与 plan「先摸清楚再动手」的目的相反。

同时改三处文案/提示：拒绝文案加「（bash 只允许只读命令，如 git log / ls / rg）」
（让模型知道墙在哪，对齐 2026-08-29 headless 盲试的教训）、`plan/prompt.ts` 的
full / sparse 两档提示词、`website/use/permissions.md` 两处 plan 说明。

**M5：审批框当场决定批准后的权限模式（`DialogManager.tsx` + `app.ts` + 新增 `plan/approval-decision.ts`）**

「批准并执行」拆成三项，`approve` 决策串扩展成 `approve:<acceptEdits|auto|previous>`：

- `y` 批准 → `acceptEdits`（保持最常用路径）
- `m` 批准 → 沿用进入 plan 之前的模式
- `a` 批准 → `auto`（仅当分类器接线可用**且**未被企业策略禁用时才出现）

解析与校验落在 core 的纯函数 `parsePlanApprovalDecision`：非法值、`plan`、被
`disabledModes` 禁用的档位一律**降级为「沿用进入前的模式」**，不让审批失败，也
不让对话框成为绕过企业策略的后门。批准消息（`buildPlanApprovedMessage`）带上最终
生效的模式，模型据此判断「这次 edit 要不要先问」。

## 放弃了什么（以及为什么不选）

**1. 没在 `enforceModeHardConstraint`（Step 9 出口总闸）里另写一份只读判断。**
文档要求「总闸用同一个函数」，我照做——但实测发现光靠这一条会开一个口子：
不传 `tool` 的调用路径（SDK / 嵌入 / 测试）走 Step 5.5 时**不执行**只读读路径校验，
于是 `cat /etc/passwd` 一路走到 Step 9 被新分支放行，而 `default` 下它是 ASK。
**比 default 宽 = 违反 M4 的硬约束。** 解法是给放行加一道资格判据：`req.toolName === "bash" && tool`。
资格来自「工具自己确认过只读」（Step 5.5 已判只读并校验过读路径），权限层不替它猜；
不传 tool 时退回原拒绝，方向是多拒一条而不是多放一条。

**2. 没有复用 `shared/HotkeyChoiceList` 重写整个 PlanApprovalDialog。**
`src/ui/CLAUDE.md` L4-E 要求「新增确认类弹窗一律复用该组件」。这个弹窗不是新增的，
而且它有两个 `HotkeyChoiceList` 不支持的形态：「其他…」自由输入行、以及「拒绝，附修改意见」
的反馈输入态。所以按 L4-E 的**实质要求**改造既有手写键盘处理：键位表集中到 `options` 的
`hotkey` 字段、匹配统一走 `matchHotkey`（大小写敏感）、三条路径（↑↓+Enter / 数字 / 字母）并存。
没有沿用原来的 `key.name === "y"` 硬编码分支。

**3. 没做 auto 选项的「可配置隐藏」。** 只按「分类器可用 + 未被策略禁用」显示，
不新增 `showAutoInPlanApproval` 之类的开关——多一个配置项就多一条要测的分支，
而 `disabledModes` 已经覆盖了企业管控的真实需求。

## 拿什么证明它生效了

**变异自证（两条，都是先改坏再恢复）：**

- 去掉 `checkPlanMode` 里 if 的 `&& tool` → `pipeline-order-matrix.test.ts` 的
  `plan + 只读但不传 tool → 拒绝` 变红（1 fail）；恢复后 120 pass / 0 fail。
- 去掉 `isApprovableExecMode` 里的 `isModeDisabledByPolicy` → `approval-decision.test.ts`
  的「企业策略禁用 auto 降级」「策略禁用 acceptEdits 同样降级」两条变红（2 fail）；
  恢复后 13 pass / 0 fail。

**真实 checker 探针（不是靠读代码推断）：**

```
plan + 传 tool stub（= 生产路径）：
  ALLOW  git log --oneline -5 / ls -la / cat README.md      (step=5.5)
  ASK    cat /etc/passwd  → 「只读命令读取工作区外」        (step=5.5，读路径校验先命中)
  DENY   npm install x    → 「计划模式下只允许只读操作（bash 只允许只读命令…）」(step=9)
plan + 不传 tool：git log → DENY (step=9)
deny-write + ls（传 tool）：DENY（M4 只放宽 plan）
```
