# 命令系统批次 1：补全不吞输入、保护名覆盖全部来源、模板流水线先注入后参数

## 决定了什么

三组，关注点互不相交，同属「坏了但没有任何提示」：

1. **D4 + D5（补全）**：`mid-input.ts` 新增三个纯函数 `resolveSlashCompletionTarget` /
   `applySlashCompletion` / `canSubmitSlashCompletionDirectly`。补全 state 带 `replaceFrom`
   （检测侧早就算好的 `startPos`），中间位置只替换 token；Enter 直接提交只在「单行、整条输入就是一个命令 token」时成立。
   斜杠补全改按光标所在行判定，与 `useAtCompletion` 同口径，不再把非首行光标钳成 `firstLine.length`。
2. **D7 + D9（注册表）**：保护名单下沉到 `core/src/command-contract/protected-names.ts`，
   检查点放在 `UnifiedCommandRegistry.dedupe`。非 builtin 来源的命令名撞保护名就丢弃并 warn，别名撞保护名只丢该别名。
   plugin / MCP 不再另起一套只比 name 的合并，改为 `getCommands` 里把静态结果与动态来源一起再过一次 `dedupe`。
   命令名撞已被占用的别名同样丢弃并 warn，同一条 warn 按文本去重。
3. **D14 + D15 + D16（`custom.ts` 模板流水线）**：先在**原始模板**上切出 `@{}` / `!{}` 段，注入都处理完之后，
   只对字面文本段做参数替换。文件注入的分档是：cwd 内普通文件直接放行；cwd 外（先 realpath 再判断）或命中
   `matchesSensitivePath` 的走 `requestUserConfirmation`，fail-closed；读取上限 10MB，超出截断并提示；每次读取留 info 日志。
   占位符只认 `$1`..`$9`，`$0` 和越界的保留字面量，切分复用 bash parser 的 `tokenize`
   （新导出 `splitShellWords`），单趟替换。

## 放弃了什么（以及为什么不选）

- **保护名检查放进各 loader**：同一段检查要写 N 遍，第 N+1 个来源出现时必漏。修复前正是这个形态
  （只 custom 一处）。`custom.ts` 的加载期早拦保留，只是因为 legacy 回退路径（`cli.ts`）不经注册表。
- **D9 只给 `existingNames` 补别名（方案 ①）**：两套合并口径仍然并存，也拿不到 warn 和保护名检查。
  dedupe 的成本是 O(n·别名数)，命令只有几十到上百个，可以接受。
- **D14 靠转义用户参数**：转义 shell 参数是众所周知会写错的路。代价要明说：`@{$1}` 不再生效。全仓 grep 过，
  只有博客 §8.2 提到这种写法，没有任何模板实际在用；博客的修订归批次 3（§18）。
- **D15 所有文件注入都弹确认**：cwd 内普通文件是主用法，全部弹确认会逼用户养成无脑点「是」的习惯。
- **D16 越界时报错**：可选参数用法会因此无法使用。保留字面量就足以让人看出缺了什么。
- **补全逻辑留在 InputArea 里改**：要测 React 组件得起渲染，所以把判定与应用抽成纯函数直接单测。
