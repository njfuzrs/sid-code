# 插件缺陷 36–43：缓存分槽、installed.json 逐条校验、来源标记与错误可见性收口

## 决定了什么

按《20260927-SDK与插件-顺着sc-17核出的缺陷》的缺陷 36–43 逐条修，一个 PR 内交付：

- **36（`loadPluginHooks` 的 memoize 忽略 `hookSystem`）**：单 slot `memoize` 换成
  `WeakMap<HookSystem, Promise<HookDiagnostic[]>>`。每个 HookSystem 实例拿自己的注册结果，
  `clear()` 换成重新赋值一个空 WeakMap（WeakMap 不可遍历）。失败仍不缓存。
  前提不再是「靠注释维持」：`new HookSystem` 在仓内已有 3 个实例
  （`app.ts` / `agent/agent-hooks.ts` / `command/hooks-cli.ts`），分槽后不必靠断言兜底。
- **37（`installed.json` 逐条 entry 零校验）**：新增 `installedEntryIssue(raw)`，按
  `InstalledPluginEntry` 的 6 个必填字段（name/path/source/version/installedAt/enabled）
  校验类型，`external` / `market` 存在时也校验。`readInstalledPlugins` 跳过不合格条目、
  记 warn，并通过可选回调交给 loader 转成 `PluginLoadResult.errors` 里的 `generic-error`。
  `assemblePluginLoadResult` 的 `entry.source.endsWith` 另加显式 `typeof === "string"` 双保险 ——
  这一行原来在 assemble 里抛出去就是整个插件系统不可用。
- **38（`registerBuiltinPlugin` 无重复注册防护）**：改成先到者占名 + warn，返回是否写入。
  与 `command/registry.ts` 的 `registerAlias`、`loader.ts` 的 `mergePluginSources` 策略一致
  （同仓另两个注册表都是「先到者优先 + 报错」，只有这里是 last-write-wins）。
- **39（`addPluginScopeToServers` 只做浅拷贝）**：新增 `cloneMcpServerConfig`，深拷
  `args` / `env` / `headers` / `includeTools` / `excludeTools` / `oauth`。作用域隔离
  不再只做到一层。
- **40（`BUILTIN_PLUGINS` 生产恒为空）**：**不接线、不删除，按「架构脚手架」诚实标注**。
  `builtin.ts` 文件头与 `getBuiltinPlugins` 注释写明：生产零注册、`isBuiltin` 恒 false、
  下游分支是预留分支，能力盘点按「空注册表」记账（判据是数写入点，不是数读取点）；
  任何注册必须在 `loadAllPlugins()` 第一次调用之前。补一条「无注册时返回空数组」测试。
- **41（插件 skill 被硬编码标成 `source="project"`）**：`ExtensionSource` 增加
  `"plugin"` 取值；`loadPluginSkills` 的 `scanSingleDir` 改传 `"plugin"`，删掉
  `skill.source = "project"` 的覆盖；`/skills list` 面板新增「插件 (plugin):」分组并从
  用户级/项目级里排除。`isTrustedSkillSource` 同步把 `source === "plugin"` 判为不可信。
- **42（`scanSingleDir` 丢弃 `scanDir` 的 errors）**：签名改为返回
  `{ files, errors }`；`loadPluginSkills` 把扫描错误转成
  `{ type: "component-load-failed", component: "skills" }` 记录到组件错误清单
  （缺陷 22 里这个错误类型产生点为 0，这里补上一处真实产生点）。
- **43（`isSourceAllowedUnderLock` 生产消费者为 0）**：接线到
  `ExtensionLoader.scanWithResult` 的 `mergeFiles` —— 逐文件复核来源白名单。
  原先只有「按层跳过」（锁定时整个不扫 user/project），这是按来源过滤的兜底，
  能覆盖 additional dirs / 插件 skill 等「目录布局与来源不一一对应」的未来路径。
  与 41 配套：插件 skill 的 source 现在是 `plugin`（受信），锁定 skills 面时不会被误拦。

## 放弃了什么（以及为什么不选）

- **36 没有选「加一条 `if (registeredTo !== hookSystem) throw`」**：文档给了这个选项，
  但它把可用性变成「要么对、要么崩」。分槽缓存成本是每个实例一份 Promise，收益是
  多实例场景直接正确（隔离 agent 将来接插件 hook 不需要再改这里），不需要靠断言维持不变量。
- **37 没有在 `loadInstalledPlugins` 里逐条校验而不动 `readInstalledPlugins`**：那样
  `assemblePluginLoadResult` 读注册表算 `builtinOverrides` 时仍会碰到坏条目，而它是
  更早的一处解引用。校验放在唯一的读入口，所有读者（operations / market / auto-update）
  一起受保护。副作用是写回时坏条目会被清洗掉——这是有意的（它们本来就加载不了），
  已写进注释。
- **38 没有选 throw**：注册冲突在运行时无法恢复，throw 会让整个插件系统起不来。
  同仓 `registerAlias` 的选择是「保留先注册者 + warn」，跟随它，并把「是否写入」
  作为返回值给调用方判断。
- **40 没有删除内置插件层**：`registerBuiltinPlugin` 通过 `plugin/index.ts` 导出，
  属于公开扩展 API；删掉是破坏性变更。也没有「随便塞一个插件进去」让它看起来在跑 ——
  内置插件的内容是产品决策（对齐 CC 的 `initBuiltinPlugins()` 空实现，本就是预留脚手架）。
  选择诚实标注 + 修正盘点口径，并保留未来接线的入口。
- **41 没有只在面板层按 `loadedFrom === "plugin"` 分组、不动 `source`**：那样
  `ADMIN_TRUSTED_SOURCES` 里的 `"plugin"` 永远匹配不上实际值，缺陷 43 一旦按来源过滤，
  插件 skill 会被当成项目来源拦掉。两个字段的职责边界必须先划清（`source` = 策略判据，
  `loadedFrom` = 加载位置），否则修一个引入另一个。
- **43 没有删掉 `isSourceAllowedUnderLock`**：文档给的另一个选项是「明确标注备用」。
  删掉会让将来「按来源过滤」这条路径无从接入；接线成本是一个同步判断，且未锁定时
  立即返回 true，零额外开销。
- **42 没有新增 `scanSingleDirWithErrors` 并行 API**：全仓只有 `loadPluginSkills` 一个
  调用者（另一处是注释），两个签名并存会让下一个人选错。直接改签名。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/plugin/ ./packages/core/tests/extension/ ./packages/core/tests/skill/`
  → **694 pass / 0 fail**。新增/加断言覆盖：
  - 36：两个 HookSystem 各自注册自己的插件 hook（旧实现第二个实例 0 个 hook）；

    把坏条目报成 `generic-error`（旧实现抛 `Cannot read properties of undefined`）；

    两个插件共用一份配置互不影响；
  - 40：无注册时 `getBuiltinPlugins()` 返回 `[]`；
  - 41：插件 skill 的 `source` 与 `loadedFrom` 都是 `plugin`；
