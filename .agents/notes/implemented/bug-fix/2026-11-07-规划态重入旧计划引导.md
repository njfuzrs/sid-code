# 重入规划态时把「上一份非空计划」交给模型判断，并落 `stale_plan_found` 计数

## 决定了什么

落地《20261103-05H2-规划态生命周期收口-落地方案》§一的缺口 1（P1）：`enter()` 从前只做状态迁移，
不判断同项目下上一次留下的计划还作不作数。现在：

- `PlanModeManager.enter()`（`packages/core/src/plan/state.ts`）在占位本次计划文件**之前**扫
  `sidPaths.plansForProject(project)`，取「有内容、`mtime` 最新」的那份 `.md` 记为旧计划；
  与本次占位到的路径相同时不算（兜底路径可能返回已存在的文件）。
- 判据复用 `PlanModeManager.hasPlanContent`，与 `enter-plan-mode` 的 `planExists` 同口径：
  0 字节占位与只有空白字符的文件都算「没写」。
- `buildPlanModePrompt`（`packages/core/src/plan/prompt.ts`）新增可选第三参数 `stalePlanPath`，
  命中时在「计划文件」小节后插一段**一次性**引导：先 `read` 旧计划 → 判断与当前任务的关系 →
  二选一（无关就覆盖重写本次路径；相关就搬有效部分、删过时段落）。
- 只注入一次：路径存在 `PlanModeManager.stalePlanPath`，由 `enter_plan_mode` 的 `tool_result`
  带走；`exitPlan()` 清空。不新增第三条注入通道（`buildPlanModeReminder` 的 full/sparse 分档不动）。
- `PlanTransitionMeta.stalePlanFound` + `PlanTransition` 落盘 `stale_plan_found`（`packages/cli/src/app.ts`），
  `false` 也落——分母是全部 enter 类跃迁。

## 放弃了什么（以及为什么不选）

- **按 mtime 自动删旧计划**：计划是资产还是产物尚未定论（剖析 5.9 候选 6），删除不可逆；
  先只做提示，把处置权留给模型和用户。
- **做成每轮提醒**：`prompt.ts` 已有 full/sparse 两档节流，再加一条会稀释「当前在规划态」
  这个信号；过期判断也不像只读约束那样每轮都需要。
- **用「文件存在」判旧计划**：`reservePlanFile` 进入时就 `O_EXCL` 占一个空文件，进入后
  「存在」恒真；用它判断会把本次自己的占位也算成旧计划。
- **在 `permission_mode` 入口也注入提示**：那条路（`--permission-mode plan` / settings）
  没有 `tool_result` 可返回，硬加就得新开一条注入通道；本次只落埋点，不解决它的提示问题。
- **按 session 过滤并行会话的计划**：计划文件名里没有 session 标识，硬猜只会引入假阴性
  （漏掉真正该提示的那份）。误报的代价只是多读一份文件，可接受。
- **只记 `true` 不记 `false`**：那样只能回答「撞上过几次」，算不出「进入多少次里撞上过」，
  而后者才是判断这条引导值不值得留的依据。
