# 多代理五项 P2：工具区不在任务中途变长、停滞看字节数、团队任务按任务合并、深度跨进程、ESC 不杀后台子代理

## 决定了什么

来源：`docs-research/sid-code/bugfixes/todo/20260926-多代理-顺着sc-06核出的缺陷.md` 的 F2 / F4 / F6 / F8 / F9。

- **F2** `tool/late-mcp-freeze.ts` + `query/loop.ts`：延迟加载**关闭**时，queryLoop 开始时给 MCP 工具名拍快照，本次 loop 只发这一批，中途连上的 MCP 工具从下一条用户消息起可见。延迟加载开启时不冻结（MCP 本就走 deferred 池，冻了会挡住 tool_search 激活）。只冻 MCP，内置工具随模式变化的 isEnabled 不动。
- **F4** `task/shell-task.ts` + `disk-output.ts`：增长判据改为文件字节数（新增 `getTaskOutputSize`），提示词匹配仍用 1024 字节尾部。判据抽成纯函数 `stepStallCheck`。
- **F6** `task/team-task-store.ts`：落盘改为「mkdir 文件锁 → 重读磁盘 → 按任务 `updatedAt` 合并进内存 → 写回」；新增 `claimNextTeamTask`，在同一把锁里先同步再认领，`swarm/team.ts` 的认领循环改用它。合并逻辑 `mergeTeamTasksFromSnapshot` 在 structured-task-store。
- **F8** `agent/depth-context.ts` + `sub-agent.ts`：spawn 时经 `SID_AGENT_DEPTH` 把子代理自身深度传进子进程，`getAgentDepth()` 以它为 ALS 缺省值。
- **F9** `agent/tool.ts`：后台子代理的 abort 转发按 reason 分流，`user-cancel` / `midturn-preempt` / `sibling_bash_error` / `race-settled` 这四种轮级 reason 不转发，其余（会话超时、团队硬超时、未知 reason）照转并保留 reason。

## 放弃了什么（以及为什么不选）

- F2 不缓存 `description()`（会让模型看到过期工具集）；不把 MCP 强制改走 deferred（用户显式 `toolSearch:false` 就是要全量直出）。冻结的粒度是「一次 loop」而不是整个会话：会话级冻结等于 MCP 晚到就永远用不上。
- F4 不调大 `tailBytes`：阈值多大，文件超过它之后问题照旧。
- F6 不加进程内锁（问题不在单进程并发）；不改成追加日志（改动面太大，按任务合并已经能消除「整份旧快照覆盖」）。锁等 2s 拿不到就无锁写入并 warn：锁是一致性增益，不能让调度卡死在陈旧锁上。
- F8 不在子进程里扫消息历史推断深度（会被压缩改写，正是博客 §5.6 反对的锚点）。
- F9 不删监听器：它是后台任务响应会话级中断的唯一通道，删了会留下孤儿。

- 变异自证：去掉 F6 锁内的 `syncFromDisk` 后跨进程测试 2 条红；把 F9 的判据改成 `if (false)` 后 1 条红。还原后全绿。
