# 模型元数据体系收尾：D3 剩余调用点 + D6/D7/D9/D10 四个次生缺陷

方案文档 `docs-research/.../20260818-模型元数据体系重构-数据源选错档位与投票规则反向-彻底修复方案.md`
的 PR9–PR13，合并成一个 PR 交付（五项互不耦合、全是 P1/P2 收尾项，各自 diff 都很小）。

## 决定了什么

**PR9（D3 剩余调用点）—— 抽共用层而不是复制三遍。**
`fallback.ts` 两处钳制与 `query/loop.ts` 截断续写 Stage 1 都用 `lookupRegistry(x)` 取
`maxOutputTokens`，那是个内含六级模糊瀑布的函数，排在采集缓存之前 → 手写表猜出来的值
盖掉采集到的真值。新增 `packages/core/src/llm/model-lookup.ts`，把
「registry 精确 → 采集精确 → registry 模糊」三段收成 `resolveRegistryMaxOutputTokens`。

放在**新模块**而不是塞进 `model-registry.ts`：后者是零 import 的纯数据表
（`telemetry/cache-bench-core.ts:15` 的不成环判断依赖这个性质），塞进去就破了。

`cache-bench-core.ts:224`（协议判定）与 `model/model.ts:279`（纯展示）按方案**不改** ——
它们与窗口/上限无关，拆 exact/fuzzy 无语义收益。`lookupRegistry` 兼容包装因此保留。

**PR10（D9 OpenRouter 侧过滤）—— 落它是为了对称性，不是为了修当下的错数字。**
三个源里 OpenRouter 是唯一没有非对话过滤器的。补上 `architecture.output_modalities`
判据（与 models.dev 的 `modalities.output` 同形）。

⚠ **实测它今天命中 0 条**：2026-08-21 拉 OpenRouter 全量 417 条，output 模态全部含 `"text"`。
方案文档说这里有污染，实测不成立 —— 注释里如实标注了这一点，没有写成「修掉了 N 条污染」。

**PR11（D7 并发写）—— 只补原子写，不补重读。**
方案 §6.2 原文说两个模块都缺「写盘前重读」，但它自己的 #64 修正块已推翻：
`gateway-pricing.ts` 两个写点本来就是 read-modify-write，缺的是原子写
（`renameSync` 全文 0 命中）。与 `model-capabilities.ts` 正好互补。
新增 `writeCacheFileAtomic`，两个写点（`recordFailure` / `syncGatewayPricing`）共用。

**PR12（D6 网关字段）—— 先做职责边界修订，再加字段。**
`gateway-pricing.ts` 头部原写「只采价格，protocolKind 等能力字段本模块绝不触碰」，
按那句话加 `supported_endpoint_types` 是违规的。边界改成
「采**端点自报的一切事实**（价格 + 支持的协议类型），不采**模型固有能力**（窗口 / 输出上限）」。
判据从「叫什么名字」换成「谁自报的」。

同时把否定性结论写进注释：该网关 `/v1/models` 与 `/api/pricing` **两个接口都不提供
contextWindow**（实测 `/v1/models` 76 条的键并集只有 5 个字段，无一个 capability 字段），
所以 D6 不能当 D1 的替代方案。

字段**只采集不消费**：协议族判定仍走 `classify.ts` 正则。切换判定要处理
「网关词汇 → protocolKind」映射与缓存过期降级，是另一件事。

**PR13（D10 覆盖率口径）—— 绝大部分已随 PR3/PR7 落地，本次只补两处漂移。**
`scripts/catalog-coverage.ts`（278 行）与带日期的覆盖率注释都已存在，
`package.json` 里也已有 `catalog:coverage`。本次修的是我自己这次改动造成的注释失真：
① 过滤器枚举补上 OpenRouter；② 「`/api/pricing` 没有能力字段」这句话在 PR12 之后不再准确
（它确实带 `supported_endpoint_types`），改成说清那个字段为什么**不能**当对话模型判据。
方案要求的「litellm 1874 键 → 3040 键 / 裸名去重 1874」口径修正，代码里已经是 3040 口径。

## 放弃了什么（以及为什么不选）

**放弃「output 必须恰好是 `["text"]`」这个更严的 OpenRouter 判据。** 实测会误杀 15 个
**合法对话模型**：`openai/gpt-audio`（`["text","audio"]`，ctx 128K）、
`google/gemini-3-pro-image`（`["image","text"]`，ctx 131K）、`openai/gpt-5-image`（ctx 400K）等。
「输出里有别的模态」与「不是对话模型」是两件事。判据必须是黑名单（数组存在且不含 text 才拒），
缺字段一律放行 —— 与另两个源的「未知不等于非对话」同口径。

**放弃拿 `supported_endpoint_types` 替换 `catalog-coverage.ts` 的名字判据。**
看起来它比正则启发式权威，但实测 10 条非对话条目**全部同时带 `openai`**
（`["openai","embeddings"]` / `["openai","jina-rerank"]` / `["openai","image-generation"]`），
用它当判据会把 embedding 模型判成对话模型，直接污染覆盖率分母。

**放弃给 `gateway-pricing.ts` 引跨进程 flock。** 价格缓存是纯优化项，真撞上丢更新的后果
只是下次 TTL 到期重采，不产生错数字。残留窗口在注释里如实标注了、没声称为零。

**放弃把三段阶梯合并进 `token-estimator.getMaxOutputTokens` 与
`config.resolveMaxOutputTokensForModel`。** 它们多一层「用户 `availableModels[]` 声明」，
那一层按**别名**查（同真名的两个端点上限确实可能不同），与新函数按**真名**查的键口径不同，
合并会把两种键搞混。

**放弃 stacked PR。** CONTRIBUTING.md 有实测教训：base 不是 `main` 时 CI 一次都不跑，
自动改 base 发的是 `edited` 事件，必需检查恒 pending、不报红只转圈。五项合一个 PR、base 直指 main。

  三源 min（旧）  contextWindow  n=77  一致 33 (42.9%)  低估 44

三项全部达标，且 min 那一行仍在同一张表里作为对照 —— 曲线动了能归因。

**新增门禁全部做过变异自证**（CLAUDE.md：防线的验收判据是「真被触发过」）：

| 变异 | 结果 |
| --- | --- |
| 删掉 OpenRouter 过滤器 | 2 fail（丢弃类 + 投票污染类） |
| 过滤器改成白名单（恰好 `["text"]`） | 4 fail（含误杀 15 个对话模型那条） |
| `writeCacheFileAtomic` 退回直写 | 2 fail |
| `computeVersion` 漏掉 `supportedEndpointTypes` | 1 fail |
| 三段阶梯退回单次 `lookupRegistry`（模糊排到采集前） | 2 fail |

⚠ **第一版原子写断言是个 false gate，已换掉。** 原来断言「不残留 `.tmp`」——
直写路径也不会留 `.tmp`，所以退回直写后**照样 40 pass / 0 fail**。改成断言
**目标文件 inode 必须变**：`rename` 是替换上去（换 inode），直写是原地 truncate + 写
（保持 inode，那个窗口正是半截 JSON 的来源）。换判据后变异立刻抓到 2 fail。
这一条记在测试注释里，防止下一个人改回去。

**外部数据全部实测核过，不是照抄方案文档**（自检第 4 问）：
OpenRouter 417 条 / 该网关 `/api/pricing` 68 条的 `supported_endpoint_types` 7 种取值 /
非对话条目全部同时带 `openai`。方案文档说 OpenRouter 有非对话污染，实测不成立，已在注释纠正。

**这次的 trade-off（自检第 3 问）**：PR12 用「更安全 / 可观测」换了一点「更省」——
`supportedEndpointTypes` 进了内容指纹，老用户首次升级会多一次写盘（价格没变但字段变了）。
这是必要的：不进指纹就会走「版本未变，跳过写盘」，新字段永远进不了磁盘，
表现为内存里有、日志显示采集成功、下次启动又没了。已有专门用例锁住。
