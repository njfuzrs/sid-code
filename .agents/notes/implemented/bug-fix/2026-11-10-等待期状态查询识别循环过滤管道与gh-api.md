# 等待期状态查询拦截的匹配面扩到循环、过滤管道与 gh api

## 决定了什么

`task/status-query-commands.ts` 的 `matchStatusQuery` 不再只认「最后一段简单命令」，
现在认三种最常见的查询写法（N3）：

1. **循环展开**（`for … do gh … done` / `while` / `until`）：`findLoop` 从扁平段列表里
   识别单条非嵌套循环，循环体逐段过命令表；循环头（`for x in …` / `do` / `done`）视为无害。
   `for pr in 694 696 697` 这类全数字字面量列表把变量替换成每个值分别匹配，
   subject 取排序去重的 `gh:pr:694,696,697`；非字面量列表（`for pr in $(gh pr list …)`)退化成
   `gh:pr:multi`（刻意不是 `current` —— 那会和「查当前分支的 PR」撞同一个对象）。
2. **只读过滤管道**（`head` / `tail`（非 `-f`）/ `jq` / `grep` / `wc` / `sort`（非 `-o`）/
   `cut` / `awk`（无 `-i`、无 `>`））：最后一段是纯过滤时向前找查询段；
   过滤段**不限定位置**（962011a6 的主流写法是 `gh api … | head; echo; gh pr view …`）。
   会写/会持续等的（`tee` / `tail -f` / `sort -o` / `awk 'print > f'`）一律不算。
3. **`gh api` 状态端点**：只认 GET，路径匹配 `repos/<o>/<r>/commits/<ref>/(check-runs|check-suites|status|statuses)`
   与 `repos/<o>/<r>/actions/runs[/<id>][/jobs]`；带 `-X`/`--method` 非 GET 或
   `-f`/`-F`/`--field`/`--raw-field`/`--input` 一律不认（这些会让 gh 推导成写请求）。
   新 family `gh_api_checks` / `gh_api_runs`；subject 用 `gh:commit:<ref>` / `gh:run:<id>`。

另补两处小口子：`HARMLESS_COMMANDS` 加 `date`（轮询打时间戳，真实轨迹有 `sleep 30; date '+%H:%M:%S'; gh pr view …`）；
`isVolatileKey` 加 `_at` / `_url` 后缀（GitHub REST 是 snake_case，`started_at` / `details_url`
不剥掉的话 gh api 查询的签名永远不相等、拦了等于没拦）。

三条安全边界一条都没放松：没有**声明的**等待源时一次都不拦（判据 1 仍在 `status-poll-guard.ts`）；
距上次实际执行 ≥120s 放行一次探测；含写操作的复合命令一律放行
（循环体里出现 `gh pr merge` / `git push` / `bun test` 都照旧 null）。

## 放弃了什么（以及为什么不选）

- **命令替换赋值**（`SHA=$(gh pr view N --json headRefOid -q …) && gh api …/$SHA/check-runs`）：
  subject 依赖运行时变量值，签名不稳定；且 63 次里大多是一次性取 SHA，不是轮询。不修。
- **多行循环 / 多行命令**：`flattenCommand` 遇换行直接放弃（原设计如此）。放松会连带覆盖
  heredoc、`bun -e '…'` 这类含换行的长命令，误判面变大，而实测只有 12 条仍漏。
- **在 `parser.ts` 里加 `for_statement` 节点**：parser 是权限判定的上游
  （`isReadOnlyCommand` / `extractPathsFromCommand` / checkpoint 共用），新增节点类型要同步
  每一处 switch；而本模块只需要「是不是状态查询」，扁平段列表够用。风险与收益不成比例。
- **`gh api …/actions/jobs/<id>`（job 详情）**：文档只要求 commits/* 与 actions/runs*。
  962011a6 里那两次是拉日志（`> file`）不是查状态，按写重定向已放行。
- **混合「查询 + 其他工作」的命令**（`gh pr view …; git fetch; git log`）：`git log` 等不在
  `HARMLESS_COMMANDS`，整条放行。这是刻意的保守方向 —— 这类命令不是纯轮询。

（同一条两次 / 列表顺序不同 / 前置 `cd` 不同 → 同一 signature）。
