# P2 五项对齐修复：xhigh 不再在子代理塌缩、workflow 预算接共享池、/loop 认尾随 every、phase 对账、团队可常驻

## 决定了什么

对照 `20-2026新功能与生态演进` 方案里的 P2 五项，按源码现状逐项修（不是照文档的旧路径改）：

- **P2-1** 子代理 effort 走能力层。新增 `agent/sub-agent-effort.ts` 的 `buildSubAgentEffortParams`，`executeInner` 与 `executeCustomInner` 两处手写的「xhigh|max → max，其余 → high」都换成它。它复用主循环同一套 `resolveEffortCapability` + `applyToSendParams`：GPT-5.6 族 xhigh 原样透传，DeepSeek/GLM/o-series/Grok 由各族 applier 钳制，原生 Claude manual 路径 xhigh 是独立的 32K 预算档。思考预算上限经 `maxThinkingTokens` 交给 applier，不再粗暴降到 high。未指定 effort 仍关 thinking（既有行为）。
- **P2-2** workflow 预算接共享池。`WorkflowTool` 新增 `setSessionOutputTokensReader`，`app.ts` 的 `wireSubAgentUsageSink` 注入 `sessionState.getTotalUsage().outputTokens`（主循环 + 全部子代理的 flow 累计）。子代理用量在 `onResult` 里同步回写 SessionState，预算硬门在下一次 `agent()` 才检查，所以直接读会话总量就是池子，不加本 run 的 `outputTokens`（那会算两次）。未注入读口时退化为只计本 run。`types.ts` 的 `spent()` 注释从「池子共享」的悬空断言改成「语义由宿主的 spentReader 决定」。
- **P2-3** `/loop` 认尾随 every。新增 `extractTrailingEvery`，`review PRs every 2 hours` 解析成 2h 间隔 + 任务正文，与前导间隔 `/loop 5m task` 走同一段建任务逻辑。`every` 必须是句尾独立词，任务正文里的 every 不误判。不整除的间隔仍降级提示，不建任务。
- **P2-4** `phase()` 与 `meta.phases` 对账。`WorkflowRuntime` 接 `declaredPhases`，未声明标题告警但照常分组（同一标题只告警一次）；`strictPhases` 或 `SID_CODE_WORKFLOW_STRICT_PHASES=1` 时抛 `UndeclaredPhaseError`。没给声明列表时不对账，既有行为不变。内联子 workflow 经 `withDeclaredPhases` 用自己的 meta 对账，跑完恢复父声明。
- **P2-5** 团队可常驻，默认关闭。`TeamOptions.resident` 开启后，成员做完活不退出，挂起等新任务、`shutdown_request` 或 signal abort；`run()` 在「全部任务完成且全员空闲」时自动给挂起成员发 shutdown 收尾。挂起期间 drain 到的非 shutdown 消息（如 `plan_approval_response`）回灌收件箱，不丢。`mailbox` 的 kind 扩出 `shutdown_request/response` 与 `plan_approval_request/response`，`team_message` 同步。默认 `resident` 不传 = 一次性批，所有现有调用方行为不变。

## 放弃了什么（以及为什么不选）

- **P2-1 不让子代理走主循环的 `getEffortSetting` 运行时档位。** 子代理的 effort 是调用方显式传入的（workflow `agent({effort})`、skill frontmatter），没有「跟随会话 /effort 切换」的语义。接运行时档位会让子代理的推理强度在执行途中被用户的 `/effort` 改掉，和「任务声明什么档位就用什么档位」矛盾。只修「显式档位被手写映射塌缩」这一层。
- **P2-1 不在子代理里再手写一份五档映射。** 之前的 bug 就是两处手写映射互相漂移、又都绕过能力层。新增一族的钳制规则只该改 applier 一处，所以子代理直接调用 `applyToSendParams`。
- **P2-2 不把共享池做成 runtime 自己累加主循环用量。** runtime 拿不到 SessionState（它被设计成可注入假 runner 单测）。累加逻辑放在 runtime 里就要把会话态传进去，而「已花费多少」本来就是宿主的读口（`spentReader` 注释早已写明「由宿主提供」）。所以只改宿主侧的接线，runtime 不动。
- **P2-2 的读口不加本 run 的 `outputTokens`。** 子代理用量经 usageSink 同步回写 SessionState，预算检查发生在下一次 `agent()` 调用时，此时上一轮用量已在会话累计里。两者相加会把本 run 已回写的部分算两次，预算提前耗尽。
- **P2-4 默认不拒绝执行，只告警。** phase 对不上是进度树的展示问题，严格拒绝会让一个写错标题的脚本整段跑不起来。严格模式留给 CI 防漂移，用环境变量显式开。
- **P2-5 默认不常驻。** 常驻让 `run()` 的耗时从「任务做完」变成「协作结束」，而 `team_create` 和全部 dependsOn 测试都按一次性批写。改默认等于改所有调用方的终止语义。常驻作为显式 opt-in，挂起、唤醒、shutdown、自动收尾、消息回灌都在这个开关后面。
- **P2-5 不做成员级独立权限模式和独立 transcript。** 方案里列的这两项是常驻会话的完整体，但当前成员的权限走 escalate 给 leader、transcript 走 sidechain，改它们要动权限层和会话持久化，超出「让成员能挂起并被再次唤醒」这个缺口。留在常驻模式内部用现有的 mailbox + 任务清单实现。

## 拿什么证明它生效了

worktree `p2-fixes`（基线 `a5d1a795`）上：

- `bun test packages/core/tests/agent/sub-agent-effort.test.ts` → 5 pass。其中「GPT-5.6 族 xhigh 原样透传」断言 `reasoningEffort === "xhigh"` 且与 max 档不同；「原生 Claude manual 路径」断言 xhigh 预算 32000、max 预算 50000。

- `bun test packages/cli/tests/command/loop-every.test.ts` → 6 pass。`review PRs every 2 hours` 建出 cron `0 */2 * * *`、prompt 为 `review PRs`；`review every PR in the queue` 落 `submit_prompt` 不建任务。
- `bun test packages/core/tests/workflow/runtime.test.ts` → 29 pass。含严格模式抛 `UndeclaredPhaseError`、未声明标题照常分组、`withDeclaredPhases` 结束后恢复父声明。
- `bun test packages/core/tests/swarm/team-resident.test.ts` → 5 pass。常驻成员挂起后认领中途新建的任务（`claimedTaskCount === 1`），`shutdown_request` 后回 `shutdown_response`，挂起期间的 `plan_approval_response` 在下一次任务的 `drainInbox` 里读到。
- `bun test packages/core/tests/swarm/` → 50 pass（含既有 dependsOn / timeout / mailbox，确认一次性批未回归）。
- `bun run affected-tests` 判定的选测（cli、agent、swarm、tool、workflow 五个目录）→ **3246 pass / 0 fail**。首次跑出 53 fail 全部是 worktree 缺 `packages/tui-renderer/src`（ENOENT scandir），`bun run vendor:fetch` 后归零。
- `make build` → 自检通过，构建日志无 `will always be undefined` 警告。
