# 参考页生成器清洗：事实挂在可执行的源上，维护者的话不上官网

## 决定了什么

B29 改的是「源头文案说错了」，这次改的是「生成器把不该上官网的东西搬上去了」。全部落在 `scripts/docs-gen-reference.ts` 与源码注释，不手改 `website/ref/` 的 AUTO-GEN 区。

- **`permissionMode` 取值自省（D115）**：`config/schema.ts` 导出 `PERMISSION_MODES` 元组，`VALID_PERMISSION_MODES` 由它派生；生成器直接读这个元组，`ref/settings.md` 该行类型列显示 `enum`、9 个取值。注释里不再写「N 种模式」。
- **说明清洗（D117）**：生成时剥内部编号（`G10` / `M2` / `B1` / `P2-3` / `GAP-04` / `SEC-AUDIT-…` / `ADR-040` / `spec 17` / `§17.5` / `Phase 2.4` / `E.11` …）与 `xxx.ts:NNN` 源码位置，源码注释保持原样（那是溯源线索）。
- **不拼分组注释、只取首段（D118）**：JSDoc 只取第一个空行之前的段落，空行之后是写给维护者的；Config 接口里的 `//` 行一律视为分组小标题，不再拼进第一个字段（`hooks` 原来整条说明就是「Hook 和 MCP」）。截断从按字数改为按句，首句超长时保留完整首句。
- **对象字段展开子键（D119）**：主表下新增「对象字段的子键」一节。schema 声明的对象从 zod 自省子键，说明按子 schema 块取 JSDoc、缺了用同形 TS 接口补；passthrough 对象从 TS 接口读。`trace.upload` 额外展开一层，上传入口 `url / token / autoUpload / deleteAfterUpload` 可查。
- **Hook 页（D121 / D122）**：description 改为「配置键名、是否会触发与触发时机」，不再承诺载荷；表头补一句「只有 PascalCase 的 7 个事件没有 snake_case 别名」；「三路竞速」改写成「与分类器、用户弹窗并行竞争、先到先决」；`G11：` 由清洗剥掉。
- **env 页（D123 剩余部分）**：help 环境变量段重复登记直接报错；页首按数据写出「扫到 N 个里多少在表、多少在页尾、表里几个是扫描认不出的读法」。

## 放弃了什么（以及为什么不选）

- **Hook 页补载荷列**：要从各 `fire*Event` 的入参类型导出，成本高、类型名对用户也不直观。清单默认选「改 description 不再承诺」，照做。
- **全部对象字段递归展开**：只展开一层，`trace.upload` 是唯一例外（上传唯一入口）。递归会把 `budgetRules`、`exporters` 这类数组元素结构也拉进来，页面变成类型转储。
- **改源码注释来去掉编号**：编号是维护者追溯「为什么这么写」的线索，删了就丢了。只在生成时剥，源码不动；新字段照「首段给用户、空行后给维护者」写即可。
- **子 schema 注释整份文件抽一张表**：`commitAttribution` 同时出现在 worktree 与 git 两个子 schema，整份抽会把 worktree 那条说明安到 git 上（实测撞到），所以按块取。
