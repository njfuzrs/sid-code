# /perf 性能指标只算主循环，中断轮与截断流单列

## 决定了什么

修 PR-A（D1 D2 D3 D4 D6 数据部分，D18 对齐）。北极星方向：**可观测**，修的是「更快」曲线的分母。

- **唯一的主循环判据** `packages/core/src/trace/call-scope.ts` 的 `callScopeOf()`：`main` / `subagent` / `side`。
  判据顺序：index ≥ `SIDE_OBSERVER_INDEX_BASE`（900_000）→ side；`caller=agent:fork` 或 `agent_id=fork:*` → side；
  有 agent_id 或 caller → subagent；否则 main。号段常量从 `llm/resilient-stream.ts` 搬到这个叶子模块，
  分配侧 import 它，仓库里只剩一个字面量。`digest.ts` 原来那处 `i < 900_000` 也改成调它。
- **三处聚合按 scope 分开**（D2）：`aggregateSessionMetrics`、`aggregateProviderStats`、
  `aggregateLatencyByModel`（新增 `scope` 参数，缺省 `"main"`）的 TTFT / 生成耗时只收 main。
  `provider-health.ts`（`/trace --health`）显式传 `"main"`。子代理和后台调用单列成
  `subagent_ttft_*` / `side_ttft_*` / `*_gen_n`，留给 PR-B 的「后台辅助」行用。
- **中断分组**（D3）：`TurnComplete.stop_reason === "abort"` 进 `e2e_interrupted_n/max`，不进 `e2e_*`。
  `stream_completed` 新增 `aborted: true`，条件是 `!sourceExhausted && !timedOut`。digest 的 gens
  和 collector 的 `total_gen_elapsed_ms` 都跳过 `aborted` / `timedOut`。
- **tok/s 会话中现算**（D1）：公式收成 `builder.ts` 的 `deriveOutputTps()`，SessionEnd、索引行、中途快照、
  `/perf` 都调它。选的是「builder 在中途快照里也写 `output_tokens_per_sec`」，所以所有读 traj 的地方都能拿到；
  `/perf` 再按同一公式兜底，覆盖旧二进制写出的快照。另加 `deriveReasoningShare()` 给 PR-B 的瓶颈判定用。
- **工具时间只算主循环**（D6）：带 `agent_id` 的 `PostToolUse` 不再累加 `total_tool_duration_ms`，
  另记 `subagent_tool_duration_ms`，只做归因。
- **A6 / D18**：开工时 `/cost` D17 的 PR 还没开，本 PR 写的时候 #767（`fix(trace): 吞吐分母只计主循环生成耗时`）
  先合入了。合并 main 时按 A6「已合入则复用」处理：保留 #767 新增的 `side_gen_elapsed_ms` 字段与测试，
  只把它的判据 `agentId || caller !== undefined` 换成 `callScopeOf`（覆盖同一集合，另外认 900_000+ 副段），
  并加上跳过截断流。现在 `total_gen_elapsed_ms`、digest gens、tok/s 用的是同一个 `callScopeOf` + `isTruncatedStream`。
- **分位数补全**（D4 / A7）：digest 增加 `ttft_p99`、`gen_p50/p99`、主循环 TTFB 分布 `main_headers_*`。
  这些都**不进** session-index。
- **口径切换点**（A8）：索引行加 `perf_scope: "main"`。`/perf --days` 在任一期含旧口径行时提示一行；
  `--by-version` 点名含旧口径行的版本；`northstar/README.md`「更快」一节加了口径变更记录。

**口径切换点：0.1.616（合入日 2026-11-12）起**，`session-index.jsonl` 的 `ttft_p50/p95`、`gen_p95/gen_n`、
`tps`、`tool_duration_ms`、`e2e_*` 都换成新口径。影响幅度（方案 2.4 节，11-01 后 178 个会话）：89% 的会话混有后台或子代理样本；
单会话 TTFT P95 虚高中位数 +6%、P95 +72%，45 个会话虚高 >20%；「每会话 P95 的 P95」22.8s → 21.5s。
**北极星 trade-off：牺牲了历史曲线的连续性，换来口径正确**。跨这个版本的 TTFT P95 曲线会下移一个台阶，那是口径变了，不是变快了。

## 放弃了什么（以及为什么不选）

1. **子代理并进主口径**（理由是「前台子代理用户也在等」）：不选。拒绝的理由**不是**「用户不在等」，
   而是两者不可比：子代理上下文更短、thinking 场景少，混进同一组分位数没有语义。所以单列，不丢弃。
2. **中断轮直接剔除**：不选。`query/turn-complete.ts` 头注释已经论证过，慢的轮往往会被打断，
   剔掉会让 P95 系统性偏低（选择偏差）。所以单列「另有 N 轮中断（最长 X）」，用户能看到，分位数也有语义。
   `error` / `max_turns` / `max_duration` / `stalled` 留在主口径：那些是 agent 自己慢或失败，剔掉同样会让 P95 好看。
3. **重算历史索引**：不选。轨迹会被 LRU 清掉，索引行没法从原始事件重算；只重算一部分会让同一个窗口里混两套口径、
   而且分不出来，比统一标注更糟。改成按行标 `perf_scope`，消费侧按行判断。
4. **按版本号硬编码切换点**（`app_version >= 0.1.616` 视为新口径）：不选。dev 构建和正式版共用版本号，
   按版本号切会把同一版本里的新老行判错。按行上的 `perf_scope` 判。
5. **`aborted` 用 `signal?.aborted` 判**（方案 A3 原文写法）：不选，因为那样写**在生产里恒为假**。
   anthropic / openai 三条路径都刻意不把外部 signal 交给 lifecycle（T7 契约，见 `anthropic.ts` 同名注释），
   字段永远落不下来，测试又会因为夹具传了 signal 而全绿。改成「源未正常耗尽且非超时」，并用
   「不传 signal、消费方 break」的测试锁住（变异 M11）。
6. **会话级 TTFB 字段叫 `ttfb_p50`**：不行。结构门禁（`observability-d22-d30.test.ts` 缺陷 26）只允许
   `latency-by-model.ts` 声明 ttfb 分位字段，防止有人做跨 model 汇总。所以改叫 `main_headers_p50/p95`，
   注释写明单模型时才有意义。
7. **给子代理 `stream_completed` 补落 `agent_id`**：不选。老轨迹没有这个字段，改了也只对新数据生效；靠 `caller` 判已经足够
   （11-01 后扫描：子代理 `stream_completed` 全部带 `caller=agent:builtin|custom|summary`）。

## 拿什么证明它生效了

- **事件形态组合表**（A1 要求）：扫 11-01 之后全部会话，统计 `(事件, caller, agent_id 前缀, index 段)`：
  主循环 30200 条 `stream_completed` 都**没有** caller；fork 全部在 900k+ 段；子代理全部带 `caller=agent:*`、
  在 10000+/20000+ 段；compact / goal_eval 带 caller 且在 900k+ 段，先命中 side。没有落错桶的组合。全表贴在 PR 正文。
- **取证会话端到端对账**（T-A9）：`packages/core/tests/fixtures/perf-scope/` 下放了脱敏夹具
  （只留数值和归属字段，grep 过无路径、无用户名）。`buildDigest` 的结果与 `recompute.py` 逐项一致：
  `ttft_n=161 / P50 5880 / P95 15407 / P99 32092`、`side_ttft_n=4`、`gen_n=161 / P95 128313`、`e2e_n=2`、`e2e_interrupted_n=1`。
  这里**与方案不同**：方案写 `gen_n=160`，前提是被打断那条流带 `aborted`；这份轨迹是 0.1.614 写的，没有该字段，
  按「老轨迹不反推」仍计入，所以是 161，与 recompute.py「仅主循环 n=161」一致。
- **真实二进制**：同一会话 `/perf 20261110-152006-77684ab7`，线上 `sid-code` 输出 `P95 29s (n=165)`、端到端 `n=3`；
  本分支构建出的二进制输出 `P95 15s (n=161)`、端到端 `n=2`。会话进行中的快照 `/perf 20261112-112701-5d0a8b51`：
  线上「生成速度 无样本」，本分支「28 tok/s」（D1）。新二进制跑一次正常无头会话，3 条 `stream_completed` 都没有
  `aborted`（没有误标）。`/perf --days 7` 输出「本期含 260 个、上期含 268 个旧口径会话」，`--by-version` 点名了 0.1.606–0.1.615。
- **变异自证 12 处**，每处都看到了对应断言变红：删副段判据、TTFT 不分 scope、provider ttfts 不过滤、
  中断判据改成 `!== end_turn`、不跳截断流、索引不标口径、latencyByModel 不过滤、collector gen 不过滤、
  子代理工具进合计、`aborted` 恒真、`aborted` 改用 signal（生产恒假）、中途快照不写 tps。
  最后一处最初**没有**测试能抓到，因此补了 `builder.test.ts` 的三条断言。
- 门禁：`bun run affected-tests:run` 17633 pass / 0 fail；`make build` 自检通过；`bun run smoke` 26/26；
  lint / format:check / lint:boundary / typecheck:gate / docs:gen-reference --check 全绿。
