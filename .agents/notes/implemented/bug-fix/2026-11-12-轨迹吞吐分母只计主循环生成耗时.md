# 轨迹吞吐分母只计主循环生成耗时，辅助调用另记 side_gen_elapsed_ms

## 决定了什么

`output_tokens_per_sec` 的分母 `total_gen_elapsed_ms` 从「所有 stream_completed 一律累加」
改成「只累加主循环的流」：带 `agentId`（fork / 子代理）或 `caller`（旁路调用，如标题生成）
的 `stream_completed` 不再进 `total_gen_elapsed_ms` / `gen_samples`，另记新字段
`side_gen_elapsed_ms`（落盘同名，仅在有值时输出，无辅助调用的会话轨迹形状不变）。

- `packages/core/src/trace/collector.ts`：`writeRetryTelemetry` 的 stream_completed 分支按
  `agentId || caller !== undefined` 分流（与 `streamAttributionFields` 同判据）。
- `packages/core/src/trace/builder.ts`：`TraceMetadata` / `TrajectoryMetaOutput` 补
  `side_gen_elapsed_ms` 并序列化。

分子 `total_tokens_received` 只在主循环 AfterModel 累加（collector.ts），修复前分母混入
辅助调用生成耗时，取证会话（20261110-142303-21c3a481 第一段）实测：分母 124,306ms 中
23,879ms 来自 5 次 fork，吞吐被低估 20%（140 → 174 tok/s）。辅助调用占比一变曲线就平移，
跨版本不可比——这正是北极星铁律 3（分母口径必须和指标一起写死）禁止的形态。

## 放弃了什么（以及为什么不选）

- **不把辅助调用的生成耗时并进分子分母（「全口径吞吐」）**：分子
  `total_tokens_received` 的口径是主循环（fork 的输出 token 不进 collector 的 AfterModel
  累加），要把分子也扩到辅助调用需要动 fork 的 token 采集链路，改动面大且「全口径吞吐」
  混入了 fork 首请求未命中缓存的等待，不再描述用户体感的生成速度。北极星
  `northstar/README.md` 里 tokens/sec 定位是「更快」方向的体感辅助口径，主语是主循环。
- **不保留旧值兼容（如把旧口径数字重算成新口径）**：历史轨迹里主循环与辅助的耗时
  已混在 `total_gen_elapsed_ms` 中不可拆分，只能以本字段上线为界做口径断点，
  在字段注释与本文写明「跨版本连线要小心」，不做静默重算。
- **不在 fork 侧同步采集「辅助吞吐」指标**：`side_gen_elapsed_ms` 只留累计耗时，
  辅助调用的输出 token 在 `side_tokens_received` 已有会话级计数，需要时可离线派生，
  不为它加在线派生字段（无人消费）。

## 拿什么证明它生效了

- 用取证会话 events.jsonl（截断到 2026-11-10T06:28:50Z）核实事件形态：31 条主循环
  stream_completed 均无 agentId/caller，5 条 fork 均带 `agentId=fork:*` + `caller=agent:fork`，
  elapsedMs 合计 23,879ms——与方案文档 2.2 节的拆分一致，判据覆盖两类事件。
- 新增 T-D1（`packages/core/tests/trace/collector.test.ts`，主循环 1000ms + fork 500ms +
  旁路 300ms）：断言 `total_gen_elapsed_ms === 1000`、`gen_samples === 1`、
  `side_gen_elapsed_ms === 800`、SessionEnd 后 `output_tokens_per_sec ≈ 17440`。
- 变异自证：把分流条件改成 `false && (...)` 后该用例变红（111 pass / 1 fail，
  报错正是 total_gen_elapsed_ms === 1000 这条），恢复后 collector + builder 测试
  147 pass / 0 fail。
