# P1 状态查询匹配面按真实轨迹形态补齐（R4）

## 决定了什么

`matchStatusQuery`（P1 等待期拦截的判据 2 入口）在 `20261112-175603-ca8d7e5c` 窗口里
**44 条真实查询一条都认不出**，于是判据 2 从未成立、P1 一次都没触发。原因是四处匹配面
各自漏一类形态，叠加起来正好覆盖该会话 100% 的写法。改 `packages/core/src/task/status-query-commands.ts`：

1. **纯过滤器按语义认脚本解释器**：`python3 -c "…"`（含引号内多行正文）、`node -e`、
   `ruby -e` 进 `isReadonlyFilter`，但正文必须**不含**写文件 / 起子进程 / 访问网络的信号
   （`SCRIPT_WRITE_SIGNALS`）。heredoc 形态（`python3 <<'EOF' … EOF`）的正文由
   `extractHeredocBlocks` 从原文取出——它已被 `parseBashCommand` 剥掉，args 里只剩 `<`。
2. **`flattenCommand` 不再「见换行就放弃」**：折叠引号外的连续空白并保留引号外换行
   （`splitOutsideQuotes` 仍把它当 `;`），引号内的换行原样保留。多行循环因此也能展开。
3. **命令表补 `gh api …/pulls/<n>[/reviews|/commits|/files]`**（family `gh_api_pulls`，
   prefix `gh:pr:`），写标志仍由 `ghApiGetPath` 统一拒绝。
4. **赋值段展开**（`x=$(<命令>)` 还原成内部命令）+ **派生对象归并**
   （`gh:commit:<变量>` 且变量来自 `gh api …/pulls/<n> … '.head.sha'` → `gh:pr:<n>`）。
5. **选查询段时跳过末尾无害段**（`date` / `echo`），并给 `date` 单开
   `isHarmlessSegment`：`date -s` / `--set` 是改系统时钟，不算无害。
6. **归一化抹组合时长**（`13m43s` / `1h2m3s`）：原单段正则只能抹掉一半
   （`13m` 后紧跟 `4`，`\b` 不成立），`gh run list` 的 ELAPSED 列因此每轮都算「变了」。

## 放弃了什么（以及为什么不选）

- **改 `parser.ts` 让它产出 `for_statement` / `assignment` 节点**：parser 是权限判定
  （`isReadOnlyCommand` / `extractPathsFromCommand` / checkpoint）的上游，新增节点类型要同步
  每一处 switch。本模块只需要「扁平段列表 + 一点文本预处理」，风险与收益不成比例。
- **在 `isReadonlyFilter` 里做真正的脚本语义分析**：只做关键词级筛查。一段把
  `open('f','w')` 拼出来的脚本能绕过——但绕过的后果只是「少拦一次」（判据 2 不成立 → 放行），
  属于既有的「宁可漏，不可误伤」方向。反过来做 AST 级判断要引依赖、要处理三种语言。
- **把脚本正文整体踢出签名**（让同一条 `gh pr view` 的不同 python 呈现共享 memo）：
  签名语义是「决定输出形态的那段命令」，呈现方式变了输出形态就变了，混用会互相污染。
  代价是同一个 PR 换一种打印方式就重新计数——这是刻意的保守，不是 bug。
- **`date` 从 `HARMLESS_COMMANDS` 里直接删掉**：它是轮询打时间戳的高频写法，删了会让
  `sleep 30; date …; gh pr view …` 整条因「有一段不认识」而放行。改成按参数判 `-s`/`--set`。
- **给 `gh api …/pulls/<n>` 复用 `gh_pr_view` family**：pulls 端点返回的是 REST snake_case
  （`mergeable_state` / `head.sha`），与 `gh pr view --json` 的字段集不同。D13 的覆盖判定
  要求「同族才认为 monitor 覆盖了这条查询」，混族会让模型在 monitor 期间看不到 REST 独有字段。
