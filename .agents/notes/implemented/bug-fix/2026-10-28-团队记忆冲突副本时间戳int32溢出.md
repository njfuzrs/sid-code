# 团队记忆冲突副本名的时间戳改用 Math.floor，不再 `| 0` 截成 int32

## 决定了什么

`packages/core/src/memory/team/sync.ts` 生成 `<key>.conflict-<ts>.md` 时把 `Math.max(...) | 0` 改为 `Math.floor(Math.max(...))`。毫秒时间戳 > 2^31，`| 0` 截成 int32 后每约 24.8 天符号翻转一次；负半周产出 `k.conflict--2140….md`，`store.ts` 的 `/\.conflict-\d+\.md$/` 认不出它，冲突段的「当前生效版本」算错。2026-10-28T00:54Z 进入负半周，main 与全部 PR 的 CI 同时变红（`sync.test.ts`「缺陷 8」，以及经 `memory/` 子进程连带的运行时落盘门禁）。

新增回归用例，用 `utimesSync` 把 mtime 钉在负半周，不依赖当前时间。

## 放弃了什么（以及为什么不选）

- **放宽正则为 `-?\d+`**：只是让错名字被认出来，副本名仍然随日期正负摆动，排序和人读都错。
- **改用 `Date.now()`**：语义变了（原意是取较新一方的 mtime），没有必要。
- **测试里改用当前时间加断言放宽**：会恢复成「一半时间能红」的门禁，等于没有门禁。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/memory/team/sync.test.ts`：修后 21 pass；把 `| 0` 改回去后 2 fail，报 `Received: "k.conflict--2140213284.md"`，新增用例同时红。
- `bun test ./tests/build/no-real-trajectory-writes-runtime.test.ts`：修前在 main `d7f7b855` 上 1 fail（子进程退出码 1），修后 3 pass。
