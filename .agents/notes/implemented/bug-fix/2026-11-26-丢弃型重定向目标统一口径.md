# 丢弃型重定向目标统一到 {/dev/null, /dev/zero}，族 A 三处收敛为一处判定

## 决定了什么

「这个重定向目标算不算写盘」此前在仓里有 5 处实现，口径各不相同。本次把它们明确分成两族，
**族 A 统一到一个判定函数**，族 B 刻意不共用但补上注释说明理由。

族 A —— 问的都是「这个重定向算不算写盘 / 算不算纯查询」：

| 位置 | 修前口径 |
| --- | --- |
| `tool/bash/parser.ts` 的 `DISCARD_TARGETS` | `{/dev/null, /dev/zero}` |
| `permission/allow-composition.ts` 的 `isPipelineFilterStage` | 本地另一份 `{/dev/null}` |
| `task/status-query-commands.ts` | 字面量 `.filter((t) => t !== "/dev/null")` |

修法：`parser.ts` 导出 `isDiscardRedirectTarget(file)`（判据是**整段精确相等**，禁止
`startsWith`——`/dev/nullo` 会前缀命中 `/dev/null`，这个坑已经在注释里记着），
另两处改为 import 它，删掉各自的本地副本与那句已经变成假事实的注释
（「与 parser.ts 的 `DISCARD_TARGETS` 同口径」）。

族 B —— 问的不是「算不算写盘」，只加注释不共用：

- `permission/bash-security.ts` 的 `stripSafeRedirections`：注入检测的前置剥离，
  剥不剥 `/dev/zero` 不影响括号计数，只认 `/dev/null` 是正确的。
- `tool/jit-affected-paths.ts` 的 `bashWriteTargets`：问「哪些写入不进快照」，
  `/tmp/` 与 `/dev/*` 是两个不同理由，按前缀判而不是按丢弃型目标判。

顺带把 `parser.ts` 注释里三处**漂移的行号引用**（`bash-security.ts:123` 实际是 `:134`、
`:119` 实际是 `:130`）改成符号名——行号引用一漂就变成误导，符号名更耐久。

## 放弃了什么（以及为什么不选）

- **族 A 统一到只认 `/dev/null`（保持最窄口径）**：那是把三处对齐到「最不完整」的那一份。
  `/dev/zero` 与 `/dev/null` 一样是设备节点、写进去即丢弃；收紧到只认 `/dev/null` 等于在
  代码里固化一个错误事实，下一个人会再问一遍「为什么不算」然后加回来，来回震荡。
  而放宽的实际触发面接近零（要写出 `cat f | tail -5 > /dev/zero` 才算）。
- **族 B 也强行共用同一个判定**：`stripSafeRedirections` 的目标是剥离无害重定向后再做
  括号计数，`bashWriteTargets` 的目标是判断哪些写入不进 checkpoint 快照，两者问的都不是
  「丢弃型目标」。强行共用会让三个不同语义耦合在一张表上，将来任何一处要为自身需求扩充
  集合都会溢出到另外两处。
- **`jit-affected-paths.ts` 里删掉冗余的 `p === "/dev/null"`**：它确实被前面的 `^/dev/`
  正则完全覆盖。保留是因为删它属于与本缺陷无关的清理，而保留 + 注释点明「这是历史补丁叠加、
  不要以为 `/dev/zero` 被特判了」对下一个读代码的人信息量更大。
- **只为「修 bug」改族 A 两处而不抽函数**：那样两处各自还要维护一份集合，下次改口径
  依然会漏一处。抽函数是让「改口径只改一个地方」成为结构事实。

变异自证（把 `DISCARD_TARGETS` 改回只认 `/dev/null`）：

```text

  isReadOnlyCommand：echo hi > /dev/zero → 只读
```

`/dev/null/x`、`/DEV/NULL`、空串——确保判据是「整段精确相等」而不是前缀匹配。
