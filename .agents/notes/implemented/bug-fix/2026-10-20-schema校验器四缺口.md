# schema 校验器：循环 $ref 不再崩、组合关键字生效、shape 递归、pattern 限时

## 决定了什么

修 `json-schema-validator.ts` 的四个缺口（缺陷文档 20260927-编排与调度 第三部分 P1-7 / P2-6 / P2-7 / P3-1）。
它有三个调用方：StructuredOutput 工具、SDK 文本提取、子代理文本兜底，`--json-schema` 无头模式也走 StructuredOutput。

- **P1-7 循环 `$ref`**：`validateNode` 带 `refStack`（自上次下降到子数据以来展开过的 ref），
  重复即报「schema 存在循环 $ref」校验错误；下降到 properties/items 时清空，所以树形自引用照常工作。
  `checkSchemaShape` 静态找「不消耗数据的 ref 环」（沿 $ref 与组合关键字走），走 StructuredOutput 的不可重试分支。
  `StructuredOutputTool.execute` 再包一层 try/catch，工具不再抛异常。
- **P2-6**：实现 `allOf/anyOf/oneOf/not/if-then-else`；`additionalProperties:false` 无 `properties` 时按「只接受空对象」处理。
  其余不实现的约束关键字（patternProperties/uniqueItems/multipleOf/…共 14 个）在 shape 阶段**明确拒绝**并给改写建议，
  不再安静忽略。注解关键字（format/title/…）继续放行。
- **P2-7**：`checkSchemaShape` 递归走 properties/items/additionalProperties/$defs/definitions/组合关键字，
  错误带位置（`位于 #/properties/x`）；解不出的 `$ref`、非法正则也在这里拒绝。
- **P3-1**：`pattern` 在一个复用的空 `vm` context 里以 100ms timeout 执行，超时报校验错误。
- `--json-schema` 解析（`json-schema-arg.ts`）在启动期就跑 shape 检查，坏 schema 直接退出，不等模型烧一轮。

## 放弃了什么（以及为什么不选）

- **引 Ajv**：项目约定零依赖，且只需要窄子集。
- **对不支持的组合关键字只拒绝不实现**（文档的最小修法）：`if/then` 恰是 §5.3「critical 时 evidence 必填」的唯一写法，
  拒绝等于禁止举证类 schema。四个组合关键字实现成本小（各十行），于是实现；只拒绝真正长尾的那 14 个。
- **shape 阶段静态识别嵌套量词**（`(a+)+`）：形态识别必误伤 `(\d+\.)+` 这类合法写法，又漏掉 `(a|a)+`。
  改用运行期限时，判据是「真的跑超时了」而不是「长得像」。
- **对被测字符串截断长度再 test**：会让合法的长字符串校验结果变错，且 25 字符就能 84ms，截断救不了。
- **pattern timeout 取更小值**：Bun 下 vm 超时判定有约 150ms 固定开销（timeout=50/100 都实测约 250ms 返回），
  再调小不缩短墙钟，只增加误杀正常正则的风险。

代价（更准 ↔ 更快）：每次 pattern 校验多一次 vm 调用，实测 1000 次约 1ms，可忽略；最坏情况从「无上界」变为约 250ms。
兼容性：以前「安静通过」的 schema 若用了 14 个不支持关键字或悬空 `$ref`，现在会被拒绝——这是有意的，
否则约束不生效且无人知晓。仓内 website/evals/tests 用 grep 核过无此类用法。

## 拿什么证明它生效了

- 复现脚本 `17-schema校验器缺口.ts` / `18-循环ref栈溢出打穿工具层.ts`（路径改指 worktree）：
  1–5 段全部从 `VALID` / `THREW RangeError` / `null` 变成对应错误；18 输出
  `execute 返回: {"output":"[StructuredOutput] 提供的 schema 非法: schema 存在循环 $ref: #/$defs/A → #/$defs/B → #/$defs/A","isError":true}`。
- ReDoS 上界：`^(a+)+$` 配 n 个 a + b，n=20/25 正常判 3ms/84ms，n=30/40/60 均约 250ms 报「疑似灾难性回溯」（修前 30 字符 248ms 且指数增长）。
- 变异自证 7 处（运行期环检测 / 静态环检测 / oneOf / addlProps 无 props / 不支持关键字拒绝 / shape 递归 / pattern 限时），
  每处都让对应新增断言变红，恢复后全绿。
- `bun run affected-tests:run` 3939 pass 0 fail；`make build` 自检通过；lint / format:check / lint:boundary /
  lint:command-system / typecheck:gate（66/66）全绿。
