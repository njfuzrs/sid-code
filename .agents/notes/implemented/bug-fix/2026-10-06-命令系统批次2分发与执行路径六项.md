# 命令系统批次 2：记账挪进 dispatch、fork 降级走 inline 唯一出口、legacy 命令透传门控

## 决定了什么

前置核查（§3.4）：`command-usage.json` 落在 `state/`，trace 上传器、`/bug`、`/export`、
`/debug`、`/doctor` 都不读 `state/`，所以它不会被带出本机。D1/D2 仍是 P1，分批不变。

1. **D1 + D2（使用频率记账）**：`recordUsage` 从 `app.ts` 的 `onSlashCommand` 开头挪进
   `CommandExecutor.dispatch`，和 `logCommandInvoke` 放在一起。dispatch 只在「查到命令 + 过了门控」
   之后才会被调用，`cmd.name` 本身就是 canonical name，`executeImmediate` 也走这里。
   `/m` 记到 `model` 名下；未知命令、路径 passthrough、被门控拒绝的命令都不再写盘。
2. **D8（fork 降级）**：没有 providerRegistry 时，`executeFork` 返回 `null`，不再自己拼一个
   `submit_prompt`。`executePrompt` 收到 `null` 后落到 inline 分支，那里是唯一的 inline 出口：
   上报 `addInvokedSkill`，hooks 不卸载。
3. **D13（local-jsx 死锁）**：`call()` 正常返回空 jsx、又没调 `onDone` 时，resolve 为 `{ type: "skip" }`。
4. **D3（前导空白）**：`dispatchInput` 入口先 `trim()`，和 `canRunDuringStreaming`、`parseSlashCommand` 同口径。
5. **D12 第一步（legacy 门控）**：`adaptLegacyCommand` 新增可选参数 `gates`，`loaders.ts` 用一张
   不导出的名字表 `LEGACY_BUILTIN_GATES` 给 5 条命令补字段：`cost` / `stats` / `theme` 设 `immediate`；
   `allow` / `deny` 设 `immediate + requiresArgs`。这是过渡手段，命令迁到 `commands/` 后删掉对应条目。

## 放弃了什么（以及为什么不选）

- **D1 在消费侧同时查别名**（`max(score(name), ...aliases)`）：会把两端口径不一致的状态固定下来，
  每次补全还要多查 N 次。
- **D12 给 legacy `Command` 接口加五个可选方法**：那是给一个 `@deprecated`、计划删除的接口扩容，方向相反。
- **`/add-dir` 标 `requiresArgs`**（缺陷文档的初稿建议）：读 `permissions.ts` 后确认无参是合法用法，
  效果是列出白名单。标上之后，补全回车就不能直接列表了，所以否决。
- **`/language` 标 `immediate`**：它会调用 `rebuildSystemPrompt`，会和正在进行的那一轮请求交错，不符合
  「不碰模型正在读写的状态」这条判据，所以不加。
- **测试复用 `LEGACY_BUILTIN_GATES`**：如果复用，「表里漏了字段」和「适配器没透传」两种错误会同时变绿；
  导出它还会让命令体系门禁 G1 的死导出数从 36 涨到 37。所以测试里按名字写死期望值。
