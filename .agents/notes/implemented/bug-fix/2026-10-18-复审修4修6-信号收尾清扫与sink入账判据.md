# 复审 修-4 + 修-6：清扫按最后一段判收尾、删掉 2s 强退分支、sink 入账判据统一来源

## 决定了什么

修-4（信号收尾与清扫）：

- **M1**：`pid-manager.ts` 新增 `lastSegmentHasSessionEnd`，判据是「最后一个 SessionStart 之后是否还有 SessionEnd」，替换原来的全文子串判断。resume 会话追加在同一个 `events.jsonl`，以前「正常结束 → resume → kill -9」会凭旧段的 SessionEnd 被误删 heartbeat，而 heartbeat 正是 digest 判强杀的证据。生产调用改由 `SID_CODE_HEARTBEAT_SWEEP=off|dry-run` 控制，删掉的会话 id 全部写进日志，事后能复看。
- **M3**（复审决策 2）：删掉 `STUCK_TEARDOWN_MS` 和 `decideRepeatSignal` 的计时分支。收尾过程中再来 SIGTERM/SIGHUP 一律 `ignore`，再来 SIGINT 仍是 `force_exit`。1.5s 兜底抽成 `armForceExit`，让真进程测试跑的是生产代码。
- **L5/L7**：只写不读的 `terminalDead` 改成 `terminalDeathCause`（`terminal_closed`/`pipe_closed`），由 `onSignal` 读取。EPIPE（`-p … | head`）现在记 `reason=other`、退出码 141，不再冒充 SIGHUP 的 129 / `terminal_closed`。
- **L6**：第一个信号的日志也带上 `isTTY` 和 cause。`process.exit` 前最多等 200ms 执行 `log.flush()`，仍在 1.5s 兜底之内。
- **T4/T5/T6**：
  - T4：heartbeat 用例截获 `setInterval` 回调，真跑一次 interval 体。
  - T5：删掉原来的恒真用例，换成「真实文件 WriteStream 的 EIO 照原路崩溃、onDead 不触发」。
  - T6：新增 python `pty.fork` 真 pty 集成用例，关掉 master 后收尾跑完、done 落盘、退出码 129；另加「收尾异步挂起由 armForceExit 兜底」的真进程用例。

修-6（S13 加固）：

- **D6**：`billing-usage-sink-ticket.test.ts` 的门禁不再写死 3 个文件，改为扫描 `src/**` 里所有 `usageSink(` / `usageSink?.(` 调用方。另有一条自证断言：扫描结果必须包含已知的 3 个调用方，防止扫描器失明后拿到空集全绿。
- **L12**：`hasNonZeroUsage` 放进 `llm/billing-sink.ts`，3 个调用方共用。`workflow.ts` 的 `onResult` 以前只要 sink 存在就 `return true`，现在 usage 全为 0 时返回 false，让票据把认领过的 fetch 补交给观察者。门禁同时要求每个调用方都用这个同源判据。

## 放弃了什么（以及为什么不选）

- **M1 比较 SessionEnd 时间与 heartbeat mtime**：要逐行 parse 时间戳，大会话的 events 有几 MB。还要假设两边时钟同源。比较子串的 `lastIndexOf` 位置就够了。
- **M1 首次启动强制 dry-run**：会让 223 个存量残留一直不被清掉，「每次启动都报未正常收尾」的问题会重新出现。最后选了默认照常删 + 开关 + 全量 id 日志。
- **M3 的三个否决项**（与复审 §8 决策 2 一致）：
  - `removeAllListeners` 恢复默认处置：会重新引入 S15。
  - 调整 2s 阈值：这个分支本身就执行不到，改数值没有意义。
  - Worker/子进程看门狗：为极低频场景引入新的进程模型，成本不成比例。
- **M3 的牺牲**：收尾里出现同步死循环时，第二个 SIGTERM 杀不掉进程，只能靠 SIGKILL。换来的是关终端时收尾不被第二发 SIGHUP 打断，后者有 209 个会话的实证。
- **L7 给 EPIPE 新开一个 SessionEnd reason**：会改 `hook/types.ts` 的联合类型，牵动参考页和外部 hook 契约。`other` 已有，语义也够用。
- **D6 的门禁扫描范围**：只扫源码里的调用形状，不做 AST。注释行先剥掉再匹配，`setUsageSink(` 声明排除在外。

## 拿什么证明它生效了

变异自证（每条都真改了生产代码，看到变红后再恢复）：

| 变异 | 变红的用例 |
| --- | --- |
| `lastSegmentHasSessionEnd` 恒返回 true（等价于旧的全文判据） | `M1：resume 后被强杀…保留 heartbeat`、`lastSegmentHasSessionEnd：按最后一段判` 2 fail |
| 删掉 `collector.ts` 的 `if (this.heartbeatStopped) return;` | `T4：真跑 interval 体…` 1 fail（旧用例在这个变异下是绿的） |
| `target.on` → `once` | `监听器常驻…`、`真进程 · 两发 SIGHUP` 2 fail |
| `armForceExit` 不调 exit | `真进程 · 收尾异步挂起由 forceExit 兜底` fail（5326ms 后被测试 kill） |
| watcher 改成在 `uncaughtException` 里按 code 吞掉 EIO | `T5：未被监听的流…照原路崩溃` fail |
| 去掉 SIGHUP 监听 | `真 pty · 关闭终端后收尾落盘` fail（out=-1，被信号杀）。⚠️ `on→once` 这条锁不住，pty 关闭只发一次 SIGHUP，那个变异由「两发 SIGHUP」用例负责 |
| `workflow.ts` 退回 `if (this.usageSink)` | `L12：每个 sink 调用方都用同源判据` fail，rel=tool/workflow.ts |
| 新增一个不开票据的 `agent/zz-mut.ts` sink 调用方 | 两条门禁都报 rel=agent/zz-mut.ts（写死清单时这里是绿的） |

测试与构建结果见 PR 描述。

未证实：

- L6 刷盘之前是否真的会丢日志，没有复现，只是把风险消掉了。
- L7 的 141 退出码没在 `sc-dev -p … | head` 下端到端跑过，靠 `terminalDeathCause` 纯函数和源码断言锁住。
