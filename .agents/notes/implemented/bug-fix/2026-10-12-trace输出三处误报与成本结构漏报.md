# /trace 输出：修三处与原始数据相反的结论，补成本结构与后台 fork 可见性

## 决定了什么

复盘会话 `20261011-220000-97ae3124` 的 /trace 输出时，逐项回源 events.jsonl / session.traj 核对，
发现三条结论与原始数据相反，另有几项现成数据从未渲染。全部在 `packages/core/src/trace/` 内修：

1. **`retry_wasted_tokens` 误报（最严重）**：报「8 次重试白烧 0.47M token / 61.5%」，实际 8 次全是
   旁路调用（1 次标题生成 + 7 次 fork），20 条 `RetryTelemetry` 全是 `stream_completed`，零重试。
   根因：§5.4 的拆分判据读 `StreamPhase.agent_id`，而 OpenAI 族 emit 点不传身份，Set 恒空。
   修法：增加第二身份源 `BilledRequest.accounted === false`（billing-sink 两族都落），与原判据取 max。
2. **`session_end_missing` + `hypothesis_process_killed` 误报**：对活会话跑 /trace 必报。
   修法：`findSessionProcess()` 读 `<root>/trajectories/.pids/*.json` 按 session_id 匹配并 `kill(pid,0)`，
   存活则不报，头部显示「进程仍在运行 (PID …)」。
3. **头部 `tok ↑` 违反 stock/flow 铁律**：用的是末轮快照 `total_tokens_sent`（80833），
   与累计输出并排；改用 `total_cumulative_prompt_tokens`（763109），老轨迹退回并标「末轮」。
4. **补渲染**：缓存命中率、推理 token 占比、旁路调用成本（实测占主循环 67%，此前完全不显示）、
   后台 fork 的工具调用（只在 `PermissionDecision.execution_context=forked` 留痕）、
   warn.log 的 `CACHE_BREAK` 条数、前缀断裂中「历史被缩短」的轮次数。
5. **TTFT 缓存分桶**：`cache_hit` 是 `cache_read > 0`，DeepSeek 网关几乎全未命中也报 256，
   导致 20/20 进 hit 桶。OpenAI 族 completed 事件新增 `cache_read_ratio`，分桶按 ≥0.5 判命中；
   无比例的老事件退回布尔，历史曲线不平移。
6. **心跳假 hang**：终态快照（completed/aborted/error）未清理时被心跳当 active_request，
   `elapsed_ms` 持续增长（实测 2.8h）。改为只选非终态快照，残留数另落 `stale_terminal_snapshots`。
7. 小修：`ls` 的 `dir_path` 加入参数锚点（原显示 `{dir_path}`）；user_prompt 展示前剥 NUL 等控制字符
   （实测 prompt 开头是 NUL 字节，`String.trim()` 不剥）。

## 放弃了什么（以及为什么不选）

- **在 openai.ts 所有 emitStreamPhase 点补传 agentId**：是更根本的修法，但要改 provider 主路径
  十余处、还牵动快照键（B4 的 key 含 agentId），风险面远大于诊断层修复。BilledRequest 已是
  两族统一出口，作为判据足够可靠；补身份留作后续。
- **两个身份源相加**：同一批流会被算两次，取 max。
- **直接改 `cache_hit` 语义为比例阈值**：会让全部历史 TTFT 分桶曲线整体平移，无法区分
  「修了」还是「口径变了」。所以新增字段、消费侧判定。
- **复用 pid-manager 查进程**：其路径固定走 `sidPaths.trajectories()`，而 digest 根目录可显式指定
  （测试 / 离线分析），复用会「分析 A 目录、去 B 目录查 PID」。

## 拿什么证明它生效了

- 新增 `packages/core/tests/trace/digest-trace-audit-20261012.test.ts` 16 条（含反向断言：真重试仍报、
  PID 已死/缺失仍报 session_end_missing）。
- 变异自证：把 otherChain 判据回退为只看 StreamPhase、把 liveProcess 置空 → 3 条变红；恢复后 16/16 绿。
- `bun run affected-tests:run`：2553 pass / 0 fail；`make build` 通过，无 `will always be undefined`。
- 真实会话重跑 `bun scripts/trace-digest.ts 20261011-220000-97ae3124`：retry_wasted_tokens 消失，
  头部显示 `tok 763109↑/36212↓（累计）`、`缓存命中 73.7%`、`旁路调用 8 次 $0.0329 … 合计 $0.0819`、
  fork 工具 `glob×2 save_memory×2 bash×1 ls×1 read×1 edit×1`、`1 轮历史被缩短`、`2 条 CACHE_BREAK`。
- 局限：该会话的 TTFT 分桶仍显示「未命中：无样本」，因为它的事件早于 `cache_read_ratio` 埋点；
  新判据需新会话才有样本。心跳改动只有代码审读，没有单测覆盖。
