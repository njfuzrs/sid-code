# 会话持久化与检查点四项 P1（N2 / N3 / N7 / N13）

承接 2026-09-28 的七项 P0（PR #115）。工单：`docs-research/.../20260927-会话持久化与检查点-顺着sc-08核出的缺陷.md`。
P2（N8 / N11 / N12 / N14）不在本次范围。

## 决定了什么

- **N2 `-c` 被遮住**：`SessionStore.loadLatest()` 改为沿 mtime 降序逐个 `load()`，取第一个成功的；
  读正文前按首行排掉 sidechain，判据复用 `isSidechainContent`（与 `getAllSessionFiles` 的 D9 修复同一口径）。
  **按工单要求先于 N3 落地**——N3 让 sidechain 开始落盘后，「最新 mtime 是 sidechain」会成为常态。
- **N3 sidechain 只接了 1/3 路径**：收敛为 `SubAgent.openSidechain()` 单一入口，三条路径都调：
  - `executeInner`：改用该入口，行为不变；
  - `executeSpawnedInternal`（默认路径）：父进程执行工具，故落 user_prompt + 每次 tool_use/tool_result + 最终输出；
    结束状态 completed / failed（意外退出）/ aborted（超时、用户中止），`finally` 写 end；
  - `executeCustomInner` + `executeSpawnedCustom`：agentId = `custom-<type>-c<序号>`，同类型并发不串写。
- **N7 压缩后回退空转**：`RewindPoint` 增加 `conversationStale`，`onContextCompacted` 调
  `rewindManager.onMessagesCompacted()` 把已有点标为失效。涉及对话的回退遇到失效点（或下标越界兜底）时
  **整次不执行**：对话、文件、回退点全部原样，返回 `conversationUnavailable`；UI 显示「未回退」和原因。
  「仅代码」不受影响（文件锚点是快照 id）。
- **N13 二进制被 U+FFFD 损坏**：快照读入改为字节 + `TextDecoder(fatal, ignoreBOM)` 判定，含 NUL 或非法 UTF-8 即二进制，
  存 `binary: true` + 原始字节 base64（超阈值叠加 gzip），一律 `full`、不做 diff；回滚按字节写回。
  编码/解码收成 `encodeFullEntry` / `decodeFullEntry`，createSnapshot、重建、淘汰重锚定共用。老索引无 `binary` 字段按文本读。

## 放弃了什么（以及为什么不选）

- **N7 按偏移重映射下标**：压缩把旧轮换成摘要，被摘掉的轮次没有映射目标；幸存尾部的位置取决于摘要+ack 注入条数，
  推算是在猜。猜错会截掉用户想留的消息，比明确拒绝更坏。
- **N7 锚点改用消息 uuid**：内存 `Message` 没有稳定 id，要给 ctxMgr 全链路补字段，超出 P1 的范围；作废 + 失败可见已消除空转和回退点被清空。
- **N7「对话+代码」失效时只回滚文件**：只做一半会让文件和对话错位，结果与用户选的档位不符。
- **N13 检测到二进制就不建快照**：比现状好，但 base64 只多约 4/3 体积（还可叠 gzip），就能换来真正能回滚。
- **N3 让子进程自己写 sidechain**：要改 sub-agent 协议和 headless 侧；父进程已掌握工具往返，足以还原可续跑的骨架。
  子进程每轮的纯文本输出协议里没有，这一缺口与残卷同源，记为已知限制。
- **把 `setCompactObserver` 改成透传 meta**：会改变 D10 的摘要落盘判据，不属于本次，保持原样。
