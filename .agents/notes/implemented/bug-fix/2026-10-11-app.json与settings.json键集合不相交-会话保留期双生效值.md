# app.json 与 settings.json 键集合不相交：会话保留期不再有两个生效值

## 决定了什么

**现象**：TUI 启动提示「已按保留策略清理 1 个旧会话（保留 30d；可在 settings.json 的 sessionRetention 调整或关闭）」，
而代码默认值从 53047e30 起已经是 365d / 不限数量 / 10GB。

**根因**：v4 迁移定下了「app.json 不存行为配置」，但它的白名单 `APP_CONFIG_OWNED_KEYS` 误收了 9 个行为键
（theme / showLineNumbers / debug / debugLevel / debugLogFile / checkpoint / sessionRetention / trace / telemetry）。
`loadConfig` 又按「settings 先读、app 后读」合并，app.json 的值因此盖掉 settings.json 和代码默认值。
维护者本机 app.json 里存着 `sessionRetention: {maxAge:"30d", maxCount:50}`，正好是 53047e30 之前的旧代码默认值。
另外，轨迹 / 笔记清理（startup-housekeeping）只读 `getSettings()`，会话清理读 `loadConfig`，
同一台机器上就成了会话 30 天删、轨迹 365 天删，提示里叫用户去改的 settings.json 也盖不过 app.json。

**改动**：
1. `app-config.ts`：AppConfig 和白名单只保留程序自己写的运行状态（numStartups / firstStartTime / hasCompletedOnboarding /
   hints / lastPricingSyncVersion / projects），`createDefaultAppConfig()` 只剩 `numStartups: 0`。
   之前的默认值里带着 debug:false / INFO，`saveAppConfig` 每次计数都会把它们一起写进磁盘。
2. `config.ts`：`loadConfigFile` 不再读 app.json，用户级配置只认 settings.json。
3. 迁移 v7 `move-behavior-keys-out-of-app-json.ts`：把这 9 个键从 app.json 里移出。值等于**当前或已登记的历史**代码默认值的，
   算作快照，直接删掉不搬；其余值算用户设置，settings.json 里没有这个键时才补进去。v4 跳过这 9 个键，交给 v7 处理。
4. `cli.ts` → `runStartupHousekeeping({ retention })`：会话、轨迹、笔记三处的保留期都用同一个 `getRetentionSettings(config)`。
5. 文案和文档：help、/telemetry 提示、官网 headless / skills 页里叫用户去 app.json 写配置的 4 处
   （其中 `trust_project_extensions` 在 app.json 里从来不生效）。

## 放弃了什么（以及为什么不选）

- **只把 `sessionRetention` 移出白名单**：另外 8 个键是同一种问题（debug / showLineNumbers 照样会被 app.json 快照盖住），
  只修一个，下次换个键还会复发。
- **v4 直接重跑、搬走全部越界键**：v4 只认得「当前默认值」。`30d / maxCount 50` 是历史默认值，v4 会把它当成用户设置，
  搬进 settings.json。这样只是换个文件继续盖住新默认值，事故原样保留。所以要单独写 v7，带一份历史默认值登记表。
- **嵌套对象做字段级合并**：对象只要有一部分和默认值吻合，就说明有人改过。猜字段归属有可能删掉用户设置，所以宁可整段搬。
- **给 app.json 做一份分发模板（类似 team-defaults.template.json）**：app.json 是运行状态，不是配置。
  分发模板等于再写一份默认值快照，正是这次要消灭的东西。团队默认值应该放 `scripts/team-defaults.template.json` → settings.json。

## 拿什么证明它生效了

- 新门禁 `app-config.test.ts`「键集合不相交」：白名单和 `defaultConfig()` / `SettingsSchema` 的键交集为空。
- `config.test.ts`：app.json 里放 30d 快照后，`getRetentionSettings(loadConfig()).maxAge === "365d"`，并且 maxCount 为 undefined。
- 迁移 v7 有 9 个用例，用维护者本机 app.json 的真实形态做输入：7 个快照只删不搬；`telemetry.enabled:true`（默认是关）
  搬进 settings.json；运行状态原样保留；结果幂等；settings.json 损坏时抛错且不改动 app.json；变异自证（maxCount 改成 100 就会被搬）。
- 在临时目录用真实 app.json 副本跑迁移，结果见 PR 描述。
- 已知副作用：老默认值 `debug:false` 被当成快照删掉以后，生效值回到代码默认 `debug:true`。这是 b1d18d08 起就定下的默认值，
  之前只是被 app.json 的旧快照盖住了。
