# 切换模型 / fallback 的思考参数与关闭泄漏观测（PR-3 + PR-5）

## 决定了什么

对应排查文档 `20261016-思考开关不生效与切换模型异常` 的 PR-3 + PR-5，合成一个 PR。前置 PR-1 / PR-2 已在 #325 合入。

**PR-3（D8 D9 D10）**
- **D8**：`ThinkingManager` 的启用位可以传回调，每次读取时现算。App 传 `() => this.resolveEffortCap().supportsThinkingToggle`，与状态栏同口径（真名 + alias）。启动在 kimi / gpt-5.x、再 `/model` 切到 Claude 后，`think hard` / `ultrathink` 不再永久失效。
- **D9**：新增 `SendParams.thinkingIntent`，由调用方在 applier **之前**写入：主循环写 `resolveThinking` / `resolveAppliedEffort` 的结果，子代理写 `task.effort` 的结论。`streamFromFallback` 调新模块 `llm/fallback-thinking.ts`，先**清空** `thinking` / `reasoningEffort` / `outputConfig` / `thinkingBudgetCapped`，再按备用模型能力重跑 applier。能力判定由 app.ts 注入 `resolveEffortCapability` 回调（availableModels 的 provider / baseURL / supportsThinking / compat 别名），缺省时按进程级别名表翻译真名。
- **D10**：`openai.ts convertMessages` 新增一条：Claude 历史（thinking 块，没有 `_meta`）发往 `requiresReasoningContentForToolCalls` 的模型时，把 tool-call 轮的 thinking 文本写进 `reasoning_content`，signature 丢弃。有原生 `_meta.reasoning_content` 时以原生为准。

**PR-5（§4.7 观测）**
- `BilledRequest`（events.jsonl）新增 `thinking_wire`（`enabled` / `adaptive` / `disabled` / `omitted`，读**最终请求体**）、`thinking_in_response`、`thinking_intent`。已接线的路径：Anthropic 流式 / 非流式、Chat Completions 流式 / 非流式。Responses API 路径未接线，字段缺省，不会被算进分母。
- `BeforeModel` → raw.jsonl 新增 `thinking_intent`（`on` / `off` / `auto`）与 `thinking_control`。
- digest 新增 `thinkingLeak`：主循环泄漏率与非主循环思考率分开算，分母写死为「意图 = 关」的 fetch；恒思考模型上「意图关但线上发了开」单列为 `offButSentOn`；按 model 分组。

## 放弃了什么（以及为什么不选）

- **D8 改成「切模型时调 `setEnabled`」**：要保证所有切换路径都通知到，以后新增一条就会漏。现算回调与 `pushKnobDisplay` 同口径，天然跟着当前模型走。
- **D8 顺带「归正 `runtimeThinking`」**：意图粘性是 PR-2 采纳的特性。状态栏与实际不符的根因是 D5，已由 PR-2 修掉。
- **fallback 取 `params.thinking.enabled` 当输入**：恒思考模型上它已被强制成 true，会把「主模型关不掉」传染给备用模型。
- **fallback 取用户 `/think`**：side-call / 子代理 / fork 也经 `streamWithResilience` 走 fallback。取用户意图的话，用户设 `on` 时这些调用一降级就开思考，强制 `tool_choice` 也会被降成 `auto`。而且 `ModelFallback` 在 core 里，本来就拿不到 App 的运行时态。
- **⚠ 覆盖面更正（2026-10-18 复审 R4）**：上一条以及「决定了什么」里写的「side-call / 子代理 / fork 也经 `streamWithResilience` 走 fallback」**不成立**。回源码核过：生产里 10 个 `streamWithResilience` 调用点（recall / forked-agent / agentic-loop ×2 / context-collapse / auto-compact / partial-compact / hook runner / goal evaluator / headless）都不传 `fallbackModel` 也不传共享 `fallback`，`resilient-stream.ts` 现建的 `ModelFallback` 没有备用模型，重试耗尽直接抛错。**生产中只有主循环会 fallback**，D9 的重解析只在主循环上生效。「side-call / 子代理要不要接 fallback」是另一件事（记忆里有「子代理绕过 Fallback」的历史），刻意不混进本批。
- **side-call 逐个补写 `thinkingIntent`**：`SIDE_CALL_NO_THINK` 的 `enabled:false` 不会被 applier 改写，fallback 缺省按它推断为「关」，方向安全。改 14 个调用点只会增加漂移面。
- **D10 无条件、全量迁移**：旧 `deepseek-reasoner` 带 `reasoning_content` 会 400；全量回灌整段 Claude 思考就是「思考链回传上下文膨胀」那份报告的形态。所以只迁 tool-call 轮、过能力位、空文本跳过。
- **D10 在切模型时一次性改写历史**：会改动持久化的会话，切回 Claude 时还要再改回去。在转换层按目标模型现算更稳，也不碰存储。
- **PR-5 取 raw.jsonl**：side-call 在 raw.jsonl 里恒 0 条（§8.8），算出来永远是 n=0 的假绿。
- **PR-5 落全量请求体**：events.jsonl 刻意控制体积，三个字段就够复算。
- **把恒思考模型的「关不掉」算进泄漏率分子**：Opus 5.5 会话会把泄漏率顶到 100%，掩盖真正可修的泄漏（D1 / D2 形态），所以单列。
