# 斜杠命令的 confirm 结果在 TUI 里弹可操作的确认框

## 决定了什么

`packages/cli/src/app.ts` 的 `handleCommandExecutionResult` 里，`case "confirm"` 原先只把
`message` 当文本打到屏幕上，没有任何控件，`onConfirm` 永远不会被调用。/login（已登录时重新登录）、
/logout、/goal 覆盖目标都走这条路，用户卡在提示上，确认不了也取消不了。

现在改成：经 `interactionQueue` 串行弹确认框，确认后调 `onConfirm()`，把它的结果递归交回
`handleCommandExecutionResult`（可能是 text，也可能又是一次 confirm）；取消时回执「已取消」，
Esc 也按取消处理。

确认框复用 `shellConfirmRequest` 这个 state 格子，`ShellConfirmRequestInfo` 加了可选的 `message`。
`DialogManager.tsx` 的 `ShellConfirmDialog` 在 message 模式下只显示说明文字和「确认 / 取消」，
不显示 shell 命令。

## 放弃了什么（以及为什么不选）

- 新开一个 `commandConfirmRequest` 格子：App.tsx 的 Esc 中断、双击 Esc 回退、
  `derive-streaming-state`、DialogSwitch、两套 Layout 等十余处都用 `shellConfirmRequest`
  判断「有确认框在屏」。新格子要逐处补上，漏一处就会出现「确认框在屏时 Esc 把流式中断了」这类问题。
  复用旧格子，这些判断自动生效。
- 危险态默认聚焦「取消」：这几个 confirm 都是用户刚主动敲的命令，默认聚焦「确认」更顺手。
  Esc 和 n 仍然是取消。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/components/command-confirm-dialog-keys.test.tsx`，用真实按键驱动：
  说明文字可见、不含「Shell 命令」，回车 → true，n → false，Esc → false，3 pass。
- `login-commands.test.ts` 与 `approval-dialogs-keys.test.tsx` 照常通过（共 18 pass）。
- `bun run affected-tests:run`：2460 pass / 0 fail。`make build` 自检通过，没有 `will always be undefined` 警告。
