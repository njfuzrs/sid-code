# 只读命令的读路径工作区校验（B5）：该放的放、该拦的拦

## 决定了什么

PR-3 修 B5 的两个方向。修前两条都和 CC 不一致：

- `cat /etc/hosts`（工作区外）在 Step 5.5 被**静默放行**——只读命令的路径参数此前没人看；
- `cat ../README.md`（cwd=`<ws>/packages`，目标在工作区内）反被 Step 2 的「路径遍历」
  文本正则 `/\.\.[\/\\]/` 拦成**危险确认**。

修法是把这个判据从「文本里有几个 `../`」换成「按 cwd 解析后落在哪」：

**1. 新增读路径提取器**（`permission/shell-command-variants.ts` 的
`readTargetsFromExpansion` / `extractBashReadTargets`，与 `extractBashWriteTargets` 并列）。
吃同一份 `expandShellCommand` 结果，所以 `sh -c 'cat /etc/hosts'` 的内层也看得到。
覆盖 `READ_ONLY_COMMANDS` 里所有带文件参数的读类命令（`cat`/`head`/`tail`/`less`/`wc`/`stat`/`du`/`ls`/`file`/
`grep`/`rg`/`sed`/`awk`/`jq`/`find`/`diff`/`sort`/`uniq`/`cut`/`comm`/`paste`/`column`/`tree`…），
**`git` 刻意不提取**（它的路径由只读 git 的边界判定管，两处判同一路径迟早结论打架）。
输入重定向（`< file`）也算读路径；`<<`/`<<<` 不是文件，跳过。

**2. 按每段的有效 cwd 解析**（`readonly-compound.ts` 的 `ReadOnlyCompoundResult.stages`）。
`cd A && cat ../f` 的 `../` 基准是 A，不是整条命令的起始 cwd。cd 链已在 PR-2 里算过，
这里**消费它的结果而不是再走一遍**——两套 cd 链路迟早漂移。

**3. 工作区外 → 普通确认**（`checker.ts` 的 `evaluateReadOnlyReadPaths`，接入 Step 5.5 / 5.6）。
判定走 `PathValidator.validateAccess(path, "read")` + `isWithinWorkingDirectories`；
敏感文件 / 系统目录 / Unicode 混淆仍归 Step 2 危险命令层，这一层只补「工作区外」这一类
（同一路径两套结论最难归因）。

**4.「路径遍历」正则只对非只读命令保留**（J3）。`hardcodedDangerCheck` 加 `skipPathTraversal`，
由 `checkDangerousCommand` 在命令含 `../` 且可判只读时置位。`python3 ../x.py` 这类非只读命令
**行为不变**，仍是危险确认。

**5. 会话级 `Read(<目录>/**)` 规则生效**（`isReadPathCoveredByReadRule`）。bash 读路径不会被
`checkAllowRules` 命中（那条链路按 `req.toolName` 匹配，`Read(...)` 工具名对不上），
所以单独取一遍 allow 里的读类规则、用与文件工具相同的 `matchPathRule` 口径比对。
Decision 的 `metadata.suggestedReadDir` 带上建议目录，供确认框的「本会话允许读取 <目录>」用。

**J4 豁免**（`readonly-read-paths.ts` 的 `createSidSelfReadPathFilter`）：只豁免 sid 自己
让模型去读的三类路径——后台任务输出（`sidPaths.tasks()`）、计划文件（`sidPaths.plans()`）、
会话工具输出落盘（`<trajectories>/sessions/`）。**不豁免整个 `~/.sid-code`**
（里面有 `settings.json`、`usage-ledger.jsonl`），**不豁免 `/tmp`**（CC 也不）。

## 放弃了什么（以及为什么不选）

**只豁免整个 `~/.sid-code`（J4 的 A 案）——否决。** 那样 `cat ~/.sid-code/settings.json`
和账本文件也会静默放行，而它们恰恰是最该拦的。

**给读路径校验也加上「敏感文件」判定——否决。** `cat ~/.ssh/id_rsa` 在 Step 2 就被
「读取 SSH 密钥」拦成危险确认（修前修后都是），这一层再判一次只会产生两套结论。
`evaluateReadOnlyReadPaths` 因此只看「在不在工作目录集合内」，其余一律 `continue`。

**确认框的「本会话允许读取 <目录>」按钮——本轮只做规则侧，UI 入口留待后续。**
规则生效链路已完整（`metadata.suggestedReadDir` + `isReadPathCoveredByReadRule`，
集成测试覆盖「配了规则 → 同目录放行 / 目录外仍确认」）。缺的是 `permission-choices.ts`
到 `app.ts` 的选项接线，它属于 TUI 键盘交互改动（需 G4 `smoke:tui` 验证），
与本 PR 的核心（读路径判定）是可分离的交付单元。用户当前可用 `/allow` 或 settings
手写 `Read(//dir/**)` 达到同样效果。

**给 `git` 也提读路径——否决。** `git show HEAD:f` / `git -C <dir>` 的路径语义是 git 自己的，
PR-1 的 `judgeReadOnlyGitInOwnRepo` 已经管了仓库归属；两处都管会出现「一处放行一处拦」。

## 拿什么证明它生效了

**单测 14 例**（`packages/core/tests/permission/readonly-read-paths.test.ts`）：
提取器认哪些参数是路径（含 `grep` 跳模式 / `-e`、`-f` 的值、`find` 取起点、`diff` 取两个、
`sed` 跳脚本、`echo` 不提取、输入重定向、`sh -c` 内层）、按段 cwd 解析、`;` 多候选、
`~` 展开、J4 豁免边界（`tasks/` 与 `tasks-evil/` 不能互相误伤）。
`bun test ./packages/core/tests/permission/readonly-read-paths.test.ts` → **14 pass / 0 fail**。

**集成测试 18 例**（`readonly-read-paths-integration.test.ts`，真实 `PermissionChecker` +
`BashTool.prototype.checkPermissions`），逐行对齐方案 §6.1 的 PR-3 表格：
- 变放行 8 例（`cat ../README.md` / `ls ../` / `grep -rn foo ../packages` / `cat packages/../README.md`
  × default / acceptEdits）；
- 变确认 4 例（工作区外绝对路径、`ls /tmp`、`cd <ws> && cat <工作区外>`、cd 进子目录后 `../`
  仍在工作区内 → 放行）；
- 必须不变 3 例（`cat ~/.ssh/id_rsa` 仍是危险确认、`python3 ../x.py` 仍报「路径遍历」、
  工作区内无 `../` 的只读命令照旧放行）；
- J4 2 例（`tasks/*.output` 放行、`settings.json` 仍确认）；
- 会话规则 1 例（配 `Read(//<dir>/**)` 后放行、目录外仍确认）。
`bun test ./packages/core/tests/permission/readonly-read-paths-integration.test.ts`
→ **18 pass / 0 fail**。

**变异自证**（先把被测代码改坏、确认断言变红、再恢复）：
1. 去掉 Step 5.5 的两行读路径校验 → **4 fail**（工作区外读取全变放行）；
2. 把 `skipPathTraversal` 恒置 `false`（恢复「路径遍历」对只读命令生效）→ **9 fail**。
两次都把恢复后的版本重跑确认回到 18 pass / 0 fail。

**PR-2 夹具的合法契约变更**：`readonly-compound-integration.test.ts` 的「本会话 21 条原文」里
#8 是 `sed -n '1,80p' /tmp/sid-poll-probe/sim.ts`——读的是**工作区外**的 `/tmp` 文件，
按 B5 修后应从 ALLOW 变 ASK（正是 §6.1「变确认」那一行的同类形态）。已把它单独拆成
断言 ASK 的用例，其余 20 条仍断言 ALLOW。`bun test ./packages/core/tests/permission/readonly-compound-integration.test.ts`
→ **64 pass / 0 fail**。

**门禁**：
- `bun run affected-tests:run` → **1410 pass / 0 fail**（58 files）。
- `make build` → 成功（编译产物自检全绿）。
- `bunx tsc --noEmit -p packages/core`：改动文件零类型错误。

**过程中发现并修掉的两个真 bug**（都不是「测试写错了」）：
1. `evaluateReadOnlyReadPaths` 最初用 `verdict.outsideWorkingDirs` 当判据——但白名单非空时
   `validateAccess` 在「目录不在白名单中」那一步就返回了，该字段只在**白名单为空**时才置位。
   实测 `allowedDirectories: [ws]` 下工作区外路径全部漏判成放行。改用
   `isWithinWorkingDirectories(verdict.resolvedPath)`。
2. `stages` 最初用 `[...possible, ...history]` 当 cwd 候选，把 cd **之前**的目录也带了进去：
   `cd <ws>/packages && cat ../README.md` 于是多解析出一个 `<ws>/../README.md`（工作区外），
   该放行的判成越界。改用只含「cd 成功后确定目录」的 `stagesCwds`
   （`;` 的回退目录都在工作区内，少算它不会漏掉任何越界读）。
