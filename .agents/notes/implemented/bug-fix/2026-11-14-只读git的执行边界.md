# 只读 git 的放行边界：前导变量白名单 + 换仓库选项不剥离 + 仓库归属判定

## 决定了什么

把「只读 git 命令跳过确认」这条快速路径的三处缺口一次补上（方案里的 B1 / B2 / B4，PR-1）：

**B1 前导变量赋值只按白名单放行**（`tool/bash/read-only-validation.ts`）。旧实现完全不看
`VAR=x cmd` 里的 `VAR`，于是 `GIT_EXTERNAL_DIFF=/tmp/evil.sh git diff`、
`GIT_CONFIG_COUNT=1 … git status` 与裸 `git diff` 同样判只读、零确认执行——一条看起来是
`git status` 的命令能跑任意程序。现在 `SAFE_ENV_VARS` 只收 16 个只改输出/运行时行为的变量
（`LANG`/`NO_COLOR`/`TERM`/`RUST_LOG` 等）加 `LC_*`，**任何 `GIT_*`、`*PATH`、`*_OPTIONS`、
`PAGER`、`EDITOR`、`HOME`、`TMPDIR`、`SHELL`、`BASH_ENV`、`ENV`、`IFS` 都不收**。
黑名单补不全（git 自己读几十个变量），所以这一步只能是白名单。

配套改了 `tool/bash/parser.ts`：新增 `extractShellStatements`，把**独立变量赋值语句**
（`GIT_DIR=…` 单独一行）也带出来——`extractSimpleCommands` 会丢掉 `command` 为空的条目，
判不到它。普通独立赋值（`B=origin/x` 换行再 `git show $B:…`）保持放行，只有
`GIT_*` 与注入类变量名在独立赋值里也判非只读（同名变量可能早被 export 过，
判定不能依赖运行时会话状态）。

**B2 换仓库类全局选项不再被剥离**（同一文件）。`SAFE_GIT_GLOBAL_VALUE_OPTS` 删掉
`-C` / `--git-dir` / `--work-tree`，`SAFE_GIT_GLOBAL_BOOL_OPTS` 删掉 `--bare`。
它们的共同语义是「用哪个仓库」，与 `cd <目录>` 等价——`cd` 判非只读时 `-C` 不能例外。

**B4 只读 git 必须作用在本仓**（新增 `permission/git-repo-trust.ts` +
`permission/readonly-git-boundary.ts`，接入 `permission/checker.ts` Step 5.5）。
判定只做 stat 与读一个小文件（`.git` 目录 / `.git` 文件的 `gitdir:` + `commondir` /
裸仓库形态 `HEAD`+`objects/`+`refs/`），不起子进程。四种结果 `own` / `foreign` / `bare` / `none`，
只有 `own` 放行；**本仓的 linked worktree 算 own**（公共 git 目录相同）。

权限层的两条路径共用 `judgeReadOnlyGitInOwnRepo`：

- 工具说 allow → 命令含 git 段时再判边界，越界就**不返回 allow**、落到后续步骤（最终是普通确认）；
- 工具没意见（passthrough）→ **补回**被 B2 严格口径挡掉的 `git -C <本仓内目录> <只读子命令>`。
  剥掉的只有 `-C`，且目标必须是字面量、属本仓；剥完仍要逐段复用 `isReadOnlyCommand`
  重判只读，**不另写一套只读规则**（两套规则必然漂移）。前导变量赋值在重判时一并拼回去，
  所以剥 `-C` 不会把 `GIT_DIR=… git -C <本仓> status` 洗白。

## 放弃了什么（以及为什么不选）

**不做「前导变量黑名单」。** 现成的黑名单（`bash-security.ts` 的 `validateDangerousVariables`）
只盖 `PATH` / `LD_*` 等九个，而 git 自己读 `GIT_EXTERNAL_DIFF`、`GIT_CONFIG_*`、`GIT_DIR`、
`GIT_EXEC_PATH`、`GIT_SSH_COMMAND`、`GIT_PAGER`、`GIT_EDITOR`…… 一个都不在。补一节漏一节。

**不做「`-C` 目标必须在工作区物理范围内」。** 方案 B2 的原话是「解析后在工作目录内」，
但本仓的 linked worktree 常常建在工作区外（`/tmp/wt`），它的**公共 git 目录与主仓相同**、
配置与 hooks 都来自主仓，按物理位置判会把它误判成「别人的仓库」而白弹确认。
改用 B4 的仓库归属判据（`trust === "own"`）——比物理位置**更本质**，也没放松：
判据从「在哪」变成「是谁的」，`foreign` / `bare` 依然不放行。

**不给 `env VAR=x cmd` / `export VAR=x` 单独放宽。** 实测（2026-11-14）这两种写法修前就是
ASK：`env` 剥离后程序位是 `GIT_…=…`（不在只读表），`export` 本身也不是只读命令。
方案 §6.1 把 `env GIT_EXTERNAL_DIFF=…` 列在「变确认」组，实测它属于「修前修后都 ASK」。
只让 `isReadOnlyCommand` 保持「不认识 env 赋值对」的保守口径，不放宽。
代价是 `env LANG=C git log` 这类安全写法仍会确认一次——比放宽后漏掉一个 `GIT_*` 划算。

**不对裸 `git status` 加例外。** `none`（不在任何仓库里）也落确认，按方案口径
「git 会报错，不危险，但没必要放行」。副作用是非 git 工作区里所有只读 git 都多一次确认；
这是安全方向上的退化，接受。

**没有改 `isReadOnlyCommand` 的其它消费者。** `isReadOnlyCommand` 只是变严（并发安全判定、
末尾 `pwd -P` 回写会跟着变保守），属于方案里已点破的「无害」一侧；权限层的补回只发生在
Step 5.5，不下沉到工具层。
