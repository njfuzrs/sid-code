# 压缩结局三态化，失败计数与 loop 层熔断归一到 settleCompaction

## 决定了什么

- **三态结局**（`query/compact/outcome.ts` 的 `judgeCompaction`）：`applied / noop / failed`。判定顺序为「消息数下降 → savedTokens>0 → 主动压缩类 trigger 带 noopReason 判 noop → 其余 failed」，**实测证据优先于 noopReason**。
- **恢复路径不许 noop**：`NOOP_ALLOWED_TRIGGERS` 只有 `threshold_blocking/emergency/hard` 和 `empty_param_retry`。PTL、context_overflow、ctx_window_exceeded 是 API 已拒收之后的路径，「没东西可压」在这些路径上算失败。
- **计数与熔断只有一个写入点**：`settleCompaction(deps, sid, {state, promptSeq}, info)` 内部维护 `consecutiveCompactFailures`（applied 清零、failed +1、noop 不动），达到 3 次时置 `LoopState.compactCircuitOpen`。它在本条用户消息内 latch，之后的 applied 只清零计数、不关闸。调用方原来手写的 8 处计数全部删掉；PTL 失败和 empty_param 失败原先不落 `CompactionAttempt`，现在也经它落盘。
- **熔断语义按路径分开**：阈值 hard 档开闸后只跳过 `contextCollapse` 和 `autoCompact`（都调 LLM），本地管线和 emergencyTruncate 照做，主循环继续。如果熔断状态下管线也一步没做，就不算一次尝试，不插边界、不置重注入标志。PTL 兜底改读 `compactCircuitOpen`，仍是「终止本轮」。
- **`AutoCompactOutcome` 拆出 `"failed"`**，返回 `{ kind, reason? }`。原来降级截断也没切成时返回 `"skipped"`，现在改成 `"failed"`；`"skipped"` 只留给 too_few_messages、lock_held、hook_blocked。
- **context_overflow 补同源 token**：它原来是唯一只传消息数的调用点。
- **可观测**：
  - 新增事件 `CompactionCircuitBreaker`（每条消息最多 1 条）和 `CompactionSkipped`（每跳过一次花钱的动作就发一条，用来量「更省」）；
  - `CompactionAttempt` 增加 `outcome / judged_by / noop_reason / prompt_seq / turn / consecutive_failures`（判定后的值）`/ circuit_open`；
  - `TurnComplete` 增加 `consecutive_compact_failures?` 和 `compact_circuit_open?`。
- 删除 `LoopState.transition` 死字段（写 1 次、读 0 次）。可测试性由 `LoopTransition` 事件和 `continueCounts` 承载。

北极星：服务「更省」（停止白烧的 collapse/autoCompact）和「可观测」。牺牲的是「更准」：熔断后只剩有损的本地截断，warning 文案会告知用户。

## 放弃了什么（以及为什么不选）

- **给阈值三档各补一行 `+1`**：新增 trigger 时照样会漏；也没区分 noop，「历史已经极简」的正常会话 3 轮内就会误熔断。
- **noopReason 最高优先级**：hard 档管线报「没东西可压」、随后 autoCompact 真压动了，这种情况会被判成 noop，横幅不画、notifyCompaction 不调。
- **`unknown` 第四态**：只对应 context_overflow 一个漏传 token 的调用点，把 token 补上即可。
- **熔断后跳过一切压缩、继续跑**：PTL 路径上 API 已拒收，跳过压缩再发同一个请求必然空转（交互模式 maxTurns=Infinity）。blocking/emergency 跳过的是零成本的本地截断，省不了钱，只会更快撞上 PTL。
- **把 autoCompact 的 `"skipped"` 原样映射成 noop**：会把「摘要失败且降级截断也没切成」漏计。
- **SessionState 级跨消息熔断**：和进程级 `AutoCompactCircuitBreaker`（5 分钟恢复期）重叠，会形成第二个事实源。
- **loop 层也调 `recordDefenseTrigger("compact_breaker")`**：同一类事件会在 defense 指标里被两个熔断器各记一次。
- **让 `LoopTransition` 事件改读 `state.transition`**：事件会从「报告本次入参」退化成「报告状态里存的值」，写入路径一出错就会滞后错位。
- **给 `done` 出口加埋点**：出口数是代码结构事实，不是运行时指标。
