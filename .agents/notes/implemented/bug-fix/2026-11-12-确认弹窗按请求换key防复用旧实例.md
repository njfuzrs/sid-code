# 确认类弹窗按请求对象换 key，连续同类请求不再复用旧实例

## 决定了什么

`DialogRenderer`（`packages/cli/src/ui/components/DialogManager.tsx`）给权限框、Shell 确认框、
Plan 审批框、AskUserQuestion 框都加上按**请求对象**派生的 React `key`（WeakMap 发号）。
每来一个新请求就强制重挂载，组件内的 `resolvedRef` 去重和光标 state 都回到初始态。

根因：模型一次发两个都要确认的工具调用（如两个并行 bash）时，第一个答完后 app.ts
`updateState({ permissionRequest: null })`，interactionQueue 随即写入第二个请求。两次 update
合并进同一帧，React 看到的是「同一位置、同一组件类型、只换了 prop」，于是复用旧实例：
`resolvedRef.current` 还是 true，`decide` 直接 return，而 `HotkeyChoiceList` 的 handler
照样返回 true 吞掉按键。表现就是第二个弹窗 Enter / y/n/a / Esc 全无反应、关不掉。

用户报告的是「acceptEdits 下不行、auto 下正常」。这不是 acceptEdits 的逻辑问题：
auto 模式下分类器放行了这类命令，根本不会弹第二个框；acceptEdits 对非 fs 的 bash
照常弹框，于是撞上。default 模式同样会复现（PTY 探针实测）。

## 放弃了什么（以及为什么不选）

- **在 `request` 变化时用 effect 重置 `resolvedRef`**：effect 在提交之后才跑，
  中间有一个窗口（预输入）仍会被吞；并且光标 state 也得一起手动重置，四个对话框
  各写一遍，下一个新增对话框还会忘。换 key 一处解决全部状态。
- **在 app.ts 里把 null 和下一个请求拆成两帧**（比如 setTimeout）：依赖时序，
  而状态桥的合并策略将来改了就会复发；问题出在组件身份，应该在组件身份上修。
- **去掉 `resolvedRef` 去重**：它防的是双击回车把同一个请求 resolve 两次，
  这一层还要保留。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/components/permission-dialog-consecutive-requests.test.tsx`
  （真 KeypressProvider + rerender 换 request）：6 pass。
  变异自证：去掉所有 `key={requestKey(...)}` 后 6 个用例全红，恢复后全绿。
- PTY 端到端探针（xterm-headless 驱动 `make build` 产物，回放两个并行 `curl` bash 调用）：
  修复前 `--permission-mode acceptEdits` 下第二个弹窗按两次 Enter 仍在屏（`after key closed: false`）；
  修复后 acceptEdits 与 default 都是 `after key closed: true`。
- 回归层：G1（组件按键单测）。之前没拦住，是因为已有确认框测试都只挂载**一个**请求，
  没有覆盖「同一位置连续换请求」这一帧。
