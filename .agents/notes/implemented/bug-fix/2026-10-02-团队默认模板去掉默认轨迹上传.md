# 团队默认模板去掉 `trace.upload`，并用迁移 v6 收回已写进老用户配置的那段

## 决定了什么

- `scripts/team-defaults.template.json` 的 `trace` 只留 `{ "enabled": true }`（本地采集），
  删掉整段 `trace.upload`（`url` 指向 sid-code.cc、`auto_upload: true`、共享 token）。
  这份模板经 install.sh 首装整份拷贝、经迁移 v1 给缺 `trace` 的老用户补进去，
  于是照官网装的任何人会话轨迹默认自动上传到维护者后端，与「数据主权」和
  `team/observability.md`「上传默认不发生」正面冲突，且不报任何错。
- 新增迁移 v6 `remove-team-default-trace-upload`：`trace.upload.url` 与 `token`
  **两项都精确等于旧模板值**才删 `trace.upload` 子键，保留 `trace` 其它字段，只动 userSettings，
  写盘走 `patchSettingsFile`，删了就打一条启动提示告知用户。
- `website/team/defaults.md` 补一句「模板不含上传配置，要集中收自己填」。

## 放弃了什么（以及为什么不选）

- **只改模板不加迁移**：改模板只影响新装用户；已经写进磁盘的那段永远不会被收回。
- **只按 url 匹配（或只按 token）**：组内拿到真实 token 的人同一地址自配上传会被误删，
  后果是「轨迹静默不再上传」——与本迁移要修的问题同型。两项都对上才动，宁可漏删。
- **把 `auto_upload` 改成 false 而不是删**：仍把维护者地址与 token 留在陌生人磁盘上，
  且 token 本身已公开，留着没有意义。
- **在 uploader 里硬拦旧地址**：把一次性数据清理变成永久运行时特判，且会误伤合法自配。

不在本 PR 范围（需运维动作、仓库里做不了）：轮换服务器 `UPLOAD_TOKEN`、
用 `--upload-team-defaults` 替换公网 `team-defaults.json`。旧 token 已在 git 历史里，
删文件不等于撤销，轮换是必须的。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/migrations/`：41 pass / 0 fail。新测试含 7 条反向用例
  （同地址自有 token、自建地址沿用旧 token 字串、env 占位符 token、类型不对、文件不存在、写盘保真）
  与经 runner 的 v1→v3→v6 串联（旧 IP 时代用户最终无 upload；缺 trace 的老用户补进来的不含 upload）。
- 变异自证：把判据改成只比 url，「用户换了自己的 token」「env 占位符 token」两条转红（9 pass / 2 fail），复原后全绿。
