# 废弃工具参数从 zod schema 移到别名层，调用侧仍兼容

## 决定了什么

1. `grep.total_max_matches` 与 `bash.is_background` 从各自 zod schema 删除。
   常驻（非延迟）工具 schema 合计从 31,679 字节降到 31,380，每轮少 299 字节上下文，
   按 25 个常驻工具的口径均摊在两个字段上（文档估算的 212 字节只算了字段本身，
   实测差值包含 JSON Schema 的 `required`/`properties` 连带变化）。
2. 在 `input-alias.ts` 的 `ALIASES` 登记两条旧名映射
   （`total_max_matches → head_limit`、`is_background → run_in_background`）。
   改名发生在 `validateToolInput` 里、zod 校验**之前**，所以老对话记忆带出来的旧键
   仍然能通过；两键同时出现时保留协议字段、丢弃旧名（沿用 `activeForm` 的守卫）。
3. 删掉执行层对旧名的全部判断：`bash.ts` 5 处
   （`withForegroundSleepNotice` / `withWaitUntilNotice` / `beginBashTracking` /
   `withTrackedFileChanges` / `executeCommand`）与 `grep.ts` 的
   `?? params.total_max_matches`。执行层只认协议字段。
4. 同步删掉两处会误导模型的文案：`grep.head_limit` 描述里的「替代旧的
   total_max_matches」、`bash` usageGuide 里的「旧名 is_background 已废弃」。
   schema 里已经没有这两个名字，再提只会让模型以为参数还在。
5. `website/ref/tools.md` 由 `bun run docs:gen-reference` 重新生成（两个字段从表里消失）。

## 放弃了什么（以及为什么不选）

- **保留字段、继续标 deprecated（即改动前的现状）**。30 天用量统计里两个字段
  没有一次是有意义的值（`grep` 495 次全为 `null`、`bash` 528 次全为 `false`），
  全部来自走 OpenAI strict 线的 gpt-6 系列——是 schema 强制模型给 optional 字段填占位值，
  字段存在本身就在消耗上下文和模型输出 token，收益为零。
- **只删 schema、不留别名**。zod 对未声明的键是**静默剥离**，不报错。删干净而不改名
  会让旧键从「生效」变成「静默忽略」：`is_background: true` 会退化成前台执行、
  `total_max_matches` 会退化成默认 250 条——这是正确性回归。别名层改名是零成本兼容。
- **在执行层保留 `|| params.is_background` 兜底**。别名发生在执行之前，兜底分支
  永远为假；留着只会让后来读代码的人以为旧名还有独立通路，也会让 grep 兜底验收失真。
- **用 zod preprocess 做改名**。`input-alias.ts` 文件头已论证：preprocess 会把
  schema 的 `def.type` 变成 `pipe`，破坏 nullish / numeric 两层的拆包，
  `active_form:null` 会从「剥成缺省」退化为「校验失败」。

## 拿什么证明它生效了

- **单测（真实链路，validateToolInput → execute）**：
  `bun test ./packages/core/tests/tool/input-alias.test.ts ./packages/core/tests/tool/grep.test.ts ./packages/core/tests/tool/bash-stability.test.ts`
  → `70 pass / 0 fail`。新增 D3 组 4 条：grep 旧名按 `head_limit` 执行、
  bash 旧名走后台并拿到 `task_id`、两键并存保留协议字段、旧名传 `null` 被 nullish 层剥掉。
- **schema 真值**：`bun run packages/cli/src/entrypoints/bootstrap.ts --dump-tools`
  后用 `grep -o '"total_max_matches"\|"is_background"'` 搜产物 → 输出为空；
  附录 A `resident_bytes.py` 统计 → `常驻 24 个，合计 31380 字节`（基线 31,679，少 299，
  验收门槛 ≥200）。
- **源码兜底**：`grep -rnF 'is_background' packages/core/src` 与
  `grep -rnF 'total_max_matches' packages/core/src` → 各只剩 `input-alias.ts` 的别名登记。
- **选测**：`bun run affected-tests:run` → `1713 pass / 1 skip / 0 fail`（106 个文件）。
- **构建与门禁**：`make build` 自检通过；`bun run lint` / `format:check` /
  `lint:boundary` / `lint:command-system` / `lint:legacy-tool` / `typecheck:gate` /
  `docs:gen-reference --check` 全过；`bun run smoke` 26 例全过。
- **G2 变异自证**：`bun run scripts/smoke/mutate.ts B2-seatbelt CG1-cwd-cross-root`
  → 4 条变异全部 `killed`（其中两条配方指向本次改过的 `bash.ts`：sandbox 包裹失效、
  cwd 跨根不通知），说明改动过的文件仍被冒烟用例有效覆盖，不是「改了也没人测」。
