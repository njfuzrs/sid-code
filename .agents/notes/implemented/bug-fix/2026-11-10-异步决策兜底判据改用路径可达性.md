# 异步权限决策的兜底判据改用「路径可达性」，并删掉零引用的旧 resolver

## 决定了什么

`resolvePermission()`（三路竞争）里三处判据原先不同源：grace 初始化只看 `options.userDecision`，Race 3 看 `userDecision && isInteractive && !isSubAgent`，兜底看 `!isInteractive && !hookDecision && !classifierDecision`。现在统一成一个 `userDecisionPath`（`userDecision && isInteractive && !isSubAgent`）。

兜底分支的触发条件从「非交互且无 hook/classifier」改成「三路都没接上」（`!userDecisionPath && !hookDecision && !classifierDecision`），文案从「非交互模式，无自动决策路径」改为「无任何权限决策路径，立即拒绝」。`DecisionSource` 的 `"auto"` 保留，语义从「非交互的自动决策」改为「三路都没接上时的框架兜底」。

删除 `PermissionResolver` 类（`@deprecated`）与 `createDecisionId()`：全仓 `.ts` grep 只有定义处，零引用。

同步 `tool-executor.ts` 的 `normalizePermissionSource` 注释与 `website/blog/sc-11-hooks.md` 里引用的代码片段。新增 `packages/core/tests/permission/async-decision.test.ts`（8 用例）。

## 放弃了什么（以及为什么不选）

- **纯删兜底分支**（A10 原文给的两个选项之一）：删掉后「调用方传 isInteractive=true 但没接 userDecision」会退化成等满 300s 超时才 deny（探针实测 timeoutMs=300 时 305ms 返回 timeout）。分支不可达的根因是唯一调用方写死 `isInteractive: true`，但判据本身是错的、可复发：任何新增调用方都会踩。保留分支换判据，对现有唯一调用方零行为变化，还顺手堵住这个坑。
- **接上真实的交互状态**（另一个选项）：不可行。真实非交互场景在 `checker.isNonInteractive()` 层就把 ask 落成 deny（`checker.ts:2086`），返回的决策不带 `needsConfirmation`，`tool-executor` 根本不会启动三路竞争——即使接上真实值，这个分支在真实非交互场景仍不可达。且「真实交互状态」没有单一来源：权限层用 `print/maxTurns/externalAskChannel`，core bootstrap 用 `process.stdout.isTTY`，cli bootstrap 另有初始 `true` 的 UI 状态。
- **删掉 `DecisionSource` 的 `"auto"`**：不删。改判据后它有了真实产出者；它已进入本地轨迹与遥测映射（`normalizePermissionSource` 把 `auto` 映射到 `other`），而 core 的 exports 是 `"./*"` 通配，删枚举成员属于对外类型收窄。
