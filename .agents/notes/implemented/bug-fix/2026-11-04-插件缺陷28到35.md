# 插件缺陷 28–35：标识符/注册表/生命周期操作按边界与真实语义收口

## 决定了什么

按《20260927-SDK与插件-顺着sc-17核出的缺陷》的缺陷 28–35 逐条修，一个 PR 内交付：

- **28（`parsePluginId` 首个 `@`）**：改 `lastIndexOf("@")`。`buildPluginId` 与 `parsePluginId`
  现在互逆；`manifest.ts` 的错误 source 不再手写 `${pluginPath}@${sourceKind}` 模板，
  统一走 `buildPluginId`，与 `LoadedPlugin.source` 同一构造口径。
- **29（installed.json 的 path 与键名）**：`loadInstalledPlugins` 保留键名，逐条校验：
  `path` 必须是非空绝对路径；`external !== true` 时 `path` 必须落在 `getPluginsDir()` 之内
  （`path.relative` 判据）；加载后 `key === plugin.name`，不一致报 `generic-error` 并跳过。
  新增 `InstalledPluginEntry.external`，`installPlugin` 在 `--no-copy` 时写入 `true`。
- **30（`path-not-found` 的 component）**：`component` 改为可选；装载器里两处「整个插件目录
  不存在」不再硬编码 `"commands"`，`formatPluginError` 按有无 component 输出两种文案。
- **31（`--delete-files` 前缀判据）**：`uninstallPlugin` 的 `startsWith(pluginsDir)` 换成
  `isStrictlyInside()`（`path.relative` 结果非空、不以 `..` 开头、非绝对路径），
  `/plugins-backup/foo` 与 `/pluginsEVIL` 不再被 `rm -rf`。
- **32（依赖闭包算完就丢）**：`enablePlugin` 按 `resolution.closure` 逐项 `setPluginEnabled`
  （依赖在前、根在后），返回消息列出同时启用的依赖；lookup 改走 `findRegistryKey`，
  支持依赖写成插件名或完整 source。
- **33（`enabledKeys` 死变量）**：删除构造/填充/维护三处与那条错误的「触发级联」注释。
  级联由 `stillEnabled` + `changed` 固定点驱动，与该集合无关。
- **34（生命周期操作不刷新运行时）**：新增 `runtime-refresh.ts` 注册器，app 启动时注册
  一个闭包调 `refreshActivePlugins({ unifiedRegistry, toolRegistry, hookSystem, mcpManager,
  skillManager })`；install/uninstall/enable/disable 完成后调 `refreshPluginRuntime()`。
  命令层与 TUI 面板只有在**未刷新**（headless / CLI 子命令 / 测试 / 刷新失败）时才提示
  「运行 /reload-plugins 使其生效」。
- **35（内置插件 `${PLUGIN_ROOT}` 展开为空）**：在 `hook/config-normalize.ts` 的
  `convertHandler` 里显式拒绝：command/args 出现 `${PLUGIN_ROOT}` / `$PLUGIN_ROOT` 而
  `ctx.pluginRoot` 未提供，或出现 `CLAUDE_PLUGIN_ROOT` / `SID_CODE_PLUGIN_ROOT` 而
  `pluginRoot ?? skillRoot` 都没有 → 报 error 诊断并跳过该 hook。

## 放弃了什么（以及为什么不选）

- **29 没有一刀切「path 必须在 plugins 目录内」**：`--no-copy` 是显式的原地引用功能
  （开发场景），路径本来就在插件目录外。用 `external` 标记区分「用户显式选择的外部路径」
  与「手改 installed.json 塞进来的路径」。代价是**旧版 `--no-copy` 条目没有该标记，
  升级后会被拒并提示重新安装**——这个兼容性破坏是有意的：静默放行等于保留
  「一个可编辑 JSON 就能让加载器扫描任意目录」的攻击面。
- **35 没有选「保留占位符原样」**：字符串保留 ≠ 安全，shell 仍会把 `${PLUGIN_ROOT}`
  展开成空串，`/hooks/x.sh` 照旧产生。也没有只在内置插件层检查：这是「声明了路径变量
  但来源没有提供值」的通用错误，放在归一化层能同时覆盖内置插件、无根 skill 等所有来源。
- **34 没有让 operations 直接 import refresh.ts**：operations 是纯生命周期逻辑，不知道
  `hookSystem` / `skillManager` / `mcpManager` / `UnifiedRegistry` 在哪个进程里存在；
  调用方有斜杠命令与 TUI 面板两个，各自能拿到的句柄也不同。注册器让两者共用一条路径，
  未注册的进程（headless / CLI 子命令 / 测试）自然退化为旧行为。
- **32 没有只启用直接依赖**：`resolveDependencyClosure` 返回的闭包已按依赖顺序排好，
  只启用直接依赖会让传递依赖继续缺失，下一次加载又被 `verifyAndDemote` 降级。
