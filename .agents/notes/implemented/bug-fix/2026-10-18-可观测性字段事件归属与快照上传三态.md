# 轨迹可观测性字段：fork 事件归属、/debug 上传三态、end_time 只在真结束时写、ts/index 口径、失败事件带错误摘要

## 决定了什么

S10、S11、S12、S14、S17（20261016 静默停住方案 §2 D 类）。

- **S10 事件归属**
  - StreamPhase / HttpConnected：在请求发起时捕获一次 `RequestContext`，emit 点显式带上 `agent_id`、`caller`（`stream-observer.ts` 的 `streamAttributionOf`，openai / anthropic 两个 provider 都改了）。
  - PermissionDecision：由 fork（`forked-agent.ts`）和子代理（`tool-executor` / `agentic-loop` / `sub-agent`）的执行入口显式传 `agentId`。
  - 主循环事件逐字节不变，不加 undefined 字段。
  - 归属只写进事件，不进快照 key。
- **S11 /debug 上传状态**
  - `uploadSnapshot` 超时返回 `pending:true`，`/debug` 分三态显示（✓ / ◐ 仍在后台上传 / ✗）；`clearTimeout` 收掉 5s 定时器。
  - 中途快照走 `uploadSession(..., {snapshot:true})`：不清理本地文件，`.uploaded` 写 `final:false` 和 `snapshot_at`。
  - backfill 和本地淘汰统一用 `hasFinalUploadMarker` 判是否已上传；历史无字段的标记按 final 兼容。
  - backlog 补 `noTraj / emptyTraj / tooNew / errored / unaccounted`，主行加 `live N`，不平时提示「计数自检不平」。
- **S12 end_time**
  - 进行中的会话省略 `end_time`，新增 `snapshot_at` 和 `session_ended`，`exit_status` 写 `live`。
  - digest 的 `deriveDuration` 缺 `end_time` 时回落到 `snapshot_at`，并标「进行中，截至快照」。
- **S14 时间戳与 index 口径**
  - 新增单一事实源 `EVENT_TS_SEMANTIC`，只在 `SessionStart` 里写一次 `ts_semantics`。
  - raw.jsonl 完整行加 `ended_at` / `elapsed_ms`。
  - collector 侧给主循环的 StreamPhase / HttpConnected / BilledRequest 补 `pair_index`（与 BeforeModel 同一个全局 index）。带 `agent_id` 或 `caller` 的事件不补。
- **S17**：PostToolUseFailure 带 `error_kind`，以及截断到 200 字符的 `error_head`；上传前剥掉 `error_head`，只留本地。

## 放弃了什么（以及为什么不选）

- **在 `appendHookEvent` 里统一调 `getRequestContext()` 补归属**：ALS 只在流的 `next()` 期间有值，PermissionDecision 拿不到；定时器 flush 会继承注册时的 ALS，产生误标。
- **用 emit 的第 4 参 agentId 做归属**：它是快照 key 的第三段，而 provider 侧读快照时不带它，一个流会被拆成两个 key，watchdog 看到的快照就永远不前进。
- **end_time 写 null**：服务端是否接受 null 无法在本仓核实，所以改为省略这个字段。
- **逐行加 ts_semantic**：实测 4049 行要多出约 89KB（+7.3%），改为在 SessionStart 写一次。
- **改现有 timestamp / index 语义**：曲线会整体平移且不报红，所以只新增 `pair_index`。
- **error_head 上传云端**：脱敏只覆盖标准格式的密钥，路径脱敏默认关闭，所以只留在本地。
