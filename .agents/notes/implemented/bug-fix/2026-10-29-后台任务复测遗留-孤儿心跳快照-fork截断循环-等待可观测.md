# 心跳不再把子代理孤儿快照报成主循环 hang；fork 截断不再空参重试到超时；后台等待入参与进度进轨迹

## 决定了什么

来源：#358/#362 合入后的端到端复测（会话 `20261019-114231-fe220250`）遗留的 A1/A2/C1/C2。

- **C1 心跳孤儿快照**。根因有三点叠加：provider 层快照 key 无身份；loopId 按写入时的 ambient 取值，子代理请求跨越主循环 queryLoop 边界时会写进已被 `clearAllSnapshots` 清过的旧 namespace；这把 key 不属于任何清理路径。修法：
  - 方向 1：`streamWithResilience` 发起时把 `loopId` 绑进 RequestContext，同一条流不再拆成两把 key。`StreamSnapshot` 新增 `loopId` 和 `ownerAgentId`（取 ALS 身份，只做归属、不进 key）。`cleanupAgentSnapshots` 也按 `ownerAgentId` 认领清理。
  - 方向 2：心跳选取抽成纯函数 `pickHeartbeatSnapshot`。「无 agentId」不再等于「主循环」。无归属且 loopId 不是当前 ambient 的快照记为孤儿，不进 `active_request`，单独计数为 `stale_orphan_snapshots`。
- **C2 fork 截断循环**。`forked-agent` 遇到入参 JSON 解析失败时不再带着 `{}` 执行工具，而是回一条明确的 tool_result（「max_tokens=2048 截断，拆成多次小 edit」）。同一 `(工具, file_path)` 连续 2 次截断就提前结束本次 fork，结果带 `truncatedGiveUp: true`。
- **A1**：`TOOL_INPUT_SUMMARY_KEYS` 增加 `block` / `timeout` / `task_id` / `run_in_background`。
- **A2 选 (c)**：`PostToolUse` / `PostToolUseFailure` 增加 `progress_events` 计数，只在大于 0 时写；不新增事件类型。

## 放弃了什么（以及为什么不选）

- C1 方向 3（provider 层 key 带 agentId）：会拆开 `updateStreamStats` / `recordStreamProgress` / watchdog 的读取键，`stream-observer.ts` 的 StreamAttribution 注释明确警告过。方向 1 加 2 已经消除了假 hang，没必要冒这个风险。
- C2 只放大 session-memory fork 的 `maxTokens`：会抬高旁路成本，牺牲「更省」，而且大段改写仍可能截断。先给模型正确的信号，再加上限连击退出。
- A2 (a) 不记：测试只能证明 UI 帧，证明不了真实会话里进度有没有出现。(b) 首末条 span：要新增事件类型，而一个计数已经能回答问题。
- B1（中间唤醒批次闸门）单独记在 `rejected/feature/2026-10-29-后台任务批次唤醒闸门.md`。
- A3 北极星口径、digest 表头成本口径、900015 abort 漏发终态 phase：不在本 PR 范围，原文档仍保留为待办。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/trace/heartbeat-orphan-snapshot.test.ts` 5 pass。它复刻了「流中途 clearAllSnapshots(loop1) 再切到 loop2」的时序。三处变异各自转红：去掉漏斗的 loopId 绑定、cleanup 不按 owner 清、孤儿判据置 false，各自导致 1 fail。
- `bun test ./packages/core/tests/agent/forked-agent.test.ts` 23 pass。恢复「解析失败照常执行」或去掉连击退出，`★C2` 用例转红。
- `collector.test.ts` 的 `★A1` / `★A2`：从白名单删掉 `block`，或删掉 event-handler 透传的 `progress_events`，各自 1 fail。
- 未做的验证：没有用 `sc-dev` 重跑 4 路后台子代理的端到端复测来观察真实心跳文件，结论来自时序复刻单测。
