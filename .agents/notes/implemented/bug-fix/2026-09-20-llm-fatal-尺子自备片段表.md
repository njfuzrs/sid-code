# `llm_fatal` 第三次漏判：尺子自备片段表，正分 / 满轮 502 不删

## 决定了什么

`verifier_health.llm_fatal` 只认「主模型请求失败」和「API 错误」+401/402/403。
网关这回回的是 `LLM 错误: Invalid token` / `Remote end closed …` /
`The socket connection was closed unexpectedly` —— 两条路径都没命中，
A2 六题、A1 三题 0 分进了能力分母（08b）。cc 臂 `cc_api_error_status`
已经能取到，但没有任何消费方接进这把尺子（08a §3.1）。

同一函数一次覆盖两侧，**三条同时成立**才 True：

1. 命中尺子自备片段表（`invalid token` / `remote end closed` /
   `socket connection was closed`）或硬拒码（sid：`sid_errors`；
   cc：`cc_api_error_status ∈ {401,402,403}`，不含 502/429）
2. 权威轮数 < `MAX_TURNS`（sid 只认 `sid_cost_source == "stream-json-result"`；
   兜底 `total_steps` 不许拿来比。cc 认 `claude-code.txt` 的 `num_turns`）
3. reward 不是正分（`build-pmars` socket 关了但已经解出）

消费方仍是 `w3-classify.py` / `compare-paired.py`，不再分叉。
⛔ 不对真实 `runs/` `--apply`，⛔ 不重跑 `w3-summary` 覆盖 `results/`。
已发表 pass@1 46.3% / 50.0% 是当时尺子下的历史事实。

## 放弃了什么（以及为什么不选）

**① 放弃「对齐产品 `RETRYABLE_CONNECTION_MESSAGES`」。**
2026-09-20 拿那张表撞 A2/A1 原文：A2 六题**零命中**，A1 socket 才有。
按「不要另写一份」落地，修完 `llm_fatal` 仍是 0。产品表还含
`terminated` / `failed to fetch` / `network error`，当评分排除太宽。

**② 放弃再叠一句中文「LLM 错误」。** 上一轮补 402 就是叠「API 错误」+ 状态码；
这次连这四个字都没有。再叠会迎来第四次（换一个网关回 `token invalid`）。

**③ 放弃 `api_error_status` 有值就 True。** A3 收敛后 53/54 为 None，
唯一非空是 `make-mips-interpreter` 的 **502 × 17、num_turns=43**。
502 可重试且本题已满轮，当 fatal 会把真实撞满洗成待重跑。

**④ 放弃用 `subtype == error_during_execution` 单独判。** 含 agent 真崩溃。

**⑤ 放弃事后改成绩。** 不重跑 54 题、不覆盖 `results/`。正确说法是
「当时分母掺了 6 个考场 0，敏感度见 08b §3」。
