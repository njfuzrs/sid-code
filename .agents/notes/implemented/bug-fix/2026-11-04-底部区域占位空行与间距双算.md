# 瞬态行占位在历史新增时放掉，TodoPanel 与 footer 下方的冗余空行去掉

## 决定了什么

用户截图（2026-11-04）里底部区域有三类多余空行，根因各不相同：

1. **回合中途的空白块**（「思考中」与 spinner 之间 3 行、Todo 末行与 spinner 之间 4 行）。#559 的 `useHeldRows` 让瞬态行（Toast / 状态提示 / 退出警告 / Composer 状态行 / 输入框高度）「出现过就占到下一轮开始」。BottomRegion 留白区是 `gap={1}`，一行空占位 = 1 行空白 + 1 行 gap，回合中出现过一次的提示会以 2 行空白的形式一直挂到回合结束。
   改法：`hooks/useHeldRows.ts` 增加第二个释放点，即历史区新增一项时（`HeldRowsContext.epoch` = `staticItems.length` 变化）放掉。这时帧本来就在变高，与 busy 上升沿同理。规则抽成纯函数 `nextHeldRows`，`InputArea` 的 `padInputRows` 改为复用它，不再手写一份。
   全屏布局（`DefaultAppLayout`，`height=rows` 固定）不会整帧重画，占位只浪费空间，所以下发 `enabled:false`。
2. **TodoPanel 上下各多 1 行**。`TodoPanel` 外层 `marginTop/marginBottom={1}` 与 gap 叠加，违反 BottomRegion 文件头「子组件不带外部 margin」的约定，从 6 月起就存在。已去掉。
3. **footer 下方 2 行**。`MainScreenLayout` 给 BottomRegion 传了 `paddingBottom={1}`，而帧写完后光标本来就停在下一行（`main-screen.ts` 光标约定），两者叠成 2 行。已去掉 padding，保留光标行作为与终端底边的间隔。

## 放弃了什么（以及为什么不选）

- **把 Toast / 状态提示合并成一个固定槽位**：这是诊断阶段的首选。但截图里的空白主要来自「占到回合结束」这个时长，不是来自槽位数量。合并之后空槽仍然挂一整个回合，只是从 2 行降到 1 行，还要改两个组件的语义和优先级。按历史增长释放直接消掉时长，改动更小。
- **占位态不放进 gap 容器**（空占位不吃 gap）：做不到。gap 由父容器按子节点数计算，子组件只要渲染出节点就会吃到 gap；返回 null 又等于不占位。
- **撤掉 #559 的占位**：会回到长会话里退格、提示消失时每次整帧重画 183KB 的状态，牺牲的是「更快」。

trade-off：释放那一帧，如果放掉的行数多于历史新增的行数，仍会发生一次整帧重画。E2E 里一整轮的重画次数没有变化（见下），说明真实流量下这个代价没有显现。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/ui/hooks/useHeldRows.test.tsx`：5 pass。**变异自证**：删掉 `|| policy.epoch !== state.prevEpoch` 后，「历史新增一项时放掉」与整帧用例 2 fail；恢复后转绿。
- `layout-bottom-region-snapshot` 快照的 diff 正是预期的三处：TodoPanel 上下各 −1 行，主屏 footer 后 −1 行；全屏的空行移到了留白区顶部（高度固定，总行数不变）。
- `main-screen-shrink-e2e`（PTY 里起真实 TUI + mock 模型）：`resets {"完整一轮":2, 其余全 0}`，与 #559 记录的基线一致，视口最长连续空行仍满足 ≤3。
- `bun run affected-tests:run`：2762 pass / 0 fail；`make build` 自检通过；lint、format:check、lint:boundary、typecheck:gate 全绿。
- 还没验证：没有在真实终端里用 `sc-dev` 手动跑一轮带 Ctrl+O 提示的长回合。
