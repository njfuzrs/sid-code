# 计划生命周期五项缺陷与可观测性

对照 docs-research 规划文档 §4「计划的生命周期」逐项核源码，确认 5 个真实缺陷，并补齐让它们在轨迹里可见的埋点。

## 决定了什么

1. **执行阶段不随用户回合结束**。删掉 `endExecution()` 和两处回合开头的调用。执行阶段只有三个出口：
   - `enter()`：新计划取代旧计划；
   - `forceExit("cancel" | "clear")`：用户取消，或 `/clear` 作废；
   - `completeExecution()`：执行阶段写下的 todo 清单全部完成。

   修复前，用户插一句话、ESC 后说「继续」、后台子代理的完成通知，都会把执行阶段清掉，压缩重注入、计划文件放行、Recovery Hook、fidelity 随之一起失效。
2. **取消和拒绝超限要如实告知**。这两条路径改为注入明确的 followup，告诉模型「没有被批准，不要执行」，超限时带上最后一次的修改意见。状态机记录 `lastOutcome`，`exit_plan_mode` 在非规划态只有 `isExecuting()` 为真时才说「已审批通过」。
3. **步骤计数改成肯定口径优先**。
   - 有步骤类标题（实施步骤、修改方案、Steps 等）时，只数这些章节；有标题但没有步骤类标题时，退回到排除口径；完全没有标题时全数。
   - 解析时隔离代码围栏。
   - 规划 prompt 要求把步骤写在 `## 实施步骤`。
   - 执行期修订计划后，重新解析步骤，并重放已发生的调用来对齐。
4. **压缩重注入带上路径和阶段**。截断时写明「以文件为准，用 read 读取 <路径>」。门控扩大到待审批阶段。紧急截断也重注入计划。
5. **计划文件原子占位**。`openSync(path, "wx")` 遇到 EEXIST 就把序号加一。配套三处改动：
   - write 工具把 0 字节文件当作新建；
   - 退出时回收从未写入的占位文件；
   - 启动清理回收崩溃遗留、超过 1 天的空占位文件。
6. **可观测性**：
   - 新增 `PlanTransition` 事件，字段有 `reason`、`executing_before/after`、`rejection_count`、`decision_source`、`feedback_chars`（只记长度）；
   - 新增 `PlanReattach` 事件，字段有 `plan_chars`、`truncated`、`compaction_source`；
   - `PlanFidelity` 增加 `step_parser_version`、`step_source`；
   - digest 新增 `plan_lifecycle` 行，内容是跃迁序列、结局、执行阶段跨了几个回合、重注入次数；
   - 对 v1 旧口径的步数，按当前口径重算计划文件并并列展示。

## 放弃了什么（以及为什么不选）

- **把执行阶段的结束挂到「回合结束 + 没有 todo」上**：todo 和计划之间没有绑定关系，模型不建 todo 的执行会被误判为「已完成」。
- **用 `[A-Z]` 这类结构化标记要求模型标注步骤**：真实计划都是自由标题。改 prompt 只能约束新计划，旧计划和不听话的模型仍要靠解析器兜底，所以选「步骤标题优先 + 否定词表兜底」。
- **继续补否定词表**：标题是开放集，词表永远追不上。本机 7 份真实计划有 4 个章节名词表都不认识，这是实测结果。
- **改用 sessionId 或随机 slug 防撞名**：计划文件名是给人翻的（§4.2），O_EXCL 能在保留现有命名的前提下消除竞态。
- **超长计划不截断、全量重注入**：异常大的计划文件会把压缩后腾出的空间吃回去。保留 20K 上限，同时给出取回方式。
- **把真实计划文件放进测试夹具**：这些计划来自公司仓库，不能进开源仓库，所以按它们的章节结构合成了夹具。

## 拿什么证明它生效了

- 修复前用本机数据验证（`~/.sid-code/trajectories/sessions`，403 个有 events 的会话，其中 7 个用到 plan）：
  - 7/7 的 `PlanFidelity.plan_step_count` 在 11 到 20 之间，而「修改方案」的真实项数是 3 到 5；
  - D1、D2、D4、D5 没有任何样本，原因是这些场景近 30 天没人走过，而且跃迁根本不落事件。
- `bun test ./packages/core/tests/plan/plan-lifecycle-defects.test.ts`：23 pass。真实计划形态的夹具从 14 步降到 3 步。
- 变异自证：10 个变异点都让对应断言变红。变异点包括：一律说已批准、去掉步骤章节优先、去掉围栏隔离、去掉修订重对齐、重注入不带路径、紧急截断不重注入、退回 existsSync、write 不认空占位、不回收占位、reason 写错。D1 的方法已经删除，由源码哨兵断言把关，不允许 app.ts 再调用 `endExecution(`。
- 上线后的验收口径：
  - D1：`plan_lifecycle` 的「执行阶段跨 N 个用户回合」中 N > 0 的比例，修复前必然为 0；
  - D2：`reason=cancel` 之后同一会话出现 `exit_plan_mode` 且输出含「审批通过」的次数，应为 0；
  - D3：同一计划文件的 `recount_v2` 与 v1 记录值的差距；
  - D4：`PlanReattach.truncated` 的比例；
  - D5：同一分钟同主题的路径冲突数。
