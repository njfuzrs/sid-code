# 隔离 worktree 子代理一律按自己的 ALS 工作目录取值，并让「它在哪个目录、碰了哪个目录」进轨迹

## 决定了什么

根因是同一个：`withAgentCwd` 只改 ALS、不 chdir，子代理里所有直接读 `process.cwd()` 的地方拿到的都是主仓根。按 §3 四层模型逐层收口：

**② 进程层（逻辑）**
- `sub-agent.ts`：四处 `enhanceSubAgentPrompt(..., process.cwd())`、spawn 的 `workdir`/`cwd`、teammate 注册 cwd 全改 `getCwd()`。系统提示词的「当前工作目录」从此是 worktree，D13 隔离提示也真正出现了，并且点名 worktree 根和主仓根。
- 子代理 JIT：项目根取 `getAgentRoot() ?? process.cwd()`，并在调用时同步取值，不依赖队列回调里 ALS 的传播。`jit-telemetry` 的 `rel()` 先按 projectRoot `resolve` 再求相对路径，否则相对入参会被按 process.cwd() 补全，判成项目外。
- `bash.resolveCwd`：在子代理上下文里，cwd 失效时回退到子代理自己的 root；root 也不存在就报错，命令不执行。不再回退到 `getOriginalCwd()`，也就是主仓。
- `checker`：sed 目标解析和 LLM 分类器共用 `resolveBashCwdForCheck`，口径是 input.cwd 优先、再取 getCwd()。分类器原先拿的是 `process.cwd()`。
- 隔离 worktree 的路径判定收成一处：`cwd-context.splitIsolatedWorktreePath` / `getIsolatedWorktree`。W12、D13、digest 都用它。
- 自定义子代理（`executeCustom`）新增 `cwd` 字段。有它时包 `withAgentCwd`，并强制走进程内执行。

**③ 运行时层**
- `advisories.checkDependencyConsistency` 改为接收实际建成的 symlink 目录清单。对每个 `**/node_modules`，从所在包目录逐级向上比对 lockfile。原先只认顶层的 `"node_modules"`，monorepo 子包配置下整条告警不生效。

**可观测 / 数据层**
- `SubagentStart` 新增 `isolation`、`agent_cwd`。`agent_cwd` 列进 `LOCAL_ONLY_EVENT_DATA_FIELDS`，上传前剥离。
- `jit_context` 新增 `isolated_worktree`。
- `sidechain_start` 落盘 `systemPrompt`、`cwd`。sidechain 只在本地，不进上传通道。之前子代理的系统提示词在任何轨迹里都看不到。
- digest 子代理段新增 `isolation: {spans, absPathCalls, mainRepoPathCalls}`。这就是修复效果的主口径：隔离子代理带绝对路径的工具调用里，有多少落在主仓、却不在自己的 worktree 内。

## 放弃了什么（以及为什么不选）

- **在 `withAgentCwd` 里顺手 `process.chdir`**：chdir 是进程级全局态，并发子代理会互相串台。ALS 方案存在的理由就是为了不 chdir（`swarm/team.ts` 以前只能串行就是这个原因）。
- **只修提示词，不动 JIT 和 bash**：提示词修好后，模型大概率改用相对路径，但 JIT 加载错规则文件、bash 在 cwd 被删后落进主仓，这两件事和模型怎么写路径无关，单修提示词不会消失。
- **bash 失效时回退到 worktree 根之后还是找不到，就回退到主仓**：这正是要消除的静默越界。宁可报错。
- **子代理系统提示词写进 `events.jsonl`**：events 会上传，提示词里有绝对路径，还可能有预加载的技能和记忆。sidechain 只在本地，是更合适的落点。
- **digest 口径把相对路径也计入分母**：相对路径按子代理 cwd 解析，不可能越界。计进去只会稀释信号，修复前后的比值都会被压低。

## 拿什么证明它生效了

- 修复前基线（本机轨迹，2026-10-16~22，4 个会话、11 个 `sub_agent(isolation:"worktree")`）：529 次带路径工具调用里 501 次打在主仓绝对路径（约 95%），9/11 第 1 轮就用了主仓路径，D13 提示零次出现。取数方法：`raw.jsonl` 的派发入参 ↔ `sessions/<proj>/` 的 sidechain，用 `parentToolUseId` 关联。
- 新测试 `packages/core/tests/agent/isolated-subagent-cwd.test.ts`（13 条）以及 digest、advisories 的新增用例。每条修复都做了变异自证，把修复改回旧行为后对应用例变红：提示词 cwd、JIT 根、bash 兜底（2 条）、SubagentStart 字段、上传剥离、自定义路径 cwd、sidechain systemPrompt、end 无 start 守卫、digest 越界判据、monorepo lockfile。
- 修复后的端到端验证要在真实会话里看：`bun scripts/trace-digest.ts <id>` 的「隔离子代理 N 个：绝对路径调用越界到主仓 x/y」应当接近 0。样本少，需要积累几轮会话。旧会话没有 `agent_cwd`，不出这个口径，所以修复前后不可直接比曲线，只能对比上面的手工基线。
