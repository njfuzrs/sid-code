# bash 前台超时提示：识别 watch/常驻命令，并回读重定向文件尾部

## 决定了什么

会话 20261019-163503-c0e3e484 里，模型跑 `pnpm -r test:unit > /tmp/all-unit.txt 2>&1`。`test:unit` 是裸 `vitest`（0.34.6 默认 `watch: !isCI`），测试跑完就进了 watch，进程不会退出，600 秒后超时。根因在模型：前 6 次它都用的 `vitest run`，第 7 次换了脚本，换之前没核对脚本内容。harness 的问题是超时提示放大了这个错误：
- 提示只给一条出路「请用 run_in_background=true 重试」。对不会退出的命令这条建议不对，模型照做后后台任务同样挂住，最后只能 task_stop 杀掉。
- 输出全被重定向进了文件，提示里只能显示「(命令无输出)」，真正的线索 `Waiting for file changes` 在文件里，模型看不到。

改动（只改超时这一条分支，正常退出、失败、取消的路径都没动）：
- 新增 `packages/core/src/tool/bash/timeout-diagnostics.ts`：
  - 管道输出为空时，用现有的 `extractRedirectTargets` 找出写入类重定向目标，回读文件尾部。只读不写，每个文件最多读 2KB，最多读 2 个文件。只认绝对路径和 `~/`，跳过 `/dev`、`/proc`。
  - 在可见输出和回读的尾部里识别 watch、dev server、交互等待的固定原文。命中就明确告诉模型「转后台无效，改成一次性运行」；没命中就先提醒它检查命令会不会自己退出，原来的 run_in_background 建议保留。
- `bash.ts` 的超时分支接上这个模块，外面包一层 try/catch，诊断出错就退回旧文案。

## 放弃了什么（以及为什么不选）

- **给 bash 子进程默认注入 `CI=1`**：这次确实能直接修好，但它会悄悄改变用户命令的语义。vitest 会变成 `allowOnly=false`，有些工具会关掉交互或颜色，CI 感知的脚本会走发布或严格分支。这是拿「更准」去换「更快」。而且它对不认 `CI` 的常驻进程（dev server、`tsc -w`）没用。
- **按命令名静态拦截（看到 `vitest` 不带 `run` 就拒绝）**：命令只是 `pnpm test:unit` 时，静态分析看不到脚本里写的是什么，要么漏判，要么得去解析 package.json，规则会越补越多。从输出特征判断更可靠，也和具体工具无关。
- **超时时回读相对路径的重定向目标**：命令里常有 `cd x && ... > rel.txt`，按 spawn 时的 cwd 去解析可能读到别的文件，宁可不读。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/tool/bash-timeout-diagnostics.test.ts ./packages/core/tests/tool/bash-stability.test.ts`：40 pass / 0 fail。原有的「超时提示引导使用 run_in_background」断言仍然通过。
- 端到端用例模拟了这次的形态：`{ echo 'Waiting for file changes...'; sleep 30; } > log 2>&1`，timeout 1s。超时结果里带出了文件尾部，并判定为「不会自己退出」。
- 变异自证 ①：把 `bash.ts` 里的 `outputEmpty` 改成恒 `false`，端到端用例变红，报的是 `Expected to contain: "Waiting for file changes"`。
- 变异自证 ②：把 watch 特征正则改坏，同一条用例变红。两处都已恢复。
- 未验证：这条新提示能不能让真实模型第一次就改用 `vitest run`，需要后续轨迹来观察。
