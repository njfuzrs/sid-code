# 两处「绿的但没跑」改成会红：curated 非交互放行、Agent Note 门禁路径未解码

## 决定了什么

修 `20260927-工程化与交付-顺着sc-x3核出的缺陷.md` 的 X3-08 + X3-09（同一关注点：
两道门禁在无人值守调用下静默失效），合成一个 PR。

1. **X3-08：缺 `changelog/curated/v<ver>.json` 时，非交互调用不再降级为 warn 放行**
   （`scripts/release.sh`）。判定顺序改为 **显式 flag > tty 确认 > 失败**：
   - 新增 `--allow-no-curated`：放行必须是人写在命令行上的声明，日志打印
     「已显式放弃 v<ver> 的用户文案」；
   - 有 tty 时保留原交互确认（`[ -t 0 ] && [ -e /dev/tty ]`）；
   - 其余（agent / CI / `</dev/null`）→ `fail`，提示两条出路
     （补文案后 `--no-bump` 重跑 / 显式加 flag）。
   `scripts/RELEASE.md` 两处同步（`:67-68` 的发布步骤注释、`:221` 的 curated 章节）。
2. **X3-09：`verify-agent-note` 的 cwd 与 git 失败不再静默**
   （`scripts/verify-agent-note.ts`）：
   - `root` 从 `new URL("..", import.meta.url).pathname` 改为
     `fileURLToPath(...)` —— 前者是 percent-encoded，仓库路径含空格/非 ASCII 时
     cwd 指向不存在的目录；
   - `trackedNotes()` 在 `r.error` 或 `r.status !== 0` 时抛错，顶层 `catch` 后 exit 1
     （写法对齐 `scripts/change-scope.ts` 的 `git()`），不再 `?? ""` 兜底成空数组。
   - 同形写法 `scripts/fetch-ripgrep.ts:41` 一并改掉，并加静态扫描守住复发。

## 放弃了什么（以及为什么不选）

- **X3-08 不选「`/dev/tty` 存在就从 `/dev/tty` 读」。** agent / 自动化进程常常有
  `/dev/tty` 设备节点但**没人应答**，`read </dev/tty` 会把「假绿」换成「挂死」——
  对无人值守的发布链更糟。这是缺陷文档明确写下的否决项，本次沿用。
- **X3-08 不选「缺 curated 一律硬失败」。** 缺文案本身不该拦发布（官网那一版显示
  「本版没有用户可见的变更」——不好，但不该让紧急修复先等一次 LLM 起草）。
  要修的只是「放行由调用环境决定」这件事，所以给的是显式 flag 而不是删掉放行路径。
- **X3-08 不选「只改文案不改结构」。** 保持 warn 但把话说重（"将被视为放弃"）
  仍把决定权留给环境：agent 调起时人在看别的日志，warning 与 error 的可见性不同。
- **X3-09 不选「在 `pathname` 后面手写 `decodeURIComponent`」。** 那只解码 URL 转义，
  对 `+`、Windows 盘符、UNC 路径等边界仍不完整；`fileURLToPath` 是 Node 提供的
  唯一正确换算，且两处都只是一行替换。
- **X3-09 不选「把 `trackedNotes` 改成返回 `{ok, files}`」。** 那是 `change-scope.ts`
  为了「只读命令失败不致命」做的设计；这里失败就是门禁失效，没有可继续的语义，
  抛错更直接。
- **不顺手修「`git ls-files` 对非 ASCII 文件名加引号转义」。** 实测确认存在
  （中文 Note 文件名会被输出成 `"…\347\244\272…"`，`endsWith(".md")` 判不中），
  但仓库现存 672 份 Note 全是 ASCII 文件名，且它与 X3-09 的「路径」问题不同源
  （一个是 cwd、一个是输出转义）。单独记，不在本 PR 里扩大范围。
