# write 截断检测的末行引号判据改为逐字符状态机：注释和撇号不再算未闭合

## 决定了什么

台账 T3（Harness 厚薄归位专项，#672）。`tool/truncation-detector.ts` 的「末行以未闭合字符串结尾」判据，从「末行 `"` `'` `` ` `` **三种引号总数**为奇数」改成 `findUnclosedQuote`：按引号类型逐字符走状态机，处理转义，并且下列情况不当作定界符：

- 行注释之后的内容：`//`；行首或空白后的 `#`；`.sql` / `.lua` / `.hs` / `.elm` 里行首或空白后的 `--`；同行闭合的 `/* … */`。
- 两侧都是字母的英文撇号（`it's`、`don't`）。Python 字符串前缀 `f'` / `rb'` 等除外，这些情况下引号是真正的定界符。
- 单看一行判断不了开还是关的形态，一律不报：三引号 `"""` / `'''`（docstring 的开头或结尾），以及行首就是反引号的行（多行模板串的收尾）。

修复前误判的末行，全部会导致合法的覆盖写入被拒，并把模型引向「分段写入」：`# it's done`、`// don't touch`、`x = 1  # it's fine`、`print("it's done")`、`-- user's table`、`"""`、YAML 的 `description: Don't do this`、单独一个收尾反引号。

## 放弃了什么（以及为什么不选）

- **01 的建议「末行是注释就跳过」**：不够。`print("it's done")` 不是注释也会误判（2 个双引号 + 1 个撇号 = 奇数），YAML 裸值也一样。问题的根子是「混在一起数引号」，不是「注释」。
- **`--` 对所有语言都当注释**：不选。shell 的 `--flag`、C 的自减都会让扫描提前停下，`git commit --message "wip` 这种真截断会被漏掉。变异 M5 守着这一条。
- **反引号一律不当定界符**（模板串天然跨行）：不选。`const s = \`abc` 这种单行内没闭合的串仍然是高置信度的截断信号；只放过「行首就是反引号」这个收尾形态。
- **改成真正的分词器 / 按语言解析**：不选。检测器的定位是轻量启发式（宁可漏报不误杀），括号平衡那一路仍是主信号。
