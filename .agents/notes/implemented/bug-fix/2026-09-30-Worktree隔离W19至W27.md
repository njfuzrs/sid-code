# Worktree 隔离：权限加载、并行出口、GC 年龄与创建判据补齐（W19–W27）

## 决定了什么

来源：`docs-research/sid-code/bugfixes/todo/20260926-Worktree隔离-顺着sc-19核出的缺陷.md`。W1–W18 已在 #123 及之前合入，本轮做 W19–W27。

- **W19** `scripts/pr-batch.sh` 的 prepare 和 reperm：同一份展开后的模板用 `tee` 写到两处，`.claude/settings.local.json` 给 claude 读，`.sid-code/settings.local.json` 给 sid-code 读。模板的 `_comment` 同步更新。
- **W22** 权限规则跟随工作区：
  - `RuleLoader` 构造时没给目录的实例，每次 `loadAll` 重新取 `process.cwd()`。cli.ts 先建 checker、后 chdir 进 worktree，启动期的 `initRules` 因此读到 worktree 的 `.sid-code/`。
  - 新增 `reloadWorkspaceSources(dir)`：只换 project / local 两个来源，会话规则、cliArg、policy 都保留。
  - `PermissionChecker.reloadWorkspaceRules` / `deriveForWorkspace`。
  - `worktree/canonical.ts` 增加 `onWorkspaceChange` / `notifyWorkspaceChange`。`enterWorktreeCwd`、`exitWorktreeCwd`，以及 `exit_worktree remove` 那条裸 `switchCwd` 路径都会发通知。App 登记回调，先重载主 checker，再重新下发子代理 checker（下发的是快照，不重新 wire 就还是旧规则）。
  - `SubAgentTool` 的隔离子代理（前台和后台）改用 `deriveForWorkspace(worktree)` 派生的 checker。
- **W20** `swarm/team.ts`：成员 worktree 的 `setupWarnings` 落 `log.warn`，同时挂到 `TeammateResult.setupWarnings`，并前置到成员输出里，leader 能看到。
- **W21** `workflow/sub-agent-runner.ts`：`isolation:"worktree"` 下，非 git 仓库或创建失败时直接抛错，不再带着 `cwd=undefined` 继续跑、写进主仓。与 `sub_agent` 工具的语义对齐。
- **W23** `cleanup.ts` 新增 `lastActivityMs`：年龄取几路信号里最新的一个，包括目录 mtime、worktree 自己 gitdir 下的 `HEAD` / `index` / `logs/HEAD`，以及 `git status` 报出的每个改动路径的 mtime（symlink 不算，与 `countRealChanges` 口径一致）。
- **W24** `include-copy.ts`：按 gitignore 规则重写匹配。`!` 取反、尾 `/` 只匹配目录、含 `/` 即锚定、否则在任意层级按名字匹配，glob 用已有依赖 `minimatch`，最后命中的规则胜出。被 `--directory` 折叠的目录只在两种情况下展开逐文件判定：有否定规则可能伸进去，或者有锚定 glob 指向它内部。
- **W25** `tmux.ts`：session 名超过 50 字符时，保留可读前缀，拼上全名的 8 位 sha256。不超长的名字不变，存量 session 不受影响。复用前还会核对 `#{session_path}`，对不上就不复用，返回 null。
- **W26** `manager.create`：`originalHeadCommit` 取 `resolveBaseTreeish` 结果对应的 commit，也就是 worktree 实际切出的起点。解析失败才退回主仓 HEAD。
- **W27** `manager.remove`：hook 建的 worktree 如果没配 `WorktreeRemove`，直接抛错，不再报假成功。

## 放弃了什么（以及为什么不选）

- **W19 让 RuleLoader 也读 `.claude/settings.local.json`**：那是另一个工具的配置目录，格式和信任边界都不归 sid-code 管。W4 的守卫刚把 `.claude/` 当敏感目录处理，反过来又把它当规则源，两处语义会打架。改写入侧成本最低，也不扩大信任面。
- **W22 在 checker 里每次决策都按 `getCwd()` 现读规则文件**：I/O 会进入每一次权限判定的热路径，而且主会话和并发子代理会互相影响。事件驱动的重载只在切换时付一次成本。
- **W22 worktree 模块直接 import checker 去重载**：方向反了，worktree → permission 会成环。所以用回调登记，由持有 checker 的 App 接线。
- **W21 降级时在返回值里打标记，而不是抛错**：调用方（workflow 脚本）没有检查标记的习惯，标记等于没有。抛错会让 runtime 的 parallel / pipeline 按既有语义落 null，失败因此可见。
- **W23 用 worktree 内所有文件的最大 mtime**：大仓里要遍历整棵树（含 symlink 进来的 node_modules），GC 是启动路径，承受不起。status 报出的改动集加上 gitdir 三件套已经覆盖「编辑」「add」「commit」「checkout」四类活动。
- **W24 引入 `ignore` 包**：项目里已有 `minimatch`，再加一个依赖不值。gitignore 需要的四条规则在 minimatch 之上实现不到 60 行。
- **W25 撞名时换个后缀新建**：名字不稳定，同一个 worktree 两次 `tmux: true` 会落到两个 session。哈希是全名的函数，稳定且不撞。
- **W27 hook worktree 没配 remove hook 时用 rmSync 兜底删**：sid-code 不知道这个目录是怎么来的（可能是别的 VCS 的工作副本），盲删的风险远大于留一个目录。

## 拿什么证明它生效了

- `packages/core/tests/worktree/w19-w27-defects.test.ts` 18 pass，跑在真实临时 git 仓库上（W26 用本地 bare 仓充当 origin）。
- 变异自证：把 W23（年龄改回 `statSync(dir).mtimeMs`）、W25（改回裸 `slice`）、W26（基线改回主仓 HEAD）各自回退，对应用例变红（4 fail），恢复后全绿。
- 旧用例的调整：`symlink-pollution` D 组、`w6-w10` W8 组、`w11-w18` 的 GC 用例原来只拨目录 mtime 来模拟「老 worktree」，这正是 W23 修掉的盲区。现在连 gitdir 的 HEAD / index / logs 一起拨老。
- `bun run affected-tests:run` 5391 pass / 0 fail；`make build` rc=0，没有 `will always be undefined`；lint、lint:boundary、format:check、docs:gen-reference --check 全绿。全量 `bun test` 交给 CI。
- 没有验证的：没在真实 TUI 里 `/enter_worktree` 之后数弹窗次数（W22 的 App 接线只有编译和单测覆盖到 checker 这一层），没有起真实 tmux session 验证 `session_path` 核对，也没有起真实 swarm 验证 lockfile 不一致告警（W20 用的是源码断言）。
