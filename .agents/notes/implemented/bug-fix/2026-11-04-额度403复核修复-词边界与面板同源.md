# 额度 403 修复的复核收尾：词边界、面板同源与三处测试缺口

## 决定了什么

来源：PR #573（`fix(llm): 网关额度 403 按上游 code 归为额度耗尽并跨循环共享`）合入后的
事后 review。改动分两类：两处行为收紧、三处测试缺口补全；另把两处「刻意不这么做」
从注释里的口头承诺变成有断言钉住的事实。

**① `QUOTA_TAG_MARKERS` 从裸子串改词边界**（`error-normalize.ts::looksLikeQuotaTag`）。
初版用 `t.includes(m)`，`balance` 因此命中 `load_balancer_unavailable`。初版 Agent Note
只记账「最坏后果是按 request_suspect 的 2 次预算处理」——**漏了第二层**：命中后
`recordGiveUp` 会 `markQuotaExhausted`，同账户所有并行循环 60s 内一发不发。一次 LB
故障被放大成「账户余额空了」的全局假信号，量级不是「2 次重试」。
改为复用 `error-lexicon.ts::matchesWord`（`_` 当分隔符），并补 `credits` 条目覆盖
`insufficient_credits`（词边界会把 `credit` 后的 `s` 当成同一个词）。
`matchesWord` 同时从私有改为导出 —— 边界规则只该有一份。

**② `codeFromStructured` 增加可选 `message` 参数**（只在 401/403 参与额度窄口）。
初版传 `message: ""`，导致「网关只在 message 写额度、不给 code」这条路径上面板仍显示
`auth_failed`，与漏斗判的 `quota_exhausted` 不同源 —— 正是 PR #573 声称已消除的那条
裂缝，只是变窄了。两个调用点（`query/engine.ts`、`cli/app.ts`）一并传入。
口子精确限制：非 401/403 一律空串；401/403 有 status 时会提前从 `byStatus` 返回，
**不会**走到分类器末尾的 `matchErrorLexicon`，所以它不会变成第二套文本分类器。

**③ 补三处测试缺口**：
- `retry_same` 清除标记（方案 §3.5 原文验收项；代码在 `fallback.ts:1804`，此前零覆盖）
- TTL 过期与续期（`DEFAULT_QUOTA_EXHAUSTED_MS` 是解死锁的唯一自愈出口，此前零覆盖）
- `usage_limit_reached` 不写共享标记（把刻意行为钉住，见下）

**④ 补两处论证到注释**：`usage_limit_reached` 为什么不共享（模型级配额的归因风险）、
`recordGiveUp` 的 `accountExhausted` 为什么只认 `quota_exhausted`。

## 放弃了什么（以及为什么不选）

- **让 `codeFromStructured` 全局接受 message**：那会让它变成第二套文本分类器，与
  「结构化优先、文本兜底只有 `inferErrorCode`」的分层冲突。只在 401/403 开、且只跑
  额度词表，才不破坏这条分层。
- **让 `usage_limit_reached` 也写账户级共享标记**：`hit your opus limit` 是模型级配额，
  记成 (端点, 凭据) 会把「opus 用满」放大成「整个账户没钱」，连带拦住还有余量的模型。
  这与 PR #573 第 8 条（额度不写模型嫌疑）要避免的归因错误同族，只是方向相反。
  代价是这类失败仍按族判 2 次、仍写模型嫌疑 —— 那是更接近事实的结论。
- **保留裸子串、只在 Agent Note 里记账**：初版的记账结论本身就是错的（低估了连带后果），
  靠文档约束不住。词边界有现成实现，成本是一行 import。
- **用 fake timer 测 TTL**：`markQuotaExhausted` 的 `ttlMs` 参数就是为注入留的入口，
  直接传 `0` / `1_000` 比拨时钟更简单，也顺带测到了 `getQuotaExhausted` 的读时清理。
- **改降级 provider 的共享路径**：`tryFallback` 是另一套控制流，改动风险大于收益；
  方案 §3.3 ⑥ 的字面范围是「漏斗判定后共享」的主路径。已在原 Note 记为已知范围。

## 拿什么证明它生效了

### 单测：30 → 38 条，全绿

```
bun test ./packages/core/tests/llm/quota-403-classification.test.ts
→ 38 pass / 0 fail（88 expect）
```

新增 8 条：
- 第 2 组：「`load_balancer_unavailable` 不被当成额度 code（词边界）」
  「复数形态 `insufficient_credits` 仍判额度」
- 第 4 组：「403 + 只在 message 写额度 → 面板也判 quota_exhausted」
  「message 参数不会放宽到 401/403 之外，也不会误伤真鉴权」
- 第 5 组：「用户选 retry_same 清除标记并真实重发」「TTL 到期后标记自动失效」
  「续期：重复 mark 把到期时刻往后推」「usage_limit_reached 不写账户级共享标记」

### 变异自证（五项，都是先改坏再恢复）

| 变异 | 结果 |
| --- | --- |
| `codeFromStructured` 的 `quotaProbe` 改回 `""` | 第 4 组两条**变红**（2 fail） |
| `looksLikeQuotaTag` 改回 `t.includes(m)` | 第 2 组 `load_balancer_unavailable` **变红**（1 fail） |
| 删掉 `retry_same` 分支的 `clearQuotaExhausted` | 「retry_same 清除标记」**变红**（1 fail） |
| `accountExhausted` 加上 `usage_limit_reached` | 「不写共享标记」**变红**（1 fail） |
| `getQuotaExhausted` 的到期判据改成永不过期 | 「TTL 到期失效」**变红**（1 fail） |

每次变异后都恢复，并确认 `grep -rn "MUTATION" packages/core/src` 无残留、
测试回到 38 pass / 0 fail。

### 复核后的已知范围（不是缺陷）

- 共享只覆盖主 provider 入口；降级 provider 的额度耗尽既不写也不查标记。
- `quota_exhausted_shared` 只有埋点，digest 尚未产出「省了多少发请求」的统计（属 PR5）。
