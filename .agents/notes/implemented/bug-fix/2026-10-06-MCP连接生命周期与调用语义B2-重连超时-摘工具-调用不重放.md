# MCP 连接生命周期与工具调用语义（B2）：重连有总超时、断线摘工具、非幂等调用不重放

## 决定了什么

- **D3**（`config.ts`）：`getMcpServerSignature` 先用 `expandConfigEnvVars` 展开，再拿真值比较，所以 `${VAR}` 和字面值两种写法只会连一次。URL 签名带上 transport（`http:` / `sse:` …），同一 URL 用不同协议不再被当成重复误删（这是文档里提到的「另一个独立的签名缺陷」）。
- **D4**（`env-expansion.ts`）：`expandConfigEnvVars` 改成返回副本的纯函数，覆盖 command / args / url / **headers / env**。建连（`createTransport`）、策略过闸（`policy.ts`）、签名去重三处共用这一个入口。serverConfigs 里继续存模板原文，重连时按最新环境重新展开。未设置的变量会 warn 一次。
- **D15**（`transport.ts` / `client.ts`）：新增 `McpTransportError`，传输层只在**确定没送达**时打 `notDelivered`：传输已关闭、连接没建起来、HTTP 429。`callTool` 只在 `notDelivered` 或调用方声明 `idempotent` 时重试，超时和断流一律不重发。list / read / initialize 保留原来的重试。「传输已关闭」标成 `terminal`，任何请求都不再白等退避。
- **D16**（`manager.ts` / `permission/*`）：adapter 暴露 `isDestructive / isIdempotent / isOpenWorld` 三个方法。`destructiveHint` 接到 checker 的 Step 13.5，产出 `decisionReason: destructiveTool`，并归入 `isSafetyConfirmation`：yesMode、auto 分类器、hook allow 都不能放行，但用户的显式 allow 规则、always-allow、预授权仍然生效。`idempotentHint` 接 D15。`openWorldHint` 透传到 decisionReason 和 explainer 文案。
- **D14**（`manager.ts`）：`MCPToolAdapter.execute` 外层用 `getMcpToolTimeout()` 做总超时，**包住全部重试**，超时后 abort 内层请求。官网 `SID_CODE_MCP_TOOL_TIMEOUT` 这一项保留，现在真的生效了。
- **D24**：抽出 `connectWithTimeout`（Promise.race + abort），connectAll / addServer / 断线重连 / half-open 探测四条路径共用，原来两份内联拷贝删掉。顺手抽了 `dropClient`。
- **D25**：`handleDisconnect` 清理 client 之后立刻调 `onToolsRefresh(name, [])`，stdio 直接 FAILED 和远程 RECONNECTING 两条路径都覆盖；重连成功后再注册。
- **D27**：重连退避改走 `computeBackoffMs`，上限 30s，与 client 的请求重试同源；client 重试和重连都至少等满对端的 `Retry-After`（429 / 503，秒数或 HTTP-date，超过 1h 不采信）。`pMap` 每项单独 catch，经 `onError` 换成兜底值，一项抛错不再丢掉同批其他结果（`connectOne` 原本已经 catch 过，这次再在 pMap 层兜住）。
- **D29**：删掉 `loop.ts` 的 `MAX_MCP_INSTRUCTION_BLOCK_LENGTH = 4000`，`manager.ts` 的 `MAX_INSTRUCTIONS_LENGTH` 成为唯一事实源（已导出）。
- **D30**（`cli.ts`）：`onPromptsChanged` 挪到 `connectAll` 之前赋值。unifiedRegistry 还没建好时到达的通知先记成 pending，建好后补发一次。

## 放弃了什么（以及为什么不选）

- **D15 全局关掉 tools/call 重试**：会把「连接没建起来」这种确定安全的重试也丢掉，远程 server 冷启动时的成功率会下降。
- **D16 拿 `readOnlyHint` / `destructiveHint: false` 放行**：hint 是 Server 自己声明的，只能用来收紧（R7）。没声明 destructive 的工具照旧走默认 ask。
- **D16 让 destructive 工具连 always-allow / allow 规则都不能放行**：那等于否决用户自己的明确决定，而且 MCP 工具没法像 `.git/hooks` 那样给出「绝对危险」的本地判据。
- **D25 远程重连窗口内不摘工具（保 prompt cache）**：模型会去调一个必然失败的工具，失败还以业务错误形式返回，导致原地空转。按 §7.9 正确性优先。
- **D14 从官网删掉这个 env**：缺陷文档给了两个选项，接线成本低，而且分层超时是博客 §9.2 的论点，所以选了接线。
- **D30 在 App 侧重新拉一次命令列表**：只是绕开问题，「先连后挂回调」的窗口还在，别的订阅者照样会漏。
