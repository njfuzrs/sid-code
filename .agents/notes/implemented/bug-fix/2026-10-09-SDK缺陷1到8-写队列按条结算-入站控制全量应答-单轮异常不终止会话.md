# SDK 缺陷 1–8：写队列按条结算、入站控制全量应答、单轮异常不终止会话、删死参数、补 stdin 空闲上限

## 决定了什么

来源：`docs-research/sid-code/bugfixes/todo/20260927-SDK与插件-顺着sc-17核出的缺陷.md` 缺陷 1–8。

- **缺陷 1**（`sdk/structured-io.ts`）：`write()` 改为每条消息带自己的 resolve/reject，drain 循环逐条结算、
  单条写失败只 reject 它自己并继续写后面的。旧实现「入队即 resolve」→ 并发下错误错位一格、失败谎报成功、残留消息静默丢失。
- **缺陷 2**：`sendRequest` 的 abort 监听器在 resolve / reject / 写失败三条路上都解绑。
- **缺陷 3/4**（`sdk/headless-runner.ts`）：入站 `control_request` 每条必回 `control_response`。
  `initialize` 返回 `supported_control_subtypes`；`set_model` 走 `applyPrimaryModelSwitch`（同 `/model`，先校验 availableModels）；
  `get_context_usage` 读 `ctxMgr.getContextUsageForDisplay`；`mcp_message` 等仍回 error「未实现」并列出支持清单。
  `initialize` 里的 system_prompt / json_schema / max_turns / max_budget_usd **携带即回 error 并指向对应 CLI 参数**。
  driver 新增可选 `getModel()`，set_model 后 system/init 报新模型。
- **缺陷 5**：删除 `trackResolvedToolUseId` / `isResolvedToolUseId`（只写不读）。重复投递的响应已由「结算即删 pending，同 id 第二条按孤儿丢弃」覆盖。
- **缺陷 6**（`sdk/query-engine.ts`）：删除 `SDKQueryEngineConfig` 的 maxTurns / maxBudgetUsd / systemPrompt / jsonSchema，app.ts 不再传。
- **缺陷 7**：`runHeadlessStreaming` 的 `idleTimeoutMs` 真正实现（无轮在跑 + 队列空 + 无入站消息达上限即正常收尾），
  `runHeadless` 透传；CLI 侧旋钮 `SID_CODE_SDK_IDLE_TIMEOUT_MS`，**缺省 0 = 关闭**。死字段 maxTurns / maxBudgetUsd 一并删除。
- **缺陷 8**：每条命令独立 try/catch，抛异常且未出过 result 的补 `error_during_execution`（`SDKQueryEngine.errorResult`），然后继续处理下一条。

## 放弃了什么（以及为什么不选）

- **在 SDKQueryEngine 里实现 maxTurns / 预算上限**：内核已经硬停并映射成 error_max_turns / error_max_budget_usd。
  再加一层同谓词上限只是多一个杀手（memory: 多层同值只换杀手），且两层数字可能漂移。
- **`initialize` 运行时设置 system_prompt / json_schema**：两者在进程启动时装进内核（buildSystemPrompt / StructuredOutputTool 注册）。
  半生效比不生效更糟，所以明确拒绝。
- **idle 超时默认开**：与 `maxSessionDurationMs` 默认 0 同一「保活优先」取向，宿主两轮之间空闲多久是它的自由。
  默认开会把正常的长空闲宿主（IDE 插件）杀掉。
- **`set_model` 持久化到 settings.json**：宿主控制的是这一次会话，写盘会影响用户后续交互会话。
- **缺陷 1 用 Promise 链**（方案 b）：等价，但 per-message deferred 更直接地表达「谁的错归谁」，选了 (a)。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/sdk/`：150 pass / 0 fail。新增用例覆盖文档里的三条实测探针：
  write 第 2 次抛错 → 只有 B rejected、C 仍写出；共享 signal 连发 20 个请求 → 监听器数归零；
  3 条 user 第 2 轮抛错 → 3 条 result `[success, error_during_execution, success]`（旧实现只有 1 条）。
- 变异自证：把 `turnErrorResult` 改回 `throw err` → 缺陷 8 用例红；把 `detach` 置空 → 缺陷 2 两条用例红。
- 真实二进制 `sid-code -p --verbose --input-format stream-json --output-format stream-json` 投 4 条控制请求：
  initialize / get_context_usage 回 success（used_tokens=23660 / max 1000000），set_model 非法名 / mcp_message 回带原因的 error。
- `bun run affected-tests:run` 2077 pass / 0 fail；`make build` 通过，`will always be undefined` 0 条；lint / format:check / lint:boundary 绿。
