# 子代理模型解析不再隐式降档，连接一律跟着最终模型走，流处理 content 恒密集

## 决定了什么

事故会话 `20261011-105810-19708b1a`：主模型 `origin-deepseek-v4-1-flash` 正常，10 个子代理全部失败。这次失败叠了三个独立缺陷，三个都修了：

1. **隐式降档**（`llm/registry.ts` `resolveModelForTier`）。内置 explore/plan/summarize 标了 `modelTier: "cheap"`，用户没配 `subAgentModels` 时，会在 `availableModels` 里按单价挑最便宜的。结果选中 `claude-haiku-5-5`（0.10 USD/M），而它在该网关分组下没有渠道，返回 503，5 个子代理零轮全部失败，用户从没选过它。现在档位**只认**显式环境变量 `SID_CHEAP_MODEL` / `SID_STRONG_MODEL`，没设就跟主模型。
2. **模型/连接错配**（`agent/sub-agent.ts` 的四条执行路径）。重派时主模型显式传了 `task.model`，但 provider 仍按**类型**查到的是 explore 默认模型（haiku，anthropic 族）的连接。于是 `deepseek-v4-pro` / `gpt-5.4`（openai 族）被用 Anthropic 协议发到了错的端点。四处同型：
   - `executeInner`：`getProviderForSubAgent(type)` 改为 `getProviderForModelName(activeModel)`，baseURL 同步改按模型取。
   - `executeSpawned`：原来**完全忽略** `task.model`，现在 `task.model` 存在时走 `getSpawnConfigForModel`。
   - `executeCustomInner` / `executeSpawnedCustom`：`modelOverride` 原来配的是 "task" 类型模型的连接（spawn 路径只重算了真名），现在整套连接按 override 模型解析。
   - 新增 `ProviderRegistry.getSpawnConfigForModel(model)`，`getSpawnConfigForSubAgent(type)` 改为委托给它，规则只有一份。
   - `/compact` 的 `runPartial` 同型：用 summarize 模型但发给主 provider，已改。
3. **子代理流处理留空洞**（`agent/stream-processor.ts`）。原来按 SSE index 直接写 `content[index]`，且只认 text/tool_use，thinking 块被跳过。always-on 思考模型（`claude-sonnet-5-gateway`）的「thinking(0) + tool_use(1)」响应会产出 `[<hole>, tool_use]`，agentic-loop 遍历时崩在 `undefined is not an object (evaluating 'block.type')`。现在与主循环 `query/stream-processor` 同构：index→position 映射加 push，thinking 在 stop 时转成 thinking 块并带上 signature，redacted_thinking 原样保留，未知类型不占位，`stream_restart` 时一并清空映射。

另修可观测性：`anthropic.ts` 的 `AUDIT:API`、`headers_received`、`HttpConnected` 原来打的是构造时的 `_model`。provider 实例按 (provider, baseURL) 缓存，这个值恒为主模型，于是子代理的 503 被记成 `model=主模型`，直接误导排查。现在一律记本次请求的 `params.model`。

文档同步：`website/extend/subagents.md` 去掉了「零配置也已经在省钱了」一节，改写为「没配就跟主模型」。

## 放弃了什么（以及为什么不选）

- **保留价格派生，加一层可用性探测或失败后回退主模型**：这只是把隐式选择换个方式藏起来。价格表回答不了「此刻能不能用」，探测要多一次请求，并且依赖网关的错误语义（本次网关对不可用模型回 503，有的回 200 加 HTML）。失败回退会把首轮延迟翻倍，而且失败仍然发生过，只是用户看不见。根本问题是**用户没选的模型不该被用**，所以直接删掉。
- **只把 haiku 从候选里排除，或给 availableModels 加 `enabled` 字段**：属于为单个模型打补丁。下一个更便宜但不可用的模型照样中招，`enabled` 也要用户先知道有这个坑。
- **只修 `executeInner` 一处错配**：spawn 路径和 custom 两条路径有同样的错配，只修一处就等于把 bug 换个执行模式继续留着（编译版二进制不走 spawn，dev 版走），这正是「同一逻辑两处并列实现」反模式。
- **流处理只加 `content.filter(Boolean)` 兜底**：那样 thinking 块（以及 signature）照样丢。Anthropic 多轮回传缺了 thinking 会退化或 400，症状只是从崩溃换成了更隐蔽的推理链断裂。
- **用户想省钱怎么办**：显式配 `subAgentModels.explore` 或 `SID_CHEAP_MODEL`，选了谁用户自己知道，坏了也知道去哪改。

## 拿什么证明它生效了

- 事故复现：用事故的 settings.json 跑 `resolvePricingUSD`，确认最便宜的是 `claude-haiku-5-5` 0.10。流处理用「thinking(0) + tool_use(1)」事件序列在旧 `processStream` 上复现出 `undefined is not an object (evaluating 'b.type')`。
- 新增 `tests/agent/stream-processor-dense-content.test.ts`（5 例）：在旧实现上 4 例 fail，新实现全部通过。
- 新增 `tests/agent/sub-agent-provider-routing.test.ts`（10 例）：只回退 sub-agent.ts（registry 保持新版）时 4 条错配路径全部 fail，新实现全部通过。
- 重写 `tests/llm/subagent-model-tier.test.ts`：其中「事故形态」用例锁死了「表里有更便宜的跨 provider 模型也绝不选中，spawn 连接仍是主模型的」。
- 五道门禁本地全绿：`bun test` 15910 pass / 0 fail（1077 文件），`make build` 自检通过，`bun run lint` / `format:check` / `lint:boundary` 通过；`docs:gen-reference` 已重生成 `website/ref/env.md`。
- 未验证：没有对真实网关重放事故会话，修复后的端到端行为由上述单测锁定，没有线上实测。
