# 发布清理止血：RELEASE_KEEP_VERSIONS 默认 0，0 = 不清理

## 决定了什么

对应 B46（发布产物归档与历史版本保留）P0。归档层（OSS）与「已归档才删」门禁接入前，
服务器版本目录是唯一原始字节，此前保留窗口 5 已永久丢掉 20 个版本。

- `scripts/release.sh`：清理块前加 `RELEASE_KEEP_VERSIONS -eq 0` 短路，打印「归档门禁未接入，跳过清理」；
  默认值 5 → 0；新增非负整数校验，非法值直接退出。
- `scripts/rollback.sh` 头注释同步口径。
- `tests/release-channel.test.ts` 新增 4 条：默认值、N=0 真跑不删、N=1 对照会删、非法值拒绝。

## 放弃了什么（以及为什么不选）

- **只改默认值**：清理用 `tail -n +$((N+1))`，N=0 即 `tail -n +1`，会删光除指针外的全部版本。守卫与默认值必须同一提交。
- **测试里手抄清理脚本**（A2 那条的做法）：证明的是副本，不是脚本。新测试从 `release.sh` 抠出真实 `if…fi` 块，用 `run_ssh` 桩本地执行。
- **非法值时当作 0 静默跳过**：拼错的配置应当暴露，选择拒绝发布。

## 拿什么证明它生效了

- `bun test ./tests/release-channel.test.ts`：30 pass / 0 fail。
- 变异自证（逐个改坏再恢复）：默认值改回 `:-5` → 「默认值是 0」红；守卫 `-eq 0` 改成 `-eq 99` → 「N=0 一个都不删」红（此时真实代码删掉了 3 个目录）；
  去掉整数校验分支 → 「非整数配置值拒绝发布」红。每次只红目标那条。
- 线上验收（待下次 `--upload`）：服务器版本目录数 = 发布前 + 1，日志出现「跳过清理」。
