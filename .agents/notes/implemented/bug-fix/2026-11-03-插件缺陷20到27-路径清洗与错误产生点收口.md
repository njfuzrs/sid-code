# 插件缺陷 20–27：路径清洗、错误产生点、加载器收成一层

## 决定了什么

对应《20260927-SDK与插件-顺着sc-17核出的缺陷》缺陷 20–27，一个 PR 收口。八条里七条在 `packages/cli/src/plugin/`，一条（缺陷 24）在 `packages/shared/src/utils/memoize.ts`。

**缺陷 20 不再需要修（已消失）**：`merge.ts` 随旧命令体系在 2026-11-01 删除，`mergePluginCommands` / `replacePluginCommands` 全仓已无生产引用。只清理了两处指向已删文件的陈旧注释（`loadPluginCommands.ts` 的「在 merge.ts 处理」、`refresh.ts` 的 `CommandRegistry.replacePluginCommands`）。

**缺陷 21（P0 安全）四个入口统一路径清洗**：`resolvePathInsidePlugin(pluginPath, declared)` 拒绝绝对路径与空串，`resolve` 后断言 `resolved === root || startsWith(root + sep)`；`path-escape` 作为新的 `PluginError` 类型。覆盖 `commands` / `skills` / `agents` / `hooks`（显式声明时）与 `mcpServers` 字符串路径五个入口——文档只点名前三个，后两个是同一根因的入口，一并修。额外加 `realpath` 复核：插件目录里放一个指向外部的符号链接（`commands -> /etc`）`resolve` 拦不住；默认目录分支（声明缺省时 `join(pluginPath, "commands")`）同样走这条复核。

**缺陷 22（P1）三种空壳错误接线**：新增 `component-errors.ts` 模块级收集器（组件是延迟加载的，失败进不了 `PluginLoadResult.errors`）。`component-load-failed` 由命令/Skill/Agent 三个 loader 的 readdir 失败、单文件读取失败、frontmatter fail-closed 跳过产生，汇入 `/plugin list` 与 `/reload-plugins` 输出；`plugin-not-found` 由 `enable/disable/uninstall` 对不存在插件产生；`generic-error` 承接组件刷新时的未预期异常。`trust-rejected` 仍未接线（见下）。

**缺陷 23/25/26（P1/P2）加载器诚实收成一层**：删除 `assemblePluginLoadResult(_fullLoad)` 的未使用形参；`loadAllPluginsCacheOnly` 改为 `loadAllPlugins` 的同一 memoize 实例别名；整段删除跨 slot 预热（25a/25b/25c 随之消失）；`mergePluginSources` 形参按真实优先级重排为 `(inline, installed, builtin, errors)`，三处矛盾注释统一为「inline > installed > builtin，先放入者占名」。

**缺陷 24（P1）memoize 失败驱逐**：`fn(...args).catch(...)` 在 reject 时 `cache.delete(undefined)` 后原样抛出；相等判断防止误删后来填入的新缓存。

**缺陷 27（P2）manifest 校验收紧**：`version` 补 semver 校验；`dependencies` 元素复用 `name` 的 slug 正则；删除从未被填充的 `ManifestValidationResult.warnings` 字段与全仓零调用者的 `parseAndValidateManifest`（同步删 `index.ts` re-export）。

## 放弃了什么（以及为什么不选）

- **缺陷 23 没有做成「真两层」**。候选两条：① cacheOnly 只读 `installed.json` 构造骨架——但组件路径、hooks、MCP、skills 全部来自 `plugin.json`，骨架会拿到空 hooks，启动期插件 hooks 直接失效；② 新增 `~/.sid-code/plugins/index-cache.json` 持久化索引实现跨进程零扫描——引入新磁盘契约与失效策略，且没有性能数据证明值得。选择让命名与实现一致：只有一层完整加载，memoize 只保证进程内单次执行，注释明写「不要再加回换汤不换药的形参」。
- **缺陷 22 的 `trust-rejected` 保留空壳**。它需要一套「本地插件首次加载需用户确认」的信任机制，涉及交互设计与 UI，属新功能；本次不伪造一个语义不对的产生点，在 Note 与缺陷文档里标注「随信任机制落地接线」。
- **缺陷 27 没有保留 `warnings` 通道**。给「一条两端都没接的警告通道」找用途只能编造场景（如 version 宽松降级为 warning），但 27a 已决定不合规 version 是 error；删除是唯一诚实的收尾。
- **缺陷 21 没有把清洗下沉到 `validateManifest`**。校验函数只拿到 manifest 内容、拿不到插件根目录，路径边界必须在 `manifest.ts` 有 `pluginPath` 的地方判。
- **没有顺手把 5 个组件 loader 的 `loadAllPluginsCacheOnly` import 改名**。行为不变，改名会扩大 diff 到本批缺陷之外的文件；别名注释已说明它不再是 cache-only。
