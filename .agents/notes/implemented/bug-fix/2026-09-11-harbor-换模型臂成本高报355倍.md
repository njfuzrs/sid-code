# Harbor 换模型臂的成本高报 355 倍：容器 settings.json 从不写 pricing

## 决定了什么

**A1 臂（sid + deepseek）换模型到 `origin-deepseek-v4-1-flash` 时，把价格显式透传进容器。**
三处改动，一条主线：

1. **宿主 `~/.sid-code/settings.json`** 给该模型补 `pricing`（厂商价目表人工核对）：
   `input:2 / output:8 / cacheRead:0.04 / cacheWrite:0`，`currency:"CNY"` + `fxToUSD:1/7.1`，
   `peakWindows`（UTC 01-04、06-10 = 北京 09:00-12:00、14:00-18:00）+ `offPeakMultiplier:0.5`。
   ⚠️ 存**人民币原价 + 显式汇率**，不存折算好的美元 —— 与 `model-registry.ts` 里
   DeepSeek 那几条同口径，理由见 `DEEPSEEK_CNY_TO_USD` 注释：折算后存会让
   「汇率漂移」与「厂商涨价」长得一模一样，无法归因。
2. **`sid_code_agent.py` 新增 `_host_pricing()`**，`_render_settings()` 把它写进
   `availableModels[0].pricing`。此前该函数**完全不写 pricing 字段**。
3. **`run-model-switch.sh` 的 openai 侧模型名改为可覆盖**（`SID_MODELSWITCH_MODEL`，
   默认值从 `deepseek-v4-pro` 改为 `origin-deepseek-v4-1-flash`），并让**闸 2 探针请求体
   复用同一个变量** —— 此前 `-m`、`--model-name`、探针 body 三处各写一遍模型名。

**这个 bug 的形态**：容器里那份 settings.json 由 `_render_settings()` 渲染，不写 pricing ⇒
容器内 `resolvePricing` 顺着优先级往下落到**网关采集缓存**，而 new-api 网关对**未定价渠道**
回的是占位值 **input=75 / output=75 USD/1M**（`origin-deepseek-v4-flash-vision` 也是同一对
75/75，这是它的指纹）。真实价 1-2 元 / 4-8 元 per 1M ⇒ **同一份 token 量算出的钱高报 355 倍**。

⛔ **没有任何一层会拦住它**：`cost_usd` 照样是个数、汇总照样出表，而
`arm_health.py:452` 的 `pricing_ratio` 偏离判据**明确只对 sonnet 定价有效**、
换模型臂刻意不判。「更省」方向的主口径就是单位任务成本 —— 这一格错了，整条臂的钱都是废数。

## 放弃了什么（以及为什么不选）

- **⛔ 不在 `sid_code_agent.py` 里硬编码价格**。宿主 settings.json 已经是 shim 取
  base_url / api_key 的事实源（`gateway.py:_load_upstream`），价格也放那里 ⇒ 只有一份、
  改一处生效。在渲染函数里再抄一份的形态是两处不一致时**静默按错的那份算**，
  而本仓已有多次「同一事实存两份然后漂移」的前科。
- **⛔ 不改 `model-registry.ts` 加一条 `origin-deepseek-v4-1-flash`**。看着更"正规"，
  但**对本次评测完全无效**：容器跑的是 pin 住的二进制 `30586ff003c9`（2026-08-30 构建），
  改 TS 源码不重新交叉编译进不了容器。而 pin 是刻意的（见 `run-model-switch.sh` 头注释：
  必控变量），为一条价格去动它等于把「换模型」这一个变量变成两个。
- **⛔ 不修网关采集链路那个 75/75**（用户明确要求先跑评测）。它是**上游自报的占位值**，
  真正的修法是在 `gateway-pricing.ts` 侧把「占位价」识别出来不入库 —— 那是独立一件事，
  且**用户手写价优先级最高**（`resolvePricing` 步骤 1/2），本次透传已经绕过它。
  ⚠️ 但这意味着**其它未定价渠道仍然踩同一个坑**，缺口留着。
- **⛔ anthropic 侧不给模型名旋钮**。A2/A3 的 sonnet 是必控变量，给它一个环境变量出口
  等于给「悄悄改掉基准」开口子。

## 拿什么证明它生效了

**① 机理与量级实测（`bun /tmp/pchk.ts`、`/tmp/pchk2.ts`）**：

```
修前 resolvePricing("origin-deepseek-v4-1-flash") → {"input":75,"output":75}
     （registry exact/fuzzy 双 MISS ⇒ 确认它是从网关缓存来的）
修后 resolvePricing(别名, availableModels, 网关端点) → CNY 2/8 + peakWindows + fx
     peak    周五 10:30 北京 → inUSD=0.28169 outUSD=1.12676
     offpeak 周五 21:40 北京 → inUSD=0.14085 outUSD=0.56338   （恰为一半 ✅）
同一份用量 1M in + 200K out：$90.00（修前）→ $0.2535（修后）= 355×
```

**② 容器侧真实产物核过**（⛔ 不是只核宿主那份）：实例化 `SidCodeAgent` 调
`_render_settings()`，`availableModels[0]` 里 `pricing` 九个字段逐个在，
`currency`/`fxToUSD`/`peakWindows`/`offPeakMultiplier` **全部原样通过**。

**③ pin 住的那个二进制真的认这些字段**（这一条最容易漏）：
`git show 30586ff003c9:packages/core/src/config/settings/types.ts` 的
`ModelPricingSchema` 带 `.passthrough()`；同 commit 的 `cost-tracker.ts` 有
`effectivePricing` 且 `calculateUSDCost` 调它。⇒ CNY 与分时段在**那个二进制里**生效，
不是只在 HEAD 生效。若没这条，2 CNY 会被当 2 USD 算（高估 7.1 倍）。

**④ `_host_pricing` 三条路径都试过**：命中返回九字段；模型不存在 → 打警告返回 None；
条目存在但没配 pricing（`deepseek-v4-pro`）→ 打警告返回 None。
⚠️ 两条失败路径**刻意只警告不抛**：宿主没配价不该让整轮评测起不来，但静默退化到
75/75 正是这段代码要消灭的东西，所以必须吵一声。

**⑤ 闸 2 探针与真跑用同一个模型名**：改前三处各写死一遍，改后 body 由 `$SHIM_MODEL_NAME`
插值；实测渲染出的 JSON 合法且 `model=origin-deepseek-v4-1-flash`。
⇒ 「上游健康」这个结论的主语现在**就是真跑的那个模型**。

**⑥ 上游真实可用**（宿主直连 3 连、经 shim 3 连，均 2-3 次 200，首次为冷启超时）：
上游 SSE 自报 `model=deepseek-v4-flash-202605`，带 `reasoning_content`。
⚠️ 顺带一个判读事实：**别名与上游真名不同**，所以「跑的是哪个模型」只能取
`availableModels[0].modelId`（= `arm_health.py:sid_model()` 的口径），⛔ 别取别名。

**⑦ 行号引用门禁**：插入 71 行让 `evals/CLAUDE.md` 的 9 条 `file:line` 出处超出
±12 容忍窗 ⇒ `tests/eval/evals-claude-md-citations.test.ts` **正确地红了 9 条**。
新行号**逐条 `sed -n` 核过落在真实代码上**（⛔ 不是按偏移量推的），改后 23 pass / 0 fail。

**⚠️ 尚未证明的部分（不冒充已验证）**：本 Note 写于 A1 臂跑到闸 2 时。
**真实 54 题跑完后的 `cost_usd` 是否落在合理区间，尚未核**。
判据：单题成本应显著低于 A2（sonnet）的 $0.683 均价；若仍出现数十美元的单题成本，
