# /login 授权链接面板随登录流程结束自动关闭，/logout 成功回执改走状态栏

## 决定了什么

- `CommandPanelSpec` 新增可选 `until?: Promise<unknown>`（`packages/core/src/command-contract/types.ts`）。
  `app.ts` 的 `showCommandPanel` 在这个 Promise 落定（成功或失败）后关掉面板，
  前提是屏上的面板还是这次打开的那一个（按对象身份比较）。期间被别的命令替换或被用户 Esc 掉，就不去动。
- `/login` 返回的授权链接带 `panel: { until: entry.done }`，`done` 是登录流程结束的 Promise。
  覆盖成功、失败、超时、`/login cancel` 四种结束方式。重复 `/login` 返回的面板绑的是同一个流程。
- 链接文案改了：原来写的是「可以继续使用」，可面板在屏时输入框被替换掉了，根本用不了。
  现在写「授权完成后本面板自动关闭；也可以先按 Esc 关掉面板继续使用」。
- `/logout` 正常路径（后端解绑成功）的回执收成一行，走状态栏，几秒后自己消失。
  原来是 4 行，按 `PANEL_MIN_LINES=3` 进了面板，登出已经完成，还要用户按 Esc 去关一个只写着「成功」的面板。
  解绑失败、后端不支持解绑、没配后端这三种异常路径仍然多行进面板：用户需要读完并照做（联系管理员）。
- TUI 里登录失败的提示把 core 文案里的「sid-code auth login」换成「/login」：用户人在 TUI 里，该给他 TUI 的入口。

## 放弃了什么（以及为什么不选）

- **在 `login.ts` 里直接调一个「关面板」回调**：要往 `CommandContext` 加一个 UI 专用能力，
  而且命令得自己判断面板是不是还属于它。`until` 把「面板活多久」声明在结果上，
  判断留在唯一知道面板身份的地方（`showCommandPanel`）。别的命令以后也能复用。
- **订阅 `onCredentialChanged` 关面板**：只有成功时会触发，失败、超时、取消都不会触发，面板照样残留。
- **`/login` 的链接改走状态栏**：链接很长，状态栏只有一行，放不下也没法复制。
- **登录完成后在面板里原地显示结果，而不是关掉**：用户还得按 Esc，问题没解决。结果已经由 notify 报到状态栏了。
- **用 `until.finally(close)`**：`until` reject 时 `finally` 返回的 Promise 也会 reject，没人接就是 unhandled rejection。
  所以用 `then(close, close)`。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/command/login-commands.test.ts` 新增用例：
  - 面板带 `until`，等待期间不落定，`/login cancel` 后落定；重复 `/login` 拿到的是同一个 `until`。
  - 文案含「自动关闭」，不再含「可以继续使用」。
  - 正常登出的回执只有 1 行；后端返回 500 时仍有 ≥3 行，内容含「通知后端解绑失败」。
- 「关面板」这一步在 `app.ts` 的 TUI 闭包里，没有单测覆盖。靠类型检查和一次真实的 `/login` 操作验证。
