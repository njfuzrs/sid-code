# Skill 文档核查残留收口：skip 语义、缺省值注释、随仓 SKILL.md 过时承诺

## 决定了什么

2026-10-18 的 Skill 扩展页核查记录（`docs-research/.../todo/20261018-Skill扩展页文档核查发现的代码缺陷与文档问题.md`）里的代码缺陷 B1-B3 与 41 项官网文档问题已于 `6096ce1c` / `d42de70e` 等提交修完。本次只收口剩下的「文本与代码事实不符」：

1. `website/extend/skills.md` 权限继承段：原文「主会话 `--dangerously-skip-permissions`：子代理同样完全跳过权限检查」在 `ea2fc86d`（2026-10-21）之后已不成立 —— 子代理侧 `skipPermissions` 恒为 `false`，主会话 skip 档在子代理侧归一为 `always-allow`（`packages/core/src/permission/sub-agent-checker.ts:51-53,59-63`），危险命令与安全类确认仍然拦。改写为准确描述。
2. `packages/core/src/skill/types.ts` 与 `command-adapter.ts` 的注释：`mode` / `context` 都不写时执行上下文已是 inline（`executor.ts:resolveSkillExecutionContext`），两处注释仍写「delegate / fork 默认」；`effort` 注释漏掉已支持的 `xhigh`。
3. 随仓分发的 SKILL.md / learnings.md：
   - `code-review/SKILL.md` §5 SLA 表仍把 P95 15min 写成执行层 `timeout`（该字段已废弃，子代理无墙钟上限）；
   - `code-review/learnings.md` 的历史偏差仍把 builtin 加载 bug 与 `timeout-mins = 15` 当现状；
   - `skill-creator/SKILL.md` 把文件布局与执行模式绑定（运行时两种布局与 mode 无关），并把 `name` 写成必填（目录型可回退目录名）。

同步重新生成 `packages/core/src/skill/builtin-embedded.generated.ts`（hash `db400f8b6e79bed1`），否则二进制释放的仍是旧文本。

## 放弃了什么（以及为什么不选）

- **不删 `learnings.md` 的历史 section**：该文件自己约定「不要修改历史 section（保持时间线证据）」。采用就地加「✅ 已修复」标注，既不篡改时间线，也不让人把旧结论当现状。
- **不改 `code-review/SKILL.md` §8 的「真 LLM baseline 未跑」**：它与 frontmatter `baseline_executed_real: true` 矛盾，但核查记录 R5 明确界定「本次只确认 timeout 过时，不推断其他发布数据」。留给单独的发布数据校准任务，避免这个 PR 混入无关判断。
- **不声称 D43 已端到端验证**：官网 `-p` 示例的 Bash Permission 终局仍未实跑，本次只对齐源码语义，不宣称跑过集成测试。
- **不动 C1（`/skills` 面板不收录插件 / MCP Skill）**：那是产品范围裁决，不是文档错误；没有裁决前改代码等于替产品拍板。
