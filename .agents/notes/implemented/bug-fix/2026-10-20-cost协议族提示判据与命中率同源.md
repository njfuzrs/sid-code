# `/cost` 协议族提示改为按 modelUsage 逐模型 provider 判断，与命中率同源

## 决定了什么

`packages/cli/src/command/builtins.ts` 的 `CostCommand` 里，「openai 协议为隐式缓存，60-70% 属正常上限」这行提示的判据：

- 旧：`ctx.config.provider === "openai" && !totalUsage.cacheCreationInputTokens`。一个按当前模型判断，一个按全会话写入量判断，两个条件的范围不一样。
- 新：遍历 `ss.modelUsage`，按每条记账时的 `provider` 判断。只要有 openai 族条目产生了命中，且这些条目的写入量全是 0，就提示。写入量只看 openai 族自己的条目。
- 会话里还有别的协议族产生命中时，改用混用版文案，说明整体命中率是各族加权的结果，不能直接套 60-70% 的标准。

命中率本身走 `getNormalizedCacheUsage()`，也是遍历 `modelUsage`。两边现在用的是同一份数据。

修掉的失效场景：

- 先 anthropic，再 `/model` 切到 openai：anthropic 那部分的写入量让旧条件恒为假。
- 主模型 openai，子代理用 anthropic：不切模型也会漏提示。
- 先 openai 再切 anthropic：历史上 openai 那部分的命中率没有任何解释。

`website/use/cost.md` 同步改了触发条件的描述。

## 放弃了什么（以及为什么不选）

- **只把 `ctx.config.provider` 换成「会话里存在 openai 条目」，写入条件仍用全会话 `totalUsage`。** 先 anthropic 后 openai 的场景下，anthropic 的写入量仍然大于 0，条件还是假，等于没修。所以写入量必须只取 openai 族的条目。
- **按族分别给阈值判定（例如 anthropic 低于 80% 就报警）。** 这会把文档里写明的「经验区间，不是代码阈值」改成代码里的硬阈值，属于新需求，而且阈值没有轨迹数据支撑，所以不在这次范围内。
- **在分模型行里加每个模型的命中率。** 能把混用会话解释得更细，但会改 `/cost` 的输出结构和文档示例，超出缺陷修复的范围，以后有需要再单独做。
- **担心自定义 provider 名不等于 `"openai"`、却走 openai 协议的情况。** 这种情况不存在：`packages/core/src/llm/registry.ts` 的 switch 只认 anthropic/openai/ollama，其他名字直接抛错。Responses API 也挂在 openai provider 下面，provider 名仍是 `"openai"`。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/command/cost-protocol-hint.test.ts`，6 个用例，走真实的 `SessionState.updateUsage` 和 `CostCommand.execute`：
  - `bun test ./packages/cli/tests/command/cost-protocol-hint.test.ts` → `6 pass / 0 fail`。
- 变异自证：把判据临时换回旧条件后重跑，结果 `3 pass / 3 fail`。挂掉的正好是场景 A、B、D（先 anthropic 后 openai、先 openai 后 anthropic、openai 主模型配 anthropic 子代理），恢复后全绿。
