# 工具卡片一律折叠，执行中也零正文：把「先展开再收起」造成的高度跳变与整帧重画消掉

## 决定了什么

1. **撤掉 compact 的「少量行降级」**（`packages/cli/src/ui/history-adapter.ts`）。
   #808 / #810 曾加过两档阈值：正文视觉行 ≤5 行（shell 类 ≤1 行）就降级回原样展示。
   现在只剩一个例外——**空正文**降级（折叠零行与不折叠等价，留着只会让标题行多一个「0 行」假指标）。
   声明 compact 的工具（read / grep / glob / ls / read_many / web_fetch / web_search / lsp /
   成功退出的 bash）只要正文非空就折叠。

2. **shell 工具执行中也走折叠形态**（`ToolMessage.tsx` 的 `isShellRunningCollapsed`）。
   执行中不再渲染「命令行区 + 4 行实时输出 tail」（`bash.ts` 的 `PROGRESS_TAIL_LINES = 4`），
   命令并进标题行（复用 compact 的 `collapsedShellDescription`），实时反馈只把 tail 的
   **最后一行**截到 40 列塞进标题行尾部（`liveTailLine`）。

3. **组尾 `ctrl+o` 提示的判据覆盖执行中的 shell**（`ToolGroupMessage.tsx`）。
   提示行必须在执行中就占位，否则卡片高度按住了、提示行却在完成那一刻新冒一行。

4. **删掉已成为死代码的 `countVisualLines` / `ESTIMATE_WRAP_COLUMNS`**（`ui-utils.ts`）：
   它是行数降级的唯一消费者。

### 为什么：两个叠加的成因，都不是「渲染后测高」

- **成因一（观感）**：执行中卡片 = header + 命令行区 + tail ≈ 最多 7 行；完成瞬间折成 1 行。
  用户看到的就是「先刷地展开、再刷地收起」。
- **成因二（闪烁放大器）**：主屏帧一旦占满视口，**任何变矮**都会触发整帧重画
  （`packages/tui/src/frame/main-screen.ts:116` 的 `p >= viewportRows` 分支：清屏 + 清 scrollback
  + 重写全部历史，长会话一次几百 KB）。7 行 → 1 行的收缩正好落在这个分支上。

另需澄清一个误解：**并不存在「先渲染内容测高度再决定折多少」的实现**。降级是数据层拿
content 字符串做估算（`countVisualLines`，80 列折行），不涉及渲染与测量；性能焦虑不成立。
真正的问题是那个判据让卡片形态随输出规模跳。

## 放弃了什么（以及为什么不选）

- **放弃「≤5 行不折」这个体验优化**（#810 的初衷：`glob` 匹配 3 个文件、`grep` 命中 2 条折起来
  反而逼用户按 ctrl+o，而 ctrl+o 是全局档位、一按全展开）。
  理由：它换来的「少按一次 ctrl+o」是以「卡片高度随输出规模变化」为代价的，而后者叠加主屏的
  整帧重画就是可感知的闪烁。规模信息仍由标题行摘要承担（`getResultSummary` 的
  「N 行输出 / N 个文件 / N 个结果」），正文走 ctrl+o。

- **放弃执行中的多行实时输出**（这是唯一的实时反馈手段，`ToolMessage.tsx` 原注释明确说
  长命令「不再卡在无输出」靠它）。严格做到「执行中与成功后同高」就只能是零正文。
  补偿：最后一行留在标题行（不占高度），完整 tail 按 ctrl+o 仍能看。

- **没有选择「保留 tail 但完成后也占住那几行」**（用 held rows 留白）：
  用户要的是折叠，不是留空行；留白等于用永久的空白换一次跳变，屏幕利用率更差。

- **没有动 `task_output` 的 progressLine 与 `sub_agent` 的 agentProgress**：
  它们同样在完成时变矮，但那是「过程可见」的刻意设计，且与本次诉求（bash/read/grep 类
  工具卡片）不是同一批。留作后续单独判断。

## 拿什么证明它生效了

- `packages/cli/tests/render-port/main-screen-shrink-e2e.test.ts`：重画计数从改动前的
  `完整一轮 3` 变成 **`完整一轮 2`，第二轮 0**（该用例正是记录「bash 折叠让整帧重画 +1」的
  那条，2026-11-13 合入时被迫把上限放宽过一次）。
- 新增 `ToolMessage-compact.test.tsx` 的「执行中的 shell：与成功后同高（0 高度变化）」5 条：
  执行中整帧 1 行、与成功态行数相同、不含 4 行 tail 正文、命令仍在标题行、
  最后一行可见、ctrl+o 展开回多行。
- 数据层测试改成反向锁：`≤5 行同样折叠`、`一句话结论也折叠`、`shell 一句话结论同样折叠`、
  `grep 与 bash 同一口径`、`尾部换行不影响判定`——防止「一眼看完就不折」被悄悄加回来。
- `bun test ./packages/cli/ ./tests/website/`：3663 pass / 0 fail。
- `make build`：自检通过。
- **冻结基线 `term-bench/baseline/C2.json` 手改 6 处**（按 L5.3，不重生成，逐项如下）：
  1. `total.bytes` 6414 → 6472
  2. STEP「bash 执行中」`cursor.y` 8 → 9
  3. STEP「bash 执行中」`metrics.bytes` 256 → 314
  4. STEP「bash 执行中」`screen` 插入 `"  ctrl+o 展开完整输出"`
  5. STEP「bash 执行中」`styled` 插入 y=5 的 `ctrl+o` / `展开完整输出` 两个 run

  逐项核对结论：全部差异都来自「提示行提前到执行中占位」，无其它渲染差异
  （STEP 2「屏外项完成」、STEP 3「退出后」逐字段相同，`eraseScreen` 仍为 1）。
