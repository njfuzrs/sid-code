# 11 个 major 升级（PR #108）：修 CI 两处红，并把 11 个 bare `zod` 导入钉到 `zod/v3`

## 决定了什么

放行 Dependabot `rest` 组（11 个更新），并修掉它带来的三件事——其中第三件 CI 抓不到：

1. **`format:check` 红**（`packages/core/src/ide/integration.ts`）。oxfmt 0.63→0.64 改了
   `return !!( ... )` 里冗余括号的处理，跑 `bun run format` 即消。纯排版，无行为变化。

2. **`参考页生成器 · --check 自洽 > 干净状态下 --check 退 0` 红**（ubuntu + macos 同一条）。
   根因不是参考页陈旧，而是 **zod 4 换了内省结构**：`scripts/docs-gen-reference.ts:365`
   读的是 v3 的 `_def.typeName`，v4 挪到了 `_zod.def.type`。

   ⚠️ **这里最危险的处置是"跑一下 `bun run docs:gen-reference` 让它绿"** ——
   我跑过一次，`--check` 确实退 0 了，代价是 `website/ref/settings.md` **45 行的
   `类型` 列全部退化成 `?`**（`string`/`number`/`boolean`/`enum` 连同 enum 取值、
   `≥0`/`整数 ≥0` 约束一起消失）。门禁只问"参考页与源码一致不一致"，
   不问"参考页还有没有信息"，所以那条路是**用文档质量换绿灯**，且不会有任何东西报红。
   已 `git checkout` 撤销。

3. **11 个 bare `import { z } from "zod"` 被静默从 v3 翻成 v4**（真正的隐患，五道门禁全绿也测不出）。
   本仓刻意跑两套 zod 方言：`zod/v4` 子路径给工具层（要 `z.toJSONSchema`），
   bare `zod` 给 sdk/settings/keybindings（见 `packages/core/src/sdk/lazy-schema.ts` 的注释）。
   `"zod": "^3.25.0"` → `"^4.4.3"` 之后，bare `zod` 的解析目标从 v3 变成 v4，
   而这 11 个文件全部按 v3 的语义写的。已全部改成显式 `from "zod/v3"`
   （zod 4.4.3 仍导出 `./v3` 子路径，实测在 exports 里）。

   修完 `docs-gen-reference --check` 直接退 0 —— 生成器不用改一行，
   因为它读的 `SettingsSchema` 又是 v3 对象了。这也顺带证明 2 与 3 是同一个根因。

已核实的一处 v4 语义漂移（这是"钉回 v3"而非"改内省代码"的第二个理由）：
`packages/core/src/config/settings/validation.ts` 的 `generateSuggestion()` 按
`issue.code` 分派，而枚举错误在 v3 是 `invalid_enum_value` + 带 `options`，
v4 变成 `invalid_value` 且 `received` 字段消失：

```
v3: {"code":"invalid_enum_value","received":"zzz","options":["a","b"]}
v4: {"code":"invalid_value"}
```

即 settings.json 写错枚举值时，v4 下"有效值为: a, b"这句建议会**静默消失**
（函数落到 `return undefined`，不报错）。没有测试覆盖这条，属于
[[metric-exists-but-value-is-junk]] 那类"过了检查但没测到东西"。

## 放弃了什么（以及为什么不选）

**否决「继续搁置整个 PR」。** 今天早些时候的
`2026-08-24-修两个SDK安全告警-与12个major的批量升级分开.md` 把这批 major 从 #105
拆出来搁置，理由成立且**当时是对的**：安全修复不该等 12 个 major 的行为验证。
但那条理由是**关于上线时机**的，它到期了 —— SDK 安全修复已独立落地，
现在这批 major 是独立单元，没有东西再被它拖着。那份 Note 留下的条件是
「按 `src/ui/CLAUDE.md` L2.3 要用整帧渲染验证对齐，不是跑通单测就算完」，
本次**照做了**（见下一节），不是绕过。

**否决「改 `docs-gen-reference.ts` 去适配 v4 内省」。** 技术上可行
（`_zod.def.type` / `_zod.def.entries` / `_zod.def.checks[]._zod.def.check` 都能读出来，
已实测），但那是把生成器**同时**绑到两套内部结构上，而 `_def` / `_zod` 都是
zod 的私有字段。真正的问题不在生成器，在于 11 个 v3 语义的文件被静默换了运行时。
先修错位，再谈适配。

**否决「把 sdk/settings 整体迁到 v4」。** 那是一次真正的迁移（`ZodEffects`、
`z.record` 单参、issue code 语义、`safeParse` 错误结构逐一核对），
和"消化一批 Dependabot major"不是同一个单元。按 CONTRIBUTING 的三条测试
（可独立上线 / 可独立回滚 / 一次 review 完），它得单独开一个 PR。

**否决「只钉 `packages/core/src/config/settings/types.ts` 一个文件」**（那是让
`--check` 退 0 所需的最小改动，实测足够）。剩下 10 个文件照样是 v3 语义跑在 v4 上，
只是当前没有门禁照到它们 —— 留着就是把同一个坑留给下一个人，而下一次触发它的
可能是用户的 settings.json 报错信息，不是 CI。

## 拿什么证明它生效了

**五道门禁**（本地全绿，对应 CI 的 test + lint 两个 job）：

```
bun test           → 10802 pass / 0 fail / 78602 expect（744 文件 / 147.97s）
make build         → exit=0；`will always be undefined` 与 `warn` 各 0 命中
bun run lint       → Found 0 warnings and 0 errors
bun run format:check → All matched files use the correct format
bun run lint:boundary → 越界依赖 0 处 / 测试跨包相对路径 0 处
```

失败前的对照是 CI 上的 `10801 pass / 1 fail`，同为 10802 总数 ——
说明修复没有让任何测试被静默跳过。

**参考页没有退化**（这是本次最容易骗过自己的一格）：修完
`bun run scripts/docs-gen-reference.ts --check` 输出
`✓ 参考页与源码一致，CLI 双源对账通过`，而 `git status` 里
**`website/ref/` 零改动** —— 即"绿"是靠恢复 v3 内省拿到的，
不是靠把 45 行类型列改写成 `?`。

**TUI 宽度：v8 是收敛不是回归**（履行上一份 Note 留的整帧验证条件）。
`string-width` 7→8 改了三个字形的宽度，其中 `⏺`(U+23FA) 正是本仓
`figures.ts:14` 的主 bullet：

```
        renderer  Bun.stringWidth  sw7  sw8
⏺       1         1                2    1     ← v7 是离群值
⚠       1         1                2    1
▪       1         1                2    1
● ⎿ ✻   1         1                1    1
你好     4         4                4    4
🎉      2         2                2    2
```

方向是**v8 向 `packages/tui-renderer/src/stringWidth.ts` 与 `Bun.stringWidth` 靠拢**
（该文件的注释本来就写着"string-width 把 ⚠ 错报成 2"）。
布局权威是 renderer，不是这个包，所以对齐不受影响；
且 8 个消费点（`markdown.ts` / `Footer.tsx` / `text-buffer.ts` 等）全是动态测量，
没有任何针对 v7 宽度写死的补偿常量（grep `26A0` / `23FA` 零命中）。

整帧渲染实测（60 列，bullet 行 + 树枝行）：
