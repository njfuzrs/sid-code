# 计费金额对账按请求实际走的端点取价，消掉 111 个假的 high

## 决定了什么

- `trace/digest.ts::checkBillingAmountConsistency` 重算 Σ BilledRequest 时，`calculateUSDCost` 的 `baseURL` 参数原来恒为 `undefined`，现在传请求实际走的端点。网关采集价因此能查到，不再一律落到注册表价。
- 端点来源：`BilledRequest` 不带 `base_url`，同一次调用的 `AfterModelRaw.data.base_url` 带，按 `index` 配对。配不上的调用（后台任务 900000+ 段，以及没有 AfterModelRaw 的主链调用）用会话里唯一的那个端点。会话用过不止一个端点、又有调用配不上时，不判。
- 价表可查性检查 `resolvePricing(model)` 也带上端点，与重算口径一致。
- 返回值加 `baseURL`。`billing_amount_mismatch` 的 detail 写明重算用的是哪个端点的价表（或「注册表价（轨迹无端点信息）」），加 `pointer`，并提示「token 逐项对得上而金额对不上，先查是否价表不同」。
- 不改事件格式、不改采集侧，历史轨迹直接受益。

## 放弃了什么（以及为什么不选）

- **给 `BilledRequest` 加 `base_url` 字段**：只修未来的会话，本地已落盘的 116 个误报会一直留着；而 AfterModelRaw 里已经有这个信息。
- **配不上端点时一律用会话第一个端点**：多端点会话会把一个端点的调用按另一个端点的价算，正是这次事故的形态。宁可不判。本地 506 个有计费事件的会话里只有 3 个用过两个端点。
- **把阈值从 1% 放宽**：误报的偏差是 77%，放宽阈值掩盖不了，还会把真的双记一起放过去。
- **把 high 降为 medium**：修完后剩下的 6 个偏差在 1.8%–65%，是该查的真差异，降级只会让它们更难被看到。
- **用户自配的 `availableModels` 价**：digest 读不到用户配置，这条盲区保留。provenance 已标 `lossy: true`，注释写明。

## 拿什么证明它生效了

- 新增 6 条单测（`packages/core/tests/trace/digest-billing-amount.test.ts`「按端点取价」组），在隔离的 `SID_CONFIG_DIR` 里写一张 cacheWrite = 0 的网关价表，复刻事故形态。
- 变异自证，两处都看到了预期的红：
  - 把 `baseURL` 改回 `undefined`：「按 index 配上端点」和「后台任务退回唯一端点」两条失败（11 pass / 2 fail）；
  - 去掉多端点退让：「多端点会话不判」失败（12 pass / 1 fail）。
- 本地真实数据验收：对当前 summary 里报 `billing_amount_mismatch` 的 117 个会话，用本分支的 `scripts/trace-digest.ts --json` 逐个重跑。111 个不再报，6 个仍报。不再报的 111 个逐个复算过，全部是「按端点价重算后与账本差 < 1%」，没有一个是因为退让（无账本 / 多端点 / 查不到价）才不报。
- 仍报的 6 个：5 个在 uniapi（偏差 1.8%–65%），1 个在 ppchat（账本比计费事件多 33%）。这是真实差异，交给计量方向去查。
- `bun run affected-tests:run`：982 pass / 0 fail。`make build` 自检通过，无 `will always be undefined` 告警。
