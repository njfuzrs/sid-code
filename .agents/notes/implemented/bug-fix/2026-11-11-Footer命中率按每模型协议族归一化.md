# Footer ⚡ 命中率改由 core 的 `getCacheHitRate()` 推送，删掉 UI 层的协议族重算

## 决定了什么

Footer 的缓存命中率（行1 的 `⚡N%` 与自定义 statusLine 脚本的 `cacheHitRate`）**不再由 UI 层计算**，
改为读 `SessionState.getCacheHitRate()` 推下来的那个整数。

一条完整的接线（每层只做一件事）：

- `packages/core/src/session/state.ts`：新增 `getCacheHitRate(): number | undefined`。
  内部走既有的 `getNormalizedCacheUsage()`——**按每个模型自己记账时的 `stats.provider` 逐条归一化后加总**
  （anthropic 的 `inputTokens` 是未命中余量、openai 的 `prompt_tokens` 含命中）。
  `cacheHitTokens <= 0 || promptTotal <= 0` → `undefined`（不渲染该列），与修复前的显示条件一致。
- `packages/cli/src/ui/cost-bridge.ts`：`subscribeCostToBridge` 的 patch 里加 `cacheHitRate`。
  入账订阅（`updateUsage` + `addSideCost` 都触发）本来就覆盖主循环与辅助调用，命中率顺势刷新。
- `packages/cli/src/app.ts`：`StateBridge` 构造的初始状态里也读一次（resume 进来的会话 `modelUsage` 已有值，
  首帧就该显示，不必等下一次入账）。
- `packages/cli/src/ui/state-bridge.ts`：`getConversationClearedPatch()` 把 `cacheHitRate` 重置为 `undefined`
  （`/clear` 清空 `modelUsage` 后不能继续显示上一会话的命中率）。
- `packages/cli/src/ui/{App.tsx,components/BottomRegion.tsx,components/Footer.tsx}`：`TUIState` 加
  `cacheHitRate?: number`，透传到 Footer。
- `packages/cli/src/ui/hooks/useStatusLineData.ts`：`deriveCacheMetrics` 的签名从
  `(usage, model, availableModels)` 改成 `(cacheHitRate?: number)`——只做「数字 → 文本 + 颜色」，
  不再碰 `normalizeCacheUsage` / `SessionState.inferProvider`。

## 放弃了什么（以及为什么不选）

- **不在 UI 层保留「当前模型 provider」的重算作为兜底**。那正是缺陷本身：单模型会话看不出问题，
  但会话里换过模型、或主模型与子代理协议族不同时，会把 anthropic 的未命中余量当成 openai 的含命中
  全量去减（反之亦然），命中率直接算错，且与 /cost 是两个数。留一份兜底等于留两条会分叉的口径。
- **不把 `getCacheHitRate()` 直接实现在 UI 侧（如 `cost-bridge.ts` 里做除法）**。
  命中率的分母口径（`promptTotal`）是北极星铁律 3 的敏感项，`/cost`、`/stats`、SessionEnd 账本
  三条消费路径已经共用 `getNormalizedCacheUsage()`；把除法放在 UI 只会让「同一指标两种算法」
  有第二个落点。方法放 `SessionState` 上，谁都能读、只有一个实现。
- **不改成「无命中时显示 ⚡0%」**。修复前的显示条件是 `cacheHitTokens > 0`，无缓存的模型/会话根本
  不渲染这一列（避免把「没这个概念」显示成「效果很差」）。本次只修数字算错，不改显示条件。
- **不顺手改 `/stats`（D9）与 `≈$` 判据（D7）**。它们同属方案里的 PR-A，但各自要动别的契约
  （`StatsDialog` 的单价取数、`ModelUsageStats` 快照字段、billing label 语义），与 D18 无依赖。
  按「一个 PR = 可独立回滚单元」分开做，本 PR 只含 D18。

## 拿什么证明它生效了

三层断言 + 两轮变异自证（CLAUDE.md：新增回归必须先把代码改坏，确认断言变红）。

- **G1 core 取数源**：`packages/core/tests/session/cache-usage.test.ts` 新增 3 条——
  anthropic（input 1,000 未命中 + 命中 9,000）与 openai（input 10,000 含命中 6,500）两条 `modelUsage`
  → `getCacheHitRate() === 78`（= (9000+6500)/(10000+10000)）；无入账 → `undefined`；有 prompt 零命中 → `undefined`。
- **G1 接线**：`packages/cli/tests/ui/cost-bridge.test.ts` 新增 T-A8——真实 `SessionState` + `StateBridge` +
  生产订阅函数，两条跨族 `updateUsage` 后 `bridge.current.cacheHitRate === 78`。
- **G1 整帧**：新增 `packages/cli/tests/ui/components/footer-cache-hit-rate.test.tsx`——给 Footer 传
  `cacheHitRate={78}` 且 `usage` 是跨族合计形态（旧算法在同一份 props 下会算出 `⚡141%`），
  断言行1 出现 `⚡78%` 且**不出现** `141`；另锁「省略 → 整帧无 ⚡」「0 → ⚡0%」「窄终端不折行」。
- **变异 1**：把 `useStatusLineData` 的 `cache: deriveCacheMetrics(cacheHitRate)` 改回
  「合计 usage + 当前模型 openai 口径」→ 整帧用例 3 条红，实际帧为
  ` gpt-4o · 5% · ↑40k ↓2k · $0.1200 · ⚡141% · ⟳ 3`。恢复后绿。
- **变异 2**：删掉 `cost-bridge.ts` 里的 `cacheHitRate: session.getCacheHitRate()` →
  T-A8 红（`Expected: 78` / `Received: undefined`）。恢复后绿。
- 四组测试合跑：`bun test ./packages/cli/tests/ui/cost-bridge.test.ts ./packages/cli/tests/ui/status-line-data.test.ts ./packages/cli/tests/ui/components/footer-cache-hit-rate.test.tsx ./packages/core/tests/session/cache-usage.test.ts`
