# 索引已满时，同 key 覆盖的「结论级替换」必须留痕

## 决定了什么

后台提取代理把新事实写进**同一个 key** 时，旧条目的主题陈述会被静默换掉：磁盘上那条
记忆的标题还是旧的，正文讲的已经是另一件事（MD3）。索引已截断时这个问题被放大 ——
新建 key 大多直接成为「磁盘上有、模型看不见」的孤儿，写入压力全压到既有 key 上。

新增 `packages/core/src/memory/conclusion-guard.ts`，判据是**结构的，不是语义的**：

- 取旧条目正文的**首行结论**（第一个非空行里 `Why:` 之前那句主题陈述）；
- 新 value 里**没有**这句话、且**没有** `推翻：` / `纠正：` 标签 → 拒绝，并把旧结论原文
  回告给模型（它照抄一句就能改对）；
- 三处放行面：旧结论还在（细节级更新）、带推翻标记、**索引没满**（新建 key 可行，
  不必收紧同 key 覆盖）。

闸门落在**三条写入路径**上，同一份判据实现：

| 路径 | 落点 |
| --- | --- |
| `save_memory` | `tool/memory.ts`，`store.set` 之前 |
| `write` 工具 | `tool/write.ts`，与 P1-8 的 secret 闸门同一位置 |
| `edit` 工具 | `tool/edit.ts`，比的是 `finalContent` 而非 `newString` |

`paths.ts` 新增 `resolvePrivateMemDir()`：索引是**每条线各一份**（project / global /
agents/<type>），容量判据必须按那一条线的 `MEMORY.md` 判，不能拿 project 的索引去判
global 的写入。`MemoryGuardKind` 新增 `conclusion_replace`（带 `via` 区分两条路径）。

## 放弃了什么（以及为什么不选）

**① 不做语义判断。** 「这两句话是不是同一个意思」无法用字符串判定。判据只问
「旧的首行结论还在不在」，它挡不住「旧结论还在、后面又混进一大段新主题」那种混杂式追加
—— 那同样让一条记忆承载两件事，但结构判据分不出来。后半段交给 P1-2 的核实轮次与人工 review，
不在本闸门的承诺范围内（文件头注释里已写明这条边界）。

**② 不把闸门做成恒关。** `推翻：` / `纠正：` 是放行标记，`更新：` / `补充：` **刻意不在表里**
—— 它们和「追加」是同一个意思，放进来等于所有普通更新都能通过，闸门就白加了。
这与 P0-4 的 `NEGATION_ACK_MARKERS` 排除「更正：/修改：」是同一个理由。

**③ 主题陈述过短时不判定。** 归一化后短于 8 个字的「主题」在任何新内容里都能被
`includes` 命中，拿它当判据只会让闸门恒开，还会让人误以为防住了。这是主动接受的漏拦。

**④ 闸门只在索引已满时生效。** 索引没满时新建 key 是可行的，把同 key 覆盖一并收紧
会让正常的记忆迭代成本上升，而这条闸门要解决的只是「索引满 → 写入压力全压到老 key
→ 老 key 被静默换主题」这条放大链。

**⑤ 判据顺序按性能排。** 这条闸门挂在 write/edit 的**每次调用**上。先用「不在配置根下
就不是记忆路径」的廉价否定，再跑纯字符串判据早退，只有「看起来是一次结论级替换」时才
反推记忆目录（`getAutoMemPath` 会 fork git，单次实测 5.4ms）。普通源码文件的写入
不会为此额外付进程启动成本。

## 拿什么证明它生效了

新增 `packages/core/tests/memory/conclusion-replace-p1-1.test.ts`（20 个用例），
覆盖 T-M5 的四条：两条路径都拒、磁盘逐字未变、带标记/细节级/索引未满三种放行、
`更新：`/`补充：` 不算声明。

**变异自证**（三次注入，每次都先恢复再下一轮）：

| 注入 | 结果 |
| --- | --- |
| `hasOverturnMarker` 恒返回 `true` | 20 个用例里 **7 个红** |
| 删掉 `edit.ts` / `write.ts` 的闸门调用（只留 save_memory） | `edit 换掉首行结论` + `write 丢掉旧首行结论` **2 个红** |
| 去掉两处的 `readIndexCapacity(...).truncated` 判据 | 两个「索引未满放行」**2 个红** |

命令与输出：


⚠️ 第一次跑测试时有 2 个用例红，原因是**测试样本本身**的缺陷：记忆文件的
`description:` 复用了正文首行，导致 edit 的 `old_string` 命中两处、报「多处匹配」而
不是被闸门拦下。已改成固定描述并复跑。这条记在这里，是因为它正是「断言通过/失败的原因
和你想的不一样」那类，只看红绿会误判成实现有问题。
