# 后台任务 follow-up：等待进度行、bg_task_get 阻塞口径、整帧测试

来源：对 PR #358（`20261019-后台子代理task_output空白头与结果双投递`）落地情况的二次复核。复核发现三处缺口，本 PR 一并补上，并修正原 Agent Note 的两处口径问题。

## 决定了什么

- **task_output 等待进度行（原方案 §4 F4 的漏项）**：
  - `TaskOutputTool.execute` 接收 `onProgress`，阻塞等待时立即上报一次、之后每 500ms 刷新：「等待任务完成 · 已等 Ns · esc 可中断」。
  - 上报放在终态 / 超时判定**之后**、sleep 之前：放在 sleep 之后会在任务已结束时多报一条「仍在等」。
  - TUI 侧：非 shell 工具的执行中 `progressMessage` 统一渲染到**卡片下方一行**（`ToolMessage.progressLineSection`），header 不再重复这段文案。
  - **影响范围不止 task_output**：所有无结构化进度的非 shell 工具（LSP 阶段文案「等待语言服务器就绪…」、web_fetch、MCP 纯文案进度）都从 header 尾部移到下方一行，卡片高度 +1 行。这是有意推广（阶段文案塞在 header 尾部同样会被挤断），已用 LSP 整帧断言锁住范围。
  - MCP 的有结构化进度（`progress !== undefined`）保持原样（header 文案 + 结果区进度条），避免同一条文案出现两次。
- **bg_task_get 阻塞口径（原方案 F3 未覆盖的同类入口）**：
  - 描述从「要等完成，用 block=true 问一次即可」改成「完成会自动通知，不要为等待完成而阻塞或轮询；block=true 仅在用户明确要求等结果时使用」。
  - 同文件里另外三处与新描述相反的文案一并改掉（模型调用时离它们最近，只改 description 会被抵消）：
    - schema 的 block 描述「true 时问一次即可拿到结果，无需轮询」→「等待完成不需要它，完成会自动通知」；
    - timeout hint「可以再次调用本工具继续等（可加大 timeout）」→「会自动收到 task-notification，不要再次阻塞」。旧文案正是基线会话 `senfhxhhe`「阻塞满 600s → 再调一次」的形态；
    - not_ready hint「要等它完成请用 block=true（默认）」→「完成时会自动通知」。
  - **保留** `block` 原语与默认值 true。它是 P1-3 为治「`bg_task_list` 空参轮询 49 次 / 占全部工具调用 18.8%」刻意加上的，删掉会退回轮询。
  - 中英两份 system prompt 同步改成「不要用 task_output / bg_task_get 阻塞等待或轮询」。
  - 协调模式提示词（`coordinator/mode.ts`）原写「task_output: 读取 Worker 的执行结果 / 通过 task_output 阅读发现」，是绕开 F3 的入口；改成「结果以 task-notification 自动送达，task_output 仅查看进度」。
- **整帧测试（原方案 §5 最后一行）**：新增 `packages/cli/tests/ui/task-output-display.test.tsx`，从 `buildCompletedToolCall` + `ToolGroupMessage` 走完整链路，断言元数据标签 / JSON / 字面 `\n` 不上屏。
- **修正 #358 的 Agent Note**：用例数「14 例」→ 实际 11 例；digest 行的变异声明从「—」补成实际变异。

## 放弃了什么（以及为什么不选）

- **不把 `bg_task_get` 的 block 删掉 / 改成 task_output 同款「不要阻塞」**：会推翻 P1-3 的设计，让模型回到空参轮询。两处提示词的冲突用「统一口径 + 保留原语」解决，而不是二选一。
- **不把 `block` 默认值改成 false**（外部 review 提议过）：P1-3 的防轮询效果依赖「问一次就拿到」；cc 的 `TaskOutputTool` 同样 `default(true)`，它是靠描述标 DEPRECATED 引导 Read 输出文件，不改默认值。正确性已由 #358 的 F1（认领 + 撤回）机械保证，F3 只降概率，不值得为它碰 P1-3。
- **不把进度行收窄到只对 task_output 生效**：按工具名分派正是 `tool-progress-route.ts` 自述要拆掉的模式；LSP 阶段文案放下方一行同样更好读。
- **不给 task_output 做专用 React 渲染组件**：沿用通用卡片 + 一行进度，不新建第三块 UI 区（见反模式记忆 `subagent-progress-third-region-antipattern`）。
- **不动 `bg_task_list` 的 header**：它没有 task_id，合理形态是「列出后台任务」而非「任务描述」，与本轮「区分并行 task_output」的目标不同，留作 polish。
- **不改 PR #358 的正文数字**：PR 已合并，编辑正文会触发一次无意义的 CI 重跑；数字修正落在仓库内的 Agent Note 里，随本 PR 可追溯。
