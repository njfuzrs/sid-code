# 用户级 CLAUDE.md 的 `## Allowed Tools` 从「静默失效」改为真正生效

## 决定了什么

**让用户级 CLAUDE.md 的 `## Allowed Tools` 生效**，而不是撤掉官网的承诺。

- `packages/core/src/permission/checker.ts`：新增 `addPreApprovedRules(rules)`，把运行期补入的
  预授权规则加进 `preApproved`（Step 12 的放行集合）。用 Set 承接，热重载重复补入天然幂等。
- `packages/cli/src/app.ts` `applyProjectRules`：写入 `config.allowedTools` 时同步调用
  `checker?.addPreApprovedRules?.(rules.allowedTools)`；合并改用 `new Set(...)` 去重。

根因是**时序**，不是解析或过滤：`preApproved` 在 `PermissionChecker` 构造函数里从
`config.allowedTools` 快照一次（`checker.ts` 构造函数），而 CLAUDE.md 由 app 层在 checker 构造
**之后**才加载（`cli.ts` 建 checker → `app.init()` → `doInit` 里 `applyProjectRules("startup")`）。
修前实测：规则确实被解析（`allowedTools=["Bash(git remote add *)"]`，用户级是可信层、
`ignoredSecurityFields=null`），也进了 `config.allowedTools`，但 `preApproved=[]`，
`check()` 走 `step=14` 默认 ask。

顺带修掉同一条路径上的一个小缺陷：原先每次 `applyProjectRules`（热重载 / 切 worktree /
导入审批）都对 config 做一次裸追加，数组只增不减。现在合并去重。

## 放弃了什么（以及为什么不选）

1. **撤掉 `website/use/permissions.md:211` 的承诺**（把「用户级 `## Allowed Tools` 生效」
   改成「不生效」）。否决理由：代码意图明确（`applyProjectRules` 有专门的日志
   `CLAUDE.md 工具白名单` 与合并逻辑），B6 只剔除了**项目侧**不可信层，用户级一直属于
   可信层；撤承诺等于删掉一个用户已经在用、而且安全上成立的功能。
2. **让 Step 12 直接读 `this.config.allowedTools`、废掉 `preApproved` 快照**。否决理由：
   快照的隔离意图是「派生实例（子代理 frontmatter 的 permissionMode）从干净态起步」，
   改读 config 会把 `config.allowedTools` 的数组引用语义（浅拷贝共享）与「谁在什么时机
   写进来」耦合在一起——将来新增一个 config 写入点，其生效范围会变得不可推导。
   显式同步方法把「运行期补入」变成一次可 grep、可断言的调用。
3. **把 CLAUDE.md 的加载挪到 checker 构造之前**。否决理由：加载要读文件系统与合并链，
   checker 在 cli 层、规则在 app 层，挪动等于把 app 的初始化顺序倒置，影响面远大于补一行同步。
4. **只在 `applyProjectRules` 里对 config 去重、不同步 checker**。这就是修前的现状，
   等于没修。

## 拿什么证明它生效了

最小对照（`/tmp/b32-repro.ts`，唯一变量是写入时机）：

```
[A 构造前写入（--allowed-tools / settings）] allowed=true  step=12
[B 构造后追加（CLAUDE.md 真实时序）]        allowed=false step=14 (ask)  preApproved=[]
```

端到端（`/tmp/b32-e2e.ts`，伪造 HOME + 真实 `loadAllCLAUDEmd` 读用户级 CLAUDE.md）：

```
loadedPaths     = ["<tmp>/CLAUDE.md"]
allowedTools    = ["Bash(git remote add *)","Bash(git branch -m *)"]
ignoredSecurity = null
→ 修前 check: allowed=false needsConfirmation=true step=14  config 有规则、preApproved=[]
```

新增测试 `packages/cli/tests/utils/claudemd-allowed-tools.test.ts` 三条断言：
构造后补入放行 `step=12`（并先断言未补入时是 `step=14`，证明不是别的路径给的放行）、
重复补入幂等、静态扫描 `app.ts` 的 `applyProjectRules` 必须含 `addPreApprovedRules?.(...)`
与 `new Set(` 且不含裸追加整句。
