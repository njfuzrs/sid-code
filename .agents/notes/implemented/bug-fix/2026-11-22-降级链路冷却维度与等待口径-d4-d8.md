# 冷却改为账户维度、服务端等待超限统一 give_up、并补白撞率度量

## 决定了什么

第一批（D1 可读性 / D2 / D3）已在 PR #947 落地；本方案完成剩余 D4–D8：

- **D4 冷却 key 改账户维度**（`availability.ts`）：冷却表 key 从裸模型名改为
  `scope:<quotaScopeKey>`，scope 缺失时回落 `model:<name>`。7 个冷却 API
  （mark / get / clear / probe / release / isConsumed）全部加可选 `scope` 参数；
  `fallback.ts` 的 6 个调用点传 `primaryProvider.quotaScope?.()`。
  同一端点 + 同一凭据下，模型 A 撞的 429 现在对模型 B 生效。
- **D5 入口冷却补注释**（`fallback.ts`）：说明「刻意不豁免主线程」与 I4 的
  `isSharedSignalExemptSource` 不是同一套判据，防止后人"顺手统一"。
- **D6 退避硬上限**（`retry-backoff.ts`）：限流分支的 +20% jitter 在加完之后
  再钳一次 `cappedMaxMs`。此前只在乘指数后钳 `baseDelay`，指数触顶后每次
  仍多睡 0~20%（配置 120s 时实测可达 144s）。
- **D8 服务端等待超限统一 give_up**（`recovery-policy.ts`）：`GiveUpReason` 新增
  `server_wait_too_long` 并进入 `I1_EXCEPTIONS`；三条路径（Retry-After header /
  归一化 retryAfterMs / rate-limit-reset）统一判定，超过 `MAX_DELAY_MS` 直接
  give_up，evidence 带真实 `wantedDelayMs`。同步 `digest.ts` 的
  `I1_EXEMPT_GIVE_UP` 与 `recovery-invariants` 的闭集断言。
- **D7 白撞率度量**（`retry-telemetry.ts` + `digest.ts` + `retry-backoff.ts`）：
  retry 事件新增 `retryAfterMs`；digest 的 provider 统计新增 `serverWaitRetries` /
  `blindRetries` / `blindRetryRatio`。分母只含「服务端明确给了等待要求」的重试，
  分母为 0 时不落字段。**退避基数（5s）维持不变**——先有度量再谈调参。
- `serverRequestedWaitMs` 从 `recovery-policy.ts` 抽到 `retry-backoff.ts` 共享，
  恢复决策 / 退避计算 / 遥测归因三处同源，避免三份平行实现漂移。

## 放弃了什么（以及为什么不选）

- **D4 没有选「scope 缺失时跳过冷却」**：会让不实现 `quotaScope()` 的 provider
  连 S2 都没有，退回放大形态；也没有选「全局 key」，那会把两个账户的限流窗口
  混成一个，比不共享更糟。回落裸模型名 = 维持现状语义，`scope:` / `model:` 前缀
  保证两种形态不撞车。
- **D4 没有把 `model` 参数从 API 里删掉**：回落路径仍需要它；key 生成收在一个
  私有 `cooldownKey()` 里，避免 7 个方法各写一份。
- **D5 选 B（补注释）而不是改行为**：让主线程跳过冷却需要实测数据证明
  「跳过后不会在窗口内再撞 429」，当前没有；注释先把「为什么这样」钉住，成本为零。
- **D7 不改 `retryBackoffBaseMs`**：方案明确「先补白撞率度量，再决定 5s 是否合理」。
  没有度量就调参只能靠猜，而 5s 同时被「避免盲撞」与「别让用户等太久」两边拉扯，
  改错方向两个指标一起坏。
- **D8 让 persistent 模式也 give_up**：persistent 的语义是「等多久都行」，但服务端
  要求 >120s 时继续盲等只会把一次明确拒绝拖成一次长超时；早失败更诚实。若未来
  发现无人值守任务因此受损，再单独讨论 persistent 豁免（代码里已有专门用例记录
  这个决定）。
- **没有改 `calculateRetryDelay` 的既有钳制**：D8 的 give_up 在决策层先命中，
  退避层的钳制保留作兜底——直接调 `calculateRetryDelay` 的路径（如 agentic-loop
  的重试）仍需要它。
