# 生成式参考页的错误改在源头文案，不手改 website/ref/

## 决定了什么

`website/ref/` 下 6 个生成页 `--check` 一直是绿的，也就是「页面 = 源码文案」成立；错的是源码文案本身。本次只改生成源，再跑 `docs:gen-reference`：

- `packages/cli/src/help.ts`
  - `-y, --yes` 原写「自动批准所有权限请求」，改为「自动批准需确认的操作（危险命令仍拦截…）」。依据是 `permission/checker.ts` 的 yesMode 刻意不早退。
  - `--permission-mode` 从 6 个取值补齐到 `VALID_PERMISSION_MODES` 的 9 个，`manual` 注明是别名。
  - `--provider` 改成「协议族」口径，注明 openai 族含 Chat Completions 与 Responses。
  - `mcp` 用法行补上 `pending|approve|reject|serve`。
  - `SID_CODE_EFFORT_LEVEL` 补 `xhigh`。
  - 删掉 `SID_CODE_RESPONSE_HEADER_TIMEOUT_MS` 的重复登记，env 页计数从 123 变为 122，与实际一致。
- `/effort` 的 description、argumentHint 和 help 文本补 `xhigh`（`EFFORT_LEVELS` 本就含它）。
- `/statusline` 的 description 删「对齐 CC」。
- `config.ts` JSDoc 与 `settings/types.ts` 分组注释：删掉进入 `ref/settings.md` 的「对齐 claude-code / 对标 CC / CC 客户端无此开关」，只写能力；`permissionMode` 的「支持 6 种模式」改为指向 `VALID_PERMISSION_MODES`。
- 三个 ref 页页首 HTML 注释里的旧路径 `src/cli.ts`、`src/help.ts` 改成 `packages/cli/src/...`。这些注释在 AUTO-GEN 标记之外，生成器保留不动，所以直接改页面。

## 放弃了什么（以及为什么不选）

- 手改 `website/ref/` 的 AUTO-GEN 区：下次生成就会被覆盖，pre-commit `--check` 也会拦。
- 把 `permissionMode` 改成可自省的 `z.enum`，以及生成器的内部编号清洗：这是 B34 的范围，要动生成器和 Zod 类型，风险面不同。本次只把文案改对，类型列仍是 `string`。
- `SID_CODE_TRACE` 支持 `0/false` 关闭：清单 D26 ① 已按「只认 1/true 强制启用」的现状改过帮助文本。要改的是行为不是文案，不在本次范围。

## 拿什么证明它生效了

- `bun run docs:gen-reference --check`：「参考页与源码一致，CLI 双源对账通过」。
- `grep -n "对齐 CC\|对齐 claude-code\|对标\|CC 客户端" website/ref/*.md website/public/llms.txt` 命中 0 行。
- `ref/cli.md` 中 `-y`、`--permission-mode`、`--provider`、`mcp` 四行，以及 `ref/env.md` 的 `SID_CODE_EFFORT_LEVEL` 行，都已显示新文案；env 页计数为 122。
- `bun run affected-tests:run`：2483 pass / 0 fail；`make build` 自检通过，无 `will always be undefined`；`format:check` 与 `lint` 都绿。
