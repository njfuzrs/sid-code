# 触发率窗口 A 与 B 必须共用

## 决定了什么

`policy-trigger-rate.ts` 的 `--limit N` 现在切 **A 和 B 同一时间窗**：最近 N 个会话 `session.traj` mtime 的 min..max，再加减 10 分钟 pad（启动探针可能早于 traj 最终 mtime）。`--all` 才扫全文件，JSON `window.all=true`，那种数不能进北极星。

保留字段 `denies_by_rule` / `decisions_same_tools` / `rate_a` / `window`。`window` 补 `from` / `to` / `appliedTo: "both"` / `all` / `rowsInWindow` / `probe_denies`。`source=policy-probe` 的行不计入 A，避免探针把触发率刷成 100%。

无 timestamp 的 audit 行进不了 `--limit` 窗。`--limit` 但本机没有会话时 A 不得退回全文件（空窗比假曲线更诚实）。

## 放弃了什么（以及为什么不选）

- **只改人读文案、JSON 仍用全文件分母**：05 已引用字段名；撒谎的是分母，不是标签。
- **另起一套 JSON**：旧字段继续撒谎，下游会继续引用。
- **按「最近 N 行 audit」切**：audit 是跨会话追加文件，行数 ≠ 任务。契约写的是相关任务，应对齐会话时间包络。
- **无会话时 A 退回全文件**：这正是修前 `--limit` 只切 B 的形态，单测若只种 audit 不种会话会把洞锁回去。
- **和 L1 停用续命合成一个 PR**：关注点不同，回滚 L2 不该带走停用修复。

## 拿什么证明它生效了

```
bun test ./tests/scripts/policy-trigger-rate.test.ts
# 11 pass / 0 fail。修前必红：旧 2026-09-19 Read(.env) deny + 新 09-22 bash deny，
# --limit 1 只覆盖新段 → denies_by_rule===1，分母不含旧段 bash。

bun scripts/policy-trigger-rate.ts --limit 20 --json
# 修前（05 记录）：denies_by_rule=3 / decisions_same_tools=3199（含 09-19 .env）
# 修后：denies_by_rule=2 / decisions_same_tools=201
#   from=2026-09-20T12:22:19.546Z to=2026-09-22T10:20:11.986Z appliedTo=both all=false
# 2 = 正向 07:44 bash curl + 反向误伤 08:01；.env 不在窗。
```
