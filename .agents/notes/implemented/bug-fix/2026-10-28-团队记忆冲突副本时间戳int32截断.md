# 团队记忆冲突副本时间戳不再按 int32 截断

## 决定了什么

`packages/core/src/memory/team/sync.ts` 生成冲突副本名时用 `Math.max(mtimeMs) | 0` 取整。
毫秒时间戳远超 int32，`| 0` 后约每 24.8 天在正负之间翻一次；2026-10-28 起落在负区间，
副本名变成 `k.conflict--2146557852.md`，`store.ts` 索引侧 `\.conflict-\d+\.md$` 失配，
「当前生效版本」被写成副本自己。现象是 PR #454–#457 全部 CI 红在同两条用例
（`sync.test.ts` 缺陷 8 用例，以及以子进程跑 `memory/` 的落盘门禁连带变红），与各 PR 改动无关。

改为 `Math.trunc(...)`；索引侧正则放宽为 `\.conflict--?\d+\.md$`，兼容已经落盘的负数副本名。

## 放弃了什么（以及为什么不选）

- 只改测试正则接受负号：测试会绿，但副本名与索引解析仍错，等于把缺陷锁进断言。
- 改用 ISO 日期做副本后缀：改变已落盘文件命名契约，旧副本需迁移，收益只是可读性。
- 不兼容旧负数名：已在用户磁盘上的副本不会自己消失，索引会继续把副本当成生效版本。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/memory/team/sync.test.ts`：22 pass 0 fail。
- 新增两条用例用固定 mtime（不依赖跑测当天日期）钉住完整毫秒名与旧负数名解析；
  变异自证：把两处改回旧实现后 3 条变红（含原缺陷 8 用例），恢复后全绿。
- `bun test ./tests/build/no-real-trajectory-writes-runtime.test.ts`：3 pass。
- `bun run affected-tests:run` 357 pass；`make build`、`lint`、`format:check`、`typecheck:gate` 通过。
