# 成本口径失效与「幽灵流」白烧 —— 三缺陷修复（D1/D2/D3）

## 决定了什么

一次会话自报 $0.2234、官方账单 ¥7.23，差 **4.56 倍**。排查出三个**独立**缺陷，按
「消除 / 收敛 / 兜底」三档修，**顺序不可交换**：

**档 A（消除）· D2：计费入账收口到 provider 发生侧。** 新增 `llm/billing-sink.ts`。
根因是入账挂在**消费侧**而消费侧有 N 个入口：主循环走 `AfterModelRaw`、18 条 side-call
走 `recordSideCall`、fork **什么都没有** → 实测 39 次建连只有 17 次进账，**22 次真实计费
请求完全未入账**（占该会话账单 31%）。收口点选在三条协议路径发 `StreamPhase(completed)`
的同一处（`openai.ts` ×2 + `anthropic.ts` ×1），挂 `finally` 而不是 `[DONE]` 分支 ——
厂商按收到的 prompt 计费，超时/中断/提前 break 那几种出口恰恰是白烧最集中的地方。
去重键是**单次 fetch**（`fetchId`）而不是单轮：主循环的 usage 跨 attempt 累加，轮粒度会漏。

**档 A · D2 的归因层：请求级身份走 ALS。** 新增 `llm/request-context.ts`，在
`streamWithResilience`（所有非主循环路径的唯一咽喉）包一次 `streamInRequestContext`，
9 条调用链全部自动带上 `{turnIndex, agentId, callerLabel}`。替代的是
`sse-chunk-dumper.ts` 那个只有主循环写的模块级全局量 —— 它让 fork 的 7 个流全落在
主循环 `index=17` 上、attempt 涨到 8，**在轨迹里长得就是「一个请求重试了 8 次」**。

**档 A · D1：`ModelPricing` 补三个维度。** 币种（`currency`+`fxToUSD`）/ 时段
（`peakWindows`+`offPeakMultiplier`）/ as-of（`asOf`+`source`）。DeepSeek 官方定价是
**人民币**且 2026-08-16 起分峰谷（空闲价恰为高峰一半），旧表四个裸数字**表达不出来**，
于是「汇率漂移」与「厂商涨价」长得一模一样、过期不可检测（潜伏 5 天）。
时段判定收在 `priceTierAt` 一处，`effectivePricing` 调它而不自己再写一遍 ——
两份实现会漂移成「账本说 offpeak、却按 peak 收钱」。配套把高峰占比落进账本
（`peakRatio`），因为分时段一旦生效**成本就不再可复现**（重算用的是重算时刻的时段）。

**档 B（收敛）· D3：end_turn 后台任务单飞闸门。** 新增 `agent/background-task-gate.ts`。
`end_turn` 后系统又跑 44 秒、发 7 次十万 token 请求（fork 继承主对话全历史），
用户为一个**已经答完**的任务多付约 ¥2.3（占账单 32%）。语义是**串行 + 丢弃**而非排队 ——
排队只会把并发换成「攒一串请求一次性烧掉」。同时删掉工具轮那处 `updateSessionMemory`
触发（§5.7），它与主循环下一轮请求并发。

**档 C（兜底）· 归因修正与对账。** `digest.ts` 按 `agent_id`/`caller` 把白建连接拆成
「真·重试」与「其它调用链」两类成因（此前把 side-call 流全算成 `retryWastedTokens`，
**归因指向了错的子系统**）；新增 `scripts/pricing-reconcile.ts` 拿官方账单比账本
（能同时抓单价错、幽灵流漏采、影子调用漏计**三类**成因，而定期同步只能抓第一类），
带 `--check-asof` 的陈旧提示。

## 放弃了什么（以及为什么不选）

**给 `forked-agent.ts` 补一次 `recordSideCall`（第一版方案，已否决）。** 它修的是
**这一个实例**而不是**这一类缺陷**：下一条新增调用链照样会漏，且照样没有东西会报红。
判据升级为「必须让『新增一条调用链却漏记账』在结构上不可能，而不是让它可被检测」——
一个需要作者记得做某件事才成立的机制，等价于没有这个机制。`recordSideCall` 有 18 个
手写调用点，意味着这个机制已经被依赖了 18 次，下一次失效只是时间问题。

**关掉 fork（B4）。** 实测它不是空转：`.session_memory.md` 在会话窗口内产出 10,279 字节
结构化笔记，而 `auto-compact` 会**优先**用它替代压缩时的摘要 LLM 调用。关掉 = 省这一次的
¥1.0、亏掉后续每次压缩的摘要调用、并丢掉跨会话记忆 —— **净亏**。真正的缺陷不是
「fork 存在」，是它的调度方式与计价方式都错了。

**主循环 `finally` 里 await 两个 fork（B3）。** 把用户可感知的收尾延迟拉长 44s（实测），
拿「更快」换「更准的账」，净退步。

**fork 不继承全量历史（B2）。** 省得最多（成本几乎全在输入侧），但**会改变记忆提取质量**，
必须带 eval 证据。且它的性价比只有在档 A 落地、这笔钱第一次可见之后才能评估 —— 本轮不预判。

**只改单价数字。** 连兜底都不是：它连「下次涨价能被发现」都做不到。

**`asOf` 陈旧硬拦。** 会换来一个「每次都红然后被人卸掉」的 hook。核价必须人去官网看，
一个当下无法自助解决的门禁唯一的出路就是绕过它。所以退出码恒 0，只提示。

**追 hallucination rate。** coding agent 上没有可复算的 grounded 分母。

## 拿什么证明它生效了

**六道判据全部有自证测试，且逐个做了变异自证**（一个不能报红的门禁是假门禁）：

| 判据 | 测试 | 变异注入 → 结果 |
| --- | --- | --- |
| 1 恒等式 + §5.4 归因 | `trace/billing-identity-invariant.test.ts` | `agent_id` 判据退回改造前 → **3/6 fail** |
| 2 对账 fixture（两会话） | `trace/billing-reconcile-fixture.test.ts` | `ghostStreams` 改 0 → **2 fail**；只留一个会话 → **3 fail** |
| 3/6 发生侧收口 | `llm/billing-sink-structural.test.ts` | `recordBilledRequest` 直接 return → **5/9 fail** |
| 4 end_turn 无并发 | `agent/background-task-gate.test.ts` | 闸门永不拒绝 → **2/7 fail** |
| 5 attempt 唯一性 | `trace/billing-reconcile-fixture.test.ts` | 见判据 2 同文件 |
| D1 三维度 | `llm/pricing-dimensions.test.ts` | `effectivePricing` 不折算 → **7/16 fail**；`priceTierAt` 恒 peak → **7 fail**；`getPeakRatio` 分母 0 返回 0 → **1 fail** |
| 双记防线 | `llm/billing-self-reported-labels.test.ts` | 白名单漏一个 → **2 fail**；多一个不存在的 → **1 fail** |

**事故基线可复算**（不只活在 markdown 里）：从两个真实会话的 `events.jsonl` 提出 fixture，
方案里的数字**逐项对上** —— pro 会话 `HttpConnected=39 / AfterModelRaw=17 / 幽灵流 22`、
自报 `$0.22344`（¥7.23÷7.1 ÷ 它 = **4.56**）、`maxAttempt=8`、最忙 `index=17` 挤了 40 个 phase、
带 `agent_id` 的 StreamPhase **0 个**；flash 会话 `13/6/7`、记账 cache_read **392,320**。

**`--check-asof` 两个分支都实测会响**：一条 `asOf` 改 2025-01-01 → 报「598 天前」；
改 `2026-13-99` → 报「不是合法日期（手写错了）」；当前 90 条定价中 6 条带 asOf，全部在期内。

**双记风险是查出来的，不是推演的**：静态扫出 **6 条**链既自己 `recordSideCall` 又走漏斗
（recall / auto-compact / context-collapse / partial-compact / hook-runner / goal-evaluator）。
`app.ts` 原有注释引用了一个**根本不存在**的 `BILLING_SELF_REPORTED_LABELS`，即成本会翻倍 ——
现已实现该白名单 + `shouldChargeBilledRequest` 收口，并加静态扫描门禁防漂移。

**工程门禁**：`make build` exit=0（自检通过，无 `will always be undefined`）；
`bun run lint` / `lint:boundary` / `format:check` 全绿；`affected-tests:run`
**6031 pass**（`packages/cli/tests/cli/flag-e2e.test.ts` 有 1 条间歇失败，
已在**干净 main 的 worktree** 上以同一批次复现同一条失败（batch 6，`mcp list` 5001ms），
且该测试不 import 任何本次改动模块、剥离本次改动后仍失败 → 判定为存量 flake，非本次引入）。

## 如实标注的 trade-off 与残留

1. **成本数字会跳变一大截，那不是退步，是底座从错的换成对的。** 「更省」方向的主口径
   此前**低估 4.56 倍**，历史上所有基于它的「更省了多少」结论与版本间曲线都不可用。
   建议在 `northstar/` 快照里**显式断开**修复前后的成本曲线。
2. **缓存命中率的分母也是错的**（只统计 17 条记账流，而 fork 的流命中率极高）。
3. **主循环仍走旧入账路径**（`accounted: true` 只做恒等式核对）。一次把主循环也搬过来
   需要同一个 PR 内改完 `updateUsage`/`AfterModelRaw`/`cost-recompute`/账本四侧，
   中间态必然双记 —— 刻意分阶段。当前形态下恒等式已成立、新增调用链天然入账。
4. **闸门仍是「作者要把新钩子接到闸门上」的形态**。结构性消除是把 end_turn 后台任务
   改成统一任务队列（单一入口、串行、带预算），本轮未含 —— 写在
   `background-task-gate.ts` 文件头，避免下一个人误以为后台并发已根治。
5. **白名单是手写表**，漏加一个标签 → 那条链记两次钱。方向是**安全的**（高估可被对账
   发现，漏记是静默的），且有静态扫描门禁兜。
6. **fork 抢跑对 prompt cache 前缀的影响未分析**（轨迹里有 16 条 `prefix_break`），
   §5.7 之外的中间轮次并发、`/cost` 跨时段边界展示 —— 均为待办，不是结论。

对应北极星：主要服务**更省**（消灭 56% 漏采 + 停掉 44s 白烧 + 单价口径修对）与
**可观测**（归因从「重试白烧」纠正到具体调用链）。牺牲的是一点**更准** ——
删掉工具轮 Session Memory 增量触发后，长工具链会话在首个 `end_turn` 前压缩会回退
传统 LLM 摘要（既有降级路径，非新增故障）。
