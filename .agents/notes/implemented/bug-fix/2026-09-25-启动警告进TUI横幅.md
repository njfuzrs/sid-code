# 启动期 baseURL 覆盖提示进 TUI 横幅，不再打 stderr

## 决定了什么

per-model `base_url` 覆盖 env baseURL 的提示改记到 `config._validationDiagnostics.warnings`，由 TUI 启动横幅（`Notifications`）和 `--print` 的 stderr 诊断共同消费。

- `loadConfig` 在 `_validationDiagnostics` 整体赋值之后调 `recordBaseURLOverrideWarning`。赋值是整体替换，放前面会被盖掉。
- 不放进 `resolveCurrentModelConfig`：它是 `/model` 切换、会话恢复、引导完成的共同咽喉，运行时再调会把启动提示重复塞进一份不再刷新到 TUI 的列表。顺手删掉了它已经没人读的 `envBaseURL` 参数。
- 文案把两个 URL 和「怎么改」各自放一行。横幅按列硬切，长句会被从 `https://` 中间切开。
- `Notifications` 按行渲染：整段交给一个 `Text` 时，`\n` 后续行不经过左侧 3 列标记，续行顶格。

## 放弃了什么（以及为什么不选）

- **把 logger 初始化提前到 `loadConfig` 之前。** 不选。`initLogger` 的参数（debug 级别、日志文件、是否 fileOnly）来自 `loadConfig` 的结果，顺序反不过来。提前只会让日志配置读到默认值。
- **TUI 起来后回读启动期 stderr。** 不选。stderr 兜底是 `enabled=false` 实例的降级路径，回读它等于把一条降级通道变成数据通道，而且 alternate buffer 下主屏内容已经不在了。
- **继续 `getLogger().warn`，只是把 initLogger 提前到这条 warn 之前。** 不选。fileOnly 模式下 warn 进文件不进终端，用户还是看不到；非 fileOnly 又回到「打在 TUI 渲染之前、被清掉」。
- **在横幅里对 URL 做软换行。** 不选。`wrapAnsi` 是按列硬切，改它会影响所有文本。文案侧换行只解决这一个提示。

## 拿什么证明它生效了

`bun test ./packages/core/tests/config/config.test.ts ./packages/cli/tests/ui/components/startup-warning-banner.test.tsx`

```
18 pass
0 fail
46 expect() calls
Ran 18 tests across 2 files. [109.00ms]
```

配置测试拦截 `process.stderr.write`，断言覆盖发生时诊断里有一条 `baseURL`、stderr 不含「被模型」，env 与模型值相同时诊断为空。横幅测试用 `loadConfig` 的真实文案渲染，断言两个 URL 各自落在同一行内（不是 `https` 与 `://` 分成两截），并且含「请删除该模型的 base_url」和「按任意键关闭」。

80 列下的实际渲染：

```
⚠  环境变量 baseURL 被模型「my-model」的 base_url 覆盖
   环境变量：https://env.example/v1
   实际使用：https://model.example/v1
   优先级：per-model base_url > env(SID_CODE_LLM_BASE_URL/OPENAI_BASE_URL)。
   如需 env 生效，请删除该模型的 base_url 配置或直接改模型配置。
按任意键关闭
```
