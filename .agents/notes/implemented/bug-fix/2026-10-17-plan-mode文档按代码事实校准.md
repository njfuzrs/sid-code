# 官网 Plan Mode 页（plan-mode.md）按代码事实校准——修正 5 处错误断言与 7 处失准表述

## 决定了什么

对 `website/use/plan-mode.md`（Plan Mode 与 Todo 页）做逐条代码比对后，修正 12 处与当前代码不符的内容。**只改文档，不改代码**：

1. **Todo 状态数错误（最严重）**：原文写「三个状态 pending / in_progress / completed」，实际是**四态**，`blocked` 于 2026-10-06 新增（`todo-write.ts:23` schema enum、`:49` 类型、`:53` `TODO_STATUSES` 三处一致）。已补第四态并说明其语义（卡在需要用户动手的外部条件上）。
2. **状态字形全错**：原文 `⬜ / ⏳ / ✅`。TUI 面板实际是 `○ / ◐ / ● / ◌`（`packages/cli/src/ui/constants/figures.ts:93-100`）；回给模型的文本版才是 `⬜ / 🔄 / ✅ / ⏸`（`todo-write.ts:56-63`）。`⏳` 这个字形在代码里不存在。已改为面板字形并单独标注文本版。
3. **「能跑只读命令」不成立**：原文表格「能」列写「跑只读命令」。实际 `checkPlanMode` 对 bash 整类拒绝（`checker.ts:2190-2195`），`READ_ONLY_TOOLS`（`:235-241`）不含 bash，判据不看命令内容是否只读。已改为如实描述 + 标注沙箱自动放行这一唯一例外（Step 7 早于 Step 9）。
4. **`tryFastPathEval` 条件错误**：原文说快速路径含「报告型任务已交付」。实际 fast-path 只有测试全绿/构建成功两条（`evaluator.ts:189-191`）；报告型已拆为 `tryReportFallbackEval`（`:155-178`），**只在评估器调用失败后**兜底（`:232-245`）。已改正并说明为什么移出（`:138-142` 注释记录了「实干型目标 + 720 字废话」被误判的实测）。
5. **`/clear` 落 `__CLEARED__` 哨兵不成立**：`persistGoalState(clearMarker=true)` 分支全仓零调用方，`/clear` 只做 `this.goalState = null`（`app.ts:2877`）。已改为如实描述「开新会话 → 目标随之清空」。代码侧接线问题已登记到 docs-research bugfixes todo。
6. `/plan` 的真实行为是 `submit_prompt` 让模型调 `enter_plan_mode`（`builtins.ts:1293-1298`），且有未文档化的 `exit`/`quit`/`status` 子命令（`:1277-1291`）。已补。
7. 计划文件命名补三个细节：主题可省略（`plan/state.ts:499`）、同分钟冲突加 `-2/-3`（`:502-505`）、项目名取 git root basename（`plan/slug.ts:97-110`）。
8. 拒绝计划**连续 5 次强制退出**（`state.ts:65,176-187`）原文未提，已补。
9. 退出途径原文写「只能走工具或斜杠命令」过于绝对：审批框取消、reject 超限、企业策略改模式都会退出；`exit_plan_mode` 在非 planning 态还是幂等成功（`exit-plan-mode.ts:71-90`）。已补两点说明。
10. 评估流程漏了「前 2 轮跳过评估」（`goal-gate.ts:204-210`、`goal/config.ts:42` `minTurnsBeforeEval: 2`）——这是用户最容易感知的一步，已补为第 4 步。
11. `reminderInterval: 4` 的位置标错（实际在 `goal/config.ts:39`，`goal/reminder.ts` 只有回注逻辑）；状态栏 paused 文案实际是 `⏸ 目标已暂停 N/M 轮`（`useStatusLineData.ts:336`）；`plan_fidelity` 按计划文件聚合取末条快照。均已改。
12. plan 模式的子代理限制补边界：`subType` 为空时放行（`checker.ts:2167`），但子代理内部仍受 plan 权限约束（`agent/tool.ts:542-556` 共享 checker）；`plan`/`verify` 虽是只读类型也不在放行名单。工具名更正为 `todo_write`（`TodoWrite` 是类名）。

## 放弃了什么（以及为什么不选）

- **不在本 PR 里修代码**：`__CLEARED__` 哨兵接线问题按用户要求只登记不修，写在 `docs-research/sid-code/bugfixes/todo/20261017-plan-mode文档核查发现的代码缺陷-clear目标哨兵未接线.md`（含方案 A 删死代码 / 方案 B 接线两种取舍）。混进本 PR 会让「纯文档纠偏」的 review 边界变糊。
- **不把 4 项「看似缺陷实为设计」写进缺陷文档的缺陷清单**，而是作为附录记录：plan 模式 bash 全拒、报告型不在 fast-path、拒绝 5 次强制退出、`subType` 空放行——读注释后确认都是刻意设计，写进缺陷清单会让下一个人重复论证要不要改。
- **不删「能/不能」表格改为纯文字**：表格是用户最快扫到能力边界的形态，问题只在内容错了，不在形态。改内容、加两条边界说明即可。
- **不承诺「未来会支持只读 bash」**：没有任何代码迹象表明要放宽，写这种前瞻等于制造新的文档漂移。
