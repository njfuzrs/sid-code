# 后台提取代理写 feedback 必须带用户原话，且不许把自身操作步骤写成经验

## 决定了什么

修 `20261113-记忆提取把agent行为固化成经验` 的 P0-1 + P0-2（方案 PR-1），三处：

1. **提示词（P0-1）**：`memory/extract/prompts.ts` 的「不应该保存」新增一条，显式禁止把
   「你自己本轮采取的操作步骤、流程编排、命令顺序、文件位置选择」写成经验，并点破
   「用户没反对 ≠ 用户要求」；「应该保存」四条统一以「用户」为主语，第一条补
   「必须是用户自己说出来的」限定。
2. **代码闸门（P0-2）**：`tool/memory.ts` 新增判据——`querySource === "memory-extract"`
   且 `type === "feedback"` 且正文没有 `「…」`（≥4 字）包住的用户原话 → 拒绝写入，
   错误文案给出改正指引，并记 `memory_guard{kind:"feedback_no_quote"}`。
3. **注入链路**：新增工具声明字段 `consumesQuerySource`（`tool/types.ts` 契约 +
   `internal-fields.ts` 剥离 + `bridge.ts` 透传 + `forked-agent.ts` 按需注入
   `_querySource`）。`save_memory` 自报该字段。

## 放弃了什么（以及为什么不选）

- **不用 `_agentId` / `via === "forked"` 判来源**：注入给工具的值写死为
  `"forked-agent"`，`writeVia()` 只能分辨到 `"forked"` 粒度，而那个粒度同时覆盖
  memory-extract / auto-dream / session-memory-update。按它拦会把后两个后台任务的
  feedback 写入一起打掉，失败形态是「写入静默减少」，没人会发现。
  （T-M8c / T-M8c2 就是这条的守卫。）
- **不做无差别注入**：`_querySource` 只给自报者。无差别注入会从 `StructuredOutput`
  严格 schema 校验、workflow 返回值、MCP server arguments 三条出口漏出去——这与
  2026-11-04 `_agentId` 事故同源。
- **不只在 prompt 里写规则**：prompt 单独存在时不可验收（模型可以不听），
  而代码闸门单独存在时每次被拒都浪费一轮。两边同一判据、同时落地。
- **不扩大到主模型路径**：主模型写 feedback 通常就是用户当轮明确要求的事，
  硬拦会给所有用户造成可感知的回归；`_querySource` 拿不到时一律放行是安全默认。
- **不用关键词黑名单判「是不是 agent 自述」**：「步骤」「做法」这类词在真正的用户
  原话里也会出现。用「有没有可引的原话」这个结构性判据，误判面小得多。

## 之前为什么没拦住

提示词里没有任何一句拦「把 agent 自己的操作」当经验，代码侧也没有任何以「来源」为
判据的闸门——`via` 只用于埋点口径，不参与准入判断。所以这条缺陷的失败形态是
「写入成功、遥测看不出异常」，只有人去翻记忆正文才发现。
