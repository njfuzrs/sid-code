# 空闲时关终端（SIGHUP）改记 exit_status=terminal_closed，不再记成 abort

## 决定了什么

`packages/cli/src/app.ts` 的信号处理在派发 SessionEnd 前先取样「当前是否有轮次在跑」
（`this.busy` 或未 abort 的 `abortController`，必须在自己调 `abort()` 之前取样），
经纯函数 `sessionEndReasonForSignal` 决定 reason：

- 空闲 + SIGHUP → `terminal_closed`（新增到 `SessionEndInput.reason`）；
- 忙 + SIGHUP、以及 SIGINT / SIGTERM 无论忙闲 → 仍是 `abort`。

collector 对非 exit/other 的 reason 原样落 exit_status；`terminal_closed` 不在
collector / digest 的 abnormal 名单里，所以不再计入中断。

现场数据（本地 205 个会话）：abort 126 个，其中 SIGHUP 125、SIGTERM 2；
有对话的 82 个 abort 里 81 个收到信号时上一轮已 end_turn（空闲中位 4.7 分钟）。
即后台看到的「几乎全是 abort」主要是关终端窗口被误归类。

## 放弃了什么（以及为什么不选）

- **空闲 SIGHUP 改走 `exit` 路径、按 stop_reason 推断成 end_turn**：曲线最好看，
  但抹掉了「会话是被关窗口结束的」这条事实，且 `exit` 会触发
  `finalizeGuardrailSession` 把护栏回填成 confirmed_true_positive——关窗口不是
  用户对护栏结果的确认，会污染误报口径。
- **SIGINT 空闲时也降级**：Ctrl-C 是用户主动发的终止，与关窗口语义不同，保持 abort。
- **只在 digest 侧把 SIGHUP 的 abort 剔出 abnormal**：轨迹里没有结构化的信号字段
  （只在 warn.log 文本里），消费侧只能靠裸子串反推，属于「归因与真实信号脱节」。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/session-end-reason-for-signal.test.ts`：空闲 SIGHUP →
  terminal_closed；忙时 SIGHUP → abort（反向自证）；SIGINT/SIGTERM 恒 abort。
- `packages/core/tests/trace/collector.test.ts` 新增用例：terminal_closed 原样落进
  `session.traj` 的 `metadata.exit_status`。
- `bun run affected-tests:run`：3585 pass / 0 fail；`make build` 通过、无 undefined 警告；
  `typecheck:gate` 66/66 无新增。
- 未做：真 pty 关窗口的端到端复现。合入后以新会话的 exit_status 分布验收——
  预期 abort 占比从 ~61% 降到个位数，terminal_closed 接走大头。
- 已上传的历史轨迹不会被改写；后台 `stats_service.py` 的成功率只认 end_turn，
  terminal_closed 仍算非成功，这一点是否调整留给后端决定。
