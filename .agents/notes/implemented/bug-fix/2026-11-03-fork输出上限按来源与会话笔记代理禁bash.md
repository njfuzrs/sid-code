# fork 输出上限按任务类型取值，会话笔记代理禁 bash 且入参进轨迹

## 决定了什么

三处改动，都落在「后台 fork 代理」这一层（会话 `20261103-114056-3b4f9ca7` 复盘 C1 / C2）：

1. **输出上限按 `querySource` 取值**（`agent/forked-agent.ts`）：
   `session-memory-update` 与 `memory-extract` → 8192，其余 fork 保持 2048。
   常量从 `FORK_MAX_TOKENS` 改成 `FORK_MAX_TOKENS_BY_SOURCE` + `forkMaxTokensFor()`，
   截断提示里的 `max_tokens=` 数字也改用实际值（原先是硬编码常量，改上限后会报错数）。
2. **会话笔记代理不给 bash**（`memory/extract/permissions.ts`）：
   `createSessionMemoryPermissions` 的 bash 分支从「只读命令放行」改为一律 `tool_not_allowed`。
   同时 `session-memory/prompts.ts` 的提示词把目标文件**绝对路径写在第一行**，并明说
   「不要编辑其它文件、不要运行 bash」。`buildSessionMemoryUpdatePrompt` 因此多一个必填参数。
3. **forked 路径的工具入参进轨迹**（`tool/input-summary.ts` + `trace/collector.ts` +
   `permission/decision-telemetry.ts` + `analytics/events.ts` + `agent/forked-agent.ts`）：
   摘要补到 `PermissionDecision` 事件的 `input_summary`，allow / deny 都带。

## 放弃了什么（以及为什么不选）

- **全局把 fork 上限提到 8192**：其他 fork（`/btw`、分类、摘要）输出本来就短，
  提高上限没有收益，失控时反而浪费更多。按任务类型给值，新增任务默认仍拿 2048。
- **从 fork 可见工具里拿掉 bash**（方案文档原话是「同时从 fork 可见工具里拿掉」）：
  做不到，而且不该做。`buildToolDefinitions` 刻意返回注册表**全量**定义（`forked-agent.ts`
  顶部有 ⛔ 注释）：fork 的请求是「主对话完整前缀 + 追加提示」，tools 段一变整条
  prompt cache 前缀全 miss，而 messages 段是数万 token。省下几 KB schema 换来每次 fork
  全价重付整段历史。所以只做「权限层拒绝 + 提示词写明」，不裁剪可见工具。
- **给 forked 路径补一条 `PreToolUse` 事件**（方案文档原话）：核实后这条路径**根本不写**
  `PreToolUse` —— forked 刻意不 fire 用户 hook（避免内部 side-call 刷屏），
  `trace/digest.ts` 里也明写「fork 的工具不进主 traj、也不进 PreToolUse，唯一留痕是
  `PermissionDecision.execution_context=forked`」。硬补一条 PreToolUse 会让轨迹里出现
  没有配对 `PostToolUse` 的孤立事件，并污染主循环的「用了哪些工具」统计
  （`metadata.tools_used`、PreToolUse 计数）。所以把摘要补在**已存在的唯一载体**
  `PermissionDecision` 上，达成文档要的目的（被拒命令 / edit 路径可复盘），不新增事件类型。
- **让 `logPermissionDeny` 把摘要塞进遥测**：不行。`analytics/events.ts` 顶部三条硬约束
  要求「路径只出扩展名」，摘要含路径与命令原文。摘要只透传给 `recordPermissionDecision`
  进本地轨迹，`emit` payload 一个字段都不加；上传时照旧由
  `LOCAL_ONLY_EVENT_DATA_FIELDS` 的 `input_summary` 剥掉。

## 拿什么证明它生效了

- 相关四个测试文件全绿（84 pass / 0 fail）：`tests/agent/forked-agent.test.ts`、
  `tests/trace/permission-forked-deny-kind.test.ts`、`tests/memory/sc07-memory-p0-p1.test.ts`、
  `tests/session-memory/half-wired-p1.test.ts`。
- **变异自证**（逐项改坏 → 对应断言变红 → 恢复）：
  - 把 `FORK_MAX_TOKENS_BY_SOURCE` 的两个 8192 改回 2048 → C1 的两条断言红；
  - 把 `summarizeToolInput` 改成恒返回 `undefined` → C2-3 的两条断言红；
  - 把 session-memory 的 bash 分支改回 `allow` → sc07 一条 + denyKind 一条 + C2-3 bash 一条红；
  - 把提示词里的 `${targetFile}` 删掉 → 「写死绝对路径」那条红。
  恢复后 `grep -rn MUTATION packages/core/src/` 无残留，再跑一遍 84 pass。
- 一个实测副作用值得记下来：测试里的 mock provider 如果只 yield `message_delta`
  （没有 content block），`streamWithResilience` 会一直等不到结束，5s 超时。
  新写的 capturing provider 已补完整 content block 序列，注释里写明了原因。
