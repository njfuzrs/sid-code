# 未声明的工具参数不再静默剥离，harness 附言挪出不可信包裹

## 决定了什么

**T2（D1）：模型传了 schema 没声明的顶层键时，不再「成功但静默丢参数」，改成「照常执行 + 结果开头一行提示 + 一条遥测事件」。**

- `input-validator.ts` 新增纯函数 `findUnknownTopLevelKeys(schema, input)`：只处理**顶层 `z.object` 且未知键会被剥离**的 schema，返回模型传了但没声明的键（`_` 开头的内部字段除外，那是 `stripInternalFields` 的职责）。
- `validateToolInput(tool, input, { modelKeys })` 返回 `ignoredKeys`：`modelKeys` 是模型**原始发出**的键（`block.input` 的键），用来把「模型写错参数名」与「hook 改参注入的字段」分开。hook 注入的未知键只发事件（`source: "hook"`），不进提示——模型根本没传过它。
- 新增事件 `ToolInputUnknownKeys { tool, keys, source, silenced }`：只记键名不记值。
- 「已知无影响键」名单 `IGNORABLE_UNKNOWN_KEYS`（登记在 `input-alias.ts` 的 `ALIASES` 旁边，每条带理由、不按模型名）：目前只有 `grep` 的 `-n`——sid 在 `output_mode=content` 时恒带 `--line-number`，丢了不改结果，提示反而会让模型以为结果里没有行号。名单里的键只进事件的 `silenced`。
- 三条执行路径都拼提示且拼在外部内容包裹**外面**：主循环 `query/tool-executor.ts`、子代理 `query/run-tool-use.ts`、fork 子代理 `agent/forked-agent.ts`。

**D11（与 T2 同一个拼接位置，一起做）：执行器把「工具产出」和「harness 附言」拆成两个变量。** 工具产出（含 PostToolUse 的整段替换）照旧进 `wrapExternalContent`；`unknownKeysNotice`、`hookModifiedNotice` 前置，`[Hook 附加上下文]`、`[Hook 反馈]`、编辑失败提醒、状态轮询提示后置，都在 `<external-content untrusted="true">` 之外。改之前 hook 写的话在 MCP / `ReadMcpResource` / `web_search` 结果里会被标成不可信内容，模型会当它不存在。

## 放弃了什么（以及为什么不选）

- **不把 schema 改成 `.strict()`**。那等于把 30 天 170 次「成功但丢参数」全变成硬失败，其中 105 次是会话里对结果毫无影响的 `-n`；也会让旧轨迹回放、用户 hook 注入额外字段的场景直接报错。
- **不改成报错**。`-n` 这类键报错会白花一轮往返，还会把 `is_error` 率抬成「实现写错了」的假信号（文档把「`grep` 的 `is_error` 率不该动」写成了验收判据）。提示的措辞对准「下一次别再带」，不是「这一次重来」。
- **不做嵌套未知键**（`todos[].activeForm` 这类）。嵌套形态有数组、联合、record 多种，一次做全的风险大于收益；别名层已经接住了已知的那一类，剩下的等 `ToolInputUnknownKeys` 的真实数据再决定。这一处边界写在这里，不是遗漏。
- **不对 `StructuredOutput` 和 MCP 工具做**：前者的 schema 由用户提供，未知键语义归用户；后者没有 `zodSchema`，走 `!schema` 早退。
- **不按模型名登记忽略键**。模型会换、能力会漂移，按模型名硬编码是本仓明令禁止的做法（用户 2026-07-06 定的规则）。名单只按「工具名 + 键名」+ 理由登记。
- **门禁探针键不用文档里的 `__probe_unknown__`**。它以下划线开头，会被「`_` 开头是内部字段」的规则正确排除，导致 41 个工具全部误报失败。改用 `zz_unknown_probe`。这是文档与实现之间的一个真实冲突，记在这里避免下一个人重踩。
- **子代理路径的 hook 附言仍留在包裹内**（`runPostToolHooks` 返回的字符串已经把附言拼进产出）。本次只修 T2 的提示落点与主循环的 D11；改 `runPostToolHooks` 要动返回结构与现有 hook 对齐测试，属于 D11 的剩余部分，不在 T2 的范围里。

## 拿什么证明它生效了

- **新增三个测试文件，85 条断言全绿**：
  - `packages/core/tests/tool/input-validator-unknown-keys.test.ts`（29 条）：顶层检出、passthrough/record/union/非对象/z.lazy 边界、`_` 开头排除、`hasOwn` 防原型链、modelKeys 区分 hook、`-n` 进 silenced、校验失败也发事件、事件只带键名。
  - `packages/core/tests/query/tool-executor-unknown-keys.test.ts`（10 条）：用会被包裹的 `web_search` 断言提示在 `<external-content>` 之前、`[Hook 附加上下文]` / `[Hook 反馈]` 在 `</external-content>` 之后、hook 改参告知在包裹之前、T2 提示与 D11 附言同时出现时顺序稳定；子代理出口同位置。
  - `tests/tool/unknown-keys-coverage.test.ts`（46 条）：从 `--dump-tool-meta` 取真实注册表 42 个工具，双向对账构造清单，逐个断言 `findUnknownTopLevelKeys(schema, { zz_unknown_probe: 1 })` 能检出探针键；豁免只有 `notebook_edit`（没有 `zodSchema`，T3 补完后删掉这条豁免）。
