# 五条主表命令的写形态改判非只读，主表死条目统一标注

## 决定了什么

`packages/core/src/tool/bash/read-only-validation.ts` 里，主表 `READ_ONLY_COMMANDS`
有 5 条命令「带写文件参数仍被判只读」——`isReadOnlyCommand` 的结果直接决定 plan 模式
与 deny-write 下是否免确认，等于零确认执行：

| 命令 | 修前漏判的形态 | 实际后果 |
| --- | --- | --- |
| `yq` | `yq -i '.a=1' f` | 原地写任意文件 |
| `tree` | `tree -o out.txt` | 写任意文件 |
| `file` | `file -C -m x` | 生成 `x.mgc` 落盘 |
| `date` | `date -s '2020-01-01'` | 改系统时钟 |
| `hostname` | `hostname evil` | 改主机名 |

修法是把 5 条加进 `CONDITIONAL_COMMANDS` 按参数判（与早已在表里的 `sed -i` / `sort -o`
完全同型），主表条目保留不删。同时做两件配套：

1. `CONDITIONAL_COMMANDS` 分支上方加机制注释——**命中本表即 `return false` 或 `continue`，
   主表同名条目永不生效**；`tee` 的真实安全性 100% 依赖那行 `() => false`，删它等于开一个
   「零确认写任意文件」的洞。主表里同样因为被覆盖而永不生效的 10 条（`git` / `npm` / `bun` /
   `sed` / `tee` + 本次 5 条）统一加行内标注，不再让人误以为改主表能改行为。
2. `packages/core/tests/tool/read-only-validation.test.ts` 的 `KNOWN_GAPS` 里 5 个
   `test.failing` 全部去掉，写形态并入 `WRITE_FORMS`，并新增 `D7_SAFE_FORMS` 成对断言
   「安全形态必须仍判只读」。

## 放弃了什么（以及为什么不选）

- **把 5 条从主表删掉、只在 `CONDITIONAL_COMMANDS` 里判**：看起来更「干净」，但主表条目是
  「这类命令可能只读」的旁证，删掉之后 `SAFE_FORMS` 的覆盖完整性断言失去依据；而且
  `tee` 的例子证明「主表有条目 + CONDITIONAL 覆盖」是本文件既有的表达方式，只删一部分
  会让下一个人分不清哪种才是惯例。
- **`tree` 按「能读文件内容就不算只读」收紧，只放行纯目录列举选项白名单**：
  这是实现过程中尝试过的版本，会让 `tree -L 2` / `tree --gitignore` 这类高频只读用法
  每次白弹一次确认。`--gitignore` 读 `.gitignore` 只用于过滤输出，不写盘、也不把内容
  回灌上下文，与 curl「请求发往任意主机 + 响应体进模型上下文」不是同一类风险。
  拿假想的安全伤更快，且量大到用户立刻能感知。
- **`date` 只按 `--set` / `-s` 判，不管位置参数**：macOS/BSD 的 `date 010100002020`
  不带任何选项就能改系统时钟，只判 `-s` 会留一个洞。
- **`date` 按「位置参数一律非只读」判、不跳过带值选项**：这是实现初稿，会把
  `date -d yesterday +%F` / `date -j -f %Y-%m-%d 2020-01-01 +%s` 判成要确认。
  最终按 `DATE_VALUE_OPTS`（`d`/`f`/`r`/`v`）跳过它们的值，并用 `-j`（BSD 只解析不设置）
  放行位置参数形态。
- **用 `hasShortOpt(args, "s")` 判 date 的写形态**：`date -Iseconds` 的 `seconds` 里
  含字母 s，会命中同一个判据、把 ISO 输出格式误判成改时钟。改成逐字母扫短选项段，
  遇 `I` 就 break（剩余部分是 timespec）。
- **一刀切 `return false`**：能让写形态全绿，但会把 5 条高频只读命令全部降级成要确认。

## 拿什么证明它生效了

```text
SID_CONFIG_DIR=$(mktemp -d) bun test \
  packages/core/tests/tool/read-only-validation.test.ts \
  packages/core/tests/permission/discard-redirect-target.test.ts \
  packages/core/tests/memory/readonly-prefix-subset-reconcile.test.ts
  → 157 pass / 0 fail / 192 expect

SID_CONFIG_DIR=$(mktemp -d) bun test packages/core/tests/permission/ \
  packages/core/tests/tool/ packages/core/tests/memory/
  → 4120 pass / 0 fail / 30761 expect（221 files）
```

变异自证（每条都是「改坏 → 变红 → 恢复 → 绿」）：

```text
把 CONDITIONAL_COMMANDS.yq 改成 () => true
  → 3 fail：yq -i '.a=1' f / yq --inplace '.a=1' f / yq -ei '.a=1' f
  → 恢复后 157 pass

把 date 判据里 DATE_VALUE_OPTS 的跳过逻辑删掉
  → date -d yesterday +%F 变红（这条正是「过保守」的回归保护）
  → 恢复后绿

把 tree 判据改回白名单收紧版本
  → tree -L 1 / tree --gitignore 变红
  → 恢复后绿
```

真实命令核对（`isReadOnlyCommand` 直调）：

```text
yq -i '.a=1' f            → false（修前 true）
tree -o out.txt           → false（修前 true）
file -C -m x              → false（修前 true）
date -s '2020-01-01'      → false（修前 true）
date 010100002020         → false（修前 true）
hostname evil             → false（修前 true）
date -d yesterday +%F     → true
tree -L 1                 → true
file -m x f               → true
```
