# LSP 诊断新鲜度：客户端代际屏障 + 有界 flush 窗口 + 内容指纹漂移校验

## 决定了什么

修 `docs-research/.../20261105-LSP诊断新鲜度-推送不带version时判不了过时-设计方案.md` 里的问题：
typescript-language-server 5.x 的 `publishDiagnostics` 不带 `version`，原有的 version 闸门对它
**恒不生效**，编辑同步窗口又只覆盖到「didChange 发给 stdin」为止——服务器在那之后仍会推旧内容
的诊断，客户端分不出来。

四处改动：

1. **客户端代际 + 屏障**（`lsp/barrier.ts` 新增，`server-manager.ts` 接入）。
   `changeFile` 发完 didChange 后紧跟一个 `textDocument/documentSymbol` 请求作屏障，**不 await**。
   屏障响应到达 = 服务器已按序处理完本次变更。编辑器侧把 `syncing` 窗口从「到 didChange 发出」
   延长到「到屏障越过 + flush」，这段内到达的推送判 `stale_syncing` 丢弃。
   `DiagnosticRegistry` 用 `syncSeq` 当代际号；旧代际的屏障回调到得晚时被 `passBarrier` 的代际
   校验拒绝，不能结束新代际的窗口。屏障失败/该服务器被关闭屏障时降级为 `unverified` 并**照常注入**
   （退化为修复前行为，比「永远不出诊断」好）。

2. **有界 flush 窗口（本项与设计文档不同，是实测推翻假设后加的）**。
   设计文档 §3.1 断言「屏障之后到达的推送全部是新内容，7 次探针无反例」。
   本次 30 次采样里出现了**反例**：旧内容诊断在屏障响应之后 **+5ms / +48ms** 才到达。
   根因在 tsls 源码：`FileDiagnostics` 用 `pDebounce(..., 50)` 合并推送（cli.mjs:19857），
   定时器可能在 didChange 之前就已排队、到期才推，**它不看 didChange**——所以屏障响应
   不能证明「基于旧内容的推送都已发出」。同一批采样里新内容推送最早在屏障后 172ms 到达，
   故取 **100ms flush**（落在 48 与 172 之间），由 `BarrierGate` 在屏障响应后补等。
   两个数字都写进了 `barrier.ts` 的文件头注释，换服务器/版本需重测。

3. **didOpen 不挂屏障（e2e 暴露的真实缺陷）**。
   最初对所有 `changeFile` 都挂屏障，e2e E3 实测失败：`didOpen` 后 3 秒内 `pending` 始终为空，
   `hasPublishedFor` 恒 false。原因是文件刚打开时 tsserver 还在加载，屏障请求排队很久，窗口
   被拖长，首次推送被全部丢掉——而 tsls 只在内容变化时才重推，于是**这个文件永远拿不到诊断**
   （比过时更糟）。修法：屏障只在 didChange 时挂。语义上也成立——didOpen 没有「旧代际」，
   服务器侧内容就是刚发过去的内容。

4. **内容指纹漂移校验（S3：bash 的 sed -i / formatter / git checkout 等带外修改）**。
   `server-manager` 在 didChange/didOpen 时记 `sha1(content)` + 当时的 `mtimeMs/size`。
   `collectDiagnosticText` 注入前只对**候选文件**（`pendingUrisFor(owner)`，通常 1–3 个）做两级校验：
   mtime/size 未变直接放行（**不读盘**），变了才读盘算 sha1 比对。判漂移的文件本轮不注入、
   清掉其 pending，并顺手触发一次 `syncFileToLSP`（把带外修改变成「晚一轮的正确诊断」）。
   `collectDiagnosticText` 因此改成 **async**，两处调用点 `await`。

5. **新鲜度判定落轨迹 + 注入标注**。`PublishCounters` 增 `freshByVersion / freshByBarrier /
   unverified / baseline`，`CollectStats` 增 `driftedFiles / injectedFirstPublish`，
   `LspDiagnostics` 事件带全部新字段，digest 输出行改成
   `推送: N 次 新鲜度: version x / 屏障 y / 未验证 z / 基线 w 丢弃过时: … 漂移 d`。
   `formatDiagnostics` 只在 `fresh_by_version` / `fresh_by_barrier` 时给文件标题加
   `（基于你最近一次编辑后的内容）`——`unverified` 与 `baseline` 不标注（不说谎）。

## 放弃了什么（以及为什么不选）

- **只上屏障、不加 flush 窗口**（= 设计文档 §3.1 原方案）：30 次采样里 3 次旧推送在屏障之后
  才到（+5ms / +48ms），判据会漏。这不是理论风险，是实测。
- **给 didOpen 也挂屏障**：e2e E3 实测会让该文件**永远拿不到诊断**（首次推送被吞、服务器不重推）。
- **编辑后 await 等诊断再返回工具结果**：实测 tsls 新结果在 didChange 后 300–1700ms 才到，
  每次 edit 加几百毫秒，长任务数百次编辑不可接受。且干净文件可能不推，要等到超时。
- **按时间戳判过时**（推送距 didChange < X ms 视为旧）：服务器延迟随文件大小/冷启动从几十 ms
  到秒级，任何固定阈值两头错。屏障是因果判据，时间只是它的补充窗口（且有实测上界）。
- **pull 诊断 `textDocument/diagnostic`**：tsls 5.1.3 无 `diagnosticProvider`（本次再核源码确认）。
- **解析 bash 命令猜改了哪些文件**：形态无穷（sed -i / formatter / 脚本 / git），漏报不可控；
  内容指纹是对**结果**校验，与命令形态无关。
- **每轮对全部已打开文件做漂移校验**：O(打开文件数) 次 stat，长会话能到上百个文件，
  换来的只是对「不注入的文件」的判定。只校验候选文件。
- **监听文件系统（fs.watch）推 didChange**：macOS fsevents 合并/延迟、watch 句柄成本、
  与 edit 工具竞态；为低频的带外修改引入常驻机制不值。
- **改 `publishDiagnostics` 里的 version 字段 / 删掉 `publishes_with_version`**：改不了上游；
  且该字段对 tsls 恒 0 是真实信息，下游 digest 与测试在读它。

## 拿什么证明它生效了

**单测（`packages/core/tests/lsp/`，U1–U11 按设计方案 §5.1）**：`bun test ./packages/core/tests/lsp/`
→ **188 pass / 0 fail**（含 e2e 4 条）。

**变异自证**（CLAUDE.md 要求，脚本化逐条改坏 + 跑 + 从备份恢复）：

| 变异 | 预期 | 实测 |
| --- | --- | --- |
| `endEdit` 恢复成结束 syncing | U1 红 | 1 fail（U1） |
| `passBarrier` 不校验代际 | U3 红 | 1 fail（U3） |
| 屏障失败时不结束 syncing | U4 红 | 3 fail（U4×2、U6） |
| 去掉漂移校验 | U7 红 | 1 fail（U7 manifest） |
| 漂移校验去掉 mtime/size 快路径（永远读盘） | U8 红 | 1 fail（U8） |
| 标注对 unverified 也加 | U10 红 | 1 fail（U10） |

六条全部按预期变红；恢复后 `diff` 与备份逐字节一致、无 `MUTATION` 残留。

**真实服务器 e2e（`packages/core/tests/lsp/e2e/diagnostic-freshness.e2e.test.ts`，本机 tsls 5.1.3）**：

- **E1**（didChange 落在 syntax/semantic 推送之间）：多个 T 采样、命中即停，
  观察到 `stale_syncing > 0`（真的踩进 S1 窗口）且**未注入旧内容标记**。
- **E2**（编辑后等 2500ms）：注入新内容诊断、带「基于你最近一次编辑后的内容」标注、
  `fresh_by_barrier ≥ 1`。
- **E3**（编辑后 `writeFileSync` 带外改写）：`drifted_files=1`、本轮不注入旧内容；
  等重同步完成后下一轮注入新内容诊断。
- **E4**（小文件常规编辑，退步门禁）：正常注入。

E1 的窗口宽度是**实测**的（本机 tsls 5.1.3、6000 行文件、约 260–560ms）。CI 无 tsls 时
以 `console.error` 明确写出跳过原因并 skip，**不静默绿**。

**门禁**：`bun run affected-tests:run`（3089 tests / 3088 pass）、`make build` 通过、
`bun run lint` / `format:check` / `lint:boundary` / `lint:command-system` / `lint:legacy-tool` /
`typecheck:gate`（62 处存量、基线 64、**无新增**）/ `docs:gen-reference --check` 全绿。

`affected-tests:run` 里唯一失败是 `packages/core/tests/agent/isolated-subagent-cwd.test.ts`
的「未绑定 cwd 时不出现隔离提示」——三条举证：① 该测试不 import lsp（`grep -l "lsp\|LSP"` 无命中）；
② 在**父仓 main** 上单跑通过；③ 成因是当前 cwd 就在 worktree 内，`SubAgent` 注入了
【隔离环境提示】，而用例断言的是「未绑定 cwd 时不出现该提示」——worktree 环境固有，与本次改动无关。
