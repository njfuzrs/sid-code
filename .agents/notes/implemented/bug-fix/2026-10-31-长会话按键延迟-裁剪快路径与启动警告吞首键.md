# 长会话按键延迟：横向裁剪不裁时跳过 sliceColumns；启动警告不再吞首键

## 决定了什么

对应排查报告 `20261030-长会话输入框打字粘贴上屏延迟-排查报告.md` 的 #1 与 #5（原 PR1 + PR2，按用户要求合成一个 PR）。

1. **`packages/tui/src/output.ts` getScreen 横向裁剪快路径**：`from === 0 && to >= width` 时直接返回原行，不跑 `sliceColumns`。
   工具标题行（`ToolShared.tsx` 的 `<Box overflow="hidden" height={1}>`）每行都处在横向 clip 里但一列都不裁，
   长会话 blit replay 每帧要把上千行重新 tokenize 加逐字符 `stringWidth`，占 getScreen 一半以上。
2. **`packages/cli/src/ui/components/Notifications.tsx`**：「按任意键关闭」启动警告时，可插入字符
   （`key.insertable`：字母、空格、粘贴）关闭警告后 `return false`，继续传给 InputArea；非插入键（Esc、方向键、回车）
   照旧消费。原来一律 `return true`，有启动警告的会话首键 100% 丢失，违反 `ui/CLAUDE.md` L4-A「永不丢失用户输入」。

## 放弃了什么（以及为什么不选）

- **按报告拆成两个 PR**：报告里的理由是关注点和包都不同、分开回滚更干净。用户明确要求合成一个 PR，
  两处改动各自只有几行，回滚时手工 revert 单个文件即可，代价可接受。
- **快路径下沉到 `sliceColumns` 内部**（`start === 0 && end >= 行宽` 就返回）：`sliceColumns` 要先算行宽，
  而 getScreen 这里已经有 `caches.getStringWidth` 的缓存值。放在调用点不用重复计算，也不影响 `sliceColumns` 的其他调用方。
- **关闭警告的键一律放行**：回车会直接提交空输入或触发别的动作，Esc 会被下游当成中断。只放行可插入字符，
  就和「用户本来想打字」的意图对齐。
- **#2（视口之上的行复用缓冲）、#4（补全菜单浮层）**：不在本 PR 范围，见报告 PR3、PR4。

## 拿什么证明它生效了

- 端到端 A/B（`scripts/perf-keystroke-latency.ts`，会话 `20261020-110542-ce7ea52e`，120×40，n=80，
  隔离 `SID_CONFIG_DIR=/tmp/kl-home`，同一批交替跑两轮）：见下表，`base` 是只删掉快路径那一行后 `make build` 的二进制。

  | 轮次 | 臂 | p50 | p95 | p99 |
  |------|----|-----|-----|-----|
  | 1 | base | 47.4 | 57.8 | 79.1 |
  | 2 | fix | **16.7** | **35.2** | 53.5 |
  | 3 | base | 37.4 | 60.7 | 97.2 |
  | 4 | fix | **24.5** | **36.1** | 37.2 |

  两轮 fix 的 p50 比相邻 base 低 35–65%，p95 从约 58–61ms 降到约 36ms。报告给的通过线是 p50 ≤ 22、p95 ≤ 36：
  第 2 轮达标，第 4 轮 p50 24.5、p95 36.1 **略超**。base 臂两轮之间也漂了 10ms（47.4 → 37.4），与报告记录的跨批次
  38–54ms 浮动一致，n=80 两轮不足以区分「略超线」和噪声。结论只到「明显改善、与报告 A/B（46→19）同量级」，
  不声称达到通过线。剩下的线性成本是 #2（PR3）的范围。

- 字节等价：新测试 `packages/tui/tests/output-clip.test.ts` 断言「clip 不裁时与无 clip 的屏幕逐字节相同（带 ANSI 样式）」，
  且左裁 / 右裁仍照旧裁。`packages/tui/tests/`、`packages/cli/tests/render-port/`（含 term-bench，不带 `UPDATE_TERM_BENCH`）全绿。
- 变异自证（快路径）：把条件改成 `if (true) return line;`，「左边界压进文本时照旧裁掉左侧」变红（2 pass / 1 fail）。
  右裁那条不红，因为右边界另有 Screen 的 `maxX` 兜底，这是预期的。
- 变异自证（首键）：`packages/cli/tests/ui/components/startup-warning-banner.test.tsx` 新增两条，经真实 `KeypressProvider`
  解析链驱动。把 `return !key.insertable` 改回 `return true`，「可插入字符关闭警告后继续传给输入框」变红（3 pass / 1 fail）。
- 测量踩坑：隔离目录只带 `trusted-extensions.json` 不够，项目 `.mcp.json` 的审批框会挡住全部输入（80 键全部 5000ms 超时）。
  还要带上 `state/mcp-approvals.json`。
