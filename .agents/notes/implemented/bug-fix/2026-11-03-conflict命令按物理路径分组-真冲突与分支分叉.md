# /conflict 命令按物理路径分组：真冲突与分支分叉不再混为一谈

## 决定了什么

`packages/cli/src/command/commands/conflict/conflict.ts` 的展示层从「按逻辑键平铺」改为
**按物理路径分组**，改了三处行为：

1. **会话明细补实际物理路径**：当意图记录里的 `physicalPath` 与逻辑键（折叠后的主仓路径）
   不同时，额外输出一行 `└ 实际路径: …`。此前用户只能看到一个主仓路径，看不出这份意图
   实际落在哪个 worktree。
2. **冲突拆成两组**：
   - `⚠ 同文件并发（可能互相覆盖）`——同一份**物理文件**被 ≥2 会话写，保留原来的
     「关闭其他会话」建议；
   - `ⓘ 分支分叉（各改各的 worktree 副本，合并回主仓时才可能冲突）`——同一逻辑文件、
     物理路径互不相同，**不再**给「关闭其他会话」建议（关会话消除不了分叉，补救动作是合并）。
3. **冲突口径收紧到 edit/write**：与 `checkConflict` 的默认 `blockingOperations`
   同口径，两个会话都只是 read 同一文件时不再报冲突。

判据抽成导出纯函数 `groupIntentConflicts(intents)`，命令只负责渲染——分组口径可单测，
不必靠解析命令输出。

## 放弃了什么（以及为什么不选）

- **放弃「按逻辑键聚合 + 靠文案解释分叉」**：旧实现的问题是判据错了（把物理上互不相干的
  两份副本当成同一份文件），换文案治不了——用户看到「潜在冲突」和「关闭其他会话」时
  已经做出了错误决策。判据必须落到物理路径。
- **放弃「在命令里跑 `git rev-parse` / 读 `.git` 判断是否为 worktree」**：写入侧
  （`file-intent.ts` 的 `resolveIntentKey`）已经把 `physicalPath` 归一化好并落盘，
  展示层再探一次盘等于把同一份判定做两遍，还得处理「意图记录来自旧版本没有该字段」
  的三态。回退口径统一为 `intent.physicalPath ?? intent.path`，与
  `conflict-detector.ts` 一致。
- **放弃「在 UI 层再做一次 realpath 归一化」**：符号链接会在展示层制造第二套路径口径；
  realpath 是写入侧的一次性工作，读取侧只消费（与 `checkConflict` 不加 IO 的理由同源）。
- **放弃「把分叉也塞进 `⚠` 警告组」**：语义相反——一组是说「会互相覆盖」，另一组是说
  「不会互相覆盖」。共用一个组名必然要附加解释，而解释读不过标题。两组分开，标题即结论。
- **放弃「顺手把 `ConflictDialog.tsx` 的分叉文案补上」**：分叉在当前实现里根本不弹窗
  （`conflict-gate.ts` 直接放行 + 输出附说明），对话框只服务真冲突，加分支等于写死代码。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/command/conflict-cmd-physical-path.test.ts`，**12 pass / 0 fail**
  （纯函数 7 例 + 命令端到端 5 例：真冲突 / 分叉 / read 双读不报 / 单会话 / 实际路径展示）。
  端到端用 `SID_CONFIG_DIR` 重定向 tmpdir，直接落意图 JSON 造出「同逻辑键、不同物理路径」
  的记录（tmpdir 里造不出真实 worktree，且真建 git worktree 对一条展示命令的测试过重）。
- **变异自证 3/3 全被抓**（每次改坏一个变量、复跑、恢复后确认 12 pass）：
  ① 分组退回按逻辑键（`physicalPath: logicalPath`）→ 3 fail；
  ② 去掉 read 过滤（`if (false) continue`）→ 3 fail；
  ③ 删掉「实际路径」输出行 → 1 fail。
- `bun run affected-tests:run`（判定 selective，cli 包全量）→ **2701 pass / 9 skip / 0 fail**。
- `make build` exit 0（产物自检 5 项全绿）；`bun run lint` / `format:check` /
  `lint:boundary` / `lint:command-system` / `lint:legacy-tool` / `typecheck:gate` 全绿；
  `docs:gen-reference --check` 通过（改了 `cli/src/command/`，生成物无漂移）。
- worktree 内先删掉指向主仓的 `node_modules` 软链并 `bun install`：否则
  `import.meta.resolve("@sid-code/cli/…")` 解析到主仓 checkout，测试会测到旧代码
  （假绿）。复验解析结果指向 worktree 内的 `packages/cli` 后才开始改。
