# 修 @anthropic-ai/sdk 两个 moderate 告警，刻意不搭 #105 那 12 个 major 的车

## 决定了什么

把根包 `@anthropic-ai/sdk` 从 `^0.79.0` 升到 `^0.120.0`，子包（eval-framework）
从 `^0.117.1` 一并对齐到同一版本，解掉 2026-08-24 翻开 Dependabot 告警后立刻报出的
两个 moderate：

| 告警 | 影响区间 | 首个修复版 |
| --- | --- | --- |
| Memory Tool 默认文件权限不安全 | `>= 0.79.0, < 0.91.1` | 0.91.1 |
| Memory Tool 路径校验可越出沙箱到兄弟目录 | `>= 0.79.0, < 0.81.0` | 0.81.0 |

**两个告警的受影响面在本仓是零** —— 全仓 grep `memory_20` / `memoryTool` /
`betaTools` / `createMemoryTool` 零命中，我们只用 `messages.create` / `messages.stream`
与错误类型。所以这不是"正在被利用"的紧急修复，而是"把版本推出区间、让告警清零"。
**但仍然要修**：留着它意味着以后每次看告警列表都要重新做一次这个判断，
而下一个看的人未必会去 grep。

**顺带对齐了根与子包的版本**：此前根 0.79.0 / 子包 0.117.1 两个版本并存
（`bun.lock` 里有 `eval-framework/@anthropic-ai/sdk` 这条嵌套解析）。
现在单一解析到 0.120.0，`grep -o '"@anthropic-ai/sdk@[0-9.]*"' bun.lock | sort -u`
只剩一行。

## 放弃了什么（以及为什么不选）

**否决「合 #105 一次了事」**（Dependabot 的 `rest` 组，12 个更新）。它确实包含
这次要的 SDK 升级，但同时捆了 11 个别的 major：`chalk` 5→6、`string-width` 7→8、
`wrap-ansi` 9→10、`cli-truncate` 5→6、`cli-boxes` 3→4、`supports-hyperlinks` 3→4、
`marked` 17→18 等等。三条理由：

1. **它已经红了**，且红在两处：`format:check` 有 1 个文件不合规、
   `参考页生成器 · --check 自洽 > 干净状态下 --check 退 0` 失败。
2. **那批全是 TUI 渲染底座的依赖**（`string-width` / `wrap-ansi` / `cli-truncate` /
   `chalk` 直接决定列宽计算与换行），按 `src/ui/CLAUDE.md` L2.3 的规矩，
   动它们要用整帧渲染验证对齐，不是跑通单测就算完。那是独立一件事。
3. **把"安全修复"绑在"12 个 major 的行为验证"上，等于让安全修复的落地速度
   由最难验的那一个决定** —— 正是 CONTRIBUTING 里"上线时机能推翻合并"那条判据
   要防的形态（见 [[pr-unit-criteria-independently-shippable]]）。

**否决「只升到 0.91.1（刚好越过区间）」**。0.91.1 与 latest 0.120.0 之间没有已知的
破坏性变更影响我们用的那几个 API（实测四个符号全在），停在 0.91.1 只会让下一次
Dependabot 立刻再提一个 PR，白付一轮 CI。

**没有动 `@types/bun`**（#105 里也捆了它）—— 它已经由 #103 独立合入。

## 拿什么证明它生效了

**版本推出区间**（这是"告警会不会清零"的直接判据）：

```
node_modules/@anthropic-ai/sdk/package.json                  → 0.120.0
packages/eval-framework/node_modules/@anthropic-ai/sdk       → 0.120.0
grep -o '"@anthropic-ai/sdk@[0-9.]*"' bun.lock | sort -u      → 只剩 "@anthropic-ai/sdk@0.120.0"
bun install --frozen-lockfile                                 → exit=0（CI 第一步）
```

**SDK 实际调用面还在**（不只看测试绿 —— 测试可能 mock 掉 SDK，
见 [[metric-exists-but-value-is-junk]] 那类"过了检查但没测到东西"）。
真起一个 client 打印符号类型：

```
messages.create: function
messages.stream: function
APIUserAbortError: function
APIError: function
```
这四个正是 `packages/core/src/llm/anthropic.ts` 与 `llm/errors.ts` 用到的全部 SDK 表面。

**五道门禁**：`bun test` **10802 pass / 0 fail**（744 文件 / 149.46s，与升级前同样的
10802/0，说明没有测试被静默跳过）；`make build` exit=0 且
`will always be undefined` 与 `warn` 各 **0 命中**；
`lint` / `format:check` / `lint:boundary` 全 exit=0；
`bunx tsc --noEmit` 里 SDK 相关文件（`anthropic` / `llm/errors` / `sse-event`）
命中数 **0**（仓库有存量类型错误不进门禁，所以只核这几个文件）。

**受影响面为零的证据**：`grep -rn "memory_20\|memoryTool\|betaTools\|createMemoryTool"`
在 `packages` + `scripts` 下零命中 —— 两个告警都只影响 SDK 的 Local Filesystem
Memory Tool，我们没用它。

**告警已清零**（合并后复核，PR #106 于 2026-08-24 02:31 合入）：

```
gh api .../dependabot/alerts --jq '[.[]|select(.state=="open")]|length'  → 0
两条告警均 state=fixed, fixed_at=2026-08-24T02:31:11Z
```
注意 `fixed_at` 与合并时间只差 4 秒 —— GitHub 是按 main 上的清单重算的，
不是靠 PR 里写了什么。所以这个 0 是它自己算出来的，不是我声明的。
