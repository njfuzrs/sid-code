# Fork 炸弹判据改正则，并加「引号外才判」的掩码

## 决定了什么

`packages/core/src/permission/checker.ts` 里 Fork 炸弹的判定推倒重写，不再是
`DANGEROUS_PATTERNS` 表里的一条正则：

1. **正则改对**。旧写法 `/:()\s*\{…/` 里 `()` 是**空捕获组**而非字面括号，
   实际语义是「`:` + 可选空白 + `{`」。于是真正的 `:(){` 不命中（`(` 挡在中间），
   而 `function : {` 恰好命中——**行为是巧合而非设计**。
   新写法 `(?::\s*\(\s*\)|function\s+:)\s*\{[^}]*:\s*\|\s*:[^}]*&[^}]*\}\s*;`
   把两种写法都显式收进来，与 `read-only-validation.ts` 的「只读判定」保持同一口径。
2. **显式脱离 pipeline 分组**。原先它能生效，靠的是模式源码里恰好含 `\|`，
   被 `pipelinePatterns` 的 `source.includes("\\|")` 归类，从而对 `expansion.scripts`
   （未拆段）匹配。把 `\|` 换成 `[|]` / `\x7c` 任一等价写法，它就会掉进
   `nonPipelinePatterns`，改对**已拆段**的 `expansion.variants`（`{p:":(){"}` /
   `{p:":"}` / `{p:"}"}`）匹配 → 永远失配，且没有任何用例会红。
   现在由 `detectForkBomb` 显式判，不依赖正则字面量的副作用。
3. **加引号掩码**（`maskQuotedRanges`）。判据只认**代码位**：先把引号内（含引号外
   词首 `#` 之后）的字符等长替换成空格，再匹配。
   因为改正则后若直接 `.test(原文)`，`echo ':(){ :|:& };:'`、
   `git commit -m "…fork bomb…"`、`grep ":(){ :|:& };"` 会变成 critical **硬拒**——
   always-allow / acceptEdits 下没有出口，用户点不了「允许」，而这恰是讨论该形态时
   最常见的写法。等长替换而非删除是为了不打断正则里的 `[^}]*` / `\s*` 计数。

## 放弃了什么（以及为什么不选）

- **不做结构化判定（迁进 `dangerous-command.ts` 按 token 判）**。
  那一层的输入是 `commands[].program + args`，而 fork bomb 的判据在「函数定义 +
  `:|:` 自调用 + `&` 后台」这段**文本结构**上。拆段恰好把它拆碎
  （实测 `[":(){ :", ":", "}"]`），`:|:&` 这段函数体在 token 层面已经不存在了。
  要判只能重新在原文上扫，等于把这份工作原地重做一遍。
- **不加 `#` 注释的完整词法解析**。只做「词首 `#` 到行尾」这一层保守处理
  （`atWordStart` 仅在行首 / 空白 / `;&|()<>` 之后为真）。
  更完整的做法要处理 `$#`、`${#x}`、`a#b`、引号内 `#` 等，收益是几个边缘误报，
  代价是一旦算错就是把真炸弹当注释放过去——**方向错了**。宁可漏掩（多报一次）。
- **不并入 `eval "$(…)"` / `eval $var` 这类动态构造**。它们的执行内容要跑起来才知道，
  与 PR #443 记的「程序语义藏在参数里」同类，结构化那一层也拿不到。属另案，
  已在 `maskQuotedRanges` 的注释里写明「已知不覆盖」。
- **不放宽到 `curl … | sh` 那一类管道的通用处理**。本次只动 Fork 炸弹一条判据，
  high/medium 与其余 critical 的行为了无变化，回归面锁在单一形态上。

## 拿什么证明它生效了

- **修前（`main` @ `aae2cfc8`）实测**：`always-allow` 档下 `:(){ :|:& };:` 与
  `(:(){ :|:& };:)`、`true; :(){ :|:& };:` **全部 allowed=true**（静默放行）；
  `function : { :|:& }; :` 反而拦得住（旧正则空捕获组的巧合）。
- **修后实测**：11 个危险形态全部 `allowed=false / severity=critical / pattern=Fork 炸弹`
  （经典、`&` 前空格、`;` 收尾、括号内带空格、`function` 写法、分组、`;` 复合、
  `if/else`、`sh -c`、`eval '…'`、`bash <<EOF` 正文）；
  8 个数据形态全部 `allowed=true`（单/双引号 `echo`、`printf`、`grep`、
  `git commit -m` 两种引号、纯注释、行尾注释）。
- **`bun test ./packages/core/tests/permission/dangerous-command-matrix.test.ts`**：
  170 pass / 0 fail。新增 D2 两组（11 条危险 + 8 条数据）与一条拆段前提断言
  （`expandShellCommand(":(){ :|:& };:").variants === [":(){ :", ":", "}"]`，
  锁住「判据不能改去查 variants」这个前提）。
- **变异自证两轮**（CLAUDE.md 要求）：
  ① 把 `FORK_BOMB_PATTERN` 换回 `/:()\s*\{…/` → **10 项 FAIL**（正好是危险组里
  依赖新正则的那 10 条，`function :` 那条仍绿——它就是旧正则巧合覆盖的形态，
  反过来印证了上面「巧合而非设计」的判断）；
  ② 把 `maskQuotedRanges(script)` 改回 `script` → **8 项 FAIL**（正好是数据组全量）。
  两轮之后恢复，`170 pass / 0 fail`。
- **门禁**：`bun run affected-tests:run` 1751 pass / 0 fail（selective，1 个目标）；
  `make build` 成功且产物自检全过；`bun run smoke` 43/43；
  `bun run lint` 0 warning 0 error；`bun run format:check` 全通过；
  `bun run typecheck:gate` 62 处错误 / 基线 62 处，无新增。
- **回归由哪一层守**：G1 单测（`dangerous-command-matrix.test.ts` 的 D2 两组）。
  不需要 G2：给定命令后判定是纯函数，没有跨模块时序。
