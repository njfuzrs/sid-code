# 子代理非正常出口统一收尾，并把停止原因带回父代理

## 决定了什么

子代理此前只有「打满轮次」一个出口会收尾。另外四条非正常出口（父代理停止 / 上下文窗口耗尽 ×2 /
循环恢复耗尽 ×2）一律直接 `return`，父代理拿到的只有 salvage 的启发式残卷。而这几条路上
子代理往往已经读完文件、跑完命令，只差一次「把话说完」——一次不带 tools 的请求就能把整段
工作从「白跑」变成「可用」。

具体改了六件事：

1. **统一收尾函数**（`agent/agentic-loop.ts`）：把原先内联在打满轮次那一处的 227 行收尾逻辑
   抽成 `runFinalizeTurn(opts)`，四个出口共用。抽成函数而不是复制：里面的两段恢复
   （升档 → 续写）、孤儿 `tool_use` 补齐、响应里 `tool_use` 的剥离，每一条都是踩出来的。
2. **`task_stop` 默认优雅停止**（`tool/task-stop.ts` / `task/agent-task.ts` /
   `agent/agentic-loop.ts`）：新增 `stopRequestSignal`，与 `signal` 是两件事——
   后者是「立刻停，什么都别做」（ESC / 会话退出 / `force: true`），前者是「别开新轮了，
   把话说完」。默认路径置停止信号 + 60 秒兜底定时器（到点没交回总结就 `killAgentTask`），
   任务以 `stop_action=stopped_by_parent` 正常完成，结果走既有完成通知交回。
3. **窗口耗尽出口**（`context_window_exhausted` ×2）：失败前先 `emergencyTruncate()` 腾空间
   再跑收尾轮；总结真的产出了才标 `success: true`，没产出照旧走失败出口（不制造空壳 success）。
4. **循环恢复耗尽出口**（`loop_recovery_exhausted` ×2）：同样先收尾再返回。
5. **salvage 补强**（`agent/salvage.ts`）：新增「读过的文件（去重带行段）」与「最后 5 次
   工具调用」。前者回答「覆盖到哪了」，后者回答「它试过哪些路」——`toolEvidence` 只留最近
   6 条且每条截 800 字，答不了这两个问题。
6. **对父代理可见**（`agent/stop-notice.ts` / `agent/tool.ts` / `task/agent-task.ts`）：
   `stop_action` 不是 `finalize` 时，同步回程头部与后台通知都写明停止原因。不改 status ——
   这三个出口产出的都是可用结论，任务确实完成了，差异只在附注。

## 放弃了什么（以及为什么不选）

- **不复用 `signal` 承载「请求停止」**：abort 之后循环里每一处 `signal.aborted` 判定都走
  中止分支，收尾轮在结构上就起不来——而那正是最需要它的时候。必须两条独立通道。
- **不给 `task_stop` 加「等总结回来再返回」**：那会让父代理卡在工具调用里最长 60 秒。
  改为立刻返回「已请求停止」，结果走既有完成通知，与后台任务的投递模型一致。
- **不新增任务状态枚举**：`stopped_by_parent` / `max_turns` / `context_window_exhausted`
  的产出都是可用结论，任务状态仍应是 completed（TUI 面板、任务统计、changelog 口径都不必改）。
- **不给「窗口耗尽」单独写一套裁剪**：复用 `emergencyTruncate()`（现成的最激进一档，
  且返回 `CompactionOutcome` 能如实告知腾没腾出空间）。
- **不从实现反推 G2 冒烟用例的 `expect`**：`tests/smoke/cases/` 的期望只能从人工核过的
  轨迹里抄。本次 G1 已覆盖核心判据，G2 用例留给维护者用真实轨迹补（见文末）。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/agent/ ./packages/core/tests/task/ ./packages/core/tests/tool/`
  → **2967 pass / 0 fail**（235 文件，含新增的 7 条 PR11 断言）。
- **变异自证**：删掉主循环里 `config.stopRequestSignal?.aborted` 那段 break，
  `pr11-nonnormal-exit-finalize.test.ts` 的「停止信号一开始就置位 → 直接收尾」用例立刻变红
  （`expect(toolCounts.length).toBe(1)` 收到 2）；恢复后 7 pass。说明断言真的在看这段代码。
- `make build` → 通过（含产物自检：git-status 锚点、止损阀、skill 内嵌、ripgrep、review 子命令）。
- `bun run lint` → 0 warning / 0 error（3273 文件）；`bun run format:check` → 全绿。
- `bun run typecheck:gate` → 本次改动的文件零新增类型错误。
- `bun run docs:gen-reference` → 重新生成 `website/ref/tools.md`（`task_stop` 新增 `force` 参数）。

**已知未覆盖**：`tests/smoke/cases/` 下的两条 G2 用例没有加。原因是 G2 的 `expect` 必须
从人工核过的回放轨迹里抄，agent 无法自行生成合法夹具（反推实现得到的期望是假绿）。
PR11 的判据目前由 G1 守住：收尾轮是否发出、是否不带 tools、归因是否正确、salvage 清单是否
被收集——都是开关型断言，不依赖模型行为。
