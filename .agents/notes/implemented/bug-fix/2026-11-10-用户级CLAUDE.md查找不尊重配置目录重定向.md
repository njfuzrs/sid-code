# 用户级 CLAUDE.md 的查找改为尊重配置目录重定向

## 决定了什么

`findGlobalCLAUDEmd()` 的第一候选从 `join(homedir(), ".claude", "CLAUDE.md")` 改成
`join(getClaudeHome(), "CLAUDE.md")`；`/memory` 面板的 `discoverMemoryFiles()` 同步改掉同源的
一处，并把 `displayPath` 从写死的 `~/.claude/CLAUDE.md` 改为按真实路径缩写（重定向后不在家目录
下就显示绝对路径，避免面板指向一个并未被读取的文件）。

依据：`CLAUDE_CONFIG_DIR` 是配置目录重定向的既有契约（`paths.ts` 的 `getClaudeHome()` 认它，
同层的 `userRulesDirs()` 也早就走它），只有这两处还在直接读 `homedir()`。

**为什么这不只是“读错文件”**：这一层的 `layer` 是 `user`（可信层），能设 `## Permission Mode`
与 `## Allowed Tools`。配置目录被重定向（隔离、CI、多账号）后仍读真实 HOME 的那份，
等于隔离意图被一份“本该读不到的文件”抬了权限档——与 B6 是同一类风险的不同来源。

## 放弃了什么（以及为什么不选）

1. **只改 `rules.ts` 不改 `/memory` 面板**。否决理由：面板会展示一个并未被加载的文件，
   用户按面板去看/改配置，改的不是生效的那份。
2. **改 `findGlobalCLAUDEmd` 的候选顺序**（先 `sidHomePath` 再 `getClaudeHome`）。
   否决理由：`--print`/CI 这类同时设了 `SID_CONFIG_DIR` 与 `CLAUDE_CONFIG_DIR` 的场景下，
   两个候选会指向同一个文件，顺序无意义；而默认（都不设）时 `~/.claude/CLAUDE.md` 优先是
   CC 兼容的既有行为，不该顺手改。
3. **给 `findGlobalCLAUDEmd` 加 `home` 参数便于测试**。否决理由：为一个已被
   `CLAUDE_CONFIG_DIR` 覆盖的路径再开一个新注入口，只会让“到底以哪个为准”更难推导；
   测试用环境变量即可。

```
findGlobalCLAUDEmd() = /Users/zhourusheng/.claude/CLAUDE.md   ← 仍读真实 HOME
```
