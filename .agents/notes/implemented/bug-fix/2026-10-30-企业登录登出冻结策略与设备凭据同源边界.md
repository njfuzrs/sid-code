# TUI 登出不再重载企业策略；设备凭据只随内置事件后端发出

## 决定了什么

修 2026-10-22 核查官网 `team/login.md` 时发现的 4 条代码缺陷（D1–D4）：

- **D1（P1）登出解除企业管控**：`app.ts` 的企业状态刷新原先订阅 `onCredentialChanged`（登录登出不分），
  登出也调 `reloadEnterprisePolicy`。没凭据时远程 loader 只采信 10 分钟内的缓存，而轮询间隔 30 分钟，
  于是远程 deny / bridge 开关大概率被清掉。改为订阅新增的 `onCredentialAcquired`（core `identity/credential.ts`，
  cred 为 null 不触发）：登出后本会话已生效的企业策略与预算冻结到会话结束，与 `/logout` 回执一致。
- **D2（P1）第三方 collector 收到设备凭据**：`HttpExporter` 新增 `attachDeviceCredential`，**默认 false**，
  只有 `init-helpers.ts` 里内置 `sid-backend` 打开。`analytics.backends[]` 的 http 后端只用自己的 `authHeader`，
  没配就稳定不发，不拿设备凭据兜底。
- **D3（P2）第三方 401 误报「企业登录已失效」**：随 D2 消失（`lastBatchUsedDeviceCredential` 只在带了设备凭据时为真）。
- **D4（P3）`backend.url` 不合法却提示「未配置」**：core `login-status.ts` 新增 `backendUnavailableHint()`，
  基于 `inspectBackendUrl()` 区分 invalid / none；`/login`、`sid-code login`、`sid-code auth enroll` 三个入口改用它。
  提示里给来源，**不回显原值**（不合法的一种是 URL 带用户名密码）。官网 `team/login.md` 同步改了这一句。

## 放弃了什么（以及为什么不选）

- **调大 `POLICY_CACHE_STALE_MS`**：它同时管启动与超时回退时是否采信缓存，调大会续命已撤销的 deny（`policy.ts` 注释写了为何是 10 分钟）。
- **登出时冻结「已生效远程策略」到一个新状态位**：比「不重载」多一套状态，而不重载已经满足承诺；登出后不再有凭据，`policy-poll` 本来也不拉。
- **D2 用 `resolveBackendUrl().origin` 与 endpoint 比同源**（market.ts 判据）：第三方 collector 恰好和 backend.url 同源时仍会带凭据，
  且内置后端的地址本就由 backend.url 派生，按「谁构造的」判比按 URL 推断更硬。默认关 = 新增 exporter 不会悄悄带出凭据。
- **旧端点环境变量 `SID_CODE_*_ENDPOINT` 的同源判断**（文档旁支）：本 PR 不动，那是计划删除的兼容层，另议。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/analytics/http-exporter.test.ts`：21 pass；新增「第三方 collector 不带设备凭据（D2/D3）」3 条。
  变异自证：把默认值改回 `?? true`，这 3 条全红，恢复后全绿。
- `bun test ./packages/core/tests/identity/login-status.test.ts ./packages/cli/tests/app/enterprise-logout-keeps-policy-wiring.test.ts`：全绿。
  变异自证：① `onCredentialAcquired` 去掉 null 过滤 → 行为用例红（初版用 `c.credential` 时**没红**：订阅方抛错被 emitChanged 吞了，已改写断言）；
  ② app.ts 改回 `onCredentialChanged` → 接线用例红；③ `backendUnavailableHint` 不认 invalid → D4 两条红。
- 未在真机连企业后端复现（缺陷文档的四步 TUI 复现需要测试后端），D1 的证据只到单测 + 接线静态断言这一层。
