# 同一个外部对象的第二个等待不再起进程，改为返回带出口的回执

## 决定了什么

`bash`（`run_in_background` + `wait_until_seconds`）/ `monitor` / `schedule_wakeup` 三个入口，
在**启动进程或排唤醒之前**统一过一道按对象单活的准入判定：

- 新增 `wait-subjects.ts`：从命令行、脚本正文（含变量展开与 `< 64KB` 读取上限）、唤醒 prompt
  三个来源抽对象签名（`gh:pr:779` 这类），命令表复用 `status-query-commands` 的切片规则，
  另补一层宽松正则兜住「查询写在输出文本里」的既有 monitor 形态。
- 新增 `wait-admission.ts`：`decideWaitAdmission` 返回 `start` / `duplicate` / `replace` 三态。
  duplicate = 同对象 + 归一化命令相同且脚本正文未变，或新期限落在已有等待剩余期限之内。
  抽不出对象签名一律 `start`。
- `WaitSource` 增加 `command` 与 `scriptHash` 两个可选字段：只比 subjects 的话，
  `bash a.sh` 与 `bash b.sh` 等同一个 PR 永远判不出重复；只比路径的话，改过内容的脚本
  会被误判成重复（方向正好反了）。
- duplicate 不 spawn，回执点明在盯的对象、旧等待最晚回报时刻、以及**按 kind 正确的出口**
  （`task_stop` / `cron_delete`）。`isError: false`——这不是失败。
- `replace` 只判定不淘汰（旧的继续跑），淘汰留给 R6。回执会点破这件事，不静默。

## 放弃了什么（以及为什么不选）

- **不在各工具里各写一份判据**。三个维度（对象、命令、脚本版本）任漏一个，那条路径就静默失效
  且没有测试覆盖——b0aa0f1e 正是「每个入口只管自己那一类」的产物。
- **不做「起了再 kill」**。先 spawn 再终止会先产生一次输出与一条终态通知，与「本次未重复启动」
  自相矛盾，也是 b0aa0f1e 四条噪音的来源。因此判定必须在 spawn 之前，`registerWaitUntil`
  只负责登记。
- **不把普通后台任务纳入去重**。没有 `wait_until_seconds` 的后台命令承诺是「退出或静默时回报」，
  不是模型声明的等待；纳入会误伤「等 PR + 跑 bun test」这种合法组合（a7d1c888 的形态）。
- **不在抽不出签名时保守拒绝**。抽不出 = 不参与去重 = 行为与改动前完全一致；
  抽错（把无关的两个等待判成重复）比多起一个进程更糟，因为它会挡住模型真正需要的第二次等待。
- **不在这一 PR 里做 R6（同对象替换）**。淘汰旧进程牵涉 task_stop 语义与通知时序，
  与「不重复启动」是两个可独立回滚的行为。判据已经返回 `replace`，R6 只需改调用点。
- **不顺带修 R1 的其余部分**（`registerWaitUntil` 的 `commandFamilies`、monitor 旧函数的
  全量口径收口）。本 PR 只带 R2 跑起来所必需的抽取能力。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/task/wait-subjects.test.ts ./packages/core/tests/task/wait-admission.test.ts`
  → 25 pass / 0 fail（真值表 8 条 + 抽取规则正反例 + 回执格式）。
- `bun test ./packages/core/tests/tool/bash-wait-until.test.ts ./packages/core/tests/tool/wakeup-wait-admission.test.ts ./packages/core/tests/tool/monitor.test.ts`
  → 三入口集成全绿；其中 `monitor.test.ts` 的 T-M1-15 是**契约变更**同步：
  旧断言「第二个同对象 monitor 照常启动、只加提示」与新行为直接冲突，改为断言不 spawn + 回执含出口。
- G2 新增 `tests/smoke/cases/R2-dup-wait-same-subject`（回放 b0aa0f1e 的四次同脚本等待）：
  `bun run smoke R2-dup-wait-same-subject` → PASS（60.4s），
  运行产物里 `WaitRegistered{kind:shell}` 1 条、`TaskLifecycle{phase:started}` 1 条、
  `subjects:["gh:pr:779"]`，另三次工具结果含「本次未重复启动」。
- 变异自证：`bun run smoke:mutate R2-dup-wait-same-subject`（配方把准入判定废成恒 `start`）
  → 用例转红，证明确实是这条判据在拦，而不是断言恒绿。
- `bun run affected-tests:run` → 4187 pass / 2 fail；两个失败均为
  `tests/build/rules-paths-scope-nonempty.test.ts` 的 worktree 固定假失败
  （`.git` 是 gitdir 指针 → `ruleOwnerDir` 解析到主仓根，`candidates` 恒空），
  父仓 main 单跑 3 pass / 0 fail，该文件不 import 本次任何改动模块。
- `bun run typecheck:gate` → 62/62 无新增；`bun run lint` 0 error；`bun run format:check` 通过。
- 已知未达成的验收项：R2 验收 3（「先 wakeup 再起 bash → 唤醒被替换」）依赖 R6，
  本 PR 只做到「识别为 replace 并启动新的」，旧等待不淘汰。
