# 控制端静默不再被当成管理员强制断开

## 决定了什么

中继把「这一侧 60 秒没有发帧」和「管理台点了强制断开」合成同一个 `1008 admin_disconnect`，
CLI 收到 1008 走永久失败并 `process.exit(1)`。人在权限弹窗前犹豫超过一分钟，本机 agent
就被踢下线，`permission_expired` 也送不回来。

改了三处，跨两个仓库：

- **中继**（`agent-backend` 的 `relay.py`）：空闲与强制断开用不同的码与 reason。
  强制断开维持 `1008 admin_disconnect`，继续写 `disconnect_reason` 与审计。
  空闲用 `1001 idle_timeout`，且**不**把会话标成 `disconnected`——标了会让旧 token
  永久作废，重连即 4001。空闲判据从「本侧 `last_inbound`」改成「两侧最近一帧的较新者」，
  抽成纯函数 `_idle_verdict`。
- **CLI**（`ws-transport.ts`）：`1008` 只有 reason 是 `admin_disconnect` 才算永久失败，
  其余 1008 与 `1001` 走重连。探活判据从「多久没收到任何入向消息」改成「发出的心跳
  有没有被送回来」——中继把 ping 回显给发送方自己，所以对端不说话不再被判成半开。
- **CLI 启动**（`bridge-runner.ts`）：`start()` 原先只让一个微任务就读永久失败。
  服务端在 `open` 里直接 `close` 时，关闭回调与 `onopen` 在同一轮任务里先后跑完，
  微任务读到的还是「没失败」，`runBridge` 会先打印「已启动」。改成在 `connect()`
  之前挂上关闭等待，关闭发生在握手 resolve 之前时那个 Promise 已经放行。
- **管理台**（`BridgeSessions.tsx`）：连接建立后每 20 秒发一次
  `{type:"status", data:{ping:true}}`。这个帧中继会转发，CLI 主循环不认识 `status`，
  不进队列。

## 放弃了什么（以及为什么不选）

- **把 `IDLE_TIMEOUT_SECONDS` 调到大于 60 秒。** 与权限超时重合只是触发条件，不是根因。
  调大只是把窗口挪一寸，人犹豫两分钟照样死。
- **让管理台周期发 `user_message` 保活。** 每条都会进 CLI 主循环，变成真的远程指令。
- **只改中继、不改 CLI 的探活。** 端到端第一次跑就暴露了：中继不再误杀之后，CLI 自己的
  半开探活在 60 秒时把连接断开重连，重连即 4001。只改一侧等于把杀手从中继换成 CLI。
- **探活继续看「任何入向消息」，靠控制端回 ping 来喂。** 控制端崩溃或笔记本合盖时没有
  回帧，CLI 照样把自己断开。回显放在中继，不依赖控制端还活着。
- **把 `1008` 从永久失败码里整个删掉。** 管理员强制断开就不再能让被盗会话的 CLI 退出。
  所以 1008 保留，但只认 `admin_disconnect` 这一个 reason。
- **空闲超时也写 `disconnect_reason`。** reason 是给人读的审计理由，空闲不是一个理由，
  它是传输层事件。
- **在父进程里 `mock.module` 替换 `bridge-runner` 来测成功提示。** bun 的
  `mock.module` 是进程级的，`mock.restore()` 不还原被替换的模块（用最小两文件
  实验确认：恢复后另一个文件拿到的仍是 mock）。那条测试留在父进程时，同一次
  `bun test` 里排在它后面的「永久失败」测试拿到一个 `start()` 什么都不做的假类，
  4001 / 1008 两条断言放空；单独跑那个文件又是绿的。把它整个放进子进程。

## 拿什么证明它生效了

单测：

- `agent-backend`：`pytest tests/test_bridge_relay.py tests/test_bridge.py` → **34 passed**。
  新增三条：一侧静默不判空闲、两侧都旧才判、空闲关闭是 `1001 idle_timeout` 且会话仍是
  `paired`、没有 `disconnect` 审计。原有的管理员断开用例改为断言 `1008 admin_disconnect`
  且 `disconnect_reason` 与审计都在。
- `sid-code`：`bun test packages/core/tests/bridge/` → **107 pass**。`1008` 带
  `admin_disconnect` 才永久失败；`1001 idle_timeout` 不永久失败；`status` 保活帧不进主循环。

端到端（本地 sidecar + 真实 `WebSocketBridgeTransport`/`BridgeCore`，心跳间隔注入为 500ms，
不靠真等 65 秒——那一段会被主机休眠污染）：

```
PASS 4 权限超时仍是拒绝: 通过（decision=false, expired 帧已到, 连接仍在）
PASS 1 静默不再杀连接: 通过（静默 7s，两侧仍连接，无永久失败）
PASS 1b 静默后仍能转发: 通过（收到文本 pong）
PASS 3 管理员强制断开: 通过（控制端 1008 admin_disconnect，CLI 永久失败：1008 管理员强制断开）
PASS 控制端完全静默：两侧仍连接，无永久失败
```

最后一条是对照：控制端完成 auth 后一帧不发。修复前 CLI 在两个心跳周期后判定半开、
断开重连、重连即 4001。

收尾时重跑（2026-09-27，本机）：

- `bun test ./packages/cli/ ./packages/core/tests/bridge/ --test-name-pattern '^(?!.*\[slow\])'`
  → **1678 pass / 0 fail**。修启动竞态之前，这组里 4001 与 1008 两条是红的，
  单独跑 bridge 目录又是绿的——红只在和 cli 测试同进程时出现。
- `make build` → 自检通过。`bun run lint` / `format:check` / `lint:boundary` 全过。
- `agent-backend`：`ruff check .` 全过，`alembic check` 无新操作，
  `pytest tests/test_boundaries.py` → **29 passed**，`pnpm exec tsc -b` 通过。
