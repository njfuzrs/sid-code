# @ 提及补齐四项：左边界锚点、多文件总预算、行范围与去重、目录条目列表

## 决定了什么

接着 #409 的三道防线，在 `packages/cli/src/app.ts` 的 `expandAtReferences` 里再补四项：

1. **左边界 `(?<!\w)`**：`@` 前面是 `\w` 时不认作文件引用（`foo@bar.com` 不再去读 `./bar.com`）。
2. **多文件总预算 `AT_INLINE_TOTAL_MAX_BYTES = 256KB`**：同一条消息里按出现顺序累加，超出的进 `skippedPaths`，reason 为「本条消息 @ 内联总量超过 256KB」，同时告知模型和用户。
3. **行范围 `@f.ts#L10-20` / `#L5`**：只内联对应行。源文件上限放宽到 10MB（只是为截一段而读），截出来的内容仍受 100KB 单文件上限和总预算约束。
4. **去重**：App 持有 `atInlined`（key = 绝对路径 + 行范围 → mtime + 注入时的标题行）。只有 mtime 没变、**并且**标题行还在当前上下文的 user 消息里，才跳过并注入一句「已在上文中」。`/clear` 时清空。
5. **目录**：`@dir` 与 `@dir/` 都注入条目名列表：不递归，子目录带 `/`，最多 1000 条，超出附「另有 N 项未列出」。列表也计入总预算。

缺口文档的第 3 项（单条超大 user 消息让压缩层无解）不在本 PR。它改的是压缩层，属于另一个子系统，文档也要求先设计再动手。

## 放弃了什么（以及为什么不选）

- **照搬 CC 的 `(^|\s)` 锚点**：输入框的 @ 补全（`ui/hooks/useAtCompletion.ts` 的 `extractAtPattern`）只在 `@` 前是 `\w` 时不触发。在 `看下@src/a.ts` 这种中文紧贴的写法里，补全会弹出来。如果展开要求前面是空白，用户选了补全项，文件却不会注入。展开和补全的判据必须一致。代价是空白后的 `@scope/pkg` 仍然会匹配，这和 CC 一样，它跟 `@src/a.ts` 在语法上区分不开。当前目录没有同名路径时 stat 不命中，什么也不注入。
- **照抄 CC 结尾的 `\b`**：它会吃掉末尾的 `/`，而末尾 `/` 正是目录提及的标志。
- **复用 FileReadTracker 判断「已在上下文」**（缺口文档的建议）：tracker 只记录读过以及读时的 mtime，不知道内容是否还在上下文里。压缩、旧结果清理、撤回未发送的轮次都会拿掉内容，tracker 却不变。据它去重，模型会以为自己看过，实际看不到。
- **按模型窗口比例定总预算**：需要从 provider 取窗口值，改动面更大。先用常量。
