# 同步回程落盘失败时要留标记，不能让父代理把截断结果当成完整结论

## 决定了什么

`packages/core/src/agent/tool.ts` 的 `buildSyncSubagentSummary()`：结论超过 16,000 字符时
照旧经 `persistLargeOutput` 落盘并截断；但**落盘失败**（`persisted.savedPath` 为空，通常意味着
磁盘满或目录权限异常）时，正文尾部在「已截断 N 字符」之外再追加一行
`[全文落盘失败，以上不是完整内容]`，且不输出 `<output-file>`（没有文件可指时给指针就是骗人）。

背景是 T4（PR #894）落地后的一处可观测性退化：旧路径（上下文层 >30,000）落盘失败时会留下
`文件=[保存失败]` 标记（`context/tool-result-storage.ts` 把 `"[保存失败]"` 塞进 `savedPath` 位），
而同步回程复用 `persistLargeOutput` 的静默降级时，这个标记没有跟着传下来。结果父代理拿到
16,000 字的截断正文，没有任何信号提示它「全文已经丢了」。

配套新增一条测试用例（`packages/core/tests/agent/sync-subagent-result.test.ts`），用只读目录
**造 EACCES 数据**——这个失败分支在日常轨迹里等不到样本（磁盘从来没满过），只能主动构造。

## 放弃了什么（以及为什么不选）

- **复用 `buildPersistedReference` 的引用形态**：它是「整段替换成 ~200 字节引用」，会把已经
  留在窗口里的 16,000 字原文一起丢掉。宁可留着能留的部分 + 一句标记。
- **给 `truncateForNotification` 加一个「落盘失败」参数**：那是后台通知与同步回程共用的函数，
  改签名会波及后台路径与其测试，与本次关注点无关。判断放在调用方（`buildSyncSubagentSummary`）
  只多一个三元分支。
- **不做，保持静默降级**：T4 之后父代理拿到的是 16,000 字而非 0 字，比旧路径已经好得多，
  所以这不是「不回滚就出事」的缺陷。但只要落盘真的失败，父代理就无法区分「完整」与
  「被截断且全文丢了」——它可能基于残缺结论继续改代码。一个固定字符串换掉这个盲区，值。
- **失败时干脆不截断、把超长正文整段塞回窗口**：会把父上下文直接撑爆，比丢信息更糟。

## 拿什么证明它生效了

变异自证（把失败分支改回原来的无条件 `truncateForNotification(..., outputFile)`）：

```
$ bun test ./packages/core/tests/agent/sync-subagent-result.test.ts
error: expect(received).toContain(expected)
Expected to contain: "[全文落盘失败，以上不是完整内容]"
(fail) 超过上限 > 落盘失败时明确告知全文没留下来（不能静默当成完整结论）
 5 pass
 1 fail
```

恢复实现后：

```
$ bun test ./packages/core/tests/agent/sync-subagent-result.test.ts
 8 pass
 0 fail
```

端到端探针（单独脚本，`SID_CONFIG_DIR` 指向 tmpdir，把 `tool-outputs` 目录 chmod 500 制造 EACCES）：
20,000 字结论 → 回程正文 16,130 码点、无 `<output-file>`、尾部带上述标记，`persistLargeOutput`
打出 `EACCES: permission denied` 警告。造数据是本条唯一可行的取证方式：真实使用中该分支
从未触发，等样本等于永远不验。
