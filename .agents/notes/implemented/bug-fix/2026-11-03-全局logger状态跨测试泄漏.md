# 全局 logger 跨测试泄漏用「测试侧复位 + 静态门禁 + preload 兜底」三件套修掉

## 决定了什么

D60：`packages/cli/tests/command/agents-summarize-tools.test.ts` 的 `captureJson()` 把整段
`console.log` 当 JSON 解析，而 `packages/core/tests/config/sid-home-path-derivation.test.ts`
把进程级单例 logger 打开后没有复位（`console` 默认 `true`，非 ERROR 级别走 `console.log`），
于是前一个文件留下的状态让后一个文件抛 `SyntaxError: Unrecognized token '^['`。
只红一次、重跑就绿，PR #538 的作者差点被引向错误归因。

改了三处，都是测试与测试基建，**不动产品代码**：

1. **复位两个污染源**。`sid-home-path-derivation.test.ts` 的 `initLogger` 加 `console: false`
   （该用例只断言落盘），并在 `afterEach` 里 `initLogger({ enabled: false })`；
   `collector.test.ts` 的 `captureTraceWarns()` 同样加 `console: false`，`restore()` 里连
   logger 一起复位（原来只还原 `warn` 方法）。
2. **加静态门禁** `packages/core/tests/debug/logger-global-leak-gate.test.ts`：扫全部 6 个
   测试根，凡是 `initLogger({ enabled: true|非字面量 })` 却没有 `console: false` /
   `fileOnly: true` 的调用一律报红。豁免清单只有一处（`unattended-pipeline.test.ts`，
   它的被测对象就是 `consoleToStderr` 的控制台分流），且每条豁免都要写理由。
3. **加 preload 兜底**：`tests/preload-isolate-sid-home.ts` 里注册全局 `afterEach` 复位 logger。
   bun 1.4.2 上**实测**该 `afterEach` 对每个测试文件的每个 test 都执行（2 文件 × 2 test = 4 次，
   preload 本身只加载一次），不是"应该生效"。

## 放弃了什么（以及为什么不选）

- **`NODE_ENV=test` 时 logger 的 `console` 默认改成 `false`（或 `consoleToStderr` 默认 true）**。
  这是为测试改产品代码的默认值，会让「测试里 logger 到底打到哪」多一层隐式规则，
  而真正的根因是测试没清共享状态。否决。
- **只改受害方** `captureJson()` 让它跳过非 JSON 行。它会让下一条同形测试（捕获
  `console.log` 再解析）继续踩同一个坑，且把真实污染掩盖成"解析逻辑的兼容问题"。否决。
- **只做静态门禁、不做 preload 兜底**。静态扫描是穷举式防线：只扫 6 个已知测试根，
  正则也可能漏掉某种写法。文档原方案对 preload 打了「未核实」的问号；本次核实生效后
  补上，作为判据式兜底（不依赖穷举）。代价是「不要在 `beforeAll` 里开 logger」——
  已写进 preload 注释。
- **只做 preload 兜底、不做静态门禁**。兜底会让泄漏"不可见"，门禁才能在 review 阶段
  点名到文件与行号。两者互补，都做。

## 拿什么证明它生效了

1. **修前红、修后绿（确定性复现）**。在 worktree 根放一个 `.sid-code/agents/probe-agent.md`
   让 `custom.ts` 打一条 INFO（否则本地复现不出「捕获窗口里有日志」这个条件），
   然后同一进程跑两个文件：
   - 修前（把 `console: false` 与 `afterEach` 复位临时改回去）：
     `bun test ./packages/core/tests/config/sid-home-path-derivation.test.ts ./packages/cli/tests/command/agents-summarize-tools.test.ts`
     → **19 pass / 1 fail**，失败是 `JSON Parse error: Unrecognized token ''`，位置
     `agents-summarize-tools.test.ts:31`，与 CI 的形态一致。
   - 恢复修复后同命令 → **20 pass / 0 fail**。
2. **门禁变异自证**（恒绿的门禁比没有门禁更危险）：先只加门禁、不改污染源，跑
   `bun test ./packages/core/tests/debug/logger-global-leak-gate.test.ts` → 门禁**报红并点名**
   `packages/core/tests/config/sid-home-path-derivation.test.ts:95 → initLogger({ enabled: true, logFile: … })`；
   补上 `console: false` 后 → **5 pass / 0 fail**。另有三条变异用例（违规写法被抓、
   合规写法不误报、注释里示意代码不误报、引号内的 `)` 不会截断判定）。
3. **preload 兜底的行为核实**（不是推断）：在 `/tmp` 建最小实验（一个 preload 注册
   `afterEach` + 两个各含 2 个 test 的文件），`bun test` 输出 `[preload] afterEach ran` 4 次、
   `[preload] loaded` 1 次。
4. **回归面**：11 个直接涉及 logger 的测试文件（`logger-level-gate` / `collector` /
   `redaction-gaps-pr-b` / `export-failure-throttle` / `unattended-pipeline` / 两个 mcp
   corrupt / `gateway-pricing` / `sid-home-path-derivation` / 新门禁 /
   `agents-summarize-tools`）一起跑 → **286 pass / 0 fail**；全量 `bun test` 与
   `make build` 的结果见 PR 正文。
