# IDE diff 死接线：把「展示」接成写盘前的内容协商，顺带拆掉一个 30 秒超时陷阱

## 决定了什么

修掉缺陷清单 **D1**（IDE diff 展示是完全的死代码）。这是十六条里唯一一条
**必须建立在另一条修复之上**的（D3 协议对齐，已在 `fix/ide-notification-protocol` 里），
所以本分支从那个 PR 分出，而不是从 main。

| 改动 | 文件 |
| --- | --- |
| 新建 diff 运行时 holder（死链缺的那一环） | 新增 `ide/runtime.ts` |
| `negotiateContentViaIDE()`：写盘前的内容协商 | `ide/tool-hooks.ts` |
| 在 `Bun.write` **之前**接线（edit 两处、write 一处） | `tool/edit.ts`、`tool/write.ts` |
| IDE server 注册显式长超时（30 分钟） | `ide/integration.ts` |
| `ide.diffPreview` 开关（默认 **false**） | `config/config.ts`、`cli/src/cli.ts` |

**最重要的一条发现不在清单里：这个功能哪怕接对了，也会被一个 30 秒超时打死。**

IDE 注册 MCP server 时不带 `timeout`，于是走 `getMcpTimeout()` 的 **30 秒**默认值，
而传输层对超时的处理是**硬 reject**（`transport.ts` 的 `setTimeout` → `MCP 请求超时`）。
但 `openDiff` 等的是**一个人**读完 diff、可能还手改几行再保存 ——
30 秒是"用户去接了杯水就必然失败"的量级。

失败方式还**特别难归因**：diff 明明弹出来了，用户改完保存，而 CLI 侧早已 reject，
编辑被当作"IDE 不可用"照原样写掉，**用户的手改静默丢失**。
所以这不是"调大一点更宽松"，是功能能否成立的前提。

（顺带发现：`getMcpToolTimeout()`（那个 120s 的工具调用超时）**零调用点**，
是另一处死代码。本 PR 没动它 —— 它不在这十六条里，且改它会影响所有 MCP server。）

## 放弃了什么（以及为什么不选）

**① 没有改 `ToolUseContext` 去传 `MCPManager`。** 断层的直接原因是编辑工具拿不到
manager（`execute(input)` 只收 input，`ToolUseContext` 里只有 `mcpClients: unknown[]`）。
改 context 要动工具执行器、所有 Tool 实现与大量测试夹具，代价与收益不成比例。
沿用本仓已有的同款范式 `memory/team/runtime.ts` —— **`edit.ts` 已经在用它**拿团队记忆配置。

**② 接在写盘之前，不是写盘之后。** `DiffResult` 有五个分支
（`saved{content?}` / `rejected` / `closed` / `unsupported` / `error`），
说明设计时就知道 diff **不是展示功能**，而是一次**阻塞的、有返回值的内容协商** ——
用户可以在 diff 视图里继续手改再保存，此时该落盘的是**用户改过的版本**。
接在"改完之后"就只剩展示，失去了全部意义。

**③ `diffPreview` 默认 false。** 开启后每次 edit/write 都变成**一次等人的交互**
（最长 30 分钟）。无人值守 / 批量 / CI 场景下会直接把 agent 挂住 ——
让一个便利功能默认开启，等于把它变成一个卡死风险。

**④ `TAB_CLOSED` 视为「未表态」而非「拒绝」。** 用户可能只是关掉了预览窗口，
把它当拒绝会让编辑**莫名消失**。按未表态处理 = 与没有 IDE 时行为一致。

**⑤ `saved` 但 `content` 缺失时用 `newContent`，不回退 `oldContent`。**
缺失是合法的（用户直接接受、未二次编辑），回退成旧内容会**静默丢掉本次编辑**。

**⑥ 只有「用户明确拒绝」能阻断编辑。** 没有 IDE / 开关没开 / IDE 断开 / RPC 抛异常 /
响应是未知状态（协议漂移），一律"照原样写"。**一个预览功能不该有能力阻断编辑。**

**⑦ `error` 分支从静默改成打 warn。** 此前它是静默的（调用方按"IDE 不可用"处理），
于是 diff 全部失败时用户完全看不出来 —— 这正是清单警告"验收判据不能是函数被调到了"
的原因。

**⑧ 用 `close_tab`（单个）而非 `closeAllDiffTabs`。** 后者会把用户正在看的其他 diff
一起关掉。这个单标签页接口正是 D3 补上的。

**⑨ `write.ts` 里下游三处从 `params.content` 改成 `contentToWrite`。**
tracker 内容快照、行数骤降警告、`structuredPatch` 都必须反映**真的写进去的内容** ——
tracker 记错会让下次 edit 把**用户自己的改动**误判为"外部修改"。

## 拿什么证明它生效了

**① 用例刻意不断言"函数被调到了"** —— 清单对 D1 写了明确要求：

> ⚠️ 验收判据必须是「IDE 里真的弹出了 diff 且用户手改能被拾取」，
> 不能是「函数被调到了」—— 因为 `error` 分支是静默的。

真实 IDE 弹窗单测验不了，但那条要求的**实质**可以验：**用户手改的内容有没有真的
落到磁盘上**。所以用假 IDE server 回放 `openDiff` 响应，然后**读真实文件**断言内容：

```
write：模型写"// 模型生成的版本"，用户在 diff 里改成"// 用户手改的版本"
  → readFileSync 断言磁盘上是用户版本，且 not.toContain("模型生成的版本")  ✅
edit：同上，磁盘上是 const b = 999（用户版），不是 const b = 3（模型版）      ✅
```

假 server 还按 **CC 扩展的真实 wire 协议**校验入参
（`Object.keys(args).sort()` 必须等于 `[new_file_contents, new_file_path, old_file_path, tab_name]`），
参数名错了用例就红 —— 直接盯住"上游死接线掩盖下游协议不兼容"那个坑。

**② 四次变异自证**（本仓铁律：每条规则须变异自证）：

```
变异1：write.ts 回到死接线（去掉协商调用）        → 10 pass / 4 fail  ✅ 红
变异2：IDE 超时改回 30s（diff 等人必然失败）      → 13 pass / 1 fail  ✅ 红
变异3：TAB_CLOSED 误当拒绝（编辑莫名消失）        → 13 pass / 1 fail  ✅ 红
变异4：忽略用户手改内容（写模型版本）             → 12 pass / 2 fail  ✅ 红
复原 → 14 pass / 0 fail                                            ✅
```

**③ 门禁固化了 D1 的实证命令**：`grep -rn "tool-hooks" packages` 曾是 **0 命中**，
现在断言 `edit.ts` / `write.ts` 剥注释后含 `negotiateContentViaIDE` 与
`ide/tool-hooks.ts`；并断言**协商调用的位置排在 `Bun.write` 之前**
（接在写盘之后就失去意义，这条是 mutation 变异1 抓到的那类错误）。

**④ 降级路径逐条触发**：未注入 / `enabled=false`（断言**一个 RPC 都不发**）/
IDE 断开 / RPC 抛异常 / 未知状态 —— 五条全部断言"照原样写"。

**⑤ 命令与输出**：

```
bun test ./packages/core/tests/ide/   → 70 pass / 0 fail
bun test ./packages/core/tests/tool/  → 986 pass / 0 fail（edit/write 无回归）
make build                            → 自检通过；grep "will always be undefined" 无命中
lint / format / lint:boundary         → 全绿（越界依赖 0 处）
```

**⑥ 尚未验证的部分，明确列出**：
- **真实 IDE 里 diff 是否真的弹出、用户手改是否真的被拾取 —— 没有验证过。**
  这需要装 `anthropic.claude-code` 扩展的环境。本 PR 的证据链止于
  「按 CC 扩展的 wire 协议回放响应时，用户版本会落到磁盘」。
  **这正是清单点名不许冒充的那一步**，所以在此显式声明未做。
- **30 分钟超时的真实长等待未跑过**（不值得等）；门禁断言的是常量值与它显著大于
  30s 默认值这件事。
- 我试过用 `--print` 跑一次真实端到端（无 IDE 时编辑行为不变），但那条路径需要真实
  模型调用且本次没有触达 edit 工具，**没有产生任何证据**，故不作为依据。
  "默认关时行为逐字节不变"这条由单测覆盖（断言零 RPC）。
