# monitor 的暂存行有了窗口冲刷，且四个终态出口统一走 finalizeAndDrain

## 决定了什么

修 review 文档《20261109-等待态四PR合入后review缺陷-修复与验收方案》的 D3（P0，来源 PR #683）。

三条修复，全部落在 `packages/core/src/task/monitor-task.ts`：

1. **暂存行不再只等「下一行」**：`MonitorRateGate` 新增 `msUntilWindowReset(now)` 与
   `flushDeferred(now)`；`spawnMonitorTask` 在 `admit` 返回 `defer` 时挂一个
   「窗口剩余时间 + 20ms」的定时器（`unref`），到点把暂存行作为**一条新事件**投递并开始新窗口。
   修复前，最后一个分片失败后脚本沉默到期限，这批行就一直不投递——R3 实测 `err7` 到期限时被整个丢掉。
   `admit` 里硬编码的 `60_000` 抽成 `NOTIFY_WINDOW_MS`，并加 `notifyWindowMs` 测试钩子（属 `MonitorGateLimits`，
   与既有的 `perMinuteNotifyLimit` / `totalNotifyLimit` 同一通道）。
2. **四个终态出口收敛到 `finalizeAndDrain(taskId, ctl, outcome)`**：close / error / stop（到期、突发阀、总量阀）/
   kill（`task_stop`、Ctrl+F、会话退出）共用。顺序是**先冲刷 → 再置 `finalized` → 写终态**：
   事件通知必须先于终态通知入队（先给现场「哪个分片失败」，再说「监控结束了」），
   `finalized` 必须最后置位（否则后续出口会因短路跳过冲刷）。
   四条路径里手写的 `ctl.finalized = true` 全部删除，`stopMonitorProcess` / `killMonitorTask`
   只负责「kill 进程组 + 转交」，`ActiveMonitor.stopReason` 这个随之失去读写点的字段也删掉。
3. **突发阀停止时也带现场**：`pushLines` 触发突发阀时把**触发这一批**的行先收进 `pendingLines` 再停
   （修复前 `recordLine` 在 `push` 之前 return，`seq 1 100` 一次到达时整批凭空消失，模型只看到「事件过密」）。
   `drainAll(lines, maxLines?)` 支持按场景指定上限：`rate_burst` 用 `MAX_BURST_FLUSH_LINES = 40`
   （与 `BURST_LINE_LIMIT` 同值——判定过密的那个量级本身即「够看的现场量」），保尾不保头，
   文案复用「前 N 行已省略，完整输出见 .output」（这些行是真的被省略，与 D18 的失实措辞不同）。

新增测试 9 条（29 pass），其中 6 条从真实入口进：`spawnMonitorTask` 真实子进程 × 4、
`new TaskStopTool().execute()` × 1、源码级收敛守卫 × 1。

## 放弃了什么（以及为什么不选）

- **把「窗口到期自动 emit」做进 `MonitorRateGate` 内部**：gate 是纯逻辑（可单测、无宿主依赖），
  定时器属于宿主。放进 gate 会让纯逻辑被迫注入时钟与调度器，等于把测试钩子扩散到每个 gate 用例。
  现在的切法是「gate 只回答剩余多久、怎么冲刷；宿主负责挂定时器」。
- **注入假时钟（`wait-registry.ts` 的 `__setMonoClockForTest` 那种）**：文档建议的做法是注入时钟，
  本次改用 `notifyWindowMs` 缩短窗口。理由：真实 `setTimeout` + 真实时间推进走的是生产同一条路径，
  少一套时钟注入面；测试耗时从 60s 降到 300ms，同样能在单测超时内完成。**差异已在此点明**：
  测的是「窗口到点会冲刷」这条逻辑，不是「60s 这个数字」。
- **不给 `flushDeferred` 的总量阀分支写测试**：`admit` 的 total 检查在最前、emit 会清空 `deferred`，
  所以「deferred 非空且 total 已满」实际不可达（写入的是防御性代码）。构造不出来的分支不做假测试；
  真正需要保证的是「总量阀停止时暂存行不丢」，那条由 `finalizeAndDrain` 的冲刷用例覆盖。
- **顺手做 D18（「…另有 N 条」与「共 N 条事件」的文案）**：D18 说的是「已合并进正文却写另有」的失实措辞
  与事件计数单位，属独立缺陷。本次只新增 D3 要求的「前 N 行已省略」文案，既有文案一个字没改。
- **顺手做 D15（`exit` 宽限与孙进程）**：它要改同一段生命周期（`close` 之外的第二个退出触发点），
  与本次「四出口收敛」叠加会让 review 分不清「冲刷」与「退出判据」两件事，单独 PR 更好回滚。
- **用 `ToolUseContext.agentId` 之类的外部信息决定终态文案**：`stopMonitorProcess` / `killMonitorTask`
  已经用 `outcome.kind` 显式表达来源，文案在 `finalizeMonitor*` 里按 kind 分派，不需要额外上下文。

## 拿什么证明它生效了

- **回归用例**（`packages/core/tests/task/monitor-task.test.ts`，29 pass / 0 fail / 208 expect）：
  - R3 迁入：`for i in 1..7; echo err$i; sleep 0.3; done; sleep 5` + 期限 3.5s →
    断言事件串含 `err7`，且 `err7` 事件的下标 **小于** 终态通知下标；
  - 窗口定时器：`perMinuteNotifyLimit: 1, notifyWindowMs: 300` + `echo err1; sleep 0.25; echo err2; sleep 5` →
    `err2` 在任务仍 `running` 时送达（不是退出 / 到期冲刷）；
  - `task_stop`：持续阀用满后等 350ms（`err7` 已 defer），`new TaskStopTool().execute()` →
    事件通知含 `err7` 且下标在 `killed` 终态之前、状态为 `killed`；
  - 突发阀：`printf '%s\n' $(seq 1 100)` 单次写（< PIPE_BUF，原子到达）→ 事件首行「前 60 行已省略」、
    含 `100` 与 `61`、不含独立行 `60`；
  - 收敛守卫：读源码文本，`ctl.finalized = true` 只允许出现在 `finalizeAndDrain`（唯一例外是测试辅助
    `__clearActiveMonitorsForTest`）。
- **变异自证**（每条都看红了哪条断言，然后恢复）：
  1. 删 `flushBatch` 里的 `scheduleDeferredFlush()` → 窗口定时器用例红（`status` 为 `completed`，
     说明 `err2` 只能等进程退出才送达）；
  2. 删 `finalizeAndDrain` 整段冲刷 → R3（`Expected "err7"` / `Received "err1…err6"`）、
     `task_stop`（`Received ""`）、突发阀（`Received ""`）三条红，窗口定时器仍绿——两个修复点各自独立被锁住；
  3. 把事件入队挪到写终态之后 → R3（`Expected: < 6` / `Received: 7`）与 `task_stop`
     （`Expected: < 0` / `Received: 1`）的顺序断言红；
  4. 突发阀分支不收集本批行 → 突发阀用例红（`Received ""`）；
  5. 在 `stopMonitorProcess` 里手写一句 `ctl.finalized = true` → 收敛守卫红（`sites` 多出 `stopMonitorProcess`）。
