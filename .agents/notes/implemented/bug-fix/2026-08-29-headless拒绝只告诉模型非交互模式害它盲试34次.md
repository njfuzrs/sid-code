# headless 拒绝只把「非交互模式」告诉模型，害它盲试掉 34/66 次工具调用

## 决定了什么

**一、修 agent 本身（本次主体）。** `packages/core/src/permission/checker.ts` 非交互
`ask → deny` 分支的 `decisionReason.reason` 从写死的 `"非交互模式"` 改成带上真实成因
（`result.reason`）并显式说破「重试相同输入不会改变结果」。

关键点是**这个字段就是模型看到的那句话**：`query/tool-executor.ts` 用
`explainDecision(decision)` 拼 tool_result，而它**优先读 `decisionReason`**，
`decision.reason` 只在前者缺失时兜底。于是那条带成因的长文本**只进审计日志、从不进对话**，
模型收到的是 `权限拒绝: 拒绝 — 非交互模式` —— 一句不含任何可行动信息的话。

`decision.reason`（进审计日志的那个）**刻意不动**：A11 那份复算就是从它取的，
改它会让历史轨迹与新轨迹不同口径。

**二、补第六棒交接里的缺口 A**（`.py` metadata 丢键）：`sid_code_agent.py` 补
`sid_num_turns_without_model_interaction`，并在 `tests/eval/harbor-agent-contract.test.ts`
的 L1 加一条**通用形态门禁** —— result 事件 schema 上的每个字段都必须被 metadata 消费
或进显式豁免白名单。拦的是形态不是这一个字段。

**三、`evals/external-benchmarks/harbor/analyze-step-divergence.py`**：把两侧轨迹拉平成
「第 N 步 → 做了什么」的对照脚本（深挖用，$0，不跑评测）。

## 放弃了什么（以及为什么不选）

- **⛔ 放宽 injection 启发式 / 给 heredoc 开豁免。** 8 次拒绝来自
  `obfuscated-flags`（heredoc 正文里的 Python 三引号 `'''`、探测命令里的 `echo "---"`）
  与 `brace-expansion`（Perl 正则量词 `{1,3}`）——**这些确实是误报**，但改判据是拿
  「更安全」换「更准」，而三条真攻击载荷实测仍被这些规则拦住
  （`git diff {@'{'0},--output=...}` / `find . ''-exec` / `ls $'\x2d\x2drf'`）。
  **先把墙照亮，再决定要不要拆墙** —— 照亮零风险，拆墙要单独论证。留给下一棒。
- **⛔ 加循环检测。** 记忆里那条已定案（默认全局关闭，shape 误判≈100%）。
  这两题重复最多 2 次，**根本不在原地打转**：每一步都是新动作，只是都在试探一堵
  看不见的墙。循环检测在这里一次都不会触发。
- **⛔ 改用 `--dangerously-skip-permissions` 让评测跑顺。** 那是把要测的防线关掉，
  且 L1 门禁明文拦这个字符串。分数会涨，测的东西变了。
- **⛔ 只补 metadata 那一行，不加通用断言。** 第六棒就是这么掉的（缺口 A），
  只补一行的话下一个新字段还会掉在同一条跨语言边界上。
- **⛔ 顺手跑一次真实评测验证。** 需重编两个架构的 linux 二进制 + 4 小时 + $7，
  且缺口 B 未解（`SID_HARBOR_BINARY_*` 还指着第五棒的字节）。**本次只交付可静态
  自证的部分**，真实 run 留给下一棒 —— 见下面「尚未证明的部分」。

## 拿什么证明它生效了

**根因定位用的是权威源，不是推断。** 三处取数都指到源字段：

1. `logs/permissions-audit.log`（每题 33 行）给出**成因分类**，不是我猜的：
   两题合计 **34/66 次调用被拒（52%）**，成因是三类语义完全不同的东西 ——
   `21× 白名单外需确认` / `8× injection 启发式` / `3× 写入路径在工作区外`。
2. **把 28 条真实被拒命令回灌进真实启发式**（`validateObfuscatedFlags` /
   `validateBraceExpansion`），8/28 命中，逐条对上 audit log 的分类。
3. **实测代价**（逐轨迹复算）：环境探测型动作占 30%（`polyglot`）/ 39%（`regex-log`）；
   同一条 heredoc **原样重发两次**（步 2/3、8/10）；往 `/tmp` 写 9 次、**9 次全拒**
   却从未被告知「`/tmp` 在工作区外」。对照 mini-swe-agent **8 步提交**
   （`exit_status: Submitted`），我们 33 次调用撞满 `--max-turns 40` 未解出。

**修复前后，同一条真实调用在模型侧的差异**（走真实 `PermissionChecker` +
`explainDecision`，配置照 Harbor agent：`print` + `maxTurns 40` + `acceptEdits`）：

```
修复前： 权限拒绝: 拒绝 — 非交互模式                      （三类成因逐字相同）
修复后： 权限拒绝: 拒绝 — 非交互模式下自动拒绝（无人可确认，重试相同输入不会改变结果）：
           [injection:obfuscated-flags] 命令包含带引号的 flag…
           / 写入路径在工作区外: /tmp/test_regex.pl
```

**变异自证 4 处，每处都确认「红的是哪一条」**（本仓硬要求；这三处「测试全绿」本来就成立过）：

| 变异 | 结果 |
| --- | --- |
| `decisionReason` 改回 `"非交互模式"` | 4/5 fail，且 `new Set(seen).size` **3 → 1**（三类成因塌成一句） |
| 删掉 `.py` 那行 metadata | L1 精确点名 `dropped = ["num_turns_without_model_interaction"]` |
| **给 `schemas.ts` 加一个 Python 不消费的新字段** | L1 点名 `["some_brand_new_field"]` ← **证明它拦的是下一个字段，不只是这一个** |
| L1 抽键缩进改错（抠出空集） | `keys.length >= 9` 翻红（防门禁绿着失效） |

变异全部在 tmpdir fixture 或改完即还原，**`shasum -a 256 -c` 逐个核过复原**。

**门禁**：`affected-tests:run` **1680 pass / 0 fail**（77 文件）、`make build` 通过且
产物自检 5 项全绿、`lint` / `format:check` / `lint:boundary`（越界 0 处）全绿。

**⚠️ 尚未证明的部分（不许当成已验证）**：本次**没有跑真实 Harbor 评测**。
「34 次被拒 → 变少」「0.100 → ?」**全部未验**，只证明了成因已送达模型。
真实验证要先解第六棒交接的**缺口 B**（重编两架构 linux 二进制，核
`sid_commit == artifact-bytes`），否则跑出来与第五棒逐字节一样。
另外顺带发现一处**分析脚本自己的判据 bug**并已修：分类正则写成 `\b(...|<<\s*'?EOF)`
**恒不匹配**（`\b` 落在空格与 `<` 之间，两侧非单词字符），于是所有 heredoc 写文件
被误报成「在看文件」—— 不报错、占比表照出，只是语义整体错位。
