# 能力自愈只作用于本次请求，不写回模型属性

## 决定了什么

按方案 §5.3（F3 b/c）收口「运行时观测改写模型固定参数」这一类设计，三处一起改：

1. **b：从报错学 `maxOutputTokens` 改为只影响本次请求**。
   `model-capabilities.ts::learnFromError` 第 2 段不再 `mergeEntry` + `persist`，
   改为返回 `HealAdvice.clampMaxTokens`；`openai.ts` 的流式 `withCapabilityHealing`
   与非流式 `sendMessageNonStreaming` 把这个值钳到**本次** `max_tokens` 后重发一次，
   下一次请求回到正常预算。`max_tokens` 超区间的归因优先于 effort 自愈——
   这条错误剥 effort 重发会带着同一个非法 `max_tokens` 再失败一次。

2. **c：effort 记账改为 `(真名, baseURL)` 的进程内表**。
   删除 `recordEffortRejected`，新增 `recordEndpointEffortRejected` /
   `isEndpointEffortRejected`（`model-capabilities.ts`，端点键走 `normalizeBaseURL`）；
   `recordHealOutcome` 增加 `baseURL` 参数，结构兜底的「连续 3 次」也按端点计；
   `effort.ts::resolveFromCapabilityCache` 在查按模型名的能力缓存**之前**先查端点表。
   不再写 `effortValues: []`、不再写 `supportsReasoning: false`、不落盘、进程退出即失效。

3. **删除 `learnedOutranksCatalog` 及配套**。
   `LEARNED_PRECEDENCE_MS` / `LEARNED_FIELDS` / `restoreLearnedFields` / 两处调用
   （`persist()` 的跨进程合并、`mergeEntry()` 的进程内合并）全部删除。自愈不再写回后，
   这条「healed/probe 7 天压过目录」的优先级只剩探针一个输入；目录是模型属性的上游事实，
   一次主动探测不该在 7 天内压过它。

## 放弃了什么（以及为什么不选）

| 被放弃的方案 | 为什么不选 |
|---|---|
| 保留写盘，只把 TTL 从 7 天缩短 | `[1, N]` 与「这条路由不吃 effort」本来就是一次请求 / 一条路由的结论，不是模型属性。TTL 只改变错误结论的存活时长，不改变它是错的。 |
| b 只删除写回、不实现「本次请求钳制重发」 | 会净退化成「第一次撞区间就失败」，把已有的一次自动恢复拿走。F1 修好后默认预算 32k 基本不会再触发，但这条路径必须保持可用。 |
| c 继续按真名记账，只把落盘改内存 | 同一条真名走两条网关路由是两套行为；按真名记会让一条路由的 400 关掉另一条正常路由的 effort（这正是 F2 的同一种错误）。 |
| 保留 `learnedOutranksCatalog` | 它防的是「自愈刚学到的结论被目录一天后冲掉」，而自愈不再产生这类结论。为探针单独保留一层优先级，等于给「一次观测压过目录」留后门。 |
| 靠 `availableModels[].compat.supportsReasoningEffort: false` 取代自愈 | 那是用户显式声明，不是自动学习。它保留为「想彻底消除首次 400」的入口（`model-compat.ts:74`），不能替代默认行为。 |

## 拿什么证明它生效了

- 相关单测：`bun test` 六个 llm 文件 184 pass / 0 fail；三项变异恢复后三文件 106 pass / 0 fail。
- 选测：`bun run affected-tests:run` → `bun test ./packages/core/tests/llm/` 2210 pass / 1 fail。
  唯一失败是 `errors.test.ts` 里扫全 `src/` 的静态门禁用例 5496ms 超过 bun 默认 5s 超时；
  该文件单跑 64 pass / 0 fail，且不 import 本次改动模块——是慢 runner 上的已知 flake。
- **变异自证 3 项**（都做了「改坏 → 红 → 恢复 → 绿」）：
  1. 把 `recordEndpointEffortRejected` 改回 `mergeEntry` + `persist` → 4 个用例红
     （不写缓存 / 换端点仍乐观 / 不跨进程 / 结构兜底 3 次不落盘）。
  2. 把 `learnFromError` 第 2 段改回写 `maxOutputTokens` → 「只给本次请求的钳制上限，
     不写回模型属性」红。
  3. 在 `mergeEntry` 加回「healed 压过目录」→ T2「healed 的档位结论被目录同步覆盖」红。
- 门禁：`typecheck:gate` 62 处 / 基线 64（无新增）；lint、format:check、lint:boundary、
  lint:command-system、lint:legacy-tool 全过；`make build` 通过且构建输出无
  `will always be undefined`（新增导出已在 worktree 自己的 `node_modules` 里解析）；
  `bun run smoke` 26/26。
- 未跑全量 `bun test`：`affected-tests` 判定为 selective（1 个目标），且本 worktree 路径下
  全量已知会挂；补偿是 CI 在合并前跑全量。

**为什么之前没拦住**：b/c 的旧行为是被**当成正确锁进测试**的
（`capability-healing-attribution.test.ts` 的 T2 整块、`capability-wiring-regression.test.ts`
的记账用例）。这是「测试锁住了错误的设计」而不是「缺少测试」，所以本次是改期望 +
补反漂移断言（不写缓存、不跨进程、换端点仍乐观、目录覆盖学习值），不是新增一个原本不存在的用例。
