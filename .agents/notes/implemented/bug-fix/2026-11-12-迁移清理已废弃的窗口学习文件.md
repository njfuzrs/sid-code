# 迁移 v8 删除已废弃的 `learned-input-ceiling.json`，收回 S6 写进老用户磁盘的错误窗口值

## 决定了什么

新增迁移 v8（`packages/core/src/migrations/remove-learned-input-ceiling.ts`），删除
`~/.sid-code/learned-input-ceiling.json`。

背景：S6「运行时学习已放行输入上限」把「输入 + `max_tokens=384000` 撞 1,048,576」的 400
误判成「窗口只有 664k」，落盘覆盖注册表窗口（Footer 放大 1.5 倍、有效上下文损失约 1/3）。
PR #770 已整体删除 S6 的读写点，**代码侧不再有任何地方读这个文件**，但已经写进用户磁盘的
那份还在：排查时会误认为它仍生效，回滚 #770 时 664k 会立刻复活。

改代码只影响新装用户，已落盘的只能靠迁移收回 —— 与 v6（`remove-team-default-trace-upload`）
完全同型，所以放进同一套水位线，只跑一次。

**判据刻意保守（宁可漏删，不可错删）**：只认 S6 自己写出的那一种形态才删 ——
顶层 `schema_version === 1`；`entries` 是非空对象；**每一条**都同时带 `ceiling` /
`maxAdmitted` / `overflows` 三个有限数字。任一条不满足就原样保留（可能是用户手写的同名
文件，或将来别的功能复用这个文件名）。空 `entries` 也保留：S6 的写入路径只加条目、不产出
空对象。

不写 stderr：这是清理我们自己写错的运行时数据，用户无需做任何事，告知只是噪音。
（v6 写 stderr 是因为它涉及「轨迹曾被静默上传」，用户有权知道，性质不同。）

## 放弃了什么（以及为什么不选）

| 被放弃的方案 | 为什么不选 |
|---|---|
| 不删，留成孤儿文件（方案 §5.2 的原始结论） | 运行时确实无害（读取点已删净），但排查时会被误认为仍生效；回滚 #770 会立刻复活 664k。当初的理由「不删非自己创建的文件」是对 agent 工作区的约束，不适用于**产品收回自己写错的运行时数据**（v6 已开先例）；「一次性迁移会成为长期负担」也不成立——迁移框架就是为一次性动作存在的，水位线保证只跑一次 |
| 挂到 `startup-housekeeping.ts` 的过期数据清理 | 那是按「清理水位线节流 + 定期 GC」设计的，会**反复**扫描；本动作只需一次。而且 housekeeping 不做「删用户目录里的具体文件」这类判断，判据逻辑放进去反而更难测 |
| 直接 `rm`、不加判据 | 会把用户手写的同名文件一并抹掉。删错了是「用户数据被静默删除」，比留一个孤儿文件严重得多，风险不对称 |
| 启动时无条件删，不走迁移水位线 | 每次启动都做一次无意义的 fs 检查；且没有版本记录，将来想审计「哪台机器执行过」无从查起 |

## 拿什么证明它生效了

- **单测 15 pass / 0 fail**（`packages/core/tests/migrations/remove-learned-input-ceiling.test.ts`）：
  正向 4 个（真实 S6 形态、多 entry、文件不存在、幂等），反向 9 个（缺 `schema_version`、
  别的版本号、空 entries、缺字段、字符串冒充数字、entries 是数组、JSON 损坏、顶层是数组、
  NaN/Infinity），判据纯函数分支 3 个。
- **变异自证**：把 `isLegacyLearnedCeiling` 首行改成 `return true` 后重跑 —— 9 个反向用例
  全部变红（`6 pass / 9 fail`）；恢复后回到 `15 pass / 0 fail`。
- **迁移目录整体回归**：`bun test ./packages/core/tests/migrations/` → 80 pass / 0 fail
  （含 v1–v7 既有用例与 `no-stdout-writes` 门禁；新迁移不写 stdout）。
- **选测**：`bun run affected-tests:run` → 判定 selective，命中
  `./packages/core/tests/migrations/`，执行后 80 pass / 0 fail。
- **lint / format**：`bun run lint` 0 warning 0 error；`bun run format:check` 通过。
- **typecheck:gate**：父仓 `main` 上 62 处 / 基线 64 处，无新增；本次改动的两个文件零类型错误。
  （worktree 里该门禁报 88 项 `packages/tui` 缺依赖，属 node_modules 软链环境问题：
  ①不 import 本次改动的模块 ②父仓 main 上通过 ③成因是 worktree 软链到主仓、
  主仓未装 tui 外部依赖。三条齐备，与本次改动无关。）
- **本机实测**：删除前把文件备份到 `/tmp/learned-input-ceiling.json.bak-*`，删除后用
  #770 构建的二进制跑会话，`~/.sid-code/learned-input-ceiling.json` 未被重建。
