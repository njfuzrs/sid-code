# 配额与预算规则：超限每轮都拦，budgetRules 与 costLimit 同口径、按本地时区分周期、随 /clear 重置

## 决定了什么

修 4 项缺陷（核对官网 `website/team/quota.md` 时发现，2026-10-22）：

1. **超限只拦一次（P1）**：硬停判定与告警去重拆成两个判据。
   - `costLimit`：硬停只问 `QuotaManager.isExceeded()`，`check()` 只负责告警去重与文案。
   - `budgetRules block`：硬停只问新增的 `BudgetTracker.findBlockingRule()`，`recordTurn()` 的返回值只用于播报。
   - 主循环在**发请求前**也问一次（`checkPreRequestBudgetStop`），超限后用户再发消息不会先烧一次调用。
   - 文案区分「刚超限，自动停止」与「本会话已超限，仍拦截」，不每轮重复同一句。
2. **budgetRules 不计影子调用（P2）**：主循环改调 `recordTurn(getEffectiveTotalCostUSD(), thisCost, {model})`，
   按会话有效总花费的**增量**入账，与 costLimit 同口径。增量里属于本次主调用的部分带 model，其余不带 model
   （只进不限模型的规则）。resume 用 `hydrateSessionBaseline` 设基线，防止历史花费被当新钱再记一遍。
3. **周期键按 UTC（P2）**：`budgetPeriodKey` 按本地时区算；`weekly` 改 ISO 周（周一开始，`2026-W44`）。
   告警去重键从 `rule.id` 改为 `rule.id:periodKey`，daily/weekly 翻周期后能重新告警。
4. **/clear 不重置 budgetRules（P3）**：`clearConversation` 补调 `resetAlertLevels()` 与新增的 `resetSessionPeriod()`。
   第 1 项让硬停每轮都问，不清 session 累计的话 /clear 后第一条消息就会被拦，所以两项必须同 PR。

方向：**更安全**（花费上限从「提醒 + 停一次」变成真硬上限）。牺牲：超限后交互模式每条消息都被拦，
用户只能调高上限或 /clear；这是上限的本义，可接受。

## 放弃了什么（以及为什么不选）

- **按缺陷文档建议拆两个 PR（1 单独、2/3/4 合并）**：第 4 项依赖第 1 项（硬停改每轮问之后，/clear 必须清 session 累计），
  拆开后先合的那个 PR 会让 /clear 后立刻被拦，不满足「能独立上线」。四项都在同一对文件、一次 review 完，合成一个。
- **辅助调用记账时由 side-call 观察者直接调 `budgetTracker.recordCost`**：子代理 usage-sink、作废重试、billing-sink
  兜底是另外三条入账路，挂在 side-call 一处仍有漏；而且告警升级会在观察者里被「消费」掉，主循环看不到。
  改为在主循环按 `getEffectiveTotalCostUSD()` 的增量记账，所有入账路自然汇齐，且不会双记。
- **辅助调用增量按模型拆分以匹配 `scope.model`**：增量来自多条入账路，拆不出模型就不猜；宁可 scope.model 规则少算，
  也不把别的模型的钱记到它头上。官网已写明。
- **配置项 `timezone`**：没有用户提过，本地时区就是用户理解规则的口径；需要时再加。远程预算 `period_key` 由服务端给，不受影响。

## 拿什么证明它生效了

- 新增 `packages/core/tests/telemetry/budget-block-every-turn.test.ts`（17 例，`TZ=Asia/Shanghai`），全绿。
- 变异自证（逐个改坏后恢复），各自对应断言变红：
  - `findBlockingRule` 改成依赖告警去重 → 4 fail（含「exceeded 后每轮仍命中」）
  - `isExceeded` 恒 false → 1 fail（costLimit 第二、三轮仍拦）
  - `recordTurn` 只记主调用 → 3 fail（影子调用口径）
  - 周期键退回 UTC / epoch 周 → 4 fail
  - `resetSessionPeriod` 空实现 → 1 fail
- 既有 `cost-attribution` / `quota*` / `remote-budget` / `clear-rotates-session-wiring` 测试不改仍绿。
