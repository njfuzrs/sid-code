# `--add-dir` 改为追加工作目录：工作目录集合 = 工作区 ∪ 白名单

## 决定了什么

`PathValidator` 的白名单判据从「在白名单内」改成「在工作目录集合内」（工作区 ∪ 白名单），
新增 `isWithinWorkingDirectories()`，并把写边界（第 5 步）与 symlink 逃逸检测（第 4 步的两处判据）
一起切到这个集合上。白名单从此是**追加**语义，与三处既有文案（`help.ts` 的「追加可访问目录」、
`config.ts:299`、`website/ref/settings.md`）终于一致。

改动的行为面：

- 白名单非空时，工作区不再被挤出：读写都回到 allow（修复前是硬拒，`needsConfirmation` 未设、不转确认）。
- 追加目录（`--add-dir` / `/add-dir` / 用户级 settings）**可写且不再需确认**，对齐 Claude Code
  「additional working directories 可读也可编辑」。**这是本次唯一的安全面放宽**，且只对用户在
  CLI 参数 / 斜杠命令 / 用户级配置里显式授权的目录生效；项目级 settings 仍被 `security.ts` 禁止扩大。
- `/add-dir --list` 把工作区列在第一行并标「（工作区，始终可访问）」，空白名单时也列。
  为此给 `PathValidator` 加 `getWorkspacePath()`、`PermissionChecker` 转发同名方法。
- 顺带修根目录前缀拼接：抽出 `isPathWithinDir()`，目录为 `/` 时不再拼出 `//`。
  `--add-dir /` 从「永远不生效」变成真生效；`blockedDirectories: ["/"]` 从 fail-open 变成真拦截。

## 放弃了什么（以及为什么不选）

1. **在 `cli.ts` 里把 cwd 自动塞进 `allowedDirectories`。** 只修 `--add-dir` 一个入口：
   `/add-dir` 在空白名单会话里照样会把工作区锁掉，用户级 settings 也一样，
   而且 `/add-dir --remove <cwd>` 能把工作区移出去、又回到原问题。修在 `PathValidator` 才是唯一事实源。
2. **保留现状，在文档里写「需要同时 `--add-dir .`」。** 三处文案都得改成反直觉的说法，
   子代理与 `/add-dir` 场景下用户几乎不可能想到。
3. **顺便把「白名单为空时工作区外可读」收紧成需确认，完全对齐 Claude Code。**
   方向对，但影响面是所有用户的所有会话；无头模式下「需确认 = 拒绝」，会让大量现有流程变红。
   按 CONTRIBUTING「P0 修复不由加固项决定上线时机」，这条单独记录、不绑进本 PR。
4. **不改 `canAutoAllowFsCommandInAcceptEdits`（`checker.ts:747`）。** 它的语义是
   「bash 命令参数都在 cwd 内才在 acceptEdits 下自动放行」，与「可访问目录集合」是两个概念；
   放宽它会让 `mkdir /tmp/x` 这类命令在 acceptEdits 下静默放行，属于另一个安全面。
5. **不顺手把黑名单判据也改成按真实路径集合判断**（只复用拼接 helper）。
   黑名单的语义本来就是「禁止这些目录」，与工作目录集合无耦合，改动面越大越难回滚。

## 拿什么证明它生效了

- 新增 `packages/core/tests/permission/add-dir-additive.test.ts`（16 个用例）全绿：
  工作区读写、追加目录读写、集合外拒绝、追加目录内 `.env` 仍硬 deny、根目录白名单两条
  （`--add-dir /` 生效 + 写 `/etc` 落在系统目录保护上，断言 reason 含「系统目录写入被拦截」）、
  symlink 两向（工作区→追加目录不判逃逸；追加目录→区外→回集合内仍判逃逸）、
  `PermissionChecker` 层 `addAllowedDirectory` 前后读工作区、派生子代理 checker 继承白名单。
- **变异自证 5/5**（改坏 → 断言变红 → 恢复，恢复后逐字节校验一致）：
  第 2 步改回只查白名单 → 工作区读/写 + checker 两条用例变红；
  第 5 步改回 `isWithinWorkspace` → 「追加目录可写」变红；
  第 4 步入口条件改回 `isWithinWorkspace` → 「从追加目录出发…仍判逃逸」变红；
  第 4 步链路判据改回 `isWithinWorkspace` → 「工作区指向追加目录的 symlink 不判逃逸」变红；
  前缀判定去掉根目录特判 → 根目录两条 + 黑名单根目录变红。
- 既有用例 `enhanced.test.ts` 的「白名单外拒绝访问」语义不变（`allowedDirectories: [cwd]`），
  只有 reason 文案断言随语义同步（「不在白名单中」→「不在可访问目录中」）。
- 端到端（`sc-dev`，本 PR 完成后在采集台回证）：`--add-dir <除 cwd 外的目录>` 下读自己仓库不再被拒，
  P1v 的 `perm_nonallow` 里不再出现路径白名单拒绝。
