# 任务规划：修掉 P2-1 / P2-2 / P2-3 / P3-1 / P3-2（plan 启动路径、零消费承诺、保真度虚报、路径生命周期、子代理重注）

## 决定了什么

修掉 `20260926-任务规划-顺着sc-05-plan核出的缺陷.md` 剩下的五条（P0/P1 已由 PR #114 落地）。

- **P2-1 `--permission-mode plan` 进状态机**：`PlanModeManager.syncWithPermissionMode()`，
  App 在每个用户回合开始（TUI 与 headless 两处，紧跟 `endExecution()`）调它。
  放在回合开始而非构造函数，是因为 CLAUDE.md 规则在 `init()` 里才改 permissionMode，运行中重载也会改。
  同时把「进入前的模式」收成**唯一事实源** `planManager.prePlanMode`：删掉 App 的
  `_originalPermissionMode` 和 checker 的 `prePlanMode/setPrePlanMode/clearPrePlanMode`；
  `EnterPlanModeTool` 通过 getter 拿真实模式传给 `enter()`（从前传 `undefined`）。
  提醒 `buildPlanModeReminder(full, planFilePath)` 带上计划文件路径——这条入口从没收到过
  `enter_plan_mode` 的 tool_result，模型不知道往哪写。
- **P2-2 删掉三处零消费声明**：`exit_plan_mode` 的 `allowed_prompts`（含「一并审批」的 describe）、
  `PlanModeManager.get/setAllowedPrompts`、`PermissionSync.preApprove`、
  `shouldPlanInheritBypass` 与 checker 里输入恒空的「plan 继承 always-allow」分支。
- **P2-3 保真度匹配**：参数锚定从「可选」改为「必要」；只取参数**值**不取键名；
  候选中取锚定分最高者，同分优先尚未命中的步骤。
- **P3-1 路径生命周期**：不变量 `getPlanFilePath() !== null ⇔ isActive() || isExecuting()`。
  `forceExit()` 清路径（事件里仍带退出前的路径）；`reject()` 超限改走 `forceExit()`；
  `endExecution()` 仅在非规划态清路径（它每个回合都会被调，规划中途清会丢计划）。
- **P3-2 子代理刻意不接计划重注**：在 `sub-agent.ts` 两处 `ContextManager` 构造旁写明理由；
  博客 §13.4「我没找到」加一段更正（主代理已接线、子代理刻意不接）。

## 放弃了什么（以及为什么不选）

- **P2-2 接活 `allowedPrompts` → session allow 规则**：声明是「运行测试」这类语义短语，
  映射不成可安全匹配的规则；硬映射要么匹配不到（仍是空承诺），要么放得太宽。文档给的二选一里取「删承诺」。
- **P2-2 接活「plan 继承 always-allow」**：会让 always-allow 用户的计划模式变成全放行，
  把「计划模式只读」这条硬保证变成条件性的——这是权限放宽，不该以修死代码的名义顺手打开。
  加了一条反向断言锁住「从 always-allow 进入 plan，写普通文件仍被拦」。
- **P2-1 在构造函数 / cli.ts 启动时调一次 `enter()`**：错过 CLAUDE.md 规则与运行时重载改成 plan 的情形。
- **P2-3 保留「无锚定也算」但降权**：保真度报告的价值在于认出计划外调用，虚报比漏报更糟；
  代价是中文无空格、写不出锚定 token 的步骤现在记为 off-plan。模块仍是生产零调用，未接线。
- **P3-2 透传主代理 provider 给子代理**：explore/plan 等只读子代理压缩一次就被灌整份主计划，
  既占窗口又会诱导它做别的步骤。以后要做，应传「本子任务对应的那一段」。
