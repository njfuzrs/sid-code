# ↑/↓ 历史不再回显斜杠命令，翻历史期间不弹补全

## 决定了什么

PR #215 让 ↑/↓ 能跨会话翻历史后暴露出两个问题，本次一并修：

1. **斜杠命令不进 ↑/↓ 历史。** 翻回 `/model` 时行首 `/` 立刻弹出补全列表，补全列表接管 ↑/↓
   （历史翻不动），回车则选中补全项直接执行，打开模型弹窗，用户出不来。
   - `packages/cli/src/command/parser.ts` 新增 `isSlashCommandInput()`（纯字符串判定）。
   - `text-buffer.ts` 的 `reset`：提交斜杠命令时不推进本会话 history。
   - `useInputHistoryStore.ts`：启动时灌入 ↑/↓ 的 `projectHistory` 过滤掉斜杠命令。
   - history.jsonl 照常写，`Ctrl+R` 反向搜索仍能搜到命令（只改 ↑/↓ 这一条消费路径）。
2. **翻历史期间（`historyIndex ≥ 0`）不弹补全。** 普通历史条目末尾若是 `@path` 或 ` /cmd`，
   补全同样会弹出并吃掉 ↑/↓ 和 Enter。`InputArea.tsx` 的 `hasSuggestions` 加上
   `historyIndex < 0` 条件；用户一打字 insert 就把 `historyIndex` 清回 -1，补全恢复。

## 放弃了什么（以及为什么不选）

- **写盘时就不记斜杠命令**：会让 `Ctrl+R` 搜不到用过的命令，且丢掉了已写入的数据。只在 ↑/↓ 侧过滤更窄。
- **翻到斜杠命令时保留但不弹补全**：只靠第 2 条也能解开锁死，但对齐 CC 的体验是 ↑ 翻的是"说过的话"，
  命令回显出来仍容易误回车执行（如 `/clear`）。两条一起做。
- **用命令注册表精确判定**：reducer 拿不到命令列表；代价是 `/tmp` 这类单段路径也被当命令、不进 ↑ 历史，可接受。

## 拿什么证明它生效了

- `packages/cli/tests/ui/hooks/input-history-arrow-persist.test.tsx` 新增用例：提交 `/model`、`/model opus`
  不进 history，`看下 /tmp/a.log` 照常进；history.jsonl 含 `/model` 时 `projectHistory` 不含、全局 history 仍含。
- `bun run affected-tests:run`：2274 pass / 0 fail；`make build` 通过、无 `will always be undefined` 警告；
  `bun run lint`、`lint:boundary` 全绿。
- 第 2 条（翻历史不弹补全）没有组件级按键测试，靠代码路径保证，需在真实 TUI 里手动验证一次。
