# /plugin 无参打开交互管理面板，/plugin list 强制进输出面板

## 决定了什么

- `/plugin`（及别名 `/plugins`）无参时返回 `{ kind: "dialog", dialog: "plugins" }`，打开新增的
  `PluginsDialog`（`packages/cli/src/ui/components/PluginsDialog.tsx`），与 `/mcp`、`/skills` 同模式：
  列表 → 单插件菜单（查看详情 / 启用 / 禁用 / 检查更新 / 卸载）→ 详情，Esc 逐级返回。
- 面板动作直接调 `/plugin` 子命令背后的同一套函数（`operations.ts` / `market-operations.ts`），
  不另写逻辑；改完不自动 reload，与文本子命令一致，在反馈行提示 `/reload-plugins`。
- 内置插件只给「查看详情」；只有带 `marketplace` 的插件给「检查更新」；面板卸载不删文件。
- `/plugin list` 结果显式带 `panel`，不再受 `PANEL_MIN_LINES`(3) 约束。
- `DialogType` 新增 `"plugins"`，`DialogSwitch` 接上分支。
- 文档：`website/extend/plugins.md` 补面板说明，并更正「没有插件市场」的过时描述。

根因：无参落到 list 文本，只装 1 个插件时结果 2 行 < `PANEL_MIN_LINES`，
被 `command-result-route.ts` 路由到状态栏，一闪而过，用户既看不全也无法管理。

## 放弃了什么（以及为什么不选）

- **只给 list 加 `panel`、不做交互面板**：能解决「一闪而过」，但只读文本面板里仍不能启停 / 卸载，
  用户要记住插件名再敲子命令。用户诉求是「像 /mcp 一样查看和管理」，只修显示不够。
- **全局降低 `PANEL_MIN_LINES`**：会让所有声明了 `outputPanel` 的命令的一两行回执也弹面板、
  要按 Esc，`ui/CLAUDE.md` 明确否决过这种做法。
- **面板动作后自动 `/reload-plugins`**：面板拿不到 `AppContext` 里的注册表 / hookSystem / mcpManager，
  要为此扩 `TUICallbacks`；且与文本子命令行为分叉。先保持一致，提示用户手动 reload。
- **CLI `sid-code plugin` 无参也开面板**：无头路径不启动 TUI，`plugin-cli.ts` 无参先打印用法，保持不变。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/ui/components/PluginsDialog.test.tsx` 等 4 个文件：52 pass / 0 fail。
  其中整帧用例在 PassThrough stdin 里走完「列表含 demo-plugin@2.3.4 → Enter 菜单 → Enter 详情含路径
  → Esc ×3 关闭」；「list 只有一个插件也带 panel」用例断言结果行数 < 3 且 `panel` 已定义。
- `bun run affected-tests:run`：2685 pass / 9 skip / 0 fail。
- `make build` exit 0，自检通过，无 `will always be undefined`。
- 未在真 pty 里手动点过面板，需维护者用 `sc-dev` 敲一次 `/plugin` 复核。
