# Hook 系统对齐 Claude Code 的格式与语义：CC 的 hooks 段原样可用

## 决定了什么

按 `20261003-Hook系统-对齐CC格式与语义-方案设计.md` 的 §四 批次 1–6 一次做完（一个 PR，七个提交）：

- **批 1 加载与格式**：单一归一化层 `hook/config-normalize.ts`，嵌套 `{matcher, hooks:[...]}` 与平铺都认；
  按来源分层注册（managed / user / project / local），信任门只摘项目级、不再连带清空用户级（HC1–HC6）；
  `sid-code hooks list [--json]` 输出实际注册表与被跳过条目的原因。
- **批 2 匹配与名字**：`tool/tool-name-aliases.ts` 一张别名表，matcher 三档（精确 / 正则 / 全部）认 CC 名；
  外部 handler 的 stdin `tool_name` 发 CC 名，另带 `sid_tool_name`（HC8–HC10，Q1）。
- **批 3 环境与载荷**：导出 `CLAUDE_PROJECT_DIR`（固定为启动项目根）/ `CLAUDE_PLUGIN_ROOT` / `CLAUDE_PLUGIN_DATA`，
  命令串不再做字符串替换；补 `permission_mode` / `transcript_path` 等通用字段；缺省超时照 CC，
  SessionStart 单独 30s；`--trust-workspace`（HC11–HC14、HC20，Q2/Q3/Q5）。
- **批 4 输出语义**：SessionStart / UserPromptSubmit 的纯文本 stdout 进上下文，additionalContext 走独立
  `<system-reminder>` 不拼进用户原文，SessionStart 改 await，PostToolUse 的 exit 2 / block 回灌模型（HC16–HC18）。
- **批 5a**（Q7）：工具失败只发 PostToolUseFailure、权限拒绝只发 PermissionDenied；session-metrics、
  trace collector、telemetry probe 改订阅对应事件（HC23）。⚠️ 口径变化：工具失败率的分子**不再含权限拒绝**
  （拒绝 span 只标 `sidcode.tool.status=denied`、不带 `sidcode.success`，2026-10-07 残留回补补正），拒绝另见权限决策（B11）。
- **批 5b**：接线 8 个「预留」事件（CwdChanged / TaskCreated / TaskCompleted / StopFailure / Notification /
  ConfigChange / Elicitation / ElicitationResult），新增 PostToolBatch / PreModelSwitch / PostModelSwitch /
  UserPromptExpansion / DirectoryAdded（HC24/HC25，Q6）。内部 span 事件写进用户配置时跳过并告警（HC26）。
- **批 6 文档与迁移**：`team/migrate.md`、`extend/hooks.md`、`ref/glossary.md` 按修完后的行为重写，
  新增「与 Claude Code 的差异」表（§三.10）；迁移 skill 从「展开成平铺 + 替换 token」改为**原样复制**，
  只需处理 `.claude/` 下脚本的路径（HC30–HC45、§二 H）。

接线位置的取舍：工具副作用事件（CwdChanged / Task*）放在工具执行器统一判定（`query/tool-side-events.ts`），
不往各工具里塞 hookSystem；模型切换挂在 `applyPrimaryModelSwitch`——/model、降级链、CLAUDE.md `# Model`
三条路径的唯一汇合点；StopFailure 挂在 loop 的「超时重试耗尽」与「最终重抛」两个出口，用户中断不算；
error_type 按 HTTP 状态码归类，不读错误文案。

## 放弃了什么（以及为什么不选）

- **读取 CC 的配置文件**（`~/.claude/settings.json`、`.claude/settings.json`）：需求方硬约束，CC 配置一律走迁移。
- **PreModelSwitch 可拒绝、TaskCreated exit 2 回滚**（CC 有）：前者所在路径是同步的（/model 命令同步返回），
  改成可拒绝要把三条切换路径都改成 async；后者在任务已落盘后才触发，回滚要改 task 存储。都记进差异表，不在本 PR 做。
- **Notification 的 `idle_prompt`**：sid 没有空闲提醒机制，凭空发一个事件比不发更糟，只发 `permission_prompt`。
- **FileChanged / Setup / WorktreeCreate / WorktreeRemove / MessageDisplay / `mcp_tool` 执行**：
  前两个没有对应场景；Worktree 的 CC 语义是替换默认 git 行为，改动面大，单独立项；
  MessageDisplay 与 TUI 渲染底座重构（B9）冲突。参考页如实标 ✗。
- **把 side-event / StopFailure 的 helper 放在 `hook/` 下**：参考页生成器按「hook 层外有 `fire<Event>Event` 调用方」
  判断是否接线，放在 `hook/` 里会被当成定义而显示 ✗。放到 `query/`，同理把模型切换拆成
  `firePreModelSwitchEvent` / `firePostModelSwitchEvent` 两个方法名。
- **按错误文案子串给 StopFailure 归类**：网关自定义文案会被误归类，宁可落到 `unknown`。
