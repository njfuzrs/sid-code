# 只播一次的 reminder 写进历史，修前缀断裂与语义丢失

## 决定了什么

reminder 注入分成两档，transient 只给「每轮重新计算」的内容用：

- **persistent 档**（新增）：MCP 说明、延迟工具增量、skill listing 增量、IDE 增量。这些都由去重集合保证只播一次，所以改为写进 ctxMgr 最后一条 user 消息（独立 text block，带 `persistentReminder: true`），之后每轮原样重放。
- **transient 档**（保持不变）：todo 回注、上下文压力、权限模式、诊断、hook 反馈等，仍然只进发送副本。

改动点：

- `llm/types.ts`：`TextBlock.persistentReminder` 本地标记，不上线。
- `query/reminder-inject.ts`：加 `buildPersistentReminderBlocks` / `appendPersistentBlocks` / `isPersistentReminderBlock`。`injectReminders` 把 ambient 排在持久块**之后**，这样 transient 下一轮撤掉时，变化只出现在消息尾部。持久块也不会被当成「用户 block」去夹 critical/ambient。
- `context/manager.ts`：`appendPersistentBlocksToLastMessage`，只做尾部追加，不走 `addMessage`，避免新开一条 user 消息（OpenAI 族连续 user 会被合并）。
- `query/loop.ts`：上面四类注入改进 `persistentReminderParts`，发送副本和 ctxMgr 同时写入。两边对不齐时（末条不是 user，或尾部 ack 被剥掉）整批降级为 transient，不让副本和历史分叉。
- `agent/agentic-loop.ts`：子代理的延迟工具播报同样改走持久档。
- 下游读者逐块剔除持久块：`auto-compact` 原始任务锚点、`reactive-compact` 原始任务、`compact/quality-check` 锚点、`session/utils` 会话标题、`loop.ts` 的 `extractLastUserInput`（召回查询）、ctxMgr 紧急截断摘要。TUI 原本就按 `<system-reminder>` 前缀剥离，持久块都带围栏，所以不用改，只补了回归测试。
- compact 之后的重播（`deferredToolsPendingAfterCompact`）和 `/clear` 时清空去重集合的逻辑都不变：压缩会把持久块一起裁掉，重播正好补回来。

## 放弃了什么（以及为什么不选）

- **撤掉去重，每轮全量重发（transient 加每轮重注）**：缓存同样不断，但每轮多发约 7.6K 字符，而且这部分字节在最后一条消息上，永远进不了缓存前缀。P2 delta 化当初就是为了砍掉这笔开销（11 轮里 10 轮内容逐字节相同）。
- **新开一条独立的 user 消息承载**（照搬 CC attachment）：`Message.role` 只有 user/assistant，OpenAI 族连续 user 会被合并，部分网关直接拒绝。挂在已有 user 消息上做独立 block 是跨 provider 最稳的形态。
- **用 `_meta.origin` 整条标记**：持久块和用户原文在同一条消息里，整条打 origin 会让 TUI 把用户原文一起隐藏、让压缩跳过真实指令。所以用 block 级标记。

trade-off：方向是「更省」（缓存前缀不断）加「更准」（模型每轮都看得到 MCP 说明）。代价是这些块长期占用上下文。MCP 说明上游已经截到每个 server 2,048 字符（`mcp/manager.ts` 的 `MAX_INSTRUCTIONS_LENGTH`），总量可控；压缩后靠重播补回。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/query/reminder-inject-invariant.test.ts`：11 pass。新增 persistent 档 4 条断言：第 2、3 轮 msg[0] 和首轮逐字节相同；每轮 messages 都是上一轮实际发送内容的前缀扩展；持久块在历史里各只出现一次；transient 排在持久块之后。
- 变异自证：
  - 把持久档改回 transient，上面 4 条全红（7 pass / 4 fail）。
  - 去掉 ambient 排到持久块之后的逻辑，「transient 排在持久块之后」变红（10 pass / 1 fail）。
- `packages/core/tests/query/persistent-reminder.test.ts`：7 pass。去掉 reactive-compact 和会话标题的剔除后，对应 2 条变红。
- `packages/cli/tests/ui/history-adapter.test.ts`：54 pass（含新增的持久块不进 TUI）。
- **尚未验证的轨迹指标**（验收口径照搬缺陷文档）：修复后跑 50 个以上会话，`prefix_break` 中 `cause=none_local`、断在最后一条消息、字符级浪费 >1% 的次数应接近 0；终态 `messages.json` 含 MCP 说明块的会话比例应接近 100%。修复前基线：137 次断裂，153/162 个会话终态丢失 MCP 说明，261/277 个会话终态丢失延迟工具清单。
