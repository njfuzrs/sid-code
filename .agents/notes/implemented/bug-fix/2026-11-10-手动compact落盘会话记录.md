# 手动 `/compact` 接上压缩落盘唯一出口，会话 JSONL 与会话摘要不再丢失

## 决定了什么

手动 `/compact` 的**成功主路径**（无参 / 数字 / focus 三种模式全走
`partialCompact` → `ctxMgr.setMessages`）此前不通知压缩观察者，等于绕开了
`notifyCompacted` 这处唯一出口。观察者（`app.ts` 的 `onContextCompacted`）同时承载
四件事，手动压缩把它们一起漏掉了：

1. 会话 JSONL 的 `context_compact` 诊断记录（`sessionStore.appendCompact`）；
2. 会话摘要 `summaries/<sid>.json`（`persistSessionSummary`，resume 时补偿被裁历史的唯一通道）；
3. rewind 回退点的对话锚点失效（`rewindManager.onMessagesCompacted`）；
4. 压缩后 Session Memory 笔记的常驻注入（`injectSessionMemoryAfterCompact`）。

本次改动：

- `packages/core/src/context/manager.ts` 新增 public 出口
  `recordManualCompaction(summary, messageCountBefore)`，内部转调 `notifyCompacted`，
  meta 固定为 `{ source: "summary", summaryIsRestorable: true }` —— 手动压缩产出的是
  **历史内容摘要**，可以作恢复用会话摘要（管道压缩那种步骤描述不行）。
- `packages/cli/src/command/commands/compact/compact.ts` 在 `runManualPostCompact`
  **之后**调用它：`removedCount` 取实际净减少，文件重注入的条数不会被算成「压掉了」。
- 无参模式 LLM 摘要失败时的本地截断兜底本来就走 `compactWithSummary`，落盘行为不变。

判据来源（2026-11-10 分诊，裁决 3）：判据 1「`/compact` 后退出再 resume，恢复出来的
上下文没有被压缩」成立 —— 手动压缩过的会话既无摘要补偿，长会话恢复会掉进 D1 定义的
「按预算截尾、无补偿」最差分支；判据 2「有轨迹分析脚本因缺这条记录给出错数」在仓库内
不成立（现有统计走 `PreCompact` 事件与遥测，手动路径两条都写），故不需要扩展记录字段。

## 放弃了什么（以及为什么不选）

- **不在 `compact.ts` 里直接调 `sessionStore.appendCompact`**。只补一条诊断记录改不了
  resume 行为（`store.ts` 明文不据 compact boundary 截断历史），判据 1 的现象会原样保留；
  而且会把「三件事只接了一件」的老形态再复制一遍，下一次新增压缩入口照样漏。走唯一出口
  才能让四件副作用保持同步。
- **不扩展 `context_compact` 记录增加 `trigger: manual|auto` 字段**。遥测
  `context_compact` 事件已有 `trigger` 且口径经过 P1-6 校准；会话记录的 `source`
  只表达「对历史的损耗程度」（summary / emergency / pipeline），手动与自动都是摘要压缩，
  损耗相同。为区分而扩字段会把 `CompactionRecordMeta` → `appendCompact` → 读取方
  一起改动，收益仅是「会话文件里能看出是谁触发的」，而这件事遥测已经答得更好。
- **不改 G2 `A6-compact` 用例的期望**。它的期望来自人工实测轨迹，扩断言属于「改已有用例
  期望」，按仓库规则需要人看 diff 后加 `expect-reviewed` 标签，agent 不得给自己加。
  端到端守护留给后续人工评审时补，本次用单测锁住出口契约与调用发生。
- **不顺手修「手动压缩 `tokens_after` 可能大于 `tokens_before`」**。本机遥测里有一条
  真实反例（重注入导致），根因是取值时机，与落盘链路无关，塞进本 PR 会让 review 分不清
  哪些改动是必要的。

## 拿什么证明它生效了

变异自证（先确认断言真的会红，再恢复）：

```text
# 变异 1：注释掉 compact.ts 的 recordManualCompaction 调用
# 变异 2：manager.ts 把 summaryIsRestorable 改成 false
$ bun test ./packages/core/tests/context/manual-compaction-record.test.ts \
           ./packages/cli/tests/command/compact-analytics.test.ts
 10 pass
 2 fail        # 恰好是「出口元数据」与「手动路径调用发生」两条
```

恢复后复跑：

```text
$ bun test ./packages/core/tests/context/manual-compaction-record.test.ts \
           ./packages/cli/tests/command/compact-analytics.test.ts
 12 pass
 0 fail
 54 expect() calls
```

新增/扩展的断言锁三件事：① 出口 meta 必须是
`{ source: "summary", summaryIsRestorable: true }`；② 没真压动（净减少 ≤ 0）不通知；
③ 手动成功路径必须调用一次且传压缩前消息数，失败分支不调用。
