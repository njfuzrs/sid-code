# 本地轨迹默认不限数量，改由 10GB 体积兜底（与会话保留同口径）

## 决定了什么

- `TraceCollector.pruneOldSessions()` 默认不再按数量删（旧默认 `maxSessionsRetained: 100`）。
  防盘满改为 `trajectories/sessions/` 总体积上限，取 `sessionRetention.maxTotalSize`（默认 10GB），
  `sessionRetention.enabled: false` 时不按体积删。`trace.maxSessionsRetained` 保留，显式配置仍生效。
- 淘汰选择抽成纯函数 `packages/core/src/trace/retention.ts`：已上传优先、最旧优先；
  活跃进程正在写的会话（含 resume 的 logicalSessionId）与 `minRetention`（默认 1d）窗口内的目录永不删。
- 同步：`init-helpers.ts` 把 `sessionRetention` 接进 collector；`disk-usage.ts` 保留策略登记表、
  `config.ts` 字段注释、`website/team/observability.md`「本地保留多少」、`website/ref/settings.md`。

## 放弃了什么（以及为什么不选）

- **只把默认 100 调到 1000/3000**：仍是拿数量近似体积，问题只是推迟；而且和 PR #218 定下的
  「会话按体积兜底」口径不一致，两套旋钮各管一半。
- **另起一个 `trace.maxTotalSize`**：会话清理已经把「会话 + 同 id 轨迹」计入 10GB，
  再起一个数就是两处事实源。轨迹单独的那道兜底复用同一个值。
- 此前 `session-index.ts` / `collector.ts` 注释里「不要调大上限」的论证没有被推翻其结论
  （指标长留靠索引，不靠原始轨迹），被推翻的是它的前提「原始轨迹 ≈45MB/会话」，
  以及「原始轨迹只为指标服务」——它还是开发者调试的唯一材料。

## 拿什么证明它生效了

- 实测前提：开发者本机 `~/.sid-code/trajectories/sessions/` 恰好 100 个目录（已顶上限，最早 2026-09-11），
  合计 37MB，单个 p50 24KB / p95 1.3MB / 最大 3.2MB；一天 24~36 个会话 ⇒ 100 个只够 2~4 周。
- `packages/core/tests/trace/retention.test.ts`：反向门禁「150 个旧目录默认全部保留」；
  变异自证：把默认值改回 `?? 100` 后该用例红（8 pass / 1 fail），还原后全绿。
- `bun test` trace 相关 5 个文件 203 pass / 0 fail（含既有 LRU 用例与 P0-2 端到端）。
