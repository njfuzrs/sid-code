# done ≠ success（C2）与网关 401 占位句不得一次 Terminal（C1）

来源：`docs-research/sid-code/summary/X2-Evaluation/16-sid-code-harness缺口排查与修复.md`
§2.5（C2）与 §2.1（C1）。两条都是 A2 三臂对照实测逼出来的 P0，按 §4 合成一个 PR
（无文件冲突：C2 在 `query/` + `sdk/`，C1 在 `llm/`）。

## 决定了什么

**C2 —— `kind:"done"` 不再无条件映射成 `subtype=success`。**

判据是 loop **显式声明**的新字段 `DoneIncompleteReason`（闭集：`timeout_retry_exhausted`
/ `aborted`），由 `queryLoop` 在超时重试耗尽与 4 处 abort 收尾点打上，
`message-converter.ts` 见到它就走 `error_during_execution`。

- 改的是 converter 而不是「让 loop 改 yield `fatal_error`」：`done` 对 TUI 是正确的
  （回到等待输入），错的是 SDK 侧那个无条件映射。§2.5 点破过——不修 converter，
  以后任何「yield done 当优雅退出」都会再谎报一次。
- 判据**不是** `turnsConsumedWithoutAssistant > 0`：`break-filter-js-from-html`
  stolen=3 却真写完脚本、reward=1.0。计数只描述「被偷了几格」，不判成败。

**C1 —— 网关 401 占位句（`Invalid token. (request id: …)`）与「真 key 作废」分开。**

新增 `isGatewayPlaceholderAuthError()`：**结构化 401** + 占位句文本 + 真 key 作废措辞
优先否决。命中者走 `RetryableError("server_error")`，退避重试**封顶 3 次**
（`GATEWAY_PLACEHOLDER_AUTH_MAX_RETRIES`，独立于 `needsAuthRefresh` 闸门与
`maxRetriesPerCall=12`）；不命中者行为逐字节不变（retry-once 后 Terminal）。

两处接线，少一处就只修一半：

1. catch 路径的闸门，置于 B1-b `auth_refresh` 闸门**之前**（否则被「只放一次」封住，
   就是要修的原状），且 B1-b 显式排除占位句——刷新凭据对网关抖动无意义。
2. **流内 `error` 事件**路径：本网关真实形态不带 `streamLevel`（`type` 是空字符串），
   走 `classifyError` → 401 → `TerminalError` → 那条分支上的 `return`，**绕过 catch**。
   这里把它重新抛成 `StreamLevelError` 送进 catch，重试预算仍只在闸门那一处算。

## 放弃了什么（以及为什么不选）

- **不在 `is401Error` 文本表里加 `"invalid token"`**（§4 的 ⛔）：生产路径是
  `StreamLevelError.statusCode=401`，正文既无边界 `401` 也无认证关键词，
  只改文本表的版本在生产路径上测不到。
- **不给占位句 12 次预算**（`maxRetriesPerCall`）：坏处不是慢，是把本次调用的全部重试
  预算喂给一个可能压根不会恢复的网关故障，之后真该重试的 429/529 一次都轮不到。
- **不用反向判据**（「401 且不是真 key 作废」就重试）：那会把措辞不透明的
  `401 Unauthorized`（多半真是 key 配错）也拖进 3 次退避，把「立刻告知去换 key」
  换成「慢 3 倍再告知」。故用正向白名单。
- **不改评测容器里 `fallbackModel` 指回自己**：那是胶水层事实（`sid_code_agent.py:627-630`
  压悬空 `ali-deepseek-*`），§2.1 明确不在本 PR 改；对照 caveats 已有「无真实降级目标」。
- **不给 sid 加 `max_retries=10` 去对齐 cc**：§6 / 08 §2.4 否决过改被测对象来对齐对照。
- **C2 只标超时耗尽与 abort，不动其余 18 处 `done`**：hook 阻止、预算/配额超限、
  压缩熔断、循环检测、安全拒答等各有自己的 `terminal: true` system 事件与语义，
  把它们一并标成 `error_during_execution` 是另一件事（会改 TUI 与 headless 的既有契约），
  且 §2.5 的分母只指向超时耗尽那一类。

## 拿什么证明它生效了

**新增两个门禁文件，19 条用例全绿：**

```
bun test ./packages/core/tests/query/done-not-success.test.ts \
         ./packages/core/tests/llm/gateway-placeholder-401-retry.test.ts
  → 19 pass / 0 fail
```

**变异自证（4 次，每次都真的红了）** —— 证明门禁不是「恒绿也能过」：

| 变异 | 结果 |
| --- | --- |
| converter 的 `incompleteReason` 分支短路 | 5 fail（C2 ①③ + 双向自证） |
| loop 侧 `timeout_retry_exhausted` 标记删除 | **仅** C2 ③ fail —— 证明它钉的是 loop 侧，converter 改对也糊不过去 |
| C1 闸门短路 | 4 fail |
| 流内 error 事件那一段短路 | **仅** C1「流内 error 形态」fail —— 证明它钉的是那条绕过 catch 的路径 |

**变异自证逼出一个真问题（不是走流程走出来的）**：第 5 次变异删掉
`REAL_AUTH_FAILURE_MESSAGES` 优先否决，**11 条全绿** —— 说明那张表当时是**死代码**
（正向白名单要求 `invalid token`，而 `invalid x-api-key` 永远不含它）。
补了复合措辞用例（`authentication_error: Invalid token. (request id: …)`）后再变异，
该用例如期变红。这正是本仓「死接线」那一类：字段/表都在，从未被执行过。

**C1 的验收口径按 §2.1 执行：数 provider 调用次数，不数 `RetryTelemetry`**
（修复前 `auth_refresh` 已 > 0，那条判据会假绿）。占位句 3 次重试后落 Terminal，
总调用 = 1 + 3 = 4；真 `invalid x-api-key` 仍是 2（retry-once 后 Terminal）。

**回归与构建：**

```
bun run affected-tests:run   → 2538 pass / 0 fail（llm + query + sdk）
make build                   → 编译产物自检 4 项全过，无 "will always be undefined"
bun run lint                 → 0
bun run lint:boundary        → 越界依赖 0 处
```

**尚未验证、如实记下：** 端到端那条（§5.1「同一 3 道烧轮差集、新二进制重跑」）**没跑**。
本次是单测 + 变异层面的证明，`feal-differential-cryptanalysis` 这类真实样本在新字节上
是否不再自报 success，要等下一次评测跑。按 §5.2，C2 的验收本来就不要求重跑 feal
（fixture 即可）；C1 的 FakeUpstream 判据已由上表第 3 行覆盖。

## 北极星

- **朝向**：更准（一次做对 / 更少返工）。C1 兼更快——不再死在网关占位句上。
- **牺牲**：C1 拿「真 key 作废时多等一次退避」换「占位句不再掐死整轮」——实际没牺牲，
  因为真 key 作废被优先否决，路径逐字节不变。C2 牺牲的是「headless 消费者会多看到
  error_during_execution」，而那正是事实。
- **证明**：上面那张变异表，不是「机理上讲得通」。
