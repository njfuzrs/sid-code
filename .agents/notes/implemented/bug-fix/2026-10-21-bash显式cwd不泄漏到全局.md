# bash 显式 cwd 只作用于本次调用；自建 worktree 补路径提示；输出剥终端控制序列

## 决定了什么

来源是会话 `20261020-110542-ce7ea52e` 评估的发现 6a、10、12（PR B）。

- **6a（根因）**：`tool/bash.ts` `applyCwdTracking` 的比较基准从全局 `getCwd()` 改为**本次命令的启动目录**（`resolveCwd` 的结果）再 realpath。只有命令自己 cd 了（结束目录 ≠ 启动目录）才写回全局。被评会话里，带显式 `cwd:<主仓>`、不含 `cd` 的非只读命令把全局 cwd 来回切了 29 次，主仓被误写 13 次。
  - realpath 是必需的：`pwd -P` 返回物理路径，启动目录是逻辑路径。经 symlink 进入的目录（含 macOS `/var`→`/private/var`）下两边恒不等。
  - 连带修掉一个旧缺陷：全局 cwd 本身是 symlink 路径时，任何一条非只读命令都会报一次假的「[工作目录已切换]」，并把全局改写成物理路径。
- **10**：bash 成功执行 `git worktree add <path>` 后，在结果末尾追加「[已创建 worktree] <绝对路径>」，并提示用绝对路径或 enter_worktree 切过去。`parseWorktreeAddPath` 取不到路径时（变量、通配、含空格的引号）不提示。
- **12**：新模块 `tool/bash/terminal-control.ts` 剥离结构完整的 CSI / OSC / DCS / 两字符转义。剥离放在 `isBinaryOutput` 之后、`truncateOutput` 之前；剥完为空时回落为「(命令无输出)」。

## 放弃了什么（以及为什么不选）

- **6b（gh 只读子命令白名单）不进本 PR**：6a 修好后，只读判定已不影响 cwd 泄漏。被评会话里的 `git diff | python3 -c …` 同样被判非只读，6b 本来就修不了它。6b 的收益是并发和语义正确，拆成 B2 单独做。`gh api` 不进白名单：`-f/-F/--input` 会隐式变成 POST，误判成只读就会被并发执行。
- **不在 `resolveCwd` 层把显式 cwd 写回或隔离**：问题出在写回判据，不在解析。改解析会波及后台路径和沙箱。
- **worktree 不做「写主仓就拦截」**：合法的跨目录写会被误伤。只追加提示。
- **不用 `util.stripVTControlCharacters`**（bun 1.4.2 实测）：DCS `ESC P q#0 ESC \` 只剥掉头两个字节，留下 `q#0` 和半个 ST；未终止的 OSC `ESC ]9;4 …` 会被剥成半截。被评会话的输出里正好有 DCS 和 OSC。这里只剥结构完整的序列，与 `binary-detect.ts` 的判据一致，残缺序列原样保留。
- **不剥 `\r`**：进度条的回车覆盖是文本层面的事，剥掉会把多帧拼成一行。

- `bun test ./packages/core/tests/tool/bash-terminal-control.test.ts`：12 pass / 0 fail，含 bash 工具端到端接线 2 例。
- 变异自证（逐项改坏，看报了什么）：
  - 比较基准改回 `getCwd()`：5 条红（显式 cwd ×1、symlink ×2、子代理、worktree 用例里的 cwd 断言）；
  - 去掉 realpath：同样 5 条红。symlink 用例是显式造的软链，不依赖 macOS tmpdir 形态，在 Linux CI 上也能红；

  - 不剥控制序列：接线 2 条红。
