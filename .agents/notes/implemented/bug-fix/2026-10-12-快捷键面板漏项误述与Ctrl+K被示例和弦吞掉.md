# `?` 快捷键面板补齐漏项、改正误述，并修复 Ctrl+K 从未生效

## 决定了什么

- `?` 面板改为分组展示（输入编辑 / 发送与排队 / 会话控制 / 显示 / 后台任务），数据 = 运行时键位表
  `showInHelp` 项 + `keybindings/helpShortcuts.ts` 的 `HELP_ONLY_SHORTCUTS`。后者补上一直存在却不在
  面板里的键：Esc Esc、Ctrl+D、Tab、PgUp/PgDn、Shift+↑/↓、Emacs 编辑键、Enter 排队、空输入 ↑ 弹回排队、`?` 自身。
- 有前提条件的键把条件写进描述或分组标题（Ctrl+C 忙时中断/空闲按两次退出、Esc 仅在执行中、
  Alt+N/L 仅输出中、Ctrl+F/X/B 无任务时照常编辑、Ctrl+S 仅全屏）。标题去掉误导的「输入 /help 查看更多」
  （HelpDialog 里的快捷键比面板还少），HelpDialog 同步改准措辞。
- 列宽按内容实测宽度算列数（最多 3 列），替代固定 33%，消除「（双击确认」与孤立「）」的折行。
- `?` 判定从 Composer 挪到 InputArea：只在空输入框 + 非输出中触发，并消费该键。此前句中 `what?` 也会弹面板。
- `KeyBinding` 新增 `group` / `fixed`。fixed 键（`!` `@` 换行 ↑/↓ Ctrl+Y/W）不走 matchBinding，
  validate 拒绝改绑它们、也拒绝把别的动作绑到它们的键上（新错误码 `fixed`），`/keybindings` 标「固定」。
- `mergeBindings` 覆盖项原位替换（此前追加到表尾，keybindings.json 写了覆盖的键在面板里跑到最后）；
  改了 stroke 未写 display 时按新键重算 display，不沿用旧显示。
- `defaultChordBindings` 清空：两条「示例」和弦把 Ctrl+K 当前缀吞掉，InputArea 的 killLine 从未可达。
  示例改名 `exampleChordBindings` 只供单测。

## 放弃了什么（以及为什么不选）

- **保留和弦、前缀超时后回放 Ctrl+K**：两边都能用，但单按 Ctrl+K 要等 1.5s 才生效，手感差；
  两条和弦从未出现在任何帮助里，`copyLine` 名不副实（实为复制出一行）。用户拍板移除。
- **把仅展示键也塞进 DEFAULT_BINDINGS**：会让「stroke 全表唯一」「往返命中自身」等表级不变量失去意义，
  且诱导有人以为它们可改绑。单独放 helpShortcuts.ts 只做展示。
- **让 fixed 键真正走查表以支持改绑**：要改 InputArea 的字符级分发，范围远超本次修帮助的目标。先让配置层
  诚实拒绝，比让帮助显示一个按了没用的键好。
- **Composer 用 debounce 猜输入框是否为空**（原注释里的设想）：猜不准，且依赖时间；直接在 InputArea 判定。
