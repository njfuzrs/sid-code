# Seatbelt 沙箱：读放开 + 敏感 deny、写白名单、网络三档，并删掉 DNS 解析链

## 决定了什么

`enableSandbox: true` 之前是「开启即全挂」：每一条 bash 都在 `sandbox-exec` 这一层失败，
命令一行都没跑。修完是三件事一起改的（任意一个单独修都不够，修了 D1 暴露 D2、修了 D2 暴露 D3）：

- **profile 换威胁模型**（`packages/core/src/permission/sandbox.ts`）：从「读写都白名单」
  改为 **读默认放开 + 敏感目录 deny、写严格白名单、网络三档**。
  原设计要在 `(deny default)` 下枚举进程启动所需的全部读路径，而 macOS 11+ 的系统库在
  dyld 共享缓存里、进程启动还要 `sysctl-read` / `mach-lookup`，最小集合每个大版本都变，
  枚举维护不住（实测连 `/bin/echo hi` 都 SIGABRT，exit 134）。
  读放开后靠 deny 列表挡长期凭据：`~/.ssh` `~/.gnupg` `~/.aws` `~/.azure` `~/.kube`
  `~/.config/gh` `~/.docker/config.json` `~/.netrc` `<sid home>`。刻意**不** deny
  `~/.npmrc` / `~/.gitconfig`（私有源与提交身份依赖它们，deny 掉会让沙箱里的
  `npm install` 直接不可用；A2b 用例是这条决定看门狗）。
- **删掉 DNS 解析链**（`prepareSandboxHosts` / `resolveOneHost` / `resolvedHostCache` /
  `resolveSandboxHosts`）。Seatbelt 的 `remote ip` host 部分只接受 `*` 或 `localhost`，
  写 `"127.0.0.1:*"` 会让 sandbox-exec 报 `host must be * or localhost in network address`
  并 exit 65。原实现是在为一个 Seatbelt 不提供的能力写代码。
  `SandboxConfig.allowedHosts: string[]` → `network: "localhost" | "all" | "none"`（默认 localhost）。
- **内层 shell 跟随外层**：`wrapCommand(command)` → `wrapCommand(command, shell)`，
  不再写死 `/bin/sh -c`。按 zsh 抓的环境快照若在 POSIX mode 下 `source`，读不到文件是
  **特殊内建致命错误**（`|| true` 救不回来），shell 直接退出、用户命令不执行。
  配套 `SandboxManager.setSnapshotPath()`：profile 给本会话快照一条 `(literal ...)` 读放行
  （它在 sid home 下，被 deny 覆盖），BashTool 在快照就绪后注入。
- **配置面只开最小两个字段**：`sandboxNetwork`、`sandboxAllowedWritePaths`。
  `allowedReadPaths` 删除（读默认放开后它没有语义，留着是一个不生效的旋钮）。
- **启动自检 + fail-open 降级**：启动时用真实 profile 跑一次 `sandbox-exec ... -c 'exit 0'`（~10ms）。
  失败则 warn + **不注入 sandboxManager**（命令走无沙箱路径但说得出来），
  而不是让每条 bash 无声失败，也不是让 CLI 起不来。
- **可观测性**：新增 `sandbox_init` 事件（`enabled` / `platform` / `probe_ok` / `probe_error` /
  `network` / `write_paths_count`）与 bash 结果的 `sandboxed: boolean`
  （经 `LegacyToolResult.meta` → `tool_response.meta` → `trace/collector.ts` 落盘）。
  没有它，「开了沙箱的会话里多少条 bash 真的进了沙箱」在轨迹上完全看不见——
  B2 坏了两三个月没人发现，直接原因就是这条链没有分母。

实现期由**端到端验收**（而非单测）发现并修掉的两个额外缺口，一并记在这里：

1. **失败路径丢 `sandboxed`**：`firePostToolUseFailureEvent` 的 `tool_response` 原本只有
   `{error, output}`，`result.meta` 没透传。实测 5 次 bash 只有 3 条带 `sandboxed`，
   缺的正是 exit≠0 的那两条。补了 `tool_meta` 参数。
2. **`sandbox_init` 被 `initialized` 门禁丢弃**：`recordCustomEvent` 要求 `collector.initialized`，
   而它在 SessionStart 时才置位；`cli.ts` 的沙箱初始化早于 App，报告必然落在这个窗口里。
   改为未初始化时**排队**（上限 200 条），`initialized = true` 后补发。

## 放弃了什么（以及为什么不选）

- **「修 DNS 解析让它写对 IP」**：Seatbelt 语法不支持。`remote ip` 的 host 只接受 `*` 或
  `localhost`（2026-11-05 实测三种写法），不可能「修对」。
- **「继续枚举系统读路径」**：每个 macOS 大版本都变，且 git/bun/python 要读的路径
  （`~/.gitconfig`、`~/Library/Caches`、`/opt/homebrew`）几乎无法穷举。原实现就死在这里。
- **「按域名放行外网」**：需要「沙箱只放 localhost:<代理端口> + 本地 HTTP/SOCKS 过滤代理」，
  是独立特性，不在本次范围（记在方案文档 §7 不做清单）。
- **「探针失败 fail-closed（bash 工具直接报错）」**：默认不选。沙箱是用户显式打开的，
  静默不隔离最坏，但让 CLI 起不来 / 所有 bash 失败也不对。企业 policy 场景可能更想要
  fail-closed，那是后续开关的事，不在这次。
- **「读白名单 + 完整工具链放行」**：就算枚举出来，`~/.aws`、`~/.netrc` 这类凭据也会
  落在某个必须放行的目录里（如 `$HOME` 本身就是常见的工作区父目录），收益不可靠。
- **`~/.npmrc` 进 deny 列表**：会让私有源 `npm install` 失败，而沙箱里跑不了包管理器
  等于这个特性不可用。改为显式保留并用 A2b 用例锁住。

## 拿什么证明它生效了

修复前留底（本机 macOS 27.0.1 / bun 1.4.2 / `/usr/bin/sandbox-exec`）：

```
D1: sandbox-exec -f <旧profile> /bin/echo hi → exit 65
    sandbox-exec: host must be * or localhost in network address
    (remote ip "::1:*")
D2: 去掉网络行后同一命令 → exit 134（SIGABRT，dyld 起不来）
D3: 沙箱内 /bin/sh -c "source <zsh快照> 2>/dev/null || true && eval 'echo ran'" → exit 2、无输出
    对照（沙箱外 /bin/zsh 同一句）→ 打印 ran、exit 0
```

自动化（新增 `packages/core/tests/permission/sandbox-exec-real.test.ts`，**真跑 sandbox-exec**）：

```
bun test ./packages/core/tests/permission/sandbox-exec-real.test.ts
→ 16 pass / 0 fail（A1 基础执行、A2 工具链、A2b ~/.npmrc、A3 工作区可写、A4 工作区外不可写、
  A5 敏感目录不可读、A6 快照可 source、A6b 内层 shell、A6c sh 会吞命令、A7 realpath、
  A8 localhost 网络、A9 外网被拒、A10 network none、A11 子进程继承、A12 BashTool cwd 追踪、
  A13 BashTool 后台任务）

bun test ./packages/core/tests/permission/p2-wiring-and-sandbox.test.ts → 21 pass / 0 fail
bun test ./packages/core/tests/trace/collector.test.ts → 111 pass / 0 fail
```

变异自证 6/6 全部被捕获（脚本 `/tmp/sbx-probe/mutation-check.ts`，逐条改坏→跑用例→恢复）：

| 变异 | 捕获它的用例 | 实测输出 |
| --- | --- | --- |
| M1 网络行改回 `127.0.0.1:*` | A1 | `code: 65` |
| M2 删 `(allow sysctl-read)` | A1 | `code: 1`（dyld 起不来） |
| M3 内层 shell 改回 `/bin/sh` | A6c | 空输出、非 0 |
| M4 删 sid home 读 deny | A5 | `cat` 成功（exit 0） |
| M5 去掉 realpath | A7 | profile 里没有真实路径 |
| M6 加 `(allow file-write*)` | A4 | 写 `$HOME` 成功 |

> M3 一开始**没被捕获**：A6 给快照加了 literal 放行，`/bin/sh` 读到它也能跑；A6b 的快照内容
> 又恰好是 POSIX 兼容的。补了 A6c（`source` 一个**不存在**的文件 + `|| true`）才有区分度——
> 实测 sh → exit 1 且无输出，zsh → 打印 ok、exit 0。

端到端（本 worktree 构建的 `./sid-code`，`SID_CONFIG_DIR` 指隔离目录，用户级 settings 开沙箱）：

| 步骤 | 沙箱开 | 沙箱关（对照） |
| --- | --- | --- |
| `echo hello && git --version` | exit 0 | exit 0 |
| `cat ~/.ssh/known_hosts \| head -1` | `Operation not permitted`（管道末段掩盖成 exit 0） | exit 0，读到内容 |
| `echo x > ~/sbx-e2e-should-fail` | exit 1、文件不存在 | exit 0、**文件被创建** |
| `echo x > ./ok.txt && cat ./ok.txt` | exit 0 | exit 0 |
| `curl --noproxy '*' -m 3 http://1.1.1.1/` | exit 7 `Couldn't connect to server` | exit 0 |

轨迹核对（`trajectories/sessions/<id>/events.jsonl`）：

```
sandbox_init → {"enabled":true,"platform":"darwin","probe_ok":true,"network":"localhost","write_paths_count":3}
PostToolUse 里 tool_name=bash 共 5 条，sandboxed:true 也是 5 条（含 2 条 exit≠0）
```

故障注入（PATH 前置一个返回 65 的假 `sandbox-exec`）：

```
audit.log: ⚠ [CONFIG] macOS Seatbelt 沙箱启动自检失败，已降级为无沙箱（命令不会被隔离）: sandbox-exec: injected probe failure
events.jsonl: sandbox_init {"enabled":true,"probe_ok":false,"probe_error":"sandbox-exec: injected probe failure"}
沙箱包裹条数 0；`echo sandbox-degraded-ok` 正常执行
```

另外记录一条**验收本身暴露的配置事实**：`enableSandbox` **只从用户级 settings 生效**，
项目级 `.sid-code/settings.json` 里写它会被 `PROJECT_BEHAVIOR_FIELDS` 白名单静默忽略。
第一次端到端按方案文档的「项目级 settings」写导致沙箱没开、五步全部成功——差点被误判成
「修复没生效」。该事实已写进 `website/use/permissions.md` 的 warning 块。

性能代价（更安全方向牺牲更快）：`/bin/zsh -c true` p50 2.2ms → `sandbox-exec -p <profile>` p50 10.5ms，
每条 bash 约 +8ms，相对 LLM 往返可忽略。
