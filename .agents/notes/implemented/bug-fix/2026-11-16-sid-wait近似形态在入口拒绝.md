# `sid-wait` 的近似形态在入口拒绝，而不是让 shell 报 127

## 决定了什么

在 `parseSidWaitCommand` 旁边新增 `detectSidWaitMisuse`（`packages/core/src/task/sid-wait.ts`），
判定「剥掉 `cd <dir> &&` 前缀后以 `sid-wait` 开头、但不是合法原语」的命令，
并让**两个入口在 spawn 之前**用它拒绝：

- `packages/core/src/tool/bash.ts`：放在 `run_in_background` 分支之前，前台 / 后台都拦；
- `packages/core/src/tool/monitor.ts`：放在等待准入判定之前，连等待表都不登记。

拒绝文案由 `formatSidWaitMisuseReceipt` 按入口生成，包含四件事：拼接后不再被识别为原语、
后台会被末尾命令的退出码报成「执行成功」、可直接替换的正确命令（能从正文捞到 PR 号就填进去）、
「本次未启动任何进程」。同时把中文 / 英文 `<waiting-capability>` 段落各补一句形态约束
（整条命令只能是原语、不要拼 `; echo $?` / `2>&1` / 管道、退出码由工具结果直接报告）。

`parseSidWaitCommand` 与 `detectSidWaitMisuse` 共用同一个归一化函数 `normalizeSidWaitBody`——
两处各自归一化会让「严格形态 / 近似形态」的边界漂移，出现两头都判不中的静默空洞。

## 放弃了什么（以及为什么不选）

**放弃「入口自动改写命令」**（把 `sid-wait gh-pr 811; echo $?` 剥成 `sid-wait gh-pr 811` 再执行）。
改写等于替模型猜语义：`2>&1` 可能是作者真的想把输出留档，`&& echo done` 可能是想在成功后做别的事。
与 `parseSidWaitCommand` 既有的「不猜意图」原则一致，这里只拒绝并给出正确写法，由模型重发。

**放弃「只在后台路径拦」**。前台拼接虽然能看到 `command not found`（不像后台那样假成功），
但同样是一轮无效往返，且模型从 127 里读不出「这是形态问题」。两个入口同一判据，文案也一份。

**放弃「用 `isSidWaitCommand === false` 当近似形态判据」**。`grep "sid-wait gh-pr"`、
`bun test sid-wait-*.test.ts`、`cd r7-sid-wait && ls` 都不是原语，但也不该被拦。
只有「以 sid-wait 开头」（`^sid-wait(?:\s|$)`）才是近似形态，其余交给 shell。

**放弃「顺手加一条 G2 冒烟用例」**。判据是纯确定性的（命令字符串 → 拦 / 不拦），
单测能完整覆盖；G2 只在「跨多个模块按真实顺序串起来才会出错」时才值得造。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/task/sid-wait-gh-pr.test.ts ./packages/core/tests/tool/sid-wait-entrypoints.test.ts`
  → **43 pass / 0 fail**。新增用例覆盖：近似形态矩阵（`; echo $?` / `2>&1` / 管道 / 重定向 /
  缺参数 / 非法 PR）、不误伤矩阵（`grep "sid-wait gh-pr"`、`bun test ...sid-wait-*.test.ts`、
  `cd r7-sid-wait && ...`、`sid-wait-helper`）、两个入口「不 spawn」断言
  （`getAllTasks()` / `listWaits()` / 通知队列全空）。
- **变异自证**：把两个入口的 `if (sidWaitMisuse)` 改成 `if (false && sidWaitMisuse)` 后重跑，
  4 条入口用例全部变红（bash 后台拼接 / 后台重定向 / 前台拼接 / monitor 拼接），
  「不误伤」那条保持绿；恢复后重新全绿。说明断言不是恒绿。
- `bun run affected-tests:run` → **3040 pass / 0 fail**（config / task / tool 三个域）。
- `make build` → 构建成功，产物自检五项全过，无 `will always be undefined` warning。
- `bun run smoke` → **37 例：37 通过，0 失败**（工具执行链被改动，G2 必须过）。
- `bun run lint` / `format:check` / `lint:boundary` / `lint:command-system` / `lint:legacy-tool` /
  `typecheck:gate`（62 处错误 = 基线 62）全绿；`bun run docs:gen-reference` 无 diff。
