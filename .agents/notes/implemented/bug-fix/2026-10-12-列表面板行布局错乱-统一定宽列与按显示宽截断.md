# 列表面板行布局错乱：统一定宽列与按显示宽截断

## 决定了什么

`/commands` 面板错乱的根因是：一行用 `flex row + gap` 平铺多个 `<Text>`，外部数据（skill 描述、MCP 错误、hook 命令）一长或带换行，yoga 就压缩前面的 Text，名称被折成两行、每行描述起点不同。

审计后发现同源问题分布在 14 个组件里，统一处理：

- 新增 `packages/cli/src/ui/components/shared/text-layout.ts`：`truncateToWidth` / `oneLine` / `padEndToWidth` / `fitCell` / `clipLine` / `columnWidth`。全部按 `stringWidth` 计算，CJK 安全。`SuggestionsDisplay` 原有的 `truncateToWidth` 迁到这里，原位置保留再导出。
- **列表行（可截断）**：按终端宽度算好定宽列，整行用一个 `<Text wrap="truncate">`，不再依赖 flex 收缩。涉及 `CommandsDialog`、`McpDialog`（服务器列表、工具列表）、`HooksDialog` 列表、`MemoryDialog`（列宽加封顶）、`ConfigDialog`。
- **安全闸门和详情页（不截断）**：`TrustDialog`、`ExtensionTrustDialog`、`PermissionsDialog`、`HooksDialog` 详情页改为标签列 `width + flexShrink={0}`，值在自己那一列内换行。用户要看清自己在授权什么，不能把内容截掉。
- **小修**：`SkillsDialog` / `AgentsDialog` / `RewindDialog` / `TodoPanel` 的描述先压成单行；`ModelDialog` 的 note 列按列宽截断；`McpApprovalDialog` / `TrustDialog` 里 `.slice(0, N)` 按码元截取的写法改为按显示宽度截断。

## 放弃了什么（以及为什么不选）

- **只给名称列加 `flexShrink={0}`、描述继续换行**：`SuggestionsDisplay` 头注释记录过，这种做法会导致长描述一项占十行，长参数提示把描述挤成一字一行竖排，已经回退过一次。
- **安全对话框也统一截断**：截断会藏掉危险配置的关键片段（命令尾部、路径），等于削弱闸门。这里宁可多占几行。
- **改 `BaseSelectionList` 让它接管列布局**：二十多个调用方各自的列语义不同，强行收进基类会让接口膨胀。工具函数放在 shared，由调用方组合，改动面更小。
- **`messages/*`、`Footer`、`TableRenderer` 等非列表组件**：本次审计没有覆盖，不在本 PR 范围内，避免顺手扩大改动面。

## 拿什么证明它生效了

- `bun test ./packages/cli/tests/ui/commands-dialog-layout.test.tsx ./packages/cli/tests/ui/dialog-row-layout.test.tsx`：15 pass。这些用例在 80/100/120/140 宽度下断言「每项一行、列起点一致、无行超出终端宽度」。
- **变异自证**：把 `CommandsDialog`、`McpDialog`、`HooksDialog` 的行渲染临时换回旧的平铺写法，对应的 3+3 条渲染用例变红；还原后转绿。
- `approval-dialogs-keys.test.tsx` 原断言 `"[命令] .sid-code/…"` 依赖 kind 后面恰好一个空格。kind 列定宽后，这个前提被有意改变，所以把断言修正为「同一行 + 两行路径起点对齐」。
- `bun run affected-tests:run`：修正上述断言后，只有那一条失败，现已全绿。`make build` 通过、自检通过，无 `will always be undefined` 警告。`lint` / `format:check` / `lint:boundary` 都是 0 问题。
- 未验证：没有在真实终端里跑 `sc-dev` 目测效果，以上帧都来自测试渲染器。
