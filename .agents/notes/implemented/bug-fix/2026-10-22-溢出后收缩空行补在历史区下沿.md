# 溢出后收缩的空行改补在历史区下沿，不再切进状态栏 / 输入框

## 决定了什么

PR #390（见 `2026-10-21-主屏溢出后收缩补空行钉住footer.md`）补空行的方向是对的，插入点错了。
它在帧层按「两帧公共尾部之前，没有就插在第一个变化行」猜插入点，真实 TUI 里两头都会切进组件内部：

- 状态栏计费（`$` / `⟳`）与 spinner 消失同帧变化 → 公共尾部只剩最后一行 `sid-code ⎇ main`，空行插进状态栏两行之间；
- 输入框变矮（删字、命令补全收起）→ 公共尾部从输入框下边框起算，空行插进输入框里面。

改为由 `ink.tsx` 告诉帧层历史区下沿：`History` 用 ref 给容器节点打 `internal_history`，
出帧时 `historyEnd()` 找到它、用 `measureElement` 取 `y + height`，作为 `diffMainScreen` 的第 4 个参数。
空行补在历史区与动态区之间，动态区整块贴底。`historyEnd()` 只在收缩帧调用，其余帧不遍历树。

两种情况退回 #390 的按内容猜（再夹到视口内）：没用 `History` 的调用方（`historyEnd` 为 undefined），
以及下沿已滚出视口（动态区比视口高，比如长流式正文）。后者 review 时实测：插在下沿会动到 scrollback 里的行而 full reset；
夹到视口顶行会把空行插进正文中间（`msg8` 与 `msg9` 之间）。按内容猜在这里能对，因为变化的只有 spinner 那一块。

## 放弃了什么（以及为什么不选）

- **继续在帧层改进猜法（比如找最长公共尾部、跳过变化行）**：帧层只有字符格子，看不到组件边界；
  状态栏数字每帧都可能变，任何按内容的启发式都能构造出切错的帧。边界只有布局树知道。
- **回到擦底部 / 一律 full reset**：#390 的 note 已论证过（footer 被顶起 / `3J` 清 scrollback + 闪屏）。
- **让 CLI 层（`MainScreenLayout`）传动态区高度**：要穿过 render-port 接口，且 CLI 有多处布局；
  `History` 是底座组件，打标记对所有调用方自动生效。

代价：空行落在历史尾与动态区之间（与 #390 预期的「footer 上方空行」同类），直到后续增长填上。

## 拿什么证明它生效了

- xterm 复现（一次性脚本，已删）：W=30、H=12、历史 20 行。修复前状态栏两行之间 2 行空行、输入框内 2 行空行，
  与用户贴图同形；传入 historyEnd 后两例空行都移到 `hist19` 与 `────` 之间，动态区连续。
- `packages/tui/tests/frame.test.ts` 新增「溢出后收缩：空行补在历史区下沿」3 例：2 例走真实 `render` + `History`，
  1 例覆盖下沿滚出视口，全部断言 xterm 画面（不断言字节）。变异自证：把 `ink.tsx` 传参换成 `undefined`，前 2 例变红；
  把滚出视口分支改成 `return firstVisible`，第 3 例变红（空行进正文）；恢复后全绿。
- `frame-vectors.json` 与 term-bench 基线未改动且全绿（它们不用 History，走回退猜法，行为与 #390 一致）。
- `bun run affected-tests:run` 955 pass / 0 fail；`packages/cli/tests/render-port` 444 pass / 0 fail；
  `make build` 自检通过且无 `will always be undefined`；lint / format:check / typecheck:gate 无新增。
