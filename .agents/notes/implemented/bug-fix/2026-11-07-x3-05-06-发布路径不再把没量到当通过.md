# 发布路径上「没量到」不再等于「通过」：远端 sha 校验缺工具即拒 + promote 判据对齐 upload

## 决定了什么

修掉缺陷文档 X3-05 与 X3-06 两条，合成一个 PR（同一关注点：发布路径把「没量到」当「通过」）。

**X3-05：服务器缺 sha256 工具时不再静默降级**

- 新增 `scripts/lib/remote-sha.sh`，把 `--upload` 的「落地前校验」与 `--promote` 的「促升前复核」
  的远端脚本与本地判定抽成**一份**实现（此前各写一份 12 行字符串，天然会漂）。
- `judge_remote_sha_output` 的 `__NO_SHA_TOOL__` 分支由 `warn` 改为 `fail`，提示装 coreutils。
  确实装不了时用新增的 `--skip-remote-sha` 显式放行，日志必须打出「显式跳过」+「本次发布没有校验」。
  失败时先跑调用方传入的清理钩子（upload 侧的 `_cleanup_remote_staging`），不留远端半成品目录。
- 远端脚本生成改用 `printf`，不依赖外部 `cat`：这段是在**远端**跑的，而调用它的场景之一
  恰恰是「远端工具链不全」。实测 `PATH` 里没有 cat 时 heredoc 写法会让 generation 侧静默输出空串。
- `--upload-ripgrep` 的 `.sha256` 由裸 hash 改为 `<hash>  rg-<platform>`，与 tarball 格式一致
  （消费方 `fetch-ripgrep.ts` 按空白切分取第一段，向后兼容）。

**X3-06：`judgePromote` 不再比 `judgeReleaseUpload` 松**

- 抽出 `dirtyReasons(info, artifactName)`，upload 与 promote **共用同一份** dirty 判据。
- `judgePromote` 补上 `origin !== "release"` → 拒。
- 无身份产物按版本边界分：`version >= FIRST_IDENTITY_RELEASE_VERSION`（`0.1.608`，
  来源 `git tag --contains d2eb0ac6 --list 'v*' | sort -V | head -1`）→ 拒；
  更早的放行并明说没量到（回滚老版本是合法操作，拒掉等于老版本永远不能再 promote）。
  版本号不可解析 → 拒，不猜方向。
- `isAncestorOfMain === null` 由放行改为**拒**（这就是 X3-03(b)；缺陷文档要求 X3-06 一并处理）。
- 新增集合不变量测试：同一组 `BuildInfo` 输入，凡 upload 判拒的（`commit == v<ver>^` 除外），
  promote 也不得判过。

## 放弃了什么（以及为什么不选）

- **不加 `--skip-remote-sha`（只硬 fail）。** 否决理由：发布是应急操作，服务器可能是
  客户/第三方提供的、装不了包；硬锁死会把「服务器缺个工具」变成「这个版本发不出去」。
  选了显式 flag 而不是静默降级，是因为**放弃必须是一个写在命令行上的决定**，
  而不是由 `PATH` 决定的副作用——这与 X3-08 的判据同源。
- **无身份产物一律拒（不分版本）。** 否决理由：会让所有早于 `v0.1.608` 的历史版本
  永远无法 promote，而回滚到老版本是合法且必要的事故处置。
- **只按「提交时间晚于 d2eb0ac6」判身份边界。** 否决理由：产物只有 commit，没有 tag 语义；
  按版本号比对更贴近 `release.sh` 的实际入参（`--promote <version>`），且可被单测直接覆盖。
- **给 `judgePromote` 复制一份 dirty 判据。** 否决理由：这正是 X3-06 的成因。
  两份判据漂移不会报错，松的那一侧就是绕过路径。
- **把 `--skip-remote-sha` 也做成绕过的组合（如同时跳过 upload 与 promote 的校验）。**
  它确实是同一个开关同时影响两处——但两处本来就是同一类校验，语义一致；分开成两个 flag
  只会让人以为可以只放行一处，而实际上「服务器没装 sha 工具」是整机级事实。

## 拿什么证明它生效了

**测试（全绿）**

```
bun test ./tests/release-remote-sha.test.ts          # 13 pass / 0 fail
bun test ./tests/eval/artifact-identity.test.ts      # 56 pass / 0 fail
```

新测试是**行为断言**，不是文本断言：X3-05 那组真跑远端脚本（空 `PATH` → `__NO_SHA_TOOL__`、
内容损坏 → 「校验失败」且非 0），并真跑本地判定分支（默认 fail vs `--skip-remote-sha` 放行）；
X3-06 那组覆盖 `origin=local` / dirty 非白名单 / dirty 缺清单 / 无身份新旧版本 / `null` 祖先 /
不可解析版本，另加一条结构性的「promote 不松于 upload」集合不变量。

**变异自证（6/6 被对应断言捕获，逐条跑过再恢复）**

| 变异 | 结果 |
| --- | --- |
| X3-05 把 `__NO_SHA_TOOL__` 改回 `warn` + `return 0` | 「缺工具且没加 --skip-remote-sha」变红 |
| X3-05 把 `sha256sum -c` 改成 `true` | 「内容被改过」变红 |
| X3-06 去掉 promote 的 origin 判据 | 「origin=local」变红 |
| X3-06 去掉 promote 的 dirty 判据 | 「带着未提交代码」「dirty 没记」「集合不变量」变红 |
| X3-06 把 `isAncestorOfMain === null` 改回放行 | 「祖先关系测不出来」「pickMainRef 拒绝」变红 |
| X3-06 删掉无身份版本边界 | 「无身份 + 首个带身份版本起」「集合不变量」变红 |

**改到的既有断言（契约变更，非「改断言凑绿」）**

- `tests/release-channel.test.ts` 与 `tests/release-flow-contract.test.ts` 原先断言
  promote / upload 段内**含** `__SHA_OK__`、`sha256sum -c` 字面量。校验实现搬到共享库后
  段内不再有这些字面量，因此改为断言「确实调了 `remote_sha_verify_script` / `judge_remote_sha_output`」，
  命令本身在 `scripts/lib/remote-sha.sh` 上断。**判据强度不变**（仍要求那条校验存在），
  只是锚点跟着实现搬家。
- `tests/eval/artifact-identity.test.ts` 两条用例原先锁的是「`null` 祖先 → 放行但明说没验证」，
  那是被 X3-03(b) 判定为缺陷的旧行为，改为「拒」。
