# 子代理工具硬禁被 custom 路径绕过 + 06H1 T5a/T5b 死功能清理

Source: 20261101-06H1-委派与交接-落地方案（2026-11-01）

## 决定了什么

三件事，同一个关注点：**子代理的工具边界与上下文注入，该生效的必须生效，不生效的删掉**。

### 1. `resolveCustomTools` 的 `allowedTools` 分支补上 Layer 1 硬禁

`packages/core/src/agent/sub-agent.ts` 的 `resolveCustomTools` 有两条分支：

- `toolsFromAgentType` 分支走 `filterToolsForAgent`，硬禁生效；
- `allowedTools` 分支是「按名从 `toolRegistry` 直接取」，**此前没有任何过滤**。

后果：在自定义 agent 的 frontmatter 写 `tools: [monitor]` 就能把
`ALL_AGENT_DISALLOWED_TOOLS` 里的工具拿回去。而 monitor 的硬禁理由
（生命周期最长 30 分钟，远长于子代理；子代理一结束，它挂的监控没有事件消费者，
只能空转到期限，期间每条事件都在叫醒一个已收尾的回合）在那条路径上完全失效。
同理可拿回 `task_stop` / `task_output` / `enter_plan_mode` / `exit_plan_mode` / `save_memory`。

修法：把 Layer 1 判据抽成 `isAllAgentDisallowedTool(name)` 从 `tool-filter.ts` 导出，
两条路径共用。MCP 豁免口径与 `filterToolsForAgent` 一致（名单按内置工具名写，
对 `mcp__*` 对不上）。被裁掉的工具单独告警，与「名字写错了」的 missing 分开报——
排查时不该把「策略裁掉」误认成「工具不存在」。

### 2. T5a：删除 `AgentDefinition.omitClaudeMd` 死字段

该字段声称「省略主代理 CLAUDE.md 上下文，只读探查类省 token」，但全仓**零读取**——
子代理从来没带过项目指令，这个字段是纯装饰。删除，并在 `enhanceSubAgentPrompt`
的注释里写明「子代理一律不带主代理的项目指令」及理由。

### 3. T5b：删除 agent 级记忆整条回路

三处一并删除：

- 读端注入（`enhanceSubAgentPrompt` 里的 `buildAgentMemoryInjection`）
- 写端 agent scope（`memory.ts` 的 `saveAgentMemory` 分支，含 schema 的 `"agent"` 枚举、
  constructor 的 `agentType` 参数、`withAgentType` 方法）
- `buildIsolatedToolRegistry` 里的 `withAgentType` 绑定分支

`packages/core/src/memory/agent-store.ts`（312 行）随之删除，其测试文件同删。

## 放弃了什么（以及为什么不选）

### 放弃 T5a 的选项 A（做成按类型开关）

方案原文倾向 A：`omitClaudeMd` 缺省按类型取，通过 `SID_SUBAGENT_CLAUDEMD=1` 打开。
**没选它的理由是它与方案自己的「不选直接给 task 类带上」互相矛盾**：A 的实质就是
「实现一个能带上 CLAUDE.md 的路径，只是默认关」。方案给不选「直接带上」的理由是
「样本只有 task 3 次 / general-purpose 6 次，没有证据说明不带造成了问题；带上会让
task 类子代理 system 从几百字符涨到几万」——这条理由对 A 同样成立，甚至更强：
A 要多维护一条默认关闭、无人验证的代码路径。

B 同样满足方案的完成判据（「仓里不再有定义了、零读取的字段」），代价是 2 行删除 + 一段注释。
选 B。

### 放弃 T5b 的选项 A（放开 save_memory，只允许 scope=agent）

方案原文给的 A 是「`save_memory` 从硬禁名单移出，但子代理侧只允许 `scope: agent`」。
没选的理由有两层：

1. **它需要先修上面那个硬禁绕过缺陷**，否则「移出硬禁 + 只允许 agent scope」等于
   同时开放 customize 路径——两条改动耦合，出问题难归因。
2. 方案 B 的理由本身站得住：记忆写入归 07（主代理的后台抽取已在每轮跑），
   让每类子代理再各自攒一份记忆是一个没有需求证据的新写入源。
   仓库里 `~/.sid-code/memory/agents/` 目录不存在，说明这个功能从未被真实使用过。

### 放弃顺手修 `fork` 相关代码（T7）

T7 是判据型任务，要求 T3 上线跑满两周再评估 fork 去留。T3 于 2026-11-07 合入，
今天 2026-11-15 只有 8 天，**未到评估时点**。本 PR 不碰 `fork.ts` / `mainContextProvider`。

## 拿什么证明它生效了

### 判据 1：硬禁绕过的回归测试

新增 `packages/core/tests/agent/subagent-custom-tool-hardban.test.ts`，6 pass：

```
(pass) isAllAgentDisallowedTool（Layer 1 判据） > 硬禁名单里的工具判 true
(pass) isAllAgentDisallowedTool（Layer 1 判据） > 普通工具判 false
(pass) isAllAgentDisallowedTool（Layer 1 判据） > MCP 工具豁免
(pass) resolveCustomTools 的 allowedTools 分支 > frontmatter 声明 monitor → 被裁掉，拿不到
(pass) resolveCustomTools 的 allowedTools 分支 > 硬禁工具即便写成别名也被裁
(pass) resolveCustomTools 的 allowedTools 分支 > 声明不存在的工具 → 不进结果
```

**变异自证**：把 `resolveCustomTools` 里新增的 `isAllAgentDisallowedTool` 判定注释掉，
`frontmatter 声明 monitor → 被裁掉` 这条立刻变红；恢复后回到 6 pass。
