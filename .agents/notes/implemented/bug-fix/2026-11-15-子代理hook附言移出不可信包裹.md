# 子代理路径的 hook 附言移出不可信包裹

## 决定了什么

`query/tool-hook-lifecycle.ts` 的 `runPostToolHooks` 返回值从 `string` 改成
`{ output: string; notices: string[] }`：

- `output` 是工具产出（含 hook 整段替换后的输出），调用方按来源决定是否包进
  `<external-content untrusted="true">`；
- `notices` 是 harness 自己的附言（`[Hook 附加上下文]` / `[Hook 反馈]`），
  调用方拼在**包裹外面**。

唯一调用方 `query/run-tool-use.ts`（子代理三条执行路径收口处）改为三段拼接：
前置附言（未知键提示 / 参数被改）→ `wrapExternalContent(output)` → 后置附言
（hook 附加 / 反馈），与主循环 `tool-executor.ts` 的顺序对齐。

## 放弃了什么（以及为什么不选）

- **在 `runPostToolHooks` 内部判 provenance**：该函数不知道工具来源（MCP / web_search /
  ReadMcpResource），判据在调用方的 `resolveContentProvenance` 里。在函数内判等于把
  来源知识复制一份，两处必然漂移。
- **把附言整段去掉**：hook 反馈是用户配置的护栏（cc 对齐项），去掉等于静默降级。
- **给函数加 `keepNoticesSeparate` 开关**：唯一调用方就是子代理路径，加开关只多一条
  永不执行的分支；直接改返回结构，编译器会把所有调用点顶出来。

## 拿什么证明它生效了

- `bun test packages/core/tests/agent/subagent-hook-cc-align.test.ts
  packages/core/tests/query/run-tool-use*.test.ts` → **48 pass / 0 fail**。
  其中「进程内：PostToolUse 的 `[Hook 反馈]` 回灌到 tool_result」等用例断言附言仍在
  content 里（只是位置从包裹内移到包裹外），行为未丢。
- 主循环侧口径对照：`tool-executor.ts` 的 `prefixNotices / renderedOutput / suffixNotices`
  三段同样是「附言在包裹外」，两侧现在同序同位置。
