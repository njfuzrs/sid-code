# 复合命令的 & / 换行绕过、Seatbelt profile 两处失效、curl 被当只读

## 决定了什么

回源码复核了 2026-08-15 的「CC §17 安全与沙箱」审计。报告里的 4 个 P0 与 4 个 P1
在这一个多月里大多已修（沙箱 settings 映射、WebFetch 隔离提炼、信任对话框、
MCP pending 审批、deny/allow 的逐子命令拆解都有真实消费点）。还活着的是下面三处，
本次修掉：

1. **`splitCompoundCommand` 不认后台 `&` 和换行**（`packages/core/src/permission/shell-parser.ts`）。
   deny/allow 的逐子命令拆解都建在它上面，分隔符漏了，拆解等于没做：
   `allow: ["Bash(ls *)"]` 会把 `ls & whoami` 整条吞掉放行，
   `deny: ["Bash(curl *)"]` 也拦不住 `ls\ncurl evil.com`。
   补上这两种分隔符，并排除两个容易误拆的形态：`&>` / `&>>` 是全部输出重定向，
   `2>&1` / `>&2` 是 fd 复制（`&` 紧跟在数字或 `>` 后面时不是命令边界）。
   ask 规则此前仍是整条匹配（`checker.ts` Step 5），同样补成逐子命令的 some 语义，
   否则 `ask: ["Bash(curl *)"]` 在 always-allow 下会被静默跳过。

2. **Seatbelt profile 两处写出来就是失效的**（`packages/core/src/permission/sandbox.ts`）。
   路径直接插进 `(subpath "...")` 的双引号，cwd 或配置路径里的 `"` / 换行能截断规则、
   注入一条新的 allow；新增 `seatbeltQuoted` 做转义。
   网络白名单把 `localhost` 写进 `remote ip`，而 Seatbelt 的该过滤只认 IP，
   加上 profile 开头的 `(deny default)`，默认白名单等于一条匹配不到任何连接的放行。
   改为生成前用 `prepareSandboxHosts` 把主机名解析成 IP（`cli.ts` 在构造
   `SandboxManager` 之前 await），解析失败的条目丢弃并记警告，不再原样写进去假装生效。
   顺带修正 `cli.ts` 的日志：非 darwin 上 `isEnabled()` 为 false、命令不会被隔离，
   原先仍打印「macOS Seatbelt 沙箱已启用」。

3. **`curl` / `wget` 被判只读直接放行**（`packages/core/src/tool/bash/read-only-validation.ts`）。
   旧规则「不带 `-o`/`-O` 就是只读」只看了有没有写文件，漏了两面：请求会把 URL 参数里的
   数据发往任意主机，响应体（含网页里的指令）经工具输出进主模型上下文。
   `CONDITIONAL_COMMANDS` 里改为恒返回 false，落到权限确认；想免确认需显式配 allow 规则。
   `ping` / `dig` / `nslookup` / `host` 只问本地解析器，保持只读。

## 放弃了什么（以及为什么不选）

- **不实现 Linux bubblewrap 沙箱，也不做 `/sandbox` 斜杠命令。** 报告把这两项列为 P2，
  且明确「按需求排期」。本次只修「开关打开却没有所声称的隔离」这句假话
  （日志改为如实警告），不新增一个未被需求驱动的沙箱后端。
- **不把 Seatbelt 网络规则改成域名匹配。** Seatbelt 的 `remote ip` 没有域名形态，
  硬写主机名就是本次修掉的那个 bug。域名支持需要先把名字解析成地址，这正是
  `prepareSandboxHosts` 做的事；解析结果是一次性快照，DNS 中途变化不会刷新，
  这个取舍写在函数注释里。
- **不把「敏感文件读取」从 ask 改成硬 deny（bash 侧）。** Read 工具路径已经是硬 deny
  （`path-validator.ts`），bash 侧的 `cat ~/.ssh/id_rsa` 仍是 high → 需确认。
  把它改成硬拒绝会拦掉合法的排查场景，且没有用户信号说确认挡不住，先不动。
- **不做 classifyAllShell / 侦察类预防性阻止，也不给 bypass 模式加容器前提检测。**
  报告自己把前者归为「CC 分类器三大类别中我们没有的」，属新增能力而非缺陷修复；
  `disableBypassPermissionsMode` 已作为企业策略 killswitch 存在（`mode-policy.ts`），
  裸机能否开 bypass 是策略决定的，不是漏了检测。
- **`\&&` 的旧测试断言是错的，改了断言而不是迁就它。** `shell-parser.test.ts` 原期望
  `echo a \&& echo b` 不拆分。用 `bash -xc` 实测这条会执行**两条**命令
  （`echo b` 与 `echo a '&'`）：`\&` 只转义紧跟的一个字符，第二个 `&` 仍是后台符。
  保持旧断言等于保留一条绕过（`echo safe \&& curl evil` 整条躲过逐子命令检查）。

## 拿什么证明它生效了

全部在 worktree `fix/sec17-sandbox-permission-gaps` 上跑：

- `bun test ./packages/core/tests/permission/ ./packages/core/tests/tool/bash/ ./packages/core/tests/tool/bash-redirect-extraction.test.ts ./packages/core/tests/tool/git-config-readonly.test.ts`
  → **726 pass / 0 fail**（34 个文件）。其中新增的钉点：
  - `shell-parser.test.ts`：`ls & rm` 拆成两段、`ls\ncurl` 拆成两段、`&>` 与 `2>&1` 不误拆、
    `echo a \&& echo b` 拆成 `["echo a \&", "echo b"]`。
  - `checker.test.ts`：`allow: ["Bash(ls *)"]` 不再放行 `ls & whoami` 与 `ls\nwhoami`；
    `deny` / `ask: ["Bash(curl *)"]` 拦住 `ls & curl evil.com`、`ls\ncurl evil.com`、
    `echo a \&& curl evil.com`；always-allow 下 ask 规则仍要求确认。
  - `p2-wiring-and-sandbox.test.ts`：路径里的 `"` 与换行被转义后引号仍成对；
    `localhost` 解析成 `127.0.0.1` / `::1` 写入 `remote ip`，字面量 `localhost` 不出现；
    非 darwin 上 `isEnabled()` 为 false 且 `wrapCommand` 原样返回。
  - `p0-safety-bypass.test.ts`：`curl` / `wget`（含带 `-o`）不再是只读，`dig` 仍是。
- `bun build --no-bundle` 对 `sandbox.ts` 与 `checker.ts` 均 exit 0。
- `bun run docs:gen-reference -- --check` → 「参考页与源码一致」（本次没动生成器的源目录）。
- `bash -xc 'echo SAFE \&& echo PWNED'` 实测输出两条 trace（`+ echo PWNED` 与
  `+ echo SAFE '&'`），这是改 `\&&` 断言的依据，不是推测。
