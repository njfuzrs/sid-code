# `/stats` 缓存命中改用归一化命中量，单价按模型端点取

## 决定了什么

修 D9（P0）：`/stats` 面板（`StatsDialog`）的「缓存命中」整行是错的 ——
显示的是**当前上下文大小**，命中率算成 4%（真实 91.7%）。两处错误同源：

```ts
// 旧：分子 stock（末次请求的完整 prompt 99,126）、分母 flow（累计发送 2,398,645）
const cacheHitRate = Math.round((stockInputTokens / inputTokens) * 100); // = 4%
<StatRow label="缓存命中">{fmtNum(stockInputTokens)}</StatRow>             // = 上下文大小
```

落地三处：

1. **命中量与命中率改用 `SessionState.getNormalizedCacheUsage()`**
   （`packages/cli/src/ui/components/StatsDialog.tsx`）：`cacheHitTokens / promptTotal`，
   显示 `cacheHitTokens` —— 与 `/cost`、Footer 同一个数据源，按每个模型自己的 provider
   归一化后再加总。命中率保留一位小数（`toFixed(1)`，91.7%），与 `/cost` 逐字一致。
2. **无 `sessionState` 时整行省略**，不退回旧算法。「退回」正是这次缺陷的形态：
   旧算法不是「近似值」，是把两个不同口径的数相除。
3. **单价补端点**（`DialogSwitch.tsx`）：`resolvePricingUSD(model, availableModels)` →
   `resolvePricingUSD(model, availableModels, modelBaseURL)`，端点按「模型自己配的
   `baseURL` > 顶层 `config.baseURL`」解析，与主循环取端点的口径一致。
   计价是「模型名 + 端点」复合键，不传端点会落到「仅模型名」或跨端点兜底价，
   面板显示的单价和实际计费不是同一条。

顺带删掉 `DialogSwitch` / `BottomRegion` → `StatsDialog` 的 `stockInputTokens` 透传链
（共 3 个文件各 1 行）—— 这个 prop 在新实现里没有任何正确用途，留着等于邀请下一个人
把命中率改回去。`BottomRegion` 自己仍保留该字段，Footer 的 `↑` 继续用它。

## 放弃了什么（以及为什么不选）

- **不从 `/cost` 抽 `buildCostReport` 让 `/stats` 复用**：那是方案文档 PR-B 的 D11–D15
  重做范围，改动面（数据层 + 渲染层 + 官网 + 有意改旧测试）远大于本 PR。
  D9 是 P0 数据错，用户正在读错数，不该等面板重做。本 PR 先与 `/cost` **同源**
  （同一个 `getNormalizedCacheUsage()`），根因是「第二份算法」，同源即消灭。
  面板结构对齐留给 PR-B。
- **不在 Footer / `/cost` 侧做任何改动**：本次只修 `/stats`。「命中率两种算法」
  在 Footer 上对应 D18，属于同一 PR-A 的另一条；它的修法是 Footer 改读 bridge 推送的
  归一化命中率（跨 core/cli/UI 三层），和本 PR 不共享代码路径，混进来会让 review
  分不清哪几行是 D9。
- **不把 `stockInputTokens` 并进「上下文占用」行显示 token 数**：那会给一个
  「本来就没有 token 数」的行新增信息，属于 D3「口径标注」的范畴（PR-B）。
  本 PR 只做减法：错误的数据源直接摘掉。
- **不给「缓存命中」行加「占累计 prompt 的 X%」文案**：命中率已经以 `(91.7%)` 形式
  跟在同一行，再加一句分母说明是 PR-B 版式重做的事。

## 拿什么证明它生效了

**取证会话第一段的真实数字**（累计 prompt 2,398,645、命中 2,199,936、末次 stock 99,126）：

```text

(pass) 同名模型两个端点不同价时，面板显示本端点价
```

**变异自证**（CLAUDE.md：恒绿的断言比没有断言更危险）：

- 变异 A —— 命中率改回 `getStockPromptTokens() / inputTokens`：
  用例 1 变红，报 `Received: "│   缓存命中      2,199,936 tokens (4%) │"`
  —— 正是缺陷现场那个 4%，且看清了报的是什么。

  用例 3 变红，`Expected 1, Received 9` —— 跨端点兜底先借到了另一个端点的价。
