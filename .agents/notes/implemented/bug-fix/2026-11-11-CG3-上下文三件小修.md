# CG-3：/memory reload 补传 deny 摘要、git 快照声明分支会变、压缩摘要禁写环境事实

## 决定了什么

三件独立的小修，合在一个 PR 里，判据是「同优先级、同关注点（上下文里的环境/约束事实失真）、
每个都能独立回滚」；任一单改都不构成独立上线单元（各是一两行），合并成本低于拆开。

**M4 — `/memory reload` 补传 `denyRulesSummary`**（`packages/cli/src/command/commands/memory/memory.ts`）

`/memory reload` 走的是与启动路径**不同的**一条 `buildSystemPrompt` 调用：传了 projectRules /
memorySystemPrompt / 延迟工具开关，唯独漏了 `denyRulesSummary`。于是「刷新记忆」会顺手把
`<permission-constraints>` 约束块从系统提示词里抹掉——deny 规则本身仍在权限层生效，所以
不报错、不拦截，只是模型的约束认知静默退化到「靠撞墙发现」。

按**当前** checker 重取而不是复用启动时的值：reload 恰好会重读 CLAUDE.md，而 CLAUDE.md
可以改写 deny 规则（与 `app.ts:4726` 的重建路径同一理由）。

**H2 — `<git-status>` 声明补「分支也可能已变」**（`packages/core/src/config/attachments.ts`）

快照首行原本只声明「工作区文件状态会变」，下面那行 `Current branch:` 没有任何过期标注。
本仓的标准流程恰好是 `worktree-xxx` 改名成 `fix/xxx`，模型会拿启动时的分支名判断
「我在哪个 PR 上」。补的这句给出可执行的实时口径（`git branch --show-current`）并明说
不要直接引用快照里的那行——只声明「这是快照」不足以让模型推断出下一行已过期。

CG-6 的边界（只检测本会话 bash 执行 git 写命令，外部进程改的分支检测不到）已按后续规划
§2.4 写在代码注释里，按已知边界处理，不留作待排查项。

**S3 — 摘要 prompt 加环境事实禁令**（`packages/core/src/query/compact/auto-compact-prompt.ts`）

在 `BASE_COMPACT_PROMPT` 的输出要求里加一条：当前工作目录 / 分支 / 是否在 worktree / 对应绝对路径
**不要写进摘要**，理由是它们每一轮由系统从环境重新获取，写进摘要只留一份会过期的副本。
同时显式给出唯一例外——「当前在等待什么」照常记录（T-W1-7 有意保留，见下方「放弃了什么」）。

## 放弃了什么（以及为什么不选）

| 候选 | 否决理由 |
| --- | --- |
| M4 复用启动时算好的 `denyRulesSummary`（存进 ctx 再读） | reload 会重读 CLAUDE.md，CLAUDE.md 又能改写 deny 规则。复用旧值 = 修好了「丢失」却留下「过期」，同一个字段两个来源 |
| 给 `Checker` 接口加 `describeDenyRules?()` 声明，去掉 `as any` | 要动 `permission/types.ts` 的公共契约并按实现方全体核对。这是三件小修的一个 PR，契约改动应单独做、单独 review；本次沿用 `app.ts` 既有的 `typeof` 探测写法 |
| H2 直接删掉 `Current branch` 字段 | 分支名对「我在哪个 PR 上」是有用的免费信息。会过期是本仓 worktree 改名流程导致的，不是字段本身无用（后续规划 §2.4 的裁决） |
| H2 改成每轮跑 `git branch --show-current` | 每轮一次 git fork，买的是「外部进程改分支」这个极低频场景。CG-6 已在「本会话 bash 执行 git 写命令」这一个时机上做，这次只补声明 |
| S3 把「当前等待」也从摘要里删掉 | 它是**对话态**不是环境态：压缩后进程内登记表仍在、`hasPromiseWait()` 照常为真，但模型看不到「我在等 monitor m7 盯 PR #662」，会重复起一个盯同一对象的 monitor。台账 M5 已判「不改」 |
| S3 只改摘要 prompt、不做压缩后补发（CG-6 的事） | 生成侧先切断是 O(1) 成本且立刻生效；补发要等 CG-6 的通道。两者是纵深，不是二选一 |
| 三件拆成三个 PR | 每条各是一两行、无依赖、无独立上线价值；PR 固定成本（分支 + CI 一轮 + review 上下文切换）高于收益 |

## 拿什么证明它生效了

**新增/扩展的断言（每条都做了变异自证）**

- `packages/cli/tests/command/memory-reload-deny-rules.test.ts`（新文件，3 例）：
  ① 有 deny 规则时重建后的提示词含 `<permission-constraints>` 与规则正文；
  ② 空摘要不注入约束块；
  ③ ctx 无 `permissionChecker`（headless/测试）时 reload 照常完成、不崩。
  **变异自证**：删掉 `denyRulesSummary,` 传参 → ① 变红（`Expected to contain: "<permission-constraints>"`），
  其余两例仍绿（说明断言确实咬在这一点上，不是靠前置失败连带）。
- `packages/core/tests/config/attachments.test.ts` 新增「★分支也标明可能已变，并给出实时获取口径（H2）」：
  断言 `当前分支也可能已经变了` / `git branch --show-current` / `不要直接引用` 三者共存。
  **变异自证**：删掉那句声明 → 该例变红（`Expected to contain: "当前分支也可能已经变了"`）。
- `packages/core/tests/query/compact/auto-compact-prompt.test.ts` 新增两例：
  「★环境事实禁令」「★当前等待不在禁令范围内」。
  **变异自证**：删掉禁令段 → 两例同时变红（`Expected to contain: "环境事实"` / `"当前在等待什么"`）。

**一个现场佐证**：本次会话的 `<git-status>` 快照里 `Current branch:` 一直是
`worktree-cg3-context-small-fixes`，而实际分支在中途被改名成 `fix/cg3-context-small-fixes`——
H2 描述的现象在同一会话里就发生了一次，且在此之前模型没有任何可得的口径判断它已过期。

**牺牲了什么**：每轮多约 60 个字符的声明文本（动态区，不进 Anthropic 的 `cache_control` 段）；
摘要 prompt 多一行要求，压缩调用的输入 token 可忽略。三个方向里换的是「更准」，代价是「更省」的极小一点。
