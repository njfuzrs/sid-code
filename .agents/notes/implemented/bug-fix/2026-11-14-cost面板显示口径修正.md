# /cost 的时段、单价、请求数与断裂文案改按真实口径显示

## 决定了什么

修掉 `/cost` 面板上五类「数据算对了但显示说错话」的缺陷（方案 PR-B）：

1. **时段占比三态化**（CP-3）。`cost-report.ts` 的 `peakShare` 从 `number` 改成
   `number | undefined`，`resolvePeakShare` 在「无费用 / 旧快照 / 两桶之和 ≠ 总额」
   三种情况下返回 `undefined`，渲染层写「时段拆分不可用」。旧写法
   `(peakCostUSD ?? costUSD) / costUSD` 让全程空闲的会话恒显示「全程高峰时段」。
   措辞从「高峰占比」改为「高峰**费用**占比」，与账本 `peakRatio`（请求数分母）区分。
2. **单价列改实际均价**（CP-4）。`CostReport.main` 新增 `breakdown`（byModel 四段之和）、
   `avgPrice`（费用 ÷ token × 1e6）、`breakdownCarried`；单价列头改「均价」，
   牌价四个数字移到来源行另起一行。旧写法拿牌价乘 token 永远算不出费用（全空闲差一半），
   多模型时费用列还恒为 `$0.0000`。
3. **首行请求数拆作用域**（CP-5）。宽列写「主循环 N 次 · 辅助 M 次（本次启动后）」，
   窄列退化 `请求 a+b`；模型名阈值从 80 提到 100 列（首行多了约 20 列信息）。
   旧写法把会话级与进程级两个数合成一个「31 次请求」。
4. **断裂文案结构化**（CP-8）。`CacheBreakReport` 新增 `prefixHashSame` /
   `messagePrefixSame` 两个结构化证据字段（与 hash/`messagePrefixChanged` 同处产出），
   `CacheBreakSummary` 新增 `latest` 证据与上游/本地分类计数；渲染层**按字段拼文案**，
   不再对 `changes[]` 做字符串拼接。
5. **字节侧断裂可见**（CP-9）。`prefix-break-probe.ts` 新增进程内环形缓冲 +
   `getRecentPrefixBreaks()` / `clearRecentPrefixBreaks()`（挂在 `resetSideCallStats`
   旁边清理），collector 在 `broken` 时记一条；`/cost` 的缓存区拆成「命中下降 N 次
   （上游波动 x / 本地 y）」与「本地前缀断裂 M 次（字节级，浪费约 z% 字符）」两行。
6. **显示细节**（CP-10）：辅助调用耗时标「逐次累计」+ 注释区口径说明；单次请求样本
   < 20 不显示 p95 并显示 `n=`；辅助调用明细非零小额显示 `<$0.0001`；token 列附命中率。
7. **PR-A 收尾**：`/cost` 调 `reconcileSelfReports()` 取差额，非零时提示「N 次辅助调用
   尚未自报入账」，**只提示不补账**（补账仍在会话结束）。
8. `SessionState.updateUsage` 新增可选的 `at?: Date`（第 8 参，生产调用点一律不传），
   让 B1 的四态能被断言 —— 否则测试跑在墙钟上，无法让整个会话落进空闲窗口。

## 放弃了什么（以及为什么不选）

- **把辅助调用次数持久化进快照**（CP-5 的方案①）。它能彻底消掉作用域不一致，
  但要动快照 schema、回灌与迁移（CP-12），而本 PR 的目标是显示口径。选方案②
  「标注作用域」：不改存储、不会让旧快照反序列化失败，代价是用户仍需读一行标注。
- **均价按 `byModel` 逐行算、渲染层相加**。多模型时费用列必须是聚合值，
  逐行算再相加等于在渲染层做第二次加法（D9「排版层重算指标」的复发形态）。
  改成数据层聚合一次。
- **把 `messagePrefixChanged` 直接改名成 `messagePrefixSame`**。该字段已被聚合与遥测
  消费，改名会让新旧记录不可比。保留两者、在产出点用同一表达式同时写入。
- **`fmtUSD` 全局改成小额显示 `<$0.0001`**。表格费用列必须能验算（`token × 均价`
  与显示值比对），变成不可解析的字符串会让验算失效。只给辅助明细行用独立的
  `fmtSideUSD`。
- **把断裂文案写进 `changes[]` 再整段显示**。一条断裂可能带多个类别，join 后 90+ 列，
  70 列终端必然折行；且 `changes` 没有强弱之分，而「是不是上游波动」依赖三条证据同时成立。

## 拿什么证明它生效了

```
bun test ./packages/cli/tests/command/cost-prb-acceptance.test.ts   → 36 pass / 0 fail
bun test <8 个既有 cost 测试文件>                                    → 77 pass / 0 fail
bun run affected-tests:run                                          → 5086 pass / 0 fail（判定为全量）
bun run typecheck:gate                                              → 62/62，无新增
bun run lint                                                        → 0 warnings / 0 errors
make build                                                          → 产物自检通过
bun run docs:gen-reference                                          → 6 页 + llms.txt 生成，无漂移
```

**变异自证**（脚本逐条改坏 → 跑对应测试 → 恢复，三条全部变红）：

| 变异 | 还原的缺陷 | 结果 |
| --- | --- | --- |
| `resolvePeakShare` 回落到 `?? costUSD` | CP-3 原始 bug | B1 变红 ✓ |
| `main.avgPrice.uncached` 改回牌价 | CP-4 原始 bug | B6 变红 ✓ |
| 证据文案写死「消息前缀逐字节一致」 | CP-8 原始 bug | B11 变红 ✓ |

另外发现并修掉了一个实现缺陷：缓存段的显示条件原本只有「有命中率或省钱」，
于是**有断裂记录但命中率算不出来时，整段不渲染** —— 最该看到断裂的人反而看不到。
条件里加上「有断裂记录」，由 B9 的用例守住。
