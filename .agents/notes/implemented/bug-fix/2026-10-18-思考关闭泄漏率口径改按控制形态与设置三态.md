# 思考关闭泄漏率口径改按「设置 off × toggle」，Responses 路径补埋点

## 决定了什么

对应遗留清单（20261018 思考开关修复落地复审）的 R1 / R5 / R6 / R10 / T4。

- `BilledRequest` 增加四个观测字段，落 `events.jsonl`：`thinking_setting`（on / off / auto 三态）、
  `thinking_control`（toggle / locked-on / none）、`thinking_shown`（状态栏展示态）、
  `thinking_wire_thinks`（按线上实发推出的「服务端在思考」，不可判时缺省）。
  算法收在 `packages/core/src/llm/thinking-observation.ts` 一处。取数优先级：主循环写的
  `SendParams.thinkingObservation`（和 BeforeModel 用同一个 `cap`）> provider 出口按真名现算
  （side-call / 子代理 / fork）。fallback 重解析时按备用模型重写 control / shown。
- `aggregateThinkingLeakStats` 的分母写死为 `thinking_setting === "off"` 且 `thinking_control === "toggle"`。
  `locked-on` 单列为「恒思考关不掉」，`none` 单列为「无开关族」，auto 解析成关的单列参考，都不进分母。
  缺新字段的老记录记 `legacy`，没有 `thinking_wire` 的记 `uninstrumented`，两者都不进分母，
  非 0 时 digest 这一节标 ⚠。
- Responses API 流式 / 非流式两条路径补上 `thinking_wire`（恒为 `omitted`：请求体只有 `reasoning.effort`）、
  `thinking_in_response`（出现 reasoning 块或 reasoning token > 0）和上述观测字段。
- R10「展示≠实发」：只统计 `thinking_shown` 与 `thinking_wire_thinks` 都给出的调用；`omitted`
  且服务端默认未知（OpenAI 族、注册表未精确命中的名字）记「不可判」。`wireThinks` 由 digest
  与 `thinking-state.test.ts` 的不变量测试共用。

## 放弃了什么（以及为什么不选）

- **在 digest 里按 `thinking_wire === "omitted"` + 模型名猜「是不是恒思考」**：会让 digest
  多出第三份恒思考判据，正是 20261016 方案 §0 那种「三处各算一遍」的病。控制形态只在发生侧算一次，
  digest 只读字段。
- **把 `thinking_intent` 改成三态**：已有轨迹和 fallback（D9）都按布尔读它，改语义会让新老轨迹
  同名字段口径不同，违反「分母口径写死」。所以新增字段，旧字段保持原样。
- **老轨迹按旧口径继续出数**：旧口径就是要修的错数，宁可报「口径不可算」也不报一个看着像数据的比例。
- **OpenAI 族 `omitted` 按模型族猜服务端默认**（DeepSeek 开、GLM ≤5.2 关……）：手里没有逐模型实测数据，
  猜错会让「展示≠实发」出假阳性。宁可记不可判。
- **代价**：每个 side-call 出口多一次 `resolveEffortCapability`（纯内存查表），换来的是口径正确。
