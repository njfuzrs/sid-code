# 清单计数口径改名，并把 `-1` 的两义拆成 `null` + `reason`

## 决定了什么

落地《进度清单：横向剖析第五部分落地方案》（`docs-research/sid-code/bugfixes/done/20261031-05H1-进度清单-落地方案.md`）遗留的 T4，issue #631。

- `NoProgressNagInjected`（`kind=todo`）的两个计数字段改名，把单位写进名字：
  - `turnsSinceLastTodoWrite` → `assistantMsgsSinceTodoWrite`（单位：assistant 消息条数）
  - `turnsSinceLastReminder` → `absTurnsSinceReminder`（单位：`absoluteTurn` 差值）
  - 只改事件字段名与 `TodoReminderTurnCounts` 接口；内部逻辑、阈值、提醒行为一律不变
- `-1` 改为 `null`，并新增 `todoWriteDistanceReason: "never" | "compacted_away"`
  - 判定依据：SessionState 的 `LAST_TODO_WRITE_VERSION_KEY`（跨用户消息 + 跨压缩持久）。
    有值说明本会话写过清单，只是那段历史被压缩删掉了；无值才是真的从未写过
- 读取侧（`packages/core/src/trace/digest.ts`）**新旧都认**：
  `e.data.assistantMsgsSinceTodoWrite ?? e.data.turnsSinceLastTodoWrite`，
  `null` / 负数整体排除。必须先判 `null` 再转数字——`num(null)` 会得到 0，
  直接喂进去会把「从未写过」算成「距离 0」，正是本改动要消掉的歧义
- 同步 4 个测试文件、`website/blog/sc-05-plan.md` 的代码示例

## 放弃了什么（以及为什么不选）

- **方案 A（两个计数都改成数 assistant 消息）不选**：`absTurnsSinceReminder` 的锚点存在
  SessionState（`LAST_TODO_REMINDER_TURN_KEY`），改成消息条数要连锚点语义一起换，
  改动面比改名大，而现有提醒逻辑（5.2 ① 已证明有效）不需要动。
- **不保留旧字段名同时写两份**：新事件只写新字段，历史数据由读取侧兼容。
  同时写两份会让每条事件多 40 字节左右，且两份值将来可能漂移；
  读取侧兼容已足够覆盖历史轨迹（`digest` 是唯一生产消费者）。
- **`reason` 只给 todoWrite 距离，不给 reminder 距离**：`absTurnsSinceReminder` 直接由
  SessionState 算出，压缩不会让它丢；`null` 只可能是「从未注入过」，没有第二种来源。
  加一个恒为 `never` 的 reason 字段只会误导读者。
- **不改事件名、不新增事件**：`TodoProgressAdvanced` 的前例（T7）已经证明加字段比换事件名
  对分析脚本友好；事件名是 `scripts/` 与外部分析的过滤键，换名等于让所有历史脚本失效。

## 拿什么证明它生效了

```bash
bun test ./packages/core/tests/query/todo-reminder-scan.test.ts \
         ./packages/core/tests/trace/todo-digest.test.ts \
         ./packages/core/tests/query/todo-realtime-integration.test.ts \
         ./packages/core/tests/query/todo-nag-conditional-cap.test.ts \
         ./packages/core/tests/query/todo-plan-part5-wiring.test.ts
# → 67 pass / 0 fail / 140 expect()
```

新增/改写的用例：

- `todo-digest.test.ts`「口径 5」：`null` 不参与最大值；全 `null` → `undefined`；
  **历史事件（旧字段名 + `-1`）照常聚合**——兼容期用例
- `todo-reminder-scan.test.ts`：字段改名后全部扫描/节流用例原样通过（含
  「`TURNS_SINCE_WRITE` 真正参与判定」「C4 放宽」两组回归哨兵）
- `todo-realtime-integration.test.ts`：接线断言从 `toHaveProperty("turnsSinceLastTodoWrite")`
  改为新字段名，证明 `queryLoop` 真的在写新字段

变异自证：

- 把 `digest.ts` 的 `null` 判定删掉（直接 `num(v)`）→「全是 null → undefined」用例变红
  （`num(null) === 0`，最大停滞算成 0）
- 把兼容分支去掉（只读新字段）→「历史事件仍是旧字段名 + -1」用例变红

上线后要看的信号：新版本轨迹里 `NoProgressNagInjected`（`kind=todo`）不再出现
`-1`，且 `todoWriteDistanceReason` 的 `never` / `compacted_away` 比例可算。

trade-off：本次是纯观测口径改动，不影响主循环行为（更快 / 更省 / 更准 三条均无变化），
只让「更准」的归因多一个可分辨维度。
