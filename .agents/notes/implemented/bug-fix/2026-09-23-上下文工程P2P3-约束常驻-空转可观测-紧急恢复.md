# 用户约束常驻、同参空转运行时可观测、紧急截断补轻量恢复

来源：`docs-research/sid-code/bugfixes/todo/20260920-上下文工程-顺着sc-02-context核出的缺陷.md` 的全部 P2 / P3（P2-16 … P3-23，共 8 条）。P0 五条、P1 十条已分别在 2026-09-21 / 09-22 落地，本条收尾同一份审计的最后一批，合一个 PR。

## 决定了什么

1. **P2-16** `notebook_edit`（规范化 `notebookedit`）收进 `NON_DISCARDABLE_TOOLS`。它与 `edit`/`write` 同语义（改 Jupyter notebook、有副作用、输出不可靠重跑复现），此前两个名单都不在，落「未知工具」分支被原样跳过 —— 方向安全但不是有意设计。P0-4 那条「名单与真实 `tool.name()` 归一化后相交」的门禁同步加上它。
2. **P2-17** 新增 `generateCriticalRemindersAttachment`，成为 `PRIORITY.CRITICAL_REMINDER`（=1，最高）的**第一个生产者**。`runPostCompact` 从被压缩段里取 `kind === "correction"` 的决策点，经 `onCriticalConstraints` 回调交给 App，累积进会话级 Set 并重建 system prompt。与 deny 规则同渠道（常驻 system、不受消息压缩影响）、优先级更高（口头约束没有权限层兜底那道第二防线）。封顶 10 条、超限保留最早的。
3. **P2-18** `formatCompactSummary` 第 4 步不再复活第 2 步已判定丢弃的草稿。模型只吐 `<analysis>foo`（未闭合、无 `<summary>`）时，第 2 步算出「整段丢弃」→ 结果为空 → 第 4 步此前**从原始 summary 重新出发**，闭合正则匹配不上未闭合块，只剥标签字面量，草稿正文成为最终摘要。现记一个 `discardedUnclosedAnalysis` 标志：确实丢弃过草稿时，空就是正确结果。配套 `doAutoCompact` 的判据从「原始响应非空」改为「剥离后正文非空」，否则会注入一条只有续接说明、没有摘要内容的 user 消息，而埋点照报 `summarized`。
4. **P2-19** `applyToolChoice` 在 `none` 无法下发时改为**撤掉 `tools`**（连带 `parallel_tool_calls`）。GLM 族（`auto-only`）与 DeepSeek 思考模式（`reject-when-thinking`）下「不下发 tool_choice」等价服务端默认 `auto` —— 对 `required`/具名工具是合理放宽，对 `none` 是把约束**反转**了。模型拿不到工具定义就调不了工具，约束由结构保证。代价是这一次请求丢掉工具前缀的 cache 命中。
5. **P2-20** 新增 `query/unchanged-observation.ts`：同指纹（工具名 ⊕ 排序后入参）同返回值连续 ≥ 阈值时 warn + 落 `UnchangedObservationRun`。阈值 `UNCHANGED_OBSERVATION_THRESHOLD` 定义在这个零依赖小模块里、由 `trace/digest.ts` 导入，全仓只此一份。**只报不拦**（`intervened: false`）。
6. **P2-21** `runPostCompact` 第 1 步前后各测一次 token，落 `PostCompactReattach`：`reattachTokens` / `savedByCompaction` / `clawedBackRatio` / `compactionLevelAfter` / `willRetriggerNextTurn`。判据用 `getCompactionLevel()`（压缩触发的唯一事实源），不自己跟常数比。省下量为 0 时 `clawedBackRatio` 置 undefined 而不是填 0。auto / manual / reactive / collapse 四条路径都接了 sink。
7. **P2-22** 新增 `buildEmergencyFilePathReattach`：emergency / blocking 截断后只注入一条「最近访问过这些文件」的**路径清单**，一个字节正文都不读。经 `QueryDeps.emergencyFileReattach` 接到 loop 的两处截断点，判据与横幅同源（`settleCompaction` 返回非 null = 实测真压动）。App 侧按历史末尾角色决定是否补 assistant ack。
8. **P3-23** `cache-ttl-latch.ts` 头部补「哪些导出在生产路径上」小节（对齐 `cache-strategy.ts` 的同一纪律）：三个 TTL 决策函数**生产零调用**，`resetTTLLatch` 有调用点但清的是从没被设置过的 latch、恒 no-op。配套一道**正反两查**的门禁测试。不删代码。

## 放弃了什么（以及为什么不选）

- **P2-20 做成干预（注入提醒 / 强制收尾）**。`.agents/notes/rejected/feature/2026-07-14-工具循环检测默认开启.md` 有实测背书：42 个真实会话回放，shape 误判率 ≈100%、exact 召回 ≈0，故工具循环检测默认全关。那份否决同时写明正确切法是「输入 + 输出双重复」，并指出当时卡在「检测器只 record 输入、看不到 observation」。本阀就是那个双判据，但 digest 侧的阈值 3 **从未在运行时验证过误报率** —— 先采触发率与工具分布，有分母再谈干预。没有数据就拦是在猜。
- **把阈值留在 `digest.ts` 让新模块 import 它**（一度这么写，随即反转）。digest.ts 3481 行 + `node:fs`，是离线分析模块；让热路径顺着新模块 import 它，等于把整个离线 digest 拖进主循环。反过来零成本：离线模块 import 一个只含常量与纯函数的小模块。
- **P2-22 复用 `postCompactTail` / `buildReattachFileMessages`**。那条收尾会读盘注入最多 50K token 正文。emergency / blocking 的语义是「剩余极少、连一次 LLM 往返都危险」，刚截断腾出的空间立刻塞回 50K，下一轮必然再截断 —— 而截断是**有损**的（直接丢历史、不留摘要），不像摘要压缩可重建。故另起一条只给路径的轻量通道。
- **P2-21 顺手调预算**（`POST_COMPACT_MAX_FILES` / 50K 上限）。只报不改是刻意的：少注入会让模型重读文件（多付 1-3 轮），哪边划算取决于会话文件大小分布 —— 而那正是本埋点要采的数。文档自己也说「是否真的经常触发未做定量测算」。先采数再调参。
- **P2-17 把全部决策点（含 `architecture`）塞进常驻附件**。architecture 类是「选了什么方案」，属于摘要该覆盖的内容；塞进最高优先级附件会把 CRITICAL_REMINDER 稀释成又一个摘要副本，它就不再是「约束」通道了。只取 `correction`（不要/别/不应该/don't/should not）。
- **P2-17 改成读回 `decisions.jsonl`**。那个文件全仓没有读取方是事实，但补一条读取路径解决不了根因 —— 根因是约束走消息流会被下一次 `strip.ts` 剥掉（那是对的，防连环累积）。常驻 system prompt 才是与 deny 规则同构的解法。
- **P2-18 在第 4 步做更聪明的草稿修补**（比如猜测 summary 边界）。第 2 步已经算出「该丢弃」，再猜一遍就是两套判据。空结果交由既有的失败降级（简单截断 + 用户可见告警）处置，比静默注入草稿诚实。
- **P2-19 给 GLM / DeepSeek 加 compat 声明绕过**。`toolChoiceAutoOnly: false` 之类是「用户知道网关已修」时的出口，已经存在且优先于族推导；本缺陷是默认路径下的语义反转，要在默认路径上修。
- **P3-23 删掉 `cache-ttl-latch`**。TTL latch 有事故背书（会话中途 TTL 从 1h 降 5min 破坏缓存，~20K token 浪费）。删掉等于把这份判断也删了，等 API 放开时要重新推一遍。保留 + 写明零调用最便宜。
- **改 `firePostCompactEvent` 的对外 schema**：同 P1 那条，不由缺陷修复顺手带出去。
