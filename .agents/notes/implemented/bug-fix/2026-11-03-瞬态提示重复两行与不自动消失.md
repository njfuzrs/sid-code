# 瞬态提示只渲染一处、到点自动消失，剪贴板读图失败分原因说话

## 决定了什么

修的是用户实测的一处 TUI 缺陷：在输入框里粘贴内容后，界面上叠出**两行**「剪贴板无图片（或缺 pngpaste/xclip/wl-paste）」，且两条都**永不消失**。

四处改动：

1. **删掉 `Composer.tsx` 对 `uiState.transientMessage` 的渲染分支**。它和 `BottomRegion`
   里的 `ToastDisplay` 各渲染一份同一条消息 —— 这是「两行」的直接来源。统一由
   `ToastDisplay` 负责（它本来就在 `BottomRegion` 留白区，按 L2.2 与输入框隔 1 行）。
   连带收益：Composer 顶部状态行不再被 toast 顶掉，流式期间 spinner / 工具状态始终可见。
2. **`UIStateContext.showTransientMessage` 补到期定时器**：`Warning` 8s、`Hint`/`Info` 4s
   （口径对齐 `ui/CLAUDE.md` L4-H「短回执 4s、错误 8s」，同族常量见
   `ui/command-result-route.ts`）。新消息覆盖旧消息时先作废旧定时器，Provider 卸载时清理。
   此前这个函数**只 setState、全仓没有任何一处清空它** —— 名字叫「瞬态」，行为是永久驻留。
3. **剪贴板读图改为返回结构化结果**：`readClipboardImageToFile(): string | null` 之外新增
   `readClipboardImage(): {ok:true,path} | {ok:false,reason:"no-image"|"no-tool"}`（旧函数
   保留为薄封装）。`readClipboardMacOS/Linux/Windows` 相应返回 `"ok"|"no-image"|"no-tool"`。
4. **文案收口到 `clipboardImageFailureHint(reason)`**：`no-image` → 「剪贴板里没有图片」；
   `no-tool` 只在 Linux 给安装指引，其它平台说「当前系统无法读取剪贴板图片」。
   `InputArea.tsx` 的 `tryInsertClipboardImage` 改用新 API + 新文案。

「提示是否正确」的核实结论（用户明确要求检查）：**旧文案在 macOS 上是错的**。
`readClipboardMacOS` 是 pngpaste 优先、**`osascript` 系统兜底**，而 osascript 是 macOS 自带，
所以「缺 pngpaste」永远不可能是 macOS 上失败的原因；`xclip` / `wl-paste` 更是 Linux 专用，
并列写进提示会诱导 macOS 用户去装一个装了也没用的工具。Windows 走系统自带的 PowerShell，
同样不存在「缺工具」这一档。真正会缺工具的只有 Linux。

## 放弃了什么（以及为什么不选）

- **放弃「保留 Composer 那份、删掉 ToastDisplay 那份」**。`ToastDisplay` 是 `BottomRegion`
  里专职的瞬态块（Warning / Hint / Info / Escape / 展开提示都归它），职责单一；Composer 那处
  是「状态指示器」的位置，本该显示 LoadingIndicator / ToolResult / 权限模式。让 toast 占住它，
  流式中就看不到 spinner —— 用新缺陷换旧缺陷。
- **放弃「只删 macOS 文案里的 pngpaste、保留合并句式」**。合并句式无法区分「剪贴板里没图片」
  和「系统缺读图工具」这两种对用户意味着完全不同动作的情况；根因是读取层不返回原因，
  必须让 `readClipboardImage` 结构化，光改文案治不了 Linux 用户拿不到安装指引的问题。
- **放弃「让瞬态提示复用 `statusMessage` 通道」**。`statusMessage` 是 `app.ts` 的
  `notifyStatus` Map 通道（叠加、去重、sticky 警告共存），语义是命令回执与系统状态；
  把 UI 键交互的提示塞进去要跨 UI → app → UI 三层改造，还会污染 sticky 语义。
  就地给 `showTransientMessage` 加定时器是最小闭环。
- **放弃「在每个 `showTransientMessage` 调用点各自挂定时器」**。调用点分散在 5 个文件，
  漏一处就复现同一个 bug；`transientMessage` 是单值状态，TTL 天然属于它的写入函数。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/components/toast-display-ttl.test.tsx`：注入 60ms TTL 后
  先断言帧内含文案、再断言已消失；第二个用例验证「新消息覆盖时旧定时器被作废」
  （旧 ttl=40ms、新消息 20ms 发出，若不作废旧定时器，新消息会在 40ms 处被清掉）。
  注：toast 消失后树不能变空，故挂了一行常驻 `Baseline` —— 底座对空树不写帧，
  否则 `lastFrame()` 停在旧帧，「已消失」永远量不到（L5.2 记过的坑）。
- `packages/cli/tests/ui/components/layout-bottom-region-snapshot.test.tsx` 新增两个用例：
  同一条 toast 在 main / fullscreen 两种真实布局的整帧里**按行过滤后只出现 1 次**
  （改前是 2 次）。这条是纯计数断言，不依赖快照的整帧字符比对 —— 重复行是新增行，
  未必让旧快照变红。
- `packages/cli/tests/ui/clipboard-image.test.ts` 新增：`readClipboardImage` 的 reason
  取值合法；`no-image` 文案不含任何工具名；`no-tool` 在非 Linux 平台也不含工具名。
- 快照 diff（`git diff` 审过）：只删掉两处重复的「这是一条 Toast 警告」，fullscreen 因为
  固定高度多出一行填充空白，无其它变化。
- 门禁：`bun run typecheck:gate`（64/64，无新增）、`bun run format:check`、`bun run lint`
  全绿；`bun run affected-tests:run` 判定为 `bun test ./packages/cli/`；`make build` 通过。
