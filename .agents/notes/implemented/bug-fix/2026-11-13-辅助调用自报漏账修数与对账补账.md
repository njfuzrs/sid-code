# 辅助调用的 usage 取数收口成 collectStreamUsage，并给自报链加运行时对账补账

## 决定了什么

两个 P0 缺陷（方案里的 CP-1 / CP-2）在同一次改动里修掉，因为它们**是同一个 bug 的两半**：
前者让钱漏在发生侧与消费侧之间的缝里，后者负责让这条缝以后自己出声。

### CP-1：取数收口（根因）

7 个辅助调用点各自写着同一段取数逻辑：

```ts
} else if (event.type === "message_stop" && (event as any).usage) {
  usage = (event as any).usage;
}
```

`message_stop` 在 `StreamEvent`（`llm/types.ts`）里**没有 usage 字段**，所有 provider 也
从不往它上面挂 usage —— 用量只在 `message_start`（Anthropic 族给全量输入）与
`message_delta`（Anthropic 给增量、OpenAI 族给流尾累计）上。`as any` 让类型系统彻底失声，
于是这 7 条链的**成功路径** usage 恒为 null、`recordSideCall` 恒不触发。
更隐蔽的是它们都在 `BILLING_SELF_REPORTED_LABELS` 里被豁免了发生侧计费（因为"我自己会报"），
**两头都不记账** —— 轨迹实测静默漏了 199 次。

改动：

- `llm/types.ts` 新增 `collectStreamUsage(acc, event)`，只认 `message_start` / `message_delta`，
  其余事件原样返回。它是流式取 usage 的**唯一实现**，`as any` 全部删掉、变量类型改 `Usage | null`。
- 7 处改为调用它：`memory/recall.ts`、`query/auto-compact.ts`、
  `query/compact/context-collapse.ts`、`query/compact/partial-compact.ts`、
  `permission/bash-classifier.ts`、`hook/runner.ts`、`goal/evaluator.ts`。
  `goal/evaluator.ts` 的 `recordSideCall` 从"分支内记一次"移到"流结束后按收集到的 usage 记一次"。
- 静态门禁（`tests/llm/billing-self-reported-labels.test.ts` 新增一条）：`packages/*/src`
  里不允许出现「`message_stop` 与 `.usage` 同处一行」的写法，报错带 `文件:行`。
- 3 个 cli compact 测试的 mock 从 `message_stop{usage}` 改成真实序列
  `message_delta{usage}` → `message_stop{}`。**mock 与生产不一致正是这个 bug 能活两个多月
  没被任何测试拦住的直接原因**。

### CP-2：运行时对账补账（安全网）

豁免标签的分工是「发生侧不记钱，让消费侧自己报」。CP-1 证明这个前提会静默失效，
所以豁免必须配一个对账：

- `llm/billing-sink.ts`：新增 `SELF_REPORTED_LABEL_TO_QUERY_SOURCE`（消费侧 label →
  发生侧 querySource，**与 `BILLING_SELF_REPORTED_LABELS` 相邻**，两套命名只此一份映射）
  与 `getSelfReportExpected()` / `resetSelfReportExpected()`。`recordBilledRequest` 在票据认领
  之后累计「让给自报」的用量，按 `querySource + model + provider + baseURL` 分桶。
- `trace/side-call-sink.ts`：新增 `getReportedSelfReportTokens()`（会话维度、按 querySource 聚合
  已自报量），并让 `resetSessionSideStats()` 同时清空对账基线 —— 两边必须同一个会话口径。
- `llm/self-report-reconcile.ts`（新文件）：`reconcileSelfReports()` 做差
  （按 **token** 比不按次数比 —— 重试那笔同样是真实花费，正该补上），`applySelfReportGaps()`
  产出补账记录，label 前缀 `self-report-gap:`。
- `trace/collector.ts`：`handleSessionEnd` 里（**账本取数之前**）调对账 → 补账走真实
  `recordSideCall`（复用会话注入的 calculator，与主循环同一个 `SessionState.calculateCost`，
  并同步通知 `addSideCost`，账本行的 `total_cost_usd` 当场就含这笔钱）→ 差额落
  `SessionEnd.data.selfReportGap` → `warn` 一行 → 清空基线。
- 正常路径（消费侧报得对）gap 为空：不补账、不打日志、不落字段。

## 放弃了什么（以及为什么不选）

- **方案 ③「静态检查 usage 变量非空」**：`tsc` 在 `as any` 面前失声，而 ESLint 级别
  的自定义规则要新增一条 lint 插件链、且只能查到"变量被赋值过"，查不出"赋的是一个
  永不存在的字段"。收口成单一实现 + 静态扫坏形态覆盖得更彻底，成本更低。
- **让发生侧直接记账（去掉豁免）**：会被记两次（消费侧本来就在报），错向是高估；
  而且重试/降级路径下发生侧与消费侧的粒度不同，简单的"取一方"必然错一边。
  对账是唯一能同时抓住"漏"和"重"的形态。
- **按次数对账**：重试会让发生侧次数多于自报次数，按次数比会把真实花费报成漏账，
  方向相反。
- **补账自算金额再塞回某个局部变量**：账本读的是 `SessionState`，不通知就出现
  "补了但账本没变"。所以补账只能走 `recordSideCall`。
- **对账放在 App 的 `finalizeSessionStore()` 里**：那里确实在账本写入之前，但
  `SessionEnd.data.selfReportGap` 由 collector 构造，分散到两处会让同一次对账产生
  两份各自演化的口径。放在 `handleSessionEnd` 一个地方，时序也正确
  （`/quit` 路径是 `await fireSessionEndEvent` → `finalizeSessionStore`）。

## 拿什么证明它生效了

全部在 worktree `fix/cost-side-call-self-report` 里实测（先 `rm node_modules && bun install`，
否则 `@sid-code/core` 会解析到主仓 checkout、新增导出静默变 undefined）：

- `bun test ./packages/core/tests/llm/stream-usage-self-report.test.ts` → **7 pass**
  （7 处调用点各一条，真实事件序列驱动，token 与喂入值逐位相等）。
- `bun test ./packages/core/tests/llm/self-report-reconcile.test.ts` → **15 pass**。
- `bun test ./packages/core/tests/llm/billing-self-reported-labels.test.ts` → **6 pass**（含新门禁）。
- `bun test ./packages/cli/tests/command/compact-{analytics,focus,post-compact-wiring}.test.ts` → 全绿。

**变异自证（CLAUDE.md 要求，且这一步抓到一个真 bug）**：

- A3：在 `memory/recall.ts:306` 写回坏形态 → 新门禁 **exit 1** 并报
  `packages/core/src/memory/recall.ts:306: if (event.type === "message_stop" && (event as any).usage) {`；
  恢复后 exit 0。

  恢复后 7 pass。

  恢复后 15 pass。
