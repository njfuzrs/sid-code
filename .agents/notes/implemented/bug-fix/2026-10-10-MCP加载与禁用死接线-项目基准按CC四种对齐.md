# MCP 逐级加载 + 禁用改为持久且当场生效；各子系统的项目基准按 CC 的四种口径分别对齐

## 决定了什么

- **M1**：`.mcp.json` 从 cwd 逐级向上找到文件系统根（不含根），离 cwd 越近优先级越高（`mcp/project-files.ts`）。TUI 加载和 CLI `mcp list/pending/approve/reject` 走同一个函数。
- **M2**：`/mcp` 面板与 `/mcp disable|enable` 统一走 `toggleMcpServer`：先把禁用状态写进按 git root 索引的私有存储
  `~/.sid-code/projects/<key>/mcp-state.json`（`disabledMcpServers`），再调 `manager.disableServer/enableServer`
  当场断连、注销工具、在面板显示 DISABLED。删除了 `sessionState.mcp_disabled`（这个字段只写不读）和 `--session` 参数；**不再改写 `.mcp.json`**，历史上写进去的 `enabled:false` 照旧能读。
- **M3**：TUI 启动时，若有待审批的项目级 server 就弹审批框，选项为批准 / 全部批准 / 拒绝，默认停在「拒绝」。另外新增 `/mcp reject`；`mcp list` 会逐行列出待审批项。
- **M4**：审批 key 改为 `${gitRoot}:${name}`；旧的 `${cwd}:${name}` 仍可读，下次写入时迁到新 key。
- **§3**：新增 `config/project-bases.ts`，用四个命名函数分别对应 CC 的四种基准，逐条接入：
  - B2：local settings、权限规则读写、信任键（检查时向上继承祖先的信任）；
  - B3：skills、commands、agents、output-styles；
  - B4：rules、CLAUDE.local.md、AGENTS.md 兜底。
  - 「Bash 不再询问」的放行改写 local，不再写共享的 `settings.json`。
- **W1**：`unified-registry.setDisabledSkills` 同步更新共享 SkillManager；`/skills disable|enable` 改为热生效。
- **W3**：删除死模块 `MessageDataStore`。
- **P8**：`getSettings(workspacePath)` 收到非 cwd 的路径时绕过缓存，不再静默忽略这个参数。
- **P9**：切换 worktree 时，`onWorkspaceChange` 重载 CLAUDE.md/rules 并重建系统提示词。

## 放弃了什么（以及为什么不选）

- **统一用一个 `getProjectBase()`**：否决。CC 本身就按子系统使用四种基准。在子目录启动时不读仓库根的共享 `settings.json`，是 CC 文档写明的行为。统一成一种会偏离 CC，还会把某些子系统的语义悄悄改掉。门禁测试专门断言子目录下 B1 的共享 settings 不可见，防止有人顺手统一。
- **保留会话级禁用（`--session`）**：否决。CC 的 `/mcp` 禁用本来就是持久化的，没有「仅本会话」这一档。保留它就得再维护一套状态源，而本次要修的正是这种只写不读的死接线。
- **禁用状态写回 `.mcp.json`**：否决。这个文件入库共享，一个人的偏好会被提交给全团队。
- **读写 `~/.claude.json`**：否决。仓库规定只对齐 CC 的语义，不读 CC 的配置文件。
- **`.mcp.json` 只查到 git root 为止**：否决。CC 一直查到文件系统根（本机实测也能读到 `~/.mcp.json`）。
- 不做（单独排期）：skills 嵌套目录的按需发现；`/mcp` 面板的 pending 分组；切换 worktree 后重载 settings/hooks（属于增强，CC 也不重载）。
