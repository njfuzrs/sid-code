# grep 登记 CC 风格短参数别名，`-C:3` / `-i` 不再被 zod 静默剥离

## 决定了什么

在 `packages/core/src/tool/input-alias.ts` 的 `ALIASES` 里登记 4 条映射：

- `-C` → `context`
- `-i` → `case_insensitive`
- `-A` → `after_context`
- `-B` → `before_context`

这些是 Claude Code `Grep` 工具的**真实协议参数名**（CC 报告附录 A、Agent SDK 类型定义
`typescript.md:3475-3492`），模型按 CC 习惯传过来时，sid 的 grep schema 没有同名字段，
zod 会静默剥离：`validateToolInput(grep, {pattern:"x","-C":3,"-i":true})` 返回
`{"ok":true,"data":{"pattern":"x"}}` —— 模型拿到没有上下文行、区分大小写的结果，且
`is_error=false`，失败被藏在「成功」里。30 天轨迹 47 次真正丢意图（`-C` 28、`-i` 10、`-A` 9）。

现有 `walk()` 守卫（只在「shape 声明了 `to`、未声明 `from`」时改名）保证这四条只作用于
grep：全仓只有 `grep.ts` 声明了 `context` / `before_context` / `after_context` /
`case_insensitive` 四个字段。

## 放弃了什么（以及为什么不选）

1. **不给 schema 新增 `-n` 等带 `-` 的字段**。`-n` 是轨迹里最高频的键（105 次），但 sid
   没有对应字段：`output_mode=content` 时恒带 `--line-number`（`grep.ts`），它对结果没有影响。
   新增字段名会让仓库「零 camelCase / 全 snake_case」的约定出现第一个例外，也会让 hook 脚本里
   `jq .tool_input` 多一种需要转义的键名。`-n` 归 D1/T2 的「已知无影响键」处理：静默接受、只发事件、
   结果里不加提示（否则每次结果开头多一段噪音）。
2. **不做「命名风格归一化后相等即改名」的通用匹配**。那会让任意工具的任意键都可能被悄悄改写，
   而这里只有 CC 协议名这一批跨产品先验的证据，不是可泛化的命名规律。
3. **不改成报错**。155 次带未知键的调用里 105 次是 `-n`，改成报错会让它对结果毫无影响却白多一轮
   往返（为「更准」牺牲「更快 / 更省」）；能确定意图的部分已经由这四条别名修掉。
4. **不改 `before_context` / `after_context` / `context` 三元结构**。它们与 `-B` / `-A` / `-C` /
   `context` 一一对应，30 天内三个字段都有人用（565 / 507 / 1821 次）。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/tool/input-alias.test.ts` → **18 pass / 0 fail**
  （原有 10 条 + 新增 8 条 grep 别名用例：`-C:3`、`-C:"3"` 的 alias→numeric 链路、
  `-i`/`-A`/`-B`、两键并存 `dropped=1`、`-n` 不登记、`read` 传 `-C` 不改名）。
- **变异自证**：删掉 `ALIASES` 里 `{ from: "-C", to: "context" }` 一行后重跑，
  3 条 `-C` 相关用例变红（15 pass / 3 fail），`-i`/`-A`/`-B` 仍绿；恢复后重新 18 pass。
- `bun run affected-tests:run` → **1512 pass / 0 fail**（首轮 4 条 5s 默认超时是并发下的
  flake：`schema-naming-convention` / `shell-snapshot` 单跑 15 pass，重跑全绿）。
- `make build` → 编译产物自检 5 项全过；`bun run smoke` → **26 例 26 通过**；
  `bun run docs:gen-reference --check` → 参考页与源码一致；
  `bun run lint` / `lint:boundary` / `lint:command-system` / `lint:legacy-tool` /
  `typecheck:gate`（62 < 基线 64）全过。
- 上线后的复核口径（方案 T1 验收第 3 条）：一周后复跑轨迹脚本，`grep` 下 `-C` / `-i` / `-A`
  的未知键次数应为 0，`ToolInputAliasApplied` 事件里出现 `from="-C"` 记录。
