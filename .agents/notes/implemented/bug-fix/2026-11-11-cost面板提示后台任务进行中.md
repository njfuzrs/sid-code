# /cost 面板在后台调用仍在跑时补一行提示，而不是把面板改成实时刷新

## 决定了什么

`/cost` 的输出进 `CommandOutputDialog` 后是静态文本，打开那一刻的数字不会再变。
本次在 `packages/cli/src/command/commands/cost/cost.ts` 里加了一行提示：

- 数据源用现成的 `getBackgroundGateStats()`（`packages/core/src/agent/background-task-gate.ts`），
  取 `busy` / `busyLabel` / `pendingLabels` 三个字段，**同样把「排队中」算进提示**
  （闸门是串行队列，当前那一笔跑完会接着跑待补的，只报「进行中」会让用户以为数字快定了）。
- 只在有后台任务时输出，空闲整段省略（正常路径不加噪音）。
- 位置固定在「总费用 / 其中辅助调用」之后、「API 耗时」之前 —— 因为几乎全部的后台费用
  都记在辅助调用上，提示紧贴费用数字才有解释力。
- 抽成导出的纯函数 `formatPendingTasksNotice(view)`；`CostCommand` 的读取函数做成
  构造参数（默认读真实闸门），于是测试可以喂假状态。

## 放弃了什么（以及为什么不选）

1. **不做面板实时刷新。** 命令输出面板是通用组件，为一个纯展示命令加订阅机制不划算：
   要新增订阅生命周期、要在 `CommandOutputDialog` 里处理重渲染，收益只是省掉用户重开一次
   `/cost`。加一行状态提示已经能消除「两处数字对不上是口径不同」的误判 —— 那才是 D2 的真问题。
2. **不改 `CommandOutputDialog`，也不为 `/cost` 新写专属 Dialog。** `packages/cli/src/ui/CLAUDE.md`
   L4-H 明确：查看/诊断类命令直接标 `outputPanel`，专属面板只留给需要选择/编辑交互的场景。
3. **不把提示做成 ANSI 暗色。** D15（面板视觉重做）才引入颜色体系；现在就加 ANSI 会让
   headless / 管道输出的文本混入转义码（`/cost` 是 `headless: true`），得不偿失。
4. **测试不碰真实闸门单例。** `background-task-gate.ts` 是进程级单例，`bun test` 同批多文件
   跑在同一进程里；测试若去 occupy / `resetBackgroundTaskGate()`，会与
   `packages/core/tests/agent/background-task-gate.test.ts` 的并发用例互相清掉对方的待补队列。
   所以选择注入读取函数，而不是「测试里真的跑一个后台任务」。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/command/cost-pending-tasks.test.ts`（9 个用例）：
  纯函数覆盖「进行中 / 排队 / 两者都有 / 只有排队 / 标签缺失兜底 / 重复标签去重 / 空闲省略」，
  接线覆盖「空闲不出现」与「busy 时出现在总费用之后、API 耗时之前」。
- 既有 `packages/cli/tests/command/cost-protocol-hint.test.ts` 6 个用例保持全绿（同一命令的另一组判据）。
- **变异自证（两次，都先红后恢复）**：
  1. 删掉 `if (pendingNotice) lines.push(pendingNotice)` → 接线用例 2 条变红
     （`busy 时提示出现在费用块之后…`、`排队中的任务也会写进输出`），7 pass / 2 fail；
  2. 把 `if (view.busy)` 改成 `if (false)` → 纯函数 + 接线共 5 条变红，4 pass / 5 fail。
  恢复后 9/9 全绿。
- `bun run affected-tests:run` 判定为 selective（`bun test ./packages/cli/`）。
  首次执行遇到 worktree `node_modules` 软链导致的 `Cannot find module '@sid-code/tui'` 假失败
  （301 文件里 296 fail）；按 CLAUDE.md worktree 一节删掉软链重装依赖后，
  TUI 相关文件恢复 16 pass / 0 fail，再跑选测。
