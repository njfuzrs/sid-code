# 修复 Skill 系统七项 P1：预算封顶、总量上限、降级埋点、首轮判据、dir_path、hooks 作用域、吞异常

## 决定了什么

来源：`20260927-Skill系统-顺着sc-10-skills核出的缺陷` 的 P1-1…P1-7。P2-1 / P2-2 本轮不动。

- **P1-1**：`formatCommandsWithinBudget` 改为按**整行**（前缀 + 描述 + 换行）核算，均分的是
  扣掉各自前缀后的描述预算；bundled 特权封顶在预算的 50%（`BUNDLED_BUDGET_SHARE`，按原顺序
  先到先得），超出的与普通条目一起参与降级。`isBundled` 只认 `loadedFrom === "bundled"`，
  不再包含 `isBuiltin`：builtin 目录型 skill 磁盘上有完整 SKILL.md，模型降级后可自己 Read。
  唯一允许超预算的情形是「全部降成名字仍放不下」——再往下只能丢条目，比超预算更糟。
- **P1-2**：`MAX_SKILLS`（导出）在 `SkillManager.addSkillsWithPrecedence` 对**全量集合**执行，
  discover 两次 loadAll 与插件 / MCP / 动态发现三条追加路径全部汇到这里；同名覆盖不占名额。
  `addPluginSkills` 返回实际接纳的集合，超限被丢的不进热重载重放清单、不进 listing。
- **P1-3**：新增 `skill/telemetry.ts`（与 `trace/jit-telemetry.ts` 同款模块级 sink），
  事件名 `skill_degradation`，闭集 kind：`listing_names_only` / `listing_truncated` /
  `auth_fail_open` / `ask_no_channel` / `effort_invalid`。app 在 collector 就绪后接到
  `recordCustomEvent`。
- **P1-4**：`drainListingDelta` 首轮判据改为显式 `hasSentInitial`（init / reinit / 首次 drain
  置 true），不再用 `sentSkillNames.size === 0` 代理。
- **P1-5**：`AFFECTED_PATH_FIELDS` 常量加 `dir_path`（ls）与 `script_path`（workflow，反漂移
  断言顺带扫出来的）；`bash` 的 `command` 仍刻意不收。
- **P1-6**：hook 注册条目加 `hookScope`；`newSkillHookScope()` 为「调用完就卸」的路径
  （模型元工具、SkillCommand fork、CommandExecutor fork）生成作用域 id，卸载按
  `(skillName, scope)` 精确删；不传 scope 的 `removeSkillHooks` 语义不变（删全部）。
  顺带把 meta-tool 那行硬编码 "delegate" 的日志按实际 context 打。
- **P1-7**：`loop.ts` 的 `.catch(() => {})` 改为 `log.warn`；仍不 await。`drainListingDelta`
  的增量改为「manager 当前可见集合 − 已发送集合」，不再依赖 `pendingActivated` 被及时填充，
  晚到的激活至多晚一轮、不会被清空丢失。

## 放弃了什么（以及为什么不选）

- **P1-1 只修前缀那处**：前缀是小头（复现 B 超 81 字符），bundled 无封顶才是 31 倍超支的主因。
- **P1-1 bundled 特权直接取消**：编译内联 skill 降成名字后模型没有任何途径看到描述，
  文档 §5.5 的豁免理由对它成立，封顶比取消更贴近原意。
- **P1-2 在 loader 里改成全局计数器**：loader 不知道插件 / MCP / 动态发现这三条路径，
  放在 manager 一处即全覆盖。
- **P1-6 fork / 模型路径不再注册到主 hookSystem**：子代理当前复用主 hookSystem，
  改成独立 hookSystem 面太大；作用域 id 是最小改动且不改变任何既有生命周期。
- **P1-7 改成 await 协调器**：磁盘扫描延迟会计入每个工具轮（伤更快），而「读真实可见集合」
  已让晚到激活不再丢失，代价只剩「偶发晚一轮」。
