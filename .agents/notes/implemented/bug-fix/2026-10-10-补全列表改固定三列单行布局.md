# 斜杠命令补全列表改成固定三列、每项一行，超长截断

## 决定了什么

`packages/cli/src/ui/components/SuggestionsDisplay.tsx` 从「命令名列 flexShrink=0 + 描述列 wrap」
改为按显示列宽算好的固定三列：

- 命令名列宽 = 可见项里 `icon + label + argumentHint` 最宽者，封顶行宽 45%；
  命令名优先保全，`argumentHint` 超出部分截断为 `…`。
- 描述列 = 剩余宽度；描述先压成单行（skill description 常带换行），再按列宽截断。
- 标签列 `[命令]` 右侧对齐，所有可见项同一列。
- 整行放在一个 `<Text wrap="truncate">` 里，保证一项严格一行。

用户报的三种错乱同出一源：
① 描述起点随命令名长短漂移；② `/eval-session` 这类 skill 的长描述一项占 10 行；
③ `/mcp`、`/trace` 的长 argumentHint 把命令名列撑满，描述列只剩 1–2 列，被挤成一字一行竖排。

## 放弃了什么（以及为什么不选）

- **保留换行、只修悬挂对齐**：解决不了 ②，8 条可见项仍能撑满整屏，输入框被推出视口。
- **argumentHint 换到第二行**：每项高度不一，↑↓ 选择时列表跳动；补全列表的职责是
  「快速认出是哪条命令」，完整描述在 `/help`、`/skills` 里。
- **2026-07 那版截断实现（描述硬截 30 列）原样恢复**：它不算列宽，各行仍不对齐，
  且在宽终端上浪费大半行。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/suggestions-display-layout.test.tsx`（8 条）：60/80/120 列下
  每项一行不超宽、`[命令]` 与描述起点所在列一致、长 argumentHint 截断后描述仍可见、CJK 截断宽度。
- 变异自证：把组件换回 HEAD 旧实现，8 条全红；换回新实现全绿。
- 渲染实测（next 底座）80 列输出：

```
  › /permissions                      查看当前权限规则和模式             [命令]
  › /eval-session                     对一次已完成的 sid-code 任务会话…  [命令]
  › /trace [<id>] [--list] [--full]…  排查会话：把当前 / 指定会话轨迹…   [命令]
  › /mcp [list|add|remove|enable|di…  MCP 服务器管理（无参打开交互面板…  [命令]
  › /clear                            清空对话历史                       [命令]
```

按 string-width 量，5 行 `[命令]` 都在同一列（80 列下为第 73 列）。
