# markdown 代码块不再画行号与左边距，复制即可执行

## 决定了什么

`MarkdownAnsi` 渲染的 markdown 围栏代码块（助手回复、markdown 格式工具结果、计划评审共用）
只做语法高亮，**不画行号、不加 `paddingLeft`**。

- `packages/cli/src/ui/components/MarkdownAnsi.tsx`：`RenderCodeBlock` 固定 `hideLineNumbers: true`，
  去掉外层 `paddingLeft={1}`，`maxWidth` 改为整个 `terminalWidth`。
- `packages/cli/src/ui/contexts/SettingsContext.tsx`：删掉 `Settings.hideLineNumbers`。
  它默认 `false`，全仓无任何写入点（`App.tsx` 的 `<SettingsProvider>` 不传 `initialSettings`），
  是一个用户关不掉的死开关，留着只会让人以为行号可配置。
- `DiffRenderer`（显式 `showLineNumbers: true`）等文件内容 / diff 展示**不动**，仍带行号。

触发：会话 `20261016-222043-00223351` 的收尾「验证证据」围栏块在 TUI 里每行带行号，
用户复制命令会连行号一起复制。轨迹 `session.traj` 中原文无行号 ⇒ 行号由渲染层添加。

## 放弃了什么（以及为什么不选）

- **移植 CC 的 `<NoSelect>` 保留行号但不让复制**：CC 自己注释写明它
  "No-op in the main-screen scrollback render"，只在 alt-screen 鼠标选区生效；
  而我们默认主屏模式（ADR-040，`fullscreen.ts` `alternateBuffer ?? false`），
  复制走终端原生选择，渲染层拦不住。移植了对默认用户零效果。
  CC 能做到「复制干净」靠的是 markdown 代码块根本不画 gutter（`utils/markdown.ts` `case 'code'`
  只 `highlight.highlight(...)`），我们对齐的是这一点。
- **把行号做成可配置（接通 `hideLineNumbers`）**：代码块的主要用途是复制执行，
  默认带行号就是错的默认值；需要行号的场景已有 DiffRenderer 等专用渲染器。
  加配置只是把错误默认值包装成「用户可以自己关」。
- **翻 `colorizeCode` 的 `showLineNumbers` 默认值为 false**：语义更干净，但改动面更大
  （影响 `CodeBlock` 等调用方的隐式行为），本次只修用户可见的路径，留作后续。
- **长行折行导致复制断行**：CC 同样交给 Text 折行，对齐 CC 不算缺陷；独立议题，不在本次范围。

## 拿什么证明它生效了

- 新增 `packages/cli/tests/ui/markdown-ansi-codeblock-copyable.test.tsx`（3 条，整行比对而非
  `toContain`）：多行 bash 命令逐行原样、Python 缩进不右移、原故障形态（标题 + 无语言围栏块）。
  `bun test` → 3 pass / 0 fail。
- 变异自证两次：① `hideLineNumbers` 改回 `false` → 0 pass / 3 fail；
  ② 加回 `paddingLeft={1}` → 0 pass / 3 fail。两条修复点各自都被测试锁住。
- `affected-tests:run`、`make build`、lint / format / boundary / typecheck:gate 结果见 PR 正文。
