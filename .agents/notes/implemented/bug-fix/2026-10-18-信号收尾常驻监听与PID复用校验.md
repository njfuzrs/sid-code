# 信号收尾改常驻监听 + EIO 判在流对象上 + heartbeat 前移 + PID 复用校验（S7/S8/S15）

## 决定了什么

- **S15 治本**：`app.ts` 的三个退出信号从 `process.once` 改为 `signal-teardown.ts` 的
  `installTeardownSignalHandlers`（常驻 `on` + 重入状态位）。重复信号策略是纯函数
  `decideRepeatSignal`：收尾中再来 SIGINT → 强退；再来 SIGTERM/SIGHUP → 忽略，但 handler 已跑
  超过 `STUCK_TEARDOWN_MS=2s` 时强退（同步卡死时 forceExitTimer 触发不了，不能只剩 SIGKILL）。
  Bridge 模式那组 `once` 是常驻等待、不是同一缺陷，不动。
- **S15 EIO**：`watchTerminalOutputErrors` 在 `process.stdout/stderr` 流对象上判 `EIO/EPIPE`，
  命中后 destroy 流、`detachForShutdown` 停渲染（契约 X4，不写终端序列）、按 SIGHUP 走正常收尾。
  `cli.ts` uncaughtException 里写 stderr 包 `try`。
- **S8**：`TraceCollector.stopHeartbeat()`（同步、幂等）+ `heartbeatStopped` 守卫拦在途 tick；
  `handleSessionEnd` 开头与信号处理器第一个 `await` 之前各调一次。PID 文件刻意**最后**删。
- **S7**：`pid-manager` 判活在 `kill -0` 后用 `TZ=UTC LC_ALL=C ps -o pid=,lstart=` 批量比对，
  `lstart > start_time + 2s` 判复用；ps 不可用按存活。去掉 `slice(0,10)`；新增 `removeByPid`，
  App 全部退出路径与孤儿清理改按 pid 删；`process.on("exit")` 兜底删本进程 PID 文件。
  `scanStaleHeartbeats` 判活从「每个目录重扫 .pids」改为一次。
- **存量**：`sweepEndedHeartbeats` 在启动诊断 backfill 之后、用同一次扫描结果，只删
  「进程已死 ∧ events.jsonl 有 SessionEnd」的 heartbeat；无 SessionEnd 的保留（digest 的强杀证据）。
- **度量**：收尾进入 / 退出（含耗时）日志、重复信号到达计数（含 isTTY）。

## 放弃了什么（以及为什么不选）

- **在 uncaughtException 里按 `err.fd ∈ {1,2}` 判终端 EIO**：Bun 1.4.2 下 `err.fd` 恒 undefined，
  永不命中；只看 `code` 又会误吞写普通文件的 EIO。判据只能是「哪个流对象发出的」。
- **heartbeat 与 PID 文件一起提前删**：backfill 靠「heartbeat 新鲜 ∨ pid 活」判活，两者同时提前删
  会让收尾那 ~1.5s 内启动的另一实例把本会话当僵尸补传。
- **比对 `comm` 判 PID 复用**：Linux 截断 15 字符，与 `process.title` 比不可靠。
- **让 ps 打本地时间再 `Date.parse`**：本进程 TZ 未必等于 ps 的系统时区（实测 `bun test` 下进程
  TZ=UTC、ps 按 +08:00 打印，活进程全被判复用）。固定 `TZ=UTC` 并按 GMT 解析。
- **主验收用「有 SessionEnd 但 heartbeat 仍在 = 0」**：heartbeat 前移后它天然归零，是代理指标；
  只作辅助口径。主口径是信号路径会话 `messages.json` / `session-summary.json` 落盘率。

  断言 `done` 出现、退出码 129。**变异自证**：`target.on` → `once`，2 条红（注入 target 的 listenerCount
  与真进程两发）。
- `trace-upload-exit-path-wiring.test.ts` 原断言钉的是 `process.once("SIGHUP"`（即缺陷本身），改为钉
  「`registerSignalHandlers` 体内无 `process.once(`」；变异（插回一行 `process.once`）→ 红。
- `pid-manager.test.ts` / `heartbeat-stop-early.test.ts`：21 pass；含真子进程 PID 复用判定、12 条孤儿不截断、
  `removeByPid` 不误删共享 session_id 的文件、`handleSessionEnd` 首个 await 前 heartbeat 已删。
- 选测 `./packages/cli/ ./packages/core/tests/trace/`：3375 pass / 0 fail；`make build` rc=0 且
  `will always be undefined` 0 次；lint / format:check / lint:boundary / typecheck:gate（66/66）全绿。
- **端到端（pty + 真实模型，两发 SIGHUP 间隔 200ms，轮次在跑）**：本地构建产物 exit=129，

  「SessionEnd 收尾进入」。对照线上 v0.1.610：exit=-1（被第二个 SIGHUP 以默认处置杀掉）。
