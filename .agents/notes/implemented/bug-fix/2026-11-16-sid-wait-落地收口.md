# `sid-wait` 落地的三处收口：子代理文案、面板可辨识、终态输出尾部

## 决定了什么

排查文档《20261116-sid-wait失败率高与取舍-排查》的 A1/A2 已合并（#878），二次确认发现
三个「声称的验收层没落地」的缺口，本 PR 补齐：

1. **子代理里的回执死循环**（`packages/core/src/tool/bash.ts`）
   子代理写 `sid-wait gh-pr N` → 前台拦截回「请补 run_in_background=true」→ 照做又被
   `:1308` 的「子代理里不支持后台执行」拒 → 去掉 bg 又回到第一条。两条回执互为反向指引。
   判据改成：`getAgentRoot() !== undefined` 时换文案，直接说「不可用，交给主代理或前台
   `gh pr view` 轮询」，不再给补 bg 的指引。

2. **面板看不出「到底有没有在等」**（`packages/core/src/task/{types,shell-task}.ts`
   + `packages/cli/src/ui/{App.tsx,state-bridge.ts,components/TodoPanel.tsx}`）
   新增 `LocalShellTaskState.builtinWait`，由 `spawnBuiltinShellTask` 置位，经 state-bridge
   透传到 `TaskDisplayInfo.builtinWait`，面板标签显示 `SH·wait`。
   为什么用字段而不是让 UI 猜命令前缀：排查文档 §2.4 的 22 条失败全部是「普通后台命令
   0 秒 completed、摘要『执行成功』」，两者在面板上原本长得一样；按前缀猜会在改文案或
   改执行路径时静默失效。

3. **终态通知带输出尾部**（`packages/core/src/task/shell-task.ts`）
   `finalizeShellTaskExit` 读输出文件尾部 8KB（`takeTrailingLines` 裁到 5 行），经
   `outputTail` 传给 `enqueueTaskNotification`。空输出/读不到就不带，通知形状不变。
   这是排查文档第七节第 6 项（「比入口拦截更通用的修法」），此前只有「期限到」那条带尾部，
   所以 `EXIT=127` 这类假成功要模型再花一轮 `task_output` 才看得到。
   读尾部而不是全文：后台长任务的文件可能很大，同步读全文会阻塞事件循环。

配套测试：entrypoints 补 monitor 入口的通知队列断言 + 子代理文案用例；TodoPanel 加两条
整帧渲染用例（按行过滤，不全文 includes）；deadline-output-tail 加两条终态用例。

## 放弃了什么

- **不做「UI 按命令前缀识别内置等待」**：前缀判定在改文案/改执行路径时静默失效，
  且无法区分「描述里恰好含 sid-wait 字样」的普通命令。字段虽然要多改 4 个文件，
  但判据落在状态上，有测试锁。
- **不在 `killShellTask` 路径也带输出尾部**：既有测试
  `deadline-output-tail.test.ts` 的「普通 kill（非期限到）不带 output-tail」锁着这个形状，
  而 kill 的语义是「用户主动停」，尾部对模型没有新信息。只有自然终态带。
- **不把 output-tail 做成「只在可疑时带」**（如仅匹配 `command not found`）：需要同样的
  同步读文件，却多一条启发式判据；直接带 5 行更简单，且 `takeTrailingLines` 已限窗口。
- **不给 A2 增加「自动改写命令」**：改写等于猜语义，与 `parseSidWaitCommand` 的
  「不猜意图」同一条原则（这是上一轮 PR 已定的，本 PR 不改）。

## 拿什么证明它生效了

- 子代理死循环：`bun test ./packages/core/tests/tool/sid-wait-entrypoints.test.ts` → 14 pass，
  新用例断言「子代理里前台纯命令」的回执含「子代理里不可用」且 **不含**
  「请补 run_in_background=true」。用 `withAgentCwd` 复现原两条回执打架的场景。
- 面板可辨识：`bun test ./packages/cli/tests/ui/components/TodoPanel.test.tsx` → 16 pass，
  两条整帧用例：① `builtinWait` 显示 `[SH·wait]`、普通 shell 显示 `[SH]`；
  ② 描述文本完全相同的两条任务仍能靠标签分开（证明判据不是猜前缀）。
- 终态输出尾部：`bun test ./packages/core/tests/tool/deadline-output-tail.test.ts` → 10 pass，
  含「成功退出带最后 5 行（a-2…a-6，不是全部 6 行）」与「无输出不带该段」。
- G2 门禁：新增 `tests/smoke/cases/A15-sid-wait-near-miss`，`bun run smoke A15-sid-wait-near-miss`
  → PASS；`bun run smoke:mutate A15-sid-wait-near-miss` → `[KILLED]`（去掉入口拒绝分支后用例变红，
  证明它不是恒绿门禁）。用例的判据取自文档第八节第 1/2 层（拒绝文案 + 不 spawn），不是从实现反推。

关于「等真实数据」的取舍：A2 上线后 4 次真实调用全是正确写法，**被拒的真实样本为 0**，
日常使用中大概率永远等不到。所以把「模型写拼接形态 → 入口拒绝且不假成功」这条确定性行为
放进 G2（给定模型响应后 harness 行为确定），而不是等轨迹。A15 的 replay 来自
`2026-11-16T07:03:40Z` 的真实调用形态（`sid-wait gh-pr 876; echo "sid-wait exit=$?"`）。
