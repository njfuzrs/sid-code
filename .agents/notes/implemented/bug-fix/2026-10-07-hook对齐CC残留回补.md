# Hook 对齐 CC 残留回补：复核 #180 后补齐子代理路径、clear/compact、预算与可见性

## 决定了什么

复核 `20261003-Hook系统-对齐CC格式与语义-方案设计.md` 在 main（8e463c2f）上的落地情况，主体已修，
补齐复核出的残留：

- **会话身份**：resume 后 `transcript_path` 按逻辑会话 id（被恢复会话）拼，不再指向不存在的文件（HC11）。
- **SessionStart clear / compact**：`/clear` 两条路径与压缩收尾（`runPostCompact`，auto / manual / reactive / collapse 共用）
  重发 SessionStart；只跑用户 hook，上下文暂存在 HookSystem，下一条用户消息取走注入（HC12 / HC16）。
- **子代理路径**：PostToolUse / Failure 改 await 并回灌反馈；工具事件带 `agent_id` / `agent_type`；
  `is_interrupt` 按 abort 取值；PermissionDenied 带 `tool_use_id`；CwdChanged / Task* 在子代理也触发；
  SubagentStop 补 `last_assistant_message` / `agent_transcript_path`（HC11 / HC12 / HC18 / HC24）。
- **降级链 auto 模式发 PostModelSwitch**：`onFallback` 带 `viaDecision`，ask 模式（已经 applyPrimaryModelSwitch）不重复（Q6）。
- **超时**：纯 `async` 不强制 timeout，`asyncRewake` 仍强制；SessionEnd 串行按剩余预算扣减（Q5 / HC20）。
- **输出语义**：URL hook 非 2xx 改非阻塞错误（原先 deny）；形如 JSON 解析失败要告警；非阻塞文案对齐 CC「hook error」（HC19）。
- **环境变量**：父进程 `CLAUDE_*` 不透传（Q3）。
- **ConfigChange**：`changed_keys` 由前后快照算出；可 block（回退内存缓存，policy_settings 除外），聚合走一票否决（HC24）。
- **Q7 口径**：拒绝 span 不再带 `sidcode.success`，按 success 统计的失败率天然不含拒绝。
- **可见性与清理**：statusMessage 显示在 TUI 状态行；插件 / skill / agent 来源的归一化诊断对用户可见；
  `/hooks` 面板标注信任门跳过的项目级条目；删 `initializeFromLegacy`；handler 类型报错文案从常量派生。
- **文档**：参考页区分「内部事件（配置跳过告警）」与「刻意不做」；场景一示例改嵌套写法；偏离表补 ConfigChange block、
  CLAUDE_SKILL_DIR、shell；迁移 skill 字段表去掉「必做结构转换」并重新嵌入。

## 放弃了什么（以及为什么不选）

- **SDK initialize 握手里加 trustWorkspace**：信任门在启动期（cli.ts）就决定了加载哪些层，握手到达时为时已晚。
  SDK 宿主本来就是 spawn CLI，放行方式是命令行加 `--trust-workspace`，文档改为写明这一点。
- **ConfigChange block 时回写磁盘文件**：替用户改掉他刚保存的文件比「本会话不生效」更出人意料；只回退内存缓存。
- **clear / compact 的 SessionStart 送 runtime 消费者**：collector / hook-probe 把它当开新轨迹，会把一个会话劈成两段。
- **curated changelog v0.1.607 的「失败率不含拒绝」声明**：curated 文件由发版时 `changelog:curate` 起草并人工过目，
  不在功能 PR 里预建；口径变化已写进本 Note 与 #180 的 Note，发版 curate 时据此写入。
