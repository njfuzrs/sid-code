# goal 的「硬约束」与「评估」拆开，硬约束每轮执行

## 决定了什么

`goal.maxTurns` 与 `goal.tokenBudget` 此前只在 `handleGoalGate` 里检查，而
`handleGoalGate` 只挂在 `queryLoop` 的 `isEndTurnLike` 分支上。于是**上限只在
「模型想停」的那一轮才被读**：2026-11-16 的事故里模型连续 119 轮 `tool_use`
空转轮询，`maxTurns=150` 与 `tokenBudget` 一次都没被检查过，上限形同虚设。

把这件事按「确定性事实 vs 语义判断」切开：

- **新增 `packages/core/src/goal/limits.ts` 的 `checkGoalHardLimits`**：token 记账、
  预算判定、轮次判定三项确定性检查，纯判定不改 `status`。
- **`queryLoop` 每轮 AfterModel 之后调用一次**（`loop.ts`，在「检查停止原因」之前）。
  命中后置 `LoopState.goalLimitExit`（`"turns" | "budget"`）、写 `goal.status`、
  经 `updateGoalState` 落盘、落一条 `GoalGateDecision` trace、注入收尾提示，
  然后：
  - 本轮带 `tool_use` → 先把工具执行完（保证 `tool_use`/`tool_result` 成对），
    回到 `while` 顶部由新加的 `if (state.goalLimitExit) break` 退出；
  - 本轮无工具 → 在 `isEndTurnLike` 分支前直接 `break`。
  两条路径都汇入既有的强制总结出口（与 `maxTurns` / `stallStopRequested` /
  `deadlineAt` 同一个），只把进入条件多认一个 `goalLimitExit`。
- **`handleGoalGate` 只留评估器**：删掉预算/轮次两块与 `budgetWarning` 返回值、
  `turnUsage` 入参。预算告警（≥85%）改由每轮检查注入，并用
  `GoalState.budgetWarningEmitted` 去重（挂 `GoalState` 而非 `LoopState`：后者
  每条用户消息重建，挂错了第二条消息会再提示一遍）。
- **归因**：`done.goalLimitExceeded` / `TurnComplete.goal_limit_exceeded`
  = `{ source: "turns" | "budget" }`，与 `budgetExceeded` /
  `structuredOutputDelivered` 同范式（显式声明字段）。`GoalGateDecision` 的
  `reason` **沿用旧值** `turns_limited` / `budget_exceeded`，不新增分桶。
- `GOAL_BUDGET_WARNING_RATIO` 提成 `budget.ts` 的导出常量：门控与 loop 侧
  `goal_budget_warning` 的 transition 归因必须同源，两处各写 `0.85` 迟早漂移。

## 放弃了什么（以及为什么不选）

1. **不把评估器也摊到每轮**。评估器是一次真实模型调用（实测
   `evalTokensUsed≈6.7k`/次），每轮跑等于把「更省」方向直接做反。语义判断只在
   模型想停时才有信息量，确定性事实才需要每轮判。
2. **不新增 `DoneIncompleteReason` 取值**。那个闭集的消费方是 SDK，会把成员统一
   映射成具体错误码；goal 预算用尽该让用户看到的是 `/goal turns` / `/goal budget`，
   塞进去会让 SDK 提示「去调 `--max-turns`」。所以走显式声明字段
   （代价是 SDK 侧对该字段的消费要另做，见下一条）。
3. **`state.incompleteReason` 保持不写**（方案 §4.1 原文写的是「在 goal 限次处写一次
   `goal_turns_limited`」）。这条与同段「不要新增 `DoneIncompleteReason` 取值」直接
   矛盾，取更硬的那条：**不扩闭集**，用 `goalLimitExceeded` 表达同一事实。
   结果是 SDK 侧不会把这次 done 当异常，需要消费新字段才能区分 —— 这是明确的取舍。
4. **goal 到上限时不 `yield max_turns`**。`max_turns` 事件的 `maxTurns` 字段是
   `state.maxTurns`（主循环预算），拿它承载 goal 预算会让用户去调错参数。
5. **不把「命中上限」做成 `isEndTurnLike` 收尾链里的一道 gate**。那样 Stop hooks
   仍会拦、仍可能 `continue` 回主循环，得在更多地方堵口子；直接 `break` 与撞
   `maxTurns` 时的处置（跳过收尾链）一致，代价是 AfterAgent hook 不跑 ——
   与既有 `maxTurns` 行为同口径，不是本次新引入的不一致。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/goal/limits.test.ts ./packages/core/tests/integration/goal-hard-limits-loop.test.ts`
  → **15 pass / 0 fail**。集成用例的响应序列**全部是 `tool_use`**（旧实现下一条都
  不会触发），断言 `goal.status`、模型调用次数、`toolCalls` 次数、
  `GoalGateDecision` 条数、`done.goalLimitExceeded.source`、`tokensUsed` 精确值。
- **变异自证**（三次，均确认变红后恢复）：
  - 每轮检查条件改成 `if (false && …)` → **7 条红**（G1 四条 + G3 两条 + G4 两条）；
  - `goal.budgetWarningEmitted = true` 注释掉 → 单元 1 条 + 集成 1 条红（告警去重）；
  - `while` 顶部 `if (state.goalLimitExit)` 改成 `if (false && …)` → **5 条红**
    （证明「本轮工具跑完就不再发请求」这条断言真的在守）。
- `bun run affected-tests:run` → **1412 pass / 0 fail**（131 文件）。
- `make build` → 成功，产物自检通过。
- `bun run lint` / `bun run format:check` / `bun run lint:boundary` /
  `bun run typecheck:gate` → 全绿（typecheck 62 处 = 基线，0 新增）。

第一次变异脚本曾出现「全部绿」的假结果：`python subprocess` 把多个测试路径拼成
**一个** argv，`bun test` 按子串匹配到 0 个文件后退出 0。是 CLAUDE.md 里
「zsh 变量不做 word splitting」那条坑的 python 版，已改成 list 展开重跑。
