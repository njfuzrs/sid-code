# 一道**卡死在启动里、一次 API 都没发**的题进了配对分母，把配对均值伪造成「换档退步」（`0.250 → 0.125`，真值 `0.143 → 0.143`）

## 决定了什么

给唯一判据定义处 `verifier_health.py` 加**第四条判据** `agent_started()`，
取数源是 `agent/sid-home/debug.log` 里有没有 `[PERF] startup`，
并接进两个消费侧（`compare-paired.py` 的排除链、`analyze-model-switch.py` 的
`excluded` 集与报告行）。

**这条判据修的不是分数，是分母。** 起因是第十五棒交接要的那件事
（把两侧有效分母对齐）在执行时露出了第三道题：

`runs/modelswitch-base-rerun` 的 `fix-code-vulnerability` 拿到 `reward=0.0`，
**verifier 判分正常**，于是被当成一个真实的 0 分放进配对分母。而它的真实形态是：

| 判据 | 它 | 同 run 的健康题 |
| --- | --- | --- |
| `debug.log` 行数 | **134** | 522 ~ 3419 |
| `debug.log` 时间戳首末 | **都是 16:25:57**（进程一秒都没往前走） | 跨 2 ~ 36 分钟 |
| 最后一行 | `[SKILL] 加载了 8 个 Skill`，**再没有下一行** | 走到 `[PERF] startup` 之后正常干活 |
| `[PERF] startup` | **没有** | 其余 **90/91** 题全有 |
| `trajectories/` | **目录都没建出来** | 都有 |
| exception | `AgentTimeoutError after 3600.0s` | — |

⇒ 60 分钟墙钟全耗在一个没动的进程上，**一次 API 都没发出**。
而 cc 侧同一题是 **1.0** ⇒ 配对均值被拉成 `0.250 → 0.125`，
读起来像「换模型退步了」。接上判据后是 **`0.143 → 0.143`（n=7）**——
**那个「退步」整个是假的，方向恰好指向「我们更差」。**

这是本仓「非能力失败混进能力账」的**第四种形态**，前三种见 `agent_ran`
（零调用）、`llm_fatal`（重试链打空 / 上游硬拒）的 docstring。

## 放弃了什么（以及为什么不选）

**① 放弃「把它并进 `agent_ran`」。** 那条判据读 `agent_result` 的 in/out token，
而这一题**整份 metadata 缺失**（`sid_result_event_missing=True`）⇒ 两个 token 键都是
`None` ⇒ `agent_ran` 只能返回 **None（不可判）而不是 False**，消费侧的
`agent_ran(d) is False` 因此不成立。`llm_fatal` 读的也是同一份缺失的 metadata
⇒ **两条都放行**。判据必须取一个**不依赖被怀疑那条链路**的源，
这就是为什么用 `debug.log` 而不是 metadata。

⚠️ 也不能把 `agent_ran` 的三态改成「None 也算排除」：实测旧基线
`modelswitch-base` 的同一题 metadata 也缺失，但它**跑了 31 轮 / 2372 行**，
属于「跑过但没采到」。把 None 一并排除会把真实样本也删掉
（那正是 `agent_ran` docstring 里记的「0.100 变成 0.111」那个坑的反向）。

**② 放弃用 `AUDIT:API` 计数当判据（差点用了它）。** 它在 rerun 里区分度看着完美
（该题 0，其余 1~24）。但旧基线同一题 `AUDIT:API=0` 却跑了 31 轮 ——
因为它的权限审计日志缺失（`sid_permission_audit_missing=True`）。
**那是一个裸子串代理判据：多数情况下巧合正确，而出错那次恰好是最该拦的那次。**

**③ 放弃 `not agent_started(...)` 写法，一律 `is False`。** 没有 sid `debug.log`
的题（cc / mswea / nop 侧）返回 `None`，用 `not` 会把**整个对照侧**排除掉 ——
比不排除更坏。已实测 cc 侧 10 题全部 `None`、排除集仍为空。

**④ 放弃「顺手把这一题也重跑掉」。** 它与本次要补的那 2 题**故障形态不同**
（那 2 题是上游 502 打空重试链，这一题是卡死在启动里），
根因未定位就重跑只会再赌一次 60 分钟。**先让它在报告里站出来，再单独查。**

## 拿什么证明它生效了

**① 修复前后同口径复算**（同一对 run，只换判据）：

```
修复前：配对均值(n=8) 0.250 → 0.125   (↓1 题)   ← fix-code-vulnerability 记为 0.0
修复后：配对均值(n=7) 0.143 → 0.143   (↓0 题)   ← 它被排除，标注「启动未完成」
```

**② 判据在全仓 91 个有 sid `debug.log` 的 trial 上跑过**（分母非空，非真空绿）：
`启动完成 90 / 启动未完成 1` —— 且那 1 个正是本 Note 的主角。
交叉核验：「token 判据不排除、但 agent 根本没启动完」的题**全仓恰好 1 个**。

**③ 门禁 `tests/eval/harbor-agent-started-criterion.test.ts`：16 pass / 0 fail。**
纯 L1 静态（stdlib `ast` + tmpdir 造样本），**不起容器、不跑 harbor、不联网**
⇒ 在 CI 上真的在跑（「探测失败就 skip」等于门禁不存在，本仓踩过两次）。

**④ 四条变异自证，逐条红在预期断言上**（改完 `shasum -c` 三个源文件均 OK）：

| 变异 | 红在 |
| --- | --- |
| `is False` 改成 `not`（最该拦的形态） | 「判 `is False`，绝不用 `not ...`」 |
| 消费侧整个摘掉那条判据 | 同上 + 「作为独立排除原因」 |
| `excluded` 集漏掉 `nostart` | 「并入 excluded 集」 |
| 判据常量改名（模拟散落字面量） | 「判据字符串是具名常量」 |

**⑤ 五道仓库门禁全过**：`affected-tests:run` **1301 pass / 0 fail**、
`make build` 自检通过、`lint`、`lint:boundary`（越界 0 处）、`format:check`。

⛔ **不许说的话**：这条判据**不改变任何 agent 的能力**，它只把一次基础设施故障
从能力账里拿出来。修复后 `0.143 → 0.143` 也**不是**「换模型无差异」的结论 ——
n=7、且两侧仍有 3 题只在一侧被排除，reward 对照本身仍不成立。
