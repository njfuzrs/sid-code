# gh 的只读子命令进 bash 只读白名单，按命令组 + 子命令精确匹配

## 决定了什么

来源是会话 `20261020-110542-ce7ea52e` 评估的发现 6b（PR B2）。被评会话里 `gh issue view 373 --json …` 被 `isReadOnlyCommand` 判为 false，于是失去并发安全资格、每次都走权限判定。

- `tool/bash/read-only-validation.ts` 新增 `isReadOnlyGh`，挂进 `CONDITIONAL_COMMANDS.gh`。白名单是 `issue view/list`、`pr view/list/diff/checks`、`repo view`，外加 `gh --version` / `gh --help`。
- 带 `--web` / `-w` 判非只读：它拉起浏览器，是本机副作用。
- 重定向、命令串联沿用 `isReadOnlyCommand` 原有的 AST 判定，不在 gh 这层重复处理。

收益是并发与语义正确，不是修 cwd 翻转（那是 PR B 的 6a 已修的）。

## 放弃了什么（以及为什么不选）

- **`gh api` 进白名单**：单独落了 `rejected/bug-fix/2026-10-21-gh-api进只读白名单.md`。
- **前缀匹配（`gh pr *` 里带 view 字样就放行）**：`gh pr checkout` 名字像看，实际改本地分支和工作区。只认精确的两级名字。
- **`gh run view` / `gh release view` 等更多子命令**：被评会话没用到，没有数据说明它们值得。白名单只加有证据的，后续按需补。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/tool/gh-readonly.test.ts`：7 pass / 0 fail。覆盖被评会话原样命令、白名单全量、`gh api` 三种形态（含 GET）、14 条写操作和改本地状态的子命令、`--web` / `-w`、重定向、与写命令串联。
- 变异自证 5 处，均变红：不接线（2 红）、不拦 `--web`（1 红）、混入 `checkout`（1 红）、`api` 进白名单（1 红）、只看命令组不看子命令（2 红）。
- 回归：`./packages/core/tests/tool/`、`./packages/core/tests/permission/`、`repeated-readonly-guard`、`low-yield-spin` 合计 1866 pass / 0 fail。
