# 工具执行管线：级联取消识别、Pre/Post 全路径收尾、中断分型、hook 改参后下游跟随

## 决定了什么

对照博客 §5「十一道关卡」审计 `query/tool-executor.ts`，并扫描本机 411 个会话轨迹与 4.5 个月遥测，修了 8 处缺陷。
主循环、进程内子代理（`agent/tool-executor.ts`）、spawn 子代理（`agent/sub-agent.ts`）三条路径的修法和口径一致。

1. **并行 Bash 级联取消被当成异常**：abort reason 由 `sibling_bash_error` 改为 `sibling-bash-error`，并登记进 `ABORT_REASONS`（单一事实源 `SIBLING_BASH_ERROR_ABORT_REASON`）。新增 `abortReasonOf`，它能解析裸字符串 reason。在跑的兄弟工具原先拿到的是 `工具执行异常: undefined`（实测复现），现在拿到级联取消文案，并记为 `aborted`。`withConcurrencyLimit` 新增 `shouldStopLaunching`：级联是在 fulfilled 结果上触发的，原先队列里的任务照样一个个启动。队列占位改为按 `QueueSkippedError` 类型识别，不再匹配错误文案子串。
2. **PreToolUse 已 fire 但工具没执行，不收尾**：新增 `closeUnstarted`，对串行 Bash 级联跳过、并发队列未启动的任务、中断时还没轮到的后续批次补发 `PostToolUseFailure(kind=skipped)`。该事件只送 runtime hook。`executeSingleTool` 抛中断错误那条分支也补上了收尾。新增的 `ToolFailureKind` 值为 `aborted` / `skipped`，轨迹 `error_kind` 同步增加这两类。
3. **中断记成 tool_error**：工具执行中 `signal.aborted` 且返回 `isError` 时，漏斗与 hook 都记 `aborted`（带 `is_interrupt:true`）。判据只看 signal，不解析输出文案。bash 的中断文案改为按 `describeAbortReason(signal.reason)` 写出成因，不再一律写「用户取消」。
4. **主循环被 hook 拦下的调用不进漏斗 1**：`resolveToolPermission` 的阻止分支补上 `logToolCall` 与 `logToolFailure(hook_blocked)`。
5. **hook 改写 file_path 后，下游仍用原路径**：快照挪到权限预检之后、执行之前，按改写后的参数计算受影响文件，被拒的写操作不再建快照。PostToolUse/Failure 的 `tool_input`、LSP 同步、编辑失败计数、漏斗 filePath、`tool_input_size` 全部改用改写后的参数。
6. **hook 改写的参数不过观测回填**：新增 `buildObservableInput`，改写值同样展开 `~` 和相对路径后再交给权限层。子代理两条路径原先完全不展开，现在走同一个入口。
7. **PostToolUse 无法替换输出**：支持 CC 的 `updatedToolOutput`（所有工具）与 `updatedMCPToolOutput`（仅 MCP），替换值同样经过 `processToolResult`。原先 MCP hook 能看到原文却改不了模型看到的内容，脱敏场景实际做不到。
8. **PreToolUse 抛异常时不写 fire-once 缓存**：现在异常也按「没给意见」写入缓存，同一个 hook 不会再 fire 第二次。

可观测性方面：`trace/digest.ts` 新增 `unclosed_pre_tool_use` 异常，机械地数悬空的 Pre。`ABORT_REASONS` 哨兵测试的字面量正则加入下划线，旧正则看不见 `sibling_bash_error`，这正是它漏登记的原因。

## 放弃了什么（以及为什么不选）

- **在 executeSingleTool 的 catch 里按错误文案识别级联取消**：只能治标。根因是 reason 没登记、reason 解析不认裸字符串，文案匹配下次改一个字就静默失效，这次占位识别就是同型坑。
- **skipped 送用户 hook**：CC 对「没执行」的工具不触发 PostToolUseFailure，用户 hook 收到会把跳过当成失败告警。这个事件只为配对，所以只送 runtime。
- **hook 改参后重新跑一遍 getAffectedFiles 但仍放在预检之前**：预检阶段 hook 还没跑，拿不到改写值。挪到预检之后是唯一能拿到真实路径的位置。预检期间只有权限与 hook，不碰文件，挪位置不会丢掉写入前的状态。
- **updatedToolOutput 只对 MCP 生效**：CC 文档明确它对所有工具生效，`updatedMCPToolOutput` 是旧字段，只做 sid 的子集会让按 CC 写的 hook 静默失效。
- **把中断按 reason 细分进漏斗**（user/timeout/cascade 各一个 kind）：漏斗只回答「是不是工具自己的问题」，细分成因已经写进 hook 的 error 文本与轨迹。多加 kind 会让失败率分母再次漂移。

取舍：第 5 条把快照推迟到权限确认之后，多了一次 `getAffectedFiles` 在预检后执行（bash 命令要解析受影响文件），轻微牺牲「更快」，换来「更安全」（快照对象正确）。被拒的调用不再建快照，部分抵消了这点开销。

## 拿什么证明它生效了

- **复现**：修复前用「收到 abort 就 reject `signal.reason`」的工具调 `executeSingleTool`，得到 `{"content":"工具执行异常: undefined","is_error":true}`。
- **数据基线（修复前，本机）**：
  - 轨迹 23,654 个 PreToolUse 中 7 个无收尾，可核的 5 个都是 `已取消：同一轮中先行的 Bash…`。
  - 遥测 06-04 至 10-24 共 773 次 `tool_failure`（`tool_error` 724 / `invalid_input` 49），`aborted`、`hook_blocked`、`exception` 全为 0，但轨迹里有 2 次真实的 bash ESC。
  - 修复后可观察的数据变化：digest 的 `unclosed_pre_tool_use` 应为 0；`aborted` 从 0 变为正数，`tool_error` 相应减少；配了 hook 的环境里 `hook_blocked` 从 0 变为正数。
  - 缺陷 1、5、6、7、8 在本机触发基数为 0（未配 hook，并行轮里的 bash 失败 16 次，兄弟都已跑完），只能靠回归测试证明，本机拿不出数据曲线。
- **回归测试**：
  - `tests/query/tool-pipeline-gaps-20261024.test.ts`：19 条。
  - `tests/agent/subagent-pipeline-gaps-20261024.test.ts`：4 条。
  - `tests/trace/digest-unclosed-pre-tool-use.test.ts`：3 条。
- **变异自证**：逐条把修复改回原样，14 处全部变红。
  - 级联 reason 未登记 / 串行跳过不收尾 / 队列不停止启动 / 中断不给后续收尾 / 中断分型 / hook 阻止不进漏斗 / 快照用原参数 / 改参不展开 / 输出替换 / 异常不写缓存 / digest 不数悬空，共 11 处。
  - 子代理侧：中断分型 / 不展开 / 不替换，共 3 处。
  - 每处恢复后转绿。
- **门禁**：
  - `bun run affected-tests:run`：6066 pass / 0 fail。
  - `make build` 自检通过。
  - `bun run typecheck:gate`：无新增错误。
- **有意的口径变化**：子代理侧中断原先记 `exception`，现记 `aborted`，`subagent-hook-cc-align.test.ts` 对应断言同步更新。
