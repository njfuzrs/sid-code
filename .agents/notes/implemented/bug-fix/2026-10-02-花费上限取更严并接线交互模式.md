# 花费上限：quota.costLimit 与 --max-budget-usd 取更严的那个，交互模式接线（B18）

## 决定了什么

- 新增 `packages/core/src/llm/quota.ts` 的 `resolveEffectiveCostLimit(quota, topLevel)`：两侧正数取 `min`，`0` / 负数 / 未设都视为「这一侧不限」，不参与比较。
- `app.ts` 构造期用它替代 `quotaConfig?.costLimit ?? opts.config.costLimit`。SDK 引擎的 `maxBudgetUsd`、状态栏百分比的分母、`-p` 超限报告的 `limitUsd` 全部改读同一个 `effectiveCostLimit`。原来 SDK 和状态栏读的是 `config.costLimit` 原值，和真正会拦的那个数不一致。
- `cli.ts` 删掉「--max-budget-usd 只在 --print 下生效，交互模式已忽略」的告警。交互模式本来就有 QuotaManager，参数只是没接进去。
- 顺手修复：告警文案里上限的 `toFixed(2)` 改成 `toFixed(4)`，小于一分钱的上限不再显示成 `$0.00`。
- 文档：`use/cost.md` 的「两个必须知道的坑」改写成一条 tip，`team/quota.md` 覆盖关系一节、`ref/glossary.md` 配额词条按新行为重写，`ref/cli.md` 重新生成。

## 放弃了什么（以及为什么不选）

- **把优先级反过来（CLI 盖配置）**：会让成员用参数放宽团队上限，在「更安全」方向上开了一个口子。上限是只许收紧的语义，比的应该是数值，不是来源优先级。
- **把 0 当成最严参与取 min**：评测容器（`exec-swebench.sh`）显式写 `0` 来关掉闸门，团队模板写的是 100。如果 0 参与取 min，任何正数上限都会塌成 0，闸门直接消失，方向又反了。
- **在 cli.ts 里合并**：cli 层拿不到合并后的 settings（quota 来自 loadConfig），合并点必须和 QuotaManager 的实例化放在一起，才能保证「报告里的上限 = 真正触发停止的上限」这个不变量。

## 拿什么证明它生效了

- `packages/core/tests/llm/quota-effective-limit.test.ts` 13 条：四格（只 CLI / 只 quota / CLI 更小 / quota 更小）、0 不参与、合并结果喂给 QuotaManager 后真的会拦、`$0.0020` 显示，以及接线形态断言。变异自证：把 app.ts 改回 `??` 后有 2 条转红，恢复后 13/13 绿。
- `bun test ./packages/core/tests/llm/ ./packages/cli/tests/cli/flag-e2e.test.ts`：1781 pass / 0 fail。
- 真实模型端到端测试（临时 `SID_CONFIG_DIR`，settings 里写 `quota: {costLimit: 100}`，模拟团队默认配置）：
  - `-p ... --max-budget-usd 0.002 --output-format json` 输出 `error.reason=max_budget_usd, limitUsd=0.002, spentUsd=0.0297`，exit=1（修复前生效上限是 100）。
  - 交互模式 `sid-code --max-budget-usd 0.002 "<prompt>"`（经 `script` 伪终端运行）：TUI 输出 `成本已超出配额（$0.0306/$0.0020），自动停止`，stderr 里没有「只在 --print」告警。
