# S5/S6 复审遗留：已学上限与待定计数分开过期，窗口查询一律带端点

## 决定了什么

修复复审清单「修-3」（B3 + D1–D5 + L13–L15 + T2 + T3）：

- **B3**（`llm/learned-window.ts`）：抽出 `nextEntry()`。已学上限按 `learnedAt` 判有效，待定计数按 `firstOverflowAt` 判有效，两者分开。待定计数过期只重算计数，不再抹掉仍有效的上限。上限有效期内又溢出，就取 `min(上限, 本次已放行值)` 并续期，不用等第二次。
- **D1**：「连续 2 次」实现为「7 天内累计 2 次」，理由补进头注释：每次溢出后 reactive 压缩必然让下一个请求变小并成功，按字面「中间有成功就重置」的话学习永远不会发生。
- **L14**：`writeAll` 改为 `writeEntry(key)`，写之前重新读盘、只覆盖自己的键，临时文件名带 pid 加随机后缀。不加文件锁。
- **D4**：`getContextLimit` / `resolveContextLimit` 的调用方补传 baseURL：`app.ts` 的 fallback `resolveContextLimit`、`llm/registry.ts`（子代理窗口）、`config/system-prompt.ts` 两处（`SystemPromptContext` 新增 `baseURL`，三个 `buildSystemPrompt` 调用方带上）、`tool/tool-search-auto.ts`（`AutoThresholdInput.baseURL`）、`llm/model-profile.ts`（`/model` 展示）、`trace/collector.ts` 的上下文占用率（用 `resp.base_url`）。
- **D5**：`addCompactBoundary` 行为不变，新增 `compactBoundaryBreaksAlternation()`，尾部是 user 时打 warn，方便在日志里数出现次数。
- **T2 / T3**：新增 `packages/core/tests/llm/learned-window-followups.test.ts`，用真实 `queryLoop` 锁住两处学习调用在 `reactiveCompact` 之前，并确认请求前确实调了 `stripTrailingInternalAck`。

## 放弃了什么（以及为什么不选）

- **D2：`model-capabilities.ts` 的 `contextExceeded` 接到学习函数**。不接，维持原 Note 的理由：那条路径只在 openai effort 自愈时走，手里没有「已放行 token」和 base_url。学习唯一的接线点是 loop 的 PTL 分支，代码里已有注释说明。
- **D3：回到「能力缓存独立字段 + 改键」**。不回。独立文件 `learned-input-ceiling.json` 不经 `mergeEntry`，也不会被目录同步覆盖。方案第 3、4 条就此改为独立文件。清除入口仍是手删文件，`/model` 来源一栏已写出文件名（`model-meta-format.ts`）。
- **L13：按「输入上限」而不是「窗口」传给 ContextManager**。这次不改，只点破代价。实测 `new Manager({maxTokens: 663_013}).getCompactionThresholds()` 得到 `compactionTriggerUsed = 543_671`（82%），离真墙（约 663K–680K）还有约 18% 余量。比原方案说的「稍早」更重，牺牲的是「更省」：压缩更频繁，换来不再撞 400。要改得给 ContextManager 引入「输入上限」第二个分母，阈值、Footer、/context 三处口径都要跟着动，单独立项。
- **L15：剥 ack 之后桥话术进历史**。不改。桥消息带内部 origin，TUI 隐藏，strip 时和相邻内部消息一起剥掉。代价是后续请求会带一句模型没见过的「继续。」，影响小。
- **L14 用文件锁**：溢出一天也就几次，锁超时和陈旧锁清理的复杂度不值。剩下的竞态窗口是「重读到 rename」之间几毫秒，最坏也只丢别的键在这期间的更新。
