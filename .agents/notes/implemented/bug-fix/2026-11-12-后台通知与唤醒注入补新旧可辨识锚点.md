# 后台通知与唤醒注入补上「新旧可辨识」的锚点：tool-use-id + 绝对时间 + 回执内的确定性状态

## 决定了什么

修 R3（P0）：模型挂完一次后台等待后，把**上一轮**那条 `<task-notification>` 当成刚挂这次等待的结果（事故 b0aa0f1e，模型连续多轮 thinking 复述「后台任务 sjgm4oq76 又被杀了」，而那条通知是旧的）。根因不是模型记性差，是通知里**没有任何能与「我这次调用」对齐的事实**，也没有任何时间信息可以判断新旧。

三处改动，都是「补事实」而不是「加叮嘱」：

1. **通知带调用锚点与起止时刻**（`packages/core/src/task/notification.ts`）
   - `TaskNotification` 新增 `startedAt` / `endedAt`（epoch ms），`formatNotification` 渲染成 UTC 秒级 ISO（`<started-at>2026-11-12T06:31:05Z</started-at>`）。
   - `enqueueTaskNotification` 从 registry 自动补齐 `toolUseId` / `startedAt` / `endedAt`，**不让 14 个调用点各自传**——漏传一处就少一个判据，而这种缺失在测试里很难发现。任务已被驱逐时不写，宁可少一栏不编造。
   - `<tool-use-id>` 原来只有子代理填。新增 `Tool.consumesToolUseId` 声明（与 `consumesAgentId` 同范式）：`bash` / `monitor` 自报后，两条执行器（`query/run-tool-use.ts` 与 `query/tool-executor.ts`）在剥离伪造字段**之后**注入 `_toolUseId = block.id`，工具把它存进 task，通知因此带出来。`bridge.ts` 的透传表同步补键。

2. **唤醒注入带排定 / 触发时刻**（`packages/core/src/query/scheduled-prompt.ts`、`packages/cli/src/app.ts`）
   - `ScheduledPromptSource` 新增 `scheduledAt` / `firedAt`，来源头渲染成 `… · ID wk-xxx · 排定于 06:30:00、触发于 06:31:05 · 由你此前安排…`。
   - `stripScheduledPromptHeader` 增加「按固定形态剥掉时间段」的归一化，**同时兼容改动前落盘的历史消息**（头里没有时间段）——不这样做，resume 时 TUI 会把 harness 的话当成用户任务展示。

3. **新起等待的回执写死当前状态**（`packages/core/src/task/wait-registry.ts` 的 `describeBackgroundWaitFact`，接入 bash / monitor / schedule_wakeup 三处启动回执）
   - 「此刻没有待送达的通知」——`hasPendingNotifications()` 为假时才写；有通知在排队就整句不写（排队中的通知模型还没看到，说「没有」是错的）。
   - 「`<id>` 的终态通知已在 HH:MM:SS 送达过，**不对应本次启动的任务**」——只在会话内有已送达的**等待类**通知时写。取数点是 `registerWait` 时打标的 `everWaitedTaskIds` + `loop.ts` 通知注入汇合处的 `recordDeliveredTaskNotification`（与 `markNotificationsDelivered` 同处，口径都是「真正进了模型上下文」）。

## 放弃了什么（以及为什么不选）

- **放弃在系统提示里加「不要误读旧通知」的叮嘱**。方案文档 §修法 4 明确不做：叮嘱会在下一轮被稀释，而模型真正缺的是可核对的事实，不是又一条行为指令。
- **放弃无差别注入 `_toolUseId`**。内部字段无差别注入会从 `StructuredOutput` 的严格 schema 校验、workflow 返回值、MCP server 的 arguments 三条出口漏出去（这正是 `consumesAgentId` 当初被引入的原因）。做成声明字段 + 双向对账审计（`tests/tool/consumes-tooluseid-audit.test.ts`），漏声明/多声明都变 CI 硬错误。
- **放弃相对时间**（「3 分钟前」）。通知会排队，送达时相对表述已经失真；也放弃本地时区的 ISO——模型的「现在」没有稳定时区可依赖，UTC 秒级 ISO 是唯一无歧义表示。
- **放弃让每个调用点手传锚点**，改为 registry 补齐。代价是 `notification.ts` 多依赖一个 `getTask`（它本来就 import 了 registry 的 `isResultDeliveredByToolResult`，没有引入新边）。
- **`wait-admission` 的 duplicate 回执未在本 PR 改动**：R3 方案要求「R2 的 duplicate 回执也追加这句事实」，但 R2（#791）在写这份改动时仍未合入 main（状态 OPEN DIRTY），本分支上不存在 `wait-admission.ts`。这一条与验收第 3 条（G2 冒烟复用 R2 的 `dup-wait-same-subject` 用例）**需要在 R2 合入后补**，已如实记在 PR 描述里。没有改成基于 R2 分支开发——stacked PR 在本仓会静默不跑 CI（CONTRIBUTING.md 有专门一节记这个坑）。
