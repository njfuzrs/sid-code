# 子代理接上请求前预算闸：命中即收尾，并把「预算停止」带回父代理

## 决定了什么

**问题**：主循环每轮请求前查一次预算（`query/loop.ts` 的 `checkPreRequestBudgetStop`），
子代理一次都不查。用户配了 `costLimit` / 预算规则之后，主循环超限会停下，但**已经派出去的
子代理继续按自己的 `maxTurns` 烧到自然结束**——`wireSubAgentUsageSink` 只保证子代理的钱
记得上账，不保证会被拦住。这就是 D3。

改法（5 个源文件 + 1 个新测试）：

1. **`agent/agentic-loop.ts`**：`AgentLoopConfig` 新增可选回调
   `preRequestBudgetStop?: () => PreRequestBudgetStop | null`。主循环在
   `turns++` **之前**（与父代理停止同一位置）调它，返回非 null 就 break 出去，
   调 `runFinalizeTurn` 跑一轮**不带 tools** 的总结，归因 `stop_action=budget_exceeded`。
   新增 `BUDGET_EXCEEDED_FINALIZE_PROMPT`（要求交回「已确认的结论 / 还没查完的部分」，
   并明令不要调工具）。
2. **`agent/stop-notice.ts`**：加 `budget_exceeded` 一句话说明（PR11 的可见性通道），
   父代理回程里能看到「预算额度已用尽，以下为停止前的总结，未完成部分未继续探索」。
3. **`agent/sub-agent.ts`**：`setPreRequestBudgetStop()` + `buildBaseLoopConfig()` 透传。
   放实例上而不是 `execute()` 参数上：`SubAgent` 的调用方有 tool / custom / workflow / team
   好几条，参数化会让每条各多一个透传点，漏一条就是「某条路径上预算闸静默失效」。
4. **`agent/tool.ts`**：`SubAgentTool.setPreRequestBudgetStop()`，在
   `createSubAgentForType()` 里挂给子代理——`runSync`（前台）与 `runAsync`（后台）共用
   这个工厂，接在工厂上两条都接上；验收场景（S-F）恰好是后台子代理。
5. **`cli/src/app.ts`**：新增 `wireSubAgentBudgetStop()`，在 `wireSubAgentUsageSink()` 之后调用。
   **`quotaManager` 与 `budgetTracker` 都没有时直接 return，不注入**——这是「只对配了预算的
   用户生效」的唯一落地方式（未注入 → 循环里 `probeBudgetStop()` 短路 → 与改造前等价）。
   判据直接复用 `checkPreRequestBudgetStop`，「已花多少」用
   `SessionState.getEffectiveTotalCostUSD()` 在每次检查时现算。

## 放弃了什么（以及为什么不选）

- **不在 `agentic-loop.ts` 里直接持有 `QuotaManager` / `BudgetTracker`**。两者由 cli 层
  组装，`SubAgent` 还有 `new SubAgent(...)` 直接构造、连 registry 都没有的路径；让 core 的
  循环反向依赖这套组装方式不划算。回调把「谁在配预算」和「已花多少」一起封给注入方，
  循环只负责「命中就停」。
- **不复用 salvage 兜底**。方案明确要求「不要走 salvage」：salvage 是启发式残卷，而预算停止
  时钱已经花过，该用一次不带工具的真实请求把结论换回来。salvage 仍保留在它原本的
  「收尾本身失败」路径上。
- **不在收尾轮再查一次预算**。收尾轮是**故意允许超预算一次**的：如果它也被拦，这道闸
  就变成「花了钱、什么都没拿到」，比不拦更糟。这是本改动牺牲「更省」换「更准」的那一处。
- **fail-open 而不是 fail-closed**。回调可能因 `SessionState` 未初始化、单价表缺失等抛错；
  「不知道有没有超」不等于「肯定超了」。按超预算处理会误杀一个本来能跑完的任务，
  而主循环那道闸仍然在。宁可漏拦一次，不误杀。
- **不做 spawn 模式的预算闸**。spawn 子代理跑在子进程里，预算判据依赖的
  `QuotaManager` / `SessionState` 都在父进程，跨进程拿不到。spawn 仅在源码态
  （`entrypoints/headless.ts` 存在）启用，交付的编译二进制里不可用，故不在本 PR 范围。
  边界写进了 `wireSubAgentBudgetStop` 的注释。
- **不给 `wireSubAgentUsageSink` 顺带加检查**。「记得上账」与「会被拦住」是两件事，
  合在一个方法里下一次改一处就会以为另一处也变了。
