# openai.ts parseSSE 不再把「上游会怎么分帧」当成已知常量（D1 / D2 / D3 / D8）

## 决定了什么

四条缺陷同一个根源：解析层按「观测到的官方端点行为」写，而不是按协议写。

- **D1 / D2（SSE 行语法）**：新建 `llm/sse-line.ts` 作为 SSE 行语法的**唯一实现**
  （按 WHATWG 规范：CRLF / LF / CR 三种行尾都认；冒号后的空格可选，且只移除一个；
  `[DONE]` 按 trim 判定）。`openai.ts` 与 `openai-responses.ts` 都改走它。
  后者按 `\n\n` 切块，遇到 CRLF 流就整条流堆到 EOF，这是同型缺陷，一并收敛。
  `sse-event-line-shim.ts` 不动：它本来就对，且是字节透传型 TransformStream，形态不同。
- **D3（收尾出口）**：`completed` 遥测、延迟的 `message_delta`（usage + stop_reason）、
  `message_stop` 从 `[DONE]` 分支收敛到 while 之后的 `finishStream()`，`[DONE]` 与 EOF 共用这一个出口。
  失败出口（流内 error chunk、`insufficient_system_resource`、超时/abort 抛错）经
  `flushUsageBeforeFailure()` 把**已收到**的 usage 先交出去（`stop_reason: null`）。
  另外 EOF 时处理 decoder 残留与不以换行结尾的残行；未关闭的块（含工具块）一律关闭。
- **D8（tool_call 身份）**：`id` / `name` 按片合并（`mergeToolCallIdentityFragment`：
  相同则忽略、以已累积值为前缀则替换、否则追加），不再首片锁定。
  `content_block_stop` 新增可选 `tool_use: {id, name}` 修订通道，仅当最终身份与 start 时不同才发。
  四个消费方（query / agent stream-processor、forked-agent、headless）在解析 input 之前用它覆盖。
  收尾时仍无 id 就合成 `call_sid_<fetchId>_<index>`，并落遥测。
- 新增 `SseAnomaly` 事件（`eof_without_done` / `tool_identity_revised` / `tool_identity_missing`），
  让这几条防线在真实会话里被触发时有据可查。

## 放弃了什么（以及为什么不选）

- **只把 `"data: "` 改成 `"data:"` + `slice(5)`**：只修 D1 这一个实例，三份实现照样分裂，
  下一个差异还会再裂一次。缺陷文档对照表证明两份对、一份错，而测试全绿。
- **只在 `if (done) break` 前补一次 flush**：只补了 EOF 一个出口，流内 error 与超时照漏。
- **`content_block_start` 推迟到身份稳定再发**：arguments 增量要靠 start 建立的 index 落位，
  推迟就得在 provider 内缓存全部增量，还会改变首内容时刻（TTFT 口径）。修订通道改动更小，
  而且对 Anthropic 族零变化（身份不变就不发该字段）。
- **身份无脑拼接**：vLLM 与部分网关每片都重复完整 id/name，拼接会得到 `call_abccall_abc`，
  它能过所有非空校验，比截断更坏。
- **name 缺失时合成**：无从合成，合成一个假名等于伪造模型行为；只落遥测，交给下游的未知工具处置。
- **把 `sse-event-line-shim.ts` 也改走 sse-line**：它逐行透传且保留原始字节，已正确处理 `\r`，
  改动收益为零、风险非零。
- **D4–D7、D9**：按任务范围不在本次处理。

## 拿什么证明它生效了

- `packages/core/tests/llm/openai-sse-framing.test.ts` 共 28 条用例，夹具按协议铺
  （无空格 / CRLF / 裸 CR / TCP 切在 `\r\n` 中间 / 无 `[DONE]` / 残行 EOF / 流内 error /
  id·name 迟到、切碎、每片重复、始终缺失）。
- 变异自证：每条修复单独改回旧写法，对应断言都红了（实跑）。
  - 只认 `data: ` → 无空格两条红
  - `split("\n")` + `[DONE]` 严格相等 → CRLF / CR 早退两条红。
    第一版只看事件序列，这条变异全绿：D3 修好后，没认出来的 `[DONE]` 会落到 EOF 出口，
    序列完全相同。因此补了「`[DONE]` 后 socket 挂起、1s 内必须结束」的断言。
  - 删 EOF 统一出口 → D3 四条红
  - 删 error 前 flush → 一条红
  - 身份首片锁定 → 切碎两条红
  - 消费侧不覆盖 → 端到端四条红
- `bun run affected-tests:run`：5252 pass / 0 fail；`make build` rc=0，
  无 `will always be undefined` warning；`bun run lint` / `format:check` / `lint:boundary` 通过。
- 证据强度如实标注：D1 / D2 / D3 / D8 都有实测复现，但「真实网关发 CRLF / 不发 `[DONE]` /
  切碎 name」都**没有轨迹样本**。这是按协议做的加固，不是修线上事故。
  验收的下一步是看 `SseAnomaly` 在真实会话里出现过没有。
