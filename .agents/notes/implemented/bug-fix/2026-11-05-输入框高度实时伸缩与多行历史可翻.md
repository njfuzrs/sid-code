# 输入框高度随内容实时伸缩 + ↑↓ 翻历史遇到多行条目不卡死

## 决定了什么

用户报告两个底部输入框的问题：

1. **删行后输入框不变矮**。原因是 710a232c（2026-11-03）有意加的高度水位：`InputArea` 用 `nextHeldRows`
   把框撑在出现过的最高点，等下一轮开始或历史区新增一项才回落。目的是长会话里主屏帧已溢出视口时，
   框一变矮底座就整帧重画全部历史（`packages/tui/src/frame/main-screen.ts` 文件头）。
   **用户定：高度必须实时跟随内容**。本次删掉 InputArea 的水位（`padInputRows` / `renderPadRows`），
   空输入框分支和正常分支都按实际行数渲染。`hooks/useHeldRows.ts` 本身和其它瞬态行（Toast、状态行、
   退出提示）的占位不动。
2. **↑↓ 翻历史翻到多行条目就卡住**。普通模式的判据是 `lines.length === 1` 才翻历史：翻到一条多行
   历史后行数 > 1，↑↓ 永远只移光标，再也翻不出去。改成光标在首行按 ↑ / 在末行按 ↓ 翻历史
   （原 shell 模式已是这个口径，cc 同口径），抽成 `text-buffer.ts` 的 `arrowNavigatesHistory`，
   两种模式共用。`history-up/down` 把光标放在末行末尾，所以 ↑ 先在条目内逐行上移、到首行再继续翻，
   ↓ 在末行直接翻回。

牺牲的方向：更快（渲染开销）。长会话里退格删行 / Ctrl+U 清空多行 / Esc 清空，每让框变矮一次就整帧
重画一次，用户往上翻的 scrollback 会被拉回底部。换来的是输入框行为符合直觉。

## 放弃了什么

- **只在清空时缩回、删到一半仍占位**：每次清空只重画一次，频率最低，但用户在选项里明确选了实时自适应。
- **在底座层做「溢出后收缩不重画」**：main-screen.ts 文件头已论证，滚进 scrollback 的行拉不回来，
  擦底部和补空行两种不重画方式都必然留空白。在 UI 层占位是唯一不重画的办法，而用户拒绝了这个办法。
- **↑ 在多行条目里直接翻历史（不管光标在哪）**：会让用户无法用 ↑ 在自己编辑的多行内容里移动光标。

## 拿什么证明它生效了

- `packages/cli/tests/ui/hooks/input-history-arrow-persist.test.tsx` 新增两条：↑ 穿过三行条目翻到更早一条、
  ↓ 翻回到空输入；光标在中间行时不误翻。变异自证：把 `arrowNavigatesHistory` 改回 `lines.length === 1`，
  第一条变红（Received 停在三行条目上），恢复后 9 pass。
- `main-screen-shrink-e2e`（真实 TUI + mock 模型）：`退格删回一行` 的 resets 从 0 变 1，说明框确实
  缩回了一行。门禁从 0 次放宽到 ≤1 次，其余高频交互仍锁 0。实测输出
  `{"输入两行":0,"退格删回一行":1,"Ctrl+U 清空":0,…}`，1 pass。
- `bun run affected-tests:run` 2803 pass / 0 fail；`make build` 自检通过；lint / format:check / typecheck:gate 绿。
