# 思考开关展示改为状态词，Footer 与 /think 面板同源

## 决定了什么

Footer thinking 列不再用 `✻` / `✧` 字形，改为英文状态词，共 6 种：

| 状态 | 词 | 颜色 |
| --- | --- | --- |
| 手动开 / 关 | `on` / `off` | 成功色 / 灰 |
| auto 解析为开 / 关 | `auto·on` / `auto·off` | 成功色 / 灰 |
| 恒思考（locked-on） | `always`；意图为 off 时转警告色 | 成功色 / 警告色 |
| 无独立开关（none） | `by-model` | 灰 |

颜色规则只有一条：**实际在思考就亮色**，与是否 auto 无关。

词表与配色集中在 `packages/cli/src/ui/utils/thinking-label.ts`，三处共用：

- Footer：`useStatusLineData.ts` `deriveThinking`
- `/think` 面板：`ThinkDialog.tsx`。状态行显示当前词；每个选项后显示「→ 选它之后 Footer 会显示的词」；恒思考模型上 off 标「本模型无效」。
- `/think xxx` 回执与 help：`think.ts`

另外修正了 auto 的说明文案。auto 实际取的是模型默认值（`cap.thinkingDefaultOn`），与 effort 无关，旧文案「跟随 effort 设置」是错的。

成因：用户在会话 `20261018-001308-45d2c40b` 里看到 Footer 显示灰色 `✻`，读成了「关」。实际请求体是 `thinking enabled` + `reasoning_effort max`，意图是 auto，DeepSeek 默认开。三个原因叠在一起：字形相近、auto 不上色、没有图例。

## 放弃了什么（以及为什么不选）

- **保留字形，只改颜色**：auto 态仍然看不出来；`✧` 也与「by-model」共用，同样会被读成「关」。
- **固定 `✻` 前缀 + 状态词**：用户选了纯词，理由是与 Footer 其它列（`max`、`7%/82%`）风格一致、更省宽度。
- **中文词（开 / 关 / 恒开）**：Footer 其它列全是英文，混用中文不统一（用户明确要求）。
- **面板和 Footer 各写一套文案**：这正是原问题的形态，面板写「auto → on」，Footer 写 `✻`，两处说法对不上。改为同一个函数，并用参数化测试锁住两条路径输出相同。

- `status-line-effort.test.ts`：回归断言 `auto·on` 与 `on` 同色、不再出现 `✻` / `✧`，Footer 文本全为英文。
- `components/ThinkDialog.test.tsx`：整帧渲染，断言状态行与各选项预览正确，恒思考模型上 off 显示「→ always（本模型无效）」。
- `bun run affected-tests:run`：2545 pass / 0 fail。lint、format:check、lint:boundary、typecheck:gate 全绿；`make build` exit 0，无 `will always be undefined` 告警。
