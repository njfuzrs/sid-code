# find 副作用谓词三份副本合并为单一事实源，并用子集对账测试锁住第二套白名单

## 决定了什么

`find` 的危险谓词（会删 / 写文件或执行任意命令的那 9 个 action）此前在仓里有**三份**
字面量完全相同、只有书写顺序不同的副本：

- `tool/bash/read-only-validation.ts` 的 `isReadOnlyFind`（只读判定）
- `memory/extract/permissions.ts` 的 `FIND_UNSAFE_ARGS`（后台记忆代理的第二套白名单）
- `permission/shell-command-variants.ts` 的 `findWriteTargets`（写目标保护）

缺陷文档只点名了前两处，第三处是复核时发现的。三份副本的后果是「改一处漏一处就一边拦
一边放」，而且不会有任何东西变红。

修法：新建**零依赖**的 `packages/core/src/tool/bash/find-actions.ts`，导出
`FIND_SIDE_EFFECT_ACTIONS`，三处都 import 它。放在独立文件而不是
`read-only-validation.ts`，是因为 `permission/shell-command-variants.ts` 被
`read-only-validation.ts` 反向 import（`expandShellCommand`），让它再去 import 那份实现
会成环。本文件零依赖，任何一方都能安全引用。

同时新增 `packages/core/tests/memory/readonly-prefix-subset-reconcile.test.ts`：断言
第二套白名单 `READONLY_BASH_PREFIXES` 的每一条都能在主表 `READ_ONLY_COMMANDS`、
`CONDITIONAL_COMMANDS` 或 git 子命令分支里找到落点。为读数据把
`READONLY_BASH_PREFIXES` 加了 `export`（仅导出，不改行为）。

判据刻意是**子集关系**而不是相等：第二套白名单本来就该是主表的子集（后台记忆代理只跑
更窄的命令集），要求相等会逼人把主表全部抄进第二套——方向反了，而且会让「第二套漏了
一条新命令」这种安全侧的偏差变成必须同步的负担。

## 放弃了什么（以及为什么不选）

- **把共享常量留在 `read-only-validation.ts` 里 export**：`permissions.ts` 已经这么用
  没有问题，但 `shell-command-variants.ts` 引用它会与 `read-only-validation.ts`
  形成 import 环。虽然 ESM 能处理一部分环，但环上的初始化顺序依赖运行时而不可静态验证，
  不值得为省一个文件引入。
- **只合并文档点名的两处，第三处留着**：那等于把「三份副本」修成「两份副本」，
  缺陷的根因（同一份数据抄多遍）没消失。
- **对账测试断言两张表相等**：见上，会迫使第二套白名单随主表全量扩展，而它存在的理由是
  「后台代理只允许更窄的命令集」。
- **让 `isReadonlyBash` 直接调用 `isReadOnlyCommand` 而不留第二套白名单**：两套白名单的
  git 子命令判定已经共用同一份实现，但命令集合本身刻意不同（后台代理不该跑 `tar` /
  `unzip` 之类）。合并整张表会改变权限模型，超出本缺陷范围。
- **对账测试用正则解析源码**（照抄 `read-only-validation.test.ts` 的
  `parseMainWhitelist`）：正则对格式变化很脆。改用 TypeScript 编译器 API 解析 AST，
  并加了一条「解析自检」用例（断言解析出的集合大小 > 0 且含已知条目），
  解析器静默失效时会先让自检变红，而不是让对账测试恒绿。

## 拿什么证明它生效了

```text
SID_CONFIG_DIR=$(mktemp -d) bun test \
  packages/core/tests/memory/readonly-prefix-subset-reconcile.test.ts
  → 3 pass / 0 fail（含解析自检 + 真子集守卫）

SID_CONFIG_DIR=$(mktemp -d) bun test packages/core/tests/memory/sc07-memory-p0-p1.test.ts \
  packages/core/tests/tool/readonly-side-effect-gaps.test.ts
  → 51 pass / 0 fail

SID_CONFIG_DIR=$(mktemp -d) bun test packages/core/tests/permission/ \
  packages/core/tests/tool/ packages/core/tests/memory/
  → 4120 pass / 0 fail（221 files，含 findWriteTargets / bash-security 全部回归）
```

变异自证（对账测试真的会拦）：

```text
往 READONLY_BASH_PREFIXES 塞 "nc"
  → 1 fail：expect(received).toEqual(expected)  - []  + ["nc"]
  → 删回后 3 pass

⚠️ 不能用 "curl" 做这个探针：curl 是 CONDITIONAL_COMMANDS 的合法成员
（curl: () => false），按「属于 CONDITIONAL 委托范围」的判据它是合规的，
门禁判绿是正确行为。这个坑已写进测试注释。
```

变异自证（共享常量真的被三处消费）：

```text
把 find-actions.ts 的集合改成只含 "-delete"
  → readonly-side-effect-gaps 与 bash-write-targets 的 -exec / -fprint 用例变红
  → 恢复后全绿
```
