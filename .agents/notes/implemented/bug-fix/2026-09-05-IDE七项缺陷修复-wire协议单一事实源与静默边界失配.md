# IDE 层七项缺陷：把「静默的边界失配」收口成一个共享常量 + 一条 debug 日志

## 决定了什么

修掉 `20260903-IDE与Bridge三层实测-十六项缺陷.md` 的 D2-D8（IDE 层全部七条）。

**核心一条不是改字符串，是新建 `ide/protocol.ts` 作为 wire 协议的唯一事实源。**
D2（通知名多 `notifications/` 前缀 → 选区/@提及永久静默）与 D4（11 处测试
硬编码了同一个错误字符串，把 bug 焊死）是同一件事的两面：实现与测试用了同一个
错误常量，互相自证，测试对 bug 完全免疫。所以判据从"字符串对不对"换成
**"wire 字符串有没有第二个来源"** —— 实现与测试 import 同一个常量，
下次拼错是编译错误而不是静默失配。

逐条：

| # | 改动 | 文件 |
| --- | --- | --- |
| D2 | 通知名去前缀，改从 `IDE_NOTIFY` 出 | `ide/{protocol,selection,mention}.ts` |
| D4 | 11 处测试字面量改 import 共享常量 + 新增反漂移门禁 | `tests/ide/{context-delta,integration,wire-protocol-single-source}.test.ts` |
| D3 | `openDiff` 参数改 CC 扩展的 snake_case，响应改认内容块数组（宽容三形态），补 `close_tab` | `ide/diff.ts` |
| D5 | 连接成功后发 `ide_connected`（带 pid），排在两个订阅**之后** | `ide/integration.ts`、`mcp/client.ts` 新增 `notify()` |
| D6 | `isSubPath` 两侧 `.normalize("NFC")` | `ide/detect.ts` |
| D7 | 清理 lockfile 时加 300ms TCP 探活，三态判据（`unknown` 保留文件） | `ide/lockfile.ts` |
| D8 | 新建 `ide/wsl.ts`，让 `runningInWindows` 真的被消费（寻址 + 双向路径换算） | `ide/{wsl,detect,selection,mention,diff}.ts` |

另加一条**成本一行、收益覆盖一整类**的改动：`mcp/client.ts` 的通知分发处，
收到无订阅者的通知时打一条 debug（排掉 switch 已消费的三个标准 `list_changed`，
否则被例行噪声淹没）。它让 D2 这类 bug 从"完全不可见"变成"开 debug 就能看见"。

## 放弃了什么（以及为什么不选）

**① D8 不做完整 WSL 支持，但也不删字段。** 缺陷文档给的是二选一
（实现 WSL 或删掉字段），§四 又说 WSL 不值得投入。两个极端都不对：
删字段会连"WSL 用户连不上"这个真实症状一起删掉；做完整支持要处理
交互终端、扩展安装、文件监听一整套。取中间：**只让字段在寻址与路径这两个
真正决定"能不能连上"的接点上生效**，逻辑全部可注入、可单测。
⚠️ 诚实边界：**"在真实 WSL 里确实连上了" 没有被验证过**（开发机是 macOS）。
所以这条的说法是「死字段已被消费、推导有单测」，不是「WSL 已支持」。

**② D7 的 `unknown` 三态没有折叠成布尔。** 折叠成 `false` 会在探测本身出岔子
（fd 耗尽）时删掉健康的 lockfile。清理动作必须保守：留一个过期文件的代价是
一次连接失败并重试，删一个健康文件的代价是 IDE 明明开着却再也发现不了。

**③ D3 的响应解析没有只认标准的内容块数组。** 这条边界的对端是**我们不控制的
上游扩展**，协议随时可能被改且**改了只会静默失配**。多认对象形态与裸状态字符串
的成本是十几行，收益是上游微调时功能不至于整个归零。

**④ 无订阅者日志用 debug 而非 warn。** warn 会在每个正常会话里响 ——
私有通知本来就可能有我们不订阅的类型。噪声大到没人看等于没有这条日志。

**⑤ 没有给 D2 那类失配加"前缀归一化"。** 在路由器里同时试带/不带前缀
能让这次的 bug 自愈，但代价是把一个**协议错误**变成**协议模糊**：
以后两个不同 method 可能被归一到同一个 handler，且永远发现不了。
错误应该被拦住，不是被兼容掉。

## 拿什么证明它生效了

**① 门禁做了变异自证**（本仓铁律：每条规则须变异自证，否则可能是 false gate）：

```
变异1：protocol.ts 里把常量值改回 "notifications/selection_changed"（复现 D2）
  → 3 pass / 1 fail  ✅ 红了

变异2：mention.ts 里重新硬编码 "at_mentioned" 字面量（复现 D4）
  → 2 pass / 2 fail，报 `packages/core/src/ide/mention.ts 里出现字面量 "at_mentioned"`  ✅ 红了

复原 → 4 pass / 0 fail  ✅
```

**② D6 的用例先断言了「反例存在」**，避免退化成同义反复：
`expect(NFC).not.toBe(NFD)` + `expect(NFC.normalize("NFC")).toBe(NFD.normalize("NFC"))`
—— 先证明这两个字符串确实肉眼相同而字节不同，再断言 `isSubPath` 能匹配上。

**③ D7 用真实 socket 而非 mock**：`createServer` 起一个真端口断言 `true`；
先占后关得到一个确定没人听的端口断言 `false`；再用 `pid: process.pid`
（**一定活着**，旧 PID 判据清不掉）写一个 lockfile，断言 `cleanupStaleLockfiles()`
把它删了 —— 这一条直接证明了新判据比旧判据严。测试落盘全部重定向到 tmpdir
（`SID_CONFIG_DIR`，存/恢复原值而非无条件 delete）。

**④ D5 断言了顺序而不只是"发出去了"**：
`expect(subscribed).toEqual([selectionChanged, atMentioned])` —— 通知必须排在
两个订阅之后，否则 IDE 收到 `ide_connected` 后立刻回推的那一次选区会静默丢掉。

**⑤ 命令与输出**：

```
bun test ./packages/core/tests/ide/   → 56 pass / 0 fail
bun test ./packages/core/tests/mcp/   → 77 pass / 0 fail
make build                            → 自检 4 项全过；grep "will always be undefined" 无命中
bun run lint / format:check / lint:boundary → 全绿（越界依赖 0 处）
```

`make build` 后特意 grep 了 `will always be undefined`：worktree 里新增模块
（`protocol.ts` / `wsl.ts`）若没跑 `bun install`，`@sid-code/core` 会向上解析到
主仓 checkout，新导出在产物里是 `undefined` 而**构建仍然 exit 0**。已跑
`bun install`，warning 零命中。

**⑥ 尚未验证的部分，明确列出**：
- D2/D3/D5 的**真实验收判据是"接上真实 CC 扩展后确实收到一次选区通知 / diff 弹出且手改被拾取"**，
  这需要装 `anthropic.claude-code` 扩展的环境，本次未做。测试绿**不是**这三条的验收判据
  （D4 的教训正是"测试本来就绿"）。
- D8 的真实 WSL 连通性未验证（见上）。
