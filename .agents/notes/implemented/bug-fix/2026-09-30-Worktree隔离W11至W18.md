# Worktree 隔离：边界、锁、活会话与基线四类判据补齐（W11–W18）

## 决定了什么

来源：`docs-research/sid-code/bugfixes/todo/20260926-Worktree隔离-顺着sc-19核出的缺陷.md`，本轮只做 W11–W18。W19 及之后下一轮做。

- **W11** `manager.ts` postCreationSetup：`symlinkDirectories` 每一项先过 `unsafeSymlinkReason`。
  绝对路径、含 `..` 段、落点不在 worktree 内、源的 realpath 不在主仓内，都跳过并打 warn。
- **W12** `permission/checker.ts` Step 3.8：当前异步链绑定在 `.sid-code/worktrees/<slug>` 上时，
  写工具（write/edit/notebook_edit）的目标如果在主仓内、却不在这个 worktree 内，就硬 deny，不给确认。
  worktree 根取 `withAgentCwd` 进入时绑定的 `root`（不随 cd 变）。
- **W13** `manager.ts`：`create` / `restoreExisting` 以 `sid-code:pid=<pid>` 为理由执行 `git worktree lock`；`remove` 先 unlock。
  `cleanup.ts` 分三种情况：sid-code 锁且持有者活着算锁定，持有者已死算陈旧锁、照常回收，其它理由（人手动加的）一律尊重。
- **W14** `cleanup.ts`：GC 开始前读一次活跃会话注册表。有活会话的 cwd 落在某个 worktree（含子目录）里，就不删它。
  注册表读不到时整轮不删。
- **W15** `session/file-intent.ts`：意图表的键先经 `intentKeyForPath` 剥掉 worktree 容器前缀，
  跨 worktree 的同一相对路径就撞到同一个键。正则口径与 W4 的 `WORKTREE_CONTAINER_RE` 相同（排除以点开头的 slug）。
- **W16** `bootstrap/cwd-context.ts`：ALS store 从字符串改成 `{root, cwd}` 盒子。`setCwd` 在代理上下文里写盒子，不写全局 `state.cwd`。
- **W17** `cli.ts` 启动恢复段、`command/advanced.ts` 的 `/worktree`：`findGitRoot` 改为 `findGitRootForAgent`（canonical 优先）。
- **W18** `manager.ts` 新增 `baselineForExisting`：复用已有 worktree 时，基线取它与主仓 HEAD 的 merge-base，不再取当前 HEAD。
  `enter_worktree` 的 path 模式也用它。`countChanges` 遇到空基线时，改数「别的 ref 都够不到」的 commit，不再当 0。

## 放弃了什么（以及为什么不选）

- **W12 在子代理派生 checker 时把 workspacePath 换成 worktree**：这样会连 worktree 外的合法位置（`/tmp`、plan 文件、`/add-dir` 目录）一起收紧。
  swarm 和 SubAgentTool 两条派生路径也都得改。现在的判据只拦「写回主仓」这一种越界，一处生效，所有路径都覆盖到。
- **W12 覆盖 bash 命令正文里的绝对路径**：要做到就得解析任意 shell，误报和漏报都拦不住。bash 仍靠 worktree 本身的物理隔离。
- **W13 用 sid-code 自己的锁文件，不用 git lock**：GC 早就在读 git 的 `locked`，人也能用 `git worktree list` 看到锁。另起一套标记，就成了第二个没人读的状态。
- **W13 见到锁一律不删**：崩溃留下的孤儿会永远回收不了。所以锁理由里带 pid，持有者死掉的锁算陈旧锁。
- **W14 把子代理 worktree 写进 session-config**：那份文件按主仓维度只存一个 session-level worktree（不变量 §8.2），塞进子代理会破坏恢复语义。
  子代理 worktree 已经由 W13 的活进程锁保护了。
- **W15 把键改成仓库相对路径**：`queryFileIntents` 的调用方和冲突报告都按绝对路径展示。剥前缀后的键仍是主仓绝对路径，报告照样可读。
- **W18 把创建时的基线持久化到 worktree 里**：要多写一个文件，而且 git 之外改过分支的情况对不上。merge-base 是 git 自己能随时重算的事实。
