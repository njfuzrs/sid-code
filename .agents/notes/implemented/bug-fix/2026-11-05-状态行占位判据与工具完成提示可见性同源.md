# 空闲时输入框上方不留空占位：状态行判据与可见性同源 + 瞬态块空闲即放

## 决定了什么

用户报告：TUI 空闲时最后一条消息与输入框之间有 4 行空白。正常应只有 1 行（历史项的 `marginBottom`）。
多出的 3 行来自两处 `useHeldRows` 占位，本次两处都修：

1. **Composer 状态行判据读错了状态**（`components/Composer.tsx`）。`statusRowHasContent` 用
   `!!streaming.lastToolResult`，而 `app.ts` 的 `tool_end` 写入后回合结束也不清空。工具完成提示 2s 后
   自己隐藏，判据却恒真，状态行空闲时一直占 1 行空白；同一判据还让 YOLO / plan / 只读指示在用过一次工具后
   永久不显示（截图 footer 是 `skip-perms`，输入框上方却没有 YOLO）。修法：2s 可见性提到
   `useToolResultVisible`，判据与权限模式指示都读它。
2. **输入框上方的瞬态块空闲时还在占位**（`hooks/useHeldRows.ts` 新增 `releaseWhenIdle`）。
   Toast（Ctrl+O 展开提示等）、状态提示在空闲时出现又消失，占位挂到下一轮开始，在 `gap={1}` 里
   = 1 行占位 + 1 行 gap。ToastDisplay、StatusMessageRow、Composer 状态行传 `releaseWhenIdle: true`：
   `busy=false` 时直接回落到当前行数。

**牺牲了「更快」成全「更准」（用户定）**：主屏帧溢出视口后任何变矮都整帧重画。修复后，
回合结束一次、空闲提示消失一次，各多 1 次整帧重画（e2e 实测「第二轮」0→1、「空闲提示消失」1）。
这两类都是每轮至多一次的低频事件；高频交互（打字、退格、Ctrl+U、补全菜单、退出提示）仍锁 0。
输入框内部水位、输入框下方的退出警告不传 `releaseWhenIdle`，行为不变。

## 放弃了什么（以及为什么不选）

- **保留空行、维持零重画**：用户明确选「界面不留空白」。
- **空闲时让状态行常驻内容（恢复「? 查看快捷键」）**：能同时保住行高与零重画，但只治 1 行
  （Toast 的 2 行照样在），且要推翻 `c716349e` 的设计决定，不在本次范围。
- **在 app.ts 回合结束清空 `lastToolResult`**：要改事件语义，同一对象再写入还触发不了 effect；
  可见性是 UI 状态，判据应当和它读同一个值。
- **整个去掉 `useHeldRows`**：它挡住的是高频交互的整帧重画（#563），问题只在「空闲时还占」。

## 拿什么证明它生效了

- `tests/render-port/main-screen-shrink-e2e.test.ts`（PTY 起真实 TUI + mock 模型 + xterm 重放）新增
  「空闲 Ctrl+O 提示 → 消失」段，断言消失后输入框上方连续空行 = 1。修复后 pass；
  变异自证：把 `releaseWhenIdle` 那条释放条件改成 `false`，断言红为 `blanks: 3`（正是截图里多出的 3 行），还原转绿。
  同一门禁「第二轮」的重画上限由 0 放宽到 ≤1，理由写在断言旁。
- `tests/ui/components/layout-bottom-region-snapshot.test.tsx` 新增整帧用例：工具完成提示过期、最终回复
  入历史后，整帧必须与从没出现过工具结果时完全一致。变异（判据改回 `!!lastToolResult`）→ 红，差一行空行。
- `tests/ui/hooks/useHeldRows.test.tsx` 新增 3 例：空闲即放、回合中仍占、不传选项时空闲照旧占。
- 未做：没有在用户的真实会话里用 `sc-dev` 复现截图场景，4 行的拆分（1+1+2）来自 mock 会话。
