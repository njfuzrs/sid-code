# 切模型（/model、降级链、配置驱动）落 ModelSwitch 事件进 events.jsonl

## 决定了什么

`TraceCollector` 订阅 `PostModelSwitch`，每次切换写一条 `ModelSwitch` 事件
（`from_model / to_model / trigger / reason / after_request_index`），并立即同步 `metadata.model`。

动机：会话 20261018-230439-a41bcd77 启动模型 MiniMax-M3，用户发首条消息前 `/model` 切到
gpt-6-luna，轨迹里只有 `model_at_start` 与 `model` 两个端点值，**零条切换记录**——
看不出何时切、谁触发（手动还是降级）、切了几次。hook 事件 `app.ts` 的 `applyPrimaryModelSwitch`
早就在 fire，只是 collector 的订阅清单里没有它（死接线：生产者在、消费者缺）。

`after_request_index` 记切换前已发出的主请求数（含 resume 偏移），0 = 首请求之前就切了，
用于把一段 raw.jsonl 归到哪个模型名下。

## 放弃了什么（以及为什么不选）

- **同时订 PreModelSwitch**：Pre 只通知不能拒绝（`app.ts` 注释写明刻意偏离 CC），
  与 Post 信息量相同，订两个只会产生重复行。
- **等下一次 BeforeModel 再更新 metadata.model（旧行为）**：切完就退出的会话没有下一次请求，
  metadata 永远停在旧模型。
- **会话恢复路径（`app.ts` ~5530 恢复 agent 模型快照）也发事件**：那里注释明确「恢复不是切换」，
  不触发 hook；它的结果已体现在 SessionStart 之后首请求的 model 上。若以后要追，单独加事件，
  不要复用 ModelSwitch 污染「用户/降级切换」语义。
- **onboarding 配置向导（~10892/10926）**：同样不走 `applyPrimaryModelSwitch`，本次未覆盖，
  属于首次安装场景，发生在会话开始前的配置阶段。

## 拿什么证明它生效了

- `bun test ./packages/core/tests/trace/collector.test.ts`：103 pass / 0 fail，
  新用例覆盖首请求前手动切换（after_request_index=0）与降级切换（带 reason、index=1）。
- 变异自证：把订阅清单里 `HookEventName.PostModelSwitch` 注释掉，新用例红
  （`Expected: "gpt-6-luna" Received: "claude-test"`），恢复后绿。
- 端到端待验：`sc-dev` 起会话 → `/model` 切换 → `grep ModelSwitch events.jsonl` 应有一行。
