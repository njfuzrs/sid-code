# 官网权限页（permissions.md）按代码事实校准——修正 3 处错误断言与 6 处失准表述

## 决定了什么

对 `website/use/permissions.md`（权限与人工确认页）做了逐条代码比对核查后，修正 9 处与当前代码不符的内容，只改文档、不改代码：

1. **敏感文件一节重写**（最严重）：原文描述「always-allow 模式下读 `.env` / `*.pem` 仍要确认」，但 SEC-AUDIT-2026-07-19 P2 之后已是**硬 deny**（`path-validator.ts:334-352`，`needsConfirmation: false`），逃生舱是 settings.json 里显式 `Read(.env)` 类 allow 规则（`checker.ts:1043-1073`）。改为如实描述硬拒绝语义与逃生舱。
2. **沙箱违规观测框重写**：原文承诺「违规记录到 violations 列表、看 `[SANDBOX]` 行」，但 `recordViolation` / `getViolations` 全仓零调用点（仅 `sandbox.ts:158,163` 定义）——承诺了一个死功能。改为如实写「目前不采集违规明细」。接线方案已登记到 docs-research bugfixes todo（B1）。
3. **`/permissions` 面板能力**：原文「能看到所有来源的规则并增删」，实际面板只读展示、CRUD 走 `/allow` / `/deny`（`PermissionsDialog.tsx:4-7`），且只显示前 10 条、不按来源分组。
4. 来源优先级表补第 9 个来源 `commandScoped: -1`（`types.ts:164`）。
5. 阴影检测语义纠正：只报不同 behavior 间的遮蔽（allow 被 deny/ask 压），同类不报（`shadowed-rules.ts:46`），原文写反。
6. `Bash(prefix:git )` 与 `Bash(git *)` 的裸 `git` 匹配差异标明（`shell-rule-matching.ts:109-135`）。
7. 启动确认行补 `debug: false` 前置条件（`cli.ts:2598`，`debug` 默认 true 见 `config.ts:988`）。
8. 沙箱 profile 表补 `(allow process-exec)` / `(allow process-fork)`，网络规则标明实际写解析后的 IP、解析失败丢弃（`sandbox.ts:185-186, 28-75`）。
9. `/add-dir` 一节改准：工作区边界仅对**写**操作生效（`path-validator.ts:322-329`），读无工作区边界拦截。

核查过程中差点改错的一处（未改，已核实相符）：danger 框断言「skip-permissions 下 `rm -rf /` 不会被拦」——表面上主流程 Step 2 危险命令拦截在 `hasPermissionsInner` 里先于一切，但 `skipPermissions` 的早退点在外层 `check()`（`checker.ts:1340`），先于 `hasPermissionsInner`（`:1380`），所以文档原断言正确。

## 放弃了什么（以及为什么不选）

- **不在本 PR 里顺手修代码**（沙箱 violations 接线、`permission-choices.ts:104-107` 的 UI 文案漂移、`types.ts:149` 注释总数漂移）：用户明确要求「代码缺陷写 todo 文档、不修」。三项已登记到 `docs-research/sid-code/bugfixes/todo/20261016-权限页文档核查发现的代码缺陷-沙箱违规观测未接线等3项.md`（B1/B2/B3），与本文档 PR 一一对应。混进本 PR 会让「纯文档纠偏」的 review 边界变糊。
- **不删除文档里的「沙箱违规」warning 框**而是改写为如实描述：删掉等于用户失去「这个观测不存在」的知情权，下次有人排查沙箱失败还是会去找不存在的 `[SANDBOX]` 行。
- **不把 `manual`（CLI schema 里 `default` 的 CC 别名）写进模式表**：它不是独立的 `PermissionMode` 类型值（`mode.ts:7-15` 共 8 个），写进去反而制造「第 9 种模式」的误解。

- 关键反例自证：修正 6 的差异由单测佐证（`tests/permission/shell-rule-matching.test.ts:45-48` 断言 `git *` 匹配裸 `git`；`:107-110` 断言 `prefix:git ` 不匹配）。
