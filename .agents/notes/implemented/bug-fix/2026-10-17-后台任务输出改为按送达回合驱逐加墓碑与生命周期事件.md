# 后台任务 `.output` 改为按送达回合驱逐 + 墓碑 + `TaskLifecycle` 事件（S3 / S16 / PR-3）

## 决定了什么

- 「已送达」与「已入队」拆开。`notified` 保留原义（终态已写、完成信息有投递通道），新增 `notificationDeliveredTurn`，只在 `injectPendingNotifications` 把通知放进上下文时由 `markNotificationsDelivered` 置位。轮中与空闲唤醒两条路径都走这个函数。前台子代理（notify=false）的结果走 tool_result，终态写入时直接置位。
- 驱逐判据按回合，不按毫秒，判据收口到 registry `evictDecision`：
  - 已送达：送达之后主循环又完整跑完至少一个回合，并且面板驻留期（30s / killed 3s）与 task_output 续期都已过；
  - 未送达：完成后 10min 走安全阀，同时写 warn 日志。
- 新增回合纪元 `task/lifecycle.ts`。`queryLoop` 在第 2 轮起的每轮开头**先**推进纪元**再**注入通知，finally 收尾再推进一次。顺序反过来的话，本轮刚送达的通知会被记到上一轮。
- 9 个终态写点不再写 `evictAfter`，现在只有 task_output 续期写它。`evictTerminalTasks(force)` 参数删除，因为生产代码没有调用方，留着等于一个能绕过回合门的开关。
- `hasPendingEviction` 与判据同口径：只有已送达且送达回合已过的任务才开 TUI 1s 定时器。等回合的任务靠回合推进时 registry 发出的通知来重新判定；未送达任务靠 registry 内一个 unref 的安全阀定时器，print 模式下也能生效。
- 墓碑：驱逐前同步读 `.output` 末尾 2KB，与 status/exitCode/时间一起登记，最多保留 200 条。read 工具遇到 ENOENT 且路径是 `sidPaths.tasks()/<id>.output` 时返回墓碑，不再报通用的「文件不存在」。
- `TaskLifecycle{task_id, task_type, phase: started|completed|delivered|evicted, status, background, ts, turn, reason?, exit_code?}` 由 registry 单点发出（register / 终态迁移 / 送达 / 驱逐与清理），通过模块级 sink 进入 events.jsonl，sink 在 app.ts 与 JIT 埋点同处接线。

## 放弃了什么（以及为什么不选）

- 计时起点从入队挪到送达、仍按 30s：送达发生在每轮开头，紧接着就是可能长达 116s 的模型调用，TUI 每秒驱逐一次，文件照样会在模型读之前被删。
- 把 30s 拉长到固定 5min：任何固定值都会被更长的 reasoning 越过，这只是掩盖问题。
- 去掉驱逐：`.output` 会无限堆积。
- 每个终态写点各自发 `completed` 事件：9 处很容易漏一处，所以改在 `updateTask` 里检测「非终态 → 终态」迁移，单点发出。
- 墓碑覆盖 bash `tail`/`cat`：做不到，这是诚实边界。真正让文件在模型读之前不被删的是按回合驱逐。

## 拿什么证明它生效了

- 单测 `tests/task/evict-terminal-tasks.test.ts`（S3 段 9 条）、`tests/task/task-output-lifecycle.test.ts`（7 条）、`tests/task/panel-dismiss.test.ts`（改写 5 条）。核心用例：送达后在同一回合内调 120 次 `evictTerminalTasks`（模拟长调用期间 TUI 定时器 tick），文件仍在，`hasPendingEviction()=false`；`markMainTurnCompleted()` 之后才删。变异自证用例对同一状态内联旧的毫秒判据，得到「此刻就删」，新判据保留。
- `bun run affected-tests:run`：4663 pass / 0 fail。`make build` 自检通过，`will always be undefined` 0 处。`bun run lint`、`lint:boundary`、`format:check`、`typecheck:gate`（66/66，无新增）、`docs:gen-reference --check` 全绿。
- 端到端：本地 mock 上游（OpenAI chat）回放「后台 bash → 前台 sleep 3 → read 其 `.output` → 收尾」，用本 worktree 构建的 `./sid-code -p`，`SID_CONFIG_DIR` 隔离。events.jsonl 依次出现 `TaskLifecycle` started(turn=0) → completed(turn=1) → delivered(turn=2)；同一回合内 read 拿到了 `BG-DONE-MARKER`（raw.jsonl 命中）。print 模式退出前没有出现 `evicted`，进程结束时任务仍在送达回合内，符合新判据。
- 线上验收曲线：`TaskLifecycle` 中「evicted 早于 delivered」与「evicted 与 delivered 同 turn」的计数应恒为 0；看 `delivered.ts − completed.ts` 的 p95；`reason=safety_valve` 的占比用来校准 10min 占位值。
