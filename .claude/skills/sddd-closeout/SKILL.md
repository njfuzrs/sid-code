# Spec 收尾流程

## 何时使用
- 一个 Spec 的所有 Task 都已完成
- 用户说"收尾"或"这个 Spec 做完了"

## 收尾检查清单

### 1. 状态更新
- [ ] 更新 tasks.md 所有 Task 状态为完成
- [ ] 更新 tasks.md 进度概览
- [ ] 更新 spec.md 的 status 为 `Done`
- [ ] 更新 spec.md 的 `completed_tasks` 字段

### 2. 文档同步
- [ ] 如果修改了目录结构 → 更新 CLAUDE.md 的目录结构章节
- [ ] 如果涉及架构决策 → 在 `docs/decisions/` 新增 ADR
- [ ] 如果发现新的失败模式 → 更新 `docs/failure-modes.md`
- [ ] 如果修改了 API → 更新相关契约文档

### 3. 偏差审查
- [ ] 审查 tasks.md 的"执行偏差记录"，确认所有偏差已处理
- [ ] 对照 plan.md 检查代码变更，确认无未记录的偏差
- [ ] 如果偏差涉及 Spec 核心意图变更，更新 spec.md

### 4. 归档回顾（知识沉淀）
在 tasks.md 末尾填写归档回顾：

```
## 归档回顾

### 实际 vs 预期
- 预估任务数：N，实际任务数：M
- 主要偏差原因：[简述]

### 经验教训
- [本次实现中学到的经验]
- [AI 在哪些任务上表现好？哪些需要更多人工介入？]

### 产生的新知识
- [新增的失败模式编号]
- [新增的 ADR 编号]
- [更新的 CLAUDE.md 章节]
```

### 5. 迭代文档更新
- [ ] 更新 `docs/iterations/当前迭代.md` 中该 Spec 的状态

### 6. 确认完成
向用户报告收尾结果，列出已完成和未完成的检查项。
