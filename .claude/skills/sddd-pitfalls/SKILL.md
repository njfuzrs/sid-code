# 失败模式检查

## 何时使用
- 开始实现新的 Task 前
- 遇到技术选型决策时
- 用户说"有什么需要注意的坑吗"

## 检查流程

1. 读取 `docs/failure-modes.md`
2. 根据当前任务的关键词，筛选相关的失败模式
3. 向用户报告：
   - 与当前任务相关的已知坑（编号 + 摘要）
   - 对应的预防措施
   - 是否需要调整当前计划

## 报告格式

```
⚠️ 与当前任务相关的已知失败模式：

1. #N [失败模式名称]
   - 触发条件：[何时会踩坑]
   - 预防措施：[怎么避免]

建议：[是否需要调整计划]
```

## 新坑记录

如果在执行过程中发现了新的失败模式：
1. 追加到 `docs/failure-modes.md`
2. 格式参考已有条目：
   ```
   ## N. [失败模式名称]
   - **触发条件**: [何时会踩坑]
   - **症状**: [表现是什么]
   - **根因**: [为什么会发生]
   - **预防**: [怎么避免]
   - **发现日期**: YYYY-MM-DD
   - **相关 Spec**: SPEC-NNN 或"通用"
   ```
3. 如果该失败模式属于高频问题，建议更新 CLAUDE.md 的"高频失败模式（Top 3）"
