# 偏差记录协议

## 何时使用
- 执行 Task 时发现 plan.md 中的技术方案无法按预期实现
- 发现了比 plan.md 更优的实现方式
- 需要新增 plan.md 中未列出的文件或步骤
- spec.md 中的验收标准存在矛盾或无法满足
- 性能约束未满足

## 严重程度判断

| 严重程度 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 低 | 发现更优方案、新增辅助文件 | 记录偏差，继续执行 |
| 中 | 性能约束未满足、范围需要调整 | 记录偏差并标记 ⚠️，继续执行，完成后人工评估 |
| 高 | 技术方案不可行、需求矛盾、接口不符 | 记录偏差并暂停，等待人工决策 |

## 记录格式

在 tasks.md 的"执行偏差记录"区域追加：

```
- [YYYY-MM-DD] [低/中/高] [偏差描述：具体问题 + 原因] → [处理方式]
```

**有效记录示例：**
```
- [2026-03-07] [中] plan.md 指定使用 pandas.read_csv()，但测试文件编码是 GBK 而非 UTF-8，导致解析失败。已修改为 pd.read_csv(file, encoding='gbk')。建议在 spec.md 中补充"支持 GBK 编码"的验收标准。
```

**无效记录示例（不要这样写）：**
```
- [2026-03-07] [低] 发现了一些问题，已处理
```

## 偏差涉及接口变更时
必须同步更新 plan.md 的"文件修改范围"章节，并在偏差记录中注明。
