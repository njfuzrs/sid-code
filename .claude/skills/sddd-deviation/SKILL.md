# 偏差记录协议

## 何时使用
- 执行 Task 时发现 plan.md 中的技术方案无法按预期实现
- 发现了比 plan.md 更优的实现方式
- 需要新增 plan.md 中未列出的文件或步骤
- spec.md 中的验收标准存在矛盾或无法满足
- 性能约束未满足

## 偏差分类

### 类型一：可自主处理的偏差（实施细节调整）
Agent 在不改变 Spec 意图的前提下调整实施细节：
- plan.md 指定用库 A，但发现库 B 更适合且项目已有依赖
- 需要新增一个 plan.md 中未列出的辅助文件
- 任务执行顺序需要调整（发现隐含依赖）

**处理方式：** Agent 自主调整，在 tasks.md 偏差记录中注明，继续执行。人工在 PR Review 时确认。

### 类型二：需要升级的偏差（架构/接口/需求变更）
偏差涉及 Spec 的核心意图、API 契约、或跨模块影响：
- spec.md 中的验收标准在技术上不可行
- 实现方案需要修改已有的 API 契约
- 发现需求本身存在矛盾或遗漏

**处理方式：** Agent 暂停执行，记录偏差并标记为"高严重程度"，等待人工决策。

## 严重程度判断

| 严重程度 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 低 | 发现更优方案、新增辅助文件 | 记录偏差，继续执行 |
| 中 | 性能约束未满足、范围需要调整 | 记录偏差并标记 ⚠️，继续执行，完成后人工评估 |
| 高 | 技术方案不可行、需求矛盾、接口不符 | 记录偏差并暂停，等待人工决策 |

## 记录格式

在 tasks.md 的"执行偏差记录"表格中追加一行：

```
| Task N | YYYY-MM-DD | 低/中/高 | [偏差描述：具体问题 + 原因] | [处理方式] |
```

**有效记录示例：**
```
| Task 2 | 2026-03-07 | 中 | plan.md 指定使用 io.ReadAll()，但大文件场景下内存占用过高。改为 bufio.Scanner 逐行读取。建议在 spec.md 中补充"支持大文件流式处理"的验收标准。 | 已修改实现，继续执行 |
```

**无效记录示例（不要这样写）：**
```
| Task 2 | 2026-03-07 | 低 | 发现了一些问题，已处理 | 已处理 |
```

## 偏差涉及接口变更时
必须同步更新 plan.md 的"文件修改范围"章节，并在偏差记录中注明。

## 偏差确认机制

```
Agent 记录偏差到 tasks.md
    ↓
偏差严重程度判断：
    ├── 低（信息性）→ 记录即可，继续执行，人工在 PR Review 时审查
    ├── 中（需关注）→ 记录并标记 ⚠️，继续执行，完成后人工评估
    └── 高（需决策）→ 记录并暂停当前任务，等待人工确认后继续
```
